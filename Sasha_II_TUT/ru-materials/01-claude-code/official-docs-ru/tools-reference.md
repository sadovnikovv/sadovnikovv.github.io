# Справочник инструментов

> Полный справочник по инструментам, которые может использовать Claude Code, включая требования к разрешениям и поведение каждого инструмента.

Claude Code имеет доступ к набору встроенных инструментов, которые помогают ему понять и изменить вашу кодовую базу. Названия инструментов — это точные строки, которые вы используете в [правилах разрешений](https://code.claude.com/docs/ru/permissions.md#tool-specific-permission-rules), [списках инструментов субагентов](https://code.claude.com/docs/ru/sub-agents.md) и [matcher хуков](https://code.claude.com/docs/ru/hooks.md).

Чтобы контролировать, какие инструменты может использовать Claude и когда он запрашивает разрешение, настройте [правила разрешений](https://code.claude.com/docs/ru/permissions.md#tool-specific-permission-rules) в ваших настройках, [хуки](https://code.claude.com/docs/ru/hooks.md) или [список инструментов субагента](https://code.claude.com/docs/ru/sub-agents.md#supported-frontmatter-fields). См. [Настройка инструментов с помощью правил разрешений и хуков](#configure-tools-with-permission-rules-and-hooks) для каждого места, которое принимает имя инструмента.

Чтобы добавить пользовательские инструменты, подключите [MCP-сервер](https://code.claude.com/docs/ru/mcp.md). Чтобы расширить Claude переиспользуемыми рабочими процессами на основе промптов, напишите [скилл](https://code.claude.com/docs/ru/skills.md), который работает через существующий инструмент `Skill` вместо добавления новой записи инструмента.

> [!NOTE]
>
> В [авторежиме](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) классификатор решает большинство запросов разрешений вместо вас. Столбец `Permission required` показывает, запрашивает ли инструмент разрешение в [режиме Manual](https://code.claude.com/docs/ru/permission-modes.md) для путей внутри рабочего каталога. Инструменты доступа к файлам, отмеченные как No, включая `Read`, `Grep` и `Glob`, по-прежнему запрашивают разрешение для путей вне [рабочего каталога и дополнительных каталогов](https://code.claude.com/docs/ru/permissions.md#working-directories), за исключением файлов, которые нужны самому Claude Code.
>
> `Bash` отмечен как Yes, но запускает встроенный набор [команд только для чтения](https://code.claude.com/docs/ru/permissions.md#read-only-commands) без запроса разрешения.

## Настройка инструментов с правилами разрешений и hooks

В большинстве случаев Claude решает, когда использовать эти инструменты, и вам не нужно называть их самостоятельно при взаимодействии с Claude. Вы ссылаетесь на имена инструментов напрямую при определении разрешений и другой конфигурации:

* в [`permissions.allow`](https://code.claude.com/docs/ru/settings-reference#permissions-allow) и [`permissions.deny`](https://code.claude.com/docs/ru/settings-reference#permissions-deny) в параметрах и интерфейсе `/permissions`
* в флагах CLI [`--allowedTools` и `--disallowedTools`](https://code.claude.com/docs/ru/cli-reference)
* в опциях Agent SDK [`allowedTools` и `disallowedTools`](https://code.claude.com/docs/ru/agent-sdk/permissions#allow-and-deny-rules)
* в frontmatter [`allowed-tools`](https://code.claude.com/docs/ru/skills#frontmatter-reference) skill
* в условии [`if`](https://code.claude.com/docs/ru/hooks-guide#filter-by-tool-name-and-arguments-with-the-if-field) hook

Все они принимают один и тот же формат правил: `ToolName(specifier)`. Спецификатор зависит от инструмента, и несколько инструментов используют один формат:

| Формат правила | Применяется к | Детали |
| :- | :- | :- |
| `Bash(npm run *)` | Bash, Monitor | [Сопоставление шаблонов команд](https://code.claude.com/docs/ru/permissions.md#bash) |
| `PowerShell(Get-ChildItem *)` | PowerShell | [Сопоставление шаблонов команд](https://code.claude.com/docs/ru/permissions.md#powershell) |
| `Read(~/secrets/**)` | Read, Grep, Glob, LSP | [Сопоставление шаблонов путей](https://code.claude.com/docs/ru/permissions.md#read-and-edit) |
| `Edit(/src/**)` | Edit, Write, NotebookEdit | [Сопоставление шаблонов путей](https://code.claude.com/docs/ru/permissions.md#read-and-edit) |
| `Skill(deploy *)` | Skill | [Сопоставление имён skill](https://code.claude.com/docs/ru/skills.md#restrict-claude%E2%80%99s-skill-access) |
| `Agent(Explore)` | Agent | [Сопоставление типа подагента](https://code.claude.com/docs/ru/permissions.md#agent-subagents) |
| `WebFetch(domain:example.com)` | WebFetch | [Сопоставление домена](https://code.claude.com/docs/ru/permissions.md#webfetch) |
| `WebSearch` | WebSearch | Без спецификатора; разрешить или запретить инструмент в целом |

Инструменты, не указанные здесь, такие как `ExitPlanMode` или `ShareOnboardingGuide`, принимают только простое имя инструмента без спецификатора.

Разрешающее правило `Edit(...)` также предоставляет доступ на чтение к тому же пути, поэтому вам не нужно соответствующее правило `Read(...)`. Запрещающее правило `Read(...)` также блокирует инструменты Edit и Write на том же пути, включая создание нового файла там, потому что оба инструмента изменяют содержимое, которое Claude должен иметь возможность прочитать обратно. Для инструмента Write проверка запрета `Read` требует Claude Code v2.1.228 или более поздней версии.

Поля `matcher` hook используют простые имена инструментов, а не формат в скобках. Смотрите [шаблоны matcher](https://code.claude.com/docs/ru/hooks.md#matcher-patterns) для правил сопоставления. Для имён полей, которые каждый инструмент передаёт в `tool_input` в hooks, смотрите [справочник входных данных PreToolUse](https://code.claude.com/docs/ru/hooks.md#pretooluse-input).

## Поведение инструмента Agent

Инструмент Agent запускает субагента в отдельном контекстном окне. Субагент самостоятельно выполняет свою задачу, а затем возвращает свой результат в родительский диалог. Родитель не видит промежуточные вызовы инструментов или выходные данные субагента, только этот финальный результат. Тот же инструмент также может запустить участника команды или разветвление:

* **Участник команды**: если включены [команды агентов](https://code.claude.com/docs/ru/agent-teams.md), вызов с параметром `name` может вместо этого запустить [участника команды](https://code.claude.com/docs/ru/agent-teams.md#how-claude-starts-agent-teams), который отправляет отчет через сообщения команды, а не путем возврата результата
* **Разветвление**: везде, где включен [режим fork](https://code.claude.com/docs/ru/sub-agents.md#turn-fork-mode-on-or-off), инструмент может запустить [разветвленного субагента](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation), который наследует полный родительский диалог вместо начала с нуля

Чтобы ограничить количество ходов, которые выполняет подагент, установите `maxTurns` в [определении подагента](https://code.claude.com/docs/ru/sub-agents.md#supported-frontmatter-fields). Когда подагент достигает лимита, Claude Code отмечает возвращаемый результат как частичный выход, и Claude может [возобновить подагента](https://code.claude.com/docs/ru/sub-agents.md#resume-subagents) для продолжения.

Какие инструменты может использовать подагент без разветвления, зависит от полей `tools` и `disallowedTools` в [определении подагента](https://code.claude.com/docs/ru/sub-agents.md):

* **Ни одно поле не установлено**: подагент наследует каждый [инструмент, доступный подагентам](https://code.claude.com/docs/ru/sub-agents.md#available-tools).
* **Только `tools`**: подагент получает только перечисленные инструменты.
* **Только `disallowedTools`**: подагент получает каждый инструмент родителя, кроме перечисленных.
* **Оба установлены**: `disallowedTools` имеет приоритет. Инструмент, указанный в обоих, удаляется.

В каждом случае разрешенный набор ограничен [инструментами, доступными подагентам](https://code.claude.com/docs/ru/sub-agents.md#available-tools): инструмент, который недоступен подагентам, никогда не предоставляется, даже если указан в `tools`. Где условия в записи таблицы инструментов `SubagentHandback` выполняются, Claude Code также предоставляет подагенту этот инструмент, даже если вы его опустите в `tools` или указали в `disallowedTools`.

Если каждая запись в списке `tools` подагента не соответствует используемому инструменту, инструмент Agent обычно возвращает ошибку с названием записей вместо запуска подагента; см. [Agent would be spawned with zero tools](https://code.claude.com/docs/ru/errors.md#agent-would-be-spawned-with-zero-tools) для сообщения и способов исправления каждой записи.

Запуск подагента сам по себе не запрашивает разрешение. Claude Code проверяет вызовы инструментов подагента в соответствии с вашими правилами разрешений по мере его работы.

Где вы видите запросы разрешений подагента, зависит от того, работает ли он на переднем плане или в фоновом режиме. Claude Code запускает подагентов в фоновом режиме по умолчанию, кроме [случаев, которые работают на переднем плане](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background).

* **Подагенты на переднем плане** показывают те же запросы разрешений, которые вы видели бы в основном диалоге, в момент каждого вызова инструмента.
* **Субагенты в фоновом режиме** выводят запросы разрешений в вашу основную сессию. Запрос указывает, какой субагент запрашивает, и нажатие Esc отклоняет этот вызов инструмента без остановки субагента.

Чтобы [ограничить то, что может достичь подагент](https://code.claude.com/docs/ru/sub-agents.md#control-subagent-capabilities) с самого начала, сузьте его поле `tools`, например исключив Bash из списка, или установите правила отказа в ваших настройках.

## Поведение инструмента AskUserQuestion

Claude использует `AskUserQuestion` для задания вам вопросов с несколькими вариантами ответов, когда ему требуется решение или уточнение. Ответьте, выбрав вариант, или введите свой текст через строку `Other` или поле примечаний.

### Таймаут автоматического продолжения вопроса

Вопросы остаются открытыми до тех пор, пока вы на них не ответите. Если вы хотите, чтобы оставленный без ответа вопрос в конечном итоге закрылся и позволил Claude продолжить без вас, установите параметр [`askUserQuestionTimeout`](https://code.claude.com/docs/ru/settings-reference#askuserquestiontimeout) на `60s`, `5m` или `10m` либо в вашем пользовательском файле `settings.json`, либо из строки **Question auto-continue timeout** в `/config`.

После того как вопрос остается без ввода в течение этого времени, диалог закрывается автоматически: он отправляет все уже выбранные вами варианты и сообщает Claude, что вы можете быть отвлечены от клавиатуры, поэтому Claude действует по собственному усмотрению и может переспросить позже. Вы видите обратный отсчет в течение последних 20 секунд. Нажмите любую клавишу, чтобы перезапустить таймер. Пока ваш терминал сообщает, что его окно находится в фокусе, таймер не ведет обратный отсчет.

Таймер никогда не запускается для вопроса, который Claude задает в [фоновой сессии](https://code.claude.com/docs/ru/agent-view.md), в [режиме программы чтения с экрана](https://code.claude.com/docs/ru/accessibility.md) или пока сессия подключена к [Remote Control](https://code.claude.com/docs/ru/remote-control.md). Такие вопросы ждут, пока вы на них не ответите. Таймаут применяется только к вопросам с несколькими вариантами ответов `AskUserQuestion`; запросы разрешений, включая подтверждение плана, никогда не разрешаются автоматически при неактивности.

## Поведение инструмента Bash

Инструмент Bash запускает каждую команду в отдельном процессе.

### Что сохраняется между командами

* Когда Claude выполняет `cd` в основной сессии, новый рабочий каталог переносится на более поздние команды Bash, пока он остаётся внутри каталога проекта или [дополнительного рабочего каталога](https://code.claude.com/docs/ru/permissions.md#working-directories), который вы добавили с помощью `--add-dir`, `/add-dir` или `additionalDirectories` в настройках. Это включает команды, которые Claude выполняет в ответ на ваши более поздние сообщения.
  * Сессии субагентов никогда не переносят изменения рабочего каталога.
  * Если `cd` приводит за пределы этих каталогов, Claude Code сбрасывает на каталог проекта и добавляет `Shell cwd was reset to <dir>` к результату инструмента.
  * Чтобы отключить этот перенос, чтобы каждая команда Bash начиналась в каталоге проекта, установите `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR=1`.
* Переменные окружения не сохраняются. `export` в одной команде не будет доступен в следующей.
* Псевдонимы и функции оболочки, определённые в файле запуска оболочки, доступны. При запуске сессии Claude Code загружает `~/.zshrc`, `~/.bashrc` или `~/.profile` в зависимости от вашей оболочки, захватывает полученные псевдонимы, функции и параметры оболочки и применяет их к каждой команде Bash.

Активируйте ваше окружение virtualenv или conda перед запуском Claude Code. Чтобы переменные окружения сохранялись между командами Bash, установите [`CLAUDE_ENV_FILE`](https://code.claude.com/docs/ru/env-vars) на скрипт оболочки перед запуском Claude Code или используйте [хук SessionStart](https://code.claude.com/docs/ru/hooks.md#persist-environment-variables) для его динамического заполнения.

### Ограничения по времени ожидания и выводу

Каждая команда выполняется с таймаутом, и Claude управляет им: когда ему требуется больше времени, чем по умолчанию для команды, он передаёт параметр `timeout` с этим вызовом. Вы никогда не устанавливаете таймаут для отдельной команды.

Две [переменные окружения](https://code.claude.com/docs/ru/env-vars.md) контролируют, что Claude получает для команды, которая выполняется на переднем плане:

* `BASH_DEFAULT_TIMEOUT_MS` — значение по умолчанию, когда Claude не передаёт таймаут; две минуты из коробки
* `BASH_MAX_TIMEOUT_MS` — по умолчанию устанавливает потолок, который ограничивает всё, что запрашивает Claude: эффективный потолок — это больший из двух, десять минут из коробки

В сессии, где действует [ограничение времени для фоновых команд](#time-limit-for-background-commands), `timeout` для команды, которую Claude запускает в фоновом режиме, вместо этого устанавливает, как долго команда может работать там, с отдельным значением по умолчанию и максимумом этого ограничения. Инструмент [PowerShell](#powershell-tool) следует тем же правилам таймаута и читает те же две переменные.

#### Ограничения по выводу

Claude Code передаёт вывод команды в рабочий файл по мере выполнения команды; команда, вывод которой превышает 5 ГБ, прерывается. Когда команда завершается, Claude Code читает вывод обратно из этого файла, вплоть до окна обратного чтения, описанного ниже. Сколько вывода достигает Claude встроенно, зависит от того, рассматривает ли Claude Code результат как ошибку:

| Результат | Что получает Claude |
| :- | :- |
| Действительный | Встроенно до примерно 30 000 символов по умолчанию; после этого путь файла, сохранённого в каталог сессии и усечённого после 64 МиБ, плюс предпросмотр до первых 2 000 символов, и Claude читает или ищет файл, когда ему нужен остаток |
| Ошибка | Встроенно до примерно 10 000 символов; после этого выдержка начала и конца этого размера, вырезанная из окна обратного чтения, без пути файла |

Команда, которая выходит с кодом 1, считается действительным результатом для инструмента Bash только когда Claude Code распознаёт код выхода 1 как благоприятный результат для этой команды: `grep`, `rg`, `egrep`, `fgrep`, `find`, `diff`, `test` и `[`, плюс `git diff` и `git grep`. Каждая другая команда, которая выходит с кодом 1, считается ошибкой, даже когда код выхода 1 — это благоприятный информационный результат: нет совпадений для `pgrep` и `jq -e`, файлы, которые отличаются для `cmp`.

[`BASH_MAX_OUTPUT_LENGTH`](https://code.claude.com/docs/ru/env-vars) устанавливает, сколько символов вывода Claude Code читает обратно из рабочего файла в результат команды: 30 000 по умолчанию, вплоть до жёсткого потолка в 150 000. Увеличьте его, когда ваши команды регулярно переполняют это окно, например подробная сборка или полный лог набора тестов. Увеличение его расширяет окно обратного чтения, которое также является окном, из которого вырезается выдержка команды с ошибкой. Это не повышает встроенные потолки: действительный результат выше встроенного потолка поступает как путь файла плюс предпросмотр независимо от этой переменной.

Чтобы изменить, сколько действительного результата Claude получает встроенно, установите вместо этого параметр [`bashOutputMaxChars`](https://code.claude.com/docs/ru/settings-reference#bashoutputmaxchars), вплоть до 128 000 символов. Он задаёт размер встроенного потолка и окна обратного чтения вместе, и Claude Code затем игнорирует `BASH_MAX_OUTPUT_LENGTH`. Требует Claude Code v2.1.261 или новее.

### Фоновые команды

Для долгоживущих процессов, таких как серверы разработки или сборки в режиме наблюдения, Claude может установить `run_in_background: true` для запуска команды как фоновой задачи и продолжения работы во время её выполнения. Просматривайте и останавливайте фоновые задачи с помощью `/tasks`. После того как вы остановите одну там или из подключённого клиента, такого как настольное приложение, Claude переходит дальше вместо ожидания. Если команду запустил субагент, дальше переходит именно этот субагент.

#### Когда фоновая команда останавливается

Команда, которую запустил [субагент переднего плана](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background), останавливается, когда заканчивается запуск этого субагента, независимо от того, завершился ли он, не удался или был прерван. Команда, которую запустили основной диалог или фоновый субагент, продолжает работать после финального ответа, пока она не выйдет, не будет остановлена или не достигнет своего [ограничения по времени](#time-limit-for-background-commands).

Пока команда, которую запустил основной диалог, ещё выполняется, запуск в неинтерактивном режиме с флагом `-p` [остаётся открытым после своего результата](https://code.claude.com/docs/ru/headless.md#background-tasks-at-exit), пока эта команда не выйдет или не достигнет своего ограничения по времени. Команда, которую запустил фоновый субагент, останавливается при выходе запуска.

#### Ограничение времени для фоновых команд

В сессии, которая выполняется без участия человека, например при запуске с флагом `-p`, в приложении Agent SDK, в задании CI или в облачной сессии, фоновые команды Bash и PowerShell имеют ограничение по времени. Локальная сессия, в которой вы работаете из терминала, настольного приложения или расширения VS Code, не имеет ограничения по времени для фоновых команд.

Ограничение по времени требует Claude Code v2.1.285 или новее. До v2.1.288 оно действовало в каждой сессии.

Ограничение по времени отсчитывается с момента перехода команды в фоновый режим:

* Команда, которую Claude запускает в фоновом режиме, получает 30 минут или `timeout`, который Claude передаёт с `run_in_background`, вплоть до максимума в 2 часа
* Команда, которая начинается на переднем плане и затем переходит в фоновый режим по истечении своего таймаута, получает 30 минут с момента перехода

При запуске с флагом `-p`, промпт которого вы передаёте как текст, а не с помощью `--input-format stream-json`, оба значения по умолчанию составляют 10 минут вместо 30.

Когда фоновая команда достигает своего ограничения по времени, Claude Code останавливает её и сообщает Claude, почему, и Claude может запустить команду снова с более длительным `timeout`, если работа всё ещё нужна. Уведомление об остановке гласит `Background command "<description>" was stopped after reaching its background time limit`.

#### Повысьте ограничение времени для фоновых команд

Две [переменные окружения](https://code.claude.com/docs/ru/env-vars.md) повышают эти ограничения для команд Bash и PowerShell одинаково. Обе принимают миллисекунды, и ни одна не может сократить ограничение: более низкое значение оставляет значения по умолчанию и 2-часовой максимум на месте.

* Установите `BASH_DEFAULT_TIMEOUT_MS` выше `1800000`, чтобы заменить 30-минутное значение по умолчанию этим значением, как для команд, которые Claude запускает без `timeout`, так и для перемещённых команд. При запуске с `-p`, промпт которого вы передаёте как текст, любое значение выше `600000` заменяет его 10-минутное значение по умолчанию
* Установите `BASH_MAX_TIMEOUT_MS` выше `7200000`, чтобы повысить 2-часовой максимум до этого значения. Установка `BASH_DEFAULT_TIMEOUT_MS` выше `7200000` повышает максимум таким же образом

#### Команды переднего плана, которые переходят в фоновый режим

Когда команда переднего плана достигает своего таймаута без завершения, Claude Code переводит её в фоновый режим вместо остановки, если только команда не начинается с `sleep`. Перемещённая команда имеет [ограничение по времени](#time-limit-for-background-commands), отсчитываемое с момента перемещения, и перемещённая команда субагента переднего плана всё ещё останавливается, когда заканчивается запуск этого субагента.

Установка [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`](https://code.claude.com/docs/ru/env-vars#variables) или запуск в [режиме bare](https://code.claude.com/docs/ru/headless.md#start-faster-with-bare-mode) отключает автоматическое фоновое выполнение, поэтому команда, достигшая своего таймаута, вместо этого останавливается.

Результат команды, перемещённой в фоновый режим, указывает, что произошло:

* Когда таймаут запускает перемещение, результат сообщает об этом явно: `Command did not complete within its 120s timeout and was moved to the background`, с секундами, соответствующими применённому таймауту, за которым следует ID задачи и путь файла, в который записывается вывод.
* `cd`, `pushd`, `popd` или `chdir` внутри команды, которая перемещается в фоновый режим, никогда не переносится: результат гласит `Session cwd remains <dir>; directory changes made by the backgrounded command do not apply to subsequent commands.`, поэтому Claude не действует на изменение каталога, которое не произошло.

### Ограничение памяти на Linux и WSL

На Linux и WSL установите [`CLAUDE_CODE_TOOL_MEMORY_LIMIT`](https://code.claude.com/docs/ru/env-vars#variables) на размер, такой как `4G`, чтобы ограничить память, которую могут использовать команды Bash, PowerShell и инструмента [Monitor](#monitor-tool), чтобы одна неконтролируемая сборка не могла занять память, которая нужна остальной сессии. Требует Claude Code v2.1.233 или новее. До v2.1.246 команды инструмента Monitor выполнялись вне ограничения.

* Укажите размер как количество байтов или с суффиксом `K`, `M`, `G` или `T`. Установите `0`, `off`, `false`, `no` или `none`, чтобы отключить ограничение. Claude Code игнорирует любое другое значение, которое он не может прочитать как размер, например `4e9`.
* Claude Code считает все команды Bash, PowerShell и Monitor сессии по одному ограничению, а не каждую команду отдельно.
* Claude Code применяет ограничение с помощью cgroup памяти. Когда он не может настроить cgroup, команды выполняются без ограничения, и лог отладки из `claude --debug` сообщает, почему.
* После того как первый процесс, который Claude Code запускает, включил ограничение или отключил его из-за значения off или неудачной настройки cgroup, Claude Code удерживает этот результат, пока вы не перезапустите. Чтобы применить изменённое или удалённое значение или исправленную настройку, запустите `claude` снова.
* Когда команды не могут оставаться под ограничением, ядро завершает команду, и ничто в её результате не называет ограничение.

Claude Code также может считать другие виды процессов, которые он запускает, по тому же ограничению. Установите [`CLAUDE_CODE_TOOL_MEMORY_CGROUP_EXCLUDE`](https://code.claude.com/docs/ru/env-vars#variables) на список видов, разделённый запятыми, которые нужно исключить из ограничения; Claude Code применяет ограничение к каждому виду, который не в вашем списке. Установите его на `none`, чтобы ограничить каждый вид, или на `all-new`, чтобы ограничить только команды инструментов Bash, PowerShell и Monitor. Требует Claude Code v2.1.246 или новее. Виды, которые вы можете назвать:

* `mcp`: локальные [MCP-серверы](https://code.claude.com/docs/ru/mcp.md)
* `lsp`: [языковые серверы](#lsp-tool-behavior)
* `hooks`: команды [хуков](https://code.claude.com/docs/ru/hooks.md)
* `plugin`: команды, которые запускают [плагины](https://code.claude.com/docs/ru/plugins/overview.md)
* `helper`: собственные вспомогательные команды Claude Code, такие как `git`
* `agent`: дочерние процессы Claude Code, такие как [участники команды агентов](https://code.claude.com/docs/ru/agent-teams.md)

Что бы вы ни указали, применяются эти правила:

* **Неизвестные имена**: Claude Code игнорирует имена, которые он не распознаёт
* **Переменная не установлена**: Claude Code берёт набор других ограниченных видов из конфигурации, которую Anthropic доставляет с сервера, и этот набор может меняться со временем, поэтому установите переменную, когда вам нужен набор, который не меняется
* **Хуки, контролирующие разрешения**: даже когда ограничены все виды, Claude Code исключает из ограничения хук, который может заблокировать или изменить результат действия, и любой MCP-сервер, который такой хук вызывает, поэтому завершение ядром хука, контролирующего разрешения, не может разрешить действие, которое он блокировал

## Поведение инструмента Edit

Инструмент Edit выполняет точную замену строк. Он принимает `old_string` и `new_string` и заменяет первую на вторую. Он не использует регулярные выражения или нечеткое совпадение.

Для применения редактирования должны пройти следующие проверки. Перед любой из них путь, соответствующий [правилу отказа `Read`](https://code.claude.com/docs/ru/permissions#tool-specific-permission-rules), отклоняется, включая создание нового файла там.

* **Read-before-edit**: Claude читает файл в текущем диалоге перед его редактированием, и чтение, прерванное уведомлением [`PARTIAL view`](#large-files), не учитывается. Claude Opus 4.6, Claude Haiku 4.5 и более старые модели всегда требуют чтения. Более новые модели могут редактировать непрочитанный файл, когда его чтение не потребовало бы запроса разрешения и инструмент Read доступен.
* **Match**: `old_string` должна появиться в файле ровно так, как написано. Даже одного символа пробела или различия в отступе достаточно, чтобы не совпасть.
* **Uniqueness**: `old_string` должна появиться ровно один раз. Когда она появляется более одного раза, Claude либо предоставляет более длинную строку с достаточным окружающим контекстом, чтобы определить одно вхождение, либо устанавливает `replace_all: true` для замены всех вхождений.

Файл, который изменился на диске после последнего чтения Claude, все еще может быть отредактирован, когда `old_string` точно совпадает с текущим содержимым однозначно и Claude Code может прочитать файл без запроса. Сопоставление с текущим содержимым файла обеспечивает безопасность, и результат отмечает, что файл содержит другие изменения, поэтому Claude перечитывает его перед редактированиями, которые зависят от окружающего содержимого. В любом другом случае, например при устаревшей `old_string` или той, которая совпадает более одного раза без `replace_all`, Claude читает файл снова перед редактированием.

Claude также может редактировать файл без отдельного вызова Read после того, как просмотрит его с помощью команды Bash, например `cat` или `grep`. Это команды `cat`, `nl`, `bat`, `batcat`, `head`, `tail`, `sed -n 'X,Yp'`, `grep`, `egrep`, `fgrep` и `rg`, каждая из которых запускается на одном файле без конвейеров или перенаправлений. Если команда не вывела никакого текста файла, например когда поиск ничего не нашел, проверка read-before-edit по-прежнему применяется.

Когда Claude просматривает файл таким образом, Claude Code также загружает все [`CLAUDE.md` подкаталогов](https://code.claude.com/docs/ru/memory#how-claude-md-files-load) и [правила с областью действия по пути](https://code.claude.com/docs/ru/memory.md#path-specific-rules), которые применяются к этому файлу. См. [Правила разрешений Read и Edit](https://code.claude.com/docs/ru/permissions.md#read-and-edit) для информации о том, какие команды Bash охватывают ваши правила отказа `Read` и `Edit`.

### Защита файлов только для чтения в Perforce

Чтобы Edit, Write и NotebookEdit не перезаписывали файлы только для чтения в рабочем пространстве Perforce, установите [`CLAUDE_CODE_PERFORCE_MODE`](https://code.claude.com/docs/ru/env-vars#variables) в значение `1`. Тогда эти инструменты отказываются изменять файлы только для чтения и сообщают Claude, что сначала нужно выполнить `p4 edit`.

### Файлы не в UTF-8

Claude не может использовать [NotebookEdit](#notebookedit-tool-behavior) для файла, который не является допустимым UTF-8. То же касается Edit, если только файл не начинается с метки порядка байтов UTF-16 little-endian. Когда Claude пытается это сделать, инструмент отклоняет изменение и оставляет файл нетронутым. К отклоняемым файлам относятся текст не в ASCII, сохраненный в устаревшей кодировке, такой как Windows-1252 или Shift-JIS, двоичные файлы и UTF-8 с недопустимой последовательностью байтов.

Инструменты отказываются, поскольку они сохраняют весь файл обратно в UTF-8, что заменило бы каждый байт, который они не могут декодировать, символом замены `U+FFFD`. Вместо этого [ошибка, которую получает Claude](https://code.claude.com/docs/ru/errors.md#file-is-not-valid-utf-8), указывает ему внести изменение с помощью shell-команды, которая сохраняет кодировку файла, или сначала спросить вас о преобразовании файла в UTF-8.

Claude по-прежнему может заменить такой файл с помощью Write, если только новое содержимое не содержит `U+FFFD` — символ, который Read показывает Claude вместо байтов, которые не удается декодировать. Эта защита не позволяет Claude записать обратно искаженный текст, который он прочитал. Когда Write все же заменяет файл, он сохраняет новое содержимое в UTF-8, поэтому исходная кодировка файла теряется.

## Поведение инструмента EndConversation

Инструмент EndConversation завершает текущую сессию. Claude использует его только в двух ситуациях:

* когда вы продолжаете отправлять оскорбительные сообщения после того, как Claude сделал четкое предупреждение и не смог перенаправить диалог
* когда вы явно просите Claude завершить сессию, а затем подтверждаете, что все еще хотите продолжить, когда Claude спрашивает об этом

Общее разочарование, ругательства или неудачное выполнение задачи не подходят, как и запросы вредоносного контента, которые Claude отклоняет вместо завершения сессии. Claude Code следует тому же подходу, что и claude.ai, который может [завершить редкое подмножество чатов](https://www.anthropic.com/research/end-subset-conversations).

После завершения Claude интерактивной сессии сессия блокируется. Новые запросы и большинство команд возвращают `Claude ended this conversation. Start a new session (or /clear) to continue.`, и только `/clear`, `/resume`, `/help`, `/exit` и `/feedback` продолжают работать. Claude Code записывает завершение в стенограмму сессии, поэтому возобновление завершенной сессии восстанавливает блокировку; история сессии не удаляется.

Возобновление завершенной сессии в [неинтерактивном режиме](https://code.claude.com/docs/ru/headless.md) с флагом `-p` вызывает ошибку и выходит с кодом 1, поэтому скрипт не читает завершенный запуск как успех.

Инструмент никогда не запрашивает разрешение, и [PreToolUse hooks](https://code.claude.com/docs/ru/hooks.md#pretooluse) не запускаются для него. Пока остается любой другой инструмент, вы не можете его заблокировать: [правила отказа и запроса](https://code.claude.com/docs/ru/permissions.md#tool-specific-permission-rules), называющие `EndConversation`, не имеют эффекта, и ни `--disallowedTools`, ни список `--tools` не могут его удалить. Исключение преднамеренно: инструмент ничего не делает, кроме завершения разговора, никогда не читая и не изменяя файлы или данные, и такая защита работает только если сессия, к которой она применяется, не может ее отключить. Когда ваши правила отказа удаляют все остальные инструменты и также совпадают с `EndConversation`, как это делает `"*"`, Claude Code удаляет его также, а не оставляет его единственным инструментом, если правило разрешения явно не называет `EndConversation`. Список отказов, который удаляет все остальные инструменты без совпадения с `EndConversation`, оставляет его на месте.

[Подагенты](https://code.claude.com/docs/ru/sub-agents.md) никогда не получают инструмент. Фоновые задачи, которые совместно используют список инструментов основного разговора, видят его, но вызов его там ничего не завершает.

Инструмент появляется только когда выполняются все следующие условия:

* **Модель**: модель сессии — Claude Opus 4.8, Claude Sonnet 5, Claude Fable 5 или более поздняя версия одного из этих семейств.
* **Поверхность**: интерактивная сессия терминала, включая сессию `claude` в интегрированном терминале IDE, что является тем, как [плагин JetBrains](https://code.claude.com/docs/ru/jetbrains.md) его запускает. Другие поверхности не включают инструмент, такие как:
  * неинтерактивные запуски `-p`
  * сессии через пакеты TypeScript и Python [Agent SDK](https://code.claude.com/docs/ru/agent-sdk/overview.md)
  * панель [VS Code extension](https://code.claude.com/docs/ru/vs-code.md), которая поставляется с собственным CLI
  * [GitHub Actions](https://code.claude.com/docs/ru/github-actions.md)
  * [облачные сессии](https://code.claude.com/docs/ru/claude-code-on-the-web.md)
* **Режим запуска**: не сессия [`--bare`](https://code.claude.com/docs/ru/headless#start-faster-with-bare-mode). Режим bare загружает только инструменты shell и файлов, поэтому инструмент никогда там не регистрируется.
* **Поставщик**: недоступно на [Amazon Bedrock](https://code.claude.com/docs/ru/amazon-bedrock.md), [Claude Platform on AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md), [Google Cloud's Agent Platform](https://code.claude.com/docs/ru/google-vertex-ai.md) или [Microsoft Foundry](https://code.claude.com/docs/ru/microsoft-foundry.md), или на сессиях, вошедших через [облачный шлюз](https://code.claude.com/docs/ru/claude-apps-gateway).

## Поведение инструмента EnterWorktree

Инструмент EnterWorktree создаёт изолированный [git worktree](https://code.claude.com/docs/ru/worktrees.md) и переключается в него. Если передан `path`, инструмент переключается в существующий worktree вместо создания нового.

* **Какие worktree можно указать в `path`**: при первом входе целевым может быть worktree текущего репозитория. В репозитории, который содержит другие репозитории, это также может быть worktree вложенного в него репозитория.
* **Когда запрашивается подтверждение**: для `path` вне `.claude/worktrees/` перед входом запрашивается ваше подтверждение, поскольку это переносит рабочий каталог сессии и доступ на запись в это расположение. Создание нового worktree и пути внутри `.claude/worktrees/` подтверждения не требуют. До v2.1.206 Claude входил в пути вне `.claude/worktrees/` без запроса.
* **Изнутри worktree**: в сессии внутри worktree доступна только форма с `path`, и целевой путь должен находиться в `.claude/worktrees/` репозитория сессии. То же самое относится к субагенту с закреплённым рабочим каталогом, например с [`isolation: worktree`](https://code.claude.com/docs/ru/sub-agents#supported-frontmatter-fields).
* **Когда инструмент отсутствует**: если включён параметр [`permissions.blockWritesOutsideWorkingDirectories`](https://code.claude.com/docs/ru/settings-reference#permissions-blockwritesoutsideworkingdirectories), Claude Code удаляет `EnterWorktree` и `ExitWorktree` или отклоняет их вызовы. Чтобы продолжить работу в worktree, см. [У Claude нет инструмента `EnterWorktree`](https://code.claude.com/docs/ru/worktrees#claude-has-no-enterworktree-tool).

## Поведение инструмента Glob

Инструмент Glob находит файлы по шаблону имени. На Windows он входит в набор инструментов по умолчанию. На macOS, Linux и WSL Claude Code исключает Glob и [Grep](#grep-tool-behavior) из набора инструментов по умолчанию, и Claude выполняет поиск с помощью `find` и `grep` через инструмент Bash. В оболочке Claude эти две команды запускают встроенные версии `bfs` и `ugrep`, и поиск достигает ваших хуков и правил разрешений как вызовы `Bash`.

На macOS, Linux и WSL вы получаете инструменты Glob и Grep обратно в этих случаях:

* Вы указываете `Glob` или `Grep` в [`--tools` или `--allowedTools`](https://code.claude.com/docs/ru/cli-reference#cli-flags) при запуске сессии или в эквивалентных параметрах [Agent SDK](https://code.claude.com/docs/ru/agent-sdk/overview.md). С `--tools` вы получаете те, которые указали, а указание любого инструмента в `--allowedTools` восстанавливает оба. Разрешающее правило в файле настроек не имеет этого эффекта.
* Правило разрешений [deny](https://code.claude.com/docs/ru/permissions.md#match-all-uses-of-a-tool), флаг `--disallowedTools` или [`--restricted`](https://code.claude.com/docs/ru/cli-reference#cli-flags) удаляет `Bash` из сессии.
* [Субагент](https://code.claude.com/docs/ru/sub-agents.md#available-tools) указывает `Glob` или `Grep` в своем поле `tools` и исключает `Bash`. Указанные инструменты возвращаются только для этого субагента или для всей сессии, когда он запускается как основной агент сессии через [`--agent`](https://code.claude.com/docs/ru/sub-agents#invoke-subagents-explicitly) или настройку `agent`.

Glob поддерживает стандартный синтаксис glob, включая `**` для рекурсивного сопоставления каталогов:

* `**/*.js` соответствует всем файлам `.js` на любой глубине
* `src/**/*.ts` соответствует всем файлам `.ts` в каталоге `src/`
* `*.{json,yaml}` соответствует файлам `.json` и `.yaml` в текущем каталоге

Результаты сортируются по времени изменения и ограничены 100 файлами. Если лимит достигнут, Claude видит флаг усечения в результате и может уточнить шаблон.

Glob не учитывает `.gitignore` по умолчанию, поэтому он находит файлы, игнорируемые git, наряду с отслеживаемыми. Это отличается от [Grep](#grep-tool-behavior), который пропускает файлы, игнорируемые git. Чтобы заставить Glob учитывать `.gitignore`, установите `CLAUDE_CODE_GLOB_NO_IGNORE=false` перед запуском Claude Code.

Claude Code определяет разрешение для вызова Glob перед проверкой существования каталога поиска. Он по-прежнему выполняет проверку разрешения на чтение для отсутствующего `path` вне [рабочих каталогов](https://code.claude.com/docs/ru/permissions.md#working-directories), поэтому запрос разрешения для пути не означает, что путь существует.

Значение `pattern` или `path`, содержащее нулевой байт, возвращает ошибку с просьбой к Claude удалить его.

## Поведение инструмента Grep

Инструмент Grep выполняет поиск в содержимом файлов по шаблонам. Если [Glob](#glob-tool-behavior) находит файлы по имени, то Grep находит строки внутри них. На macOS, Linux и WSL инструмент Grep отсутствует по умолчанию при тех же условиях, что и Glob. Информацию о том, когда оба инструмента доступны, см. в разделе [Поведение инструмента Glob](#glob-tool-behavior).

Grep построен на основе [ripgrep](https://github.com/BurntSushi/ripgrep) и использует синтаксис регулярных выражений ripgrep, а не POSIX grep. Шаблоны, содержащие метасимволы регулярных выражений, требуют экранирования. Например, поиск `interface{}` в коде Go требует шаблона `interface\{\}`.

Шаблон, glob или тип файла, который ripgrep отклоняет, возвращает ошибку, которая включает диагностику ripgrep, чтобы Claude мог исправить входные данные и выполнить поиск снова. До версии 2.1.208 Claude Code сообщал об отклоненном входе как `No files found` вместо ошибки, даже если искомый текст существовал в целевых файлах.

Три режима вывода контролируют, что возвращается:

* `files_with_matches`: только пути файлов, без содержимого строк. Это режим по умолчанию.
* `content`: совпадающие строки с файлом и номером строки. Когда параметр `offset` инструмента указывает за последнее совпадение для шаблона, который имеет совпадения, Grep возвращает `No entries at this offset`, поэтому Claude расширяет или сбрасывает смещение вместо того, чтобы заключить, что шаблон не совпадает.
* `count`: количество совпадений на файл, за которым следует итого по всем совпадающим файлам. Итого охватывает каждое совпадение, даже когда параметры `head_limit` или `offset` инструмента усекают перечисленные записи для каждого файла.

Claude может ограничить результаты по файлу с помощью параметра `glob`, такого как `**/*.tsx`, или по языку с помощью параметра `type`, такого как `py` или `rust`. По умолчанию шаблоны совпадают в пределах одной строки. Claude может установить `multiline: true` для совпадения через границы строк.

Grep соблюдает `.gitignore`, поэтому файлы, игнорируемые git, пропускаются. Для поиска в файле, игнорируемом git, Claude передает его путь напрямую.

Claude Code определяет разрешение для вызова Grep перед проверкой того, существует ли путь поиска `path`. Он по-прежнему выполняет проверку разрешения на чтение для отсутствующего `path` вне [рабочих каталогов](https://code.claude.com/docs/ru/permissions.md#working-directories), поэтому запрос разрешения для пути не означает, что путь существует.

## Поведение инструмента LSP

Инструмент LSP предоставляет Claude анализ кода от работающего языкового сервера. После каждого редактирования файла он автоматически сообщает об ошибках типов и предупреждениях, чтобы Claude мог исправить проблемы без отдельного этапа сборки. Claude также может вызвать его напрямую для навигации по коду:

* Перейти к определению символа
* Найти все ссылки на символ
* Получить информацию о типе в позиции
* Список символов в файле
* Поиск символа по имени во всём рабочем пространстве
* Найти реализации интерфейса
* Отследить иерархии вызовов

Claude Code держит инструмент неактивным до тех пор, пока вы не установите [плагин анализа кода](https://code.claude.com/docs/ru/plugins/code-intelligence.md) для вашего языка. В [облачных сеансах](https://code.claude.com/docs/ru/claude-code-on-the-web.md) Claude Code не запускает языковые серверы плагинов, поэтому инструмент LSP остаётся неактивным там. Claude Code берёт конфигурацию языкового сервера из плагина, и вы устанавливаете двоичный файл сервера самостоятельно.

Claude Code возвращает результат ошибки для каждого вызова LSP в файле, языковой сервер которого он не может запустить.

## Инструмент Monitor

Инструмент Monitor позволяет Claude наблюдать за чем-либо в фоновом режиме и реагировать при изменении, не прерывая диалог. Попросите Claude:

* Отслеживать файл лога и отмечать ошибки по мере их появления
* Опрашивать PR или задачу CI и сообщать об изменении статуса
* Наблюдать за каталогом на предмет изменений файлов
* Отслеживать вывод любого долгоживущего скрипта, на который вы его направите
* Подключиться к потоку WebSocket и сообщать каждое сообщение по мере его поступления

Для большинства наблюдений Claude пишет небольшой скрипт, запускает его в фоновом режиме и получает каждую строку вывода по мере её поступления. Для сервера, который уже отправляет события, Claude может открыть [WebSocket](#websocket-source) вместо запуска скрипта.

Вы продолжаете работать в той же сессии, а Claude вмешивается при поступлении события.

Каждое наблюдение, которое запускает Claude, имеет крайний срок: 5 минут по умолчанию, максимум 30 минут и максимум 10 минут в [неинтерактивном](https://code.claude.com/docs/ru/headless.md) запуске с одним промптом с флагом `-p`.

По истечении крайнего срока наблюдение завершается. Claude получает одно уведомление, поэтому он может снова запустить наблюдение, если оно всё ещё необходимо.

Остановите монитор, попросив Claude отменить его или завершив сессию. Когда вы останавливаете [субагента](https://code.claude.com/docs/ru/sub-agents.md), который запустил мониторы, например из `/tasks`, эти мониторы останавливаются вместе с ним.

Когда Monitor запускает команду, он использует те же [правила разрешений, что и Bash](https://code.claude.com/docs/ru/permissions.md#tool-specific-permission-rules), поэтому шаблоны `allow` и `deny`, которые вы установили для Bash, применяются и здесь. Пока активен [авторежим](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode), Claude Code откладывает разрешающие правила, которые называют сам `Monitor`, наряду с другими [широкими разрешающими правилами, которые он отбрасывает](https://code.claude.com/docs/ru/permission-modes.md#how-the-classifier-evaluates-actions), поэтому классификатор проверяет команды Monitor так же, как он проверяет команды Bash.

В следующих случаях Monitor требует минимальной версии или Git Bash:

* **Минимальная версия**: на Amazon Bedrock, Claude Platform on AWS, Google Cloud's Agent Platform или Microsoft Foundry, а также при установленных `DISABLE_TELEMETRY` или `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` для Monitor требуется Claude Code v2.1.310 или новее. Это требование действует, когда [получение флагов функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching) отключено
* **Windows**: инструмент доступен, только если установлен [Git Bash](https://code.claude.com/docs/ru/setup.md#set-up-on-windows)

Плагины могут объявлять мониторы, которые запускаются автоматически при активации плагина, вместо того чтобы просить Claude запустить их. См. [мониторы плагинов](https://code.claude.com/docs/ru/plugins/components.md#monitors).

### WebSocket source

Когда сервер уже отправляет события через WebSocket, Claude может подключиться к нему напрямую вместо написания скрипта опроса. Каждый вид активности сокета либо становится событием, либо завершает наблюдение:

* **Текстовые сообщения**: каждое становится одним событием, даже если сообщение занимает несколько строк.
* **Двоичные сообщения**: не передаются. Claude получает строку-заполнитель, такую как `[binary frame, 512 bytes]`.
* **Сообщения размером более 1 МиБ**: наблюдение завершается, поэтому подпишитесь на отфильтрованный поток, если он существует.
* **Закрытие сокета**: наблюдение завершается и Claude получает код закрытия.

Наблюдение WebSocket принимает входные данные `ws` вместо `command`, и один вызов Monitor не может объединять оба. Входные данные `ws` имеют два поля:

| Поле | Обязательно | Описание |
| :- | :- | :- |
| `url` | Да | Эндпоинт для подключения. Должен быть URL `ws://` или `wss://` без встроенных учётных данных или пробелов, используя только символы ASCII |
| `protocols` | Нет | Имена подпротоколов WebSocket для предложения во время рукопожатия. Каждая запись должна быть действительным токеном подпротокола, и список не может содержать дубликаты |

Крайний срок `timeout_ms` применяется и к наблюдению WebSocket: наблюдение завершается в крайний срок, и `TaskStop` отменяет его раньше.

Без разрешающего правила для `Monitor` у вас запрашивается подтверждение перед тем, как Claude откроет WebSocket; в [авторежиме](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) вместо этого решение принимает классификатор, если только не применяется [правило запроса](#bash-rules-that-deny-or-prompt-for-websocket-watches). Запрос не предлагает опцию пропускать будущие запросы для того же хоста.

#### Адреса и хосты, запрещённые для наблюдений WebSocket

Claude Code отклоняет URL-адреса, указывающие на приватный, link-local или облачный адрес метаданных, включая имена хостов, которые ваш компьютер разрешает в такой адрес. За [прокси](https://code.claude.com/docs/ru/network-config.md#proxy-configuration) наблюдение может достичь приватного, link-local или облачного адреса метаданных, если прокси его не блокирует, поскольку Claude Code не проверяет адрес, который находит прокси. Claude Code также отклоняет хосты в `sandbox.network.deniedDomains`, а когда в управляемых настройках установлен [`allowManagedDomainsOnly`](https://code.claude.com/docs/ru/settings-reference#sandbox-network-allowmanageddomainsonly), — любой хост вне управляемого списка разрешённых доменов.

Если наблюдение за прокси завершается ошибкой `could not resolve <host>`, перезапустите Claude Code v2.1.319 или новее с переменной [`CLAUDE_CODE_PROXY_RESOLVES_HOSTS`](https://code.claude.com/docs/ru/env-vars#variables), установленной в `1`, чтобы прокси сам разрешал имя хоста.

#### Правила Bash, которые запрещают наблюдения WebSocket или запрашивают для них подтверждение

Если Claude Code отклоняет вызов `Monitor`, открывающий WebSocket, поищите [запрещающее правило или правило запроса](https://code.claude.com/docs/ru/permissions.md#manage-permissions), записанное как `Bash` или `Bash(*)`. Сделайте то же самое, если для этого вызова запрашивается подтверждение, несмотря на ваше разрешающее правило для `Monitor`. Правило, охватывающее каждую команду Bash, распространяется и на эти наблюдения WebSocket:

* **Запрещающее правило**: если правило действует на момент начала сессии, у Claude нет инструмента Monitor, поэтому он не может запустить наблюдение. Если вы добавите правило во время сессии, следующий вызов `Monitor` от Claude будет отклонён. Отказ выглядит так: `Permission to use Monitor has been denied: it runs code as Bash does, and a rule denies Bash.`
* **Правило запроса**: у вас запрашивается подтверждение наблюдения. Разрешающее правило, хук `PreToolUse`, режим `bypassPermissions` или классификатор авторежима не могут одобрить его за вас. Вы можете одобрить его из [хука `PermissionRequest`](https://code.claude.com/docs/ru/hooks#permissionrequest). Там, где ответить некому, например в режиме `dontAsk`, Claude Code отклоняет наблюдение.

Чтобы разрешить выполнение этих наблюдений, сузьте правило до нужных вам команд, например `Bash(rm *)`.

Правило запроса, а также запрещающее правило, добавленное во время сессии, распространяются на эти наблюдения в Claude Code v2.1.319 или новее.

## Поведение инструмента NotebookEdit

NotebookEdit изменяет Jupyter notebook по одной ячейке за раз, нацеливаясь на ячейки по их `cell_id`. Он не выполняет замену строк по всему notebook так, как [Edit](#edit-tool-behavior) делает на простых файлах.

Три режима редактирования контролируют, что происходит с целевой ячейкой:

* `replace`: перезаписать источник ячейки. Это значение по умолчанию.
* `insert`: добавить новую ячейку после целевой. Без `cell_id` новая ячейка переходит в начало notebook. Требует установки `cell_type` на `code` или `markdown`.
* `delete`: удалить целевую ячейку.

NotebookEdit отклоняет файл notebook, который не декодируется как UTF-8, по [тому же правилу, что и Edit](#non-utf-8-files), и ничего не записывает.

Правила разрешений используют формат пути `Edit(...)`. Правило, такое как `Edit(notebooks/**)`, охватывает вызовы NotebookEdit на файлы в этом каталоге.

### Замена ячейки очищает её сохранённые выходные данные в файле

Когда NotebookEdit заменяет ячейку кода, её счётчик выполнения и сохранённые выходные данные очищаются. Чтобы вернуть выходные данные, повторно выполните эту ячейку и все ячейки, которые используют определённые в ней функции или переменные. Рабочий процесс в VS Code описан в разделе [Работа с Jupyter notebooks](https://code.claude.com/docs/ru/vs-code.md#work-with-jupyter-notebooks).

## Инструмент PowerShell

Инструмент PowerShell позволяет Claude выполнять команды PowerShell в собственном режиме. В Windows это означает, что команды выполняются в PowerShell вместо маршрутизации через Git Bash. Доступность инструмента зависит от вашей платформы:

* **Windows без Git Bash**: инструмент включен автоматически.
* **Windows с установленным Git Bash**: инструмент включен по умолчанию для учетных записей claude.ai и Console; установите `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` для включения в сеансах Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry, или `0` для отключения.
* **Linux, macOS и WSL**: инструмент является дополнительным.

Ваши [PreToolUse hooks](https://code.claude.com/docs/ru/hooks.md#powershell) получают строку команды инструмента в `tool_input.command` с теми же полями, что и инструмент Bash.

Сопоставьте `Bash|PowerShell` в hooks, которые проверяют команды оболочки; раздел [PowerShell hook input](https://code.claude.com/docs/ru/hooks.md#powershell) объясняет, почему сопоставления только `Bash` недостаточно.

### Включение инструмента PowerShell

Установите `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` в вашей среде или в `settings.json`:

```json theme={null}
{
  "env": {
    "CLAUDE_CODE_USE_POWERSHELL_TOOL": "1"
  }
}
```

В Windows установите переменную на `0` для отключения инструмента. В Linux, macOS и WSL инструмент требует PowerShell 7 или более поздней версии: установите `pwsh` и убедитесь, что он находится в вашем `PATH`.

В Windows Claude Code автоматически обнаруживает `pwsh.exe` для PowerShell 7+ с резервным вариантом `powershell.exe` для PowerShell 5.1. Когда инструмент включен, Claude рассматривает PowerShell как основную оболочку. Инструмент Bash остается доступным для POSIX-скриптов при установленном Git Bash.

Claude Code запускает PowerShell с `-ExecutionPolicy Bypass` только в области процесса, поэтому скрипты `.ps1` и импорт модулей работают на установках Windows по умолчанию без изменения политики машины. Обход области процесса не переопределяет Group Policy `MachinePolicy` или `UserPolicy`, поэтому политики предприятия по-прежнему применяются. Чтобы вместо этого соблюдать эффективную политику выполнения машины, установите `CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1`.

### Правила запрета Bash также отключают инструмент PowerShell

В Windows с установленным Git Bash запрет Bash также отключает инструмент PowerShell на время сессии. Это относится как к ограниченным правилам, таким как `Bash(git push *)`, так и к простому `Bash`, а также к правилам из любого из ваших файлов настроек или из `--disallowedTools`. Claude Code делает это, потому что правило `Bash` не ограничивает инструмент PowerShell, у которого есть [собственные правила разрешений](https://code.claude.com/docs/ru/permissions.md#powershell). Если бы PowerShell оставался включенным, Claude мог бы выполнить в нем то, что ваше правило запрещает в Bash.

Чтобы оставить инструмент PowerShell включенным наряду с правилом запрета Bash, сделайте одно из следующего:

* Установите `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` в вашей среде или в блоке `env` файла настроек, как показано в разделе [Включение инструмента PowerShell](#enable-the-powershell-tool).
* Добавьте в файл настроек ограниченное [правило разрешений `PowerShell`](https://code.claude.com/docs/ru/permissions#powershell), например правило запрета `PowerShell(git push *)`.

Без одного из этих вариантов ограниченное правило запрета Bash оставляет инструмент Bash доступным, а Claude Code отключает PowerShell без предупреждения. Правило, которое полностью удаляет инструмент Bash, оставляет Claude без инструмента оболочки на время сессии.

### Выбор оболочки в параметрах, hooks и skills

Три дополнительных параметра контролируют, где используется PowerShell:

* `"defaultShell": "powershell"` в [`settings.json`](https://code.claude.com/docs/ru/settings-reference#all-settings): маршрутизирует интерактивные команды `!` через PowerShell. Требует включения инструмента PowerShell.
* `"shell": "powershell"` на отдельных [command hooks](https://code.claude.com/docs/ru/hooks.md#command-hook-fields): запускает этот hook в PowerShell. Hooks запускают PowerShell напрямую, поэтому это работает независимо от `CLAUDE_CODE_USE_POWERSHELL_TOOL`.
* `shell: powershell` в [skill frontmatter](https://code.claude.com/docs/ru/skills.md#frontmatter-reference): запускает блоки `` !`command` `` в PowerShell. Требует включения инструмента PowerShell.

Команды PowerShell следуют [тому же поведению сброса рабочего каталога основной сессии](#what-persists-between-commands), что и команды Bash, включая переменную окружения `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR`.

Команды PowerShell также получают переменные, которые хуки сохраняют через `CLAUDE_ENV_FILE`, при условиях, описанных в разделе [Сохраняемые переменные в командах PowerShell](https://code.claude.com/docs/ru/hooks.md#persisted-variables-in-powershell-commands). Требуется Claude Code v2.1.296 или более поздней версии.

### Код выхода 1 от поиска и `git diff` в PowerShell

Если поиск `grep` или `rg`, не нашедший совпадений, показывает `Error: Exit code 1`, когда Claude выполняет его в инструменте PowerShell, это не значит, что поиск завершился неудачей. Вам не нужно ничего делать. Ошибка может появиться, когда поиск является частью более длинной команды. Например, когда `rg` завершается с кодом выхода 1, `rg foo | Out-Null` показывает ошибку, а `rg foo` — нет.

Инструмент PowerShell может считать код выхода 1 обычным результатом для `grep`, `rg`, `egrep`, `fgrep`, `findstr`, `git grep` и `git diff`. Команды поиска используют код выхода 1, чтобы сообщить об отсутствии совпадений. Для `git diff` код выхода 1 означает, что файлы различаются. Команда, которая показывает ошибку при выполнении Claude, [считается завершившейся неудачей](https://code.claude.com/docs/ru/skills.md#when-an-injected-command-fails) в скилле с `shell: powershell`.

### Кодировка Windows и коды выхода

* Перенаправление с `>` и `>>` записывает файлы UTF-8 в PowerShell 5.1
* Claude Code кодирует текст, переданный в стандартный ввод собственной команды, как UTF-8
* Claude Code захватывает вывод ошибок без последовательностей экранирования ANSI
* Команда, дочерний процесс которой ожидает стандартного ввода, получает конец файла вместо зависания
* Если `where.exe` не находит совпадений или `fc.exe` либо `diff.exe` обнаруживают, что файлы различаются, результат может показывать `Error: Exit code 1`, хотя команда не завершилась неудачей. Вам не нужно ничего делать.
* Если код выхода `robocopy` от 1 до 7 отображается как ошибка, копирование не завершилось неудачей, и вам не нужно ничего делать. `robocopy` завершается с кодом от 0 до 7, чтобы сообщить о результате, например о скопированных файлах, и с кодом 8 или выше при неудаче.

### Ограничения предварительного просмотра

Инструмент PowerShell имеет следующие известные ограничения во время предварительного просмотра:

* Профили PowerShell не загружаются
* В Windows sandboxing не поддерживается

## Поведение инструмента Read

Инструмент Read принимает путь к файлу и возвращает его содержимое с номерами строк.

Чтение пустого файла возвращает уведомление о том, что файл существует, но его содержимое пусто, а `offset` за последней строкой возвращает уведомление, дающее количество строк файла.

Read обрабатывает несколько типов файлов помимо простого текста:

* **Изображения**: файлы PNG, JPEG, GIF и WebP возвращаются как визуальное содержимое, которое Claude может видеть, а не как необработанные байты. Claude Code изменяет размер и повторно сжимает большие изображения, чтобы они соответствовали ограничениям размера изображения модели перед отправкой, поэтому Claude может видеть уменьшенную версию большого снимка экрана.

  Если Claude пропустит мелкие детали на уровне пикселей в большом изображении, попросите его обрезать интересующий вас регион, например с помощью ImageMagick через Bash, а затем прочитать обрезанное изображение.

  Read отказывается читать файл изображения размером более 128 МБ и возвращает ошибку, которая предлагает Claude изменить размер изображения или экспортировать уменьшенную копию, а затем прочитать эту копию. Если Claude останавливается на этой ошибке, вместо того чтобы так сделать, см. [File is too large to read as an image](https://code.claude.com/docs/ru/errors.md#file-is-too-large-to-read-as-an-image).
* **PDF-файлы**: Claude читает короткие файлы `.pdf` целиком. Для PDF-файлов длиннее 10 страниц он читает диапазоны с параметром `pages`, таким как `"1-5"`, до 20 страниц за раз. Чтение диапазонов страниц отображает страницы с помощью `pdftoppm` из poppler-utils, поэтому установите его с помощью `brew install poppler` на macOS или `apt-get install poppler-utils` на Debian и Ubuntu. На Windows и других платформах установите сборку poppler, которая помещает `pdftoppm` в ваш `PATH`. Без этого чтение диапазона страниц завершается ошибкой `pdftoppm is not installed`.
* **Jupyter notebooks**: файлы `.ipynb` возвращают все ячейки с их выводом, включая код, markdown и визуализации. Notebook, ячейки которого в сумме занимают более 256 КБ или превышают [лимит токенов](#large-files), вместо этого возвращает ошибку. Claude Code отказывается читать файл notebook размером более 100 МБ; ошибка сообщает Claude, как прочитать часть notebook вместо этого, например срез ячеек, с помощью команды shell.

Read читает только файлы, а не директории. Claude выводит содержимое директории с помощью команды shell, такой как `ls`.

Read отказывается читать файл, расширение которого он считает двоичным, например `.xlsx`, `.parquet`, `.heic` или `.zip`. После отказа Claude продолжает работу: ошибка предлагает скилл для этого типа файлов, если он доступен, или же shell-команду или скрипт, который читает этот формат. Если вы [упомянете через `@`](https://code.claude.com/docs/ru/common-workflows#reference-files-and-directories) файл, который Read отказывается читать, Claude получит путь к файлу, но не его содержимое.

### Большие файлы

Claude может прочитать текстовый файл, размер которого превышает то, что возвращает один вызов Read. По умолчанию один вызов возвращает не более 25 000 токенов или значение, заданное вами в [`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`](https://code.claude.com/docs/ru/env-vars), и отклоняет чтение целого файла размером более 256 КБ, поэтому Claude читает большой файл постранично с помощью `offset` и `limit`. В Claude Code v2.1.296 или новее он может вместо этого прочитать весь файл или длинный диапазон строк за один вызов, установив `allow_large: true`, когда это необходимо, например потому что вы попросили весь файл. Размер такого чтения рассчитывается исходя из места, оставшегося в [контекстном окне](https://code.claude.com/docs/ru/context-window.md) сессии, а не по лимитам по умолчанию. Для изображений, PDF-файлов и notebook их лимиты сохраняются.

Что получает Claude, когда чтение превышает лимиты по умолчанию:

* **Весь файл превышает лимит токенов**: первая страница файла с уведомлением `PARTIAL view`, сообщающим, какую часть файла он получил и как прочитать больше с помощью `offset` и `limit`
* **Весь файл больше 256 КБ или чтение с `offset` или `limit` превышает лимит токенов**: ошибка, предлагающая прочитать часть файла с помощью `offset` и `limit` или вместо этого искать конкретное содержимое с помощью [Grep](#grep-tool-behavior)

## Поведение инструмента SendFeedback

Отзыв, написанный Claude, — это отчет об обратной связи о Claude Code, который Claude пишет для вас. Для этого требуется Claude Code версии 2.1.238 или более поздней. Claude Code сохраняет каждый черновик на вашем компьютере в папке `~/.claude/feedback/drafts/`, и ничего не попадает в Anthropic до тех пор, пока вы его не отправите. Claude создает черновик с помощью инструмента SendFeedback в следующих случаях:

* Инструмент или команда продолжает давать сбой
* Он не может помочь с тем, что вы просили
* Вы указываете на ошибку, которую он допустил, или он сам ее замечает
* Вы просите его отправить отзыв

### Что вы видите, когда Claude создает черновик

После того как Claude ставит черновик в очередь, над вашей подсказкой появляется карточка с названием черновика. Нажмите `1`, чтобы просмотреть черновик, нажмите `2` дважды, чтобы отправить его как есть, или нажмите `0`, чтобы отклонить его. Отклоненный черновик остается в вашей очереди. После того как вы отклоните карточку, Claude Code спросит, хотите ли вы отключить функцию отзывов, написанных Claude. Он перестанет спрашивать после того, как вы дважды откажетесь.

По умолчанию в сеансе отображается не более трех карточек; Anthropic может изменить это ограничение с сервера без выпуска новой версии. После достижения лимита и всякий раз, когда вы устанавливаете [`feedbackDrafts`](https://code.claude.com/docs/ru/settings-reference#feedbackdrafts) на `quiet`, вы видите только количество черновиков в очереди в нижнем колонтитуле подсказки.

### Просмотр и редактирование черновика

Запустите `/feedback` без аргументов, чтобы открыть вашу очередь. Она содержит список всех черновиков в очереди из всех ваших сеансов, включая черновики, карточки которых вы отклонили или никогда не видели. Выберите черновик, чтобы открыть его для просмотра, где вы можете:

* Редактировать название, область и детали
* Установить **Send transcript** на `yes` или `no`. Когда стенограмма сеанса, в котором Claude поставил черновик в очередь, все еще доступна, она по умолчанию установлена на `yes`, что отправляет эту беседу в Anthropic; `no` отправляет только отчет
* Отправить черновик, удалить его или оставить в очереди на потом

Чтобы вместо этого написать отчет самостоятельно, нажмите `w` для стандартного диалога обратной связи. `/feedback` с текстом после него и `/bug` открывают этот диалог напрямую.

### Отправка черновика

Когда вы отправляете черновик, Claude Code отправляет его так же, как отчет `/feedback`, с тем же [сроком хранения](https://code.claude.com/docs/ru/data-usage.md#feedback-using-the-%2Ffeedback-command), и удаляет черновик с вашего компьютера. Когда вы отправляете с карточки, она показывает `✓ Sent`; когда вы отправляете из очереди, она закрывается с квитанцией ID.

Отчет содержит:

* Ваше название, область и детали
* Информацию об окружении, такую как версия Claude Code, операционная система и модель
* ID недавних запросов API
* Стенограмму беседы, когда вы оставили **Send transcript** на `yes` на экране просмотра. Отправка с карточки никогда не включает стенограмму

Claude Code сохраняет ваш рабочий каталог в локальном черновике, чтобы он мог найти стенограмму, и не отправляет каталог.

В [организациях с нулевым сроком хранения данных](https://code.claude.com/docs/ru/zero-data-retention.md#features-disabled-under-zdr), а также в организациях, где применена [конфигурация HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md), Claude Code не включает инструмент SendFeedback в ваши сессии. Если сессия в организации с нулевым сроком хранения данных все еще предлагает инструмент, черновики остаются на вашем компьютере, и отправка завершается с ошибкой `Feedback collection is not available for organizations with custom data retention policies.`

### Удаление или сохранение черновика

Когда вы удаляете черновик, Claude Code удаляет его с вашего компьютера. Черновик, который вы оставляете в очереди, истекает через 30 дней или через [`cleanupPeriodDays`](https://code.claude.com/docs/ru/settings-reference#cleanupperioddays), если это значение меньше. Очередь содержит 10 черновиков из всех ваших сеансов, и когда Claude ставит одиннадцатый, Claude Code удаляет самый старый. Когда вы запускаете `/exit` с черновиками из сеанса, все еще находящимися в очереди, Claude Code спрашивает, хотите ли вы их просмотреть или удалить перед выходом.

### Отключение отзывов, написанных Claude

Установите **Claude-drafted feedback** на `off` в `/config`, что запишет параметр [`feedbackDrafts`](https://code.claude.com/docs/ru/settings-reference#feedbackdrafts), или установите [`CLAUDE_CODE_SEND_FEEDBACK=0`](https://code.claude.com/docs/ru/env-vars) на один сеанс. В любом случае Claude не сможет ставить черновики в очередь. Чтобы продолжить создание черновиков без карточек, установите `feedbackDrafts` на `quiet`. Администраторы могут установить `feedbackDrafts` в [управляемых параметрах](https://code.claude.com/docs/ru/managed-settings.md), которые имеют приоритет над вашим собственным параметром.

### Сеансы без отзывов, написанных Claude

Claude Code включает инструмент в интерактивные сеансы терминала на вашем собственном компьютере, которые используют Claude API вместо облачного провайдера. Он исключает инструмент из:

* Неинтерактивных запусков `-p` и сеансов [Agent SDK](https://code.claude.com/docs/ru/agent-sdk/overview.md), которые не имеют экрана для просмотра очереди
* [Облачных сеансов](https://code.claude.com/docs/ru/claude-code-on-the-web.md), которые не могут писать в очередь на вашем компьютере
* Сеансов на [Amazon Bedrock](https://code.claude.com/docs/ru/amazon-bedrock.md), [Claude Platform на AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md), [Google Cloud's Agent Platform](https://code.claude.com/docs/ru/google-vertex-ai.md) или [Microsoft Foundry](https://code.claude.com/docs/ru/microsoft-foundry.md)
* Сессий, которые обращаются к Claude через [LLM-шлюз](https://code.claude.com/docs/ru/llm-gateway) с собственным ключом или токеном шлюза
* Сеансов, где вы установили [`CLAUDE_CODE_SEND_FEEDBACK=0`](https://code.claude.com/docs/ru/env-vars) или [`DISABLE_FEEDBACK_COMMAND=1`](https://code.claude.com/docs/ru/env-vars), установили `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` на любое непустое значение или отключили [получение флагов функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching)
* Организаций, которые отключили отзывы о продукте, [организаций с нулевым сроком хранения данных](https://code.claude.com/docs/ru/zero-data-retention.md#features-disabled-under-zdr) и организаций, где применена [конфигурация HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md)
* Сессий, в которых Claude Code [перестал предлагать отправку отзывов после отклоненного отчета](https://code.claude.com/docs/ru/errors.md#feedback-is-disabled-by-your-organizations-policy)

## Доступность инструмента Task

Инструменты отслеживания задач `TaskCreate`, `TaskGet`, `TaskUpdate`, `TaskList` и `TodoWrite` доступны по умолчанию только на моделях Opus 4.7, Sonnet 4.6, Haiku 4.5 и более ранних моделях. Везде, где инструменты доступны, вы получаете четыре инструмента Task или `TodoWrite` вместо них, когда вы установите [`CLAUDE_CODE_ENABLE_TASKS=0`](https://code.claude.com/docs/ru/env-vars).

На всех остальных моделях Claude Code исключает инструменты, если вы не согласитесь на их использование. То же самое применяется к ID модели, который Claude Code не распознает, например к пользовательскому имени модели, обслуживаемому через [LLM gateway](https://code.claude.com/docs/ru/llm-gateway). На более новых моделях Claude отслеживает многоэтапную работу без письменного контрольного списка, а определения инструментов и напоминания занимают контекст. Без инструментов Claude ничего не добавляет в [список задач](https://code.claude.com/docs/ru/interactive-mode.md#task-list) во время работы.

Если вы хотите использовать эти инструменты на модели, которая не имеет их по умолчанию, выполните одно из следующих действий:

* Экспортируйте [`CLAUDE_CODE_ENABLE_TODO_TOOLS=1`](https://code.claude.com/docs/ru/env-vars) перед запуском Claude Code, например `CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude`. Claude Code затем предоставляет одинаковые инструменты на каждой модели и каждом провайдере
* Назовите один из инструментов в [`--allowedTools`](https://code.claude.com/docs/ru/cli-reference#cli-flags), например `claude --allowedTools TaskCreate`
* Перечислите инструменты в [`--tools`](https://code.claude.com/docs/ru/cli-reference#cli-flags), что ограничивает встроенные инструменты сеанса только теми, которые он называет. Включите нужные вам инструменты вместе с другими встроенными инструментами, которые вы используете
* В Agent SDK параметры [`allowedTools` и `tools`](https://code.claude.com/docs/ru/agent-sdk/todo-tracking#model-availability) работают так же, как два флага

В [фоновых сеансах](https://code.claude.com/docs/ru/agent-view.md) и в [облачных сеансах](https://code.claude.com/docs/ru/claude-code-on-the-web.md) Claude Code предоставляет одинаковые инструменты на каждой модели, независимо от того, указана она в списке или нет.

Описанный здесь набор по умолчанию применяется в Claude Code версии 2.1.268 и позже.

### Инструменты отслеживания задач в субагентах и командах агентов

Субагент имеет инструменты отслеживания задач только тогда, когда они есть в вашей сессии, независимо от того, какую модель запускает субагент. Участник [команды агентов](https://code.claude.com/docs/ru/agent-teams.md), работающий в том же процессе, имеет инструменты отслеживания задач, когда они есть в вашей сессии. Участник команды в [разделённой панели](https://code.claude.com/docs/ru/agent-teams.md#choose-a-display-mode) — это отдельный процесс Claude Code, который [наследует](https://code.claude.com/docs/ru/agent-teams.md#permissions) ваш список `--tools` и правила запрета, но не `--allowedTools`, поэтому проверьте, что вы задали:

* **Нет списка `--tools` или правила запрета, и `CLAUDE_CODE_ENABLE_TODO_TOOLS` не задана для участника команды**: участник команды имеет те инструменты отслеживания задач, которые его собственная модель имеет по умолчанию.
* **`CLAUDE_CODE_ENABLE_TODO_TOOLS` экспортирована в вашей оболочке**: Claude Code передаёт участнику команды фиксированный набор переменных окружения, который не включает экспортированную вами переменную. Чтобы задать её и для участника команды, запустите сессию, выполнив `claude --settings '{"env":{"CLAUDE_CODE_ENABLE_TODO_TOOLS":"1"}}'` в вашей оболочке. Участник команды также получает ваше значение [`--settings`](https://code.claude.com/docs/ru/settings#change-a-setting-for-one-session).
* **`--tools` называет инструменты отслеживания задач**: участник команды имеет их на любой модели.
* **Инструмент отслеживания задач отсутствует в `--tools` или назван в правиле запрета**: у участника команды нет этого инструмента.

Без инструментов Task агент координирует работу со своей командой через сообщения вместо [общего списка задач](https://code.claude.com/docs/ru/agent-teams.md#assign-and-claim-tasks).

## Поведение инструмента WebFetch

WebFetch принимает URL и промпт, описывающий, что нужно извлечь. Он загружает страницу и преобразует ответ в Markdown, если сервер возвращает HTML. Для большинства загрузок он затем применяет промпт к содержимому в отдельном вызове модели, и Claude получает результат этого вызова, а не исходную страницу. Шаг преобразования не настраивается.

Поэтому WebFetch по своей природе работает с потерями. Промпт извлечения определяет, что дойдёт до Claude, так что результат, в котором говорится, что на странице что-то не упоминается, может означать лишь то, что промпт об этом не спрашивал. Попросите Claude загрузить страницу снова с более конкретным промптом или используйте `curl` через Bash, чтобы получить необработанную страницу.

Несколько особенностей поведения определяют ответ, который получает Claude:

* WebFetch отклоняет `localhost` и любое другое имя хоста без точки, например голое имя в интрасети, ещё до отправки запроса. [Возвращаемая ошибка](https://code.claude.com/docs/ru/errors.md#webfetch-cannot-fetch-localhost) предлагает Claude обращаться к локальным серверам через `curl` в Bash.
* URL с HTTP автоматически повышаются до HTTPS.
* WebFetch считывает до 100 000 символов содержимого страницы за один вызов. В Claude Code v2.1.290 и новее результат для более длинной страницы сообщает Claude, какой объём остался непрочитанным, чтобы Claude мог загрузить следующую часть.
* По умолчанию WebFetch кэширует каждый ответ на 15 минут, поэтому повторные загрузки того же URL выполняются быстро. В Claude Code v2.1.233 и новее задайте [`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`](https://code.claude.com/docs/ru/env-vars#variables), чтобы изменить, как долго WebFetch хранит каждый ответ.
* Если страница не загрузилась полностью в течение пяти минут, включая все перенаправления, по которым проходит WebFetch, загрузка завершается ошибкой превышения срока. В Claude Code v2.1.268 и новее задайте [`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`](https://code.claude.com/docs/ru/env-vars#variables), чтобы изменить ограничение, или установите `0`, чтобы убрать его.
* Когда URL перенаправляет на другой хост, WebFetch не следует перенаправлению, а возвращает текстовый результат с исходным URL и целью перенаправления. Затем Claude загружает новый URL вторым вызовом WebFetch.
* Когда на шаге извлечения API оказывается перегружен, Claude Code повторяет попытку с задержкой; если загрузка всё равно не удаётся, возвращается результат с ошибкой.

В режиме Manual и в [режиме разрешений](https://code.claude.com/docs/ru/permission-modes.md) `acceptEdits` WebFetch запрашивает подтверждение перед загрузкой, за исключением доменов, которые ваши [правила разрешений](https://code.claude.com/docs/ru/permissions.md#manage-permissions) уже разрешают или запрещают, а также встроенного набора заранее одобренных доменов документации, загрузка с которых выполняется без запроса. Что бы ни разрешали ваши правила, загрузка также сначала проходит [проверку безопасности домена WebFetch](https://code.claude.com/docs/ru/data-usage.md#webfetch-domain-safety-check); в этом разделе описано, что отправляет проверка, и настройка, позволяющая её пропустить. Запрос предлагает три варианта:

* **Yes**: подтверждает только эту загрузку. Следующий вызов WebFetch снова запросит подтверждение, даже для того же домена.
* **Yes, and don't ask again for `<domain>`**: подтверждает загрузку и сохраняет разрешающее правило `WebFetch(domain:...)` для этого домена в `.claude/settings.local.json` для данного репозитория. См. [как сохраняются подтверждения](https://code.claude.com/docs/ru/permissions.md#permission-system). Если ваша организация задаёт [`allowManagedPermissionRulesOnly`](https://code.claude.com/docs/ru/permissions#managed-only-settings), Claude Code скрывает этот вариант.
* **No, and tell Claude what to do differently**: отклоняет загрузку.

Чтобы заранее разрешить домен без запроса, добавьте разрешающее правило, например `WebFetch(domain:example.com)`; `WebFetch(domain:*)` разрешает все домены. [Режимы разрешений](https://code.claude.com/docs/ru/permissions.md#permission-modes) `auto` и `bypassPermissions` пропускают запрос, кроме случаев, когда домен соответствует явному правилу `ask`.

Явное правило `WebFetch(domain:...)` в `deny`, `ask` или `allow` имеет приоритет над набором заранее одобренных доменов, поэтому вы можете заблокировать заранее одобренный домен или требовать для него запрос.

Если URL является ссылкой на [артефакт](https://code.claude.com/docs/ru/artifacts.md) claude.ai, Claude Code может также запросить подтверждение на чтение самого артефакта. О случаях, когда он запрашивает подтверждение, см. [Чтение артефакта, которым с вами поделились](https://code.claude.com/docs/ru/artifacts.md#read-an-artifact-shared-with-you).

WebFetch устанавливает заголовок `User-Agent`, начинающийся с `Claude-User`, и заголовок `Accept`, который предпочитает Markdown вместо HTML, чтобы серверы, поддерживающие согласование содержимого, могли сразу вернуть Markdown.

Команды в песочнице не наследуют встроенный набор заранее одобренных доменов документации WebFetch. Чтобы команда в песочнице могла обращаться к домену без запроса, добавьте домен в [`allowedDomains`](https://code.claude.com/docs/ru/settings-reference#sandbox-network-alloweddomains) или разрешите его правилом `WebFetch(domain:...)`, которое [песочница также учитывает](https://code.claude.com/docs/ru/sandboxing.md#network-isolation). В обратную сторону WebFetch никогда не читает список разрешённых доменов песочницы, поэтому добавление домена в список разрешённых доменов песочницы или сети организации не отменяет запросы WebFetch для этого домена.

### Доступность WebFetch

В Claude Code v2.1.285 и новее установите [`CLAUDE_CODE_DISABLE_WEB_FETCH`](https://code.claude.com/docs/ru/env-vars#variables) в `1`, чтобы отключить WebFetch.

Если вы входите с учётной записью claude.ai уровня Team или Enterprise и не подключаетесь через [LLM-шлюз](https://code.claude.com/docs/ru/llm-gateway), WebFetch также зависит от политики вашей организации, которую Claude Code запрашивает у `api.anthropic.com` при запуске сессии. То же относится к сессии, тарифный план которой Claude Code не может определить, например к сессии, работающей с токеном claude.ai, предоставленным другим приложением.

Если в сессии отсутствует WebFetch, выполните `/status` в этой сессии. Если строка `Organization policy` сообщает, что политика не загрузилась, и называет web fetch среди функций, ожидающих её, значит Claude Code не предоставляет WebFetch, пока не сможет подтвердить, что ваша организация его разрешает. Вне сессии `claude doctor` выполняет собственный запрос и выводит ту же строку. Как только загрузится политика, разрешающая WebFetch, инструмент снова станет доступен без перезапуска.

## Поведение инструмента WebSearch

WebSearch выполняет запрос к серверной части [веб-поиска](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool) Anthropic и возвращает названия результатов и URL-адреса. Он не загружает страницы результатов. Чтобы прочитать страницу, найденную Claude в результатах поиска, он выполняет последующий запрос с помощью [WebFetch](#webfetch-tool-behavior).

Инструмент может выполнить до восьми серверных поисков за один вызов, внутренне уточняя поиск перед возвратом результатов. Claude может ограничить результаты с помощью `allowed_domains` для включения только определённых хостов или `blocked_domains` для их исключения. Эти два списка нельзя объединять в одном вызове.

Когда запрос поиска попадает на перегруженный API, Claude Code повторяет его с экспоненциальной задержкой; вызов, который всё ещё не удаётся, возвращает результат ошибки.

Правила разрешений WebSearch не требуют спецификатора. Простая запись `WebSearch` в `allow` или `deny` — это единственная форма.

Серверная часть поиска не настраивается. Для поиска с использованием другого поставщика добавьте [MCP сервер](https://code.claude.com/docs/ru/mcp.md), который предоставляет инструмент поиска.

> [!NOTE]
>
> WebSearch доступен в Claude API, [Claude Platform на AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md), [Claude Models в Google Cloud (под управлением Anthropic)](https://code.claude.com/docs/ru/claude-models-on-google-cloud-anthropic-managed.md) и Microsoft Foundry. На Google Cloud's Agent Platform он работает с Opus 4, Sonnet 4, Haiku 4.5 и более поздними моделями. Amazon Bedrock не предоставляет серверный инструмент веб-поиска.

### Лимит поиска сеанса

Интерактивная сессия в терминале имеет лимит в 200 вызовов WebSearch. Поиски из основного диалога и из [субагентов](https://code.claude.com/docs/ru/sub-agents.md), например при параллельном веерообразном исследовании, учитываются в одном и том же лимите.

Пока сессия находится на пределе лимита, поиски отображаются в диалоге как вызовы, которые ничего не сделали. Claude получает уведомление, указывающее ему продолжить с информацией, которую он уже собрал, сообщить об этом в своём ответе, а если ему нужны дополнительные поиски — попросить вас повысить лимит.

Чтобы получить больше поисков, повысьте лимит, дождитесь его восполнения или начните новый диалог:

* **Повысьте лимит**: задайте переменной окружения [`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`](https://code.claude.com/docs/ru/env-vars#variables) положительное целое число, например `500`. Лимит можно повысить, но не отключить.
* **Дождитесь восполнения**: в Claude Code версии 2.1.290 или более поздней лимит интерактивной сессии в терминале восполняется со скоростью около 100 вызовов в час. Чтобы изменить скорость, задайте [`CLAUDE_CODE_WEB_SEARCH_REFILLS_PER_HOUR`](https://code.claude.com/docs/ru/env-vars#variables) равной количеству вызовов в час, например `50`.
* **Начните новый диалог**: запуск [`/clear`](https://code.claude.com/docs/ru/commands#all-commands) в промпте Claude Code также сбрасывает счётчик. Если работа, которая всё ещё может порождать субагентов, сохраняется после очистки, например запущенный рабочий процесс, счётчик вместо этого переносится.

В [неинтерактивном режиме](https://code.claude.com/docs/ru/headless.md) с `-p` и в [Agent SDK](https://code.claude.com/docs/ru/agent-sdk/overview.md) лимит применяется к каждому ходу, а не к сессии. Ход длится от отправленного вами сообщения до момента, когда Claude заканчивает отвечать. Лимит сбрасывается, когда после этого вы отправляете следующее сообщение или начинаете новый запуск `claude -p`, даже с [`--continue` или `--resume`](https://code.claude.com/docs/ru/headless#continue-conversations). Чтобы получить больше поисков, повысьте [`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`](https://code.claude.com/docs/ru/env-vars#variables) или задайте скорость восполнения с помощью [`CLAUDE_CODE_WEB_SEARCH_REFILLS_PER_HOUR`](https://code.claude.com/docs/ru/env-vars#variables).

## Поведение инструмента Write

Инструмент Write создает новый файл или перезаписывает существующий полным содержимым. Он не добавляет и не объединяет. Write также перезаписывает существующий файл, байты которого не декодируются, и сохраняет новое содержимое в UTF-8, как описано в разделе [файлы не в UTF-8](#non-utf-8-files).

Требуется ли Claude прочитать существующий файл в текущем разговоре перед его перезаписью, зависит от модели и файла:

* Claude Opus 4.6, Claude Haiku 4.5 и более старые модели всегда требуют чтения, поэтому Write в непрочитанный существующий файл завершается с ошибкой.
* Более новые модели могут перезаписать файл, который они никогда не читали в этом сеансе, при тех же условиях, что и [read-before-edit](#edit-tool-behavior): чтение его не потребует запроса разрешения и инструмент Read доступен.
* Jupyter notebooks и файлы, которые Claude прочитал только частично с [уведомлением `PARTIAL view`](#large-files), требуют чтения на всех моделях.

Это ограничение не применяется к новым файлам.

Просмотр файла с помощью Bash также удовлетворяет этому требованию в соответствии с теми же правилами, описанными в [Edit tool behavior](#edit-tool-behavior).

Для частичных изменений существующего файла Claude использует Edit вместо Write.

## Проверка доступных инструментов

Ваш точный набор инструментов зависит от вашего поставщика, платформы и параметров. Чтобы проверить, что загружено в работающем сеансе, спросите Claude напрямую:

```text theme={null}
What tools do you have access to?
```

Claude дает разговорное резюме. Для точных имен инструментов MCP запустите `/mcp`.

> [!NOTE]
>
> [Инструмент advisor](https://code.claude.com/docs/ru/advisor.md) — это [серверный инструмент](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool), который запускает API, а не инструмент, который реализует Claude Code. Он не имеет имени, на которое вы можете ссылаться в правилах разрешений или сопоставителях hooks.
