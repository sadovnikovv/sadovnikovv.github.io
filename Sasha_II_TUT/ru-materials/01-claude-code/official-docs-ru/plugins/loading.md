# Справочник по загрузке плагинов

> Отследите, откуда Claude Code загружает каждый плагин, какой файл параметров решает, загружается ли он, и почему обновление ничего не изменило.

Используйте эту страницу, когда плагин не загрузился, загрузилась другая копия, чем вы ожидали, или плагин не подхватил обновление, и вы хотите увидеть, какой источник, область параметров или файл на диске это решил. На ней приведены правила, которые Claude Code применяет при запуске сеанса и каждый раз при запуске `/reload-plugins`. Вы также можете попросить Claude прочитать эту страницу и диагностировать вашу конфигурацию.

>

> * **У вас есть конкретное сообщение об ошибке**: см. [Устранение неполадок плагинов](https://code.claude.com/docs/ru/plugins/troubleshooting.md)

* Плагин, который вы отключили, всё ещё загружается: [Найдите, где плагин включен](#find-where-a-plugin-is-enabled)

## Проверьте, на каком этапе находится плагин

Запись `enabledPlugins` становится плагином, который вы можете использовать, в несколько этапов: ваши параметры объявляют его, Claude Code загружает его на диск, и работающий сеанс загружает его. Когда плагин ведёт себя не так, как предполагает файл параметров, проверьте, на каком этапе он находится:

* **Объявлен в параметрах**: `enabledPlugins` указывает, какие плагины должны быть включены, а `extraKnownMarketplaces` указывает, какие маркетплейсы должны существовать. Когда вы запускаете `claude plugin marketplace add`, Claude Code записывает маркетплейс в `extraKnownMarketplaces` в ваши пользовательские параметры, а также на диск
* **Загружен на диск в `~/.claude/plugins/`**: записи о том, что Claude Code загрузил, и сами загруженные файлы:
  * `known_marketplaces.json` записывает каждый маркетплейс, который Claude Code загрузил, с его `source`, `installLocation`, `lastUpdated` и `autoUpdate`. На одного пользователя приходится один `known_marketplaces.json`, поэтому маркетплейс, который вы добавляете в одном проекте, доступен в каждом проекте
  * `installed_plugins.json` записывает каждую установку с её `scope`, `installPath` и `version`
  * `cache/` содержит файлы плагинов
* **Загружен в работающем сеансе**: набор плагинов, который Claude Code загрузил при запуске или при последнем `/reload-plugins`. Изменения параметров или диска не достигают этого уровня до тех пор, пока вы не запустите `/reload-plugins` или не начнёте новый сеанс. Вот почему `claude plugin update` заканчивается на `Restart to apply changes.` и фоновые обновления предлагают вам `Run /reload-plugins to apply`

### Плагины и маркетплейсы, которых нет на диске при запуске сеанса

Плагины загружаются при запуске сеанса из `installed_plugins.json` и кэша без использования сети. После запуска сеанса Claude Code проверяет объявленные маркетплейсы в фоновом режиме:

* **Маркетплейс, который параметры объявляют, но `known_marketplaces.json` не содержит**: Claude Code клонирует его, затем перезагружает плагины и загружает включённые плагины, которые ещё не кэшированы
* **Объявленный маркетплейс, чей источник изменился в параметрах**: Claude Code повторно загружает его из нового источника и показывает `Plugins changed. Run /reload-plugins to activate.`

Включённый плагин, который ни один путь не загрузил и у которого нет пригодного для использования каталога кэша, показывает `Plugin "<name>" not cached at <path>` на вкладке `/plugin` **Errors**. Для исправления см. [`Plugin "<name>" not cached at <path>`](https://code.claude.com/docs/ru/plugins/troubleshooting#plugin-not-cached-at).

## Как узнать, откуда взялся плагин

У каждого плагина есть идентификатор вида `<name>@<origin>`, который вы видите в файлах настроек и в выводе `claude plugin list --json`. Часть после `@` показывает, где Claude Code нашёл плагин:

| ID заканчивается на | Как плагин туда попал | Как его включить или отключить |
| :- | :- | :- |
| `@<marketplace>` | Вы установили его из добавленного вами маркетплейса | `"<name>@<marketplace>": true` или `false` в `enabledPlugins` в файле настроек |
| `@inline` | Вы запустили Claude Code с `--plugin-dir` или `--plugin-url`, задали [`CLAUDE_CODE_PLUGIN_DIRS`](https://code.claude.com/docs/ru/env-vars#variables) или приложение на Agent SDK передало параметр `plugins`. Он загружается только для этой сессии | Включён на время сессии, если только манифест не задаёт `defaultEnabled: false` или файл настроек не задаёт `"<name>@inline": false` |
| `@skills-dir` | Вы сохранили каталог плагина, содержащий `.claude-plugin/plugin.json`, в `~/.claude/skills/` или в `.claude/skills/` проекта | Определяется значением `defaultEnabled` в манифесте, если только файл настроек не задаёт `"<name>@skills-dir"` равным `true` или `false` |
| `@synced` | Вы или ваша организация включили его для вашей учётной записи claude.ai, и Claude Code [скачал его](#synced-plugins) | Включён, если только манифест не задаёт `defaultEnabled: false` или файл настроек не задаёт `"<name>@synced": false`. Плагин, который ваша организация пометила как обязательный, загружается в любом случае |

Для плагина из маркетплейса `<name>` — это имя записи в `marketplace.json`; для `@inline` и `@skills-dir` — это `name` в манифесте плагина.

Имена источников из этой таблицы зарезервированы, поэтому ни один маркетплейс не может называться `inline`, `skills-dir` или `synced`.

### Имя записи и имя в манифесте

У плагина из маркетплейса есть два имени, и они могут различаться:

* **Имя записи в `marketplace.json`**: ключ для установки и включения. Именно его вы пишете в `enabledPlugins`, по нему называется каталог кэша, и его показывает `claude plugin list`
* **`name` в манифесте**: пространство имён, в котором находятся компоненты плагина, и то, что сравнивается при [конфликтах имён](#name-conflicts)

### Плагины, распространяемые через репозиторий

Чтобы поделиться плагином через репозиторий, укажите его в `enabledPlugins` в `.claude/settings.json` или поместите его в `.claude/skills/`. Claude Code не сканирует каталог `.claude/plugins/` проекта.

Облачная сессия не добавляет маркетплейсы, которые репозиторий перечисляет в [`extraKnownMarketplaces`](https://code.claude.com/docs/ru/settings-reference#extraknownmarketplaces), поскольку для этого требуется диалог доверия к рабочему пространству, который облачная сессия никогда не показывает.

#### Проверка доверия и ограничения компонентов для плагинов из репозитория

Плагин уровня проекта хранится в репозитории и попадает к каждому участнику, который его клонирует. Поскольку это содержимое поступает из репозитория, а не от вас, оно загружается только после той же проверки доверия, которая применяется к правилам разрешений проекта в `.claude/settings.json`. Доверия к родительской папке или запуска с `-p` недостаточно. Компоненты, выполняющие код, ограничены ещё сильнее:

* Объявленные в нём MCP-серверы проходят [такое же подтверждение для каждого сервера](https://code.claude.com/docs/ru/mcp.md), как и в `.mcp.json` проекта
* Объявленные в нём MCP-серверы в виде [MCP bundle](https://code.claude.com/docs/ru/plugins/manifest-reference.md#mcpservers) — файла `.mcpb` или `.dxt` — или из файла вне каталога плагина пропускаются. Объявляйте их встроенно или в `.mcp.json` внутри каталога плагина
* [Фоновые мониторы](https://code.claude.com/docs/ru/plugins/components.md#monitors) не загружаются

Ни проверка доверия, ни эти ограничения компонентов не применяются к плагину в вашем собственном `~/.claude/skills/`.

О том, как писать плагины для `--plugin-dir` и каталога скиллов, см. [Создание плагинов](https://code.claude.com/docs/ru/plugins/create.md).

#### Выяснение, почему плагин из репозитория не загрузился

Если плагин в `.claude/skills/` вашего репозитория не загружается, проверьте следующие причины:

* **В подкаталоге**: плагин в корне репозитория не загружается. Claude Code читает `.claude/skills/` [основного рабочего каталога](https://code.claude.com/docs/ru/permissions.md#working-directories) сессии и, в отличие от обычных скиллов и команд, не [ищет плагины в родительских каталогах](https://code.claude.com/docs/ru/skills.md#discovery-from-parent-and-nested-directories). Вместо этого запускайте из корня репозитория или [переместите туда сессию с помощью `/cd`](https://code.claude.com/docs/ru/permissions#move-the-session-to-another-directory) в версии v2.1.246 или новее
* **Из десктопного приложения, в worktree**: плагин загружается из `.claude/skills/` основного checkout, а не из worktree. См. [Что worktree разделяют с основным checkout](https://code.claude.com/docs/ru/worktrees.md#what-worktrees-share-with-the-main-checkout)
* **В папке, которой вы не доверяете**: плагин загружается только после того, как вы примете [диалог доверия к рабочему пространству](https://code.claude.com/docs/ru/permissions.md#what-runs-before-you-trust-a-folder) для этой папки
* **В организации, которая управляет Claude Code**: см. [Плагины из каталога скиллов, заблокированные управляемыми настройками](#skills-directory-plugins-blocked-by-managed-settings)

### Плагины из каталога скиллов, заблокированные управляемыми настройками

Если папка плагина в `~/.claude/skills/` или в `.claude/skills/` проекта не загрузилась и вы не видите ошибки, возможно, ваш администратор заблокировал её через [управляемые настройки](https://code.claude.com/docs/ru/managed-settings.md). Эти папки поступают от вас или из вашего репозитория, а не из маркетплейса, поэтому Claude Code пропускает их, когда администратор задаёт одно из следующих ограничений:

* **Настройка ограничена плагинами**: [`strictPluginOnlyCustomization`](https://code.claude.com/docs/ru/settings-reference#strictpluginonlycustomization) имеет значение `true` или массив, называющий один или несколько видов настройки, которые нужно заблокировать. Плагин пропускается целиком, если заблокирован хотя бы один вид, например `mcp`, независимо от того, какие компоненты в нём есть.
* **Источники маркетплейсов ограничены**: список разрешённых источников [`strictKnownMarketplaces`](https://code.claude.com/docs/ru/settings-reference#strictknownmarketplaces) без записи `{ "source": "skills-dir" }` или список [`blockedMarketplaces`](https://code.claude.com/docs/ru/settings-reference#blockedmarketplaces), содержащий такую запись.

`/plugin` и `claude plugin list` не показывают ни плагина, ни ошибки для пропущенной папки. Её команды `/<name>:<skill>` и агенты отсутствуют, как и её хуки и MCP-серверы.

Если скиллы не входят в число заблокированных видов, `SKILL.md` в корне папки по-прежнему загружается как обычный скилл. В этом случае `/<name>` продолжает работать, а вкладка **Installed** в `/plugin` показывает этот скилл в разделе **Skills**.

* **Подтвердите причину**: выполните `/status` в сессии Claude Code. Если в строке `Setting sources` указано `Enterprise managed settings`, спросите администратора, применяется ли к вам одна из этих настроек. Если нет, см. [Выяснение, почему плагин из репозитория не загрузился](#check-why-a-repository-plugin-didnt-load), чтобы найти другие причины.
* **Загрузите плагин целиком**: добавьте его в [маркетплейс](https://code.claude.com/docs/ru/plugins/create-marketplace.md#create-a-marketplace), разрешённый вашей организацией, и установите оттуда. Чтобы вместо этого загрузить его на одну сессию, запустите `claude` из оболочки с [`--plugin-dir`](https://code.claude.com/docs/ru/plugins/cli-reference#flags-that-load-a-plugin-for-one-session) и путём к папке — это работает, если только администратор не отключил и этот флаг.

### Плагины, синхронизированные с claude.ai

Плагин, который вы включаете для своей учётной записи claude.ai, также загружается в Claude Code наряду с плагинами, которые вы устанавливаете из маркетплейсов. Сюда входят и плагины, которые ваша организация включает для своих участников. Каждый из этих плагинов загружается как `<name>@synced`, без маркетплейса и без [записи об установке](#check-which-stage-a-plugin-reached).

В терминальных сессиях загружаются все скиллы, агенты, хуки, MCP-серверы и LSP-серверы синхронизированного плагина с тем же уровнем доверия, что и у установленного вами плагина из маркетплейса.

О компонентах, которые загружает Cowork, см. [таблицу поддержки компонентов](https://claude.com/docs/plugins/platform-support#compare-component-support-by-app) на claude.com.

Синхронизированные плагины загружаются в сессиях Cowork и в терминальных сессиях, в которых вы входите с помощью своей учётной записи claude.ai:

* **[Cowork](https://claude.com/product/cowork)**: Claude Code скачивает их в собственное окружение сессии при её запуске
* **Терминальные сессии**: при каждом запуске Claude Code один раз выполняет синхронизацию в фоновом режиме, скачивая новые и обновлённые плагины и удаляя те, которые вы или ваша организация отключили. Для синхронизации в терминальных сессиях требуется Claude Code v2.1.273 или новее

#### Время синхронизации в облачных сессиях Cowork

Если вы включаете или отключаете плагин для своей учётной записи claude.ai во время сессии Cowork, которая выполняется в облаке, продолжайте работать в этой сессии. Если после нескольких сообщений ничего не изменилось, начните новую сессию.

#### Время синхронизации в терминальных сессиях

Поскольку синхронизация в терминале выполняется в фоновом режиме, она может завершиться уже после начала сессии. Когда она добавляет, обновляет или удаляет синхронизированный плагин в интерактивной сессии, вы видите `Plugins changed. Run /reload-plugins to activate.` Выполните `/reload-plugins`, чтобы загрузить изменение в этой сессии, или оставьте его до следующего запуска Claude Code.

Если вы включаете или отключаете плагин для своей учётной записи claude.ai во время терминальной сессии, Claude Code скачивает или удаляет его при следующем запуске Claude Code.

#### Требования ко входу для синхронизации в терминале

В терминале плагины синхронизируются только в сессиях, в которых вы входите с помощью своей учётной записи claude.ai.

Claude Code не скачивает и не загружает синхронизированные плагины в следующих терминальных сессиях, даже после входа с помощью `/login`:

* Сессия, в которой `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN` или скрипт `apiKeyHelper` предоставляет учётные данные вместо такого входа
* Сессия, которая не [получает флаги функций от Anthropic](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), например сессия, в которой вы задали `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
* Сессия в [режиме bare](https://code.claude.com/docs/ru/headless.md#start-faster-with-bare-mode) или сессия, запущенная с `--safe-mode`
* Сессия, запущенная со списком [`--setting-sources`](https://code.claude.com/docs/ru/cli-reference#cli-flags), в который не входит `user`

Если вы вошли в более ранней версии Claude Code, этот вход не распространяется на плагины, пока Claude Code не обновит его в фоновом режиме. Чтобы получить доступ раньше, снова выполните `/login`. Синхронизация плагинов начнётся при следующем запуске Claude Code.

#### Управление загрузкой синхронизированных плагинов

Вы можете отключать синхронизированные плагины по одному, за исключением плагина, обязательного для вашей организации, или отключить все синхронизированные плагины на компьютере:

* **Один плагин**: `claude plugin disable <name>@synced` в оболочке и вкладка **Installed** в `/plugin` в сессии сохраняют `"<name>@synced": false` в ваших пользовательских [`enabledPlugins`](https://code.claude.com/docs/ru/settings-reference#enabledplugins). Чтобы исключить плагин из проекта во всех окружениях, задайте тот же ключ в закоммиченном `.claude/settings.json` проекта
* **Все синхронизированные плагины на компьютере**: задайте [`syncClaudeAiPlugins`](https://code.claude.com/docs/ru/settings-reference#syncclaudeaiplugins) равным `false` в пользовательских настройках, или ваша организация задаёт его в [управляемых настройках](https://code.claude.com/docs/ru/managed-settings.md). Claude Code прекращает скачивание, а при следующем запуске перемещает уже синхронизированные плагины в `~/.claude/plugins/.trash/` и больше не загружает их. Если ваша организация отключает Skills на claude.ai, синхронизация плагинов также прекращается
* **Плагин, обязательный для вашей организации**: плагин, который ваша организация пометила как обязательный на claude.ai, загружается, даже если вы ранее его отключили. `claude plugin disable` отклоняет его с сообщением `Plugin "<name>@synced" is required by your organization and can't be disabled here. Contact your admin to change it.`, а `claude plugin list` помечает его как `required by your org`

Об удалении плагина на claude.ai см. [Управление установленными плагинами](https://code.claude.com/docs/ru/plugins/install.md#manage-installed-plugins).

## Найдите, где плагин включен

Вы можете установить запись `enabledPlugins` в любом из шести источников. Таблица перечисляет их от самого низкого приоритета к самому высокому и указывает, к кому применяется каждый. Для самих файлов параметров см. [Файлы параметров и кто они затрагивают](https://code.claude.com/docs/ru/settings.md#where-settings-live).

| Источник | Где вы его устанавливаете | Достигает |
| :- | :- | :- |
| `--add-dir` | `.claude/settings.json` или `.claude/settings.local.json` в каталоге, который вы передаёте с `--add-dir` | Только этот сеанс. Только значение `true` имеет эффект, и каждый другой источник его переопределяет |
| `user` | `~/.claude/settings.json` | Вас, в каждом проекте |
| `project` | `.claude/settings.json` | Каждого, кто клонирует репозиторий |
| `local` | `.claude/settings.local.json` | Вас, только в этом репозитории |
| `flag` | Значение `--settings`, которое вы передаёте при запуске | Только этот сеанс |
| `managed` | [Управляемые параметры](https://code.claude.com/docs/ru/managed-settings.md) | Каждого пользователя, который охватывает политика. `true` принудительно включает и `false` блокирует, и ни один другой источник их не переопределяет |

Эти источники объединяются ключ за ключом. Для каждого идентификатора плагина применяемое значение — это значение из источника с наивысшим приоритетом, который упоминает идентификатор. Источник, который не упоминает идентификатор, оставляет значение из источника с более низким приоритетом в силе.

### Отключено в пользовательских параметрах, но всё ещё загружается

Если вы установили плагин в `false` в `~/.claude/settings.json` и он всё ещё загружается, `true` в источнике с более высоким приоритетом его переопределяет. Строка плагина в `claude plugin list` и в `/plugin` показывает `Disabled in ~/.claude/settings.json but still loads — project settings enable it, which overrides your user setting`. Сообщение называет источник, который вас переопределил: `project`, `project, gitignored` для `.claude/settings.local.json`, `cli flag`, или `managed`.

Чтобы отказаться от плагина, включённого проектом, на вашей машине, установите идентификатор в `false` в `.claude/settings.local.json`, который имеет более высокий приоритет, чем файл проекта.

### Включено в каталоге `--add-dir`, но не загружается

Claude Code читает запись `enabledPlugins` со значением `true` в одном из файлов добавленного каталога, только если включены источники настроек этого файла:

* **`.claude/settings.json`**: `project`
* **`.claude/settings.local.json`**: `project` и `local`

Проверьте, какие источники настроек загружает сессия. Они задаются с помощью [`--setting-sources`](https://code.claude.com/docs/ru/cli-reference#cli-flags). В CLI источники `user`, `project` и `local` включены по умолчанию.

Например, если вы запускаете `claude --setting-sources user --add-dir ./shared` в оболочке, Claude Code не читает ни один из файлов в `./shared`. Передайте флаг для файла, содержащего `true`:

* **`settings.json`**: `--setting-sources user,project`
* **`settings.local.json`**: `--setting-sources user,project,local`

### Включено в параметрах проекта, но не установлено

По умолчанию плагин, включённый только в `.claude/settings.json` вашего проекта, не загружается при запуске сессии, пока вы не установите его на своей машине. Если маркетплейс есть на вашей машине, вкладка `/plugin` **Errors** показывает [`Plugin "<name>" is enabled in project settings but isn't installed here`](https://code.claude.com/docs/ru/plugins/troubleshooting#plugin-is-enabled-in-project-settings-but-isnt-installed-here) или [`Plugin "<name>" not cached at <path>`](https://code.claude.com/docs/ru/plugins/troubleshooting#plugin-not-cached-at).

> [!NOTE]
>
> Если вкладка не показывает ни одного из этих сообщений, [добавьте маркетплейс](https://code.claude.com/docs/ru/plugins/install.md#add-a-marketplace) перед установкой. Найдите его источник в настройке `extraKnownMarketplaces` файла `.claude/settings.json` или спросите у сопровождающего.

Чтобы установить плагин, выполните эту команду в оболочке из каталога проекта, используя ключ плагина в `enabledPlugins`:

```shell theme={null}
claude plugin install <name>@<marketplace> --scope project
```

Чтобы загрузить плагин, выполните `/reload-plugins` в вашей сессии или начните новую сессию. Повторите установку в каждом из ваших клонов или используйте `--scope user`, чтобы охватить все ваши проекты.

Вы можете загрузить плагин без установки в следующих случаях:

* **В [каталоге семян](https://code.claude.com/docs/ru/plugins/org.md#seed-containers-and-ci)**: вам ничего не нужно запускать
* **Указан по [относительному пути](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#plugin-sources) в маркетплейсе, который вы добавили из локального пути**: вам ничего не нужно запускать, потому что плагин загружается при запуске сессии
* **Указан по относительному пути, например `./plugins/formatter`, в `marketplace.json` добавленного вами git-маркетплейса**: выполните `/reload-plugins`, чтобы загрузить его только для текущей сессии. Чтобы загрузить его для одного [неинтерактивного запуска `-p`](https://code.claude.com/docs/ru/headless), установите [`CLAUDE_CODE_SYNC_PLUGIN_INSTALL=1`](https://code.claude.com/docs/ru/env-vars).

Claude Code загружает плагин с внешним источником только когда один из этих источников устанавливает его в `true`:

* Ваши пользовательские параметры
* `.claude/settings.local.json`, который git не отслеживает
* Флаг `--settings`
* Управляемые параметры

## Найдите плагины на диске

Claude Code хранит файлы плагинов и записи состояния в одном корне плагинов, который является `~/.claude/plugins`, если вы не установили [`CLAUDE_CODE_PLUGIN_CACHE_DIR`](https://code.claude.com/docs/ru/env-vars). Каждый путь в таблице относителен к этому корню.

| Путь | Что он содержит |
| :- | :- |
| `cache/<marketplace>/<plugin>/<version>/` | Один каталог на установленную версию плагина маркетплейса. `<plugin>` — это имя записи маркетплейса и `<version>` — это [разрешённая версия](#versions-and-updates). `${CLAUDE_PLUGIN_ROOT}` указывает на этот каталог |
| `data/<plugin-id>/` | Постоянный каталог плагина, открытый как `${CLAUDE_PLUGIN_DATA}`. О том, как формируется `<plugin-id>`, см. [Переменные пути и постоянные данные](https://code.claude.com/docs/ru/plugins/components.md#path-variables-and-persistent-data). Claude Code создаёт его, когда компонент плагина впервые его использует, и сохраняет его при обновлениях. По умолчанию Claude Code удаляет его, когда вы удаляете плагин из его последней области. О `--keep-data` и других случаях, когда он остаётся, см. [удаление плагина](https://code.claude.com/docs/ru/plugins/cli-reference.md#plugin-uninstall) |
| `marketplaces/<name>/` | Клон или загрузка маркетплейса, добавленного с GitHub, другого хоста Git или URL. Маркетплейс, добавленный из локального источника `file` или `directory`, не имеет копии здесь, и его `installLocation` в `known_marketplaces.json` — это путь, который вы дали |
| `mcpb/` | Файлы, которые Claude Code извлекает из [пакетов MCP](https://code.claude.com/docs/ru/plugins/components.md#include-a-packaged-mcpb-server), объявленных плагинами. Требуется Claude Code v2.1.324 или новее |
| `synced/` | Плагины, которые Claude Code [синхронизировал с вашей учётной записью claude.ai](#synced-plugins) |
| `.trash/` | Плагины, которые синхронизация claude.ai удалила, например, после того как вы отключили один на claude.ai или прекратили синхронизацию |
| `installed_plugins.json` и `known_marketplaces.json` | Записи о том, что Claude Code установил и какие маркетплейсы он загрузил, описанные в разделе [Проверьте, на каком этапе находится плагин](#check-which-stage-a-plugin-reached). [Маркетплейс, размещённый на claude.ai](https://code.claude.com/docs/ru/plugins/install.md#add-from-claude-ai), записывается в `known_marketplaces_claudeai.json` вместо этого |
| `flagged-plugins.json` | Плагины, которые Claude Code удалил, потому что их маркетплейс их исключил. Они появляются в разделе **Flagged** в `/plugin`; см. [Размещение маркетплейса](https://code.claude.com/docs/ru/plugins/host-marketplace.md) |
| `installed_plugins.set-aside.<date>.<hash>.json` и `installed_plugins.unreadable.<date>.<hash>.kept` | Датированные копии, которые Claude Code сохраняет перед тем, как удалить записи установки, которые ни одна версия Claude Code не может использовать, или перестроить нечитаемый `installed_plugins.json`. См. [примечания по восстановлению](https://code.claude.com/docs/ru/plugins/troubleshooting.md#installed-plugins-json-could-not-be-read-and-was-rebuilt). Они устаревают по расписанию [`cleanupPeriodDays`](https://code.claude.com/docs/ru/settings-reference#cleanupperioddays) |

Поскольку `${CLAUDE_PLUGIN_ROOT}` указывает на каталог версии, путь корня плагина изменяется с каждой версией. Сохраняйте постоянные файлы плагина в `${CLAUDE_PLUGIN_DATA}` вместо этого.

### Плагины на месте и скопированные плагины

Claude Code загружает некоторые плагины на месте из того места, где вы их храните, и копирует остальные в кэш, в соответствии с их источником:

* **Плагины `--plugin-dir` и каталога навыков**: каталог загружается на месте и никогда не копируется. Архив `--plugin-url` или `.zip` `--plugin-dir` сначала извлекается во временный каталог сеанса
* **Плагины с относительным путём в маркетплейсе, который вы добавили из локального пути**: плагин загружается на месте из его пути внутри папки маркетплейса. Ваши правки в исходный каталог вступают в силу при следующем запуске сессии или `/reload-plugins`, и вам не нужно увеличивать версию. Процессы хуков плагина и серверы MCP и LSP получают `CLAUDE_PLUGIN_ROOT`, который указывает на исходный каталог. О его зависимостях пакета Node.js см. [Когда запускается установка зависимостей](#when-the-dependency-install-runs)
* **Плагины источника `command` в [режиме ссылки](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#command-plugin-source)**: каталог, который напечатала команда, загружается на месте через ссылки в записи кэша
* **Каждый другой плагин маркетплейса**: Claude Code копирует плагин в `cache/<marketplace>/<plugin>/<version>/` при установке и загружает эту копию. Файлы вне каталога плагина не копируются, поэтому когда скрипт внутри скопированного плагина читает путь выше корня плагина, такой как `../shared`, он их не находит

### Пути, которые выходят за пределы каталога плагина

Загружается ли плагин на месте или из кэшированной копии, Claude Code не позволяет ему объявлять компоненты вне его собственного каталога. Он отклоняет путь компонента, который разрешается вне корня плагина, независимо от того, объявлен ли путь в `plugin.json` или в записи маркетплейса:

* **Путь, который указывает вне плагина в написанном виде**, такой как `../shared-utils`
* **Символическая ссылка, которая ведёт вне плагина**, кроме [ссылок между плагинами в одном маркетплейсе](https://code.claude.com/docs/ru/plugins/host-marketplace.md#share-files-within-a-marketplace-with-symlinks)
* **На macOS и Linux, путь, который содержит обратную косую черту где-либо в нём**, даже когда путь остаётся внутри плагина. Компоненты, объявленные с путями обратной косой черты, поэтому загружаются только на Windows, поэтому пишите пути компонентов с прямыми косыми чертами, такие как `./commands/deploy.md`

Отклонённый путь появляется как ошибка [`path escapes plugin directory`](https://code.claude.com/docs/ru/errors#path-escapes-plugin-directory), и плагин загружается без этого компонента.

### Очистка предыдущих версий

Когда вы обновляете или удаляете плагин, Claude Code записывает маркер `.orphaned_at` в каталог предыдущей версии. Он удаляет этот каталог в фоновой очистке через 14 дней, поэтому сеанс, который уже загрузил старую версию, продолжает работать.

Очистка выполняется только пока `installed_plugins.json` записывает по крайней мере одну установку. После удаления последнего плагина осиротелые каталоги остаются до тех пор, пока вы не установите другой.

### Зависимости пакета Node.js

Когда Claude Code копирует плагин в кэш, он также устанавливает зависимости пакета Node.js плагина там, поэтому hooks и MCP серверы плагина могут их загружать.

Этот раздел охватывает пакеты npm и Bun, которые плагин объявляет в своём собственном `package.json`. О плагинах, которые зависят от других плагинов, см. [версии зависимостей плагина](https://code.claude.com/docs/ru/plugins/dependencies.md).

#### Когда запускается установка зависимостей

Claude Code устанавливает зависимости в скопированный каталог версии каждый раз, когда создаёт его:

* Когда вы устанавливаете плагин
* Когда Claude Code обновляет плагин до новой версии
* При запуске сеанса, когда включённый плагин ещё не кэширован, например, на новой машине

Для плагина с относительным путём, [загруженного на месте](#in-place-and-copied-plugins) из маркетплейса, который вы добавили из локального пути, Claude Code не устанавливает зависимости в исходный каталог. Установите их там сами, или из хука в [`${CLAUDE_PLUGIN_DATA}`](https://code.claude.com/docs/ru/plugins/components#path-variables-and-persistent-data).

Установка запускается только когда каталог корня плагина содержит как `package.json`, так и поддерживаемый файл блокировки.

Файл блокировки решает, какой менеджер пакетов запускает Claude Code:

| Файл блокировки | Менеджер пакетов |
| :- | :- |
| `bun.lock` | Bun |
| `npm-shrinkwrap.json` или `package-lock.json` | npm |

Если плагин содержит более одного из этих файлов блокировки, Claude Code использует первое совпадение, проверяя по порядку: `bun.lock`, `npm-shrinkwrap.json`, `package-lock.json`.

Claude Code пропускает установку в следующих случаях, связанных с файлом блокировки:

* **`bun.lockb`**: двоичный файл блокировки Bun невозможно проверить. Поставляйте вместо него текстовый `bun.lock` или файл блокировки npm
* **`yarn.lock` или `pnpm-lock.yaml`**: замените его файлом блокировки npm
* **Файл блокировки в формате, который Claude Code не читает**: файлу блокировки npm нужен `lockfileVersion` равный `2` или `3`, который записывает npm 7 или новее, а `bun.lock` нужен `lockfileVersion` не выше `2`

Включите файл блокировки npm, чтобы достичь большинства пользователей. Claude Code запускает менеджер пакетов файла блокировки из PATH пользователя и не пытается использовать другой файл блокировки вместо этого, если этот менеджер пакетов отсутствует.

Для плагина, распространяемого через источник npm, используйте `npm-shrinkwrap.json`, потому что npm исключает `package-lock.json` из опубликованных пакетов.

#### Ограничения на установку зависимостей

Claude Code ограничивает эту установку зависимостей так, чтобы никакой код из плагина или его пакетов не выполнялся во время неё, и ограничивает, как долго она может выполняться:

* **Только пакеты из реестра**: каждая зависимость должна быть пакетом из реестра, закреплённым в файле блокировки на точной версии. Плагин с зависимостью из git, GitHub, папки, рабочего пространства или связанной зависимостью не получает установки.
* **Загрузки по `https`**: ссылка для загрузки в файле блокировки должна использовать `https`, если только она не указывает на собственный реестр npm по умолчанию устанавливающего пользователя.
* **Отдельная папка установки**: менеджер пакетов запускается в собственной папке, которая содержит только копию проверенного списка зависимостей, поэтому npm и Bun не читают `.npmrc`, `.env` или `bunfig.toml` плагина. Когда установка завершается успешно, Claude Code перемещает полученный `node_modules` в плагин.
* **Замороженное разрешение**: установка использует ровно те версии, которые закрепляет файл блокировки, и Claude Code пропускает её, когда `package.json` и файл блокировки перечисляют разные зависимости
* **Нет скриптов жизненного цикла**: `--ignore-scripts` предотвращает запуск скриптов `preinstall`, `install` и `postinstall`, поэтому зависимости, которые собирают собственные модули в этих скриптах, загружаются, но не компилируются во время этой установки
* **Нет переопределений или патчей**: плагин, чей `package.json` задаёт `overrides` npm, не получает установки из файла блокировки npm, а плагин, который задаёт `patchedDependencies` Bun, не получает установки из `bun.lock`
* **Тайм-аут 60 секунд**: Claude Code останавливает установку, которая выполняется дольше, и рассматривает её как неудачную

Claude Code загружает плагин источника npm перед этой установкой зависимостей, и ни один из собственных скриптов установки пакета не запускается во время загрузки. См. [источник плагина npm](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#npm-plugin-source).

Вы не можете отключить автоматическую установку. Ни один параметр или переменная окружения её не отключает.

В ограниченных сетях см. [требования доступа в сеть](https://code.claude.com/docs/ru/network-config.md#network-access-requirements) для хостов, которые нужно разрешить.

#### Когда установка зависимостей не удаётся или пропускается

Если установка не удаётся или пропускается, плагин всё равно загружается, но те его части, которым нужны отсутствующие пакеты, могут не работать.

`/plugin` и `claude plugin list` показывают примечание для включённого плагина, кэшированная копия которого содержит файл блокировки и `package.json` со списком зависимостей времени выполнения, но не содержит каталога `node_modules`. В примечании указано, не завершилась ли установка или она не может быть выполнена для этого плагина. О том, что делать в каждом случае, см. [соответствующий раздел по устранению неполадок](https://code.claude.com/docs/ru/plugins/troubleshooting.md#the-packages-it-lists-are-not-installed).

Когда автоматическая установка не может предоставить зависимость, установите её из хука в [каталог постоянных данных](https://code.claude.com/docs/ru/plugins/components.md#path-variables-and-persistent-data). Это включает пакеты, которым нужны их скрипты жизненного цикла для сборки, зависимости Python, плагины, заблокированные Yarn или pnpm, и зависимости, которые не являются пакетами из реестра, например зависимости из git.

## Версии и обновления

Если автор плагина отправил новые коммиты и `claude plugin update` печатает `<name> is already at the latest version (<version>).`, версия, которую Claude Code вычисляет для плагина, не изменяется, поэтому файлы плагина на диске не изменяются.

Claude Code вычисляет версию для каждого плагина, который он устанавливает, и эта версия — это то, как он обнаруживает обновление. `claude plugin update` и фоновое автоматическое обновление вычисляют версию снова и не заменяют кэшированную копию, когда она совпадает с тем, что записывает `installed_plugins.json`. Обновление, которое запускаете вы, всё равно может [повторить попытку незавершённой установки зависимостей](https://code.claude.com/docs/ru/plugins/troubleshooting.md#the-packages-it-lists-are-not-installed) в этой копии.

Версия также называет каталог кэша плагина.

Манифест, который закрепляет `"version"`, — это один способ, которым вычисленная версия остаётся неизменной при коммитах. См. [Как Claude Code вычисляет версию](#how-claude-code-computes-the-version) для порядка разрешения.

Плагин, [загруженный на месте](#in-place-and-copied-plugins) из маркетплейса, который вы добавили из локального пути, загружает свои текущие исходные файлы при каждом запуске сессии, независимо от того, что говорит его строка версии. Для плагина из [маркетплейса, размещённого на claude.ai](https://code.claude.com/docs/ru/plugins/install.md#add-from-claude-ai), версия, которую claude.ai записывает для плагина, — это его версия, и `version` манифеста не читается.

### Как Claude Code вычисляет версию

Для маркетплейса, который вы добавили по источнику, Claude Code выбирает правило по типу `source` записи маркетплейса плагина. [Справочник маркетплейса](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#plugin-sources) перечисляет типы источников. Для каждого типа источника в этом списке, кроме `command`:

1. Поле `version` в манифесте плагина идёт первым
2. Затем поле `version` в записи маркетплейса плагина
3. Когда ни один не установлен, версия поступает из типа источника:

| Тип источника | Версия, когда поле `version` не установлено |
| :- | :- |
| `github`, `url` или `git-subdir` | SHA коммита источника, сокращённый до 12 символов. Версия `git-subdir` также содержит хэш пути подкаталога |
| `archive` | Дайджест SHA-256, сокращённый до 12 символов: закрепление `sha256` в записи маркетплейса, или дайджест загруженного файла, когда нет закрепления |
| Относительный путь внутри маркетплейса, размещённого на Git | SHA коммита установленного каталога |
| Локальный каталог, когда ни каталог плагина, ни его маркетплейс не являются репозиторием git | `unknown` |
| `npm` | `unknown` |

Claude Code не берёт версию из репозитория, который охватывает путь установки, такого как управляемый git `~/.claude`.

Для источника `command` Claude Code всегда выводит версию из того, что произвела команда: 12-символьный хэш сам по себе, или `<manifest version>-<hash>`, когда манифест устанавливает один. `version` записи маркетплейса игнорируется для источников команд. О том, что охватывает хэш, см. [Режим копирования и режим ссылки](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#copy-mode-and-link-mode).

Поскольку манифест идёт первым, манифест, который закрепляет `"version": "1.0.0"`, держит каждого пользователя на кэшированной копии до тех пор, пока его автор не изменит строку, сколько бы коммитов они ни отправили. Чтобы позволить пользователям отслеживать коммиты вместо этого, оставьте `version` вне манифеста и записи. [Размещение маркетплейса](https://code.claude.com/docs/ru/plugins/host-marketplace.md) охватывает, какой выбор подходит для какой установки выпуска.

### Когда Claude Code обновляет маркетплейс перед установкой

Когда вы устанавливаете плагин, Claude Code ищет его в своей локальной копии каталога маркетплейса. Вы можете запустить `/plugin install` в сеансе или `claude plugin install` в вашей оболочке и назвать плагин с его маркетплейсом или без. Таблица показывает, какие из этих комбинаций обновляют локальную копию.

| Имя плагина | Команда | Что Claude Code обновляет |
| :- | :- | :- |
| `name@marketplace` | `/plugin install` или `claude plugin install` | Названный маркетплейс перед поиском |
| `name` один | `/plugin install` | Только маркетплейсы, у которых автоматическое обновление включено, и только после того, как поиск не найдёт |
| `name` один | `claude plugin install` | Ничего. Он читает кэшированные каталоги без обновления |

Обновление перед установкой `name@marketplace` не зависит от параметра автоматического обновления маркетплейса или от `DISABLE_AUTOUPDATER`.

Когда обновление не удаётся, установка продолжается из кэшированного каталога и `claude plugin install` сообщает `marketplace not refreshed`.

Claude Code пропускает обновление перед установкой `name@marketplace`, когда:

* Маркетплейс был добавлен из локального источника `file` или `directory`, или определён встроенным в параметрах с источником [`settings`](https://code.claude.com/docs/ru/settings-reference#extraknownmarketplaces)
* [Каталог семян](https://code.claude.com/docs/ru/env-vars.md) предоставляет маркетплейс
* Claude Code обновил маркетплейс в течение последних 30 секунд
* Вы установили `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
* [Управляемые параметры](https://code.claude.com/docs/ru/plugins/org.md#restrict-what-users-can-install) блокируют маркетплейс, в этом случае Claude Code также отказывает в установке

### Когда запускается автоматическое обновление

В интерактивном сеансе, после того как вы отправите своё первое сообщение, Claude Code ждёт случайную задержку до десяти минут. Затем он обновляет каждый маркетплейс с включённым автоматическим обновлением и обновляет плагины, установленные из них, на диске.

Работающий сеанс сохраняет версии, которые он загрузил, и вы видите `Plugin updated: <name> · Run /reload-plugins to apply`. Загружаете ли вы или нет, новые версии загружаются при следующем запуске.

#### Какие маркетплейсы и плагины автоматически обновляются

Автоматическое обновление маркетплейса следует первому из этих, что установлено:

1. **`autoUpdate` на его записи `extraKnownMarketplaces`** в файле параметров
2. **`autoUpdate` на его записи `known_marketplaces.json`**, которую переключатель **Enable auto-update** под `/plugin` **Marketplaces** пишет. Когда файл параметров также объявляет маркетплейс под `extraKnownMarketplaces`, переключатель пишет `autoUpdate` в эту запись параметров также
3. **По умолчанию**: включено для официальных маркетплейсов Anthropic, таких как `claude-plugins-official`, отключено для `knowledge-work-plugins` и `first-party-plugins`, включено для [маркетплейсов, добавленных с claude.ai](https://code.claude.com/docs/ru/plugins/install.md#add-from-claude-ai), и отключено для каждого другого маркетплейса

Если вы установите `DISABLE_UPDATES=1`, `DISABLE_AUTOUPDATER=1` или `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, весь проход отключен и переключатель **Enable auto-update** скрыт, если вы также не установите `FORCE_AUTOUPDATE_PLUGINS=1`. [Справочник переменных окружения](https://code.claude.com/docs/ru/env-vars.md) охватывает более широкий эффект каждой переменной.

Автоматическое обновление также пропускает плагин, чья запись маркетплейса объявляет `headersHelper`. [Установки и обновления, которые отказывают команде вместо запроса](https://code.claude.com/docs/ru/plugins/host-marketplace.md#installs-and-updates-that-refuse-the-command-instead-of-asking) объясняют, когда такой плагин появляется на вкладке `/plugin` **Errors** и как вы его обновляете оттуда.

Когда скопированный плагин обновляется в середине сеанса, команды hooks, мониторы, MCP серверы и LSP серверы продолжают использовать путь предыдущей версии. Запустите `/reload-plugins`, чтобы переключить hooks, MCP серверы и LSP серверы на новый путь. Мониторы требуют перезагрузки сеанса.

### Когда источник команды повторно запускается

Плагины с источником `command` не ждут [прохода автоматического обновления](#when-auto-update-runs). Напечатанный каталог отражает состояние инструмента в момент запуска команды, поэтому Claude Code запускает [команду, которую вы приняли](https://code.claude.com/docs/ru/plugins/host-marketplace.md#change-the-command-of-a-command-source), снова в эти моменты:

* Каждый раз, когда вы устанавливаете или обновляете плагин
* Один раз за сеанс для каждого включённого плагина с источником команды, в фоновом режиме, вскоре после запуска сеанса. Этот запуск не зависит от параметра автоматического обновления маркетплейса или от `DISABLE_AUTOUPDATER`
* При запуске или на `/reload-plugins`, когда установленная версия включённого плагина отсутствует в кэше плагина

Claude Code пропускает два фоновых запуска, когда вы установили [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](https://code.claude.com/docs/ru/env-vars). Явные установки и обновления всё ещё запускают команду с этой переменной установленной.

Когда хэшированный вывод команды изменился, Claude Code устанавливает результат как новую версию и перезагружает его в работающем интерактивном сеансе, переключая [те же компоненты, которые переключает `/reload-plugins`](https://code.claude.com/docs/ru/plugins/cli-reference#reload-plugins). Вы видите уведомление о том, что плагин был перезагружен.

Если перезагрузка на месте сделает кэш подсказок сеанса недействительным, Claude Code вместо этого предлагает вам запустить `/reload-plugins`, который [предупреждает о стоимости кэша и применяется при повторном запуске с `--force`](https://code.claude.com/docs/ru/prompt-caching#enabling-or-disabling-a-plugin).

## Конфликты имён

Когда включённые плагины из разных источников имеют одно имя манифеста, этот порядок решает, какой загружается, от наивысшего приоритета к самому низкому:

1. Плагин, чей идентификатор появляется в управляемых параметрах `enabledPlugins`, как `true` или `false`. Копия `--plugin-dir`, чьё имя манифеста совпадает с частью имени идентификатора, не загружается, и вы видите `--plugin-dir copy of "<name>" ignored: plugin is locked by managed settings`
2. Включённый плагин `--plugin-dir`, `--plugin-url` или `CLAUDE_CODE_PLUGIN_DIRS`. Он заменяет установленный плагин маркетплейса с тем же именем или плагин каталога навыков:
   * **Установленный плагин маркетплейса**: заменён молча. `claude plugin list` всё ещё показывает строку маркетплейса как включённую, потому что эта строка отражает ваши параметры. Только журнал, который Claude Code пишет в `~/.claude/debug/`, когда вы запускаете с `--debug`, записывает `Plugin "<name>" from --plugin-dir overrides installed version`
   * **Плагин каталога навыков**: заменён строкой вкладки `/plugin` **Errors**, которая читает `Not loaded — the name "<name>" is already taken by a session-only plugin (--plugin-dir / --plugin-url), which takes precedence`
3. Установленный плагин маркетплейса. Плагин каталога навыков с тем же именем получает ту же строку `Not loaded`, называя установленный плагин
4. Плагин каталога навыков. Между двумя из них копия под `~/.claude/skills/` загружается и копия проекта `.claude/skills/` отбрасывается, со строкой, которая говорит, какой путь её затенил
5. Плагин [синхронизированный с claude.ai](#synced-plugins). Когда включённый плагин из любого другого источника совпадает с его именем, Claude Code загружает этот плагин и сообщает о синхронизированной копии как не загруженной. Чтобы использовать копию claude.ai вместо этого, отключите свою собственную копию

Поскольку порядок сравнивает имена манифестов, плагин `--plugin-dir` с именем `hello-plugin` заменяет `hello@example-marketplace`, когда манифест этого плагина также говорит `"name": "hello-plugin"`.

### Хуки, когда два включённых плагина имеют одно имя

Когда вы устанавливаете и включаете два плагина с одинаковым именем манифеста из разных маркетплейсов, оба отображаются как включённые в `/plugin`, но хуки одного из них не используются. Для каждого имени только один плагин регистрирует хуки из своего `hooks/hooks.json`, и только один плагин загружает [модуль хуков](https://code.claude.com/docs/ru/plugins/mods/overview.md). Когда управляемые настройки вашей организации включают одну из копий, имя закрепляется за этой копией. В противном случае имя закрепляется за копией, которую Claude Code загружает первой.

Чтобы узнать, за какой копией закреплено имя, выполните `/plugin` в своей сессии и откройте вкладку **Errors**. Там для копии, хуки которой не используются, есть примечание с названием копии, за которой закреплено имя, и то же примечание отображается в сведениях о неиспользуемой копии. Для хуков из `hooks/hooks.json` примечание начинается с `Its hooks.json hooks do not run`, а для модуля хуков — с `Its hooks module does not load`. Примечание требует Claude Code v2.1.296 или новее.

Чтобы вместо этого запускать хуки неиспользуемой копии, отключите или удалите копию, за которой закреплено имя, затем выполните `/reload-plugins` в своей сессии. Перезагрузка регистрирует хуки оставшейся копии и убирает примечание. Если копия, за которой закреплено имя, включена вашими управляемыми настройками, вы не можете её отключить, и хуки другой копии остаются выключенными, пока установлены обе.

### Держите плагин только для сеанса от загрузки

Чтобы плагин `--plugin-dir` не затенял ничего, или чтобы отключить его, когда родительский процесс передаёт флаг для вас, установите его идентификатор в `false` в любом файле параметров. Для плагина, чьё имя манифеста — `hello-plugin`, запись — `"enabledPlugins": {"hello-plugin@inline": false}`. Отключённый плагин только для сеанса не затеняет, поэтому вместо этого загружается копия маркетплейса или каталога навыков.
