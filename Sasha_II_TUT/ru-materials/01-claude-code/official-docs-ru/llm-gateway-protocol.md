# Руководство совместимости Claude Code gateway

> Поддерживайте совместимость LLM gateway с Claude Code: конечные точки, которые он вызывает, заголовки и поля тела, которые необходимо передавать, и что перестает работать при их удалении.

На этой странице документированы запросы, которые Claude Code отправляет на шлюз, включая конечные точки, которые он вызывает, заголовки и поля тела, которые шлюз должен передавать, и какие функции перестают работать, если он этого не делает. Она написана для операторов, настраивающих продукт шлюза для работы с Claude Code.

[Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway), самостоятельно размещаемый шлюз Anthropic, предоставляет собственную справку по конечным точкам по адресу `GET /protocol`, охватывающую конечные точки входа, вывода, управляемых параметров, обнаружения модели и телеметрии этого шлюза. Это отдельный документ от этого руководства.

> [!NOTE]
>
> * Чтобы развернуть существующий или сторонний шлюз для вашей организации, см. [Развертывание LLM gateway](https://code.claude.com/docs/ru/llm-gateway-rollout.md)
> * Если вы отдельный разработчик, аутентифицирующий Claude Code на шлюзе с учетными данными, которые вам были предоставлены, см. [Подключение Claude Code к LLM gateway](https://code.claude.com/docs/ru/llm-gateway-connect.md)

На этой странице рассматривается:

* [Форматы API](#api-formats) и конечные точки для обслуживания для каждого
* [Поведение клиента по методу подключения](#how-the-connection-method-changes-client-behavior): как идентификаторы моделей, значения `anthropic-beta`, поля запроса и значения по умолчанию отличаются между форматами и входом в Claude apps gateway
* [Заголовки запроса](#request-headers): какие должны достичь вышестоящего сервера и какие может использовать ваш шлюз
* [Заголовки ответа](#response-headers): что возвращать, чтобы обнаружение зависания, повторные попытки и отображение лимита использования работали
* [Блок атрибуции системного приглашения](#system-prompt-attribution-block) и как он взаимодействует с кэшированием приглашений
* [Сквозная передача функций](#feature-pass-through): что перестает работать при удалении заголовков или полей тела
* [Обнаружение модели](#model-discovery)

На этой странице используются два термина для описания того, что ваш шлюз делает с каждым заголовком и полем тела:

* **Передавать без изменений**: передать его вышестоящему серверу побайтово
* **Использовать**: шлюз может прочитать его для маршрутизации, атрибуции или трассировки и не обязан передавать его

Все, что не отмечено как передача без изменений, вы можете использовать или игнорировать.

## Форматы API

Шлюз должен предоставлять клиентам Claude Code по крайней мере один из следующих форматов API. Клиент выбирает формат и указывает Claude Code на ваш шлюз с помощью переменных в столбце "Selected by" таблицы ниже.

Google Cloud's Agent Platform — это конечная точка Claude в Google Cloud, ранее известная как Vertex AI; названия её переменных сохраняют написание `VERTEX`.

| Формат | Selected by | Endpoints | Forward unchanged |
| :- | :- | :- | :- |
| Anthropic Messages | `ANTHROPIC_BASE_URL` | `/v1/messages`, `/v1/messages/count_tokens` (опционально) | `anthropic-beta` и `anthropic-version` заголовки запроса, а также `Authorization`, когда [вход через claude.ai](#request-headers) аутентифицирует запрос к Anthropic |
| Amazon Bedrock InvokeModel | `ANTHROPIC_BEDROCK_BASE_URL` с `CLAUDE_CODE_USE_BEDROCK=1` | `/model/{model}/invoke`, `/model/{model}/invoke-with-response-stream`, `/model/{model}/count-tokens` (опционально) | `anthropic_beta` и `anthropic_version` поля тела запроса |
| Google Cloud's Agent Platform rawPredict | `ANTHROPIC_VERTEX_BASE_URL` с `CLAUDE_CODE_USE_VERTEX=1` | `:rawPredict`, `:streamRawPredict`, `count-tokens:rawPredict` (опционально) | `anthropic-beta` и `anthropic-version` заголовки запроса, и поле `anthropic_version` в теле запроса |

### Foundry и Claude Platform on AWS

Microsoft Foundry и [Claude Platform on AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md) реализуют формат Anthropic Messages. Claude Code маршрутизирует к ним через их собственные переменные, `ANTHROPIC_FOUNDRY_BASE_URL` и `ANTHROPIC_AWS_BASE_URL`, но шлюз, находящийся перед любым из них, реализует строку Anthropic Messages выше. Шлюз, находящийся перед Claude Platform on AWS, должен также пересылать заголовок `anthropic-workspace-id`, который [эта платформа требует для каждого запроса](https://code.claude.com/docs/ru/claude-platform-on-aws.md).

### Опциональные endpoints и стартовый трафик

Endpoints подсчёта токенов — единственные опциональные: когда их нет, Claude Code переходит на оценку использования контекста на основе количества символов.

Сопоставляйте по пути, а не по полному URL:

* Запросы вывода отправляются на `/v1/messages?beta=true`
* Метод Google Cloud's Agent Platform добавляет суффиксы к пути модели издателя, как в `/projects/{project}/locations/{location}/publishers/anthropic/models/{model}:streamRawPredict`

Шлюз также видит лучший трафик при запуске, который он может отклонить без нарушения чего-либо. Шлюз формата Anthropic Messages получает зонд `HEAD /api/hello` для прогрева соединения, который Claude Code пропускает, когда настроен HTTP-прокси или сертификат клиента. Шлюз формата Amazon Bedrock получает запрос `GET /inference-profiles?type=SYSTEM_DEFINED` и, когда настроенная модель является профилем вывода, поиски `GET /inference-profiles/{profile}`.

Сессии, проходящие через шлюз, не подходят для конфигурации HIPAA. В разделе [Проверьте, как разработчики входят в систему и подключаются](https://code.claude.com/docs/ru/hipaa-setup.md#check-how-developers-sign-in-and-connect) перечислены методы входа и подключения, которые подходят. См. [Конфигурация HIPAA за шлюзом](https://code.claude.com/docs/ru/llm-gateway-rollout.md#the-hipaa-configuration-behind-a-gateway).

Проверка доступности [быстрого режима](https://code.claude.com/docs/ru/fast-mode.md) никогда не появляется в логах шлюза: она вызывает `api.anthropic.com` напрямую, а не следует `ANTHROPIC_BASE_URL`, поэтому в сети, которая блокирует прямой исходящий трафик на `api.anthropic.com`, быстрый режим может сообщить об ошибке подключения, в то время как вывод через шлюз продолжает работать. Проверка безопасности домена [WebFetch](https://code.claude.com/docs/ru/data-usage.md#webfetch-domain-safety-check) также вызывает `api.anthropic.com` напрямую. Раздел [Использование быстрого режима за прокси и шлюзами LLM](https://code.claude.com/docs/ru/fast-mode.md#use-fast-mode-behind-proxies-and-llm-gateways) охватывает переменные, которые его восстанавливают.

### Потоковая передача

Claude Code читает каждый потоковый ответ вывода событие за событием по мере его поступления, поэтому то, как ваш шлюз передаёт поток, влияет на то, что видит пользователь:

* Если ваш шлюз буферизирует ответ до его завершения, Claude Code зависает.
* Claude Code ожидает полную последовательность событий каждого ответа, по порядку, вплоть до финальных событий `message_delta` и `message_stop`. Если тело завершается чисто после начала блока контента, но до этого финального `message_delta`, Claude Code рассматривает ответ как разорванное соединение. [The response above may be incomplete](https://code.claude.com/docs/ru/errors.md#the-response-above-may-be-incomplete) описывает, что в этом случае видит пользователь, а раздел [Автоматические повторные попытки](https://code.claude.com/docs/ru/errors.md#automatic-retries) — когда Claude Code вместо этого повторно отправляет запрос.
* Когда guardrail Amazon Bedrock блокирует ответ, события, которые отправляет Bedrock, могут ссылаться на блок контента, чей `content_block_stop` уже прибыл, и Claude Code рассчитывает получить их в том виде, в каком они были отправлены. [AWS Guardrails](https://code.claude.com/docs/ru/amazon-bedrock.md#aws-guardrails) описывает, как завершается такой ответ.
* Claude Code прерывает потоковый ответ, как только на него не поступают байты дольше, чем его [таймаут простоя потоковой передачи](https://code.claude.com/docs/ru/network-config.md#streaming-idle-watchdogs). Во время длительной паузы мышления SSE-события `ping` вышестоящего сервера могут быть единственными байтами в потоке, поэтому шлюз, который удаляет или буферизирует их, может вызвать срабатывание этого таймаута посреди ответа. У шлюза, который выполняет преобразование с вышестоящего сервера без пингов, такого как двоичный поток событий Amazon Bedrock, возникает тот же пробел, если только он не выдаёт собственные события `ping`.
* В [формате Amazon Bedrock InvokeModel](#api-formats) Claude Code читает ответ `/model/{model}/invoke-with-response-stream` как двоичное тело `application/vnd.amazon.eventstream`, которое возвращает Bedrock, и не может его разобрать, если шлюз преобразует его в server-sent events или переписывает этот заголовок `Content-Type`. Раздел [Ошибки потоковой передачи за шлюзом или прокси](https://code.claude.com/docs/ru/amazon-bedrock.md#streaming-errors-behind-a-gateway-or-proxy) описывает, что в этом случае видит пользователь.

### Несоответствие формата с вышестоящим сервером

Какой формат использует клиент, определяет, что получает ваш шлюз. Распространённый режим отказа — несоответствие между форматом, который клиент отправляет вашему шлюзу, и форматом, который принимает вышестоящий поставщик позади него.

* Когда клиент использует формат Amazon Bedrock или Google Cloud's Agent Platform, Claude Code отправляет только подмножество своего полного набора возможностей, которое эти поставщики принимают
* Когда клиент использует формат Anthropic Messages, Claude Code отправляет полный набор, даже если ваш шлюз пересылает на вышестоящий сервер Amazon Bedrock или Google Cloud's Agent Platform

Преодоление этого различия — задача вашего шлюза. [Сквозная передача функций](#feature-pass-through) описывает, что ломается, когда это не происходит.

Если ваш вышестоящий сервер — Amazon Bedrock или Google Cloud's Agent Platform, вы можете избежать преодоления, предоставив вместо этого формат этого поставщика. [Маршрутизация к облачному поставщику через шлюз](https://code.claude.com/docs/ru/llm-gateway-connect.md#route-to-a-cloud-provider-through-a-gateway) показывает конфигурацию клиента для этого формата.

## Как метод подключения изменяет поведение клиента

Способ подключения разработчика к вашему шлюзу определяет, какие ID моделей, значения `anthropic-beta` и поля запроса отправляет Claude Code, а также какие значения по умолчанию он применяет. Ваш шлюз видит одно из трёх поведений клиента:

* **Формат Amazon Bedrock или Agent Platform**: разработчик устанавливает `CLAUDE_CODE_USE_BEDROCK=1` с `ANTHROPIC_BEDROCK_BASE_URL` или `CLAUDE_CODE_USE_VERTEX=1` с `ANTHROPIC_VERTEX_BASE_URL`, указывающие на ваш шлюз. Claude Code использует ID моделей этого поставщика, поля запроса и значения по умолчанию.
* **Формат Anthropic Messages**: разработчик устанавливает `ANTHROPIC_BASE_URL` на ваш шлюз. Claude Code рассматривает шлюз как Claude API и не может определить, на какой upstream вы перенаправляете.
* **Вход в шлюз Claude apps**: разработчик входит в [шлюз Claude apps](https://code.claude.com/docs/ru/claude-apps-gateway). Этот шлюз использует формат Anthropic Messages, но может маршрутизировать на любой upstream, поэтому Claude Code отправляет только значения `anthropic-beta` и предположения о возможностях модели, которые также принимают Amazon Bedrock и Agent Platform.

Для них см. страницы [Microsoft Foundry](https://code.claude.com/docs/ru/microsoft-foundry.md) и [Claude Platform на AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md).

| Поля запроса для ID модели, которую Claude Code не распознаёт, например alias шлюза | Мышление с фиксированным бюджетом вместо адаптивного рассуждения, и без полей управления усилиями или контекстом. ### Параметры для нераспознанных ID моделей

Два параметра на стороне клиента изменяют то, что Claude Code предполагает для ID модели, которую он не распознаёт, независимо от того, какой метод подключения использует разработчик:

* **Контекстное окно**: начиная с v2.1.323 Claude Code по умолчанию предполагает контекстное окно размером 1M токенов. Чтобы объявить реальное окно, см. [Исправьте окно для шлюза или пользовательского ID модели](https://code.claude.com/docs/ru/model-config.md#correct-the-window-for-a-gateway-or-custom-model-id)
* **Возможности**: чтобы дать alias шлюза возможности модели позади него, сопоставьте ID Anthropic этой модели с вашим alias с помощью записи [`modelOverrides`](https://code.claude.com/docs/ru/errors#unrecognized-model-id-on-a-request) в параметрах, которые вы распространяете. Для того, где применяются переменные `ANTHROPIC_DEFAULT_*_MODEL_SUPPORTED_CAPABILITIES`, см. [передача функций](#feature-pass-through)

## Заголовки запроса

Claude Code включает эти заголовки в запросы API. Имена заголовков не чувствительны к регистру на проводе. Пересылайте `anthropic-version` и `anthropic-beta` без изменений, плюс `anthropic-workspace-id`, когда upstream — это [Claude Platform on AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md). Также пересылайте `Authorization`, когда ваш шлюз аутентифицируется в Anthropic с помощью входа разработчика в claude.ai, а не собственного ключа. Остальное шлюз может использовать для маршрутизации, атрибуции и трассировки и не обязан пересылать.

| Заголовок | Описание |
| :- | :- |
| `Authorization`, `x-api-key` | Учётные данные шлюза разработчика, в одном или обоих заголовках в зависимости от того, какую [переменную учётных данных](https://code.claude.com/docs/ru/llm-gateway-connect.md#set-the-credential-variable) они установили. При входе в claude.ai без учётных данных шлюза `Authorization` содержит токен этого входа |
| `anthropic-version` | Версия API, в настоящее время `2023-06-01`. Запросы формата Amazon Bedrock и Google Cloud's Agent Platform также содержат поле тела `anthropic_version`, значение которого — строка диалекта поставщика, а не значение этого заголовка |
| `anthropic-beta` | Значения возможностей, разделенные запятыми, для запроса. Пересылайте заголовок дословно; не создавайте список разрешений отдельных значений, потому что набор изменяется с выпусками Claude Code. Когда разработчик аутентифицируется с помощью входа claude.ai, что возможно, когда `ANTHROPIC_BASE_URL` установлен без переменной учетных данных gateway, этот заголовок также содержит возможность OAuth, которую требует upstream, и удаление его приводит к отказу этих запросов с `401` |
| `x-claude-code-session-id` | Уникальный идентификатор текущего сеанса Claude Code. Используйте его для агрегирования всех запросов из одного сеанса без анализа тел запросов |
| `x-claude-code-agent-id` | Идентификатор [подагента](https://code.claude.com/docs/ru/sub-agents.md), который выдал запрос, присутствует только в запросах от агента, порожденного Claude Code внутри сеанса. Используйте его с идентификатором сеанса для отнесения затрат к параллельным агентам |
| `x-claude-code-parent-agent-id` | Идентификатор агента, который породил запрашивающего агента, присутствует только для вложенных агентов |

Идентификаторы подагентов генерируются заново для каждого порождения. Агенты товарищей, названные члены [команды агентов](https://code.claude.com/docs/ru/agent-teams.md), повторно используют стабильный идентификатор на основе имени при переподключениях. В обоих случаях идентификатор идентифицирует агента, а не человека или устройство, поэтому не рассматривайте заголовок идентификатора агента как идентификатор пользователя.

Если ваши разработчики установили `ANTHROPIC_CUSTOM_HEADERS`, эти заголовки также появляются в запросах.

### Заголовки подсказок Gateway

Claude Code также может отправлять подсказки маршрутизации: факты для каждого запроса, которые gateway или маршрутизатор может использовать для планирования, кэширования или отнесения запроса. Требуется Claude Code v2.1.273 или позже.

Наличие их в запросе зависит от того, куда Claude Code его отправляет:

* Прямое подключение к API Anthropic: отправляются по умолчанию
* Пользовательский базовый URL: отключено по умолчанию, потому что прокси, который отклоняет неизвестные заголовки, приведет к отказу запроса. Чтобы их получить, установите [`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`](https://code.claude.com/docs/ru/env-vars) для ваших разработчиков, например в блоке `env` [управляемых параметров](https://code.claude.com/docs/ru/managed-settings.md)
* Любой другой backend, включая Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry и Claude Platform on AWS: отправляются только когда установлено `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`

Установка `CLAUDE_CODE_GATEWAY_HINT_HEADERS` на `0` останавливает заголовки на каждом подключении.

Заголовки содержат только то, что указано в строках ниже: фиксированные словари, имена инструментов, длительности и случайный идентификатор подсказки, никогда текст подсказки или содержимое файлов. Каждое значение — это печатаемый ASCII.

| Заголовок | Описание |
| :- | :- |
| `x-claude-code-request-class` | Какой тип запроса это: `main` для хода основного разговора, `subagent` для хода [подагента](https://code.claude.com/docs/ru/sub-agents.md), `workflow` для агента, работающего внутри workflow, `compaction` для запроса суммирования, который компактирует разговор, или `auxiliary` для побочных запросов, таких как названия сеансов, классификаторы и резюме. Отправляется на каждом запросе |
| `x-claude-code-agent-type` | Тип подагента, который выдал запрос: встроенное имя типа агента, такое как `Explore`, `Plan` или `general-purpose`, или `custom` для определяемого пользователем агента, `teammate` для члена [команды агентов](https://code.claude.com/docs/ru/agent-teams.md), работающего в процессе лидера, или `fork` для [ветвления](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation) текущего разговора. Присутствует только на собственных ходах подагента; запросы компактирования или побочные запросы подагента сохраняют идентификатор агента, но не содержат тип. Имя агента, выбранное пользователем, никогда не отправляется |
| `x-claude-code-compaction` | Присутствует в запросе, который суммирует диалог во время [сжатия контекста](https://code.claude.com/docs/ru/prompt-caching.md#compacting-the-conversation). Значение указывает, что его вызвало: `auto`, когда контекстное окно приближалось к заполнению, `manual` для `/compact` или `reactive`, когда API отклонил запрос как слишком длинный. Значение также равно `auto` для [сжатия при простое](https://code.claude.com/docs/ru/settings-reference.md#idlecompaction) в интерактивной сессии терминала. Отсутствует во всех остальных запросах, включая запрос, который записывает резюме в фоновом режиме перед сжатием контекста |
| `x-claude-code-context-compacted` | Присутствует один раз, на первом запросе основного разговора после компактирования, с теми же значениями, что и `x-claude-code-compaction`. Префикс разговора перед этим запросом больше не используется, поэтому кэш, основанный на нем, может быть удален |
| `x-claude-code-prev-tool-durations` | Измеренное время выполнения вызовов инструментов, результаты которых содержит этот запрос, как `<name>=<ms>;<name>=<ms>`, например `Bash=742;Read=9`. Отправляется на следующем запросе того же разговора после пакета вызовов инструментов, из основного сеанса или подагента |
| `x-claude-code-prompt-id` | Случайный UUID, который идентифицирует пользовательскую подсказку, которой служит запрос. Запросы, служащие одной подсказке, делят значение, включая ходы подагентов, которые подсказка запустила. Запросы, не отнесенные к подсказке, его опускают. Используйте его для группировки запросов сеанса по подсказке. Требуется Claude Code v2.1.283 или позже |

Перед анализом `x-claude-code-prev-tool-durations` проверьте, как Claude Code строит значение и что оно опускает:

* Записи: одна на каждый выполненный вызов инструмента, в порядке сбора его результата, в целых миллисекундах
* Ограничение: Claude Code отправляет максимум 32 записи и 4 КБ, сохраняя первые записи
* Кодирование: имена инструментов кодируются в процентах, охватывая `%`, `;`, `=`, запятую, пробел и любой символ вне печатаемого ASCII
* Анализ: разделите на `;`, затем на `=`, и декодируйте каждое имя
* Отсутствие: вызовы компактирования, побочные запросы и первый запрос нового подсказки никогда его не содержат. Не читайте отсутствующий заголовок как ход, который не запустил никакие инструменты
* Времена: каждое исключает подсказки разрешения и hooks, и параллельные вызовы инструментов каждый сообщают свое собственное время, поэтому записи не складываются в промежуток между запросами

### Пересылка как открытые списки

Рассматривайте заголовки и поля тела как открытые списки, а не закрытые. Claude Code получает возможности в выпусках, и они поступают как новые значения `anthropic-beta`, новые поля тела запроса и иногда новые заголовки `anthropic-*` или `x-claude-code-*`.

При пересылке на upstream формата Anthropic пропускайте заголовки запроса `anthropic-*` и поля тела запроса без изменений, а не создавайте список разрешений видимых вами сегодня. Gateway, привязанный к наблюдаемому списку, удаляет заголовок или поле следующей возможности и ломает его при выпуске, который его вводит.

Исключением является upstream, не относящийся к Anthropic, такой как Amazon Bedrock или Google Cloud's Agent Platform, где преодоление различия схемы — задача gateway; см. [сквозная передача функций](#feature-pass-through).

## Заголовки ответов

Claude Code читает эти заголовки ответов для обнаружения зависших потоков, чтобы решить, следует ли и когда повторить попытку, а также для отображения лимитов использования. В таблице указано, что возвращать для каждого. Также пропускайте тела ответов об ошибках без изменений, чтобы [восстановление при отклонении возможностей](#automatic-retry-and-error-forwarding) Claude Code могло соответствовать формулировке ошибки вышестоящего сервера.

| Заголовок | Что возвращать и почему |
| :- | :- |
| `content-type` | Возвращайте `text/event-stream` для потоковых ответов в формате Anthropic Messages и `application/vnd.amazon.eventstream` без изменений для ответов в формате Amazon Bedrock, где [другой тип приводит к сбою запроса](https://code.claude.com/docs/ru/amazon-bedrock.md#streaming-errors-behind-a-gateway-or-proxy) |
| `retry-after` | Возвращайте целое число секунд вместо даты HTTP. Claude Code ждет по крайней мере столько времени перед следующей [автоматической повторной попыткой](https://code.claude.com/docs/ru/errors.md#automatic-retries), и вне сеансов [`CLAUDE_CODE_RETRY_WATCHDOG`](https://code.claude.com/docs/ru/env-vars) значение выше 60 останавливает повторные попытки и показывает ошибку сразу же |
| `x-should-retry` | Пропускайте значение вышестоящего сервера без изменений. Claude Code читает этот заголовок как один из входных данных при решении о повторной попытке неудачного запроса: `true` отмечает ответ как подлежащий повторной попытке, а `false` отмечает его как не подлежащий повторной попытке. Для количества повторных попыток, отката и того, какие сбои Claude Code повторяет, см. [автоматические повторные попытки](https://code.claude.com/docs/ru/errors.md#automatic-retries) |
| `anthropic-ratelimit-unified-*` | Пропускайте значения вышестоящего сервера без изменений при каждом ответе. Claude Code читает их при успешных ответах для отображения использования в соответствии с лимитами плана разработчикам, вошедшим в систему с помощью claude.ai, и при `429` для различения лимита плана или лимита расходов от временного дросселирования; см. [лимиты использования](https://code.claude.com/docs/ru/errors.md#usage-limits) |

## Блок атрибуции системного приглашения

Claude Code добавляет в начало системного приглашения короткий блок атрибуции, содержащий версию клиента и отпечаток, полученный из разговора. Конечная точка `api.anthropic.com` удаляет блок перед обработкой, когда он поступает без изменений в качестве первого системного блока, поэтому он не влияет на кеширование приглашений первой стороны. Любой другой upstream получает его как часть приглашения.

Удаление является позиционным, поэтому оно работает только тогда, когда шлюз пересылает массив `system` без изменений. Чтобы исключить блок из приглашения без потери другого системного содержимого:

* Пересылайте массив `system` точно так, как он был получен, сохраняя блок первым: добавление другого системного блока в начало, переупорядочение массива или преобразование его в одну строку нарушает удаление, и блок затем достигает модели и ключа кеша приглашений.
* Сохраняйте блок в собственной записи массива: конечная точка рассматривает объединённый блок, который начинается с заголовка атрибуции, как атрибуцию в целом и удаляет всё объединённое в него, включая остальную часть системного приглашения.
* Если ваш шлюз должен переформатировать системное содержимое, установите [`CLAUDE_CODE_ATTRIBUTION_HEADER=0`](https://code.claude.com/docs/ru/env-vars), чтобы Claude Code опустил блок. Anthropic и конечные точки Claude облачных поставщиков читают блок для атрибуции, поэтому опустите его на клиенте, а не удаляйте или перемещайте его в шлюзе.

Переменная существует для совместимости с шлюзом и кешированием третьей стороны, а не как элемент управления конфиденциальностью: при прямом подключении полный запрос в любом случае поступает в API Anthropic. Когда оба из этих условий выполняются, Claude Code сохраняет блок в запросах классификатора [режима автоматического выбора](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) даже когда вы устанавливаете переменную на `0`:

* Запросы поступают на `api.anthropic.com`, с `ANTHROPIC_BASE_URL` не установленной или указывающей на этот хост, и ни один поставщик третьей стороны не выбран.
* Активные учётные данные не являются [профилем Anthropic или учётными данными федерации](https://code.claude.com/docs/ru/authentication.md#anthropic-profiles-and-federation-credentials).

Запросы классификатора пропускают остальную часть системного приглашения Claude Code, поэтому на этих запросах блок является единственным маркером в теле запроса, который идентифицирует их как трафик Claude Code. Когда любое из условий не выполняется, через шлюз LLM, у поставщика третьей стороны или с активным профилем или учётными данными федерации, установка `0` удаляет блок из запросов классификатора также. До версии v2.1.229 это исключение не существовало: установка `0` удаляла блок из этих запросов классификатора, и когда API отклонял неидентифицированные запросы, режим автоматического выбора не работал на каждом действии, которое он отправлял классификатору.

Начиная с Claude Code v2.1.181, блок стабилен в течение всего времени жизни разговора, когда запросы маршрутизируются через пользовательский базовый URL, поэтому кеш приглашений на стороне шлюза, использующий ключ на основе полного тела запроса, работает без отключения его, и любой поставщик, на которого ваш шлюз пересылает запросы, получает стабильный префикс приглашения. До версии v2.1.181 блок включал токен для каждого запроса, который изменял начало системного приглашения при каждом запросе. На этих версиях установите `CLAUDE_CODE_ATTRIBUTION_HEADER=0`, когда ваш шлюз выполняет любое из этих действий:

* Реализует кеш приглашений, использующий ключ на основе тела запроса.
* Пересылает запросы поставщику третьей стороны, такому как Amazon Bedrock, Microsoft Foundry или Google Cloud's Agent Platform, в формате Anthropic Messages или в собственном формате поставщика, где изменяющийся префикс снижает повторное использование кеша приглашений у этого поставщика.

## Сквозная передача функций

Claude Code рассматривает шлюз `ANTHROPIC_BASE_URL` как конечную точку в формате Anthropic и отправляет ему бета-заголовки и поля тела запроса, которые он отправляет на `api.anthropic.com`, за исключением небольшого набора диагностики и значений по умолчанию, зарезервированных для прямых соединений, таких как значение по умолчанию для потоковой передачи инструментов с точной настройкой, описанное ниже. Этот набор варьируется в зависимости от версии, поэтому не полагайтесь на его содержимое.

Потоковая передача инструментов с точной настройкой — это одно из значений по умолчанию для прямого соединения: она отключена по умолчанию всякий раз, когда запросы маршрутизируются через пользовательский базовый URL, и шлюз получает ее, когда разработчики устанавливают [`CLAUDE_CODE_ENABLE_FINE_GRAINED_TOOL_STREAMING=1`](https://code.claude.com/docs/ru/env-vars).

### Пары бета-заголовков и полей тела

Возможности, которые добавляют поля тела, связывают их с бета-заголовком, и эта пара передается вместе. Шлюз, который удаляет заголовок при передаче тела или пересылает тело в формате Anthropic на вышестоящий сервер с другой схемой, вызывает ошибки `400`.

Шлюз, который переписывает или редактирует тела запросов для проверки содержимого, нарушает связь так же, как это делает удаление, поэтому проверяйте без изменений. В таблице указано, где функция отклоняется от связи.

| Функция | Бета-заголовок и пара тела | Симптом при нарушении | Исправление |
| :- | :- | :- | :- |
| [Адаптивное рассуждение](https://code.claude.com/docs/ru/model-config.md#adjust-effort-level) | Нет бета-заголовка. Claude Code отправляет `thinking: {"type": "adaptive"}` для Claude Opus 4.6, Claude Sonnet 4.6, Claude Haiku 5.5, Claude Fable 5 и более поздних моделей и рассматривает имена моделей, которые он не распознает, такие как псевдонимы шлюза, как текущие модели, которые получают это поле | Ошибка `400`, указывающая на поле `thinking` или тег `adaptive`, когда сборка вышестоящей модели его не принимает | Обновите вышестоящий сервер. На Opus 4.6 и Sonnet 4.6 разработчики могут вместо этого установить `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1` |
| [Управление контекстом](https://platform.claude.com/docs/en/build-with-claude/context-editing) | Бета-заголовок управления контекстом связан с полем тела `context_management` | Ошибка `400` с сообщением `Extra inputs are not permitted`. Часто встречается, когда шлюз принимает запросы в формате Anthropic, но пересылает их на Amazon Bedrock. В версии v2.1.304 или более поздней Claude Code [самостоятельно повторяет попытку без этой пары](#automatic-retry-and-error-forwarding) | Пересылайте оба, или [`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`](#disable-pre-release-capabilities) |
| [Расширенный контекст](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-sizes-by-model) и [чередующееся мышление](https://platform.claude.com/docs/en/build-with-claude/extended-thinking#interleaved-thinking) | Только бета-заголовки, нет поля тела | Молча недоступно, когда заголовок удален; вышестоящий сервер никогда не видит запрос возможности | Пересылайте `anthropic-beta` без изменений |
| Бета [поля инструментов](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) | Связанные с инструментами бета-заголовки связаны с полями схемы инструментов, такими как `strict` и `defer_loading` | Ошибка `400`, указывающая на неизвестное поле схемы инструмента, когда тело проходит без своего заголовка. Для `defer_loading` см. [Повторная попытка без поиска инструментов](#retry-without-tool-search) | Пересылайте оба, или [`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`](#disable-pre-release-capabilities) |
| [Усилие](https://platform.claude.com/docs/en/build-with-claude/effort) и [структурированные выходные данные](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) | Поле тела `output_config` содержит настройки усилия, формата структурированного вывода и бюджета задачи; каждая связана с собственным бета-заголовком | Ошибка `400`, указывающая на `output_config`, часто `Extra inputs are not permitted`, на вышестоящих серверах Amazon Bedrock и Google Cloud's Agent Platform | Пересылайте поле и его заголовки вместе или попросите разработчиков установить [`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`](#disable-pre-release-capabilities), что удаляет настройки формата и бюджета задачи, но не усилия. Чтобы удалить только формат, они могут вместо этого установить [`CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS=1`](https://code.claude.com/docs/ru/env-vars), для чего требуется v2.1.288 или более поздняя версия |
| Системные сообщения в середине диалога | Нет бета-заголовка. Claude Code отправляет часть текста напоминаний и вложений как записи `role: "system"` в `messages` для Claude Opus 4.8, моделей, выпущенных после нее, и нераспознанных идентификаторов моделей | Ошибка `400`, например `Unexpected role "system"` | Claude Code [повторяет попытку без системных сообщений](#automatic-retry-and-error-forwarding). Чтобы прекратить отправку системных сообщений для псевдонима модели, выпущенной до Claude Opus 4.8, добавьте [запись `modelOverrides`](#settings-for-unrecognized-model-ids) в распространяемые вами настройки |
| [Усилие, заданное для отдельного хода](https://code.claude.com/docs/ru/prompt-caching.md#changing-effort-level) | На Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.2 и Fable 5.1 бета-заголовок связан с `output_config.effort` в записях `role: "system"`. Такая запись — это системное сообщение или запись с пустым содержимым | Ошибка `400` с сообщением `messages.N: system content must contain at least one block`, когда ваш шлюз удаляет это поле из пустой записи | Пересылайте оба или попросите разработчиков установить [`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`](#disable-pre-release-capabilities), чтобы прекратить отправку этого поля и пустых записей |
| [Кэширование подсказок](https://code.claude.com/docs/ru/prompt-caching.md) | Нет бета-связи. Claude Code прикрепляет маркеры `cache_control` к блокам `system` и записям `messages`, включая записи `role: "system"`, добавленные в середину разговора | Нет ошибки: разговор выставляется как некэшированный ввод на каждом ходу, видимый как высокие `input_tokens` с небольшой или отсутствующей активностью кэша в `usage` | Пересылайте `cache_control` без изменений везде, где он появляется, и не преобразуйте блочную форму `system` или содержимое сообщения в простые строки |
| [Подсчет токенов](https://platform.claude.com/docs/en/build-with-claude/token-counting) | Нет бета-связи; использует конечную точку `count_tokens` | Нет ошибки: Claude Code возвращается к оценке на основе символов, поэтому `/context` показывает приблизительные подсчеты | Предоставьте конечную точку для точного подсчета токенов |

Переменные `ANTHROPIC_DEFAULT_*_MODEL_SUPPORTED_CAPABILITIES` [объявляют](https://code.claude.com/docs/ru/model-config.md) возможности модели только в конфигурациях поставщика: `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY` и [`CLAUDE_CODE_USE_MANTLE`](https://code.claude.com/docs/ru/amazon-bedrock#use-the-mantle-endpoint). Они не имеют никакого эффекта за шлюзом `ANTHROPIC_BASE_URL`.

### Автоматический повтор и пересылка ошибок

Когда вышестоящий сервер отклоняет одну из этих возможностей, Claude Code может самостоятельно повторить запрос, удалив или изменив отклоненную часть:

* Когда ошибка `400` сообщает, что значение `thinking.type` `enabled` или `adaptive` не поддерживается, Claude Code один раз повторяет попытку с другим типом и сохраняет поле `thinking`. Последующие запросы к этой модели используют измененный тип до выхода из Claude Code. До версии v2.1.121 Claude Code не повторял попытку, поэтому ошибка [`thinking.type.enabled is not supported`](https://code.claude.com/docs/ru/errors#thinking-type-enabled-is-not-supported-for-this-model) доходила до разработчика
* Когда вышестоящий сервер отклоняет запись `role: "system"` внутри `messages`, Claude Code один раз повторяет попытку без этих системных сообщений в середине диалога и вместо этого передает их текст в пользовательских сообщениях. Последующие запросы в диалоге сохраняют эту форму, пока разработчик не выполнит `/clear` или диалог не будет сжат
* Когда вышестоящий сервер отклоняет только маркер `cache_control` на системном сообщении в середине диалога, Claude Code сохраняет системные сообщения и один раз повторяет попытку с перемещенным маркером. Маркер ставится на последнюю запись в `messages`, которая не является системным сообщением, — в этой повторной попытке и в последующих запросах до выхода из Claude Code
* Когда вышестоящий сервер отклоняет [подпись мышления](https://platform.claude.com/docs/en/build-with-claude/extended-thinking), включая ошибку `400`, сообщение которой говорит, что блок `bound to a different conversation`, Claude Code удаляет более ранние блоки мышления из запроса, повторяет и исключает их из каждого последующего запроса. Новые ответы по-прежнему включают мышление
* Когда шлюз или его вышестоящий сервер отклоняет запись [инструмента-советника](https://code.claude.com/docs/ru/advisor.md) в `tools` как неизвестный тип инструмента, Claude Code повторяет запрос один раз без этой записи и ее значения `anthropic-beta`. [Последующие запросы](#how-long-a-rejected-beta-value-stays-out) их не содержат. Claude Code распознает это отклонение по ответу `400` или `422`, сообщение которого называет тип инструмента после `Input tag`, например `Input tag 'advisor_20260301'`. До версии v2.1.280 Claude Code не повторял попытку при этом отклонении
* Когда вышестоящий сервер отклоняет `output_config.effort` или его значение `anthropic-beta`, шлюз получает запрос еще раз без них. [Последующие запросы](#how-long-a-rejected-beta-value-stays-out) их не содержат. Вашему шлюзу не нужны изменения, если он пересылает ошибку `400` вышестоящего сервера без изменений, а ее сообщение:
  * Называет `output_config.effort` вместе с `Extra inputs are not permitted`
  * Сообщает, что модель не поддерживает параметр effort
  * Начинается с `Unexpected value(s)` и указывает `effort-2025-11-24` для заголовка `anthropic-beta`. Требуется v2.1.310 или более поздняя версия. Разработчики, у которых [`ANTHROPIC_BETAS`](https://code.claude.com/docs/ru/env-vars) содержит это значение, продолжают его отправлять и получать ошибку `400`, поэтому попросите их удалить эту запись
* Когда вышестоящий сервер отклоняет поле `context_management` или его значение `anthropic-beta`, шлюз получает запрос еще раз без них. [Последующие запросы](#how-long-a-rejected-beta-value-stays-out) их не содержат. Claude Code распознает это отклонение по его сообщению, например содержащему `context_management: Extra inputs are not permitted`. До версии v2.1.304 Claude Code не повторял попытку при этом отклонении
* Когда ошибка `400` отклоняет по имени другое значение `anthropic-beta`, шлюз получает запрос еще раз без него, если [повторная попытка распространяется на это значение](#retry-without-a-rejected-beta-value)
* Когда вышестоящий сервер отклоняет бета-поле инструмента, отличное от `defer_loading`, например `strict`, ошибка `400` доходит до разработчика. Перед этим шлюз может снова получить запрос [без полей поиска инструментов](#retry-without-tool-search). Чтобы прекратить отправку таких полей, попросите разработчиков установить [`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`](#disable-pre-release-capabilities)

Отклонение `bound to a different conversation` поступает из проверки [сохраненного мышления](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) API, которая не срабатывает, когда содержимое `system`, `tools` или более ранних `messages` отличается от запроса, который создал мышление. Шлюз, который переписывает любое из этого содержимого, может вызвать само отклонение; [Libraries, proxies, and gateways](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking#libraries-proxies-gateways) охватывает то, что нужно пересылать без изменений.

Большая часть этой логики повторных попыток ориентируется на формулировку ошибки вышестоящего сервера, поэтому пересылайте тела ответов об ошибках без изменений. Шлюз, который оборачивает ошибки вышестоящего сервера в свой собственный конверт, нарушает путь восстановления, даже если он сохраняет код состояния, если только сообщение конверта не содержит стабильный токен `capability_rejected:`. [Claude apps gateway подставляет эти токены вместо формулировок ошибок облачных поставщиков](https://code.claude.com/docs/ru/claude-apps-gateway-config.md#upstream-error-messages), например `capability_rejected: prompt_too_long`.

#### Повторная попытка без отклоненного бета-значения

Когда ошибка `400` отклоняет по имени значение `anthropic-beta`, на которое распространяется эта повторная попытка, шлюз получает запрос еще раз без него. [Последующие запросы](#how-long-a-rejected-beta-value-stays-out) не содержат это значение. Для большинства охватываемых значений требуется v2.1.314 или более поздняя версия.

Вашему шлюзу не нужны изменения, если сообщение возвращаемой им ошибки `400` содержит значение в одной из следующих форм:

* **Предложение API**: предложение `Unexpected value(s)`, в котором указано значение для заголовка `anthropic-beta`
* **Токен `beta_header:`**: `capability_rejected: beta_header:`, за которым следует значение, — [токен `capability_rejected:`](#automatic-retry-and-error-forwarding)

Повторная попытка не охватывает такие случаи, как значение с собственной повторной попыткой, значение, которое Claude Code не распознает, или сообщение, в котором не указано никакого значения:

* **Значение с собственной повторной попыткой, например советник или поиск инструментов**: шлюз вместо этого видит [собственную повторную попытку этой возможности](#automatic-retry-and-error-forwarding)
* **Значение, которое Claude Code не распознает**: значение, заданное разработчиком через `ANTHROPIC_BETAS`, остается в каждом запросе, поэтому запросы разработчика продолжают завершаться ошибкой `400`. Попросите разработчика удалить эту запись
* **Сообщение, содержащее только `invalid beta flag`**: Claude Code предполагает, какое значение отклонил вышестоящий сервер. Если запрос содержал одно из предполагаемых значений, шлюз снова получает запрос без этого значения. Если ошибка `400` все равно доходит до разработчика, сделайте так, чтобы ваш шлюз указывал отклоненное значение в одной из этих форм

#### Как долго отклоненное бета-значение не отправляется

| Что отклонил вышестоящий сервер | Запросы, в которых оно не передается | До какого момента |
| :- | :- | :- |
| Тип инструмента-советника или значение `anthropic-beta` советника | Запросы к тому же базовому URL. `/advisor` недоступен | Выход из Claude Code |
| `output_config.effort` или его значение `anthropic-beta` | Запросы к той же модели | Выход из Claude Code |
| `context_management` или другое значение `anthropic-beta`, на которое распространяется [повторная попытка по имени](#retry-without-a-rejected-beta-value) | Запросы в том же диалоге | Завершение диалога или пересборка промпта Claude Code, например при сжатии основного диалога |
| `context_management` или другое значение, на которое распространяется эта повторная попытка, когда сообщение об ошибке начинается с собственного предложения API об отклонении, например `Unexpected value(s)`, или содержит токен `beta_header:` | Также новые диалоги с моделью, указанной в отклоненном запросе, в том числе после `/clear` | Выход из Claude Code |

#### Повторная попытка без поиска инструментов

В версии v2.1.305 или более поздней Claude Code повторно отправляет запрос без [полей `defer_loading` и блоков `tool_reference`](https://code.claude.com/docs/ru/mcp#tool-search-through-a-gateway) после ошибки `400` или `422`, в которой упоминается поиск инструментов или причину которой он не распознает. После успешной повторной попытки последующие запросы в этом диалоге также их не содержат.

Запросы разработчика продолжают работать без каких-либо изменений на шлюзе, а их инструменты MCP загружаются заранее. Когда Claude Code снова пытается использовать поиск инструментов, шлюз может видеть ещё один отклонённый запрос, за которым следует его повторная попытка. Для самого поиска инструментов Claude Code ожидает, что шлюз будет пересылать поля `defer_loading` и блоки `tool_reference` вместе с их значением `anthropic-beta`.

### Отключение предварительных возможностей

Если ваш шлюз или его вышестоящий сервер отклоняет предварительные значения `anthropic-beta` или связанные с ними поля тела и вы не можете пересылать обе части, попросите разработчиков установить `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`. Когда эта переменная установлена, Claude Code перестает отправлять предварительные возможности и связанные с ними значения `anthropic-beta`, включая:

* Управление контекстом и его поле тела `context_management`
* Бета-поля схемы инструментов, такие как `strict` и `defer_loading`. Стандартные поля инструментов `name`, `description`, `input_schema` и `cache_control` сохраняются
* Поле структурированного вывода `output_config.format`. Требуется Claude Code v2.1.287 или более поздней версии
* Поле `output_config.task_budget`
* [MCP Tool Search](https://code.claude.com/docs/ru/mcp.md#scale-with-mcp-tool-search), поэтому все инструменты MCP загружаются заранее, если только ваша организация не оставляет эту функцию включенной через управляемые настройки

Переменная удаляет не все значения `anthropic-beta`. Среди того, что она оставляет:

* Значения `anthropic-beta` для расширенного контекста, чередующегося мышления и усилия, которые также принимают облачные поставщики
* Поле верхнего уровня `output_config.effort`. В разделе [Автоматические повторные попытки и пересылка ошибок](#automatic-retry-and-error-forwarding) описан случай, когда вышестоящий сервер его отклоняет
* Поле `thinking` адаптивного рассуждения, у которого нет бета-заголовка
* Записи `role: "system"`, которые содержат [системные сообщения в середине диалога](#feature-pass-through)
* Значение `anthropic-beta` и поле `safeguards` для [серверной проверки классификатором](https://code.claude.com/docs/ru/permission-modes.md#server-side-classifier-review) в авторежиме — в сессиях, где эта проверка остается включенной, например когда `/status` показывает **Auto mode server** как `Enabled`. Чтобы отключить проверку, установите `CLAUDE_CODE_AUTO_MODE_SERVER=0` перед запуском сессии. После этого в терминале `/status` показывает **Auto mode server** как `Disabled`.
* Значение `anthropic-beta` для OAuth, которое требуется для аутентификации по подписке
* Значения заголовков и поля тела, которые разработчики добавляют сами через [`ANTHROPIC_BETAS`](https://code.claude.com/docs/ru/env-vars) или [`CLAUDE_CODE_EXTRA_BODY`](https://code.claude.com/docs/ru/env-vars)

Когда хост-платформа, которая встраивает Claude Code, устанавливает [`CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`](https://code.claude.com/docs/ru/env-vars), `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` не останавливает сеансы автоматического режима на Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry или [Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway) от запроса к серверу [проверки классификатора](https://code.claude.com/docs/ru/permission-modes.md#server-side-classifier-review). Эта проверка добавляет значение `anthropic-beta` и поле запроса `safeguards`. Установите `CLAUDE_CODE_AUTO_MODE_SERVER=0`, чтобы остановить это там.

На Claude Code v2.1.227 или более поздней версии ваша организация может сохранить [поиск инструментов MCP](https://code.claude.com/docs/ru/mcp.md#scale-with-mcp-tool-search) в соответствии с этой переменной через [управляемые параметры](https://code.claude.com/docs/ru/managed-settings.md). То, что Claude Code отправляет с этим переопределением, зависит от того, как вы подключаетесь:

* При прямом соединении без конфигурации HIPAA или через шлюз, установленный с `ANTHROPIC_BASE_URL`, Claude Code продолжает отправлять бета-заголовок поиска инструментов, поля инструментов `defer_loading` и блоки `tool_reference`
* На облачном поставщике или при входе через [Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway), переопределение не имеет никакого эффекта
* В сессии, которая [получает конфигурацию HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md#check-how-developers-sign-in-and-connect), переопределение не имеет никакого эффекта, и поиск инструментов остается отключенным

Набор возможностей, которые Claude Code отправляет, растет с каждым выпуском. Для текущих строк бета-заголовков см. [справочник бета-заголовков](https://platform.claude.com/docs/en/api/beta-headers); протестируйте свой шлюз против новых выпусков Claude Code, а не закрепляйте наблюдаемый список.

## Обнаружение моделей

Когда `ANTHROPIC_BASE_URL` указывает на gateway, который предоставляет формат Anthropic Messages, Claude Code может запросить конечную точку `/v1/models` gateway при запуске и добавить возвращаемые модели в средство выбора `/model`. Если вы или ваш администратор установили `replaceBuiltInOptions` в линейке [`modelPicker`](https://code.claude.com/docs/ru/settings-reference#modelpicker), Claude Code скрывает обнаруженные модели из средства выбора.

Разработчики включают это, установив [`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`](https://code.claude.com/docs/ru/env-vars) в своей собственной среде или через управляемые параметры. Обнаружение отключено по умолчанию, чтобы gateway-ы, поддерживаемые общим ключом API, не выводили каждую модель, к которой ключ может получить доступ, каждому пользователю.

### Когда выполняется обнаружение

Обнаружение применяется только к формату Anthropic Messages. Оно не выполняется, когда:

* Установлена любая переменная поставщика `CLAUDE_CODE_USE_*`, даже если также установлен `ANTHROPIC_BASE_URL`
* `ANTHROPIC_BASE_URL` не установлен или указывает на `api.anthropic.com`

Обнаружение все еще выполняется, когда [несущественный трафик отключен](https://code.claude.com/docs/ru/llm-gateway-connect.md#turn-off-traffic-outside-the-gateway-path), потому что запрос идет только на ваш gateway. До версии v2.1.257 обнаружение не выполнялось, пока несущественный трафик был отключен.

### Запрос и ответ

Запрос — это `GET /v1/models?limit=1000` с тайм-аутом 3 секунды по умолчанию, и любое перенаправление рассматривается как отказ, поэтому учетные данные не могут утечь на цель перенаправления. Gateway, который отвечает медленнее, чем тайм-аут, или тот, который перенаправляет `/v1/models`, даже `http` на `https`, молча не выполняет обнаружение; обслуживайте конечную точку непосредственно по настроенному базовому URL.

Чтобы дать медленному gateway больше времени, установите [`CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS`](https://code.claude.com/docs/ru/env-vars#variables). Переменная требует Claude Code v2.1.269 или позже.

Claude Code отправляет запрос обнаружения с обоими заголовками учетных данных ниже и опускает заголовок, значение которого не разрешается. Отправка обоих заголовков требует Claude Code v2.1.248 или позже. Более ранние версии отправляют только `Authorization`, когда установлен `ANTHROPIC_AUTH_TOKEN`, и только `x-api-key` в противном случае.

* `Authorization`: `ANTHROPIC_AUTH_TOKEN` как токен носителя, в противном случае значение [`apiKeyHelper`](https://code.claude.com/docs/ru/llm-gateway-connect#rotate-credentials-with-apikeyhelper) как токен носителя.
* `x-api-key`: разрешенный Claude Code ключ API, такой как `ANTHROPIC_API_KEY`. Когда значение помощника является единственным учетным данием, этот заголовок также его содержит, поэтому значение поступает в оба заголовка.

Claude Code также отправляет любые заголовки из `ANTHROPIC_CUSTOM_HEADERS`. Когда пользовательский заголовок имеет непустое значение, Claude Code отправляет его вместо встроенного заголовка с тем же именем, сопоставляя имена без учета регистра.

Когда ни одно значение заголовка учетных данных не разрешается, Claude Code пропускает обнаружение и записывает строку `[gatewayDiscovery] skipped` в журнал отладки сеанса `claude --debug`. Если вы предоставляете учетные данные только через `ANTHROPIC_CUSTOM_HEADERS`, Claude Code все равно пропускает обнаружение.

Claude Code читает `id`, опциональный `display_name` и опциональный `description` из каждой записи в массиве `data` ответа:

```json theme={null}
{
  "data": [
    {
      "id": "claude-sonnet-4-6",
      "display_name": "Claude Sonnet 4.6",
      "description": "Default model for everyday coding tasks"
    },
    { "id": "claude-opus-4-8" }
  ]
}
```

Claude Code сохраняет запись, когда ее `id` содержит `claude` или `anthropic` где-либо в строке, сопоставляя без учета регистра, и игнорирует остальное. ID с префиксом поставщика, такие как `vertex_ai/claude-sonnet-4-6` или `bedrock/anthropic.claude-sonnet-4-5`, проходят фильтр; ID, который не содержит ни одну подстроку, не проходит. До версии v2.1.223 Claude Code сохранял запись только когда ее `id` начинался с `claude` или `anthropic`, что скрывало ID с префиксом поставщика.

### Записи средства выбора и кеширование

Средство выбора — это интерактивный список моделей, который открывается, когда разработчик запускает `/model` в Claude Code. Каждая обнаруженная запись использует `display_name` как свое имя, когда gateway отправляет такое, которое отличается от `id`. В противном случае запись показывает имя модели, когда Claude Code [распознает `id`](https://code.claude.com/docs/ru/model-config#customize-pinned-model-display-and-capabilities), и `id`, когда не распознает. Например, запись с `id` `my-gateway-claude-sonnet-4-6` и без `display_name` отображается как `Sonnet 4.6`.

Обнаружение добавляет только модели, которые разрешает управляемый параметр [`availableModels`](https://code.claude.com/docs/ru/settings-reference#availablemodels).

Каждая запись также показывает `description` модели, свернутую в одну строку. Запись без `description` вместо этого читается как "From gateway". До версии v2.1.257 каждая обнаруженная запись читалась как "From gateway".

Обнаруженный ID не получает свою собственную строку, когда он совпадает со строкой, уже находящейся в средстве выбора:

* Одинаковый ID: обнаруженный ID точно совпадает с ID существующей строки, или оба ID являются написаниями одной и той же версии [Fable](https://code.claude.com/docs/ru/model-config.md#work-with-fable).
* Та же модель, что и встроенный псевдоним: когда обнаруженный явный ID называет модель, в которую встроенный псевдоним в настоящее время разрешается, средство выбора показывает только строку псевдонима. Например, пока `sonnet` разрешается в `claude-sonnet-5-5`, обнаруженный `claude-sonnet-5-5` объединяется в строку `sonnet`, а обнаруженный `claude-sonnet-5` всё ещё получает свою собственную строку.

Результаты кешируются в `~/.claude/cache/gateway-models.json` или `%USERPROFILE%\.claude\cache\gateway-models.json` на Windows и обновляются при каждом запуске. Если вы установили [`CLAUDE_CONFIG_DIR`](https://code.claude.com/docs/ru/env-vars), кеш находится в этом каталоге вместо этого. Если запрос не выполняется или gateway не реализует `/v1/models`, средство выбора возвращается к кешированному списку из предыдущего запуска или к встроенному списку моделей. Если ваш gateway обслуживает модели Claude под псевдонимами, которые не совпадают с фильтром обнаружения, разработчики могут добавить эти псевдонимы вручную с помощью переменных [конфигурации модели](https://code.claude.com/docs/ru/model-config.md).
