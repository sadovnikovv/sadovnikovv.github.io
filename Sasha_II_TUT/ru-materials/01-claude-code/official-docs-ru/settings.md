# Файлы параметров и приоритет

> Измените параметры Claude Code, выберите область, к которой принадлежит ключ, проверьте изменение и узнайте, какое значение Claude Code использует, когда ключ установлен в нескольких местах.

Параметры — это ключи JSON, которые изменяют поведение Claude Code: какую модель он запускает, что он может запустить без запроса, какие файлы он не может читать, как он выглядит в вашем терминале и что ваша организация требует.

> [!TIP]
>
> Чтобы найти конкретный ключ, перейдите на [Все параметры](https://code.claude.com/docs/ru/settings-reference.md), где перечислены все ключи с файлом, в котором вы их устанавливаете, значением по умолчанию и примером.

Claude Code читает параметры из файлов параметров JSON, таких как `~/.claude/settings.json`. Он ищет их в нескольких местах, и [файл, из которого он читает параметр, определяет, к кому применяется параметр](#settings-files-and-who-they-affect). На этой странице рассматриваются эти файлы: в какой из них поместить параметр, как изменить параметр и подтвердить его применение, и какое значение Claude Code использует, когда один и тот же ключ установлен в более чем одном файле. [Настройка разрешений](https://code.claude.com/docs/ru/permissions.md) охватывает то, что Claude Code может запустить без запроса, и как писать правила `allow`, `ask` и `deny`.

> [!NOTE]
>
> На этой странице рассматривается Claude Code, работающий на вашей машине: терминал, расширения [VS Code](https://code.claude.com/docs/ru/vs-code.md) и [JetBrains](https://code.claude.com/docs/ru/jetbrains.md), а также [приложение desktop](https://code.claude.com/docs/ru/desktop.md), которые все читают одни и те же файлы параметров. Облачный сеанс на [Claude Code в веб-версии](https://code.claude.com/docs/ru/claude-code-on-the-web.md) работает на другой машине и читает только некоторые из них; см. [Параметры в облачных сеансах](#settings-in-cloud-sessions).

## Файлы настроек и кого они затрагивают

Claude Code читает настройки из четырёх файлов, и организация также может доставлять управляемые настройки из консоли claude.ai. Каждый источник имеет область действия: круг людей и проектов, к которым применяется сохранённая в нём настройка, будь то только вы, все в проекте или все в вашей организации.

| Область действия | Файл | Кого это затрагивает | Используйте для |
| :- | :- | :- | :- |
| Пользователь | `~/.claude/settings.json` | Вас, в каждом проекте на этой машине | Личные предпочтения: тема, режим редактора, модель по умолчанию, ваши собственные правила разрешений |
| Общий проект | `.claude/settings.json` | Всех, кто работает в папке, которая его содержит. В репозитории git сделайте его коммит, чтобы товарищи по команде его получили | Разрешения команды, хуки, плагины и переменные окружения, которые нужны проекту |
| Локальный проект | `.claude/settings.local.json` | Вас, только в этом одном проекте. Claude Code исключает его из git при создании файла; если вы создадите его вручную, добавьте его в `.gitignore` сами | Личные переопределения для одного проекта и тестирование перед тем, как вы поделитесь |
| Управляемый | `managed-settings.json` и другие [управляемые источники](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms) | Всех, кому ваша организация его развёртывает; раздел [Приоритет настроек](#settings-precedence) описывает, что может его переопределить | Требования политики безопасности и соответствия |

В столбце «Файл» `~/.claude` — это папка `.claude` в вашем домашнем каталоге, а просто `.claude` — это папка `.claude` внутри вашего проекта.

### Сравните область действия каждого файла настроек

Предположим, у вас есть три проекта на вашей машине: `website/`, `api/` и `acme-app/`, у товарища по команде есть свой собственный клон `acme-app/`, и вы запускаете [облачную сессию](#settings-in-cloud-sessions) для `acme-app/`.

На графике ниже показано, в каких из этих папок применяется настройка при запуске Claude Code из них. Нажмите на файл настроек, чтобы увидеть папки, которые он охватывает.

* **`~/.claude/settings.json`**: каждый проект на вашей машине, и ничего на машине вашего товарища или в облачной сессии
* **`acme-app/.claude/settings.json`**: ваш `acme-app/`. Он охватывает клон вашего товарища и облачную сессию, только если вы зафиксируете файл в системе контроля версий; до этого это файл на вашем диске, как и любой другой, и ни у кого больше его нет
* **`acme-app/.claude/settings.local.json`**: только ваш `acme-app/`. Claude Code добавляет его в ваши глобальные исключения git при первой записи файла, поэтому он остаётся вне ваших коммитов; если вы создадите файл вручную, [добавьте его в `.gitignore` сами](#keep-personal-settings-out-of-a-repository)
* **Управляемые настройки**, будь то файл `managed-settings.json`, политика MDM или [управляемые сервером настройки](https://code.claude.com/docs/ru/server-managed-settings.md) из консоли claude.ai: каждый проект на каждой машине, на которую ваша организация их развёртывает, или на которую вы входите с учётной записью вашей организации. Только управляемые сервером настройки охватывают облачную сессию

### Найдите или создайте ваши файлы настроек

Установка Claude Code не создаёт никакого файла настроек. Если на вашей машине или в проекте он уже есть, он пришёл из одного из этих источников:

* **Управляемый**: ваша организация его развёртывает. Вы его не создаёте и не редактируете.
* **Общий проект**: в проекте, который уже использует Claude Code, он может быть зафиксирован. Если нет, создайте его в `.claude/settings.json` в папке проекта.
* **Пользователь** и **Локальный проект**: создайте их сами или позвольте Claude Code их создать. Он записывает `~/.claude/settings.json` при первом изменении опции в меню `/config`, которую он сохраняет в пользовательские настройки, например темы, и `.claude/settings.local.json` при первом предоставлении постоянного подтверждения на запрос разрешения, например "Да, и больше не спрашивайте" для команды Bash. Несколько опций `/config`, включая **Show tips**, сохраняются в `.claude/settings.local.json` вместо файла пользователя.

> [!NOTE]
>
> В Windows `~/.claude` означает `%USERPROFILE%\.claude`. Чтобы хранить файлы домашнего каталога в другом месте, установите [`CLAUDE_CONFIG_DIR`](https://code.claude.com/docs/ru/env-vars); тогда Claude Code будет сохранять ваши настройки, историю сессий и плагины там.

Claude Code также хранит пятый файл, [`~/.claude.json`](https://code.claude.com/docs/ru/claude-directory#ce-claude-json), который он записывает для себя; вам не нужно его редактировать. Он содержит данные вашей учётной записи, конфигурации [MCP-серверов](https://code.claude.com/docs/ru/mcp.md), состояние для каждого проекта, такое как решения о доверии, и [глобальные ключи конфигурации](https://code.claude.com/docs/ru/settings-reference.md#global-config-settings), которые `/config` записывает для вас.

### Поделитесь настройками с вашей командой

Сделайте коммит `.claude/settings.json`, чтобы все, кто клонирует репозиторий, получили одинаковые разрешения, хуки и настройки плагинов. Каждый товарищ по команде всё ещё может переопределить его для себя в своём собственном `.claude/settings.local.json`, поэтому личные исключения не требуют коммита. Полный файл команды см. в разделе [общие настройки команды](https://code.claude.com/docs/ru/settings-example.md#a-teams-shared-settings).

Часть того, что вы зафиксируете, ждёт, пока каждый товарищ по команде [доверит папку](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust), а некоторые ключи никогда не вступают в силу из файла репозитория; раздел [Устранение неполадок с настройкой, которая не применяется](#common-cases) охватывает оба случая.

### Держите личные настройки вне репозитория

Чтобы изменить настройку для себя в одном проекте, не меняя её для товарищей по команде, сохраните её в `.claude/settings.local.json` внутри проекта. Claude Code применяет этот файл поверх зафиксированного `.claude/settings.json`, поэтому если файл вашей команды устанавливает `"model": "claude-sonnet-5"`, а вы хотите Opus, поместите `"model": "claude-opus-5-5"` в ваш локальный файл, и изменятся только ваши сессии.

Claude Code также записывает в этот файл, держит его вне ваших коммитов и применяет его правила allow без шага доверия:

* **Claude Code также его записывает.** Когда Claude запрашивает разрешение на запуск команды Bash и вы выбираете "Да, и больше не спрашивайте", Claude Code сохраняет это [подтверждение разрешения](https://code.claude.com/docs/ru/permissions.md#permission-system) здесь как правило `allow`.
* **Вам не нужно самостоятельно добавлять его в gitignore, если только вы не создали его вручную.** При первой записи файла Claude Code в репозитории git, который его ещё не игнорирует, он добавляет `**/.claude/settings.local.json` в ваш глобальный файл исключений git, поэтому файл остаётся вне ваших коммитов в каждом репозитории. Этот файл — `core.excludesFile`, когда ваша глобальная конфигурация git задаёт для него абсолютный путь или путь с префиксом `~`; в противном случае это `$XDG_CONFIG_HOME/git/ignore` или `~/.config/git/ignore`, когда `XDG_CONFIG_HOME` не установлен. Если вы создали файл вручную и Claude Code ещё не писал в него, добавьте его в `.gitignore` сами.
* **Его правила allow не ждут доверия, пока файл остаётся неотслеживаемым.** Поскольку файл принадлежит вам, а не репозиторию, Claude Code применяет его правила `allow` без шага [доверия к рабочему пространству](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust), который он требует для зафиксированного файла. Если файл отслеживается git, шаг доверия применяется и к нему; см. [Когда вашему локальному файлу настроек нужно доверие](https://code.claude.com/docs/ru/permissions.md#when-your-local-settings-file-needs-trust).

#### Где Claude Code хранит локальный файл в репозитории git

Когда Claude запрашивает разрешение на запуск команды Bash и вы выбираете "Да, и больше не спрашивайте", Claude Code сохраняет это подтверждение как правило `allow` в `.claude/settings.local.json`. Если вы запускаете Claude Code в подкаталоге репозитория git, он читает и записывает этот файл в корне репозитория и применяет подтверждение ко всему репозиторию. В [worktree](https://code.claude.com/docs/ru/worktrees.md) он использует файл в корне основного checkout.

Два правила уточняют расположение в корне:

* **Когда файл вместо этого остаётся рядом с `.claude/settings.json`**: вне репозитория git, когда корень репозитория — это ваш домашний каталог, в Windows или когда корень репозитория либо его запись `.git` или `.claude` не принадлежит вашему пользователю.
* **Пути в файле не привязаны к корню репозитория**: правило разрешений, которое начинается с `/`, или относительный путь песочницы [привязывается вместо этого к основному рабочему каталогу сессии](https://code.claude.com/docs/ru/permissions.md#read-and-edit).

До v2.1.211 Claude Code хранил файл в начальном каталоге. Он всё ещё читает файл, который более ранняя версия оставила там, наряду с файлом в корне; если оба задают один и тот же ключ, применяется значение из корня, а правила разрешений из обоих файлов применяются. Вспомогательная функция Agent SDK [`resolveSettings()`](https://code.claude.com/docs/ru/agent-sdk/typescript#resolvesettings) всегда читает файл из начального каталога.

Claude Code читает общий `.claude/settings.json` из [основного рабочего каталога](https://code.claude.com/docs/ru/permissions.md#working-directories) сессии, поэтому, чтобы использовать файл, зафиксированный в корне репозитория, запустите Claude Code там. После того как вы [переместите сессию с помощью `/cd`](https://code.claude.com/docs/ru/permissions#move-the-session-to-another-directory), Claude Code вместо этого читает оба файла проекта из нового каталога, размещая локальный файл по тем же правилам. Чтение их из каталога, в который вы переместились, требует Claude Code v2.1.246 или более поздней версии. О сессии в worktree, которую вы запускаете из десктопного приложения, см. раздел [Что worktree разделяют с основным checkout](https://code.claude.com/docs/ru/worktrees.md#what-worktrees-share-with-the-main-checkout).

### Проверьте, что требует ваша организация

Если ваша организация управляет Claude Code, некоторые настройки определены за вас, и ничто из того, что вы поместите в ваши собственные файлы, их не изменит. Чтобы увидеть, какие именно, запустите `/status`: строка `Setting sources` называет управляемый источник, который применяется к вам. Управляемые настройки применяются везде, где Claude Code работает на этой машине; раздел [Что может изменить разработчик](https://code.claude.com/docs/ru/managed-settings.md#what-a-developer-can-change) охватывает права локального администратора и инструменты, отличные от Claude Code.

Управляемые настройки доходят до вас через [механизмы доставки](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), описанные на странице управляемых настроек, чаще всего:

* [Управляемые сервером настройки](https://code.claude.com/docs/ru/server-managed-settings.md), которые Claude Code получает из консоли администратора claude.ai или из самостоятельно размещённого [шлюза приложений Claude](https://code.claude.com/docs/ru/claude-apps-gateway)
* Политики MDM или уровня ОС и файлы `managed-settings.json` в системном каталоге
* Встраивающий хост, такой как Claude Desktop, через опцию SDK `managedSettings`; см. [Управление политикой из встраивающего хоста](https://code.claude.com/docs/ru/managed-settings.md#parent-settings-from-embedding-hosts)

В сессии [Cowork](https://claude.com/docs/cowork/overview), которая работает на вашей машине в приложении Claude Desktop, Claude Code не получает управляемые сервером настройки из консоли администратора claude.ai и читает политику, развёрнутую на вашем устройстве, если только конфигурация Claude Desktop вашей организации не устанавливает `requireCoworkFullVmSandbox`. Раздел [Где и когда применяется политика](https://code.claude.com/docs/ru/managed-settings.md#where-and-when-a-policy-applies) охватывает Cowork и облачные сессии.

Если вы администратор, руководство [Настройка Claude Code для вашей организации](https://code.claude.com/docs/ru/admin-setup.md) проводит через выбор того, что требовать, а [Развёртывание управляемых настроек](https://code.claude.com/docs/ru/managed-settings.md) охватывает доставку и то, как подтвердить, что политика действует. Сведения о предупреждении, которое может показывать редактор управляемых настроек в консоли администратора claude.ai, см. в разделе [Настройка управляемых сервером настроек](https://code.claude.com/docs/ru/server-managed-settings.md#configure-server-managed-settings).

## Измените параметр

Вы можете изменить параметр из меню `/config`, редактируя файл параметров или для одного сеанса из командной строки.

Системный запрос Claude Code не опубликован. Чтобы дать Claude постоянные инструкции, используйте файлы [`CLAUDE.md`](https://code.claude.com/docs/ru/memory) или флаг `--append-system-prompt`.

### Используйте меню /config

Запустите `/config` внутри Claude Code и откройте вкладку **Config**. Она перечисляет короткий набор личных опций, таких как тема, режим редактора и подробный вывод, не каждый ключ параметров. Выберите опцию для ее изменения; Claude Code сохраняет ее для вас:

* **Большинство опций**: `~/.claude/settings.json`
* **Несколько опций, таких как Show tips**: `.claude/settings.local.json`
* **[Глобальные опции конфигурации](https://code.claude.com/docs/ru/settings-reference.md#global-config-settings)**: `~/.claude.json`

Чтобы установить одну опцию без меню, передайте `key=value`, такой как `/config verbose=true`.

> [!NOTE]
>
> `/config` является частью интерфейса терминала. Панель чата [VS Code](https://code.claude.com/docs/ru/vs-code.md) и [приложение desktop](https://code.claude.com/docs/ru/desktop.md) его не открывают; измените параметры там, отредактировав файл параметров или через собственные параметры этих приложений.

### Отредактируйте файл параметров

Откройте файл параметров для области, которую вы хотите, в вашем редакторе и добавьте или измените ключ. Файлы параметров — это строгий JSON: комментарий `//` или запятая в конце — это синтаксическая ошибка, и Claude Code сообщает файл как [Settings Error](#fix-a-broken-settings-file) при следующем запуске. Например, чтобы позволить Claude Code запускать ваши команды lint и test без запроса и остановить его чтение файлов `.env`, добавьте это в `~/.claude/settings.json`:

```json ~/.claude/settings.json theme={null}
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}
```

Каждая запись под `permissions` — это правило, которое называет инструмент и что он может делать; [Настройка разрешений](https://code.claude.com/docs/ru/permissions.md) объясняет синтаксис. Строка `$schema` указывает на [опубликованную JSON схему](https://json.schemastore.org/claude-code-settings.json) для параметров Claude Code, которая дает вам автодополнение и встроенную валидацию в VS Code, Cursor и любом другом редакторе, поддерживающем JSON схему. Схема может отставать от самых новых выпусков CLI, поэтому предупреждение валидации на недавно задокументированном ключе не означает, что ваша конфигурация недействительна.

После сохранения запустите `/status` внутри Claude Code, чтобы подтвердить, что файл загружен; [Подтвердите, что загружено](#check-what-loaded) говорит, что показывает строка `Setting sources` и как сообщается о сломанном файле.

Для полного личного файла, файла команды и файла организации, каждый показан с комментарием на каждом ключе, который он устанавливает, см. [примеры файлов параметров](https://code.claude.com/docs/ru/settings-example.md).

### Измените параметр для одного сеанса

Чтобы попробовать значение без сохранения, установите его при запуске Claude Code. Значение применяется к этому сеансу, и ваши файлы параметров остаются такими, какими они были. У вас есть три способа это сделать:

* **`--settings`**: передайте ключ как JSON, встроенный или как путь к файлу. Claude Code применяет его выше ваших файлов пользователя, проекта и локальных и ниже управляемых параметров. Он может установить любой ключ, который может установить ваш файл параметров пользователя; он не может установить ключи `Managed` или `Global config`.
* **Флаг для этого ключа**: некоторые ключи имеют свой собственный флаг, такой как `--model` для `model` и `--effort` для `effortLevel` и `modelSettings`.
* **Переменная окружения**: экспортируйте переменную ключа перед запуском `claude`, такую как `ANTHROPIC_MODEL` для `model`.

Каждая запись ключа на [справочнике параметров](https://code.claude.com/docs/ru/settings-reference.md) перечисляет его переопределения для каждого сеанса и какой имеет приоритет, поэтому проверьте запись для ключа, который вы хотите изменить.

Команды, которые вы запускаете внутри сеанса, в основном сохраняют ваш выбор: когда вы изменяете параметр в `/config`, Claude Code записывает его в ваши файлы параметров, и `/model` сохраняет значение как ваше значение по умолчанию для новых сеансов.

Если вы нажмете `s` в средстве выбора `/model`, Claude Code переключает модель без сохранения ее как вашего пользовательского значения по умолчанию. [Отрегулируйте уровень усилий](https://code.claude.com/docs/ru/model-config.md#adjust-effort-level) говорит, какие выборы `/effort` Claude Code сохраняет как ваше значение по умолчанию для модели, которую вы используете, и какие применяются только к текущему сеансу.

Например, чтобы запустить один сеанс на Opus без изменения вашего значения по умолчанию:

```bash theme={null}
claude --settings '{"model": "claude-opus-5-5"}'
```

### Когда изменения вступают в силу

Claude Code отслеживает ваши файлы параметров и перезагружает их при изменении, поэтому он применяет большинство изменений к работающему сеансу без перезагрузки, включая изменения `permissions`, `hooks` и помощников учетных данных, таких как `apiKeyHelper`. Claude Code также загружает файл параметров, который вы создаете в середине сеанса, если его папка существовала при запуске сеанса. Для папки `.claude/` проекта он загружает файл даже когда вы создаете папку в том же сеансе.

Перезагрузка охватывает пользовательские, проектные, локальные и управляемые настройки. Claude Code запускает [хук `ConfigChange`](https://code.claude.com/docs/ru/hooks#configchange) при непосредственном редактировании файлов настроек, но не для управляемых настроек, поступающих из MDM или консоли claude.ai. Управляемые настройки, поступающие через MDM или из консоли claude.ai, доходят до работающей сессии по расписанию, а не при сохранении; [таблица способов доставки](https://code.claude.com/docs/ru/managed-settings.md#choose-a-delivery-mechanism) приводит его для каждого источника.

Claude Code читает некоторые ключи только один раз при запуске сеанса, поэтому изменение одного из них не достигает работающего сеанса. Ключи на стороне администратора, которые также ждут перезагрузки, такие как `requiredMinimumVersion`, перечислены в [где и когда применяется политика](https://code.claude.com/docs/ru/managed-settings.md#where-and-when-a-policy-applies). Те, которые вы, скорее всего, будете редактировать в середине сеанса:

* [`model`](https://code.claude.com/docs/ru/settings-reference#model): используйте [`/model`](https://code.claude.com/docs/ru/model-config#setting-your-model) для переключения в середине сеанса. Каждая модель имеет свой собственный кэш подсказок, поэтому первый запрос после переключения повторно читает весь разговор без кэша; см. [Переключение моделей](https://code.claude.com/docs/ru/prompt-caching.md#switching-models)
* [`effortLevel`](https://code.claude.com/docs/ru/settings-reference#effortlevel) и [`modelSettings`](https://code.claude.com/docs/ru/settings-reference#modelsettings): используйте [`/effort`](https://code.claude.com/docs/ru/model-config#adjust-effort-level) для изменения усилий в середине сеанса

Если удалить [`permissions.blockReadsOutsideWorkingDirectories`](https://code.claude.com/docs/ru/settings-reference#permissions-blockreadsoutsideworkingdirectories) посреди сессии, файловые инструменты сохранят блокировку в работающей сессии. Чтобы снять её, удалите ключ из всех файлов настроек, где он задан, а затем перезапустите каждую работающую сессию.

### Подтвердите, что загружено

Запустите `/status` внутри Claude Code, чтобы увидеть, какие источники параметров активны. Вкладка **Status** включает строку `Setting sources`, которая перечисляет каждый файл параметров, который Claude Code загрузил для текущего сеанса, такой как `User settings` или `Project local settings`. Когда [управляемые параметры](https://code.claude.com/docs/ru/admin-setup.md#decide-how-settings-reach-devices) действуют, запись управляемых параметров показывает в скобках, как они достигли вашей машины.

Строка подтверждает, какие файлы Claude Code прочитал; она не показывает, какой файл предоставил каждый ключ. Чтобы перечислить записи, которые Claude Code отклонил, запустите [`claude doctor`](https://code.claude.com/docs/ru/debug-your-config); для модели, которую установили параметры проекта или управляемые параметры, заголовок запуска называет файл, который ее установил. `/status` и `/config` открывают один и тот же диалог на разных вкладках, и вкладка **Config** не является представлением содержимого вашего `settings.json`.

### Исправьте сломанный файл параметров

Если вы неправильно напечатаете JSON или установите ключ на значение, которое Claude Code не принимает, Claude Code сообщит вам при запуске интерактивного сеанса. То, что он показывает, зависит от того, сколько файла затронуто:

* **Settings Error**: файл пользователя, проекта или локальный имеет недействительный JSON или значение, которое схема отклоняет. При запуске интерактивного сеанса Claude Code показывает диалог, который позволяет вам исправить файл с помощью Claude, выйти или продолжить без сломанных параметров.
* **Settings Warning**: только отдельные записи не удаются, такие как неправильное правило разрешения или неизвестное имя события hook. Claude Code пропускает эти значения и держит остальную часть файла в силе.
* **Managed settings**: Claude Code продолжает применять остальную часть файла. [Недействительные записи в управляемых параметрах](https://code.claude.com/docs/ru/managed-settings.md#invalid-entries-in-managed-settings) говорит, что он отбрасывает и какие ключи возвращаются к более строгому значению, пока вы их не исправите. Для документа управляемых параметров, который не является действительным JSON, см. [Документ управляемых параметров не может быть разобран](https://code.claude.com/docs/ru/errors.md#managed-settings-document-could-not-be-parsed).
* **Configuration error**: не удаётся разобрать [`~/.claude.json`](https://code.claude.com/docs/ru/claude-directory#ce-claude-json). Запуск `claude -p` завершается. Чтобы восстановить более раннюю копию, см. [Configuration error in \~/.claude.json](https://code.claude.com/docs/ru/errors.md#configuration-error-in-claude-json). Claude Code копирует повреждённый файл в `~/.claude/backups/.claude.json.corrupted.<timestamp>`, а в интерактивной сессии спрашивает, выйти и исправить его или сбросить к конфигурации по умолчанию. Если файл пуст и резервной копии для восстановления нет, Claude Code запускается с настройками по умолчанию.

После продолжения запустите `/status`, чтобы увидеть затронутые файлы, и `claude doctor` для деталей каждой ошибки.

Запуск `-p` не показывает диалоговое окно. За исключением случаев, когда [документ управляемых настроек не удаётся разобрать](https://code.claude.com/docs/ru/errors.md#managed-settings-document-could-not-be-parsed), Claude Code пропускает сломанный пользовательский, проектный или локальный файл либо его сломанные значения и продолжает работу с остальным. После запуска `-p`, который проигнорировал настройку, запустите `claude doctor` из терминала, чтобы увидеть, что было отброшено.

## Приоритет настроек

Когда один и тот же ключ появляется в нескольких местах, Claude Code использует значение из наивысшего уровня, который его устанавливает. Стек ниже показывает уровни, наивысший вверху; ключ на более высоком уровне переопределяет тот же ключ где-либо ниже.

Settings precedence, highest first: managed settings, command line, project local, shared project, user. A key set at a higher level overrides the same key set lower down.

По порядку, наивысший приоритет первым:

1. **Управляемые настройки**: настройки, которые ваша организация развертывает через файл `managed-settings.json`, политику MDM или [настройки, управляемые сервером](https://code.claude.com/docs/ru/server-managed-settings.md) из консоли claude.ai. Ничто в ваших собственных файлах настроек или в `--settings` не переопределяет управляемый ключ, а флаг, такой как `--model`, выбирает только из моделей, которые разрешает ваша организация. Управляемый [`model`](https://code.claude.com/docs/ru/settings-reference#model) — это начальное значение по умолчанию, а не блокировка; блокировками являются [`availableModels`](https://code.claude.com/docs/ru/settings-reference#availablemodels) и [`deniedModels`](https://code.claude.com/docs/ru/settings-reference#deniedmodels). Когда ваша организация предоставляет более одного управляемого источника, правила для [приоритета в пределах управляемого уровня](https://code.claude.com/docs/ru/managed-settings.md#precedence-within-the-managed-tier) указывают, что Claude Code читает из каждого.
2. **Командная строка**: JSON, который вы передаете с `--settings <file-or-json>` при запуске `claude`, только для этой сессии; см. [Изменить настройку для одной сессии](#change-a-setting-for-one-session). Ключ, который вы устанавливаете здесь, переопределяет тот же ключ в ваших файлах настроек проекта и пользователя, а ключ, который вы опускаете, сохраняет свое значение из этих файлов. Другие флаги, такие как `--model`, устанавливают что-то одно для сессии и не являются частью этого стека; запись ключа в [справочнике настроек](https://code.claude.com/docs/ru/settings-reference.md) указывает, какие флаги его переопределяют.
3. **Локальные настройки проекта** (`.claude/settings.local.json`): ваши личные настройки для этого проекта.
4. **Общие настройки проекта** (`.claude/settings.json`): настройки, которые ваша команда фиксирует в системе управления версиями.
5. **Пользовательские настройки** (`~/.claude/settings.json`): ваши личные настройки для каждого проекта.

Переменные окружения не являются уровнем в этом стеке. Когда поведение имеет как переменную оболочки, так и ключ настроек, какой из них применяется, решается для каждой пары отдельно, а не по уровню: `ANTHROPIC_MODEL`, экспортированная в вашей оболочке, применяется поверх ключа `model` из любого файла, в то время как `ANTHROPIC_DEFAULT_MODEL` применяется только когда ни один файл не устанавливает `model`. [Справочник переменных окружения](https://code.claude.com/docs/ru/env-vars.md#precedence) указывает, какие ключи имеют пару и какой из них Claude Code читает первым. Блок `env` внутри файла настроек — это обычный ключ и следует уровням выше.

Для нескольких ключей, чувствительных к безопасности, Claude Code соблюдает более строгое значение из более низкого уровня вместо управляемого значения; [Исключения из приоритета управляемых настроек](#exceptions-to-managed-settings-precedence) их перечисляет.

### Списки объединяются вместо переопределения

Когда вы устанавливаете один и тот же ключ списка, такой как `permissions.allow`, в более чем одном файле, Claude Code объединяет списки вместо выбора одного, поэтому каждый файл может добавлять записи без удаления записей другого файла. Четыре ключа, которые содержат списки моделей или записи для каждой модели, следуют своим собственным правилам:

* [`fallbackModel`](https://code.claude.com/docs/ru/settings-reference#fallbackmodel) — это упорядоченная цепь, где позиция имеет значение, поэтому Claude Code берет все значение из файла с наивысшим приоритетом, который его определяет.
* [`modelPicker`](https://code.claude.com/docs/ru/settings-reference#modelpicker) содержит один упорядоченный список строк плюс флаг замены, поэтому Claude Code никогда не объединяет строки из двух источников. Он берет все значение из наивысшего из управляемых настроек, `--settings` и пользовательских настроек, которые его определяют, и игнорирует ключ в настройках проекта и локальных настройках. Требует Claude Code v2.1.242 или позже.
* [`availableModels`](https://code.claude.com/docs/ru/settings-reference#availablemodels): когда применяемые Claude Code управляемые настройки его определяют, Claude Code применяет этот список как есть и игнорирует записи, которые вы добавляете в пользовательские, проектные или локальные настройки, если только приложение, которое встраивает Claude Code, не предоставляет свой собственный список моделей; см. [Исключения из приоритета управляемых настроек](#exceptions-to-managed-settings-precedence). Во всех управляемых источниках список также никогда не объединяется; [как Claude Code объединяет управляемые источники](https://code.claude.com/docs/ru/managed-settings.md#how-claude-code-combines-managed-sources) указывает, какой список источника применяется. Во всех неуправляемых областях действия Claude Code объединяет массивы как обычно.
* [`modelSettings`](https://code.claude.com/docs/ru/settings-reference#modelsettings): Claude Code разрешает его одну модель за раз, вместе с [`effortLevel`](https://code.claude.com/docs/ru/settings-reference#effortlevel). Запись `modelSettings` указывает, какое значение файла применяется к модели.

### Примеры приоритета

Пока Claude работает, Claude Code показывает подсказку в одну строку под спиннером, например "Use /config to change your default permission mode (including Plan Mode)". Предположим, вы хотите отключить эти подсказки, поэтому вы устанавливаете [`spinnerTipsEnabled`](https://code.claude.com/docs/ru/settings-reference#spinnertipsenabled) в `false` в `~/.claude/settings.json`. Каждый сценарий ниже — это что-то, что может их снова включить, и что вы можете с этим сделать.

#### Настройки команды переопределяют личные настройки

Файл `.claude/settings.json` вашей команды устанавливает это в `true`. Claude Code использует значение проекта, потому что общие настройки проекта находятся выше пользовательских, поэтому вы видите подсказки в этом проекте и больше нигде.

Вы можете вернуть свое значение: добавьте `"spinnerTipsEnabled": false` в `.claude/settings.local.json` в этом проекте. Локальные настройки проекта находятся выше общих настроек проекта, поэтому ваши сессии там перестанут показывать подсказки, а сессии ваших товарищей по команде не изменятся.

#### Настройки организации переопределяют все

Управляемые настройки вашей организации устанавливают это в `true`. Ничто из того, что вы поместите в пользовательские, проектные или локальные настройки, не отключит подсказки, и `--settings` тоже не отключит. Управляемые настройки — это наивысший уровень.

Вы не можете вернуть свое значение. Запустите `/status`, чтобы увидеть, какой управляемый источник применяется, и спросите у вашего администратора, следует ли изменить политику.

#### Командная строка переопределяет ваши файлы для одной сессии

Вы запустили сессию с `claude --settings '{"spinnerTipsEnabled": true}'`. Командная строка находится выше каждого файла, кроме управляемых, поэтому эта сессия показывает подсказки, даже если ваши файлы говорят `false`.

Вы получите свое значение обратно в следующей сессии; `--settings` действует одну сессию и не записывает ни в какой файл.

#### Флаг или переменная окружения устанавливает то же самое

Некоторые ключи имеют флаг командной строки или переменную окружения, которая переопределяет значение настройки независимо от того, какой файл его установил: `ANTHROPIC_MODEL` переопределяет настройку [`model`](https://code.claude.com/docs/ru/settings-reference#model), а `--model` переопределяет оба для сессии.

Можете ли вы вернуть свое значение, зависит от ключа: отмените переменную или удалите флаг, и проверьте запись ключа в [справочнике настроек](https://code.claude.com/docs/ru/settings-reference.md) и строку переменной в [справочнике переменных окружения](https://code.claude.com/docs/ru/env-vars.md), чтобы узнать, какой из них использует Claude Code.

### Устранение неполадок с настройкой, которая не применяется

Когда вы устанавливаете ключ и Claude Code не ведет себя так, как если бы вы это сделали, начните с `/status`, чтобы увидеть, какие файлы он загрузил, затем найдите ваш симптом ниже. [Отладка вашей конфигурации](https://code.claude.com/docs/ru/debug-your-config.md) охватывает более широкие проверки, включая тест чистой конфигурации.

#### Значение, которое вы установили, игнорируется

Что-то еще устанавливает тот же ключ, файл не может установить это значение, или файл не загрузился:

* **Более высокий уровень его устанавливает.** Другой файл настроек, флаг `--settings` или управляемый источник устанавливает ключ выше вашего; [стек](#settings-precedence) указывает, какой. Флаг или переменная окружения также может переопределить ключ самостоятельно, что решается для каждого ключа отдельно; запись ключа в [справочнике настроек](https://code.claude.com/docs/ru/settings-reference.md) указывает, какой из них использует Claude Code, а [запись `env`](https://code.claude.com/docs/ru/settings-reference#env) описывает управляемое значение `env` в сравнении с экспортом в оболочке.
* **Ключ безопасности сохраняет свое строгое значение.** Для нескольких ключей Claude Code соблюдает ограничивающее значение из любого файла, поэтому проектный `true` для [`disableClaudeAiConnectors`](https://code.claude.com/docs/ru/settings-reference#disableclaudeaiconnectors) остается включенным; см. [Исключения из приоритета управляемых настроек](#exceptions-to-managed-settings-precedence).
* **Файл не может установить это значение.** Значения [`permissions.defaultMode`](https://code.claude.com/docs/ru/settings-reference#permissions-defaultmode) `auto` и `bypassPermissions` не вступают в силу из проектных или локальных настроек; установите их вместо этого в пользовательских или управляемых настройках или передайте `--permission-mode` для одной сессии. До v2.1.257 `bypassPermissions` вступал в силу из любого файла.

  Переменная экспорта телеметрии в блоке [`env`](https://code.claude.com/docs/ru/settings-reference#env) также не вступает в силу из проектных или локальных настроек, кроме нескольких отключающих значений. [Переменные, которые Claude Code игнорирует в `env`](https://code.claude.com/docs/ru/settings-reference#variables-claude-code-ignores-in-env) перечисляет переменные и эти значения.
* **Файл сломан.** Неверный JSON или отклоненное значение заставляет Claude Code пропустить файл или запись; см. [Исправить сломанный файл настроек](#fix-a-broken-settings-file).

#### Изменение, которое вы сделали в Claude Code, теряется в новых сессиях

Когда вы сохраняете выбор для новых сессий из Claude Code, например модель по умолчанию с `/model`, Claude Code записывает это в ваш файл пользовательских настроек, `~/.claude/settings.json`. Если вы не можете писать в этот файл, например потому что другой инструмент его генерирует или связывает его с копией только для чтения, изменение применяется к текущей сессии и исчезает в следующей. Установите ключ в инструменте, который генерирует файл, или замените файл на тот, в который вы можете писать.

Если вы можете писать в файл и изменение все еще не сохраняется, проверьте, было ли изменение [только для одной сессии](#change-a-setting-for-one-session) или [более высокий уровень устанавливает тот же ключ](#a-value-you-set-is-ignored). Для ключа `model` [Новая сессия начинается с другой модели, чем вы выбрали](https://code.claude.com/docs/ru/model-config.md#a-new-session-starts-on-a-different-model-than-you-picked) перечисляет больше причин.

#### Управляемое изменение не достигло вас

Управляемые источники достигают работающей сессии по расписанию в [таблице доставки](https://code.claude.com/docs/ru/managed-settings.md#choose-a-delivery-mechanism), поэтому сначала перезапустите сессию. Если `/status` затем называет другой источник, чем тот, который изменил ваш администратор, применяется источник с более высоким приоритетом; [Как Claude Code объединяет управляемые источники](https://code.claude.com/docs/ru/managed-settings.md#how-claude-code-combines-managed-sources) дает порядок.

#### Зафиксированный ключ не достигает товарищей по команде

Две вещи не позволяют ключу в `.claude/settings.json` применяться для всех, кто клонирует репозиторий:

* **Claude Code игнорирует ключ в файле репозитория.** Ищите `User, local, or managed`, `User or managed`, `User`, `Managed` или `Global config` в столбце Scope [индекса настроек](https://code.claude.com/docs/ru/settings-reference.md#settings-index). Эти ключи никогда не применяются из общего файла, кроме нескольких, которые файл репозитория все еще может отключить. Каждая из этих записей говорит об этом в строке Scope. Ключи `Global config` применяются только из `~/.claude.json`.

  Внутри ключа `env` переменные экспорта телеметрии также никогда не применяются из общего файла, кроме нескольких отключающих значений; см. [Переменные, которые Claude Code игнорирует в `env`](https://code.claude.com/docs/ru/settings-reference#variables-claude-code-ignores-in-env).
* **Ключ ждет доверия.** Правила `permissions.allow`, `permissions.additionalDirectories`, `extraKnownMarketplaces` и большинство значений [`env`](https://code.claude.com/docs/ru/settings-reference#env) применяются только после того, как каждый товарищ по команде [доверит папке](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust). До этого они все еще видят запросы разрешений и не получают плагины с маркетплейса, который объявляет файл. Правила `deny` и `ask` применяются сразу же.

#### Правила разрешений объединяются иначе, чем вы ожидали

* **Вы выбрали "Yes, and don't ask again" в запросе разрешения, но все еще получаете запрос для того же инструмента.** Этот выбор сохранил правило `allow` в ваш локальный файл, и правило `allow` там не превосходит правило `ask` из проектного или управляемого файла; [как объединяются правила разрешений](https://code.claude.com/docs/ru/permissions.md#settings-precedence) объясняет порядок. В расширении VS Code карточка подтверждения позволяет вам выбрать файл назначения, включая общий файл проекта, что изменяет правило для всех; в CLI Claude Code пишет только в ваш локальный файл.
* **Разрешающие правила вашей организации все еще применяются наряду с вашими.** Это ожидаемо: Claude Code объединяет [`permissions.allow`](https://code.claude.com/docs/ru/settings-reference#permissions-allow) во всех областях действия, если только ваша организация не устанавливает [`allowManagedPermissionRulesOnly`](https://code.claude.com/docs/ru/settings-reference#allowmanagedpermissionrulesonly).

Claude Code берет конфигурацию модели этого приложения вместо ключей `model`, `fallbackModel`, `modelPicker` и `modelOverrides` из каждого управляемого источника, а также вместо переменных выбора модели в управляемом блоке `env`, таких как `ANTHROPIC_MODEL` и семейство `ANTHROPIC_DEFAULT_*_MODEL`. Claude Code сохраняет в силе управляемый список разрешённых моделей [`availableModels`](https://code.claude.com/docs/ru/settings-reference#availablemodels), если только приложение не предоставляет свой собственный.

## Параметры в облачных сеансах

[Облачный сеанс](https://code.claude.com/docs/ru/claude-code-on-the-web.md) работает в [облачной среде](https://code.claude.com/docs/ru/cloud-environments.md) на свежем клоне вашего репозитория, не на вашей машине. Это изменяет, какие параметры его достигают:

* **Облачные треды в проекте**: в облачном треде в [проекте](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories) не применяются ни правила разрешений, ни хуки, ни `env` из файла `.claude/settings.json` репозитория, сколько бы репозиториев ни было в проекте. В разделе [Что треды берут из ваших репозиториев](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories) перечислено, что использовать вместо этого.
* **Общие настройки проекта** (`.claude/settings.json`): читаются в сессии с одним репозиторием вне тредов проекта, потому что файл является частью клона и сессия начинается внутри него. Сделайте коммит настройки в этот файл, чтобы применить её в таких сессиях.
* **Общие настройки проекта с несколькими репозиториями**: в среде, размещённой Anthropic, сессия с несколькими репозиториями начинается выше клонов и читает только ключи `enabledPlugins` и `extraKnownMarketplaces` из файла `.claude/settings.json` каждого репозитория, но не правила разрешений, хуки, `env` или другие ключи. Маркетплейсы и плагины, которые объявляют эти два ключа, по-прежнему [не загружаются в облачной сессии](https://code.claude.com/docs/ru/cloud-environments.md#what-carries-over-from-your-setup). Для самостоятельно размещённой среды см. раздел [настройки какого репозитория применяются](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#repository-settings-in-sessions-with-several-repositories).
* **Параметры пользователя и локальные параметры проекта** (`~/.claude/settings.json` и `.claude/settings.local.json`): не читаются. Оба остаются на вашей машине, и локальный файл не находится в клоне.
* **Managed settings**: файл `managed-settings.json` или профиль MDM на вашем устройстве не достигают облачного сеанса. [Параметры, управляемые сервером](https://code.claude.com/docs/ru/server-managed-settings.md) вашей организации достигают; [покрытие поверхности](https://code.claude.com/docs/ru/model-config.md#surface-coverage) перечисляет, какие облачные сеансы их получают. [Самостоятельно размещенная среда](https://code.claude.com/docs/ru/self-hosted-environments) также читает файл управляемых параметров в образе своего runner. [Как Claude Code объединяет управляемые источники](https://code.claude.com/docs/ru/managed-settings.md#how-claude-code-combines-managed-sources) говорит, когда этот файл применяется.
* **`/config`**: в вашем браузере на claude.ai/code открывает страницу настроек **Code** или **Claude Code** в claude.ai вместо изменения значения. Чтобы изменить настройку для облачной сессии, задайте [переменную окружения](https://code.claude.com/docs/ru/cloud-environments.md#set-environment-variables) в среде. В сессии с одним репозиторием вне тредов проекта вместо этого можно сделать коммит ключа в файл `.claude/settings.json` этого репозитория.

[Что переносится из вашей установки](https://code.claude.com/docs/ru/cloud-environments.md#what-carries-over-from-your-setup) перечисляет остальное: `CLAUDE.md`, skills, MCP servers, plugins и учетные данные.
