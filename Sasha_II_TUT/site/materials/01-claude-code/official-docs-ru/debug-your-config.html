Отладка конфигурации #

Диагностируйте, почему CLAUDE.md, параметры, hooks, MCP серверы или skills не вступают в силу. Используйте /context, /doctor, /hooks и /mcp, чтобы увидеть, что действительно загрузилось.

Когда Claude игнорирует инструкцию или функция, которую вы настроили, не появляется, причина обычно в том, что файл не загрузился, загрузился из другого места, чем вы ожидали, или его переопределил другой файл. Это руководство показывает, как проверить, что Claude Code действительно загрузил, чтобы вы могли сузить, какой из этих вариантов применяется.

Для проблем с установкой, аутентификацией и подключением см. Troubleshooting установки и входа вместо этого.

Посмотрите, что загрузилось в контекст #

Команда /context показывает всё, что занимает контекстное окно в текущей сессии, разбитое по категориям: системный промпт, системные инструменты, инструменты MCP, пользовательские субагенты с указанием источника, из которого загружен каждый, файлы памяти, скиллы и сообщения диалога. Запустите её в первую очередь, чтобы убедиться, присутствуют ли вообще ваши CLAUDE.md, правила или описания скиллов. Раздел скиллов в /context также включает встроенные скиллы, которые /skills не перечисляет.

В полноэкранном режиме /context сворачивает поэлементную разбивку, поэтому выполните /context all, чтобы развернуть её.

Для деталей по конкретной категории используйте специализированную команду:

| Команда | Показывает | | :- | :- | | /memory | Расположение файлов памяти в области пользователя и проекта с возможностью открыть каждый в вашем редакторе, плюс доступ к папке auto memory и переключатель auto memory | | /skills | Доступные skills из проекта, пользователя и источников плагинов | | /hooks | Активные конфигурации hooks | | /mcp | Подключённые MCP серверы и их статус | | /permissions | Разрешённые и запрещённые правила, которые в настоящее время действуют | | /doctor | Диагностика конфигурации: здоровье установки, неверные файлы параметров, неиспользуемые расширения, дублирующиеся имена subagent в одной папке и проверенное содержимое CLAUDE.md, которое Claude может вывести из кодовой базы, с предложенными исправлениями | | /debug [issue] | Включает логирование отладки для сессии и предлагает Claude диагностировать, используя вывод журнала и пути параметров | | /status | Активные источники параметров, включая то, действуют ли управляемые параметры |

Если файл памяти отсутствует в разбивке /context, сверьте его расположение с разделом как загружаются файлы CLAUDE.md. Файлы CLAUDE.md в подпапках загружаются по требованию, а не при запуске сессии, поэтому они не отображаются в этой разбивке.

Если /context подтверждает, что файл загрузился, но Claude всё ещё не следует конкретной инструкции, проблема, вероятно, в том, как написана инструкция, а не в том, загрузилась ли она. CLAUDE.md хорошо работает для типов рекомендаций, которые вы дали бы новому коллеге, таких как соглашения проекта, команды сборки и где находятся файлы.

Соответствие снижается, когда инструкция достаточно расплывчата, чтобы интерпретировать несколькими способами, когда два файла дают противоречивые указания или когда файл вырос настолько, что отдельные правила получают меньше внимания. Напишите эффективные инструкции охватывает специфичность, размер и структурные паттерны, которые поддерживают высокое соответствие.

[!NOTE]

CLAUDE.md и permissions решают разные проблемы. CLAUDE.md говорит Claude, как работает ваш проект, чтобы он принимал хорошие решения. Permissions и hooks обеспечивают ограничения независимо от того, что решит Claude. Используйте CLAUDE.md для "мы делаем это так здесь". Используйте permissions или hooks для границ безопасности и всего, что никогда не должно происходить, когда вам нужна гарантия вместо рекомендации.

Проверьте разрешённые параметры #

Параметры объединяются в управляемых, пользовательских, проектных и локальных областях. Управляемые параметры применяются в первую очередь, когда присутствуют. Среди остальных, более близкая область переопределяет более широкую в порядке локальная, затем проект, затем пользователь. Некоторые параметры также можно устанавливать флагами командной строки или переменными окружения, которые действуют как ещё один слой переопределения. Когда параметр не кажется применяемым, значение, которое вы установили, обычно переопределяется другой областью или переменной окружения.

Чтобы найти неверные файлы параметров, запустите claude doctor из вашего терминала. Он выводит диагностику установки и параметров только для чтения без запуска сеанса. Для полной проверки, которая также предлагает исправления и запрашивает подтверждение перед их применением, запустите /doctor внутри сеанса.

Запустите /status, чтобы увидеть, какие источники параметров активны, включая то, действуют ли управляемые параметры. Чтобы понять, какую область Claude Code использует для данного ключа, см. Приоритет параметров.

Проверьте MCP серверы #

Запустите /mcp, чтобы увидеть ваши серверы и их статус подключения. Сервер может быть определён правильно, но всё ещё не предоставлять инструменты по нескольким распространённым причинам:

  • Серверы с областью действия проекта в .mcp.json требуют одноразового подтверждения. Если вы отклонили запрос, сервер остаётся отключённым. Чтобы снова увидеть запрос, выполните claude mcp reset-project-choices и перезапустите Claude Code. Он снова запросит подтверждение для каждого сервера проекта.
  • Сервер, который не запускается, отображается как failed в /mcp. Относительные пути к файлам в command или args — частая причина, так как они разрешаются относительно каталога, из которого вы запустили Claude Code, а не расположения .mcp.json.
  • Сервер, который показывает как connected, но перечисляет нулевые tools, успешно запустился, но не возвращает список tools. Выберите Reconnect из /mcp. Если количество остаётся нулевым, запустите claude --debug=mcp и прочитайте stderr сервера в журнале отладки по адресу ~/.claude/debug/<session-id>.txt.

Для расположений конфигурации и правил области см. MCP.

Проверьте hooks #

Запустите /hooks, чтобы перечислить каждый хук, зарегистрированный для текущей сессии, сгруппированный по событиям. Если хук, который вы определили, не появляется, Claude Code его не загрузил. Проверьте следующие причины:

  • Хук определён в отдельном файле. Хуки размещаются под ключом "hooks" в файле настроек.
  • Значение matcher — это массив, а не одна строка. Claude Code отображает эту запись как недопустимую настройку при запуске интерактивной сессии и в claude doctor. Если массив находится под PreToolUse или PermissionRequest, ни один из остальных хуков этого файла также не загружается.
  • Хук находится во frontmatter скилла, и ни вы, ни Claude ещё не вызывали этот скилл в текущей сессии. Вызовите его или попросите Claude это сделать, затем снова запустите /hooks. Если хук всё ещё не появляется, проверьте другие причины, например frontmatter, который не удалось разобрать, или одно из ограничений для хуков скиллов.

Если hook появляется, но не срабатывает, обычно причина в matcher. Проверьте его на эти ошибки:

  • Поле matcher — это одна строка, которая использует | для соответствия нескольким именам tools, например "Edit|Write". Разделитель , эквивалентен, поэтому "Edit,Write" соответствует тем же tools. До v2.1.191 запятая переходила к оценке regex и matcher никогда не совпадал, поэтому используйте |, если вы ещё не на v2.1.191.
  • Неправильное имя tool создаёт matcher, который ничему не соответствует, поэтому hook молча не срабатывает.

Когда вы редактируете settings.json, изменение вступает в силу в работающей сессии после краткой задержки стабильности файла, даже если вы создали файл или папку .claude/ проекта после начала сессии. Вам не нужно перезагружаться. До v2.1.257 Claude Code не обнаруживал правки в папке .claude/, созданной после начала сессии.

Если /hooks всё ещё показывает старое определение через несколько секунд после сохранения, запустите /hooks снова, чтобы обновить представление. Если /hooks показывает хук, но он всё ещё не срабатывает, следующий шаг — наблюдать оценку хука в реальном времени. Запустите сессию с claude --debug и инициируйте вызов инструмента. См. Отладка хуков, чтобы узнать формат лога, и устранение неполадок хуков, чтобы узнать о распространённых паттернах сбоев.

Протестируйте с чистой конфигурацией #

Начните с claude --safe-mode, который запускает сессию с отключёнными пользовательскими настройками, включая:

  • CLAUDE.md
  • Скиллы, плагины и хуки
  • MCP-серверы
  • Пользовательские команды и агенты
  • Пользовательские стили вывода
  • Пользовательские сочетания клавиш

Аутентификация, выбор модели, встроенные инструменты и разрешения работают нормально. Если проблема исчезает в безопасном режиме, вы сузили круг причин до одного из отключённых элементов. Чтобы найти его, используйте проверку для соответствующего элемента, например Посмотрите, что загружено в контекст, Проверьте MCP-серверы или Проверьте хуки.

Безопасный режим по-прежнему применяет управляемые хуки и политику настроек от вашей организации. Управляемые плагины, скиллы, CLAUDE.md и MCP-серверы отключены.

Если проблема сохраняется в безопасном режиме или ваши настройки сами по себе вызывают подозрения, запустите сессию без какой-либо вашей собственной конфигурации и проверьте, сохраняется ли проблема.

1. Создайте пустой каталог и перейдите в него

В оболочке, когда ни одна сессия Claude Code не запущена, создайте каталог и перейдите в него:

[tab] Bash или Zsh

```bash theme={null} mkdir -p ~/claude-clean/empty && cd ~/claude-clean/empty

[tab] PowerShell

```powershell theme={null} New-Item -ItemType Directory -Force "$HOME/claude-clean/empty" | Out-Null Set-Location "$HOME/claude-clean/empty"

2. Запустите Claude Code с чистым каталогом конфигурации

В той же оболочке задайте CLAUDE_CONFIG_DIR на новый каталог вместо ~/.claude и передайте --setting-sources user, чтобы отключить конфигурацию проекта, такую как .claude/settings.json, CLAUDE.md и .mcp.json:

[tab] Bash или Zsh

Переменная применяется только к этому запуску.

```bash theme={null} CLAUDE_CONFIG_DIR=~/claude-clean/config claude --setting-sources user

[tab] PowerShell

Переменная остаётся заданной до конца этой сессии PowerShell, поэтому последующие запуски claude в том же окне продолжат использовать чистый каталог. Чтобы вернуться к обычному каталогу, выполните Remove-Item Env:CLAUDE_CONFIG_DIR перед следующим запуском.

```powershell theme={null} $env:CLAUDE_CONFIG_DIR = "$HOME/claude-clean/config" claude --setting-sources user

При первом запуске вы снова пройдёте экраны первоначальной настройки — это признак того, что чистый каталог конфигурации действует. Управляемые настройки по-прежнему применяются, а коннекторы по-прежнему загружаются, если вы входите с учётной записью claude.ai.

3. Воспроизведите проблему

Повторите в чистой сессии то, что вызвало проблему:

  • Проблема исчезла: причина находится в вашей пользовательской или проектной конфигурации. Копируйте ~/.claude.json и файлы из ~/.claude в ~/claude-clean/config по одному. Если ни один из них не возвращает проблему, перейдите в каталог проекта в той же оболочке и запустите Claude Code без --setting-sources user. В Bash или Zsh выполните CLAUDE_CONFIG_DIR=~/claude-clean/config claude. В PowerShell переменная по-прежнему задана, поэтому выполните claude.
  • Проблема сохраняется: причина находится вне вашей пользовательской и проектной конфигурации. Выполните /status в сессии, чтобы проверить наличие управляемых настроек, проверьте переменные окружения в вашей оболочке, затем см. Устранение неполадок.

Проверьте распространённые причины #

Большинство сюрпризов конфигурации восходят к небольшому набору правил расположения и синтаксиса. Проверьте их перед тем, как предположить ошибку:

| Симптом | Причина | Исправление | | :- | :- | :- | | Hook никогда не срабатывает | matcher — это JSON массив вместо строки | Используйте одну строку с \| для соответствия нескольким tools, например "Edit\|Write". См. matcher patterns. | | Hook никогда не срабатывает | matcher использует , как разделитель в версии до v2.1.191 | Claude Code v2.1.191 или позже рассматривает , как разделитель списка, как \|. Более ранние версии оценивают запятую как буквальный символ, поэтому "Edit,Write" ничему не соответствует. Используйте \| вместо этого или обновите Claude Code. | | Hook никогда не срабатывает | значение matcher в нижнем регистре, например "bash" | Соответствие чувствительно к регистру. Имена tools написаны с заглавной буквы: Bash, Edit, Write, Read. | | Hook никогда не срабатывает | Hooks находятся в отдельном файле вместо settings.json | Нет отдельного файла hooks для конфигурации проекта или пользователя. Определите hooks под ключом "hooks" в settings.json. Только plugins загружают отдельный hooks/hooks.json. См. hook configuration. | | Permissions или hooks, установленные глобально, игнорируются | Конфигурация была добавлена в ~/.claude.json | ~/.claude.json содержит состояние приложения и переключатели UI. permissions, hooks и env принадлежат ~/.claude/settings.json. Это два разных файла. | | Значение settings.json кажется игнорируемым | Тот же ключ установлен в settings.local.json | settings.local.json переопределяет settings.json, и оба переопределяют ~/.claude/settings.json. См. settings precedence. | | Skill не появляется в /skills | Файл skill находится в .claude/skills/name.md вместо папки | Используйте папку с SKILL.md внутри: .claude/skills/name/SKILL.md. | | Skill появляется в /skills, но Claude никогда его не вызывает | Skill имеет disable-model-invocation: true в своём frontmatter или его описание не совпадает с тем, как вы формулируете запрос | Проверьте значок в /skills: метка "user-only" означает, что Claude не будет его запускать самостоятельно. См. skill invocation. | | Инструкции в CLAUDE.md подпапки кажутся игнорируемыми | Файлы подпапок загружаются по требованию, а не при запуске сессии | Чтобы загрузить CLAUDE.md подпапки, попросите Claude прочитать другой файл в этой подпапке. См. когда загружаются файлы подпапок. | | Субагент игнорирует инструкции CLAUDE.md | Встроенные агенты Explore и Plan пропускают CLAUDE.md при запуске. Пользовательский субагент загружает его так же, как основной диалог, если только в его определении не задано omitClaudeMd | Для Explore или Plan переформулируйте инструкцию в своём делегирующем промпте. Для субагента, который устанавливает omitClaudeMd, удалите это поле. Для любого другого пользовательского субагента поместите критические инструкции в тело файла агента, которое становится системным промптом агента. См. что загружается при запуске. | | Логика очистки никогда не запускается в конце сессии | Нет настроенного SessionEnd hook | Добавьте SessionEnd hook в settings.json. См. hook events list. | | MCP серверы в .mcp.json никогда не загружаются | Файл находится под .claude/ или его серверы находятся под ключом верхнего уровня servers, как в VS Code mcp.json, вместо mcpServers | Конфигурация MCP проекта находится в корне репозитория как .mcp.json, а не внутри .claude/, с серверами под ключом mcpServers. См. MCP configuration. | | MCP серверы добавлены под mcpServers в settings.json, но никогда не появляются | settings.json не читает ключ mcpServers | Определите серверы проекта в .mcp.json в корне репозитория или запустите claude mcp add --scope user для серверов с областью пользователя. См. MCP configuration. | | Добавлен MCP-сервер проекта, но не появляется | Одноразовый запрос подтверждения был отклонён | Серверы с областью проекта требуют подтверждения. Выполните claude mcp reset-project-choices, перезапустите Claude Code и подтвердите сервер. | | MCP сервер не запускается из некоторых каталогов | command или args использует относительный путь к файлу | Используйте абсолютные пути для локальных скриптов. Исполняемые файлы в вашем PATH как npx или uvx работают как есть. | | MCP сервер запускается без ожидаемых переменных окружения | Конфигурация сервера не устанавливает их, и они не находятся в окружении, которое Claude Code передаёт серверам stdio: его собственное окружение минус переменные, которые он удаляет из подпроцессов | Установите env для каждого сервера внутри записи сервера .mcp.json, что не зависит от окружения запуска или доверия рабочей области. | | Правило отрицания Bash(rm *) не блокирует /bin/rm или find -delete | Правила Bash совпадают с буквальной строкой команды, а не с базовым исполняемым файлом; см. что правило Bash не совпадает | Используйте PreToolUse hook или sandbox для жёсткой гарантии. |
