# Справочник CLI

> Полный справочник по интерфейсу командной строки Claude Code, включая команды и флаги.

## Команды CLI

Вы можете запускать сессии, передавать содержимое, возобновлять диалоги и управлять обновлениями с помощью этих команд:

| Команда | Описание | Пример |
| :- | :- | :- |
| `claude` | Запустить интерактивную сессию | `claude` |
| `claude "query"` | Запустить интерактивную сессию с начальным промптом | `claude "explain this project"` |
| `claude -p "query"` | Запрос через SDK, затем выход | `claude -p "explain this function"` |
| `cat file \| claude -p "query"` | Обработка переданного содержимого | `cat logs.txt \| claude -p "explain"` |
| `claude -c` | Продолжить самый последний диалог в текущем каталоге | `claude -c` |
| `claude -c -p "query"` | Продолжить через SDK | `claude -c -p "Check for type errors"` |
| `claude -r "<session>" "query"` | Возобновить сессию по ID или имени | `claude -r "auth-refactor" "Finish this PR"` |
| `claude update` | Обновить до последней версии | `claude update` |
| `claude gateway` | Запустить сервер самостоятельно размещаемого [Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway) для администраторов, развёртывающих SSO и политики перед Claude Code на Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry. Требует `--config`, указывающий на [`gateway.yaml`](https://code.claude.com/docs/ru/claude-apps-gateway-config). | `claude gateway --config gateway.yaml` |
| `claude install [version]` | Установить или переустановить нативный двоичный файл. Принимает версию, такую как `2.1.118`, или `stable`, или `latest`. См. [Установить конкретную версию](https://code.claude.com/docs/ru/setup.md#install-a-specific-version) | `claude install stable` |
| `claude auth login` | Войти в свою учётную запись Anthropic. Используйте `--email` для предварительного заполнения адреса электронной почты, `--sso` для принудительной аутентификации SSO и `--console` для входа с помощью Anthropic Console с биллингом за использование API вместо подписки Claude | `claude auth login --console` |
| `claude auth logout` | Выйти из своей учётной записи Anthropic | `claude auth logout` |
| `claude auth status` | Показать статус аутентификации в формате JSON. Используйте `--text` для удобочитаемого вывода. Завершается с кодом 0, если вы вошли, и 1, если нет. JSON включает поле `configDirectory` с указанием [каталога конфигурации](https://code.claude.com/docs/ru/claude-directory.md), который использует CLI. Это поле требует Claude Code v2.1.268 или новее. Поле `authMethod` в JSON принимает одно из значений: `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper` или `third_party` | `claude auth status` |
| `claude agents` | Открыть [представление агентов](https://code.claude.com/docs/ru/agent-view.md) для мониторинга и отправки параллельных фоновых сессий. Используйте `--cwd <path>` для отображения только сессий, запущенных в этом каталоге, или `--json` для вывода активных сессий в виде массива JSON для скриптов (`--json --all` также включает завершённые фоновые сессии). Передайте `--permission-mode`, `--model`, `--effort` или `--agent` для установки [значений по умолчанию для отправленных сессий](https://code.claude.com/docs/ru/agent-view.md#permission-mode-model-and-effort). Принимает `--settings`, `--add-dir`, `--plugin-dir` и `--mcp-config`, как и команда верхнего уровня `claude`. Открытие представления агентов требует интерактивного терминала | `claude agents --json` |
| `claude attach <id\|name>` | Подключиться к [фоновой сессии](https://code.claude.com/docs/ru/agent-view.md#manage-sessions-from-the-shell) в этом терминале. Передача части имени работающей сессии вместо ID требует Claude Code v2.1.290 или новее | `claude attach 7c5dcf5d` |
| `claude auto-mode defaults` | Вывести правила классификатора [авторежима](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode), встроенные в Claude Code, в формате JSON. Используйте `claude auto-mode config`, чтобы увидеть эти правила с применёнными вашими настройками. `--label <prefix>` выводит только правила, метка которых начинается с этого префикса, без учёта регистра. Требует Claude Code v2.1.208 или новее | `claude auto-mode defaults --label 'Git Destructive'` |
| `claude auto-mode reset` | Восстановить конфигурацию [авторежима](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) по умолчанию, удалив раздел `autoMode` из файла пользовательских настроек. Запрашивает подтверждение перед записью; передайте `-y`/`--yes`, чтобы пропустить запрос. Правила из [управляемых настроек](https://code.claude.com/docs/ru/server-managed-settings.md) или флага `--settings` по-прежнему применяются. Требует Claude Code v2.1.212 или новее. См. [Проверить значения по умолчанию и вашу действующую конфигурацию](https://code.claude.com/docs/ru/auto-mode-config.md#inspect-the-defaults-and-your-effective-config) | `claude auto-mode reset --yes` |
| `claude daemon logs` | Отслеживать файл лога [супервизора](https://code.claude.com/docs/ru/agent-view.md#the-supervisor-process) фоновых сессий, `~/.claude/daemon.log`, выводя новые строки по мере их появления, пока вы не нажмёте `Ctrl+C` | `claude daemon logs` |
| `claude daemon run` | Запустить [супервизор](https://code.claude.com/docs/ru/agent-view.md#the-supervisor-process) фоновых сессий на переднем плане этого терминала с выводом его лога | `claude daemon run` |
| `claude daemon status` | Вывести состояние [супервизора](https://code.claude.com/docs/ru/agent-view.md#the-supervisor-process) фоновых сессий, версию, каталог сокетов и количество рабочих процессов для диагностики. Завершается с кодом 1, если супервизор не запущен | `claude daemon status` |
| `claude daemon stop --any` | Остановить [супервизор](https://code.claude.com/docs/ru/agent-view.md#the-supervisor-process) фоновых сессий и размещённые им сессии. Передайте `--keep-workers`, чтобы оставить фоновые сессии работающими, и следующий супервизор переподключится к ним. `--any` подтверждает остановку супервизора по требованию, который используется по умолчанию. Используйте это для восстановления после [неотвечающего супервизора](https://code.claude.com/docs/ru/agent-view.md#agent-view-says-the-background-service-did-not-respond) | `claude daemon stop --any --keep-workers` |
| `claude doctor` | Вывести диагностику установки и настроек (только для чтения) из терминала без запуска сессии, включая состояние установки, ошибки валидации файлов настроек и доступность Remote Control. Для проверки настройки внутри сессии, которая также может применять исправления, запустите [`/doctor`](https://code.claude.com/docs/ru/commands#all-commands) | `claude doctor` |
| `claude import [source]` | Запустить интерактивную сессию, которая выполняет [`/import`](https://code.claude.com/docs/ru/commands#all-commands) для переноса конфигурации из других агентов для программирования в Claude Code. Принимает те же опции `--dry-run` и `--yes`, что и команда. Недоступно на Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry или Claude Platform on AWS. Также недоступно, если вы отключили [получение флагов функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching). Требует Claude Code v2.1.213 или новее | `claude import codex --dry-run` |
| `claude logs <id\|name>` | Вывести недавний вывод [фоновой сессии](https://code.claude.com/docs/ru/agent-view.md#manage-sessions-from-the-shell). Передача части имени сессии вместо ID требует Claude Code v2.1.290 или новее | `claude logs 7c5dcf5d` |
| `claude mcp` | Настроить серверы Model Context Protocol (MCP) | См. [документацию Claude Code по MCP](https://code.claude.com/docs/ru/mcp.md). |
| `claude mcp login <name>` | Запустить процесс OAuth настроенного MCP-сервера без открытия интерактивной панели `/mcp`. Работает для HTTP, SSE и серверов коннекторов claude.ai. Добавьте `--no-browser` при работе через SSH, чтобы вывести URL авторизации вместо открытия браузера. Для HTTP- или SSE-сервера вставьте URL перенаправления обратно в поле ввода. Для коннектора claude.ai см. [Повторная авторизация коннектора из оболочки](https://code.claude.com/docs/ru/remote-control.md#authorize-a-connector-again-from-your-shell). См. [Аутентификация из командной строки](https://code.claude.com/docs/ru/mcp.md#authenticate-from-the-command-line) | `claude mcp login sentry` |
| `claude mcp logout <name>` | Очистить сохранённые учётные данные OAuth для MCP-сервера | `claude mcp logout sentry` |
| `claude plugin` | Управлять [плагинами](https://code.claude.com/docs/ru/plugins/overview.md) Claude Code. Псевдоним: `claude plugins`. Подкоманды см. в [справочнике по плагинам](https://code.claude.com/docs/ru/plugins/cli-reference.md#claude-plugin-commands) | `claude plugin install code-review@claude-plugins-official` |
| `claude purge [path]` | Удалить всё локальное состояние Claude Code для проекта: транскрипты, списки задач, логи отладки, историю редактирования файлов, строки истории промптов и запись проекта в `~/.claude.json`. Опустите `[path]`, чтобы выбрать из интерактивного списка. Флаги: `--dry-run` для предпросмотра, `-y`/`--yes` для пропуска подтверждения, `-i`/`--interactive` для подтверждения каждого элемента, `--all` для всех проектов. См. [Очистить локальные данные](https://code.claude.com/docs/ru/claude-directory.md#clear-local-data) | `claude purge ~/work/repo --dry-run` |
| `claude remote-control` | Запустить сервер [Remote Control](https://code.claude.com/docs/ru/remote-control.md) для управления Claude Code из claude.ai или приложения Claude. Псевдоним: `claude rc`. Работает в режиме сервера (без локальной интерактивной сессии). См. [флаги режима сервера](https://code.claude.com/docs/ru/remote-control.md#start-a-remote-control-session). После остановки сервера вы можете вернуть сессии, которые он обслуживал. См. [Возобновить сессии после остановки сервера](https://code.claude.com/docs/ru/remote-control.md#resume-sessions-after-stopping-the-server) | `claude remote-control --name "My Project"` |
| `claude respawn <id>` | Перезапустить [фоновую сессию](https://code.claude.com/docs/ru/agent-view.md#manage-sessions-from-the-shell), работающую или остановленную, с сохранением её диалога. Используйте `--all` для перезапуска всех работающих сессий, например чтобы применить обновлённый двоичный файл Claude Code | `claude respawn 7c5dcf5d` |
| `claude rm <id>` | Удалить [фоновую сессию](https://code.claude.com/docs/ru/agent-view.md#manage-sessions-from-the-shell) из списка. Если Claude Code отказывается удалять сессию из-за её worktree, см. [Удаление сессии после отказа Claude Code](https://code.claude.com/docs/ru/agent-view.md#delete-a-session-after-claude-code-refuses). Транскрипт диалога остаётся на вашем локальном компьютере и доступен через `claude --resume` | `claude rm 7c5dcf5d` |
| `claude self-hosted-runner` | Запустить процесс runner, который регистрирует эту машину или контейнер в [самостоятельно размещаемой среде](https://code.claude.com/docs/ru/self-hosted-environments) и размещает облачные сессии Claude Code на вашей инфраструктуре. Запустите `claude self-hosted-runner setup` для пошагового руководства оператора, `claude self-hosted-runner doctor` для [диагностики развёрнутого runner](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#troubleshooting) и `claude self-hosted-runner orchestrator` для создания [runner по требованию](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#on-demand-runners). Требует Claude Code v2.1.224 или новее | `claude self-hosted-runner setup` |
| `claude setup-token` | Создать долгоживущий OAuth-токен для CI и скриптов. Выводит токен в терминал без сохранения. Требует подписки Claude. См. [Создать долгоживущий токен](https://code.claude.com/docs/ru/authentication.md#generate-a-long-lived-token) | `claude setup-token` |
| `claude stop <id>` | Остановить [фоновую сессию](https://code.claude.com/docs/ru/agent-view.md#manage-sessions-from-the-shell). Также принимается `claude kill` | `claude stop 7c5dcf5d` |
| `claude ultrareview [target]` | Запустить [ultrareview](https://code.claude.com/docs/ru/ultrareview.md#run-ultrareview-non-interactively) неинтерактивно. Выводит результаты в stdout и завершается с кодом 0 при успехе или 1 при ошибке. Используйте `--json` для получения необработанных данных и `--timeout <minutes>`, чтобы переопределить значение по умолчанию в 45 минут. Используйте `--post` с целевым pull request на `github.com`, чтобы опубликовать готовые результаты в PR одним простым комментарием от вашей учётной записи GitHub. По умолчанию используется `--no-post`. `--post` и `--no-post` требуют Claude Code v2.1.227 или новее. См. [Публикация результатов в pull request](https://code.claude.com/docs/ru/ultrareview.md#post-findings-to-the-pull-request) | `claude ultrareview 1234 --json` |

Если вы опечатаетесь в подкоманде, Claude Code предложит ближайшее совпадение и завершит работу без запуска сессии. Например, `claude udpate` выводит `Did you mean claude update?`.

`claude --dangerously-skip-permissions daemon <subcommand>` запускает подкоманду `daemon`, поэтому подкоманда работает, когда для `claude` задан псевдоним, включающий этот флаг. Только стоящий в начале `--dangerously-skip-permissions` или `--allow-dangerously-skip-permissions` направляет к `daemon` таким образом; если перед `daemon` стоит любой другой флаг, подкоманда не выполняется.

## Флаги CLI

Настройте поведение Claude Code с помощью этих флагов командной строки. `claude --help` не выводит каждый флаг, поэтому отсутствие флага в `--help` не означает, что он недоступен.

| Флаг | Описание | Пример |
| :- | :- | :- |
| `--add-dir` | Добавить дополнительные рабочие каталоги для Claude для чтения и редактирования файлов. Предоставляет доступ к файлам; Claude Code [не обнаруживает](https://code.claude.com/docs/ru/permissions.md#additional-directories-grant-file-access-not-configuration) большинство конфигурации `.claude/` из этих каталогов. Проверяет, что каждый путь существует как каталог. Вы не можете добавить большинство [сетевых путей](https://code.claude.com/docs/ru/errors.md#working-directory-is-a-network-path), таких как `\\server\share`. Чтобы сохранить эти каталоги между сеансами, установите [`permissions.additionalDirectories`](https://code.claude.com/docs/ru/settings-reference#permissions-additionaldirectories) в параметрах | `claude --add-dir ../apps ../lib` |
| `--advisor <model>` | Включить инструмент [advisor](https://code.claude.com/docs/ru/advisor.md) на стороне сервера для этого сеанса с псевдонимом модели `fable`, `opus` или `sonnet`, или полным ID модели. Имеет приоритет над параметром `advisorModel` для сеанса. `fable` требует [доступ к Fable](https://code.claude.com/docs/ru/advisor.md#choose-an-advisor-model) | `claude --advisor opus` |
| `--agent` | Указать агента для текущего сеанса (переопределяет параметр `agent`) | `claude --agent my-custom-agent` |
| `--agents` | Определить пользовательские subagents динамически через JSON. Принимает [поля, указанные для subagents, определённых через CLI](https://code.claude.com/docs/ru/sub-agents.md#choose-the-subagent-scope). С `--print` значение может быть вместо этого путём к файлу JSON, содержащему объект; форма файла требует Claude Code v2.1.281 или позже. Claude Code проверяет значение при запуске и выходит при недействительном; см. [`Invalid --agents configuration`](https://code.claude.com/docs/ru/errors#invalid-agents-configuration) для сообщения и для флагов и переменной окружения, которые пропускают проверку. Проверка требует Claude Code v2.1.242 или позже | `claude --agents '{"reviewer":{"description":"Reviews code","prompt":"You are a code reviewer"}}'` |
| `--allow-dangerously-skip-permissions` | Добавить `bypassPermissions` в цикл режима `Shift+Tab` без немедленной активации. Позволяет начать в другом режиме, таком как `plan`, и переключиться на `bypassPermissions` позже. См. [режимы разрешения](https://code.claude.com/docs/ru/permission-modes.md#skip-all-checks-with-bypasspermissions-mode) | `claude --permission-mode plan --allow-dangerously-skip-permissions` |
| `--allowedTools`, `--allowed-tools` | Инструменты, которые выполняются без запроса разрешения, за исключением чтения из [сетевых путей](https://code.claude.com/docs/ru/permissions.md#network-paths). Сопоставление шаблонов см. в разделе [синтаксис правил разрешений](https://code.claude.com/docs/ru/settings-reference.md#permission-rule-syntax). Чтобы ограничить набор доступных инструментов, используйте вместо этого `--tools`. Если указать здесь один из [инструментов отслеживания задач](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability), Claude Code также включает их для сессии | `"Bash(git log *)" "Bash(git diff *)" "Read"` |
| `--append-subagent-system-prompt` | Добавить пользовательский текст в конец системного приглашения каждого [subagent](https://code.claude.com/docs/ru/sub-agents.md), включая вложенные subagents, кроме [forked subagent](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation), который повторно использует приглашение собственной беседы. Применяется только в неинтерактивном режиме с `-p`. Требует Claude Code v2.1.205 или позже | `claude -p --append-subagent-system-prompt "Cite file paths in every answer" "query"` |
| `--append-subagent-system-prompt-file` | Загрузить текст из файла и добавить его к системным приглашениям [subagent](https://code.claude.com/docs/ru/sub-agents.md). Альтернатива `--append-subagent-system-prompt` для текста, слишком длинного для передачи в командной строке. Два флага не могут быть скомбинированы. Применяется только в неинтерактивном режиме с `-p`. Требует Claude Code v2.1.261 или позже | `claude -p --append-subagent-system-prompt-file ./subagent-rules.txt "query"` |
| `--append-system-prompt` | Добавить пользовательский текст в конец системного приглашения по умолчанию | `claude --append-system-prompt "Always use TypeScript"` |

### Флаги системного приглашения

Claude Code предоставляет пять флагов для настройки системного приглашения. Четыре устанавливают его текст, и с `--system-prompt-snapshot` вы контролируете, сохраняет ли беседа текст, с которым она началась. Все пять работают как в интерактивном, так и в неинтерактивном режимах.

| Флаг | Поведение | Пример |
| :- | :- | :- |
| `--system-prompt` | Заменяет весь запрос по умолчанию | `claude --system-prompt "You are a Python expert"` |
| `--system-prompt-file` | Заменяет содержимым файла | `claude --system-prompt-file ./prompts/review.txt` |
| `--append-system-prompt` | Добавляет к запросу по умолчанию | `claude --append-system-prompt "Always use TypeScript"` |
| `--append-system-prompt-file` | Добавляет содержимое файла к запросу по умолчанию | `claude --append-system-prompt-file ./style-rules.txt` |
| `--system-prompt-snapshot` | С `off`, перестраивает запрос при каждом запросе. С `on`, по умолчанию, повторно использует записанный запрос, где [применяется запись](#system-prompt-flags-in-resumed-conversations) | `claude --append-system-prompt "Draft rules" --system-prompt-snapshot off` |

Эти флаги можно комбинировать. Чтобы заменить промпт по умолчанию и при этом добавить собственный текст, передайте `--append-system-prompt` или `--append-system-prompt-file` вместе с `--system-prompt` или `--system-prompt-file`. В Claude Code v2.1.283 или новее можно также передать флаг вместе с его файловой формой, например `--append-system-prompt` с `--append-system-prompt-file`, и Claude Code использует оба.

Например, выполните следующую команду в оболочке, чтобы добавить и руководство по стилю из файла, и одну дополнительную инструкцию:

```bash theme={null}
claude -p --append-system-prompt-file ./style.md --append-system-prompt "Always reply in French" "Summarize README.md"
```

Claude получает системный промпт по умолчанию, за которым следуют содержимое `style.md`, пустая строка и затем `Always reply in French`. Содержимое файла идёт первым, даже если вы передаёте `--append-system-prompt` перед `--append-system-prompt-file`.

Когда текст замены объединяет инструкции, которые одинаковы при каждом запуске, с контекстом, который изменяется при каждом запуске, добавьте строку, содержащую только `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` между инструкциями и контекстом. Claude Code разделяет приглашение в первой такой строке и удаляет эту строку, поэтому часть выше неё остаётся кэшированной, а часть ниже изменяется. Требует Claude Code v2.1.275 или позже. [Кэшировать статическую часть пользовательского приглашения](https://code.claude.com/docs/ru/agent-sdk/modifying-system-prompts.md#cache-the-static-part-of-a-custom-prompt) перечисляет конфигурации, где применяется разделение.

Выбирайте в зависимости от того, подходит ли стандартная идентичность Claude Code для вашей задачи. Используйте флаг добавления, когда Claude должен оставаться помощником по кодированию, который также следует вашим дополнительным правилам: инструкции для каждого вызова, форматирование вывода или контекст домена для скрипта `-p`. Добавление сохраняет стандартное руководство по инструментам, инструкции безопасности и соглашения кодирования, поэтому вы предоставляете только то, что отличается. Используйте флаг замены, когда поверхность, идентичность или модель разрешения отличаются от Claude Code, например некодирующий агент в конвейере, который не смотрит ни один человек. Замена удаляет весь стандартный запрос, включая руководство по инструментам и инструкции безопасности, поэтому вы берёте на себя ответственность за всё, что вашей задаче всё ещё нужно.

Для постоянных персон, которые вы можете переключать и делиться между проектом, используйте [стили вывода](https://code.claude.com/docs/ru/output-styles.md). Для соглашений проекта, которые Claude должен всегда соблюдать, используйте [CLAUDE.md](https://code.claude.com/docs/ru/memory.md). [Руководство Agent SDK по системным приглашениям](https://code.claude.com/docs/ru/agent-sdk/modifying-system-prompts.md#decide-on-a-starting-point) охватывает то же решение более подробно.

#### Флаги системного приглашения в возобновлённых беседах

По умолчанию Claude Code строит системное приглашение один раз, при первом запросе беседы, с текстом из любых флагов системного приглашения, применённых, и записывает его в сеанс. До компактирования беседы каждый более поздний запрос использует это записанное приглашение, включая после возврата к беседе с `--resume` или `--continue`. Если вы передаёте другой текст флага системного приглашения, или ничего, при этом более позднем запуске, он вступает в силу после компактирования беседы или когда вы начинаете новую беседу.

Вне [облачных сеансов](https://code.claude.com/docs/ru/cloud-environments.md), если вы запускаете Claude Code в [bare mode](https://code.claude.com/docs/ru/headless.md#start-faster-with-bare-mode), передав `--bare` или установив `CLAUDE_CODE_SIMPLE=1`, запись остаётся отключённой, если вы не передаёте `--system-prompt-snapshot on`. До v2.1.268 сеансы, которые не [получают флаги функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), включая сеансы на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry, перестраивали запрос при каждом запросе и `--system-prompt-snapshot` не имел эффекта.

Чтобы перестроить запрос при каждом запросе вместо этого, например, пока вы итерируете его формулировку через запуски `--continue`, передайте `--system-prompt-snapshot off`. До v2.1.265 передача любого из флагов системного приглашения также отключала запись, если вы не передавали `--system-prompt-snapshot on`.
