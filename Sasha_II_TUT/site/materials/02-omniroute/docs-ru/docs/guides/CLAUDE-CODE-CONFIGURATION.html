Настройте CLI Claude Code (claude) для работы с OmniRoute — локально или на удалённом VPS — с отдельными профилями для каждой модели, аналогично настройке Codex.

Быстрый старт #

# Запустить Claude Code с локальным OmniRoute (активный контекст определяется автоматически)
omniroute launch

# С удалённым OmniRoute (после `omniroute connect <host>` подключение выполняется автоматически)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Создать профили для каждой модели, а затем запустить один из них
omniroute setup-claude            # записывает ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code использует glm/glm-5.2 через OmniRoute

Как Claude Code подключается к шлюзу #

Код Claude рассказывает о APIAnthropic и указывает на пользовательскую конечную точку с переменными среды (у нее нет флага --base-url ):

ПеременнаяЦель
ANTHROPIC_BASE_URLКорень шлюза URL (код Claude добавляет /v1/messages). Нет суффикса /v1.
ANTHROPIC_AUTH_TOKENОтправлено как Authorization: Bearer … — используйте свой токен доступа OmniRoute /ключ API
ANTHROPIC_API_KEYАльтернатива: отправить как x-api-key. Если оба сета, ANTHROPIC_AUTH_TOKEN выигрывает.
ANTHROPIC_MODELПринудительно использовать конкретную модель (переопределяет значение по умолчанию для средства выбора /model )
CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY1 → встроенное средство выбора /model перечисляет модели claude*/anthropic* из /v1/models
CLAUDE_CODE_MAX_OUTPUT_TOKENSОграничить количество выходных токенов на ответ (например 65536).
CLAUDE_CODE_AUTO_COMPACT_WINDOWПорог токена для автоматического сжатия

Переменные Env читаются один раз при запуске — перезапустите код Claude после их изменения.

Чтобы учетные данные менялись, а не были фиксированной строкой, задайте для apiKeyHelper в ~/.claude/settings.json команду, которая выводит текущие учетные данные на стандартный вывод. Код Claude по умолчанию кэширует выходные данные в течение пяти минут (CLAUDE_CODE_API_KEY_HELPER_TTL_MS переопределяет это) и отправляет значение как в Authorization: Bearer так и x-api-key. Сценарий должен печатать учетные данные и ничего больше. — баннер рядом с ним не помогает помощнику в v2.1.227 +.

Вот как работает Entra ID SSO : scripts/cli/omniroute-sso.mjs token печатает недолговечный токен доступа Entra, который проверяет OmniRoute вместо ключа API. См. docs/security/ENTRA_SSO.md.

omniroute launch устанавливает все это за вас: он разрешает базовый токен URL + из активного контекста (так что omniroute connect <vps> а затем omniroute launch просто работает), проверяет работоспособность сервера и запускает claude.

Атрибуция использования: сеансы и проекты #

OmniRoute группирует запросы каждого ключа API в сеансы агента и записи, которые проект каждый рабочий сеанс (таблица agent_sessions ), поэтому можно указать использование и стоимость для каждого члена команды, для каждого проекта и для каждого сеанса.

Что записывается без какой-либо настройки клиента:

ПолеИсточник
Сессиязаголовок x-claude-code-session-id (то же значение, что и metadata.user_id.session_id), стабильный для каждого сеанса
ПроектСтрока Primary working directory: Код Claude отправляет сообщение своей среды; папки рабочего дерева в .claude/worktrees/ преобразуются в имя репозитория
ВетвьCurrent branch: из статуса git Код Claude отправляется с первым сообщением
Клиентuser-agent (claude-cli/<version>)

Codex (<environment_context><cwd>) и OpenCode (x-opencode-session) распознаются одинаково. Ключи с без журнала включено сохранение только идентификатора сеанса и полей проекта, предоставленных заголовком; ничего, прочитанное из приглашения (путь, ветка), не сохраняется.

Явное название проекта (рекомендуется) #

Рабочий каталог на разных машинах различается, поэтому один и тот же репозиторий может отображаться по разным путям. Вместо этого отправьте проект явно: Claude Code добавляет любые заголовки, перечисленные в ANTHROPIC_CUSTOM_HEADERS к каждому запросу модели, а OmniRoute считывает два из них:

ЗаголовокЦенить
x-omniroute-projectНазвание проекта, например omniroute
x-omniroute-project-repoНормализованный пульт, например github.com/diegosouzapw/OmniRoute

Оба читаются только для указания авторства; они никогда не пересылаются вышестоящему провайдеру.

ANTHROPIC_CUSTOM_HEADERS считывается один раз при запуске, а файлы настроек хранят литеральные значения, поэтому вычисляйте их при запуске кода Claude. Добавьте это в ~/.zshrc или ~/.bashrc и продолжайте запускать claude из папки проекта:

claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    case $common in
      */.git) name=$(basename "$(dirname "$common")") ;;  # repository name, also in worktrees
      *) name=$(basename "$common" .git) ;;                # bare repository (/srv/foo.git)
    esac
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s|[?#].*$||; s#\.git$##')
  else
    name=$(basename "$PWD")                                # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="${ANTHROPIC_CUSTOM_HEADERS:+${ANTHROPIC_CUSTOM_HEADERS}
}x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}

Выражение sed удаляет все учетные данные, строку запроса и фрагмент, встроенные в удаленный URL, а заголовки, уже находящиеся в ANTHROPIC_CUSTOM_HEADERS сохраняются. Расширения IDE запускают Claude Code без вашей оболочки, поэтому их сеансы возвращаются в рабочий каталог.

Алиасы обнаружения — отображение моделей не-Claude в селекторе /model #

Обнаружение моделей шлюза в Claude Code выводит только идентификаторы, начинающиеся с claude или anthropic, поэтому при CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 встроенный селектор /model обычно показывает только модели Claude/Anthropic из OmniRoute — kimi/kimi-k2.6 или glm/glm-5.2 никогда не появляются, хотя маршрутизация для них работает нормально.

OmniRoute может зеркалировать любую включённую модель (и комбо) под идентификатором claude/…, чтобы она проходила этот фильтр и отображалась в селекторе:

kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado

Когда вы выбираете один из них в Claude Code, OmniRoute снимает обёртку claude/, восстанавливая реальный идентификатор перед маршрутизацией, — подлинный идентификатор claude/<real-claude-model> (фактический провайдер Claude OAuth) всегда остаётся нетронутым.

По умолчанию зеркалируются только базовые идентификаторы. При включённом опциональном флаге CATALOG_MIRROR_REFINEMENTS_ENABLED варианты с уровнями reasoning-effort, уже присутствующие в каталоге (например, codex/gpt-6-sol-high), зеркалируются как любые другие идентификаторы, так что Claude Code может выбрать явный уровень усилий, а встроенные идентификаторы auto/*, которые путь запроса не может материализовать, не зеркалируются. То, выводятся ли варианты уровней усилий вообще, по-прежнему определяется OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS — зеркало никогда не добавляет вариант, которого нет в базовом каталоге.

По умолчанию это отключено и управляется трёхуровневым переключателем (приоритет у более конкретного уровня), так что обычный OmniRoute никогда не удваивает свой каталог для клиентов, не использующих Claude Code:

УровеньГде
МодельСтраница сведений о провайдере → переключатель «Отображать в Claude Code» для каждой модели
ПровайдерСтраница сведений о провайдере → переключатель на уровне провайдера (охватывает все его модели)
ГлобальныйНастройки → Флаги функций → EXPOSE_CC_DISCOVERY_ALIASES (по умолчанию выключено)

Переменная окружения EXPOSE_CC_DISCOVERY_ALIASES принудительно включает глобальный уровень и имеет приоритет над переопределением в панели управления (при этом на экране флагов функций отображается пометка «активно через переменную окружения»). Переключатели на уровне провайдера и модели уточняют настройку дальше — например, глобально выключено + провайдер Kimi включён открывает только модели Kimi.

⚠️ Несоответствие окна контекста у моделей, отличных от Claude. Claude Code предполагает окно контекста 200K для любого идентификатора, который не распознаёт (он не может прочитать реальное окно из /v1/models). Для модели с большим окном (например, 256K у Kimi K2) установите CLAUDE_CODE_AUTO_COMPACT_WINDOW в значение ниже реального окна модели, чтобы автосжатие не срабатывало преждевременно. Сгенерированные выше профили уже делают это для каждой модели.

Блок первоначальной настройки на панели управления #

Карточка инструмента Claude (Панель управления → CLI Code) отображает точный фрагмент settings.json для этого экземпляра рядом с кнопкой информации о псевдониме обнаружения, а также кнопку копирования:

{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<адрес вашего OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<ваш API-ключ OmniRoute>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}

Базовый URL — это адрес, определённый карточкой (включая введённое вами пользовательское переопределение) и уже нормализованный: без суффикса /v1 и завершающей косой черты. Ключ никогда не отображается: блок содержит заполнитель, поэтому ключ не может утечь через снимок экрана или вставленный фрагмент. Замените заполнитель своим ключом.

Добавьте CLAUDE_CODE_AUTO_COMPACT_WINDOW в тот же блок env для любой модели, реальное контекстное окно которой не равно 200K: Claude Code предполагает размер 200K для каждого нераспознанного идентификатора, поэтому в противном случае автоматическое сжатие срабатывает в неверный момент (см. предупреждение в предыдущем разделе). Конструктор фрагмента также принимает это значение, поэтому вызывающая сторона, которой известен размер окна целевой модели, может указать его напрямую.

Источник: src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet (чистый конструктор, покрытый модульными тестами), отображаемый компонентом ClaudeGatewayOnboardingBlock.

Закрепление одной учётной записи (необязательно) #

Чтобы направлять каждый запрос Claude Code через одну конкретную учётную запись провайдера, добавьте заголовок x-omniroute-connection посредством ANTHROPIC_CUSTOM_HEADERS в тот же блок env:

"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"

Скопируйте идентификатор из элемента xxxxxxxx… в строке подключения на странице провайдера. Закрепление применяется только к идентификаторам отдельных моделей (provider/model), но не к комбинациям. Точное поведение при откате описано в разделе Закрепление учётной записи для каждого запроса.

Профили (CLAUDE_CONFIG_DIR) #

В Claude Code нет встроенных файлов профилей (в отличие от ~/.codex/<name>.config.toml в Codex). Стандартным механизмом является CLAUDE_CONFIG_DIR — отдельный каталог конфигурации для каждого профиля, каждый из которых содержит собственные settings.json, учётные данные, историю и кеш.

omniroute setup-claude получает актуальный каталог /v1/models и создаёт по одному профилю для каждой модели в ~/.claude/profiles/<name>/settings.json, используя те же имена, что и setup-codex (glm52, kimi-k27, deepseek-pro, …):

// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}

Токен аутентификации никогда не записывается в профиль. Запускайте с помощью omniroute launch --profile <name> (команда подставляет ANTHROPIC_AUTH_TOKEN из активного контекста) либо самостоятельно экспортируйте ANTHROPIC_AUTH_TOKEN и выполните CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude.

Автосинхронизация после обнаружения моделей (по желанию). OmniRoute может автоматически повторно создавать те же файлы ~/.claude/profiles/<name>/settings.json всякий раз, когда синхронизация моделей провайдера изменяет актуальный каталог, — таким образом, новые или переименованные модели получают профили без повторного запуска команды. По умолчанию эта функция отключена: включите её на панели CLI Code («Автосинхронизация профилей CLI» → Claude Code) или задайте OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true (также учитывается CLI_ALLOW_CONFIG_WRITES, включённая по умолчанию). Когда функция включена, она записывает только файлы профилей и никогда не изменяет активную конфигурацию Claude или конфигурацию Claude по умолчанию, данные аутентификации либо ~/.claude/settings.json.

Создание и использование профилей #

# Локальный OmniRoute
omniroute setup-claude

# Удалённый VPS (URL-адрес VPS записывается в каждый профиль)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Только некоторые провайдеры
omniroute setup-claude --only glm,kimi

# Также создавать профили для провайдеров локальных CLI (zcode, auggie, devin-cli-agentic,
# codex-app-server), не обнаруженных на этом хосте (по умолчанию пропускаются для локальной цели)
omniroute setup-claude --include-local

# Предварительный просмотр без записи
omniroute setup-claude --dry-run

# Запуск профиля
omniroute launch --profile kimi-k27

Уровни моделей (необязательно) #

Claude Code распределяет запросы по уровням возможностей. При необходимости сопоставьте каждый уровень с моделью OmniRoute через переменные окружения / настройки, чтобы использовать разных провайдеров для разных уровней:

export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"

В противном случае для всех запросов используется одна модель из ANTHROPIC_MODEL (её задают профили).

Удалённый режим #

После выполнения omniroute connect <host> (см. Удалённый режим) команды omniroute launch и omniroute setup-claude автоматически обращаются к этому удалённому серверу и используют связанный с ним токен доступа — дополнительные флаги не требуются. Переопределить настройки для отдельного вызова можно с помощью --remote / --api-key.

Устранение неполадок #

Claude Code игнорирует шлюз — убедитесь, что ANTHROPIC_BASE_URL не содержит /v1, и перезапустите claude (переменные окружения считываются один раз при запуске). omniroute launch сделает это за вас.

Средство выбора /model пусто / модели шлюза отсутствуют — требуется Claude Code v2.1.219+ и CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1. В средстве выбора отображаются только идентификаторы моделей claude* / anthropic*; чтобы принудительно использовать любую другую модель, задайте ANTHROPIC_MODEL=<id> (именно это делают профили).

400 Ambiguous model 'claude-…' — Claude Code всегда отправляет идентификаторы моделей без префикса (например, claude-opus-4-8), поэтому, когда одновременно подключены провайдеры Claude Code (cc/…) и Claude (claude/…), идентификатор без префикса соответствует двум маршрутам, и OmniRoute отказывается выбирать автоматически. Исправить это можно одним из двух способов: явно укажите идентификатор с префиксом через ANTHROPIC_MODEL=cc/claude-opus-4-8 или включите параметр Предпочитать Claude Code для моделей Claude без префикса — с помощью переключателя на странице провайдера Claude или OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true (по умолчанию отключено; см. Переменные окружения) — тогда идентификаторы claude-* без префикса будут направляться в Claude Code. Явные префиксы провайдеров всегда имеют приоритет.

Ошибки аутентификации — профиль не содержит токен. Используйте omniroute launch --profile (эта команда внедряет токен) или экспортируйте ANTHROPIC_AUTH_TOKEN.

Профили не изолированы — каждый профиль использует отдельный CLAUDE_CONFIG_DIR; убедитесь, что внутри сеанса команда echo $CLAUDE_CONFIG_DIR указывает на ~/.claude/profiles/<name>.
