Агентная разработка с Claude Code #

Актуально на 31 мая 2026 (v2.1.158). Всё проверено по официальной документации

Что такое агентная разработка #

Claude Code — это не чат-бот, которому ты задаёшь вопросы. Это агент: он сам читает файлы, запускает команды, вносит изменения и проверяет результат. Ты описываешь, что нужно сделать, а он разбирается как.

Это меняет подход к работе. Вместо "пишу код → прошу проверить" — "описываю задачу → агент реализует → я ревьюю результат".

Часть 1. Настройка окружения #

1.1 CLAUDE.md — мозг проекта #

CLAUDE.md — файл, который Claude читает в начале каждой сессии. Это как онбординг-документ для нового разработчика, только для ИИ.

Создание: /init — Claude анализирует проект и генерирует стартовый файл. Дальше допиливаете руками.

Что включать:

  • Команды сборки и тестов, которые Claude не может угадать
  • Стиль кода, если он отличается от стандартного
  • Архитектурные решения, специфичные для проекта
  • Инструкции по тестированию
  • Конвенции по веткам и коммитам
  • Переменные окружения и особенности dev-среды
  • Частые грабли, которые не очевидны из кода

Что НЕ включать:

  • То, что Claude может понять из кода самостоятельно
  • Стандартные конвенции языка (Claude их знает)
  • Подробную API-документацию (лучше дать ссылку)
  • Информацию, которая часто меняется
  • Описание каждого файла в проекте
  • Самоочевидные вещи вроде "пиши чистый код"

Пример:

# Стиль кода
- ES modules (import/export), не CommonJS (require)
- Деструктуризация импортов где возможно

# Рабочий процесс
- После серии изменений — запускай typecheck
- Запускай отдельные тесты, не весь suite — для скорости

# Тесты
- Фреймворк: vitest
- Команда: pnpm test
- Для одного файла: pnpm test -- path/to/test.ts

# Git
- Ветки: feature/TASK-123-краткое-описание
- Коммиты: conventional commits (feat:, fix:, refactor:)

Правило: держите CLAUDE.md до ~200 строк. Если файл разбухает — Claude начинает игнорировать инструкции. Переносите справочные материалы в Skills.

Где размещать:

  • ~/.claude/CLAUDE.md — глобальные правила для всех проектов
  • ./CLAUDE.md — правила проекта (коммитьте в git, чтобы шарить с командой)
  • Поддиректории — Claude подгружает по мере работы с файлами в них

1.2 Plugins — расширения из маркетплейса #

Plugins — экосистема расширений для Claude Code. Плагины устанавливаются из маркетплейса и могут добавлять новые инструменты, skills и даже исполняемые файлы.

Ключевое:

  • Плагины могут поставлять executables в bin/ и вызывать их из Bash
  • Конфигурация через manifest.userConfig при включении
  • Организации могут ограничивать доступные плагины через allowedChannelPlugins
  • CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE — сохранять кеш маркетплейса при проблемах с сетью (для offline-сред)
  • Background monitors — ключ monitors в манифесте плагина автоматически запускает фоновый мониторинг при старте сессии или вызове skill
  • Auto-install зависимостей (v2.1.116): /reload-plugins и фоновое авто-обновление доставят отсутствующие зависимости плагина из уже подключённых маркетплейсов — не нужно ставить руками
  • claude plugin prune (v2.1.121) — удаляет осиротевшие автоустановленные зависимости плагинов
  • --plugin-dir принимает .zip-архивы плагинов наряду с директориями (v2.1.128); --plugin-url <url> — загрузка и установка плагина из URL (v2.1.129)
  • Манифест плагина: themes и monitors теперь объявляются внутри ключа "experimental": { ... } (v2.1.129)
  • Зависимости плагинов (v2.1.143): claude plugin disable отказывается выключать плагин, на который ссылается другой включённый, и показывает копируемую disable-chain. claude plugin enable авто-включает транзитивные зависимости
  • claude plugin details <name> (v2.1.139) и /plugin-браузер (v2.1.143) показывают компонент-инвентарь и projected per-session token cost — оценку расхода контекста до установки
  • Плагин с корневым SKILL.md без папки skills/ автоматически экспонируется как skill (v2.1.142)
  • /plugin browse и discover показывают дату последнего обновления плагина (v2.1.144) и компонент-инвентарь ещё до установки (v2.1.145); после enable/disable/uninstall возвращает к списку Installed. Discover tab (v2.1.154) закрепляет плагины с пометкой «suggested for this directory» по relevance-сигналам текущего каталога
  • defaultEnabled: false в plugin.json или marketplace entry (v2.1.154) — плагин ставится, но не включается, пока пользователь не сделает это вручную через /plugin или claude plugin enable; зависимости включённых плагинов по-прежнему подтягиваются автоматически
  • Плагины в .claude/skills/ автоматически загружаются без маркетплейса (v2.1.157); claude plugin init <name> — scaffold нового плагина в этой директории. Автодополнение для аргументов /plugin: subcommands, имена установленных плагинов и плагины из подключённых маркетплейсов

1.3 Permissions — баланс безопасности и скорости #

По умолчанию Claude спрашивает разрешение на каждое действие. После десятого "yes" вы уже не читаете, а просто жмёте.

Три решения:

  1. Allowlist через /permissions — разрешаете безопасные команды:
  2. npm run lint, git commit, pnpm test — спрашивать не будет
  1. /sandbox — OS-уровень изоляции (seatbelt на macOS, bubblewrap на Linux). Агент работает в песочнице — значительно меньше вопросов, но безопасно.
  2. sandbox.failIfUnavailable — exit с ошибкой, если sandbox не может запуститься (для CI/enterprise)
  1. YOLO-режим (--dangerously-skip-permissions) — для одноразовых задач в изолированной ветке. Используйте только в sandbox без интернета.
  1. --channels — relay запросов на разрешение на телефон. Для headless/remote сессий.
  1. /less-permission-prompts (v2.1.111) — skill сканирует ваши транскрипты, находит часто используемые read-only Bash/MCP вызовы и предлагает добавить их в allowlist .claude/settings.json. Быстрый способ убрать рутинные prompts без разбора каждой команды руками.

Sandbox network filtering: sandbox.network.deniedDomains (v2.1.113) — блокирует конкретные домены, даже если они покрыты wildcard в allowedDomains. Нужно, когда хочется "разрешить *.example.com, кроме eval.example.com".

1.3 Hooks — автоматизация без вариантов #

Hooks — это скрипты, которые запускаются автоматически на определённые события. В отличие от CLAUDE.md (советы), hooks — детерминистичные: действие гарантированно произойдёт.

Типы обработчиков:

  • Command — запуск shell-команды (получает JSON через stdin)
  • Prompt — отправка промпта модели для одноразовой проверки
  • Agent — спавн субагента с доступом к Read, Grep, Glob
  • HTTP — HTTP-запрос (поддерживается для WorktreeCreate и других событий)
  • MCP tool (type: "mcp_tool") — вызов MCP-инструмента напрямую из хука (v2.1.118)

События хуков:

  • PreToolUse / PostToolUse — до/после вызова инструмента
  • Notification — когда Claude хочет привлечь внимание
  • CwdChanged — смена рабочей директории (полезно для direnv)
  • FileChanged — изменение файла на диске
  • TaskCreated — создание задачи через TaskCreate
  • PermissionDenied — после отказа auto mode классификатора (можно вернуть {retry: true})
  • PreCompact — перед сжатием контекста. Вернуть exit code 2 или {"decision":"block"} — заблокировать компакцию
  • MessageDisplay (v2.1.152) — преобразование или скрытие текста ответа ассистента в момент его отображения

Условные хуки: поле if фильтрует когда хук срабатывает (синтаксис как у permission rules).

"defer" permission: PreToolUse хук может вернуть permissionDecision: "defer" — headless сессия паузится и продолжается через --resume.

Hooks в frontmatter агента (v2.1.116): ключ hooks: в frontmatter субагента теперь срабатывает и при запуске этого агента как main-thread через --agent. Раньше работало только в «вложенном» режиме.

duration_ms в PostToolUse (v2.1.119): PostToolUse и PostToolUseFailure хуки получают поле duration_ms — длительность выполнения инструмента в миллисекундах.

Замена вывода инструмента (v2.1.121): PostToolUse хук может вернуть hookSpecificOutput.updatedToolOutput для любого инструмента — Claude увидит изменённый результат вместо оригинального.

Exec-форма команд (v2.1.139): поле args: string[] в хуке спавнит команду напрямую без shell — путь-плейсхолдеры не требуют квотинга.

continueOnBlock (v2.1.139): PostToolUse с этим флагом отдаёт reject reason обратно модели и продолжает turn, вместо того чтобы прерывать его.

Уровень эффорта в хуках (v2.1.133): поле effort.level в JSON input и переменная $CLAUDE_EFFORT доступны хукам; Bash-команды Claude тоже видят $CLAUDE_EFFORT.

terminalSequence в JSON-выводе хука (v2.1.141): позволяет эмитить desktop-нотификации, заголовок окна и bell даже когда у хука нет controlling terminal.

Stop / SubagentStop input (v2.1.145): эти хуки получают поля background_tasks и session_crons — состояние фоновых задач и запланированных /loop-кронов на момент остановки. Полезно для cleanup-логики и репортинга «что осталось висеть».

SessionStart hook (v2.1.152): может вернуть reloadSkills: true — пересканировать директории skills (skill, установленный самим хуком, станет доступен в той же сессии), и задать заголовок сессии через hookSpecificOutput.sessionTitle при старте и resume.

Практические примеры:

Auto-format после каждого редактирования:

{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{
        "type": "command",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }]
    }]
  }
}

Десктоп-уведомление когда Claude закончил:

{
  "hooks": {
    "Notification": [{
      "matcher": "",
      "hooks": [{
        "type": "command",
        "command": "osascript -e 'display notification \"Claude нужно ваше внимание\" with title \"Claude Code\"'"
      }]
    }]
  }
}

Блокировка записи в папку миграций:

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{
        "type": "command",
        "command": "echo $CLAUDE_FILE_PATH | grep -q 'migrations/' && exit 1 || exit 0"
      }]
    }]
  }
}

Настройка: Claude может сам написать hooks — попросите: "Write a hook that runs eslint after every file edit".

Файл: .claude/settings.json — коммитьте в репозиторий, тогда hooks автоматически применяются для всех членов команды.

Для enterprise: managed-settings.d/ — drop-in директория для фрагментов политик рядом с managed-settings.json. Позволяет разным командам добавлять свои правила независимо. OS CA certificate store используется по умолчанию — корпоративные TLS-прокси работают без дополнительной настройки (CLAUDE_CODE_CERT_STORE=bundled для отката).

Лимиты: вывод хука >50K символов сохраняется на диск (в контекст попадает путь + превью).

1.4 MCP — подключение внешних сервисов #

MCP (Model Context Protocol) — протокол для подключения внешних инструментов.

Подключение: claude mcp add <name> -- <command>

Полезные MCP-серверы:

  • GitHub — работа с issues, PR, code review прямо из Claude
  • PostgreSQL/MySQL — запросы к БД на естественном языке
  • Playwright — браузерная автоматизация и e2e-тесты
  • Context7 — актуальная документация библиотек (нужная версия, не training data)
  • Figma — генерация кода из дизайна
  • Sentry — анализ ошибок в мониторинге
  • Slack — отправка уведомлений

MCP Tool Search — если у вас >10 MCP-инструментов, они жрут контекст. Tool Search автоматически подгружает только нужные. Значительная экономия контекста. Включается автоматически (когда tool descriptions занимают >10% контекста). Управляется через ENABLE_TOOL_SEARCH=auto (по умолчанию), auto:N (кастомный порог в %) или false. alwaysLoad: true в конфиге конкретного сервера — отключает deferral для него (v2.1.121).

Лимиты MCP: описания инструментов и серверных инструкций ограничены 2KB. Если MCP-сервер настроен и локально, и через claude.ai — дедупликация (локальная конфигурация побеждает).

Большие результаты MCP: аннотация _meta["anthropic/maxResultSizeChars"] позволяет инструментам возвращать до 500K символов (для схем БД и т.п.).

MCP OAuth: теперь следует RFC 9728 (Protected Resource Metadata discovery).

Быстрый старт MCP (v2.1.116): при нескольких stdio-серверах запуск ускорен — resources/templates/list deferred до первого @-mention. Если у вас 5+ MCP-серверов, разница заметная.

Надёжность MCP (v2.1.121): серверы с временными ошибками авто-ретраят до 3 раз перед тем, как сообщить о сбое. /mcp показывает количество инструментов для каждого подключённого сервера и предупреждает о серверах с нулём инструментов (v2.1.128). Имя workspace зарезервировано — не называйте им свой MCP-сервер (v2.1.128).

MCP видит CLAUDE_PROJECT_DIR (v2.1.139): stdio-серверы получают эту переменную в окружении (раньше — только хуки); плагины могут ссылаться на ${CLAUDE_PROJECT_DIR} в командах MCP-конфигурации.

MCP_TOOL_TIMEOUT (v2.1.142): теперь реально поднимает per-request fetch timeout у remote HTTP/SSE серверов. Раньше всё капалось на 60с независимо от значения переменной.

Пагинация tools/list (v2.1.144): MCP-серверы, возвращающие список инструментов несколькими страницами, больше не теряют всё, кроме первой. Если у вас был сервер с >100 tools и часть пропадала — это была эта бага.

Окружение MCP-подпроцессов (v2.1.154): stdio-серверы получают переменные CLAUDE_CODE_SESSION_ID и CLAUDECODE=1 — можно различать инвокацию из Claude Code и привязывать логи к сессии. claude mcp list/get (v2.1.154) показывает неподтверждённые .mcp.json-серверы как ⏸ Pending approval вместо неявного автоконнекта, когда вывод пайпится.

1.5 Skills — знания по запросу #

Skills — это markdown-файлы с инструкциями и workflows, которые Claude подгружает по необходимости. В отличие от CLAUDE.md (грузится всегда), skills грузятся только когда нужны.

Встроенные skills:

  • /review — код-ревью локально
  • /ultrareview (v2.1.111) — облачный код-ревью с параллельным мультиагентным анализом. Без аргументов — текущие изменения, /ultrareview <PR#> — конкретный GitHub PR. С v2.1.113 запускается быстрее (параллельные проверки) и показывает diffstat в launch-диалоге. claude ultrareview [target] (v2.1.120) — неинтерактивная версия для скриптов
  • /debug — автоматическая отладка
  • /security-review — аудит безопасности
  • /batch — массовые операции через worktrees (до 30 PR)
  • /code-review (v2.1.147, переименован из /simplify) — отчёт о correctness-багах на выбранном effort level (/code-review high). Флаг --comment постит находки как inline-review-комментарии в GitHub PR. Флаг --fix (v2.1.152) применяет находки прямо в рабочее дерево
  • /simplify (v2.1.154) — снова отдельный cleanup-only review (reuse, simplification, efficiency, altitude) с авто-применением фиксов; багов не ищет — для bug-hunting используйте /code-review
  • /workflows (v2.1.154) — dynamic workflows: попросите Claude собрать workflow, и он оркестрирует от десятков до сотен фоновых агентов под одну крупную задачу. Команда показывает запущенные runs. Слово «workflow» в промпте триггерит создание; отключается настройкой «Workflow keyword trigger» в /config
  • /loop — запуск промпта/команды по интервалу (/loop 5m /foo). С v2.1.113: Esc отменяет запланированные wakeups
  • /recap (v2.1.108) — краткое саммари сессии: что произошло с прошлого раза. Автоматически включается когда возвращаетесь к длительной сессии, управляется через /config
  • /tui fullscreen (v2.1.110) — переключает текущий диалог в fullscreen-режим без мерцания (без пересоздания сессии)
  • /focus (v2.1.110) — toggle focus view (раньше был на Ctrl+O, теперь это отдельная команда; Ctrl+O теперь переключает verbose-транскрипт)
  • /undo (v2.1.108) — алиас для /rewind
  • /less-permission-prompts (v2.1.111) — анализ транскриптов и предложение allowlist
  • /powerup — интерактивные уроки по фичам Claude Code с анимированными демо
  • /release-notes — интерактивный выбор версии для просмотра изменений
  • /team-onboarding — генерирует гайд по онбордингу для нового члена команды на основе локальной истории использования Claude Code
  • /proactive — алиас для /loop
  • /usage (v2.1.118) — объединяет бывшие /cost и /stats: детализация расходов по моделям, cache-hit и статистика сессии

Удалённые команды: /tag и /vim — удалены. Vim mode теперь включается через /config.

Модель сама видит slash-команды (v2.1.108): Claude может обнаруживать и вызывать встроенные команды (/init, /review, /security-review и др.) через Skill tool — не нужно вручную командой запускать, если по контексту понятно, что стоит применить.

/skills menu (v2.1.111): нажмите t чтобы сортировать скиллы по оценённому размеру в токенах — удобно искать кандидатов на удаление при переполненном контексте. С v2.1.121 — поиск по тексту прямо в меню (type-to-filter).

Skills и effort level (v2.1.120): в тексте skill можно использовать ${CLAUDE_EFFORT} — подставляет текущий уровень усилий (low/medium/high/xhigh/max).

skillOverrides (v2.1.129): настройка в settings.json — "off" (отключить все skills), "user-invocable-only" (только по slash-команде пользователя), "name-only" (показывать без описания, экономит контекст).

/reload-skills (v2.1.152) — пересканировать директории skills без перезапуска сессии. disallowed-tools в frontmatter skill или slash-команды (v2.1.152) — убирает указанные инструменты у модели, пока skill активен.

Безопасность skills: настройка disableSkillShellExecution запрещает inline shell-выполнение в skills и плагинах.

Свои skills: создавайте в .claude/skills/:

# .claude/skills/deploy/SKILL.md
---
name: deploy
description: Deployment checklist for production
---
# Deploy Workflow
1. Run full test suite
2. Check for pending migrations
3. Build production bundle
4. ...

Вызов: /deploy

Когда что использовать:

  • CLAUDE.md → "всегда делай X" (правила, конвенции)
  • Skills → справочные материалы и workflows по запросу
  • Hooks → "обязательно делай X" (гарантированная автоматизация)
  • MCP → подключение к внешним сервисам
  • Plugins → расширения из маркетплейса

1.6 Субагенты — изоляция контекста #

Субагенты — это агенты с собственным контекстным окном. Они исследуют, возвращают резюме, не засоряя вашу основную сессию.

Создание: .claude/agents/security-reviewer.md

---
name: security-reviewer
description: Reviews code for security vulnerabilities
tools: Read, Grep, Glob, Bash
model: opus
initialPrompt: "Scan all source files for OWASP Top 10 vulnerabilities"
---
You are a senior security engineer. Review code for:
- Injection vulnerabilities
- Auth flaws
- Secrets in code
- Insecure data handling

initialPrompt — автоматически отправляет первый промпт при запуске агента (без ручного ввода).

paths: в frontmatter — YAML-список глобов для ограничения скоупа (работает и для skills/rules).

mcpServers: в frontmatter агента (v2.1.117) — подгружается и при запуске агента как main-thread через --agent, не только в качестве субагента.

Использование: "use a subagent to review this code for security" или Claude сам делегирует задачу. Именованные субагенты доступны через @ mention в typeahead.

Главная ценность: субагент может прочитать десятки файлов, но в ваш контекст вернётся только краткое резюме.

claude agents — agent view (Research Preview, v2.1.139): единая панель со всеми сессиями Claude Code — running, blocked-on-you, done. Удобно, когда параллельно крутятся 5+ агентов и нужно быстро увидеть, кто ждёт ввода. Флаги (v2.1.141–143):

  • --cwd <path> — сузить дашборд до конкретной директории
  • --add-dir, --settings, --mcp-config, --plugin-dir — пробрасываются в фоновые сессии, диспатчируемые из вьюхи
  • --permission-mode, --model, --effort, --dangerously-skip-permissions — дефолты для дочерних сессий

Идле-сессии в фоне ретайрятся демоном через 5 минут (v2.1.141), state модели/effort сохраняется между засыпаниями (v2.1.143).

Pinned background sessions (v2.1.147): Ctrl+T в claude agents закрепляет фоновую сессию — не засыпает по idle-таймауту, перезапускается in-place при обновлении Claude Code, выгружается под memory pressure только после непиннированных. Удобно для long-running babysit/CI-watch агентов.

claude agents --json (v2.1.145) — список живых сессий в JSON-формате для скриптов. Терминальный таб-заголовок процесса claude agents показывает количество сессий, ждущих ввода.

! <command> и claude --bg --exec '<command>' (v2.1.154): запуск shell-команды как фоновой сессии прямо из claude agents с возможностью attach/detach. ←← для открытия agents view теперь работает на Bedrock/Vertex/Foundry и при отключённой телеметрии; /logout в этой вьюхе реально выходит из аккаунта (раньше отправлял в background-сессию).

agent-дефолт (v2.1.157): поле agent в settings.json задаёт субагента по умолчанию для dispatched-сессий, --agent <name> — override per-launch.

Часть 2. Рабочие паттерны #

2.1 Главное правило: контекстное окно — ваш главный ресурс #

Контекстное окно вмещает всю историю: ваши сообщения, прочитанные файлы, вывод команд. Когда оно заполняется — качество деградирует.

Мониторинг: настройте status line для отслеживания заполненности контекста. Токены >=1M отображаются как "1.5m". В JSON-инпут status line передаются GitHub-репозиторий и PR-информация текущего worktree (v2.1.145) — можно показывать PR-номер/статус прямо в строке статуса.

Что делать:

  • /clear между несвязанными задачами
  • /compact чтобы сжать историю (можно с инструкцией: /compact Фокус на API-изменениях)
  • Субагенты для исследований, которые читают много файлов
  • /btw для быстрых вопросов — ответ не попадает в историю
  • Claude сам предложит /clear после 75+ минут бездействия
  • /recap — краткое саммари, что произошло в сессии. Удобно когда вернулись после паузы
  • /resume на больших сессиях: с v2.1.116 до 67% быстрее на файлах 40MB+, корректно обрабатывает dead-fork записи. Раньше /branch падал на транскриптах >50MB, /resume мог молча показывать пустой диалог — теперь обе проблемы исправлены

Autocompact: если контекст заполняется снова после 3 подряд компакций — Claude детектирует thrash loop и предупреждает.

/goal <условие> (v2.1.139) — задаёте критерий завершения, Claude продолжает работать через несколько turns, пока условие не выполнено. Оверлей-панель с elapsed/turns/tokens. Работает в interactive, -p и Remote Control.

Rewind → "Summarize up to here" (v2.1.141): новый пункт в /rewind-меню — сжимает старый контекст, оставляя свежие turns нетронутыми. Альтернатива /compact, когда нужно убрать только хвост истории.

Рендеринг: CLAUDE_CODE_NO_FLICKER=1 — alt-screen рендеринг без мерцания (виртуализированный scrollback). CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1 (v2.1.132) — наоборот, отказаться от fullscreen alt-screen и оставить диалог в обычном scrollback терминала. /scroll-speed (v2.1.139) — настройка скорости mouse wheel с live preview. С v2.1.110: Ctrl+O теперь toggle между обычным и verbose-транскриптом, focus view вынесен в отдельную команду /focus. /tui fullscreen — переключить текущую сессию в fullscreen без перезапуска. Настройка autoScrollEnabled отключает авто-прокрутку. В fullscreen: Shift+↑/↓ скроллит viewport при выделении, Ctrl+A/Ctrl+E — в начало/конец строки (v2.1.113). С v2.1.116: /terminal-setup настраивает чувствительность скролла в VS Code, Cursor, Windsurf — fullscreen-скролл стал плавным. Thinking-спиннер показывает прогресс инлайн ("still thinking" → "thinking more" → "almost done"), отдельная строка-хинт больше не нужна. С v2.1.121: набор текста в fullscreen больше не сбрасывает viewport к низу; диалоги (permissions, settings) теперь прокручиваемые. CLAUDE_CODE_FORCE_SYNC_OUTPUT=1 (v2.1.129) — принудительная синхронизация terminal output для сред с буферизацией вывода.

Prompt cache TTL: ENABLE_PROMPT_CACHING_1H=1 (v2.1.108) — 1-часовой TTL на API-key, Bedrock, Vertex, Foundry (раньше только на Bedrock). FORCE_PROMPT_CACHING_5M=1 — форсировать 5 минут. Это существенно меняет экономику длинных сессий.

2.2 Правильный workflow: Explore → Plan → Implement → Verify #

Новая задача → Оцени размер → Простая? Сразу в Implement. Сложная? Начни с Explore.

  1. Explore (Plan Mode, Shift+Tab) — прочитай код, разберись в архитектуре
  2. Plan — опиши что хочешь, Claude предложит план, скорректируй (Ctrl+G или Ctrl+X Ctrl+E — редактировать промпт во внешнем редакторе)
  3. Implement (Normal Mode) — Claude пишет код → запускает тесты → фиксит ошибки
  4. Verify — тесты, линтер, /review, /code-review high после больших фич
  5. Всё ок? Да → Commit & PR. Нет → назад в Implement с фидбеком.

Застрял 2 раза на одном месте? /clear + лучший промпт → назад к Plan. Не продолжай с загрязнённым контекстом.

Очень большая фича? Interview-паттерн → SPEC.md → /clear → новая сессия для реализации по спеку.

Explore (Plan Mode):

[Shift+Tab переключает в Plan Mode]
Прочитай src/auth/ и разберись как работают сессии и логин.

Plan:

Я хочу добавить Google OAuth. Какие файлы нужно изменить?
Какой будет flow? Составь план.

Ctrl+G (или Ctrl+X Ctrl+E) — открыть текущий промпт во внешнем текстовом редакторе для правки.

Implement:

[Switch back to Normal Mode]
Реализуй OAuth flow по плану. Напиши тесты для callback handler,
запусти тесты и исправь ошибки.

Verify: всегда давайте Claude способ проверить свою работу — тесты, скриншоты, ожидаемый результат. Это самое важное, что можно сделать для качества.

Когда пропускать план: если задача маленькая и вы можете описать diff одним предложением — делайте напрямую.

2.3 Параллельная работа: Git Worktrees #

claude --worktree feature-auth — создаёт изолированную копию репозитория с новой веткой.

Сценарий: запустили 5 задач параллельно, каждый агент в своём worktree, основная ветка чистая.

# Три параллельных задачи
claude -w feature-auth
claude -w bugfix-123
claude -w refactor-api

Для монорепо: worktree.sparsePaths — checkout только нужных директорий.

Субагенты тоже могут работать в worktrees: isolation: worktree в frontmatter агента.

Переключение в существующий worktree: инструмент EnterWorktree теперь принимает параметр path для перехода в уже существующий worktree репозитория. С v2.1.157 умеет переключаться между Claude-managed worktrees mid-session, а не только заходить в новый; managed-worktrees остаются unlocked после завершения, чтобы git worktree remove/prune могли их подобрать.

Очистка: при выходе без изменений — worktree удаляется автоматически. С изменениями — Claude спросит, оставить или удалить. Squash-merged PR worktrees тоже удаляются автоматически. С v2.1.143 при сбое git worktree remove Claude больше не делает fallback в rm -rf — gitignored и in-progress файлы не теряются.

worktree.baseRef (v2.1.133): fresh (от origin/<default>) или head (от локального HEAD). С v2.1.133 дефолт у EnterWorktree снова fresh — ставьте "head", если хотите, чтобы новые worktree включали unpushed коммиты.

worktree.bgIsolation: "none" (v2.1.143) — фоновые сессии редактируют рабочую копию напрямую, без EnterWorktree. Для репозиториев, где worktrees неудобны (LFS, монорепо-симлинки).

Добавьте .claude/worktrees/ в .gitignore.

2.4 Fan-out: массовая обработка #

Для миграций и массовых операций:

# 1. Claude генерирует список файлов
claude -p "Список всех файлов для миграции на новый API"

# 2. Скрипт обрабатывает каждый (--bare для скорости — пропускает hooks/LSP/plugins)
for file in $(cat files.txt); do
  claude --bare -p "Мигрируй $file с React на Vue. Верни OK или FAIL." \
    --allowedTools "Edit,Bash(git commit *)"
done

--bare флаг — для скриптовых -p вызовов. Пропускает hooks, LSP, plugin sync, skills. Требует ANTHROPIC_API_KEY. На ~14% быстрее до первого API-запроса.

Или используйте /batch — встроенный skill, который сам разбивает задачу на до 30 единиц и обрабатывает параллельно в worktrees.

2.5 Сессии: не теряйте контекст #

claude --continue        # продолжить последнюю сессию
claude --resume          # выбрать из недавних (с фильтрами по проекту/ветке/worktree)
claude -n oauth-refactor # дать имя сессии
claude --resume oauth-refactor  # вернуться по имени

С v2.1.144 в /resume-пикере появляются и фоновые сессии (запущенные через claude --bg или из agent view) — помечены маркером bg. Уведомления о завершении фоновых субагентов теперь включают длительность (например, "Agent completed · 3h 2m 5s").

/rename — переименовать текущую сессию. Используйте осмысленные имена.

claude project purge [path] (v2.1.126) — удалить весь project state Claude Code (сессии, транскрипты). Необратимо.

Ctrl+R history picker (v2.1.129) — по умолчанию ищет по промптам всех проектов, а не только текущего.

2.6 Исправление курса #

  • Esc — остановить Claude (контекст сохраняется)
  • Esc + Esc, /rewind или /undo (v2.1.108) — откатиться к предыдущему состоянию (и код, и диалог)
  • /clear — если Claude ошибается дважды на одну тему, начните заново с лучшим промптом
  • Ctrl+X Ctrl+K — остановить все фоновые агенты
  • Ctrl+U (v2.1.111) — теперь очищает весь input-буфер. Ctrl+Y — восстановить очищенный ввод
  • Ctrl+L (v2.1.111) — полная перерисовка экрана в дополнение к очистке prompt input

Правило: если вы исправили Claude больше двух раз по одному вопросу — контекст загрязнён неудачными подходами. /clear + лучший промпт работают лучше, чем продолжение.

Часть 4. Настройка для команды #

4.1 Что коммитить в репозиторий #

.claude/
  settings.json    ← hooks, permissions (автоприменяются для всех)
  agents/          ← кастомные субагенты
  skills/          ← командные skills и workflows
CLAUDE.md          ← конвенции проекта

Когда новый участник клонирует репозиторий — все настройки применяются автоматически.

4.2 Thinking summaries #

По умолчанию выключены (с v2.1.89). Если хотите видеть, что Claude думает — включите:

{ "showThinkingSummaries": true }

4.3 Effort levels — экономия токенов #

--effort low|medium|high|xhigh|max

  • low — простые вопросы, быстрые правки
  • medium — лёгкая разработка
  • high — стандартная разработка (default для API-key, Bedrock/Vertex, Team и Enterprise с v2.1.94; для Opus 4.8 — дефолт всегда, с v2.1.154)
  • xhigh (v2.1.111, Opus 4.7/4.8) — между high и max. Другие модели падают на high
  • max — архитектурные решения (только Opus)

Настройка: слайдер в /model, флаг --effort, переменная CLAUDE_CODE_EFFORT_LEVEL, или effortLevel в settings. С v2.1.153 /model снова сохраняет выбор как дефолт для новых сессий (как в IDE); чтобы сменить модель только для текущей сессии — s в model picker (бывшая клавиша d/modelPicker:setAsDefault переименована в s/modelPicker:thisSessionOnly). С v2.1.111: /effort без аргументов — открывает интерактивный слайдер (стрелки + Enter). С v2.1.133 уровень эффорта виден хукам (effort.level в JSON input) и Bash-командам через $CLAUDE_EFFORT.

Auto mode (v2.1.111) — Claude сам выбирает effort по задаче. Флаг --enable-auto-mode больше не нужен, для Max-подписчиков включена для Opus 4.7. С v2.1.152 auto mode больше не требует отдельного opt-in согласия. С v2.1.158 доступен на Bedrock, Vertex и Foundry для Opus 4.7 и Opus 4.8 — opt-in через CLAUDE_CODE_ENABLE_AUTO_MODE=1.

--fallback-model (v2.1.152): если основная модель не найдена, Claude переключается на fallback-модель до конца сессии вместо того, чтобы заваливать каждый запрос ошибкой.

Opus 4.8 (v2.1.154) — новая дефолтная модель. По умолчанию работает на high, для самых сложных задач — /effort xhigh. Вместе с ней включён lean system prompt как дефолт для всех моделей, кроме Haiku, Sonnet и Opus 4.7/ранее — заметно меньше baseline-расход контекста. Claude теперь задаёт multiple-choice вопрос только тогда, когда реально не может выбрать сам — раньше уточнял, даже имея достаточно контекста. Слайдер /effort подписан «Faster»/«Smarter» вместо «Speed»/«Intelligence».

4.4 Контекстное окно: 1M токенов #

Opus 4.6 и Sonnet 4.6 поддерживают 1M токенов по стандартной цене (GA с марта 2026). В Claude Code доступно для Max, Team и Enterprise планов. Это значит: можно работать с очень большими кодовыми базами в одной сессии.

/usage (v2.1.118, заменил /cost и /stats) — детализация по моделям, cache-hit и статистика сессии. С v2.1.144 /extra-usage переименован в /usage-credits (старое имя продолжает работать). С v2.1.149 показывает разбивку расхода лимитов по категориям — skills, субагенты, плагины и стоимость по каждому MCP-серверу.

4.5 Agent Teams (экспериментально) #

Требования: CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1, v2.1.32+. Рекомендуется Opus 4.6.

Компоненты:

  • Team Lead — раздаёт задачи
  • Teammates — работают параллельно в worktrees
  • Task List — общий список задач
  • Mailbox — межагентное общение

Отличие от субагентов: субагенты докладывают только родителю, teammates общаются между собой.

Когда использовать: если субагенты упираются в лимиты или им нужно обмениваться находками.

4.6 Безопасность #

  • CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1 — убирает credentials Anthropic/облачных провайдеров из окружения subprocess'ов
  • CLAUDE_CODE_SCRIPT_CAPS — лимит вызовов скриптов за сессию
  • forceRemoteSettingsRefresh — блокирует запуск, пока managed settings не получены (fail-closed для enterprise)
  • Subprocess sandboxing с PID namespace isolation на Linux (v2.1.98)
  • sandbox.network.deniedDomains (v2.1.113) — блокирует домены поверх wildcard из allowedDomains
  • Bash allow-rules стали строже (v2.1.113): Bash(find:*) больше не авто-аппрувит find -exec / -delete. Deny rules теперь матчатся, даже если команду обернули в env/sudo/watch/ionice/setsid. На macOS пути /private/{etc,var,tmp,home} считаются опасными целями для rm под Bash(rm:*)
  • Исправлен dangerouslyDisableSandbox — Bash больше не запускается без permission prompt (v2.1.113)
  • Sandbox auto-allow и dangerous paths (v2.1.116): авто-аппрув в sandbox больше не пропускает rm/rmdir, нацеленные на /, $HOME и другие критические системные каталоги — проверка на опасные пути теперь выполняется всегда
  • PowerShell permission bypass (v2.1.149): встроенные cd-функции (cd.., cd\, cd~, X:) меняли рабочую директорию незаметно, позволяя последующей команде читать вне workspace. Также закрыт парсер, доверявший устаревшим значениям PWD/OLDPWD/DIRSTACK после cd/pushd/popd
  • Sandbox write allowlist в worktrees (v2.1.149): в git worktree allowlist на запись покрывал весь корень основного репозитория вместо только shared .git (с запретом на hooks/ и config)
  • Auto-mode classifier против data exfiltration (v2.1.154): улучшено детектирование bulk-переносов содержимого репозитория
  • rm -rf $HOME с trailing slash (v2.1.154) — закрыт пропуск блокировки опасного пути, когда HOME оканчивается слэшем
  • Streaming tool execution всегда включён (v2.1.154) — в том числе при отключённой телеметрии и на Bedrock/Vertex/Foundry; раньше был за feature flag

Важно: продолжают выходить security-фиксы для Bash/PowerShell permission engine. Обновляйтесь до v2.1.149 — закрыты PowerShell cd-bypass и утечка sandbox write allowlist в worktrees; ранее в v2.1.126 была закрыта уязвимость с allowManagedDomainsOnly (игнорировалась при определённых конфигурациях).

DISABLE_UPDATES=1 (v2.1.118) — блокирует все пути обновления Claude Code для managed-окружений.

settings.autoMode.hard_deny (v2.1.136) — правила auto-mode классификатора, которые блокируют безусловно: не имеет значения, какой intent у пользователя и какие allow-исключения совпали.

ANTHROPIC_WORKSPACE_ID (v2.1.141) — для workload identity federation: скоупит выписанный токен к конкретному workspace, когда federation rule покрывает несколько.

/doctor — диагностика окружения. Нажмите f — Claude автоматически исправит найденные проблемы. С v2.1.110 предупреждает, если MCP-сервер определён в нескольких конфиг-скоупах с разными эндпоинтами. С v2.1.116 /doctor можно открыть прямо во время ответа Claude — ждать окончания turn не нужно.

/config (v2.1.119): изменения теперь сохраняются в ~/.claude/settings.json — настройки persist между сессиями. Поиск по значениям (v2.1.116): vim найдёт Editor mode, dark найдёт тему.

prUrlTemplate (v2.1.119) — настройка в settings.json: кастомный шаблон URL для code-review (полезно для GitLab, GitHub Enterprise, Bitbucket). --from-pr теперь принимает URL из GitLab, Bitbucket и GitHub Enterprise.

Custom themes (v2.1.118): создавать и переключаться между кастомными темами можно прямо из /theme.

Native binary (v2.1.113): CLI теперь спавнит платформенный нативный бинарник Claude Code (per-platform optional dependency) вместо bundled JavaScript. Быстрее старт, меньше потребление памяти.

Push-уведомления (v2.1.110): если включён Remote Control и "Push when Claude decides" в конфиге — Claude сам может слать push на мобильное, когда задача закончена или нужен ваш ввод.

4.7 3rd-party провайдеры и платформы #

Claude Code поддерживает сторонних провайдеров с интерактивными визардами настройки:

  • Amazon Bedrock — визард на экране логина. Поддержка Mantle (CLAUDE_CODE_USE_MANTLE=1). ANTHROPIC_BEDROCK_SERVICE_TIER (v2.1.122) — выбор Bedrock tier
  • Google Vertex AI — интерактивный визард (v2.1.98)
  • Perforce — CLAUDE_CODE_PERFORCE_MODE — Edit/Write/NotebookEdit блокируются на read-only файлах с подсказкой p4 edit

Windows: PowerShell tool (v2.1.111) постепенно раскатывается. Включить/выключить — CLAUDE_CODE_USE_POWERSHELL_TOOL=1. На Linux/macOS тоже работает, если pwsh в PATH. Исправлены permission rules с drive-letter путями и case-insensitive матчинг путей. С v2.1.120 Git Bash больше не требуется — PowerShell используется как fallback shell. С v2.1.126 PowerShell 7 определяется и используется как основной shell. С v2.1.143 PowerShell tool по умолчанию включён на Windows для Bedrock/Vertex/Foundry — опт-аут через CLAUDE_CODE_USE_POWERSHELL_TOOL=0. PowerShell теперь передаёт -ExecutionPolicy Bypass; вернуть прежнее поведение — CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1.

Fast mode (Claude Code Fast) с v2.1.154 по умолчанию использует Opus 4.8 — 2x от стандартной цены за 2.5x скорости. CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE deprecated (удалят 1 июня 2026); чтобы запустить Opus 4.6 в fast mode — /model claude-opus-4-6[1m], затем /fast on.

wslInheritsWindowsSettings: true (v2.1.118) — WSL-сессии наследуют managed settings с Windows-стороны.

Vim visual mode (v2.1.118): добавлены v (visual) и V (visual-line) режимы в vim mode.

Observability: OTEL_LOG_RAW_API_BODIES=1 (v2.1.111) — эмитит полные тела API request/response как OpenTelemetry log events. Для отладки в enterprise. Спаны claude_code.tool (v2.1.145) дополнились атрибутами agent_id и parent_agent_id — можно строить trace-дерево по субагентам и teammates. С v2.1.157 OTEL_LOG_TOOL_DETAILS=1 добавляет tool_parameters (bash-команды, имена MCP-инструментов и skills) в tool_decision-события.

Auto-updater (v2.1.147): ретраит транзиентные сетевые ошибки, на финальном фейле репортит конкретную категорию ошибки и OS error code, показывает текущую версию. Меньше тихих фейлов в managed-окружениях с нестабильной сетью.

4.8 Superset.sh — IDE для параллельных агентов #

Бесплатная open-source IDE (Apache 2.0) для запуска 10+ параллельных агентов через git worktrees. BYOK — ваши API-ключи, без наценки, данные остаются у вас. Только macOS. Pro $20/мес — опционально.

Часть 5. Антипаттерны (что НЕ делать) #

"Кухонная мойка" — начали одну задачу, спросили про другое, вернулись к первой. Контекст забит нерелевантной информацией. → /clear между несвязанными задачами.

"Бесконечные правки" — Claude ошибся, вы поправили, опять ошибся, опять поправили. Контекст загрязнён неудачными подходами. → После двух неудачных правок — /clear и лучший промпт.

"CLAUDE.md на 500 строк" — Claude игнорирует половину, потому что важные правила тонут в шуме. → Держите до ~200 строк. Остальное — в skills.

"Без верификации" — Claude выдал правдоподобный код, вы не проверили, задеплоили. → Всегда давайте Claude способ проверить результат: тесты, скриншоты, linter.

"Бесконечное исследование" — попросили "разберись" без скоупа, Claude прочитал 100 файлов, контекст забит. → Ограничивайте скоуп или используйте субагентов для исследований.
