FAQ и решение проблем #

Поведение Claude #

Claude игнорирует правило из CLAUDE.md.

  1. Проверьте /context — файл вообще загружен?
  2. Файл слишком длинный — важное тонет. Сократите.
  3. Сформулируйте конкретнее и добавьте акцент (ВАЖНО:).
  4. Если правило должно выполняться всегда — сделайте hook, а не инструкцию.

Claude говорит «готово», но ничего не работает. Требуйте проверку в самом промпте: «...и запусти npm test, покажи вывод». Добавьте в CLAUDE.md: «После изменений всегда запускай релевантные тесты».

Claude меняет файлы, которые я не просил трогать. Plan mode перед работой + явные границы: «меняй только src/billing/». Для критичных файлов — hook protect-files.sh.

Качество ответов падает к концу длинной сессии. Контекст переполнен. Сохраните прогресс в файл (docs/plans/...), сделайте /clear и продолжите. Или /compact <что сохранить>.

Claude выдумывает несуществующие функции библиотеки. Дайте источник: @node_modules/<lib>/dist/index.d.ts, ссылку на документацию, или подключите MCP с актуальными доками (например, Context7).

Claude зациклился и повторяет одно и то же. Esc, затем: «Ты пробовал X дважды. Перечисли факты и отброшенные гипотезы, предложи другой подход». Если не помогает — /clear и новый промпт с учётом уроков.

Разрешения #

Слишком много вопросов о разрешениях. Добавьте безопасные команды в permissions.allow (модуль 03) или выбирайте «не спрашивать снова» — правило сохранится в settings.local.json. Для правок файлов — режим acceptEdits.

Правило allow не срабатывает. Проверьте точный синтаксис: Bash(npm run test:*) — префикс, Bash(npm test) — точная команда. Помните, что deny побеждает allow. Посмотрите итоговые правила в /permissions.

Можно ли дать полную автономию? bypassPermissions / --dangerously-skip-permissions — только в изолированном контейнере без секретов и доступа к продакшену.

Skills и агенты #

Skill не вызывается автоматически. Улучшите description: что делает + когда использовать + слова, которыми вы обычно формулируете задачу. Убедитесь, что не стоит disable-model-invocation: true.

Не вижу свой skill/агента. Проверьте путь: .claude/skills/<имя>/SKILL.md (именно папка + SKILL.md), .claude/agents/<имя>.md. Проверьте YAML frontmatter (--- сверху и снизу, без табов). Перезапустите сессию. Скрипт python scripts/validate.py в этом репо проверит frontmatter.

Субагент не видит контекст нашего разговора. Так и задумано: он получает только задачу. Передавайте в задаче всё нужное (файлы, решения, ограничения).

Hooks #

Hook не срабатывает.

  • /hooks — зарегистрирован ли он?
  • matcher регистрозависим: Edit|Write, а не edit.
  • Скрипт исполняемый или вызывается через bash ...?
  • claude --debug покажет выполнение и ошибки.
  • Установлен ли jq?

Hook блокирует всё подряд. Протестируйте вручную: echo '<json>' | bash hook.sh; echo $?. Проверьте, что при «нормальном» входе выходит exit 0.

MCP #

Сервер не подключается. claude mcp list, /mcp — статус и ошибка. Для stdio-серверов запустите команду вручную — часто не хватает Node/Python или переменной окружения. Для OAuth — /mcp → авторизация.

MCP съедает много контекста. Отключите неиспользуемые серверы, держите только нужные на уровне проекта.

Деньги и лимиты #

Как тратить меньше? /clear между задачами, короткий CLAUDE.md, субагенты на Haiku для поиска, конкретные промпты с @файлами, отключённые лишние MCP. Следите через /cost и statusline.

Какую модель выбрать? Opus — сложные задачи и планирование; Sonnet — ежедневная работа; Haiku — быстрые простые задачи и субагенты-исследователи.

Прочее #

Чем Claude Code отличается от чата в браузере? Он работает с вашими файлами и терминалом напрямую: читает проект, запускает тесты, правит код, коммитит — как агент, а не как советчик.

Можно ли использовать с другими IDE? Да: VS Code и JetBrains — через расширения; в любой другой IDE — в встроенном терминале.

Работает ли на Windows? Да: нативно или через WSL. Для hooks из этого репо удобнее WSL / Git Bash (нужны bash и jq).
