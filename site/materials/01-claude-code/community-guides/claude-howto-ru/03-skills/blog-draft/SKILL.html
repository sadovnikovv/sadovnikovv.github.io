name: blog-draft description: Draft a blog post from ideas and resources. Use when users want to write a blog post, create content from research, or draft articles. Guides through research, brainstorming, outlining, and iterative drafting with version control.

User Input #

$ARGUMENTS

Вы должны учитывать ввод пользователя перед продолжением. Пользователь должен указать:

  • Idea/Topic: основная тема или идея поста
  • Resources: URL, файлы или ссылки на исследования (опционально, но желательно)
  • Target audience: для кого предназначен пост (опционально)
  • Tone/Style: формальный, разговорный, технический и т. п. (опционально)

ВАЖНО: если пользователь просит изменить уже существующий пост, пропустите шаги 0-8 и сразу переходите к Step 9. Сначала прочитайте существующие черновики, затем начинайте итерации.

Поток выполнения #

Следуйте шагам последовательно. Не пропускайте шаги и не идите дальше без согласования там, где оно требуется.

Step 0: Создать папку проекта #

  1. Сгенерируйте имя папки по формату: YYYY-MM-DD-short-topic-name
  2. Используйте сегодняшнюю дату
  3. Создайте короткий slug, удобный для URL (lowercase, hyphens, максимум 5 слов)
  1. Создайте структуру:
   blog-posts/
   └── YYYY-MM-DD-short-topic-name/
       └── resources/
  1. Подтвердите создание папки с пользователем перед продолжением.

Step 1: Исследование и сбор ресурсов #

  1. Создайте подпапку resources/ в директории поста
  1. Для каждого предоставленного ресурса:
  2. URLs: извлеките и сохраните ключевую информацию в resources/ как markdown-файлы
  3. Files: прочитайте и кратко изложите в resources/
  4. Topics: используйте web search для сбора актуальной информации
  1. Для каждого ресурса создайте summary-файл в resources/:
  2. resources/source-1-[short-name].md
  3. resources/source-2-[short-name].md
  4. и т. д.
  1. Каждый summary должен содержать:
   # Source: [Title/URL]

   ## Key Points
   - Point 1
   - Point 2

   ## Relevant Quotes/Data
   - Quote or statistic 1
   - Quote or statistic 2

   ## How This Relates to Topic
   Brief explanation of relevance
  1. Представьте пользователю summary исследований.

Step 2: Brainstorm & Clarify #

  1. На основе темы и собранных ресурсов покажите:
  2. Main themes из исследования
  3. Potential angles для поста
  4. Key points, которые стоит раскрыть
  5. Gaps в информации, которые нужно уточнить
  1. Задайте уточняющие вопросы:
  2. Какой главный вывод вы хотите донести до читателя?
  3. Какие пункты из исследования нужно подчеркнуть?
  4. Какой нужен объём? (short: 500-800 words, medium: 1000-1500, long: 2000+)
  5. Что нужно исключить?
  1. Ждите ответа пользователя, прежде чем продолжать.

Step 3: Предложить outline #

  1. Создайте структурированный outline:
   # Blog Post Outline: [Title]

   ## Meta Information
   - **Target Audience**: [who]
   - **Tone**: [style]
   - **Target Length**: [word count]
   - **Main Takeaway**: [key message]

   ## Proposed Structure

   ### Hook/Introduction
   - Opening hook idea
   - Context setting
   - Thesis statement

   ### Section 1: [Title]
   - Key point A
   - Key point B
   - Supporting evidence from [source]

   ### Section 2: [Title]
   - Key point A
   - Key point B

   [Continue for all sections...]

   ### Conclusion
   - Summary of key points
   - Call to action or final thought

   ## Sources to Cite
   - Source 1
   - Source 2
  1. Представьте outline пользователю и попросите утвердить его или внести правки.

Step 4: Сохранить утверждённый outline #

  1. После утверждения сохраните его в OUTLINE.md в папке поста.
  1. Подтвердите, что outline сохранён.

Step 5: Зафиксировать outline в git (если репозиторий git) #

  1. Проверьте, является ли текущая директория git-репозиторием.
  1. Если да:
  2. Добавьте новые файлы в stage: папку поста, ресурсы и OUTLINE.md
  3. Создайте commit с сообщением: docs: Add outline for blog post - [topic-name]
  4. Отправьте изменения в remote
  1. Если это не git-репозиторий, пропустите шаг и сообщите пользователю.

Step 6: Написать черновик #

  1. На основе утверждённого outline напишите полный черновик поста.
  1. Строго следуйте структуре из OUTLINE.md.
  1. Включите:
  2. Захватывающее вступление
  3. Чёткие заголовки секций
  4. Подтверждения и примеры из исследования
  5. Плавные переходы между секциями
  6. Сильное заключение с основным выводом
  7. Citations: все сравнения, статистика, данные и факты должны иметь ссылку на источник
  1. Сохраните черновик как draft-v0.1.md в папке поста.
  1. Формат:
   # [Blog Post Title]

   *[Optional: subtitle or tagline]*

   [Full content with inline citations...]

   ---

   ## References
   - [1] Source 1 Title - URL or Citation
   - [2] Source 2 Title - URL or Citation
   - [3] Source 3 Title - URL or Citation
  1. Требования к цитированию:
  2. Каждый факт, статистика и сравнение должны иметь inline citation
  3. Используйте нумерованные ссылки [1], [2] и т. п. или именованные цитаты [Source Name]
  4. Связывайте цитаты с разделом References в конце
  5. Пример: "Исследования показывают, что 65% разработчиков предпочитают TypeScript [1]"
  6. Пример: "React превосходит Vue по скорости рендеринга на 20% [React Benchmarks 2024]"

Step 7: Зафиксировать черновик в git (если репозиторий git) #

  1. Проверьте, находитесь ли вы в git-репозитории.
  1. Если да:
  2. Добавьте файл черновика в stage
  3. Создайте commit с сообщением: docs: Add draft v0.1 for blog post - [topic-name]
  4. Отправьте изменения в remote
  1. Если нет, пропустите шаг и сообщите пользователю.

Step 8: Показать черновик на ревью #

  1. Покажите пользователю содержимое черновика.
  1. Попросите обратную связь:
  2. Общее впечатление?
  3. Какие секции нужно расширить или сократить?
  4. Нужны ли изменения тона?
  5. Чего не хватает?
  6. Какие правки или переписывание нужны?
  1. Ждите ответа пользователя.

Step 9: Итерация или финализация #

Если пользователь просит изменения:

  1. Зафиксируйте все изменения
  2. Вернитесь к Step 6 со следующими корректировками:
  3. Увеличьте номер версии (v0.2, v0.3 и т. д.)
  4. Учтите всю обратную связь
  5. Сохраняйте как draft-v[X.Y].md
  6. Повторяйте Steps 7-8

Если пользователь одобряет:

  1. Подтвердите финальную версию черновика
