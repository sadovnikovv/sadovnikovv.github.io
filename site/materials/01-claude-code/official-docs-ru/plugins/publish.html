Публикация и распространение плагина #

Опубликуйте плагин Claude Code через собственный маркетплейс или маркетплейс Anthropic, с предварительным контрольным списком и информацией о том, как пользователи получают обновления.

Публикация плагина Claude Code означает его размещение в маркетплейсе — каталоге JSON, который содержит список плагинов и указывает, откуда получить каждый из них, чтобы другие люди могли установить его по имени и получать ваши обновления. Вы можете запустить собственный маркетплейс или отправить свой плагин в каталог Anthropic. Чтобы поделиться плагином без публикации, отправьте людям папку плагина или файл .zip для самостоятельной загрузки.

Эта страница предназначена для автора готового плагина, который готов поделиться им.

[!NOTE]

Следующие случаи рассматриваются на других страницах:

  • Ваш плагин еще не готов: начните с Создание плагина
  • Вы поддерживаете CLI или SDK с плагином в официальном маркетплейсе: см. Рекомендуйте свой плагин из вашего CLI

Начните с Выбор способа распространения, чтобы сравнить варианты распространения. Если вы уже знаете свой путь, перейдите к Подготовка плагина к выпуску, а затем следуйте разделу вашего маршрута, чтобы узнать, что сказать пользователям и как они получают ваши обновления.

Выбор способа распространения #

Выберите вариант распространения в зависимости от того, кому нужно установить плагин:

| Маршрут | Кто может установить | Что вам нужно | Получают ли пользователи ваши обновления автоматически? | | :- | :- | :- | :- | | Без маркетплейса | Люди, которым вы отправили папку плагина или файл .zip | Папка плагина | Нет. Они загружают копию, которую вы отправили | | Собственный маркетплейс | Любой, кто может получить доступ к репозиторию, который может быть приватным, который может клонировать ваша команда | Репозиторий git или другой хост с файлом .claude-plugin/marketplace.json, который содержит список вашего плагина | Выключено | | Маркетплейс Anthropic | Люди, которые добавляют его на claude.ai или в Cowork. Он также загружается в их сеансах Claude Code через синхронизацию учётной записи | Репозиторий GitHub, содержащий плагин, и платный план claude.ai для отправки | Да, после публикации отправленной вами версии |

Автоматическое обновление — это параметр маркетплейса на стороне пользователя, который получает новые версии в фоновом режиме.

Подготовка плагина к выпуску #

Имя, версия, валидация и установка из маркетплейса определяют, будет ли выпуск работать для людей, которые его установят. Проверьте их перед первым выпуском и снова перед каждым последующим.

1. Выберите постоянное имя

Пользователи устанавливают, включают и настраивают ваш плагин по name@marketplace, поэтому переименованный плагин — это другой плагин для каждой существующей установки. Выберите имя в формате kebab-case, например deploy-helper, потому что claude plugin validate предупреждает о других формах, и рассматривайте его как постоянное. Установите displayName в plugin.json для метки, которую видят пользователи.

2. Решите, как вы будете версионировать

Если вы установите version в plugin.json и позже отправите коммиты без его изменения, claude plugin update выведет <name> is already at the latest version (1.0.0). и пользователи сохранят старую копию. Либо увеличивайте version при каждом выпуске, либо опустите его в маркетплейсе, размещенном на git, чтобы Claude Code использовал SHA коммита вместо этого. См. Версии и обновления.

3. Валидация

В вашей оболочке выполните claude plugin validate --strict ./your-plugin. Чистый запуск выводит ✔ Validation passed.

  • В CI: сохраняйте --strict, который также завершает запуск с кодом выхода 1 при предупреждениях, таких как неизвестное поле манифеста или отсутствующий version. Удалите --strict, если вы выбрали опустить version на предыдущем шаге.
  • Пути: валидация сообщает пути компонентов, которые не начинаются с ./. Внутри команд hook и конфигов MCP сервера ссылайтесь на файлы как ${CLAUDE_PLUGIN_ROOT}/.... См. правила пути.

4. Установите его из локального маркетплейса

В вашей оболочке добавьте локальный маркетплейс, который содержит список плагина с помощью claude plugin marketplace add ./path-to-marketplace, установите плагин из него и запустите сеанс, чтобы подтвердить, что он загружается.

  • Для наименьшего маркетплейса, который работает, см. Создание маркетплейса.
  • Чтобы узнать, загружает ли установка ваш исходный каталог или кэшированную копию, см. Плагины на месте и скопированные плагины.

5. Заполните метаданные, которые видят пользователи

Установите description, author, homepage и repository в plugin.json и добавьте README.md в корень плагина. homepage должен анализироваться как URL. Какие значения принимает каждое поле, см. в справочнике манифеста.

6. Запустите свой набор eval

Если у вас есть набор eval, запустите claude plugin eval в вашей оболочке. Он запускает тестовые случаи плагина и оценивает результаты, что выявляет регрессии при изменении плагина. См. Тестирование плагинов с помощью eval.

Поделитесь плагином без маркетплейса #

Если плагин находится в репозитории git, люди могут клонировать его и загрузить checkout, или запустить Claude Code из своей оболочки с --plugin-url, указывающим на файл .zip, который вы прикрепляете к выпуску. Чтобы получить вашу следующую версию, они вытягивают или загружают снова. Если он не находится в репозитории, отправьте им каталог или файл .zip из него. Они загружают его одним из двух способов:

  • Для одного сеанса: они запускают Claude Code из своей оболочки с claude --plugin-dir ./deploy-helper, где путь — это клон, распакованная папка или сам файл .zip. См. Флаги, которые загружают плагин для одного сеанса.
  • Для каждой сессии: они перемещают каталог плагина с его .claude-plugin/plugin.json в ~/.claude/skills/. С этого момента Claude Code загружает его при запуске, если только их администратор не заблокировал плагины из каталога скиллов.

Добавление .claude-plugin/marketplace.json в тот же репозиторий — это то, что позволяет людям устанавливать по имени и обновляться с помощью команды; см. Публикация через собственный маркетплейс.

Отправьте плагин со своим собственным инструментом #

Если вы поддерживаете CLI или SDK, опубликуйте плагин в маркетплейсе и попросите ваш установщик или сообщение после установки запустить или вывести две команды, которые нужны пользователю: claude plugin marketplace add <source>, затем claude plugin install <name>@<marketplace>. Для обнаружения в сеансе, когда кто-то использует ваш инструмент, см. Рекомендуйте свой плагин из вашего CLI.

Публикация через собственный маркетплейс #

Ваш собственный маркетплейс — это файл .claude-plugin/marketplace.json, который содержит список вашего плагина, добавленный в репозиторий git. После того как файл находится в репозитории, плагин опубликован, без формы отправки. Вы можете сохранить файл в собственном репозитории плагина или в отдельном.

Добавьте файл маркетплейса в ваш репозиторий #

Чтобы опубликовать из собственного репозитория плагина, сохраните файл маркетплейса рядом с plugin.json в .claude-plugin/, с одной записью, чей source — это "./", корень репозитория. Дайте записи то же name, что и plugin.json, согласно Сохраняйте имя записи и имя манифеста одинаковыми:

```json .claude-plugin/marketplace.json theme={null} { "name": "your-marketplace", "owner": { "name": "Your Name" }, "plugins": [ { "name": "deploy-helper", "source": "./" } ] }


Замените `your-marketplace` именем, которое другие авторы вряд ли выберут, потому что у пользователя [не может быть двух маркетплейсов с одинаковым именем](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#marketplace-file). В вашей оболочке запустите `claude plugin validate .` в репозитории перед отправкой. О том, что проверяет этот запуск, см. [Проверка каталога](https://code.claude.com/docs/ru/plugins/cli-reference.md#validate-a-directory).

[Создание маркетплейса](https://code.claude.com/docs/ru/plugins/create-marketplace.md) охватывает макет с несколькими плагинами в одном репозитории.

### Контролируйте, кто может установить

Любой, кто может клонировать репозиторий, может установить из него, поэтому если репозиторий приватный, маркетплейс также приватный. Для хостов, отличных от репозитория git, см. [Размещение маркетплейса](https://code.claude.com/docs/ru/plugins/host-marketplace.md). Чтобы охватить всех в компании, включая людей, которые не используют git, см. [Развертывание для всей компании](https://code.claude.com/docs/ru/plugins/host-marketplace.md#roll-out-to-a-whole-company).

### Скажите пользователям, как установить

Скажите своим пользователям добавить маркетплейс, а затем установить плагин из своей оболочки, заменив источник и имена на ваши:

* Добавьте маркетплейс один раз: `claude plugin marketplace add your-org/your-marketplace`, где аргумент — это сокращение GitHub `owner/repo`, URL или путь
* Установите плагин: `claude plugin install deploy-helper@your-marketplace`
* Или сделайте оба из сеанса: `/plugin install deploy-helper --marketplace your-org/your-marketplace`. Требуется Claude Code v2.1.275 или позже. См. [Добавьте маркетплейс и установите в одной команде](https://code.claude.com/docs/ru/plugins/install.md#add-a-marketplace-and-install-in-one-command)
* Или сделайте оба действия из оболочки одной командой: `claude plugin install deploy-helper --marketplace your-org/your-marketplace`. Требуется Claude Code v2.1.292 или позже

### Отправьте обновления пользователям

Пользователи получают выпуск, когда они его запрашивают или когда для вашего маркетплейса включено автоматическое обновление:

* **По запросу**: `claude plugin update deploy-helper@your-marketplace` в оболочке пользователя обновляет маркетплейс и устанавливает новую копию, когда версия вашего плагина изменилась
* **Автоматическое обновление**: по умолчанию отключено для вашего маркетплейса. См. [Включите автоматическое обновление](https://code.claude.com/docs/ru/plugins/host-marketplace.md#turn-on-auto-update). После включения он делает то же самое, что `claude plugin update` с задержкой после запуска сеанса

[Установка плагинов](https://code.claude.com/docs/ru/plugins/install.md) охватывает команды на стороне пользователя, а [когда запускается автоматическое обновление](https://code.claude.com/docs/ru/plugins/loading.md#when-auto-update-runs) охватывает время.

## Отправить в справочник Anthropic

[Справочник Anthropic](https://claude.ai/directory) — это каталог, который люди просматривают на claude.ai и в Cowork для добавления плагинов и коннекторов. Одно объявление там достигает людей на claude.ai, в Cowork и в Claude Code. Вы отправляете из портала разработчика на [claude.ai/directory/manage](https://claude.ai/directory/manage), а раздел [Отправить плагин](https://claude.com/docs/plugins/submit#submit-a-plugin) на claude.com проведёт вас по порталу.

Официальный маркетплейс Anthropic, `claude-plugins-official`, не принимает отправки через портал справочника. Если вы работаете с контактом партнёра Anthropic, попросите у них информацию об объявлении в официальном маркетплейсе.

Чтобы отправить плагин:

**1. Убедитесь, что вы можете отправлять**

Отправка требует платный план claude.ai. На Pro, Max и Ultra вы отправляете со своего собственного аккаунта. На Team и Enterprise владелец может отправлять, а на Enterprise владелец также может предоставить разрешение **Directory** другим членам через пользовательскую роль в разделе **Organization settings > Roles**. См. [Подтвердите, что вы можете отправлять в справочник](https://claude.com/docs/directory/publish#confirm-you-can-submit-to-the-directory).

**2. Проверьте плагин локально**

Запустите `claude plugin validate ./your-plugin --strict` в вашей оболочке. Замените `./your-plugin` на путь к каталогу вашего плагина. Команда перехватывает ошибки манифеста локально; [plugin validate](https://code.claude.com/docs/ru/plugins/cli-reference.md#plugin-validate) перечисляет, какие файлы читает каждый запуск. Портал применяет дополнительные правила справочника, которые CLI не проверяет, поэтому чистый локальный запуск не гарантирует чистую валидацию портала.

[Контрольный список перед отправкой плагина](https://claude.com/docs/plugins/pre-submission-checklist#run-the-checks-before-you-submit) на claude.com содержит проверки, которые нужно запустить и исправить перед отправкой.

**3. Проверьте, что загружается где**

Некоторые компоненты плагина предназначены только для Claude Code и не загружаются на claude.ai или в Cowork. [Таблица поддержки компонентов](https://claude.com/docs/plugins/platform-support#compare-component-support-by-app) перечисляет каждый компонент по приложениям, поэтому вы знаете, что получат пользователи вне Claude Code.

**4. Отправьте через портал разработчика**

Откройте портал разработчика на [claude.ai/directory/manage](https://claude.ai/directory/manage) и следуйте инструкциям раздела [Отправить плагин](https://claude.com/docs/plugins/submit#submit-a-plugin) на claude.com.

Остальная часть процесса задокументирована на claude.com:

* [Подготовка к проверке](https://claude.com/docs/directory/publish#prepare-for-review): что происходит с каждой версией перед её публикацией
* [Обновление опубликованного плагина](https://claude.com/docs/plugins/submit#update-a-published-plugin): как новая версия доходит до людей, у которых установлен ваш плагин
* [Отправьте свой плагин, а свой MCP-сервер — как коннектор](https://claude.com/docs/directory/publish#submit-your-plugin-and-your-mcp-server-as-a-connector): что вы можете отправить
* [Переместить более раннюю отправку на портал разработчика](https://claude.com/docs/directory/publish#move-an-earlier-submission-to-the-developer-portal): что делать, если вы отправили плагин через одну из более ранних форм отправки, до того как портал существовал

### Как перечисленный плагин достигает пользователей Claude Code

Человек, который устанавливает ваш плагин из справочника на claude.ai, имеет его на своём аккаунте, и Claude Code загружает его как `<name>@synced`. [Плагины, синхронизированные с claude.ai](https://code.claude.com/docs/ru/plugins/loading.md#synced-plugins) охватывает то, что они видят и как они его отключают.

## Отправка обновлений, переименований и удалений

### Выпустите новую версию

Если вы публикуете через собственный маркетплейс и ваш `plugin.json` устанавливает `version`, увеличьте его и отправьте. Пользователи, которые запускают `claude plugin update` или имеют включенное автоматическое обновление, получают новую версию, как описано в разделе [Отправка обновлений пользователям](#ship-updates-to-users). Для справки по каталогу см. [Обновление опубликованного плагина](https://claude.com/docs/plugins/submit#update-a-published-plugin).

### Отметьте выпуск

Отметьте выпуск в git, когда другие плагины объявляют диапазон версий на вашем, потому что эти диапазоны разрешаются против тегов.

Чтобы отметить, запустите `claude plugin tag` в вашей оболочке из каталога плагина. Он создает тег `{name}--v{version}`. Добавьте `--push`, чтобы отправить тег на `origin`. [Справочник `plugin tag`](https://code.claude.com/docs/ru/plugins/cli-reference#plugin-tag) содержит список его флагов.

### Переименуйте или удалите плагин

Никогда не изменяйте `name` опубликованного плагина. После переименования пользователи, которые уже установили его, теряют плагин, потому что их установка записана под старым именем. Запись `renames` в файле маркетплейса переносит их вместо этого. Измените `displayName`, когда вы хотите другую метку.

Если переименование неизбежно, используйте карту `renames` файла маркетплейса, чтобы существующие установки переносились вместо сбоя с [`Plugin "<name>" not found in marketplace`](https://code.claude.com/docs/ru/plugins/troubleshooting#plugin-not-found-in-marketplace). Чтобы удалить плагин из маркетплейса или получить полные детали `renames`, см. [Переименуйте или удалите плагин](https://code.claude.com/docs/ru/plugins/host-marketplace.md#rename-or-remove-a-plugin) на странице размещения. [Справочник маркетплейса](https://code.claude.com/docs/ru/plugins/marketplace-reference.md#top-level-fields) содержит поле.

## Объявите зависимости

Если ваш плагин нуждается в другом плагине из того же маркетплейса для включения, перечислите его в массиве `dependencies` в `plugin.json`. Каждая запись — это простое имя или объект с диапазоном semver `version`. Когда пользователь устанавливает ваш плагин, Claude Code также устанавливает и включает зависимость.

[Зависимости плагинов](https://code.claude.com/docs/ru/plugins/dependencies.md) охватывает синтаксис диапазона, кросс-маркетплейс зависимости и как пользователи удаляют зависимости, которые им больше не нужны.
