Справочник по модам #

Полный справочник по модам Claude Code: структура модуля хуков, события, методы API модов, точки отрисовки, элементы по интерфейсам, ограничения и настройки.

Здесь можно найти любое событие, которое может обрабатывать мод, любой метод API модов, который он может вызвать, и любую точку отрисовки, в которой он может рисовать. Записи охватывают CLI Claude Code и приложение Desktop по состоянию на v2.1.290, а также расширение VS Code по состоянию на v2.1.299. Для каждой записи указаны имя и однострочное описание, а также ссылка на раздел руководства с пояснениями, если такой раздел есть.

[!NOTE]

Полный справочник — это TypeScript-декларации Claude Code для модов, в которых описаны все события, методы и элементы с примерами. Копия на GitHub может быть старше установленной у вас версии Claude Code. Если они расходятся, доверяйте копии, которую Claude Code записывает для вашей версии.

Файлы #

Мод — это каталог плагина со следующими файлами:

| Файл | Обязателен | Содержимое | | :- | :- | :- | | .claude-plugin/plugin.json | Да | Манифест плагина. Моды не добавляют обязательных полей. | | hooks/hooks.json | Да | modules: массив с одним путём к модулю хуков относительно этого файла, например "modules": ["./register.js"]. Может также содержать хуки настроек в поле hooks. | | Модуль хуков, например hooks/register.js | Да | Точка входа мода. Экспортирует register(on, options). Имеет расширение .js, .mjs, .cjs, .jsx, .ts, .mts, .cts или .tsx. Является ES-модулем. | | types/index.d.ts, если только поле types в манифесте не указывает другой путь | Когда мод использует $.state или добавляет пространство имён в API модов | Объявляет значения PluginState и любое пространство имён, которое добавляет мод. Чтобы не указывать types в манифесте, требуется версия v2.1.299 или новее. | | Файлы, имена которых заканчиваются на .test.ts или .test.tsx | Нет | Тесты, которые запускает claude plugin test |

register получает on и options. options содержит значения полей userConfig, объявленных в манифесте, с подставленными значениями по умолчанию.

Функция хука #

Мод регистрирует каждый из своих хуков, то есть обработчиков событий, вызывая on внутри register. on принимает имя события, необязательный matcher, то есть фильтр по полям события, и сам хук, например on('tool.call', { tool: 'Bash' }, async ($, e, next) => next(e)). on возвращает регистрацию с одним методом, .catch(handler), который задаёт обработчик ошибок хука.

| Аргумент | Что это | | :- | :- | | $ | API модов: все методы из раздела Методы API модов. Записывайте каждый вызов полностью, пространство имён и затем метод, например $.fs.read('notes.md'). | | e | Входные данные события в виде глубоко замороженных простых данных. Чтобы изменить их, передайте копию в next. | | next(e) | Следующий обработчик, как в middleware. Запускает хуки, идущие после этого, а затем поведение Claude Code. Разрешается в результат события. | | next.signal | AbortSignal, который прерывается, когда событие отменено | | next.origin | { plugin, tier } того, кто инициировал событие. Сам Claude Code — это { plugin: 'engine', tier: 'core' }. tier мода — это его группа приоритета в порядке запуска модов: prepend, user, append или builtin. | | next.budget | Ограничение времени хука в миллисекундах: next.budget.ms — всё ограничение, а next.budget.remainingMs — оставшееся на данный момент время | | next.to(e, tier) | Переходит к более позднему уровню: append, builtin или core. next.to(e, 'append') пропускает моды, установленные пользователем. Вызвать его может только мод из prependPlugins или appendPlugins. | | next.error | Только в обработчике .catch. kind — это throw или timeout, а message — текст ошибки. | | next.called | Только в обработчике .catch. true, если хук вызвал next. |

События #

События сгруппированы по тому, к чему они относятся; для каждого указано, когда оно срабатывает и что может вернуть хук на него. Хуки на turn.step и process.spawn — асинхронные генераторы, остальные хуки — асинхронные функции.

В последнем столбце каждой таблицы используется сокращённая запись. next(e) передаёт событие дальше без изменений. next({ ...e, text }) передаёт дальше копию с изменённым указанным полем, например next({ ...e, text: e.text.trim() }). Объект отвечает на событие без вызова next, а слово вроде reason обозначает строку, которую вы пишете, например { deny: 'Use the file tools.' }.

Инструменты #

События инструментов срабатывают вокруг каждого вызова инструмента, который делает Claude, — от описания, которое читает Claude, до решения о том, будет ли вызов выполнен:

| Событие | Срабатывает, когда | Хук может вернуть | | :- | :- | :- | | tool.call | Инструмент вот-вот запустится | next(e), { deny: reason } или { result } | | tool.check | Claude Code решает, может ли вызов инструмента выполниться, после хуков tool.call и PreToolUse. next(e) разрешается в решение, к которому пришли правила, режим разрешений и эти хуки. | next(e) или { decision }, где decision равно allow, ask или deny, с необязательным reason | | tool.describe | Один раз для каждого инструмента, когда его описание впервые отправляется Claude. Второй раз для инструмента MCP, когда Claude загружает его через поиск инструментов; при этом e.description содержит текст, который Claude читает для загруженного инструмента. | { description }, при необходимости с isDeferred, равным true, чтобы поместить инструмент за поиск инструментов, или false, чтобы загрузить его сразу. Добавьте breakPromptCache: true, чтобы отправить изменённое описание на следующем ходе. |

Поля агента и организации в tool.check #

В хуке tool.check читайте эти поля, чтобы отличить вызов субагента от вызова основного диалога и узнать, требует ли ваша организация подтверждения для инструмента коннектора:

  • e.agentId: задано, когда вызов делает субагент или участник команды, работающий в том же процессе, и отсутствует, когда вызов делает основной диалог
  • e.ceiling: ask для инструмента коннектора, для которого ваша организация установила ask, в сессиях, где эта настройка доходит до Claude Code

В tool.check поля e.agentId и e.ceiling требуют Claude Code v2.1.290 или новее.

Поле e.isReadOnly в tool.check #

В хуке tool.check поле e.isReadOnly равно true, когда инструмент сообщает, что этот вызов выполняется только для чтения. В противном случае поле отсутствует, а не равно false. Значение — это собственное сообщение инструмента, поэтому прочитайте раздел Проверка того, выполняется ли вызов инструмента только для чтения, прежде чем подтверждать вызов только на основании этого поля.

В tool.check поле e.isReadOnly требует Claude Code v2.1.304 или новее.

Промпты и то, что читает Claude #

События промптов охватывают текст, который вводит пользователь, и текст, который Claude Code отправляет Claude сам, например системный промпт и напоминания:

| Событие | Срабатывает, когда | Хук может вернуть | | :- | :- | :- | | prompt.submit | Промпт отправлен | next({ ...e, text }), next({ ...e, context }) или { drop: reason } | | prompt.fill, prompt.suggest | Текст вот-вот попадёт в поле промпта как черновик или как приглушённая подсказка | next(e) с изменённым текстом | | prompt.edit | Пользователь редактирует поле промпта | next(e) | | prompt.autocomplete | Пользователь вводит текст в поле промпта, и у курсора заканчивается слово. e.token — это слово. Claude Code не ждёт хук: его собственные строки автодополнения показываются первыми. | { suggestions } — список строк { text, label, description }, которые показываются под собственными строками Claude Code. Выбор строки записывает её text поверх слова. | | prompt.compose | Claude Code формирует системный промпт | { sections } — список { id, text, scope } в порядке отправки | | prompt.section | Один раз для каждого именованного раздела системного промпта. e.name — это id раздела в prompt.compose. | { text } или { text: null }, чтобы пропустить раздел. Добавьте breakPromptCache: true, чтобы отправить изменённый раздел на следующем ходе. | | prompt.context | Один раз для каждого диалога, для контекста, отправляемого с первым сообщением | { blocks } | | prompt.attachment | Claude Code добавляет собственное сообщение для Claude, например напоминание. e.type указывает вид, а для видов, объявленных в типах, e.detail содержит факты, на основе которых написан текст. | { text } или { text: null }, чтобы пропустить его | | prompt.mention | Claude Code вот-вот прочитает файл, упомянутый в промпте через @. Требуется Claude Code v2.1.290 или новее. | next({ ...e, path }), чтобы прочитать другой файл, или { deny: reason } | | skill.prompt | Текст скилла раскрывается для Claude | { text } | | attribution.text | Claude Code составляет текст атрибуции для коммита или pull request | { text } |

Поля источника и frontmatter в skill.prompt #

В хуке skill.prompt можно читать эти поля наряду с именем скилла в e.skill и текстом, который читает Claude, в e.text:

| Поле | Тип | Что содержит | | :- | :- | :- | | e.source | string | Кто предоставляет скилл: policySettings, userSettings или projectSettings для скилла в корпоративном, личном или проектном расположении соответственно. Другие источники дают слово вроде plugin, mcp, syncedSkills или built-in. | | e.pluginName | string | Имя плагина для скилла, у которого e.source равно plugin | | e.path | string | Абсолютный путь к файлу SKILL.md скилла или к его файлу .md для скилла, написанного как файл команды. Отсутствует, если у скилла нет файла на этой машине, как у встроенного скилла. | | e.frontmatter | object | Frontmatter файла скилла в виде простых данных | | e.frontmatterProblem | string | Причина, по которой в e.frontmatter отсутствует frontmatter файла или один из его ключей, например is a list or a single value, not a table. Отсутствует, если e.frontmatter содержит весь frontmatter или у скилла его нет. |

Хук может передать изменённые text или frontmatter в next: хуки после него читают оба поля, а Claude читает итоговый text. Хук, который изменяет любое другое поле, завершается ошибкой.

В skill.prompt поля e.source, e.pluginName, e.path, e.frontmatter и e.frontmatterProblem требуют Claude Code v2.1.299 или новее.

Отправка изменённого раздела системного промпта или описания инструмента с помощью breakPromptCache #

Чтобы изменить раздел или описание инструмента в текущем диалоге, вызовите $.ui.invalidate('prompt.section') или $.ui.invalidate('tool.describe'), чтобы ваш хук запустился снова. Верните из него { text, breakPromptCache: true } или { description, breakPromptCache: true }. Без этого поля Claude продолжает читать текст, сохранённый вместе с диалогом, для раздела или инструмента, загруженного сразу, до начала нового диалога или сжатия контекста.

Изменённый текст доходит до Claude на следующем ходе, а кэш промптов начинается заново, поэтому этот ход выполняется медленнее и обходится дороже. Это поле требует Claude Code v2.1.321 или новее. С v2.1.299 до v2.1.321 текущий диалог получал изменённый текст на следующем ходе.

e.layers и e.source в settings.read #
  • e.layers: по одному объекту { source, settings } для каждого используемого источника, содержащего настройки, начиная с самого низкого приоритета. См. Что получает хук settings.read.

| Событие | Срабатывает, когда | Хук может вернуть | | :- | :- | :- | | session.start | Один раз для каждого загруженного мода, перед первым промптом, и снова после перезагрузки этого мода. Не срабатывает после /clear, /resume или /branch. | next(e) | | session.end | Сессия завершается или выполняется /clear, /resume либо /branch. e.reason — это clear, resume, logout, prompt_input_exit или other. /branch сообщает resume. | next(e) | | session.compact | Диалог вот-вот будет сжат | { skip: reason } | | session.receive, session.send | Сообщение приходит от другого агента или сессии либо вот-вот будет отправлено другому агенту или сессии. Субагенты #

События субагентов срабатывают, когда тип субагента предлагается Claude и когда субагент или участник команды агентов вот-вот запустится:

| Событие | Срабатывает, когда | Хук может вернуть | | :- | :- | :- | | agent.offer | Тип субагента предлагается Claude | { isOffered: false }, чтобы скрыть его | | agent.spawn | Субагент или участник команды агентов вот-вот запустится, либо субагент, который завершил работу или был остановлен, вот-вот снова запустится. Для участника команды e.isTeammate равно true. Для возобновлённого запуска задано e.resume. | next({ ...e, model }), чтобы выбрать модель того, кто запускается, или { deny: reason } |

Ваш хук agent.spawn также запускается, когда субагент, который завершил работу или был остановлен, вот-вот снова запустится, например когда Claude отправляет ему сообщение с помощью инструмента SendMessage. В этом событии e.resume равно { agentId }. Если ваш хук подсчитывает субагентов, пропускайте события, в которых задано e.resume, чтобы возобновлённый субагент не учитывался повторно.

Верните { deny: reason }, чтобы отклонить возобновлённый запуск. Запуск не начинается, и субагент остаётся в прежнем состоянии. Если запуск запросил вызов SendMessage, Claude читает в качестве результата этого вызова a plugin declined the resume:, за которым следует ваша причина. Если для возобновлённого запуска вы передаёте в next изменённое событие, например с другой model, Claude Code игнорирует это изменение.

[!NOTE]

Событие для возобновлённого запуска требует Claude Code v2.1.299 или новее. До v2.1.299 ваш хук agent.spawn не запускался при возобновлении субагента. В этих версиях, чтобы отклонять вызовы SendMessage, которые возобновляют субагента, сопоставляйте этот инструмент в хуке tool.call.

Интерфейс #

События интерфейса срабатывают, когда Claude Code рисует точку отрисовки и когда пользователь использует элемент управления, нарисованный модом. В разделе Рисование в интерфейсе показано, что возвращает хук ui.render:

| Событие | Срабатывает, когда | | :- | :- | | ui.render | Точка отрисовки вот-вот будет нарисована | | ui.resolve | Загружаются моды, один раз для каждого приложения, точки отрисовки и мода. Результат — таблица элементов, которую читает $.ui.resolve(e). | | ui.press, ui.input, ui.select | Используется Button, Input или Select, нарисованный модом | | ui.focus, ui.scroll | Вот-вот изменится элемент управления в фокусе или позиция прокрутки панели или полосы | | ui.close | Панель вот-вот закроется. e.id — это панель, а e.origin.kind — plugin, person или unload. | | ui.message | Элемент Client отправляет данные своему моду | | ui.fault | Элемент Client, нарисованный вашим модом, не удалось загрузить, отрисовать или запустить. e.phase — это load, render или run, а e.reason — сообщение об ошибке. Требуется Claude Code v2.1.289 или новее. |

Другие моды #

Эти события позволяют моду воздействовать на другие моды при их загрузке: отклонить мод или изменить получаемый им API модов:

| Событие | Срабатывает, когда | Хук может вернуть | | :- | :- | :- | | plugin.register | Модуль хуков вот-вот загрузится. e.uses перечисляет его события, вызовы API модов, переменные окружения и состояние в том виде, в каком их выводит claude plugin validate. Каждый вызов записан без префикса $., например fs.read. | { refuse: reason } | | engine.create | Для этого мода строится API модов | Изменённый API модов, чтобы добавить пространство имён. Мод вне уровня user также может скрыть его. |

Когда хук другого мода вызывает метод пространства имён, которое вы добавили в engine.create, вызовы $ вашего метода выполняются в контексте этого хука, пока все хуки на этом событии не вернут результат. Например, относительный путь разрешается относительно рабочего каталога этого хука, а $.prompt.submit отклоняется, пока ход ожидает этот хук. Вызовы, которые ваш метод делает после этого, выполняются в собственном контексте вашего мода.

Телеметрия #

События телеметрии срабатывают для записей об использовании, которые логирует Claude Code:

| Событие | Срабатывает, когда | Хук может вернуть | | :- | :- | :- | | telemetry.log, telemetry.mark | Запись телеметрии вот-вот будет записана в лог или отмечено одно использование функции. В устанавливаемом моде задайте хуку телеметрии фильтр { to: 'collector' }, например on('telemetry.log', { to: 'collector' }, hook). События хуков настроек #

Каждое событие хука настроек — это событие с именем classic.<Event>, например classic.Stop или classic.PostToolUse. e — это JSON, который хук получает через stdin.

Вызовы API модов #

Каждый метод API модов также является событием, названным по его пространству имён и методу, например fs.read, model.complete или ui.open. Хук на такое событие может вернуть next(e), { deny: reason } или { value }.

Некоторые из этих событий срабатывают и для собственных действий Claude Code, поэтому, прежде чем отклонять такое событие, проверьте, равно ли next.origin.plugin значению engine.

Поля собственных запросов http.fetch Claude Code #

В хуке http.fetch значение next.origin, равное { plugin: 'engine', tier: 'core' }, отмечает один из собственных запросов Claude Code, например запрос к модели, а не вызов $.http.fetch мода. Там, где загружен встроенный страж, ваш хук не получает эти события, за исключением случаев, когда ваш мод считается модом вашей организации.

В этих событиях e.init и value, в которое разрешается next(e), могут содержать, среди прочего, следующие поля:

| Поле | Что означает | | :- | :- | | e.init.compress | Задано, когда Claude Code сжимает тело после вашего хука. e.init.body содержит несжатое тело. Чтобы отправить тело без сжатия, вызовите next({ ...e, init: { ...e.init, compress: undefined } }). | | value.isStreaming | Равно true, потому что Claude Code сам читает тело ответа, поэтому value.text пусто. Вместо этого читайте value.status и value.headers. Чтобы ответить собственным text, верните value без isStreaming. |

Эти события и поля требуют Claude Code v2.1.321 или новее.

Чтобы подогнать дерево под точку отрисовки, читайте в хуке следующие пропсы:

  • Ширина Pane или полосы: рисуйте по e.props.bodyColumns
  • Высота Pane рядом с транскриптом: когда e.props.placement равно 'dock', e.props.scroll.bodyRows — это число строк, которые панель отводит под ваше дерево
  • Высота Pane над промптом: когда e.props.placement равно 'inline', панель растёт вместе с вашим деревом до предела, а bodyRows — это этот предел. Чтобы запросить другой предел, см. поле rows в $.ui.open.

Дополнительные правила для Button:

  • action: указывает одно из собственных действий сочетаний клавиш Claude Code, и сочетание, назначенное пользователем для этого действия, нажимает кнопку, если это аккорд или клавиша с модификатором
  • Цифровые горячие клавиши на полосе: цифровой hotkey на кнопке в полосе также срабатывает, когда пользователь вводит только эту цифру в пустой промпт и делает паузу
  • Свёрнутая полоса: пока полоса свёрнута, ни привязка action, ни горячая клавиша не нажимают кнопку в ней
  • Две кнопки с одной горячей клавишей: если две ваши кнопки в одной отрисовке указывают один и тот же hotkey, он достаётся более поздней. О кнопке другого мода с той же клавишей см. Горячие клавиши не работают.
  • variant: primary или secondary, любое другое значение вызывает исключение. В терминале кнопка primary рисуется акцентным цветом, если она не plain.
  • role: dismiss помечает кнопку закрытия, любое другое значение вызывает исключение. Само закрытие выполняйте в своём onPress. В полосе, содержащей текст и ряд кнопок, приложение Desktop может нарисовать первую кнопку dismiss в ряду как собственный элемент управления закрытием. Терминал рисует кнопку так же, как без role.

Button может содержать children вместо label:

  • Чем могут быть дочерние элементы: строки и элементы Text, например имя, за которым следует приглушённая деталь, или цветная плашка. Claude Code отклоняет любые другие элементы внутри Button.
  • Имя кнопки: label задаёт имя кнопки и по умолчанию равен тексту её дочерних элементов. Задайте key или label для кнопки, дочерние элементы которой не являются одной строкой.
  • В терминале: дочерние элементы рисуются на месте метки, а нажатие в любом месте на них считается одним нажатием, поэтому каждую строку списка можно сделать одной кнопкой
  • В приложении Desktop и расширении VS Code: кнопка рисует свой label

[!NOTE]

Button с дочерними элементами, отличными от одной строки, требует Claude Code v2.1.295 или более поздней версии.

autoFocus на любом элементе управления принимает только true, поэтому, чтобы отключить его, опустите этот проп.

Расширение VS Code игнорирует некоторые пропсы элементов и рисует элемент так, как если бы вы их не указали:

  • Box: position вместе с его top, left, right и bottom, alignSelf, borderDimColor и hover
  • Text: size, mono, tabular и hover
  • Button: hotkey, plain, autoFocus, action и hover, поэтому там пользователь нажимает кнопку щелчком или клавишей Enter, когда кнопка в фокусе. Расширение также игнорирует variant и role.
  • Code: language, path, startLine, format и wrap, поэтому код рисуется без цветов и номеров строк, а блок с format: 'diff' показывает необработанный текст diff
  • Input и Select: autoFocus, а также rows у Input
  • Svg: isInteractive

Шаги отступов Box #

Пропсы отступов Box — это gap, columnGap, rowGap, padding, margin, а также формы padding и margin для одной стороны и одной оси, например paddingX и marginTop. Каждый из них принимает число ячеек терминала, например gap: 1, или имя шага, например gap: 'md'. В терминале и расширении VS Code каждый шаг равен следующему числу ячеек:

Замена bold на weight #

bold для Text объявлен устаревшим в пользу weight, но по-прежнему работает. Чтобы заменить его для Text без weight, измените bold: true на weight: 'semibold' — в Claude Code v2.1.299 или более поздней версии результат будет тем же.

В выпусках до v2.1.299 дерево, в котором задан weight, не рисуется. Если задать для Text и bold, и weight, bold не действует.

Хуки и вызовы API модов выполняются с ограничениями по времени и размеру. Claude Code пропускает хук, превысивший ограничение по времени. Дерево, превышающее ограничение по вложенности, числу элементов, ячейкам Raster или байтам Image, не отрисовывается.

sec-default@builtin — это страж, встроенный в Claude Code, который отображается как cc-plugin-sec-default в /plugin и в отладочном логе. Там, где он загружается, он выполняется перед каждым модом, установленным человеком. Если задан управляемый prependPlugins, страж загружается, только если этот список его называет, на указанной позиции.

Его исходный код находится в каталоге mods/sec-default репозитория Claude Code.

Команды #

Эти команды и флаги загружают, проверяют и тестируют мод. Команды claude выполняются в вашей оболочке, а команды / — в промпте Claude Code. В таблице <directory> обозначает путь, который вы вводите, например claude plugin validate ./first-mod. Квадратные скобки обозначают необязательный аргумент.

| Команда | Что делает | | :- | :- | | /plugin | Показывает под своими вкладками строку вида 1 mod active · first-mod, когда загружен мод, не являющийся встроенным | | claude plugin validate <directory> | Читает манифест и модуль хуков плагина и сообщает об ошибках, обрабатываемых событиях и вызовах API модов. --strict считает предупреждения ошибками, а --json выводит машиночитаемый отчёт. | | [claude plugin test [directory]](https://code.claude.com/docs/ru/plugins/mods/test#write-a-test) | Запускает все файлы в каталоге (или в текущем каталоге, если он не указан), имена которых заканчиваются на .test.ts или .test.tsx. Завершается с кодом 1, если тест не проходит. | | claude --plugin-dir <directory> | Загружает каталог плагина на одну сессию и перезагружает его модуль хуков при сохранении.
