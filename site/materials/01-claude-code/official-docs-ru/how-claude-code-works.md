# Как работает Claude Code

> Поймите агентивный цикл, встроенные инструменты и то, как Claude Code взаимодействует с вашим проектом.

Claude Code — это агентивный помощник, который работает в вашем терминале. Хотя он отлично справляется с кодированием, он может помочь с чем угодно, что вы можете делать из командной строки: писать документацию, запускать сборки, искать файлы, исследовать темы и многое другое.

Это руководство охватывает основную архитектуру, встроенные возможности и [советы по эффективной работе с Claude Code](#work-effectively-with-claude-code). Пошаговые инструкции см. в разделе [Типичные рабочие процессы](https://code.claude.com/docs/ru/common-workflows.md). Информацию о функциях расширяемости, таких как skills, MCP и hooks, см. в разделе [Расширение Claude Code](https://code.claude.com/docs/ru/features-overview.md).

## Агентивный цикл

Когда вы даёте Claude задачу, он работает через три фазы: **сбор контекста**, **выполнение действия** и **проверка результатов**. Эти фазы переплетаются. Claude использует инструменты на протяжении всего процесса, будь то поиск файлов для понимания вашего кода, редактирование для внесения изменений или запуск тестов для проверки своей работы.

![Диаграмма агентивного цикла: ваш запрос приводит к тому, что Claude собирает контекст, выполняет действия, проверяет результаты и повторяет процесс до завершения задачи. Вы можете прервать процесс в любой момент.](https://mintcdn.com/claude-code/ikqp3_70mqIahteV/images/agentic-loop.svg?fit=max\&auto=format\&n=ikqp3_70mqIahteV\&q=85\&s=4a30fb7ce2815012a9f27c955e2c6bb0)

Цикл адаптируется к тому, что вы просите. Вопрос о вашей кодовой базе может потребовать только сбора контекста. Исправление ошибки проходит через все три фазы повторно. Рефакторинг может включать обширную проверку. Claude решает, что требуется на каждом этапе, на основе того, что он узнал на предыдущем этапе, объединяя десятки действий вместе и корректируя курс по ходу дела.

Вы также являетесь частью этого цикла. Вы можете прервать процесс в любой момент, чтобы направить Claude в другом направлении, предоставить дополнительный контекст или попросить его попробовать другой подход. Claude работает автономно, но остаётся отзывчивым к вашему вводу.

Агентивный цикл питается двумя компонентами: [моделями](#models), которые рассуждают, и [инструментами](#tools), которые действуют. Claude Code — это слой вокруг модели, который предоставляет инструменты и управляет контекстом, который видит модель. Этот окружающий слой — это то, что означает термин agentic harness.

### Модели

Claude Code использует модели Claude для понимания вашего кода и рассуждения о задачах. Claude может читать код на любом языке, понимать, как компоненты связаны, и выяснять, что нужно изменить для достижения вашей цели. Для сложных задач он разбивает работу на этапы, выполняет их и корректирует на основе того, что узнаёт.

[Доступны несколько моделей](https://code.claude.com/docs/ru/model-config.md) с различными компромиссами. Sonnet хорошо справляется с большинством задач кодирования. Opus обеспечивает более сильное рассуждение для сложных архитектурных решений. Переключайтесь с помощью `/model` во время сеанса или начните с `claude --model <name>`.

Когда в этом руководстве говорится «Claude выбирает» или «Claude решает», это модель, которая выполняет рассуждение.

### Инструменты

Инструменты — это то, что делает Claude Code агентивным. Без инструментов Claude может только отвечать текстом. С инструментами Claude может действовать: читать ваш код, редактировать файлы, запускать команды, искать в Интернете и взаимодействовать с внешними сервисами. Каждое использование инструмента возвращает информацию, которая поступает обратно в цикл, информируя следующее решение Claude.

Встроенные инструменты обычно делятся на пять категорий, каждая из которых представляет различный вид агентивности.

| Категория | Что может делать Claude |
| - | - |
| **Операции с файлами** | Читать файлы, редактировать код, создавать новые файлы, переименовывать и реорганизовывать |
| **Поиск** | Находить файлы по шаблону, искать содержимое с помощью regex, исследовать кодовые базы |
| **Выполнение** | Запускать команды shell, запускать серверы, запускать тесты, использовать git |
| **Веб** | Искать в Интернете, получать документацию, искать сообщения об ошибках |
| **Интеллект кода** | Видеть ошибки типов и предупреждения после редактирования, переходить к определениям, находить ссылки (требует [плагины интеллекта кода](https://code.claude.com/docs/ru/plugins/code-intelligence.md)) |

Это основные возможности. Claude также имеет инструменты для создания subagents, задания вам вопросов и других задач оркестрации. Полный список см. в разделе [Инструменты, доступные Claude](https://code.claude.com/docs/ru/tools-reference.md).

Claude выбирает, какие инструменты использовать, на основе вашего запроса и того, что он узнаёт по ходу дела. Когда вы говорите «исправьте неудачные тесты», Claude может:

1. Запустить набор тестов, чтобы увидеть, что не работает
2. Прочитать вывод ошибки
3. Найти соответствующие исходные файлы
4. Прочитать эти файлы, чтобы понять код
5. Отредактировать файлы, чтобы исправить проблему
6. Снова запустить тесты для проверки

Каждое использование инструмента даёт Claude новую информацию, которая информирует следующий шаг. Это агентивный цикл в действии.

**Расширение базовых возможностей:** Встроенные инструменты — это основа. Вы можете расширить то, что знает Claude, с помощью [skills](https://code.claude.com/docs/ru/skills.md), подключиться к внешним сервисам с помощью [MCP](https://code.claude.com/docs/ru/mcp.md), автоматизировать рабочие процессы с помощью [hooks](https://code.claude.com/docs/ru/hooks.md) и делегировать задачи [subagents](https://code.claude.com/docs/ru/sub-agents.md). Эти расширения образуют слой поверх основного агентивного цикла. Руководство по выбору правильного расширения для ваших потребностей см. в разделе [Расширение Claude Code](https://code.claude.com/docs/ru/features-overview.md).

## Что Claude может получить доступ

Когда вы запускаете `claude` в каталоге, Claude Code получает доступ к:

* **Вашему проекту.** Файлы в вашем каталоге и подкаталогах, а также файлы в других местах с вашего разрешения.
* **Вашему терминалу.** Любой команде, которую вы можете запустить: инструменты сборки, git, менеджеры пакетов, системные утилиты, скрипты. Если вы можете это сделать из командной строки, Claude тоже может.
* **Вашему состоянию git.** Текущей ветке, незафиксированным изменениям и истории недавних коммитов.
* **Вашему [CLAUDE.md](https://code.claude.com/docs/ru/memory.md).** Файл markdown, где вы храните инструкции, специфичные для проекта, соглашения и контекст, который Claude должен знать в каждой сессии. Если ваш репозиторий содержит AGENTS.md для других агентов кодирования, Claude [может прочитать его](https://code.claude.com/docs/ru/memory.md#agents-md) вместо CLAUDE.md.
* **[Автоматической памяти](https://code.claude.com/docs/ru/memory.md#auto-memory).** Обучение, которое Claude сохраняет автоматически по мере работы, например ваши предпочтения. Первые 200 строк или 25 КБ MEMORY.md, в зависимости от того, что меньше, загружаются в начале каждого сеанса.
* **Расширениям, которые вы настраиваете.** [MCP servers](https://code.claude.com/docs/ru/mcp.md) для внешних сервисов, [skills](https://code.claude.com/docs/ru/skills.md) для рабочих процессов, [subagents](https://code.claude.com/docs/ru/sub-agents.md) для делегированной работы и [Claude в Chrome](https://code.claude.com/docs/ru/chrome.md) для взаимодействия с браузером.

Поскольку Claude видит весь ваш проект, он может работать по всему проекту. Когда вы просите Claude «исправить ошибку аутентификации», он ищет соответствующие файлы, читает несколько файлов для понимания контекста, вносит скоординированные изменения в них, запускает тесты для проверки исправления и фиксирует изменения, если вы попросите. Это отличается от встроенных помощников кода, которые видят только текущий файл.

## Среды и интерфейсы

[Агентивный цикл](#the-agentic-loop), [инструменты](#tools) и возможности одинаковы везде, где вы используете Claude Code. Что меняется, так это то, где выполняется код и как вы с ним взаимодействуете.

### Среды выполнения

Claude Code работает в трёх средах, каждая с различными компромиссами для того, где выполняется ваш код.

| Среда | Где выполняется код | Вариант использования |
| - | - | - |
| **Локальная** | Ваша машина | По умолчанию. Полный доступ к вашим файлам, инструментам и среде |
| **Облако** | Управляемые Anthropic виртуальные машины или [самостоятельно размещённые среды](https://code.claude.com/docs/ru/self-hosted-environments), которые управляет ваша организация | Делегировать задачи, работать с репозиториями, которые у вас нет локально |
| **Удалённое управление** | Ваша машина, управляемая из браузера | Использовать веб-интерфейс, сохраняя всё локально |

### Интерфейсы

Вы можете получить доступ к Claude Code через терминал, [настольное приложение](https://code.claude.com/docs/ru/desktop.md), [расширения IDE](https://code.claude.com/docs/ru/vs-code.md), [claude.ai/code](https://claude.ai/code), [Remote Control](https://code.claude.com/docs/ru/remote-control.md), [Slack](https://code.claude.com/docs/ru/slack.md) и [CI/CD pipelines](https://code.claude.com/docs/ru/github-actions.md). Интерфейс определяет, как вы видите и взаимодействуете с Claude, но основной агентивный цикл идентичен. Полный список см. в разделе [Используйте Claude Code везде](https://code.claude.com/docs/ru/overview.md#use-claude-code-everywhere).

## Работа с сеансами

Claude Code сохраняет вашу беседу локально по мере работы. Каждое сообщение, использование инструмента и результат записываются в простой текстовый файл JSONL в `~/.claude/projects/`, что позволяет [откатывать](#undo-changes-with-checkpoints), [возобновлять и разветвлять](#resume-or-fork-sessions) сеансы. Перед тем как Claude вносит изменения в код, он также создаёт снимок затронутых файлов, чтобы вы могли откатить, если потребуется. Информацию о путях, сохранении и способах очистки этих данных см. в разделе [данные приложения в `~/.claude`](https://code.claude.com/docs/ru/claude-directory#application-data).

**Сеансы независимы.** Каждый новый сеанс начинается со свежего context window, без истории беседы из предыдущих сеансов. Claude может сохранять обучение между сеансами, используя [автоматическую память](https://code.claude.com/docs/ru/memory.md#auto-memory), и вы можете добавить свои собственные постоянные инструкции в [CLAUDE.md](https://code.claude.com/docs/ru/memory.md).

### Работа между ветвями

Каждая беседа Claude Code — это сеанс, привязанный к вашему текущему каталогу. Средство выбора `/resume` показывает сеансы из текущего worktree по умолчанию, с сочетаниями клавиш для расширения списка на другие worktrees или проекты. Полный список сочетаний клавиш средства выбора и способ разрешения имён см. в разделе [Управление сеансами](https://code.claude.com/docs/ru/sessions.md#use-the-session-picker).

Claude видит файлы вашей текущей ветви. Когда вы переключаетесь между ветвями, Claude видит файлы новой ветви, но история вашей беседы остаётся той же. Claude помнит, что вы обсуждали, даже после переключения.

Поскольку сеансы привязаны к каталогам, вы можете запускать параллельные сеансы Claude Code, используя [git worktrees](https://code.claude.com/docs/ru/worktrees.md), которые создают отдельные каталоги для отдельных ветвей.

### Возобновление или разветвление сеансов

Возобновление сеанса с помощью `claude --continue` или `claude --resume` открывает его повторно с тем же ID сеанса и добавляет новые сообщения к существующей беседе. Разветвление с помощью `--fork-session` или `/branch` копирует историю в новый ID сеанса, оставляя исходный неизменным.

![Диаграмма непрерывности сеанса: возобновление продолжает тот же сеанс, разветвление создаёт новую ветвь с новым ID.](https://mintcdn.com/claude-code/ikqp3_70mqIahteV/images/session-continuity.svg?fit=max\&auto=format\&n=ikqp3_70mqIahteV\&q=85\&s=04ed0984a58e4127e05b3640265241a3)

Информацию о флагах возобновления, средстве выбора `/resume`, именовании и том, что происходит, когда один и тот же сеанс открыт в двух терминалах, см. в разделе [Управление сеансами](https://code.claude.com/docs/ru/sessions.md).

### Context window

Context window Claude содержит историю вашей беседы, содержимое файлов, выходы команд, [CLAUDE.md](https://code.claude.com/docs/ru/memory.md), [автоматическую память](https://code.claude.com/docs/ru/memory.md#auto-memory), загруженные skills и системные инструкции. По мере работы контекст заполняется. Claude автоматически компактирует, но инструкции с начала беседы могут быть потеряны. Поместите постоянные правила в CLAUDE.md и запустите `/context`, чтобы увидеть, что использует место.

Для интерактивного пошагового руководства по тому, что загружается и когда, см. [Исследуйте context window](https://code.claude.com/docs/ru/context-window.md).

#### Context Claude Code добавляет самостоятельно

Если Claude следует правилу, которое вы не писали, например добавляет трейлер `Co-Authored-By` к коммиту, правило могло поступить из [системного напоминания](https://code.claude.com/docs/ru/glossary.md#system-reminder). По мере работы Claude Code добавляет свой собственный контекст к беседе наряду с вашими сообщениями:

* Ваши файлы CLAUDE.md
* Инструкции вашего [стиля вывода](https://code.claude.com/docs/ru/output-styles.md)
* Примечание о том, что файл, который Claude ранее редактировал, с тех пор изменился на диске
* Строки атрибуции коммита и pull request

Чтобы изменить или удалить строки атрибуции, установите [`attribution`](https://code.claude.com/docs/ru/settings-reference#attribution). Чтобы удалить встроенные инструкции Claude Code для коммитов и pull request, установите [`includeGitInstructions`](https://code.claude.com/docs/ru/settings-reference#includegitinstructions) на `false`. Для других переключателей см. [Отключение контекста, который заменяет ваш агент](https://code.claude.com/docs/ru/agent-sdk/modifying-system-prompts.md#turn-off-the-context-your-agent-replaces).

#### Когда контекст заполняется

Claude Code автоматически управляет контекстом по мере приближения к лимиту. Он сжимает диалог в краткое резюме. Резюме сохраняет ваши запросы и ключевые фрагменты кода, но подробные инструкции из начала диалога могут быть потеряны. Помещайте постоянные правила в CLAUDE.md, а не полагайтесь на историю диалога.

Чтобы контролировать, что сохраняется во время компактирования, добавьте раздел «Compact Instructions» в CLAUDE.md или запустите `/compact` с фокусом (например, `/compact focus on the API changes`).

Если один файл или выход инструмента настолько велик, что контекст заполняется снова после каждого резюме, Claude Code прекращает auto-compact после нескольких попыток и вместо этого показывает ошибку. Информацию о шагах восстановления см. в разделе [Auto-compaction stops with a thrashing error](https://code.claude.com/docs/ru/troubleshooting.md#auto-compaction-stops-with-a-thrashing-error).

Запустите `/context`, чтобы увидеть, что использует место. Определения инструментов MCP отложены по умолчанию и загружаются по требованию через [поиск инструментов](https://code.claude.com/docs/ru/mcp.md#scale-with-mcp-tool-search), поэтому только имена инструментов и инструкции сервера потребляют контекст, пока Claude не использует конкретный инструмент.

#### Управление контекстом с помощью skills и subagents

Помимо компактирования, вы можете использовать другие функции для контроля того, что загружается в контекст.

[Skills](https://code.claude.com/docs/ru/skills.md) загружаются по требованию. Claude видит описания skills в начале сеанса, но полное содержимое загружается только при использовании skill. Для skills, которые вы вызываете вручную, установите `disable-model-invocation: true`, чтобы описания не попадали в контекст, пока они вам не понадобятся. Для skills, которые вы не писали, используйте [`skillOverrides`](https://code.claude.com/docs/ru/skills#override-skill-visibility-from-settings), чтобы сделать то же самое из параметров.

[Subagents](https://code.claude.com/docs/ru/sub-agents.md) работают в своём собственном context window. Subagent начинает с нуля, если это не [fork](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation), который начинается с копии вашей беседы на данный момент. В любом случае, вызовы инструментов subagent остаются вне вашего контекста, и Claude получает резюме, когда subagent завершает работу.

Информацию о том, что стоит каждая функция, см. в разделе [затраты контекста](https://code.claude.com/docs/ru/features-overview.md#understand-context-costs), а советы по управлению контекстом см. в разделе [снижение использования токенов](https://code.claude.com/docs/ru/costs.md#reduce-token-usage).

## Оставайтесь в безопасности с checkpoints и разрешениями

Claude имеет два механизма безопасности: checkpoints позволяют откатывать изменения файлов, а разрешения контролируют, что Claude может делать без запроса.

### Откат изменений с checkpoints

**Каждое редактирование файла обратимо.** Перед редактированием любого файла Claude создаёт снимок текущего содержимого. Если что-то пойдёт не так, нажмите `Esc` дважды, чтобы откатиться к предыдущему состоянию, или попросите Claude отменить.

Checkpoints отделены от git и остаются доступными при возобновлении разговора. Они охватывают только изменения файлов, и восстановление [пропускает символические и жёсткие ссылки](https://code.claude.com/docs/ru/checkpointing.md#symlinked-and-hard-linked-paths-not-restored). Действия, которые влияют на удалённые системы (базы данных, API, развёртывания), не могут быть checkpointed. Вы контролируете их с помощью режима разрешений и правил разрешений.

### Контролируйте, что может делать Claude

Выберите режим разрешений, чтобы установить, что Claude может делать без запроса. Нажмите `Shift+Tab`, чтобы циклически переключаться между режимами разрешений:

* **Auto**: классификатор проверяет большинство действий в фоновом режиме и блокирует рискованные вместо того, чтобы спрашивать вас. В Claude Code v2.1.283 или более поздней версии это [встроенный начальный режим разрешений](https://code.claude.com/docs/ru/permission-modes.md#which-mode-a-session-starts-in) для интерактивных сессий в терминале и VS Code. В более ранних версиях это встроенный начальный режим разрешений только на планах Pro, Max, Ultra и Team.
* **Manual**: Claude спрашивает перед редактированием файлов и командами shell
* **Accept edits**: Claude редактирует файлы и запускает общие команды файловой системы, такие как `mkdir` и `mv`, без запроса, всё ещё спрашивает для других команд
* **Plan**: Claude исследует и предлагает план без редактирования ваших исходных файлов

Вы также можете разрешить определённые команды в `.claude/settings.json`, чтобы Claude не спрашивал каждый раз. Это полезно для доверенных команд, таких как `npm test` или `git status`. Параметры могут быть ограничены от политик на уровне организации до личных предпочтений. Подробности см. в разделе [Разрешения](https://code.claude.com/docs/ru/permissions.md).

## Эффективная работа с Claude Code

Эти советы помогут вам получить лучшие результаты от Claude Code. Подробнее о конкретных промптах, проверке и правилах, которые стоит применять принудительно, а не указывать в промптах, см. [Лучшие практики](https://code.claude.com/docs/ru/best-practices.md).

### Попросите помощь у Claude Code

Claude Code может научить вас, как его использовать. Задавайте вопросы типа «как мне настроить hooks?» или «какой лучший способ структурировать мой CLAUDE.md?» и Claude объяснит.

Встроенные команды также помогут вам в настройке:

* `/init` проведёт вас через создание CLAUDE.md для вашего проекта
* `/doctor` запускает проверку настройки, которая диагностирует проблемы с установкой и конфигурацией и может их исправить

### Это беседа

Claude Code — это беседа. Вам не нужны идеальные запросы. Начните с того, что вы хотите, затем уточните:

```text theme={null}
Исправьте ошибку входа
```

\[Claude исследует, пробует что-то]

```text theme={null}
Это не совсем правильно. Проблема в обработке сессии.
```

\[Claude корректирует подход]

Когда первая попытка не удалась, вы не начинаете заново. Вы итерируете.

#### Прерывание и управление

Вы можете перенаправить Claude в любой момент без начала заново. Сделайте одно из следующего:

* **Нажмите `Esc`**, чтобы остановить Claude немедленно. Выполняемый вызов инструмента отменяется, и Claude ожидает вашей следующей инструкции. Если у вас есть сообщения в очереди, Claude Code [отправляет их далее](https://code.claude.com/docs/ru/interactive-mode.md#queue-messages-while-claude-works).
* **Введите коррекцию и нажмите `Enter`** без остановки Claude. Сообщение отображается как поставленное в очередь в разговоре. Если Claude выполняет вызовы инструментов, он прочитает сообщение, как только эти вызовы завершатся, в рамках того же хода, и скорректирует перед своим следующим шагом. [Поставьте сообщения в очередь, пока Claude работает](https://code.claude.com/docs/ru/interactive-mode.md#queue-messages-while-claude-works) охватывает, когда отправляются другие поставленные в очередь записи.

### Делегируйте, не диктуйте

Думайте о делегировании способному коллеге. Дайте контекст и направление, затем доверьте Claude разобраться с деталями:

```text theme={null}
Процесс оформления заказа сломан для пользователей с истёкшими картами.
Соответствующий код находится в src/payments/. Можете ли вы исследовать и исправить это?
```

Вам не нужно указывать, какие файлы читать или какие команды запускать. Claude это выясняет.
