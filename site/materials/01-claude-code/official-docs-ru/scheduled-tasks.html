Запуск подсказок по расписанию #

Используйте /loop и инструменты планирования cron для повторного запуска подсказок, опроса статуса или установки одноразовых напоминаний в сеансе Claude Code.

Запланированные задачи уровня сессии позволяют Claude автоматически повторно запускать промпт через определённый интервал в рамках сессии Claude Code. Используйте их для опроса развёртывания, контроля pull request, проверки долгоживущей сборки или напоминания себе о чём-то позже в сессии.

[!NOTE]

Эти случаи рассматриваются на других страницах:

  • Реагирование на события по мере их возникновения вместо опроса: см. Channels. Ваш CI может отправить сбой непосредственно в сессию.
  • Продолжение работы сессии от одного хода к другому до выполнения условия, а не через интервал: см. /goal.

Задачи привязаны к сессии. При возобновлении с помощью --resume или --continue Claude Code восстанавливает задачи, которые не истекли, за исключением перечисленных в разделе Ограничения. Для планирования, которое сохраняется независимо от любой сессии, создайте облачную запланированную задачу, настройте запланированную задачу Desktop или используйте GitHub Actions.

Сравните варианты планирования #

Claude Code предлагает три способа планирования повторяющихся или одноразовых задач:

| | Cloud | Desktop | /loop | | :- | :- | :- | :- | | Запускается на | Cloud, управляется Anthropic по умолчанию | Ваша машина | Ваша машина | | Требует включенную машину | Нет | Да | Да | | Требует открытую сессию | Нет | Нет | Да | | Сохраняется после перезагрузки | Да | Да | Восстанавливается при --resume, с исключениями | | Доступ к локальным файлам | Нет (свежий клон) | Да | Да | | MCP servers | Connectors настроены для каждой задачи | Config files и connectors | Наследуется из сессии | | Запросы разрешений | Авторежим по умолчанию | Настраивается для каждой задачи | Наследуется из сессии | | Настраиваемое расписание | Да | Да | Да | | Минимальный интервал | 1 час | 1 минута, если его задаёт Claude, 1 час в формах | 1 минута |

[!TIP]

Используйте облачные задачи для работы, которая должна выполняться надежно без вашей машины. Используйте Desktop задачи, когда вам нужен доступ к локальным файлам и инструментам. Используйте /loop для быстрого опроса во время сессии.

Запустите подсказку повторно с помощью /loop #

Встроенный навык /loop bundled skill — это самый быстрый способ запустить подсказку повторно, пока сеанс остается открытым. Интервал и подсказка являются необязательными, и то, что вы предоставляете, определяет поведение цикла.

| Что вы предоставляете | Пример | Что происходит | | :- | :- | :- | | Интервал и подсказка | /loop 5m check the deploy | Ваша подсказка запускается по фиксированному расписанию | | Только подсказка | /loop check the deploy | Ваша подсказка запускается с интервалом, который выбирает Claude на каждой итерации | | Только интервал или ничего | /loop | Запускается встроенная подсказка обслуживания, или ваш loop.md, если он существует |

Вы также можете передать навык в качестве подсказки, например /loop 20m /review-pr 1234, чтобы повторно запустить этот навык на каждой итерации. Запланированное выполнение запускает только навыки, которые Claude разрешено вызывать самостоятельно. Следующие элементы поступают к Claude как простой текст вместо выполнения:

  • Встроенные команды, такие как /permissions, /model или /clear
  • Навыки, отмеченные disable-model-invocation: true, включая встроенный навык /verify
  • Навыки, скрытые от Claude параметром skillOverrides или правилом Skill deny
  • MCP prompts, такие как /mcp__github__list_prs

Запуск с фиксированным интервалом #

Когда вы указываете интервал, Claude преобразует его в выражение cron, планирует задание и подтверждает кадр и ID задания.

```text theme={null} /loop 5m check if the deployment finished and tell me what happened


Интервал может предшествовать подсказке как отдельный токен, например `30m`, или следовать за ней как предложение, например `every 2 hours`. Поддерживаемые единицы: `s` для секунд, `m` для минут, `h` для часов и `d` для дней.

Секунды округляются до ближайшей минуты, так как cron имеет гранулярность в одну минуту. Интервалы, которые не соответствуют чистому шагу cron, такие как `7m` или `90m`, округляются до ближайшего интервала, который соответствует, и Claude сообщает вам, что он выбрал.

### Позвольте Claude выбрать интервал

Когда вы опускаете интервал, Claude выбирает его динамически вместо запуска по фиксированному расписанию cron. После каждой итерации он выбирает задержку от одной минуты до одного часа на основе того, что он наблюдал: короткие ожидания, пока сборка завершается или PR активен, более длительные ожидания, когда ничего не ожидается. Выбранная задержка и причина для нее выводятся в конце каждой итерации.

Приведенный ниже пример проверяет CI и комментарии рецензии, при этом Claude ждет дольше между итерациями, когда PR становится неактивным:

/loop check whether CI passed and address any review comments


В сеансе, где доступен [инструмент Monitor](https://code.claude.com/docs/ru/tools-reference.md#monitor-tool), Claude может использовать его напрямую, когда вы просите динамическое расписание `/loop`. Monitor запускает фоновый скрипт и передает каждую строку вывода обратно, что полностью избегает опроса и часто более эффективно по токенам и отзывчиво, чем повторный запуск подсказки с интервалом.

Динамически запланированный цикл отображается в вашем [списке запланированных задач](#manage-scheduled-tasks) как любая другая задача, поэтому вы можете вывести его в списке или отменить тем же способом. Список показывает его ожидающее пробуждение как одноразовую задачу, поэтому пробуждение, запланированное на `:00` или `:30`, может [запуститься немного раньше](#when-a-one-shot-task-runs-early). [Семидневное истечение срока](#seven-day-expiry) также применяется к циклу.

> [!NOTE]
>
> Динамически выбранные интервалы и [встроенная подсказка обслуживания](#run-the-built-in-maintenance-prompt) работают на каждом поставщике и с [получением флага функции](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching) отключенным. На Amazon Bedrock, Claude Platform на AWS, Google Cloud's Agent Platform и Microsoft Foundry, или с отключенным получением, оба требуют Claude Code v2.1.248 или позже.

### Запуск встроенной подсказки обслуживания

Когда вы опускаете подсказку, Claude использует встроенную подсказку обслуживания вместо предоставленной вами. На каждой итерации он работает со следующим по порядку:

* продолжить любую незавершенную работу из разговора
* ухаживать за pull request текущей ветки: комментарии рецензии, неудачные запуски CI, конфликты слияния
* запустить проходы очистки, такие как охота на ошибки или упрощение, когда ничего больше не ожидается

Каждый запуск проходит [проверки разрешений](https://code.claude.com/docs/ru/permissions.md) вашей сессии, прежде чем выполнить push или что-либо удалить.

Простой `/loop` запускает этот промпт с [динамически выбираемым интервалом](#let-claude-choose-the-interval):

/loop


Добавьте интервал, например `/loop 15m`, чтобы вместо этого запускать его по фиксированному расписанию. Чтобы заменить встроенный промпт собственным промптом по умолчанию, см. [Настройка промпта по умолчанию с помощью loop.md](#customize-the-default-prompt-with-loop-md).

### Настройте подсказку по умолчанию с помощью loop.md

Создайте файл `loop.md`, чтобы заменить [встроенную подсказку обслуживания](#run-the-built-in-maintenance-prompt) своими собственными инструкциями. Он определяет одну подсказку по умолчанию для простого `/loop`, а не список отдельных запланированных задач, и Claude Code игнорирует его всякий раз, когда вы предоставляете подсказку в командной строке. Чтобы запланировать дополнительные подсказки рядом с ней, используйте `/loop <prompt>` или [попросите Claude напрямую](#manage-scheduled-tasks).

Claude ищет файл в двух местах и использует первый найденный.

| Путь | Область |
| :- | :- |
| `.claude/loop.md` | На уровне проекта. Имеет приоритет, когда оба файла существуют. |
| `~/.claude/loop.md` | На уровне пользователя. Применяется в любом проекте, который не определяет свой собственный. |

Файл представляет собой простой Markdown без требуемой структуры. Напишите его так, как если бы вы вводили подсказку `/loop` напрямую. Следующий пример поддерживает ветку выпуска в хорошем состоянии:

Check the release/next PR. If CI is red, pull the failing job log, diagnose, and push a minimal fix. If new review comments have arrived, address each one and resolve the thread. If everything is green and quiet, say so in one line.


Изменения в `loop.md` вступают в силу на следующей итерации, поэтому вы можете уточнить инструкции во время выполнения цикла. Когда `loop.md` не существует ни в одном месте, цикл возвращается к встроенной подсказке обслуживания. Держите файл кратким: содержимое, превышающее 25 000 байт, усекается.

### Остановите цикл

* **[Цикл с самостоятельным темпом](#let-claude-choose-the-interval)**: пока цикл ожидает следующей итерации, нажмите `Esc` в пустом промпте, чтобы остановить его. Вы также можете остановить его с помощью `Ctrl+C`, пока Claude бездействует, за исключением [фоновой сессии, к которой вы подключились](#detach-without-stopping-a-loop). Уведомление `Pending wakeup cancelled` подтверждает, что цикл больше не сработает.
* **[Цикл с фиксированным интервалом](#run-on-a-fixed-interval)**: чтобы остановить цикл, такой как `/loop 5m`, попросите Claude отменить его, например `cancel the deploy check loop`. `Esc` и `Ctrl+C` не останавливают его, как и любую задачу, которую вы [запланировали, попросив Claude напрямую](#manage-scheduled-tasks). Цикл, который вы не отменили, завершается по [истечении семи дней](#seven-day-expiry).

В [режиме самостоятельного выполнения](#let-claude-choose-the-interval) Claude также может завершить цикл самостоятельно после завершения задачи. Claude вызывает инструмент [`ScheduleWakeup`](https://code.claude.com/docs/ru/tools-reference) с `stop: true`, который немедленно отменяет ожидающее пробуждение. Если итерация заканчивается без переплана или остановки, Claude Code планирует одно резервное пробуждение примерно через 20 минут и завершает цикл, когда эта итерация также не переплана.

#### Отключение без остановки цикла

Когда вы [подключены к фоновой сессии](https://code.claude.com/docs/ru/agent-view.md#attach-to-a-session) и Claude бездействует, дважды нажмите `Ctrl+C` в пустом промпте, чтобы отключиться. Цикл с самостоятельным темпом, ожидающий там следующей итерации, продолжает работать, и эта итерация начинается по расписанию. Чтобы вместо этого остановить цикл, нажмите `Esc` перед отключением. Отключение с помощью `Ctrl+C` без остановки цикла требует Claude Code v2.1.295 или новее.

## Установите одноразовое напоминание

Для одноразовых напоминаний опишите то, что вы хотите, на естественном языке вместо использования `/loop`. Claude планирует одноразовую задачу, которая удаляет себя после выполнения.

remind me at 3pm to push the release branch

in 45 minutes, check whether the integration tests passed


Claude привязывает время срабатывания к определённой минуте и часу, используя выражение cron, и подтверждает, когда оно сработает.

## Управление запланированными задачами в рамках сессии

Попросите Claude на естественном языке перечислить или отменить задачи, или обратитесь непосредственно к базовым инструментам.

what scheduled tasks do I have?

cancel the deploy check job


Под капотом Claude использует эти инструменты:

| Инструмент | Назначение |
| :- | :- |
| `CronCreate` | Запланировать новую задачу. Принимает 5-полевое выражение cron, подсказку для запуска и указание на то, повторяется ли она или срабатывает один раз. |
| `CronList` | Перечислить запланированные задачи с их ID, расписаниями, [временем следующего запуска](#jitter) и промптами. |
| `CronDelete` | Отменить задачу по ID. |

Каждая запланированная задача имеет 8-символьный ID, который вы можете передать в `CronDelete`. Сеанс может одновременно содержать до 50 запланированных задач.

## Как выполняются запланированные задачи в рамках сессии

Планировщик каждую секунду проверяет, не наступил ли срок выполнения задач, и ставит такие задачи в очередь с низким приоритетом. Запланированный промпт срабатывает между вашими ходами, а не в тот момент, когда Claude формирует ответ. Если Claude занят, когда наступает срок задачи, промпт ожидает завершения текущего хода.

Все значения времени интерпретируются в вашем локальном часовом поясе. Cron-выражение вроде `0 9 * * *` означает 9 утра там, где вы запускаете Claude Code, а не по UTC.

### Джиттер

Запланированная задача может выполниться не в то время, которое указано в её расписании. Если бы задачи каждой сессии выполнялись точно по расписанию, многие из них обращались бы к API в один и тот же момент, поэтому Claude Code сдвигает время выполнения каждой задачи. Повторяющиеся задачи выполняются с опозданием, за исключением задачи, которая выполняется каждые пять минут и записана как `*/5 * * * *`. Одноразовые задачи, запланированные на начало часа или на половину часа, выполняются немного раньше.

Чтобы узнать, когда наступит следующий срок выполнения задачи, посмотрите на строку под вызовом `CronCreate` от Claude в вашем терминале. В этой строке после расписания указано это время, например `next run 10:21 AM`. Чтобы проверить снова позже, [попросите Claude вывести список ваших задач](#manage-scheduled-tasks) и найдите `next run` в строках под вызовом `CronList`. Для отображения времени следующего запуска в этих строках требуется Claude Code v2.1.299 или новее.

#### Насколько поздно выполняется повторяющаяся задача

Если повторяющаяся задача не выполняется каждые пять минут, каждый её запуск начинается с опозданием не более чем на половину интервала до следующего запуска и не более чем на 30 минут. Ваша задача относится к одному из трёх случаев:

* **Равномерно распределённые запуски**: задача с равными интервалами, например ежечасная, ежедневная или каждые 10 минут, каждый раз выполняется с опозданием на одно и то же количество минут, в том числе когда сессия простаивает.
* **Неравномерно распределённые запуски**: задача с неравными интервалами, например запланированная на `:00` и `:15` каждого часа, может выполняться с разным опозданием при каждом запуске.
* **Каждые пять минут**: задача, записанная как `*/5 * * * *`, не задерживается. Запуск ровно через пять минут после предыдущего начался бы уже после истечения пятиминутного [кэша промптов](https://code.claude.com/docs/ru/prompt-caching.md#which-ttl-each-request-gets), поэтому каждый запуск начинается на 15 секунд раньше.

Найдите своё расписание в первом столбце этой таблицы, чтобы узнать, когда начинается каждый его запуск.

| Расписание | Когда начинается каждый запуск |
| :- | :- |
| Каждые 5 минут, записывается как `*/5 * * * *` — именно это создаёт `/loop 5m` | Через 4 минуты 45 секунд после предыдущего запуска |
| Каждые 10 минут | С опозданием от 0 до 5 минут |
| Каждые 30 минут | С опозданием от 0 до 15 минут |
| Каждый час или реже, например ежедневно | С опозданием от 0 до 30 минут |

Например, `7,37 * * * *` планирует задачу на `:07` и `:37`, между которыми 30 минут, поэтому её задержка составляет от 0 до 15 минут. Если задержка этой задачи равна 14 минутам, она выполняется в `:21` и `:51` каждый час. Изменение расписания на другую минуту сдвигает время выполнения, и задержка по-прежнему добавляется сверху.

#### Когда одноразовая задача выполняется раньше

Одноразовая задача, запланированная на `:00` или `:30`, выполняется раньше — до 90 секунд. Claude Code не сдвигает одноразовую задачу, запланированную на любую другую минуту, поэтому, когда время важно, планируйте её не на начало часа и не на половину часа: `3 9 * * *` вместо `0 9 * * *`.

### Истечение срока через семь дней

Срок действия повторяющихся задач автоматически истекает через 7 дней после создания. Задача срабатывает в последний раз, а затем удаляет себя. Это ограничивает время работы забытого цикла. Если вам нужно, чтобы повторяющаяся задача действовала дольше, отмените и создайте её заново до истечения срока или используйте [облачные запланированные задачи](https://code.claude.com/docs/ru/routines.md) либо [запланированные задачи Desktop](https://code.claude.com/docs/ru/desktop-scheduled-tasks.md) для долговременного планирования.

## Справочник выражений cron

`CronCreate` принимает стандартные 5-полевые выражения cron: `minute hour day-of-month month day-of-week`. Все поля поддерживают подстановочные знаки (`*`), одиночные значения (`5`), шаги (`*/15`), диапазоны (`1-5`) и списки, разделённые запятыми (`1,15,30`).

| Пример | Значение |
| :- | :- |
| `*/5 * * * *` | Каждые 5 минут |
| `0 * * * *` | Каждый час в начале часа |
| `7 * * * *` | Каждый час в 7 минут |
| `0 9 * * *` | Каждый день в 9 утра по местному времени |
| `0 9 * * 1-5` | Будни в 9 утра по местному времени |
| `30 14 15 3 *` | 15 марта в 14:30 по местному времени |

День недели использует `0` или `7` для воскресенья через `6` для субботы. Расширенный синтаксис, такой как `L`, `W`, `?`, и псевдонимы имён, такие как `MON` или `JAN`, не поддерживаются.

Когда ограничены как день месяца, так и день недели, дата совпадает, если совпадает любое поле. Это следует стандартной семантике vixie-cron.

## Отключите запланированные задачи в рамках сеанса

Установите `CLAUDE_CODE_DISABLE_CRON=1` в вашей среде, чтобы полностью отключить планировщик. `CronCreate` и `/loop` становятся недоступными, и любые уже запланированные задачи перестают срабатывать. Пока файл `.claude/scheduled_tasks.json` проекта содержит задачи, `CronList` и `CronDelete` остаются доступными, поэтому вы по-прежнему можете попросить Claude вывести их список или отменить их. См. [Переменные окружения](https://code.claude.com/docs/ru/env-vars.md) для полного списка флагов отключения.

## Ограничения

Планирование, привязанное к сеансу, имеет присущие ему ограничения:

* Задачи срабатывают только во время работы Claude Code и в режиме ожидания. Закрытие терминала или выход из сеанса отменяет всё. [Перемещение сеанса в фоновый режим](https://code.claude.com/docs/ru/agent-view.md#from-inside-a-session) переносит задачи `/loop` в фоновый сеанс, который продолжает работать без терминала.
* Нет наверстывания пропущенных срабатываний. Если запланированное время задачи проходит, пока Claude занят долгоживущим запросом, она срабатывает один раз, когда Claude становится свободным, а не один раз за каждый пропущенный интервал.
* В [фоновой сессии](https://code.claude.com/docs/ru/agent-view.md#from-inside-a-session) [самостоятельный цикл](#let-claude-choose-the-interval) останавливается, если время его следующего пробуждения наступает, когда процесс сессии не запущен, например после сбоя. Когда процесс запускается снова, в транскрипте отображается [уведомление о том, что пробуждение не сработает](https://code.claude.com/docs/ru/errors.md#restarted-after-its-next-loop-wakeup-was-due). Чтобы продолжить цикл, [ответьте в сессии](https://code.claude.com/docs/ru/agent-view.md#peek-and-reply) и попросите Claude продолжить его выполнение.
* Когда вы возобновляете сессию с помощью `claude --resume` или `claude --continue`, Claude Code восстанавливает задачи, запланированные с помощью `CronCreate`, за исключением повторяющихся задач, которые [истекли](#seven-day-expiry), и одноразовых задач, чьё запланированное время уже прошло. [Самостоятельный `/loop`](#let-claude-choose-the-interval) не восстанавливается, поэтому запустите `/loop` снова, чтобы перезапустить его.
* Восстановленная повторяющаяся задача не срабатывает для запусков, пропущенных, пока сессия не работала. Её следующий запуск — первый, время которого наступает после возобновления, и к этому запуску применяется [джиттер](#jitter).
* Когда вы возобновляете сессию с помощью `claude --resume` или `claude --continue`, Claude Code не перезапускает фоновые команды Bash и мониторы, которые работали на момент завершения сессии. Если какой-либо из них всё ещё нужен, попросите Claude запустить его снова.
* С [отключённой загрузкой флагов функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching) Claude Code сохраняет задачу, которую вы попросили сохранить между сеансами, в файле `.claude/scheduled_tasks.json` проекта. Когда директория `.claude` или этот файл является символической ссылкой, Claude Code возвращает ошибку вместо планирования задачи. Сохранённая задача запускается только в папке проекта, где вы её создали. Если вы скопируете файл в другую папку, например в новый worktree, сеансы там будут отображать скопированные задачи, но не будут их запускать, поэтому создайте задачу снова в этой папке.

Для автоматизации, управляемой cron, которая должна работать без присмотра:

* [Облачные запланированные задачи](https://code.claude.com/docs/ru/routines.md): запуск в облаке по расписанию, через вызов API или на события GitHub
* [GitHub Actions](https://code.claude.com/docs/ru/github-actions.md): используйте триггер `schedule` в CI
* [Desktop запланированные задачи](https://code.claude.com/docs/ru/desktop-scheduled-tasks.md): запуск локально на вашей машине
