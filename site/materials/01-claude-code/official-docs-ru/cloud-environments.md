# Настройка облачных сред

> Настройте облачные среды для облачных сеансов Claude Code: уровни доступа в сети, переменные окружения, скрипты настройки и кэширование среды.

> [!NOTE]
>
> Облачные среды применяются к [облачным сессиям](https://code.claude.com/docs/ru/claude-code-on-the-web.md), которые доступны на планах Pro, Max, Ultra и Team, а также для пользователей Enterprise с [премиум-местами или местами Chat + Claude Code](https://support.claude.com/en/articles/11845131-use-claude-code-with-your-team-or-enterprise-plan).

Каждая [облачная сессия](https://code.claude.com/docs/ru/claude-code-on-the-web.md) выполняется в облачной среде. Вы можете настроить среду, чтобы разрешить или запретить [доступ в сеть](#access-levels), [установить переменные окружения](#set-environment-variables) для сессии, сохранять [сетевые секреты](#add-network-secrets), которые сессии используют, не видя их, и запускать [скрипт настройки](#setup-scripts) перед тем, как Claude начнёт работу.

Одни и те же среды применяются везде, где вы запускаете облачную сессию:

* [Приложение Desktop](https://code.claude.com/docs/ru/desktop.md)
* [Мобильное приложение Claude](https://code.claude.com/docs/ru/mobile.md)
* Ваш браузер на [claude.ai/code](https://claude.ai/code)
* Терминал с [`claude --cloud`](https://code.claude.com/docs/ru/claude-code-on-the-web#from-terminal-to-cloud)
* [Облачные запланированные задачи](https://code.claude.com/docs/ru/routines.md)
* [Claude Tag](https://claude.com/docs/claude-tag/overview)

Каждый из этих интерфейсов также может направлять сессии в [самостоятельно размещённую среду](https://code.claude.com/docs/ru/self-hosted-environments). В разделе [Доступность и ограничения](https://code.claude.com/docs/ru/self-hosted-environments#availability-and-limitations) описано, что Claude пока не может использовать, когда сессия Claude Tag выполняется в такой среде.

> [!NOTE]
>
> Сессии [Remote Control](https://code.claude.com/docs/ru/remote-control.md) подключают веб-интерфейс и мобильный интерфейс к сессии на вашей собственной машине, которая использует сеть и файлы вашей машины, а не облачную среду. Чтобы выбрать среду, которую использует канал Claude Tag, см. раздел [Настройка среды, используемой каналом Claude Tag](#set-the-environment-a-claude-tag-channel-uses).

## Среда Default

Если у вас ещё нет среды, подключение устанавливает среду **Default**. Как это происходит, зависит от того, где вы подключаетесь:

* **Потоки CLI, такие как `/web-setup`**: создают **Default** для вас
* **Веб-подключение на Pro, Max и Ultra**: вы получаете **Default** автоматически
* **Веб-подключение на Team и Enterprise**: показывает форму **Create your first cloud environment**, если владелец не включил [Quick setup](https://code.claude.com/docs/ru/claude-code-on-the-web.md#quick-setup-for-team-and-enterprise); сохраните значения по умолчанию в форме и нажмите **Create & finish**, чтобы получить ту же среду **Default**

**Default** не имеет собственной конфигурации:

* [**Limited** доступ в сеть](#access-levels): сессии имеют доступ к реестрам пакетов и другим [доменам из списка разрешённых](#default-allowed-domains).
* Никакой другой конфигурации: **Default** не определяет переменные окружения или скрипт установки, поэтому сеансы начинаются только с [предустановленных инструментов](#installed-tools).

Если доступна только **Default**, каждый сеанс работает в ней. Когда у вас есть более одной среды, сеансы выбирают одну для каждой поверхности:

* На приложении Desktop, мобильном приложении и на claude.ai/code сеансы, которые вы запускаете сами, используют среду, показанную в [селекторе](#configure-your-environment). [Организационное значение по умолчанию](#organization-shared-environments), установленное владельцем, заполняет выбор, когда вы не выбрали ничего. Потоки в [проекте](https://code.claude.com/docs/ru/claude-projects.md#project-settings-reference) используют среду, установленную в параметрах проекта.
* Из CLI Claude Code использует ваш выбор [`/remote-env`](#select-an-environment-from-the-cli), или возвращается к среде, размещённой Anthropic, когда ваш список имеет одну, и в противном случае к первой среде в вашем списке, которая не является мостовой средой, записью [Remote Control](https://code.claude.com/docs/ru/remote-control.md), которую регистрирует для представления вашей собственной машины, а не облачной среды. Для [самостоятельно размещённой среды](https://code.claude.com/docs/ru/self-hosted-environments) передача `--environment <environment-id>` с её `ccpool_` ID [когда вы отправляете сеанс](https://code.claude.com/docs/ru/self-hosted-environments-testing.md#run-the-test-loop) переопределяет выбор `/remote-env` и резервный вариант для этого вызова. Claude Code отклоняет размещённые Anthropic `env_` ID, переданные флагу, поэтому используйте `/remote-env` для их целевого назначения. Флаг требует Claude Code v2.1.224 или позже.

Настройте среду, когда значения по умолчанию недостаточно: когда Claude нужно достичь доменов вне [списка разрешений по умолчанию](#default-allowed-domains), нужны установленные переменные окружения для его сеансов или нужны установленные зависимости перед тем, как он начнёт работу.

## Настройка вашей среды

Добавляйте, редактируйте и архивируйте среды из селектора среды под полем сообщения на экране, где вы начинаете новую сессию на [claude.ai/code](https://claude.ai/code). Чтобы попасть на этот экран, пройдите [веб-подключение](https://code.claude.com/docs/ru/web-quickstart.md). Для приложения Desktop смотрите [Облачные сессии](https://code.claude.com/docs/ru/desktop.md#cloud-sessions). Среды, которые вы создаёте, являются личными для вашей учётной записи; [общие среды](#organization-shared-environments), созданные пользователем с ролью Owner, появляются в селекторе рядом с ними. Смотрите [Установленные инструменты](#installed-tools), чтобы узнать, что доступно без какой-либо настройки.

Селектор отображается только до тех пор, пока вы не отправите первое сообщение новой сессии. Чтобы отредактировать среду своей работающей облачной сессии, выберите значок-стрелку после названия сессии вверху, затем выберите **Edit cloud environment**.

**1. Откройте селектор среды**

На экране новой сессии выберите первый элемент управления в строке под полем сообщения.

**2. Добавьте или отредактируйте среду**

* **Добавление среды**: выберите **New environment** внизу меню, чтобы открыть диалог **New environment**. Заполните форму и выберите **Add environment**. После этого ваша новая сессия использует добавленную среду.
* **Редактирование среды**: найдите её строку под **Cloud**. Если **Cloud** — это одна строка, выберите её, чтобы открыть список. Если вашей среды нет под **Cloud**, выберите строку **More** под этим заголовком. Наведите указатель на строку среды и выберите значок настроек, который появляется справа, чтобы открыть её диалог.

Когда вы добавляете среду или редактируете одну из своих, выберите в диалоге строку [**Network access**](#network-access), [**Setup script**](#add-a-setup-script) или [**Environment variables**](#set-environment-variables), чтобы открыть соответствующую настройку. После последнего изменения сохраните с помощью **Add environment** для новой среды или **Save changes** для существующей. Чтобы сохранить ключ, который сессии используют, не видя его, смотрите [Добавление сетевых секретов](#add-network-secrets).

### Установка переменных окружения

Переменные окружения используют формат `.env`, одна пара `KEY=value` на строку. Простые значения не нуждаются в кавычках, и если вы заключите значение в кавычки с соответствующей парой, кавычки не станут частью значения. Заключите в кавычки значение, которое охватывает несколько строк или содержит `#`: в неэкранированном значении `#` начинает комментарий, и остаток строки отбрасывается.

Следующий пример определяет три переменные.

```text theme={null}
NODE_ENV=development
LOG_LEVEL=debug
DATABASE_URL=postgres://localhost:5432/myapp
```

Сеанс читает значения среды в обычные переменные окружения, которые может читать любая команда, которую запускает Claude, кроме переменных `OTEL_*`. Claude Code использует их для собственного [экспорта телеметрии](https://code.claude.com/docs/ru/monitoring-usage.md#telemetry-from-cloud-sessions-and-claude-tag) и не передаёт их командам, которые он запускает.

В среде, размещённой Anthropic, сеанс читает значения среды при создании и снова каждый раз, когда Claude Code запускается в виртуальной машине сеанса после этого, что происходит в двух случаях:

* **Виртуальная машина восстанавливается после простоя**: после нескольких минут без активности виртуальная машина сеанса приостанавливается с сохранёнными файлами. Ваше следующее сообщение восстанавливает ту же виртуальную машину и снова запускает Claude Code.
* **Виртуальная машина была отозвана и перестраивается**: если приостановленная виртуальная машина с тех пор была [отозвана](https://code.claude.com/docs/ru/claude-code-on-the-web.md#environment-expired), повторное открытие сеанса подготавливает свежую виртуальную машину.

После редактирования, добавления или удаления переменной существующий сеанс в среде, размещённой Anthropic, сохраняет значения, которые он последний раз прочитал, пока его виртуальная машина не будет восстановлена или перестроена, и использует ваше изменение с этого момента. Его виртуальная машина приостанавливается сама по себе, когда сеанс неактивен, и вы не можете приостановить её самостоятельно. Чтобы использовать новое значение сразу же, попросите Claude установить его в команде, которую он запускает, например `LOG_LEVEL=trace npm test`, или запустите новый сеанс.

Облачный сеанс также устанавливает некоторые переменные сам, когда запускается. Для [`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`](https://code.claude.com/docs/ru/claude-code-on-the-web#manage-context) значение, которое устанавливает сеанс, переопределяет то, которое вы добавляете здесь, поэтому добавление этого ключа здесь не имеет эффекта.

Любой, кто использует среду, может читать значения. В среде, размещённой Anthropic, вместо этого используйте [сетевой секрет](#add-network-secrets) для ключа, который прокси агента может прикрепить к запросу. [Запросы, которые никогда не получают секрет](#requests-that-never-get-the-credential), перечислены там.

### Добавление сетевых секретов

Сетевой секрет — это API-ключ или токен, который вы сохраняете в облачной среде, чтобы Claude мог вызывать этот API из любой сессии в среде, не видя ключа. Прокси агента Anthropic добавляет ключ к запросам для перечисленных вами хостов после того, как каждый запрос покидает виртуальную машину сессии, поэтому сам ключ остаётся за пределами виртуальной машины.

Сетевые секреты доступны на планах Pro, Max, Ultra, Team и Enterprise. Чтобы проверить, можете ли вы добавить секрет самостоятельно, смотрите [Требования](#requirements).

#### Требования

Эти требования определяют, можете ли вы добавить секрет и может ли прокси агента использовать его после добавления:

* **Роль**: на любом плане вы можете добавлять и удалять секреты в своих собственных средах независимо от вашей роли. На Team и Enterprise пользователи с ролью Owner имеют роль администратора организации в вашей организации claude.ai, а пользователи с ролью Admin — нет, что меняет то, что вы видите в следующих случаях:
  * **Ваша собственная среда**: без роли администратора организации кнопка **Add secret** открывает [сокращённую форму](#add-a-secret-without-the-role)
  * **Общая среда**: пользователи с ролью Owner [добавляют и удаляют её секреты](#add-a-credential) в настройках администратора. Без роли администратора организации попросите пользователя с ролью Owner добавить секрет, потому что в диалоге среды нет раздела **Network secrets**
* **Тип среды**: облачная среда, размещённая Anthropic. У [самостоятельно размещённой среды](https://code.claude.com/docs/ru/self-hosted-environments) нет сетевых секретов
* **Доступность API**: API принимает соединения из интернета, потому что запросы выходят из сети Anthropic
* **Ключи шифрования**: если ваша организация использует управляемые клиентом ключи шифрования, вы не можете сохранять сетевые секреты

#### Добавление секрета

Вы добавляете секреты по одному. Чтобы изменить хосты или значение секрета, удалите его и добавьте снова.

Чтобы добавить секрет в [общую среду](#organization-shared-environments), откройте её для редактирования на странице **Cloud environments** в [настройках администратора](https://claude.ai/admin-settings), выберите её строку **Network secrets**, затем продолжите с шага 2. Если вы используете план Team или Enterprise и не имеете [роли администратора организации](#requirements), выполните шаг 1 в своей собственной среде, затем [заполните сокращённую форму](#add-a-secret-without-the-role).

**1. Откройте сетевые секреты среды**

[Откройте среду для редактирования](#configure-your-environment) на [claude.ai/code](https://claude.ai/code). В диалоге **Edit cloud environment** выберите строку **Network secrets**. Вы увидите секреты, уже добавленные в среду, каждый с хостами, к которым он применяется.

**2. Добавьте секрет**

Выберите **Add secret** и заполните форму. Оставьте **Secret type** по умолчанию, **Bearer**, для API-ключа, который передаётся в заголовке запроса, и заполните эти поля:

* **Allowed websites**: хосты API, например `api.example.com`. Префикс `*.` соответствует любому поддомену
* **Custom headers**: одна строка для заголовка, который несёт ключ. В строке уже указаны `Authorization` в качестве **Header name** и `Bearer` в качестве **Prefix**; вставьте сам ключ в качестве **Value**. Для заголовка вроде `X-Api-Key`, который принимает значение без префикса, измените имя и очистите префикс

Для API, который использует другой способ аутентификации, выберите другой **Secret type**. Это тот же список, который [Claude Tag](https://claude.com/docs/claude-tag/overview), интеграция со Slack для планов Team и Enterprise, предлагает для [соединений](https://claude.com/docs/claude-tag/admins/add-connections).

**3. Сохраните секрет**

Выберите **Add**. Секрет появляется в списке со своими хостами и сохраняется без кнопки **Save changes** диалога. После сохранения просмотреть значение снова нельзя.

Чтобы убедиться, что секрет работает, запустите сессию в среде и попросите Claude вызвать API, например с помощью `curl`. API отвечает так, как если бы ключ был в запросе, а ключ не появляется ни в переменных окружения сессии, ни в каком-либо файле. Если вместо этого список помечает секрет как **Not sent**, примечание под ним объясняет причину и что делать. Два секрета, хосты которых пересекаются без точного совпадения, не получают отметки, и прокси агента отправляет только один из них.

#### Добавление секрета без роли администратора организации

Если вы используете план Team или Enterprise и не имеете [роли администратора организации](#requirements), форма **Add secret** принимает один секрет для одного хоста. Выберите [строку **Network secrets**](#add-a-credential) вашей среды, а затем **Add secret**. Заполните эти поля и нажмите кнопку **Add secret** в форме:

* **Host**: единственный хост, который получает секрет, например `api.example.com`. Форма не принимает подстановочный знак `*.`
* **Secret type**: **Token** для ключа, который передаётся в заголовке запроса, или **Username and password**. Для токена вставьте ключ в поле **Token**. Для заголовка, отличного от `Authorization`, например `X-Api-Key`, укажите его имя в поле **Header**

#### Какие запросы получают секрет

Прокси агента прикрепляет секрет к запросу, когда хост запроса совпадает с одним из хостов, которые вы указали для этого секрета. Сессии могут обращаться к этим хостам, даже если [уровень сетевого доступа](#access-levels) среды иначе бы их не разрешал, за исключением [хостов, которые никогда не получают секрет](#requests-that-never-get-the-credential). Секрет применяется в каждой сессии, работающей в среде, кто бы её ни запустил, пока вы его не удалите.

#### Запросы, которые никогда не получают секрет

Прокси агента никогда не прикрепляет добавленный вами секрет к следующим запросам:

* **GitHub**: запросы к GitHub вместо этого аутентифицирует [прокси GitHub](#github-proxy), поэтому сетевой секрет для него не нужен
* **API Anthropic и общедоступные реестры пакетов**: `api.anthropic.com`, `registry.npmjs.org`, `jsr.io`, `npm.jsr.io`, `pypi.org`, `files.pythonhosted.org`, `index.crates.io` и `proxy.golang.org`
* **Запросы скрипта установки**: Claude Code подключается к прокси агента, когда он запускается, после того как [скрипт установки](#setup-scripts) запустился
* **Экспорт телеметрии Claude Code**: Claude Code отправляет свой [экспорт телеметрии](https://code.claude.com/docs/ru/monitoring-usage.md#telemetry-from-cloud-sessions-and-claude-tag) сам, а не через команду, которую он запускает, и этот запрос не проходит через прокси агента

### Выбор среды из CLI

Запустите `/remote-env` в вашем терминале, чтобы выбрать среду по умолчанию для облачных сеансов, которые вы создаёте из CLI, такие как [`claude --cloud`](https://code.claude.com/docs/ru/claude-code-on-the-web#from-terminal-to-cloud). Команда открывает средство выбора ваших существующих сред и сохраняет ваш выбор в ключ `remote.defaultEnvironmentId` в ваших [пользовательских параметрах](https://code.claude.com/docs/ru/settings.md#where-settings-live), поэтому он применяется в каждом проекте на вашей машине, пока вы его не измените, если только тот же ключ не установлен на более высоком приоритете [слой параметров](https://code.claude.com/docs/ru/settings.md#settings-precedence), такой как параметры проекта репозитория.

ID [самостоятельно размещённой среды](https://code.claude.com/docs/ru/self-hosted-environments), который имеет форму `ccpool_...`, следует более строгому правилу источника. Смотрите [`remote.defaultEnvironmentId`](https://code.claude.com/docs/ru/settings-reference#remote-defaultenvironmentid) для слоёв параметров, которые Claude Code чтит это из.

`/remote-env` только устанавливает значение по умолчанию: он не запускает сеанс и не может добавлять или редактировать среды. Управляйте ими из [селектора среды](#configure-your-environment).

### Архивирование среды

Чтобы архивировать одну из ваших собственных сред, откройте её для редактирования, выберите **Archive environment** и подтвердите. Если среда [общая для вашей организации](#organization-shared-environments), её вместо этого архивирует пользователь с ролью Owner со страницы **Cloud environments** в [настройках администратора](https://claude.ai/admin-settings), поэтому обратитесь к Owner, если вы сами не являетесь им.

Архивирование влияет на новые сеансы, а не на работающие:

* Сеансы, которые уже работают в среде, продолжают работать.
* Среда исчезает из селектора и из `/remote-env`, поэтому вы не можете выбрать её для новых сеансов.
* Сетевые секреты среды остаются прикреплёнными в её работающих сессиях. Перед архивированием удалите те, которые вам больше не нужны.
* Ни одна новая сессия не может запуститься в архивированной среде ни в одном интерфейсе:
  * **Сохранённое значение по умолчанию CLI**: если среда была вашим сохранённым [значением по умолчанию CLI](#select-an-environment-from-the-cli), Claude Code запускает облачные сессии CLI в среде, размещённой Anthropic, если такая есть в вашем списке. В противном случае он запускает их в первой среде вашего списка, которая не является [мостовой средой Remote Control](#the-default-environment).
  * **Явная настройка**: всё, что явно настроено на эту среду, например [облачная запланированная задача](https://code.claude.com/docs/ru/routines.md#environments-and-network-access), не может запускать в ней новые сессии. Укажите для него другую среду.

Когда среда, размещённая Anthropic, вам больше не нужна, архивируйте её. Ни в диалоге среды, ни на странице администратора **Cloud environments** нет возможности удалить среду, размещённую Anthropic. Если среда [самостоятельно размещённая](https://code.claude.com/docs/ru/self-hosted-environments), пользователь с ролью Owner может удалить её со страницы **Cloud environments** в настройках администратора. Если у вас нет роли Owner, попросите такого пользователя удалить её.

### Общие среды организации

На планах Team и Enterprise владелец может создавать облачные среды, которые совместно используются со всеми членами организации. Та же роль управляет всем остальным на странице администратора **Cloud environments**, включая [самостоятельно размещённые среды](https://code.claude.com/docs/ru/self-hosted-environments); роль Admin не может открыть страницу. Полный список ролей, которые могут открыть её, — это список для [управления параметрами, управляемыми сервером](https://code.claude.com/docs/ru/server-managed-settings.md#access-control).

Общие среды появляются в [селекторе среды](#configure-your-environment) каждого члена под заголовком **Organization**, после личных сред члена под **Personal**, поэтому команда может стандартизировать одну конфигурацию вместо того, чтобы каждый член пересоздавал её. Выбор значка параметров общей среды там открывает сводку её конфигурации только для чтения для каждого члена, включая владельцев.

Владелец делает среду доступной для организации одним из двух способов:

* **Создание общей среды**: используйте страницу **Cloud environments** в [параметрах администратора](https://claude.ai/admin-settings), которая также является местом, где владельцы редактируют и архивируют общие среды. Каждая имеет имя, [уровень доступа в сеть](#access-levels), [переменные окружения](#set-environment-variables) в формате `.env` и [скрипт установки](#setup-scripts).
* **Совместное использование личной среды**: откройте одну из ваших собственных сред для редактирования в селекторе среды, затем поделитесь ею из строки **Who can use it**. Среда сохраняет свой ID, поэтому сессии и запланированные задачи, которые уже её используют, не затрагиваются, и каждый член может затем её видеть и запускать в ней сессии.

Владельцы выбирают [среду по умолчанию](#the-default-environment) организации отдельно на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code).

Чтобы дать сессиям общей среды ключ, который они не могут прочитать, добавьте [сетевой секрет](#add-network-secrets) при редактировании среды на странице **Cloud environments**. Не включайте секреты в её переменные, потому что их считывают сессии каждого участника.

### Установка среды, которую использует канал Claude Tag

В каналах [Claude Tag](https://claude.com/docs/claude-tag/overview) Claude работает как общая идентичность вашей организации, а не как какой-либо член, поэтому сеансы каналов используют только среды уровня организации, либо общие среды, либо [самостоятельно размещённые среды](https://code.claude.com/docs/ru/self-hosted-environments). Чтобы дать каналу цепочку инструментов, которая не является [предустановленной](#installed-tools), такая как .NET, владелец может создать [общую среду](#organization-shared-environments) со страницы администратора **Cloud environments** с [скриптом установки](#setup-scripts), который её устанавливает. Укажите канал на среду двумя способами:

* Установите общую или самостоятельно размещённую среду как [среду по умолчанию](#the-default-environment) организации на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code).
* [Закрепите одну на канале](https://claude.com/docs/claude-tag/admins/troubleshooting#channel-sessions-use-the-wrong-environment-or-can%E2%80%99t-find-one) в параметрах администратора Claude Tag.

## Сетевой доступ

Каждая среда устанавливает один уровень сетевого доступа, который контролирует исходящие соединения, которые могут устанавливать её сессии. Новая среда начинается с уровня **Limited** с установленным флажком **Allow package managers**, поэтому её сессии могут обращаться к реестрам пакетов и другим [доменам из списка разрешённых](#default-allowed-domains).

Чтобы изменить сетевой доступ среды, [откройте её для редактирования](#configure-your-environment) и используйте селектор **Network access** в диалоговом окне. [Общая среда](#organization-shared-environments) открывается там в режиме только для чтения, поэтому Owner изменяет её сетевой доступ со страницы **Cloud environments** в [настройках администратора](https://claude.ai/admin-settings). Элемент управления, который открывает селектор, появляется в интерфейсах приложения, перечисленных в разделе [Среда по умолчанию](#the-default-environment), и в [редакторе облачных запланированных задач](https://code.claude.com/docs/ru/routines.md#environments-and-network-access).

Когда вы изменяете сетевой доступ среды, размещённой в Anthropic, её существующие сеансы следуют новому параметру в течение примерно минуты для запросов, которые проходят через [список разрешённых сетей](#access-levels) сеанса. Вам не нужно начинать новый сеанс.

> [!NOTE]
>
> Коннекторы MCP, которые вы включаете в сессии или запланированной задаче, работают без добавления их хостов в **Allowed domains**, потому что трафик коннектора проходит через серверы Anthropic, а не через сеть сессии. Это зависит от того же канала, привязанного к Anthropic, отмеченного в разделе [Безопасность и изоляция](https://code.claude.com/docs/ru/claude-code-on-the-web.md#security-and-isolation). Отключите любой коннектор, который вам не нужен, чтобы ограничить, какие инструменты может использовать Claude.

### Уровни доступа

Поле **Network access** в [диалоговом окне среды](#configure-your-environment) принимает один из трёх уровней:

| Уровень | Исходящие соединения |
| :- | :- |
| **None** | Нет исходящего сетевого доступа через сеть сеанса |
| **Limited** | [Список разрешённых по умолчанию](#default-allowed-domains), включающий реестры пакетов, GitHub и облачные SDK, пока установлен флажок **Allow package managers**, а также любые [указанные вами домены](#allow-specific-domains). См. [как выглядит заблокированный запрос](https://code.claude.com/docs/ru/errors.md#host-not-allowed-in-a-cloud-session). |
| **Full** | Любой домен |

Независимо от выбранного уровня, сеансы всё ещё могут достичь следующего, потому что каждый из них использует путь, который не проходит через список разрешённых сетей сеанса:

* GitHub, через его [отдельный прокси](#github-proxy)
* [Соединители MCP](#network-access), которые вы включаете, трафик которых проходит через серверы Anthropic
* Хосты, которые вы указали в [сетевых секретах](#add-network-secrets) среды, кроме [хостов, которые никогда не получают секрет](#requests-that-never-get-the-credential)
* API Anthropic, для собственных запросов Claude Code, даже при **None**, как отмечено в разделе [Безопасность и изоляция](https://code.claude.com/docs/ru/claude-code-on-the-web.md#security-and-isolation)

Среда, сохранённая с уровнем **Trusted** или **Custom**, продолжает обращаться к тем же хостам и открывается следующим образом:

* **Сохранена как Trusted**: открывается как **Limited** с установленным флажком **Allow package managers**
* **Сохранена как Custom**: открывается как **Limited** со списком **Allowed domains** и флажком **Allow package managers** в том состоянии, в каком вы их задали, или как **Full**, если список содержал одиночный `*`

### Разрешить определённые домены

Чтобы разрешить домены, которых нет в [списке разрешённых по умолчанию](#default-allowed-domains), выберите **Limited** в селекторе **Network access** среды, затем перечислите по одному домену в строке в поле **Allowed domains**. Ведущий `*.` соответствует любому поддомену. Этот пример разрешает три хоста, которые может потребоваться внутреннему проекту.

```text theme={null}
api.example.com
*.internal.example.com
registry.example.com
```

Пока установлен флажок **Allow package managers**, сессии в этой среде могут обращаться как к [списку разрешённых по умолчанию](#default-allowed-domains), так и к указанным вами доменам. Снимите флажок, чтобы исключить список разрешённых по умолчанию. [Трафик GitHub](#github-proxy), [трафик коннекторов MCP](#network-access) и запросы к хостам [сетевых секретов](#add-network-secrets) среды, кроме [хостов, которые никогда не получают секрет](#requests-that-never-get-the-credential), не проходят через этот список разрешённых доменов.

Если ваша организация использует [артефакты](https://code.claude.com/docs/ru/artifacts.md#availability), вам не нужно добавлять `*.frame.claudeusercontent.com` в список, чтобы сеансы могли их читать. Когда список исключает этот хост, Claude Code читает содержимое артефакта через соединение сеанса с Anthropic. Сохраняйте хост в списке разрешённых в двух ситуациях:

* **Сеансы в этой среде открывают публичные артефакты другой организации**: Claude Code получает их с хоста напрямую, поэтому добавьте его в этот список.
* **Вы настраиваете локальный CLI или самостоятельно размещённый runner**: сохраняйте хост в этом списке разрешённых. См. [требования к сетевому доступу](https://code.claude.com/docs/ru/network-config.md#network-access-requirements) и требования к сетевому доступу самостоятельно размещённого [сетевые требования](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#network-requirements).

Каждая среда имеет свой собственный список разрешённых доменов; нет списка разрешённых на уровне организации, который администраторы могут применить к средам каждого участника. Никакая [настройка, управляемая сервером](https://code.claude.com/docs/ru/server-managed-settings.md), также не добавляет домены в сетевой список разрешённых доменов среды. Чтобы дать команде один стандартный список, Owner может создать [общую среду организации](#organization-shared-environments) с сетевым доступом **Limited** и этим списком.

### Прокси GitHub

В средах, размещённых в Anthropic, все операции GitHub проходят через выделенный прокси, который держит ваши реальные учётные данные GitHub вне виртуальной машины сеанса, независимо от [уровня доступа](#access-levels) среды. Сеансы в самостоятельно размещённой среде аутентифицируют операции git с учётными данными, которые предоставляет ваше развёртывание; [Настройка git](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#configure-git) охватывает варианты, включая выданные для каждого сеанса учётные данные и согласие на использование этого же прокси. Прокси предоставляет:

* **Учётные данные Git**: git-клиент внутри виртуальной машины использует ограниченные учётные данные, которые прокси проверяет и заменяет на ваш реальный токен GitHub.
* **Запросы API**: запросы от встроенных инструментов GitHub и от `gh` под [заполнителем `proxy-injected`](#work-with-github-issues-and-pull-requests) отправляются с подставленными вашими реальными учётными данными.
* **Ограничения push**: прокси отклоняет удаление веток и push чего-либо, кроме ветки, например тега. Он не ограничивает, какие ветки может обновлять push. Для этого используйте правила защиты веток или rulesets на GitHub.
* **Область действия репозиториев**: прокси обслуживает запросы GitHub API для репозиториев, прикреплённых к сессии. Запрос API к другому репозиторию получает 403 с сообщением, которое начинается с `GitHub access to` и содержит `is not enabled for this session`. Архив исходного кода, который вы загружаете по URL `github.com/{owner}/{repo}/archive/` или `codeload.github.com`, получает ту же ошибку 403, если репозиторий не прикреплён, даже если он публичный.
* **Ограничения GraphQL**: прокси отклоняет запросы к эндпоинту GraphQL GitHub с ошибкой 403, сообщение которой начинается с `GitHub GraphQL is not available from Claude Code sessions` и указывает резервный вариант REST, `gh api repos/{owner}/{repo}/...`. Подкоманды `gh`, использующие GraphQL, такие как `gh pr` и `gh issue`, получают ту же ошибку 403. Ограничение применяется к каждому запросу через прокси независимо от предоставленных вами учётных данных, поэтому установленный вами `GH_TOKEN` получает ту же ошибку 403. Claude не может обратиться через прокси к API GitHub, которые существуют только в GraphQL, например Projects v2.

Зафиксированные файлы из публичных репозиториев поступают через `raw.githubusercontent.com`, который вместо этого обрабатывает [прокси безопасности](#security-proxy). Этот домен находится в [списке разрешённых по умолчанию](#default-allowed-domains), поэтому эти файлы остаются доступными, пока [сетевой доступ](#access-levels) среды разрешает этот список.

### Прокси безопасности

Облачные сеансы в средах, размещённых в Anthropic, работают за HTTP/HTTPS сетевым прокси в целях безопасности и предотвращения злоупотреблений; в [самостоятельно размещённой среде](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#default-deny-egress) исходящий трафик проходит через вашу собственную границу сети. Весь исходящий интернет-трафик из сеанса, размещённого в Anthropic, проходит через этот прокси, который предоставляет:

* Защиту от вредоносных запросов
* Ограничение скорости и предотвращение злоупотреблений

## Что доступно в облачных сессиях

В среде, размещённой Anthropic, каждая сессия получает свежую виртуальную машину (VM) под управлением Ubuntu 24.04 на x86\_64, независимо от вашей собственной операционной системы и архитектуры CPU, с клонированным репозиторием и предустановленными распространёнными цепочками инструментов. Когда зависимость предоставляет предкомпилированные двоичные файлы, такие как Ruby gems с нативными расширениями или предварительно собранные колёса Python, используйте её сборку для x86\_64 Linux, чтобы она соответствовала VM. Этот раздел охватывает значения по умолчанию в среде, размещённой Anthropic, встроенные инструменты GitHub, то, как [запускать тесты и сервисы](#run-tests-start-services-and-add-packages), [ограничения ресурсов](#resource-limits), которые получает каждая VM, и [ограничения времени](#time-limits) для длительной работы.

> [!NOTE]
>
> Сессии, которые ваша организация направляет в [самостоятельно размещённую среду](https://code.claude.com/docs/ru/self-hosted-environments), вместо этого работают на ваших собственных runners, с инструментами, которые предоставляет образ вашего runner.

### Что переносится из вашей конфигурации

> [!NOTE]
>
> Из конфигурации репозитория, приведённой в этой таблице, облачный тред в [проекте](https://code.claude.com/docs/ru/claude-projects.md) загружает только `CLAUDE.md`, `.claude/CLAUDE.md` и файлы `.claude/rules/` в корне репозитория, которые не [привязаны к определённым путям](https://code.claude.com/docs/ru/memory.md#path-specific-rules). Смотрите раздел [Что треды получают из ваших репозиториев](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories).

Облачные сессии начинаются со свежего клона вашего репозитория. Всё, что вы закоммитили в репозиторий, доступно. Всё, что вы установили или настроили только на своей собственной машине, в сессии недоступно. Политика вашей организации поступает отдельно через [настройки, управляемые сервером](https://code.claude.com/docs/ru/server-managed-settings.md).

| | Доступно в облачных сессиях | Почему |
| :- | :- | :- |
| `CLAUDE.md` вашего репозитория | Да | Часть клона |
| Хуки и правила разрешений в `.claude/settings.json` вашего репозитория | Да, в сессии с одним репозиторием | Часть клона. Для сессии с несколькими репозиториями смотрите, [какие настройки она читает](https://code.claude.com/docs/ru/settings.md#settings-in-cloud-sessions) |
| MCP-серверы в `.mcp.json` вашего репозитория | Да, в сессии с одним репозиторием | Часть клона, находится из рабочего каталога сессии. Для самостоятельно размещённой среды смотрите, [настройки какого репозитория применяются](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#repository-settings-in-sessions-with-several-repositories) |
| `.claude/rules/` вашего репозитория | Да | Часть клона |
| `.claude/skills/`, `.claude/agents/`, `.claude/commands/` вашего репозитория | Да | Часть клона |
| Плагины и маркетплейсы, объявленные в `.claude/settings.json` вашего репозитория | Нет | Облачная сессия не устанавливает плагины, которые репозиторий включает в [`enabledPlugins`](https://code.claude.com/docs/ru/settings-reference#enabledplugins), включая плагины из маркетплейсов, которые он перечисляет в [`extraKnownMarketplaces`](https://code.claude.com/docs/ru/settings-reference#extraknownmarketplaces) |
| [Настройки, управляемые сервером](https://code.claude.com/docs/ru/server-managed-settings.md), вашей организации | Да, кроме сессий [Claude Tag](https://claude.com/docs/claude-tag/overview) | Загружаются с серверов Anthropic при запуске сессии. О том, как `availableModels` применяется в облачных сессиях, смотрите в разделе [Охват интерфейсов](https://code.claude.com/docs/ru/model-config.md#surface-coverage). Настройки, развёрнутые на вашем устройстве через MDM или файлы управляемых настроек, не применяются, потому что сессия работает на виртуальной машине, управляемой Anthropic; в [самостоятельно размещённой среде](https://code.claude.com/docs/ru/self-hosted-environments) сессии также читают файл управляемых настроек в образе runner, согласно разделу [как Claude Code объединяет управляемые источники](https://code.claude.com/docs/ru/managed-settings.md#how-claude-code-combines-managed-sources) |
| Ваш пользовательский `~/.claude/CLAUDE.md` | Нет | Находится на вашей машине, а не в репозитории. Смотрите [Добавление личных предпочтений без коммита в репозиторий](#add-personal-preferences-without-committing-to-the-repo) |
| Ваши пользовательские `~/.claude/skills/`, `~/.claude/agents/`, `~/.claude/commands/` | Нет | Находятся на вашей машине, а не в репозитории. Вместо этого закоммитьте их в каталог `.claude/` репозитория. Облачные сессии автоматически загружают [скиллы, которые вы включили на claude.ai](https://code.claude.com/docs/ru/skills.md#skills-in-cowork-and-cloud-sessions) |
| Плагины, включённые только в ваших пользовательских настройках | Нет | Пользовательский `enabledPlugins` находится в `~/.claude/settings.json` на вашей машине |
| MCP-серверы, которые вы добавили с помощью `claude mcp add` в области действия по умолчанию local или в области действия user | Нет | В этих областях действия команда записывает в `~/.claude.json` на вашей машине. Выполните `claude mcp add --scope project` из корня репозитория, чтобы записать [`.mcp.json`](https://code.claude.com/docs/ru/mcp#project-scope) репозитория, и закоммитьте этот файл. Сессия с одним репозиторием загружает его |
| Транспортные переменные в блоке `env` файла `.claude/settings.json` вашего репозитория, такие как `NODE_EXTRA_CA_CERTS` и [переменные клиентского сертификата mTLS](https://code.claude.com/docs/ru/network-config.md#mtls-authentication) | Нет | Среда хостинга управляет API-соединением сессии, поэтому Claude Code игнорирует эти ключи и отмечает каждый проигнорированный ключ в отладочном логе сессии |
| API-ключи и токены для сервисов, которые вызывает Claude | В среде, размещённой Anthropic, как [сетевые секреты](#add-network-secrets) | Вы добавляете ключ один раз в среду, и прокси агента прикрепляет его к запросам к перечисленным вами хостам. Ключ, который прокси агента [не может прикрепить](#requests-that-never-get-the-credential), остаётся в переменной окружения |
| Интерактивная аутентификация, такая как AWS SSO | Нет | Не поддерживается. SSO требует входа через браузер, который невозможен в облачной сессии |

Чтобы сделать вашу собственную конфигурацию доступной в облачных сессиях, закоммитьте её в репозиторий.

Любой, кто использует среду, может читать её переменные окружения и скрипт настройки. Об этом говорит примечание в диалоге под **Environment variables**, которое также предупреждает не размещать там секреты. В среде, размещённой Anthropic, вместо этого храните ключ, который прокси агента может прикрепить, как [сетевой секрет](#add-network-secrets).

#### Добавление личных предпочтений без коммита в репозиторий

В среде, размещённой Anthropic, добавьте [скрипт настройки](#setup-scripts), который записывает `~/.claude/CLAUDE.md`, для предпочтений, которые вы не хотите помещать в общий репозиторий. Claude Code загружает этот файл в сессии как [пользовательские инструкции](https://code.claude.com/docs/ru/memory.md#choose-where-to-put-claude-md-files). Этот пример задаёт предпочтение для сообщений коммитов:

```bash theme={null}
#!/bin/bash
mkdir -p ~/.claude
cat > ~/.claude/CLAUDE.md <<'EOF'
Use conventional commit messages.
EOF
```

Поместите скрипт в одну из своих собственных сред, а не в [общую](#organization-shared-environments).

Выполните `/context` в следующей облачной сессии и убедитесь, что `/root/.claude/CLAUDE.md` отображается в разделе **Memory files**.

### Работа с issues и pull requests GitHub

Облачные сессии включают встроенные инструменты GitHub, которые позволяют Claude читать issues, просматривать список pull requests, получать diff и публиковать комментарии без какой-либо настройки. Эти инструменты проходят аутентификацию через [прокси GitHub](#github-proxy), используя тот метод, который вы настроили в разделе [Варианты аутентификации GitHub](https://code.claude.com/docs/ru/claude-code-on-the-web.md#github-authentication-options), поэтому ваш токен никогда не попадает в контейнер.

Вы можете сами задать `GH_TOKEN` или `GITHUB_TOKEN` в [настройках среды](#set-environment-variables) или оставить обе переменные незаданными и позволить [прокси GitHub](#github-proxy) выполнять аутентификацию за вас:

* Если вы задали токен, он передаётся в контейнер без изменений, поэтому ваши скрипты и [`gh` CLI](https://cli.github.com) от GitHub используют его напрямую.
* Если вы не задали ни одну из переменных и аутентификацию для вашей сессии выполняет [прокси GitHub](#github-proxy), обе переменные в командах, которые выполняет Claude, содержат строку-заполнитель `proxy-injected`, а прокси подставляет ваши реальные учётные данные в исходящие запросы к GitHub. Вызовы `gh api` для подключённых репозиториев работают без вашего собственного токена, но скрипт, который читает `GITHUB_TOKEN` напрямую, получает заполнитель, а не пригодный для использования токен.

Заданный вами токен является обычной переменной окружения, поэтому любой, кто использует среду, может его прочитать; при использовании прокси учётные данные не попадают ни в конфигурацию среды, ни на виртуальную машину сессии.

Чтобы проверить, какой вариант применяется к вашей сессии, попросите Claude выполнить `echo $GH_TOKEN`.

[`gh` CLI](https://cli.github.com) от GitHub предустановлен. Если вам нужна операция GitHub, которую не охватывают встроенные инструменты, попросите Claude вызвать REST API с помощью `gh api`. Подкоманды `gh`, использующие REST API, такие как `gh workflow list`, тоже работают. Прокси [отклоняет подкоманды, использующие GraphQL](#github-proxy), такие как `gh pr` и `gh issue`. `gh` автоматически читает `GH_TOKEN`, поэтому вам не нужно выполнять `gh auth login`.

### Связь результатов с сессией

У каждой облачной сессии есть URL транскрипта на claude.ai, и сессия может прочитать свой собственный ID из переменной окружения `CLAUDE_CODE_REMOTE_SESSION_ID`. Используйте это, чтобы добавлять отслеживаемую ссылку в описания PR, сообщения коммитов, публикации в Slack или сгенерированные отчёты, чтобы рецензент мог открыть запуск, который их создал.

Коммиты, которые Claude создаёт в облачной сессии, содержат git-трейлер `Claude-Session: <url>`, а описания PR содержат URL сессии на отдельной строке. Чтобы не добавлять трейлер и ссылку в описании PR, установите [`attribution.sessionUrl`](https://code.claude.com/docs/ru/settings-reference#attribution-sessionurl) в значение `false`.

Чтобы добавить ссылку на сессию во что-то, кроме коммита или PR, например в сообщение Slack, которое публикует Claude, или в файл отчёта, который он записывает, попросите Claude выполнить следующую команду и использовать её вывод. Команда заменяет префикс `cse_` в значении переменной окружения на префикс `session_`, который ожидает URL транскрипта:

```bash theme={null}
echo "https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID/#cse_/session_}"
```

### Запуск тестов, запуск сервисов и добавление пакетов

Вы не получаете доступ к оболочке на виртуальной машине сессии. Claude выполняет каждую команду за вас, поэтому формулируйте задачи из этого раздела как просьбы в вашем промпте.

#### Запуск тестов

Claude запускает тесты в ходе работы над задачей. Попросите об этом в промпте, например «исправь падающие тесты в `tests/`» или «запускай pytest после каждого изменения». Средства запуска тестов, поставляемые с [предустановленными цепочками инструментов](#installed-tools), такие как pytest и cargo test, работают без дополнительной настройки. Средство запуска, которое ваш проект объявляет как зависимость, например jest, устанавливается вместе с вашими зависимостями.

#### Запуск сервисов

PostgreSQL и Redis предустановлены, но по умолчанию не запущены. Попросите Claude запустить нужный вам сервис; он выполняет следующие команды:

```bash theme={null}
service postgresql start
```

```bash theme={null}
service redis-server start
```

Docker доступен для запуска контейнеризованных сервисов. Попросите Claude выполнить `docker compose up`, чтобы запустить сервисы вашего проекта. Сетевой доступ для загрузки образов определяется [уровнем доступа](#access-levels) вашей среды, а [список разрешённых доменов по умолчанию](#default-allowed-domains) включает Docker Hub и другие распространённые реестры.

Если ваши образы большие или загружаются медленно, добавьте `docker compose pull` или `docker compose build` в ваш [скрипт настройки](#setup-scripts). [Кэш среды](#environment-caching) сохраняет загруженные образы, поэтому в каждой новой сессии они уже есть на диске. Кэш хранит только файлы, а не запущенные процессы, поэтому Claude по-прежнему запускает контейнеры в каждой сессии.

#### Добавление пакетов

Чтобы добавить пакеты, которые не предустановлены, используйте [скрипт настройки](#setup-scripts). [Кэш среды](#environment-caching) сохраняет то, что устанавливает скрипт, поэтому установленные там пакеты доступны в начале каждой сессии без повторной установки. Вы также можете попросить Claude установить пакеты посреди сессии, но такие установки не переносятся в другие сессии.

### Ограничения ресурсов

Облачные сессии в среде, размещённой Anthropic, работают с приблизительными лимитами ресурсов, которые могут меняться со временем:

* 4 vCPU
* 16 ГБ оперативной памяти
* 30 ГБ дискового пространства

Виртуальная машина может останавливать задачи, которым требуется значительно больше памяти, например крупные задания сборки или тесты, интенсивно использующие память. Для рабочих нагрузок, превышающих эти ограничения, используйте [Remote Control](https://code.claude.com/docs/ru/remote-control.md), чтобы запускать Claude Code на собственном оборудовании, или запускайте облачные сессии в [самостоятельно размещённой среде](https://code.claude.com/docs/ru/self-hosted-environments) на вычислительных ресурсах, которыми управляет ваша организация.

### Ограничения времени

В среде, размещённой Anthropic, следующие ограничения времени применяются к длительной работе в облачной сессии, такой как сборка, установка или прогон тестов. Каждый пункт ссылается на раздел, в котором определено ограничение.

* **Команды, которые выполняет Claude**: облачная среда не задаёт собственный таймаут команд, поэтому применяются значения по умолчанию инструмента Bash. По умолчанию Claude ждёт команду переднего плана 2 минуты и может запросить до 10 минут.

  Когда команда достигает своего [таймаута](https://code.claude.com/docs/ru/tools-reference.md#timeout-and-output-limits), Claude Code [переводит её в фоновый режим](https://code.claude.com/docs/ru/tools-reference.md#foreground-commands-that-move-to-the-background), а не останавливает, если только команда не начинается с `sleep`. Команда, переведённая таким образом, может продолжать работать ещё до 30 минут, после чего Claude Code останавливает её по достижении [ограничения времени для фоновых команд](https://code.claude.com/docs/ru/tools-reference.md#time-limit-for-background-commands). Установка `BASH_DEFAULT_TIMEOUT_MS` выше `1800000` миллисекунд увеличивает это ограничение, а также значение по умолчанию для команд переднего плана.
* **Хуки SessionStart**: Claude Code отменяет хук `command` через 600 секунд, если вы не задали [`timeout`](https://code.claude.com/docs/ru/hooks#common-fields) в секундах в записи хука. Claude Code не применяет таймаут к хуку, который вы запускаете с [`async: true`](https://code.claude.com/docs/ru/hooks#run-hooks-in-the-background).
* **Скрипт настройки**: скрипт, выполнение которого занимает больше примерно пяти минут, не кэшируется. О том, как уложиться в это время, рассказывается в разделе [Требования к скрипту](#script-requirements).
* **Неактивные сессии**: после нескольких минут без активности виртуальная машина сессии приостанавливается с сохранением файлов, а приостановленная виртуальная машина позже может быть освобождена. В разделе [Установка переменных окружения](#set-environment-variables) описано, что сессия подхватывает в каждом случае, а в разделе [Environment expired](https://code.claude.com/docs/ru/claude-code-on-the-web.md#environment-expired) — как заново открыть сессию, виртуальная машина которой была освобождена.

Чтобы увеличить таймауты команд для сессий среды, добавьте [`BASH_DEFAULT_TIMEOUT_MS` и `BASH_MAX_TIMEOUT_MS`](https://code.claude.com/docs/ru/env-vars#variables) в её [переменные окружения](#set-environment-variables). Обе переменные принимают значения в миллисекундах. Например, `BASH_DEFAULT_TIMEOUT_MS=600000` устанавливает 10 минут в качестве значения по умолчанию.

## Скрипты установки

Скрипт установки — это скрипт Bash, который запускается при запуске нового облачного сеанса, перед запуском Claude Code. Используйте скрипты установки для установки зависимостей, настройки инструментов или получения всего, что нужно сеансу и что не предустановлено.

Скрипты запускаются как root на Ubuntu 24.04, поэтому `apt install` и большинство менеджеров пакетов языков работают.

### Добавление скрипта установки

Чтобы добавить скрипт установки в собственную среду, вы можете ввести или вставить его либо загрузить текстовый файл, например `setup.sh`. [Добавьте или отредактируйте среду](#configure-your-environment) и выберите строку **Setup script**. Введите скрипт в открывшемся поле или выберите **Choose file**, чтобы заменить содержимое поля текстом файла размером до 64 КБ. Затем выберите **Add environment** или **Save changes**.

Этот пример устанавливает [ShellCheck](https://www.shellcheck.net/), который не предустановлен.

```bash theme={null}
#!/bin/bash
apt update && apt install -y shellcheck
```

### Требования к скрипту

При написании скрипта установки нужно учитывать четыре ограничения:

* **Выход с нулём**: если скрипт завершается с ненулевым кодом, сессия [не запускается](https://code.claude.com/docs/ru/web-quickstart.md#setup-script-failed) или запускается без того, что скрипту не удалось установить. Добавьте `|| true` к некритичным командам, чтобы случайный сбой установки не приводил к сбою скрипта.
* **Завершение в течение пяти минут**: держите общее время выполнения скрипта примерно под пять минут, чтобы [кэш среды](#environment-caching) мог построиться. Когда установка занимает больше времени, среда не кэшируется. Запускайте независимые установки параллельно с `&` и `wait`, и переместите любую одиночную загрузку, которая не подходит, в [SessionStart hook](#setup-scripts-vs-sessionstart-hooks), который запускает её в фоне. Если новые сеансы зависают или не удаются во время установки, смотрите [New sessions hang or time out during setup](https://code.claude.com/docs/ru/web-quickstart.md#new-sessions-hang-or-time-out-during-setup).
* **Сетевой доступ для установок**: установки пакетов должны достичь реестров. Уровень **Limited** по умолчанию с отмеченным параметром **Allow package managers** охватывает [общие реестры пакетов](#default-allowed-domains), включая npm, PyPI, RubyGems и crates.io. С сетевым доступом **None** установки не удаются.
* **Переменные среды ещё не заданы**: скрипт запускается до того, как сессия задаёт [переменные окружения](#set-environment-variables) среды. Задавайте все значения, которые нужны скрипту, в самом скрипте.

### Кэширование среды

Скрипт установки запускается в первый раз, когда вы запускаете сеанс в среде. Когда установка завершается в течение [примерно пяти минут](#script-requirements), Anthropic создаёт снимок файловой системы и повторно использует этот снимок как начальную точку для более поздних сеансов. Новые сеансы начинаются с ваших зависимостей, инструментов и образов Docker уже на диске и пропускают шаг скрипта установки. Это держит запуск быстрым, даже когда скрипт устанавливает большие цепочки инструментов или получает образы контейнеров. Если установка занимает больше времени, чем примерно пять минут, среда не кэшируется.

Кэш — это снимок файловой системы, поэтому он сохраняет то, что скрипт установки пишет на диск, и теряет всё, что было только работающим. Пакеты, которые вы устанавливаете, образы Docker, которые вы получаете, и файлы, которые вы пишете, все переносятся. База данных, которую запустил скрипт, стек `docker compose up` или любой другой фоновый процесс не переносятся; запускайте их для каждого сеанса, попросив Claude или с помощью [hook SessionStart](#setup-scripts-vs-sessionstart-hooks).

Скрипт установки запускается снова, чтобы перестроить кэш, когда вы изменяете скрипт установки среды или разрешённые сетевые хосты, и когда кэш достигает своего истечения примерно через семь дней. В среде, размещённой Anthropic, скрипт установки не запускается, когда виртуальная машина сеанса [восстанавливается после простоя](#set-environment-variables), поэтому изменение скрипта достигает существующего сеанса только когда его виртуальная машина была [отозвана](https://code.claude.com/docs/ru/claude-code-on-the-web.md#environment-expired) и перестроена. Чтобы применить изменение сразу же, запустите команды в сеансе или запустите новый сеанс.

Вам не нужно включать кэширование или управлять снимками самостоятельно.

### Скрипты установки против hooks SessionStart

Используйте скрипт установки для подготовки самой виртуальной машины: цепочки инструментов и инструменты CLI, которые не [предустановлены](#installed-tools). Используйте [hook SessionStart](https://code.claude.com/docs/ru/hooks.md#sessionstart) для установки проекта, которая должна работать везде, облачно и локально, например `npm install`.

Скрипты установки и hooks SessionStart запускаются в фиксированном порядке при запуске облачного сеанса. Таблица сравнивает, где вы их настраиваете, когда они запускаются и где они запускаются.

| | Скрипты установки | Hooks SessionStart |
| - | - | - |
| **Где вы их настраиваете** | Диалог среды на [claude.ai/code](https://claude.ai/code), плюс страница администратора **Cloud environments** для [общих сред](#organization-shared-environments) | [Файл параметров](https://code.claude.com/docs/ru/settings.md#where-settings-live), такой как `.claude/settings.json` вашего репозитория; смотрите [Что переносится из вашей установки](#what-carries-over-from-your-setup) для того, какие файлы достигают облачного сеанса |
| **Когда они запускаются** | Перед запуском Claude Code, пропущены, когда существует [кэшированная среда](#environment-caching) | После запуска Claude Code, на каждом сеансе, включая возобновлённый |
| **Где они запускаются** | Только облачные сеансы | Локальные и облачные сеансы |

Если у вас есть hooks SessionStart в вашем пользовательском `~/.claude/settings.json`, не ожидайте их в облаке: пользовательские параметры остаются на вашей машине. Какие другие hooks запускаются, зависит от того, где работает сеанс:

* **Среда, размещённая Anthropic**: Claude Code запускает хуки из [настроек, управляемых сервером](https://code.claude.com/docs/ru/server-managed-settings.md) вашей организации, а вне треда [проекта](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories) — также из репозитория. Сессии [Claude Tag](https://claude.com/docs/claude-tag/overview) не получают настройки, управляемые сервером, поэтому хуки из настроек, управляемых сервером, там не запускаются.
* **[Самостоятельно размещённая среда](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#permissions-and-tool-approval)**: Claude Code также запускает hooks, которые оператор посеял из `~/.claude/` хоста runner, и hooks в файле управляемых параметров образа runner, когда этот файл является одним из [управляемых источников, которые применяет Claude Code](https://code.claude.com/docs/ru/managed-settings.md#how-claude-code-combines-managed-sources).

### Установка зависимостей с помощью hook SessionStart

Чтобы устанавливать зависимости только в облачных сессиях вне тредов [проекта](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories), объедините хук SessionStart со скриптом, который проверяет, где он работает.

Сначала добавьте hook SessionStart в `.claude/settings.json` вашего репозитория. Эта конфигурация говорит Claude Code запустить `scripts/install_pkgs.sh` из вашего репозитория всякий раз, когда сеанс запускается или возобновляется:

```json theme={null}
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR\"/scripts/install_pkgs.sh"
          }
        ]
      }
    ]
  }
}
```

`matcher` ограничивает hook событиями `startup` и `resume`, и `$CLAUDE_PROJECT_DIR` разрешается в корень репозитория, поэтому hook находит скрипт независимо от рабочего каталога сеанса.

Далее создайте скрипт в `scripts/install_pkgs.sh`. Он немедленно завершается вне облака, затем устанавливает ваши зависимости. Он пропускает `npm install`, пока `package.json`, `package-lock.json` и сам скрипт не изменились с момента последней успешной установки:

```bash theme={null}
#!/bin/bash

if [ "$CLAUDE_CODE_REMOTE" != "true" ]; then
  exit 0
fi

cd "$CLAUDE_PROJECT_DIR" || exit 1
hashes=node_modules/.install_pkgs.sha256

if ! sha256sum --check --status "$hashes" 2>/dev/null; then
  # Delete the old hashes first, so a failed install runs again next time
  rm -f "$hashes"
  if npm install; then
    sha256sum scripts/install_pkgs.sh package.json package-lock.json > "$hashes" || rm -f "$hashes"
  fi
fi

# pip skips requirements that are already satisfied
pip install -r requirements.txt
exit 0
```

Проверка `CLAUDE_CODE_REMOTE` — это то, что ограничивает установку облачными сеансами: виртуальная машина сеанса несёт эту переменную как `true`, она никогда не `true` локально, поэтому на вашем ноутбуке скрипт выходит перед установкой чего-либо.

Чтобы убедиться, что `npm install` выполнился успешно, запустите облачную сессию и попросите Claude показать `node_modules/.install_pkgs.sha256`. Файл содержит хэш для каждого из трёх файлов. Если файл отсутствует, попросите Claude запустить `npm install` и сообщить об ошибке.

> [!NOTE]
>
> Если `npm install` читает другие файлы, например `package.json` рабочего пространства, `.npmrc` или входные данные вашего скрипта `postinstall`, добавьте их в команду `sha256sum`, которая сохраняет хэши. Иначе после изменения одного из этих файлов у вас останутся старые пакеты.

#### Ограничения в облачных сеансах

Hooks SessionStart ведут себя одинаково в облаке и локально, с этими оговорками:

* **Один репозиторий на сессию**: в среде, размещённой Anthropic, сессия с несколькими репозиториями не загружает хуки из `.claude/settings.json` ни одного репозитория, поэтому определённый там хук SessionStart не запускается. Вместо этого устанавливайте зависимости для таких сессий с помощью [скрипта установки](#setup-scripts). Для самостоятельно размещённой среды смотрите, [настройки какого репозитория применяются](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#repository-settings-in-sessions-with-several-repositories).
* **Не работают в облачных тредах проекта**: облачный тред в [проекте](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories) не запускает хуки из `.claude/settings.json` репозитория, независимо от количества репозиториев. В среде, размещённой Anthropic, устанавливайте зависимости для тредов с помощью [скрипта установки](#setup-scripts). В самостоятельно размещённой среде вместо этого используйте хук в [настройках хоста runner](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#repository-settings-in-sessions-with-several-repositories).
* **Нет облачного ограничения**: hooks запускаются в локальных и облачных сеансах. Чтобы пропустить локальное выполнение, выйдите рано, если переменная окружения `CLAUDE_CODE_REMOTE` не `true`, как показано в [скрипте установки зависимостей](#install-dependencies-with-a-sessionstart-hook).
* **Требует сетевого доступа**: команды установки должны достичь реестров пакетов. Если ваша среда использует сетевой доступ **None**, эти хуки завершаются сбоем. На уровне **Limited** по умолчанию с отмеченным параметром **Allow package managers** [список разрешённых доменов по умолчанию](#default-allowed-domains) охватывает npm, PyPI, RubyGems и crates.io.
* **Совместимость с прокси**: в среде, размещённой Anthropic, весь исходящий трафик проходит через [прокси безопасности](#security-proxy), и некоторые менеджеры пакетов не работают правильно с этим прокси; Bun — известный пример. В [самостоятельно размещённой среде](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#default-deny-egress) исходящий трафик проходит через вашу собственную границу сети вместо этого.
* **Добавляет задержку запуска**: хуки запускаются каждый раз, когда сессия запускается или возобновляется, в отличие от скриптов установки, которые выигрывают от [кэширования среды](#environment-caching). Держите скрипты установки быстрыми, пропуская уже выполненную работу, как это делает [скрипт установки зависимостей](#install-dependencies-with-a-sessionstart-hook).

Чтобы настроить базовый образ, используйте скрипт установки для установки того, что вам нужно, поверх [предоставленного образа](#installed-tools), или запустите свой собственный образ как контейнер рядом с Claude с помощью `docker compose`. Полная замена базового образа ещё не поддерживается.
