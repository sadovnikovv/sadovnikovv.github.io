Поиск ошибок с помощью ultrareview #

Запустите глубокий многоагентный анализ кода в облаке с помощью /code-review ultra, чтобы найти и проверить ошибки перед слиянием.

[!NOTE]

Ultrareview — это функция исследовательского предпросмотра. Функция, цены и доступность могут измениться на основе отзывов. Команда вызывается как /code-review ultra. Когда ultrareview доступен для вашей учетной записи, /ultrareview является псевдонимом.

Ultrareview — это глубокий анализ кода, который работает как облачный сеанс на инфраструктуре Anthropic. Когда вы запускаете /code-review ultra, Claude Code запускает флот агентов-рецензентов в облачной изолированной среде для поиска ошибок в вашей ветке или запросе на слияние.

По сравнению с локальным /code-review, ultrareview предлагает:

  • Более высокий сигнал: каждый найденный результат независимо воспроизводится и проверяется, поэтому результаты сосредоточены на реальных ошибках, а не на предложениях по стилю
  • Более широкое покрытие: более крупный флот агентов-рецензентов исследует изменение параллельно, что выявляет проблемы, которые может пропустить локальный анализ
  • Без использования локальных ресурсов: анализ работает полностью в облачной изолированной среде, поэтому ваш терминал остается свободным для другой работы во время его выполнения

Ultrareview требует аутентификации с помощью учетной записи claude.ai, так как работает как облачная сессия на инфраструктуре Anthropic. Если вы вошли только с помощью API-ключа, запустите /login и сначала аутентифицируйтесь с помощью claude.ai. Ultrareview недоступен при использовании Claude Code с Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry, а также недоступен для организаций, которые включили Zero Data Retention или к которым применена конфигурация HIPAA. В этих случаях /code-review ultra вместо этого запускает локальное код-ревью в вашей сессии. Организации, использующие ключи шифрования, управляемые клиентом (CMEK), не могут запускать ultrareview. Чтобы выполнить код-ревью ваших изменений локально, запустите /code-review.

Запуск ultrareview из CLI #

Запустите ревью из любого Git-репозитория:

```text theme={null} /code-review ultra


Без аргументов ultrareview проверяет diff между вашей текущей веткой и веткой по умолчанию, включая незакоммиченные и проиндексированные изменения.

При ревью ветки Claude Code упаковывает состояние репозитория и загружает его в облачную песочницу по правилам [загрузки локального репозитория в облачную сессию](https://code.claude.com/docs/ru/claude-code-on-the-web.md#send-local-repositories-without-github). Эти правила описывают ограничения по размеру, требования к рабочей копии и то, что происходит с незакоммиченными изменениями в файлах, имена которых похожи на учётные данные или ключи, например `.env` и `*.tfvars`. Когда вы [проверяете pull request](#review-a-pull-request), Claude Code ничего не загружает с вашего компьютера.

Перед запуском Claude Code показывает диалоговое окно подтверждения с областью ревью, количеством оставшихся бесплатных запусков и оценочной стоимостью; при ревью ветки в область входит количество файлов и строк. После подтверждения ревью продолжается в фоновом режиме, а вы можете продолжать работать в сессии.

Команда выполняется только тогда, когда вы вызываете её через `/code-review ultra`; Claude не запускает ultrareview самостоятельно.

### Ревью относительно другой базы

Чтобы сравнить с базой, отличной от ветки по умолчанию, передайте имя ветки. В этом примере текущая ветка проверяется относительно `develop`:

/code-review ultra develop


Базовой ветке не обязательно существовать в вашем локальном клоне: Claude Code получает её из `origin`. Если в имени есть опечатка, Claude Code предложит в сообщении об ошибке ближайшее подходящее имя ветки.

В качестве базы также можно указать идентификатор коммита или тег; тогда ревью охватит изменения в вашей ветке, сделанные после этого коммита.

### Ревью pull request

Чтобы проверить pull request на `github.com` вместо локальной ветки, передайте номер PR:

/code-review ultra 1234


Команда также принимает `#1234`, `PR 1234` и вставленные URL-адреса PR; вставленный URL должен указывать на репозиторий в вашем текущем каталоге.

Для режима PR нужен репозиторий на `github.com`. Для репозитория на экземпляре [GitHub Enterprise Server](https://code.claude.com/docs/ru/github-enterprise-server.md) запустите `/code-review ultra` без номера PR, чтобы проверить локальную ветку.

В режиме PR облачная песочница клонирует pull request с `github.com` вместо загрузки вашего рабочего дерева. Используется аккаунт GitHub, подключённый к вашему аккаунту Claude, поэтому у этого аккаунта должен быть доступ на чтение к репозиторию.

Выполните [`/web-setup`](https://code.claude.com/docs/ru/web-quickstart#connect-from-your-terminal), чтобы подключить вход в GitHub CLI к вашему аккаунту Claude.

### Публикация результатов в pull request

В Claude Code v2.1.227 и новее при ревью pull request на `github.com` можно поручить Claude опубликовать готовые результаты в PR одним обычным комментарием от вашего собственного аккаунта GitHub. Комментарий не является ревью или одобрением и заканчивается пометкой «Generated by Claude Code». При ревью ветки Claude Code показывает результаты только в вашей сессии.

Claude Code никогда не публикует результаты, если вы не выбрали это для конкретного запуска; по умолчанию действует `--no-post`. Публикация — это выбор, который вы делаете для каждого запуска:

* **Интерактивно**: в диалоговом окне запуска выберите **Run and post the findings to the PR as me**. Если добавить к команде `--post`, например `/code-review ultra 1234 --post`, Claude Code заранее выберет этот вариант, но всё равно спросит перед запуском.
* **Неинтерактивно**: запустите [подкоманду `claude ultrareview`](#run-ultrareview-non-interactively) с `--post`. Запуская подкоманду с этим флагом, вы даёте согласие на публикацию, поэтому Claude Code публикует без вопросов. При запуске `claude -p '/code-review ultra'` Claude Code завершает работу до поступления результатов, поэтому ничего не публикует; используйте вместо этого подкоманду.

Claude Code не публикует с вашего компьютера. Он отправляет идентификатор сессии ревью в Anthropic API, который публикует сохранённые результаты ревью в виде комментария через аккаунт GitHub, подключённый к Claude. Для публикации требуется тот же вход в claude.ai, что и для самого ревью; она недоступна у сторонних провайдеров и при установленной переменной [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](https://code.claude.com/docs/ru/env-vars).

В интерактивной сессии Claude Code начинает публикацию, когда поступают результаты, поэтому не закрывайте сессию до завершения ревью. Claude Code сохраняет выбор публикации только в этой сессии. Если сессия завершится до окончания ревью, Claude Code ничего не опубликует, даже если позже вы возобновите диалог.

По завершении публикации Claude сообщает результат:

* **Опубликовано**: Claude даёт ссылку на комментарий.
* **Уже опубликовано**: предыдущая публикация того же ревью уже добавила комментарий в PR, поэтому Claude даёт ссылку на pull request вместо повторной публикации.
* **Ошибка**: Claude сообщает причину, а результаты остаются в вашем терминале, чтобы вы могли опубликовать их вручную.

### Запрос обычными словами

Вы также можете описать, над чем работаете, обычными словами:

/code-review ultra check my auth changes


Ревью по-прежнему охватывает вашу текущую ветку — ту же область, что и при запуске без аргумента. Claude сохраняет ваш текст как заметку, показывает её в диалоговом окне запуска и соотносит с ней результаты, когда они поступают.

Claude Code считает текст заметкой, только если в нём больше одного слова и он не является именем ветки или ссылкой на PR. Одно слово он воспринимает как имя ветки или ссылку на PR, поэтому при опечатке в имени ветки вы получите ошибку с ближайшей веткой, описанную в разделе [Ревью относительно другой базы](#review-against-a-different-base), а не запуск с заметкой. Если текст сочетает ссылку на PR с другими словами, например `check PR 123 again`, Claude Code тоже не запускает ревью; он просит повторить запуск только с номером PR, чтобы проверить этот PR, или без ссылки, чтобы проверить текущую ветку.

> [!TIP]
>
> Если ваш репозиторий слишком велик для упаковки, Claude Code предложит использовать режим PR. Для репозитория на `github.com` отправьте ветку через push и откройте черновой PR, затем выполните `/code-review ultra <PR-number>`.

### Ограничения diff и резервные варианты

Ultrareview проверяет diff до начала ревью и сообщает, если не может проверить его в текущем виде:

* **Diff слишком велик**: по умолчанию ревью ветки может включать до 500 изменённых файлов и 8 000 изменённых строк. Точные значения могут меняться, а в [сообщении об отказе](https://code.claude.com/docs/ru/errors.md#diff-is-too-large-for-ultrareview) указываются действующие значения, размер вашего diff и файлы с наибольшим числом изменённых строк. Слишком большой pull request Claude Code отклоняет так же, указывая количество файлов и строк, но без разбивки по файлам
* **Нечего проверять**: если diff относительно базы пуст, ultrareview отказывается и называет ветку или коммит, с которыми выполнялось сравнение, а также вашу ситуацию — например, вы находитесь на самой базовой ветке без незакоммиченных изменений или все коммиты ветки уже входят в базу. Он также предлагает выход для этой ситуации: переключиться на ветку с вашей работой, проиндексировать или закоммитить локальные правки либо указать другую базу
* **Первый коммит**: у первого коммита репозитория нет ничего более раннего для сравнения, поэтому ultrareview проверяет все файлы в нём после вашего подтверждения в диалоговом окне запуска. Если у вас есть неотслеживаемые файлы, он вместо этого отказывается и предлагает выполнить `git add` для файлов, которые нужно проверить. Действуют те же ограничения по размеру.

  Первый коммит проверяется целиком только после такого подтверждения, поэтому подкоманда `claude ultrareview` и `claude -p` отклоняют его и предлагают использовать интерактивную сессию. Требуется Claude Code v2.1.277 или новее
* **Нет базы слияния**: если у вашей ветки нет общей истории с базовой веткой или в репозитории нет базовой ветки для сравнения, ultrareview вместо этого проверяет все отслеживаемые файлы репозитория. Этот резервный вариант требует полного клона и подчиняется тем же ограничениям по размеру. Он запускается только при подтверждении в диалоговом окне запуска или при самостоятельном запуске подкоманды `claude ultrareview`. В `claude -p` и везде, где ни то ни другое невозможно, ultrareview отказывается, сообщает, что ревью охватило бы все файлы, и предлагает использовать интерактивную сессию.

  В рабочей копии без веток и других ссылок, например в состоянии detached HEAD, созданном переключением на `FETCH_HEAD` после получения по URL, Claude Code [отклоняет ревью](https://code.claude.com/docs/ru/errors.md#your-checkout-has-no-branches) и предлагает сначала создать ветку

## Цены и бесплатные запуски

Ultrareview — это премиум-функция, которая выставляет счета за дополнительное использование, а не за включенное использование в вашем плане.

| План | Включено бесплатных запусков | После бесплатных запусков |
| - | - | - |
| Pro | 3 бесплатных запуска | выставляется счет как [дополнительное использование](https://support.claude.com/ru/articles/12429409-extra-usage-for-paid-claude-plans) |
| Max | 3 бесплатных запуска | выставляется счет как [дополнительное использование](https://support.claude.com/ru/articles/12429409-extra-usage-for-paid-claude-plans) |
| Ultra | 3 бесплатных запуска | оплачивается как [кредиты использования](https://support.claude.com/ru/articles/12429409-extra-usage-for-paid-claude-plans) |

* **Бесплатные запуски**: три запуска Pro, Max и Ultra — это одноразовое выделение на учетную запись и не обновляются.
* **Стоимость одного анализа**: после использования бесплатных запусков обычно от 5 до 25 долларов в дополнительном использовании в зависимости от размера изменения, что соответствует оценке, которую показывает диалоговое окно запуска перед каждым запуском.
* **Когда запуск считается начатым**: после запуска облачной сессии. Анализ, который вы остановили рано или который не завершился, все равно использует бесплатный запуск; платный анализ выставляет счет только за ту часть, которая была выполнена.

Поскольку ultrareview вне бесплатных запусков всегда оплачивается как кредиты использования, в вашей учетной записи или организации должны быть включены кредиты использования, прежде чем вы сможете запустить платный анализ. Если кредиты не включены, Claude Code блокирует запуск. Если вы можете управлять биллингом для своей учетной записи, Claude Code направит вас к настройкам биллинга, где вы можете включить кредиты использования.

Вы также можете запустить `/usage-credits` для проверки или изменения параметра дополнительного использования.

Claude Code просит вас подтвердить выставление счетов за дополнительное использование один раз за разговор: когда вы начинаете новый разговор, например с `/clear`, Claude Code показывает подтверждение снова для следующего платного анализа.

## Отслеживание выполняемого анализа

Анализ обычно занимает от 5 до 15 минут. Анализ работает как фоновая задача, поэтому вы можете продолжать работать в вашей сессии или запускать другие команды. Если вы выбрали [публикацию результатов в pull request](#post-findings-to-the-pull-request), держите сессию открытой до завершения анализа; если сессия завершится раньше, Claude Code ничего не публикует.

Используйте `/tasks` для просмотра выполняемых и завершенных анализов, открытия подробного представления анализа или остановки выполняемого анализа. Если вы остановите анализ, Claude Code архивирует облачную сессию и не возвращает частичные результаты.

Claude также может сообщить вам, что анализ был остановлен или что его сессия не была найдена:

* Если облачная сессия анализа остановлена или [архивирована](https://code.claude.com/docs/ru/claude-code-on-the-web.md#archive-sessions) на claude.ai до завершения анализа, Claude сообщит вам, что она была остановлена.
* Если облачная сессия анализа была удалена, или вы вошли в другой аккаунт Claude или организацию с момента её запуска, Claude сообщит вам, что сессия не была найдена.
* Если вы переключили аккаунты, анализ может всё ещё завершиться под аккаунтом, который его запустил. Если анализ всё ещё выполняется, войдите обратно под этот аккаунт и возобновите разговор с помощью `claude --resume`, чтобы переподключить его.

Когда анализ завершится, Claude Code показывает проверенные результаты как уведомление в вашей сессии. Каждый результат включает расположение файла и объяснение проблемы, чтобы вы могли попросить Claude исправить это напрямую.

## Запуск ultrareview неинтерактивно

Используйте подкоманду `claude ultrareview` для запуска ultrareview из CI или скрипта без интерактивной сессии. Подкоманда запускает тот же обзор, что и `/code-review ultra`, блокирует выполнение до завершения удалённого обзора и выводит результаты в stdout. Если запуск завершается с `Error: Workspace not trusted`, см. раздел [Доверие папке перед запуском обзора](#trust-the-folder-before-the-review-runs).

claude ultrareview claude ultrareview 1234 claude ultrareview origin/main


Без аргументов подкоманда проверяет разницу между вашей текущей веткой и веткой по умолчанию, с тем же [резервным вариантом для всего репозитория](#diff-limits-and-fallbacks), что и `/code-review ultra`, когда база слияния не существует. Передайте номер PR, чтобы [проверить pull request на `github.com`](#review-a-pull-request), или базовую ветку для проверки относительно неё; [обработка базовой ветки](#review-against-a-different-base) соответствует интерактивной команде.

Запуская подкоманду, вы даёте согласие на резервный вариант для всего репозитория и на запрос о биллинге и условиях, поэтому выполнение не останавливается для их подтверждения. Согласием считается именно самостоятельный запуск. Когда Claude запускает подкоманду для вас, например через инструмент Bash, Claude Code отказывает в проверке всего репозитория.

> [!NOTE]
>
> `claude -p '/code-review ultra'` не возвращает вам результаты, поэтому в скриптах используйте `claude ultrareview`. Запуск с `-p` запускает облачный обзор и завершается, не дожидаясь его окончания. Если обзор будет списывать кредиты использования, запуск с `-p` останавливается, не запуская его.

| Флаг | Описание |
| - | - |
| `--json` | Выведите необработанный payload `bugs.json` вместо отформатированных результатов |
| `--timeout <minutes>` | Максимальное количество минут для ожидания завершения обзора. По умолчанию 45 |
| `--post` | [Опубликуйте готовые результаты](#post-findings-to-the-pull-request) в pull request как один простой комментарий с вашего аккаунта GitHub. Работает на целевых pull request на `github.com`; на других целевых объектах Claude Code игнорирует флаг и сообщает об этом. Требует Claude Code v2.1.227 или позже |
| `--no-post` | Не публикуйте результаты. Это значение по умолчанию, и если вы передадите оба флага, Claude Code не будет публиковать. Требует Claude Code v2.1.227 или позже |
| `--trust-workspace` | [Доверять текущей папке](#trust-the-folder-before-the-review-runs) только для этого запуска, без вопроса, чтобы скрипт или задание CI могли проверить checkout, которому вы не доверяли. Не принимает значения: указывайте номер PR или базовую ветку перед ним. Требует Claude Code v2.1.309 или позже |

`claude ultrareview` записывает сообщения о ходе выполнения в stderr, чтобы stdout оставался пригодным для анализа.

Запуск `claude ultrareview` требует той же аутентификации и конфигурации кредитов использования, что и `/code-review ultra`.

Подкоманда завершается с одним из трёх кодов:

* **0**: обзор завершился, с результатами или без них
* **1**: обзор не запустился или был остановлен до завершения, в облачной сессии произошла ошибка или истёк таймаут. Код также равен 1, когда [папке нет доверия](#trust-the-folder-before-the-review-runs), в том числе когда вы отвечаете `n`, нажимаете Enter или нажимаете Ctrl-C на вопросе о доверии.
* **130**: вы нажали Ctrl-C, пока подкоманда запускала обзор, ожидала результатов или отправляла комментарий `--post`, а не на вопросе о доверии

Если подкоманда завершится до получения результатов, они так и не попадут в ваш терминал. Обзор при этом может всё ещё выполняться в облаке. Повторный запуск подкоманды начнёт новый обзор, а не продолжит прежний, и новый обзор [использует бесплатный запуск или оплачивается кредитами использования](#pricing-and-free-runs).

С флагом `--post` подкоманда начинает публикацию сразу после вывода результатов и выводит ссылку в stderr.

* Если выполнение не удаётся, остановлено или истекает таймаут, подкоманда ничего не публикует.
* Если обзор завершится, но комментарий не будет опубликован, Claude Code выведет причину в stderr, а результаты останутся в stdout, чтобы вы могли опубликовать их вручную.

Для автоматических обзоров на pull request GitHub [Code Review](https://code.claude.com/docs/ru/code-review.md) интегрируется с вашим репозиторием напрямую и публикует результаты как встроенные комментарии PR без этапа CLI.

### Доверие папке перед запуском обзора

Когда `claude ultrareview` спрашивает `Trust <folder>? [y/N]`, ответьте `y`, чтобы [доверять папке](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust). Доверяйте ей, только если доверяете её коду, поскольку после этого git и Claude Code могут запускать программы, указанные в её конфигурации git и настройках проекта.

Если подкоманда не может спросить вас, например в задании CI или при выводе в файл, она завершается с [`Error: Workspace not trusted`](https://code.claude.com/docs/ru/errors#workspace-not-trusted-when-running-claude-ultrareview). Добавьте `--trust-workspace`, чтобы доверять папке для этого запуска:

claude ultrareview 1234 --trust-workspace


Чтобы проверить pull request, которому нет доверия, выполните `claude ultrareview <PR number> --trust-workspace` из ветки, которой вы доверяете. PR [клонируется в облаке](#review-a-pull-request), поэтому его ветка не нужна вам локально.

## Сравнение ultrareview и /code-review

Оба вида ревью анализируют код, но вы используете их на разных этапах своего рабочего процесса.

| | `/code-review` | `/code-review ultra` |
| - | - | - |
| Объект | ваш рабочий diff, pull request, ветка или путь | ваш рабочий diff или pull request |
| Где выполняется | локально в вашей сессии | в облачной песочнице |
| Глубина | зависит от аргумента effort | множество агентов с независимой проверкой |
| Длительность | от нескольких секунд до нескольких минут | примерно от 5 до 15 минут |
| Стоимость | учитывается в обычном использовании | бесплатные запуски, затем примерно от \$5 до \$25 за ревью в виде кредитов использования |
| Лучше всего подходит для | быстрой обратной связи в ходе итераций | уверенности перед слиянием при существенных изменениях |

Используйте `/code-review` для быстрой обратной связи во время работы или передайте номер PR, чтобы провести ревью pull request коллеги перед его одобрением. Используйте `/code-review ultra` перед слиянием существенного изменения, когда вам нужен более глубокий проход, который выявляет проблемы, способные ускользнуть от локального ревью.
