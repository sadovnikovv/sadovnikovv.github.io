# Управление сеансами

> Назовите, возобновите, создавайте ветви и переключайтесь между диалогами Claude Code. Охватывает `--continue`, `--resume`, `--from-pr`, средство выбора `/resume`, именование сеансов, экспорт стенограмм и место хранения стенограмм.

[Сессия](https://code.claude.com/docs/ru/glossary.md#session) — это сохранённый диалог, привязанный к каталогу проекта. Claude Code сохраняет его локально по мере работы, поэтому вы можете возобновить работу с того же места, создать ветку для попытки другого подхода или переключаться между задачами.

[Настольное приложение](https://code.claude.com/docs/ru/desktop.md#work-in-parallel-with-sessions), [Claude Code в веб-версии](https://code.claude.com/docs/ru/claude-code-on-the-web.md) и [расширение VS Code](https://code.claude.com/docs/ru/vs-code.md#resume-past-conversations) каждое ведёт собственную историю сеансов, а настольное приложение также может [возобновить сеанс CLI](https://code.claude.com/docs/ru/desktop.md#coming-from-the-cli). На этой странице рассматривается CLI.

## Возобновление сессии

Сессии непрерывно сохраняются в [локальные файлы транскриптов](#export-and-locate-session-data) по мере работы, поэтому вы можете вернуться к одной из них после выхода или запуска `/clear`. Используйте эти точки входа:

| Команда | Что она делает |
| :- | :- |
| `claude --continue` | Повторно открывает самую последнюю сессию в текущем каталоге |
| `claude --resume` | Открывает [средство выбора сессий](#use-the-session-picker) |
| `claude --resume <name>` | Возобновляет именованную сессию напрямую |
| `claude --resume <session-id>` | Возобновляет [сессию с этим ID](#resume-by-session-id-or-name) |
| `claude --resume <transcript-path>` | Возобновляет сессию, сохранённую в файле [транскрипта](#where-transcripts-are-stored) `.jsonl` по этому абсолютному пути |
| `claude --from-pr <number>` | Открывает средство выбора сессий, отфильтрованное по сессиям, связанным с этим pull request |
| `/resume` | Переключается на другую сессию из активной сессии |

### Возобновление выполняющейся фоновой сессии

Когда диалог, который вы возобновляете с помощью `claude --resume` или `/resume`, принадлежит [фоновой сессии](https://code.claude.com/docs/ru/agent-view.md), которая всё ещё выполняется, Claude Code открывает саму выполняющуюся сессию. Если в командной строке указан `--bg`, возобновление вместо этого становится [фоновой отправкой](https://code.claude.com/docs/ru/agent-view.md#from-your-shell). До версии 2.1.285 Claude Code отказывал и предлагал открыть сессию с помощью `claude attach <id>` или сначала остановить её с помощью `claude stop <id>`.

* **Из вашей оболочки**: `claude --resume <session>` запускает [`claude attach`](https://code.claude.com/docs/ru/agent-view#attach-to-a-session) для этой сессии в том же терминале вместо самостоятельной загрузки транскрипта. Промпт, который вы передаёте в командной строке, как в `claude --resume <session> "check the tests too"`, сначала отправляется в сессию как её следующий ход, и Claude Code выводит `Sent your prompt to the background session (<id>); opening it…` перед подключением. `claude -p --resume <session> "prompt"`, введённый в терминале, делает то же самое, поэтому `-p` не делает этот запуск неинтерактивным.

  Claude Code не открывает сессию, если командная строка содержит что-либо из следующего:

  * Ввод или вывод через конвейер или перенаправление
  * Флаги, которые настраивают сессию, такие как `--permission-mode`, `--model` или `--settings`
  * Флаги, которые читают вывод, такие как `--output-format json` или `--json-schema`
  * Флаги, которые ограничивают или перематывают запуск, такие как `--max-turns` или `--max-budget-usd`

  В любом из этих случаев, или когда [представление агентов отключено](https://code.claude.com/docs/ru/agent-view.md#turn-off-agent-view), Claude Code ничего не отправляет и завершается со статусом 1, выводя сообщение о том, что сессия выполняется в фоне, вместе с командой `claude attach <id>`, которая её открывает, или предлагая найти её в `claude agents`, если не удаётся определить ID. Добавьте `--fork-session`, чтобы вместо этого возобновить копию диалога. Чтобы продолжить сам диалог в собственной сессии с применением ваших флагов, запустите `claude stop <id>`, а затем повторите команду.

  Промпт, начинающийся с `/` или `!`, не отправляется, как и любой промпт, пока сессия ожидает вашего ответа на вопрос. В обоих случаях Claude Code не открывает сессию, а сообщение содержит `Your prompt was not sent to it` с указанием причины.
* **Изнутри сессии**: `/resume` перемещает ваш текущий диалог в фон и подключает этот терминал к выполняющейся сессии, выводя `Opening "<title>", running in the background (<id>)`. Нажмите `←` в пустом промпте, чтобы вернуться к представлению агентов, где также отображается покинутый вами диалог. Когда текущий диалог нельзя переместить в фон, например потому что вы уже подключены к фоновой сессии или сохранение сессий отключено, `/resume` выводит команду `claude attach`, которую нужно запустить вместо этого.

### Что восстанавливает возобновлённая сессия

Когда Claude Code загружает диалог из его транскрипта, возобновлённая сессия восстанавливает диалог вместе с сохранённым в нём состоянием:

* История диалога: сообщения, вызовы инструментов и результаты. Если к сессии применялось [сжатие контекста](https://code.claude.com/docs/ru/context-window.md#what-survives-compaction), диалог открывается на строке `Conversation compacted`. Claude продолжает работу со сводкой последнего сжатия, сообщениями, которые это сжатие оставило без сводки, и всеми последующими сообщениями. Сообщения, включённые в сводку последнего сжатия, повторно не загружаются.
* Прерванные вызовы инструментов: инструмент, который всё ещё выполнялся, когда предыдущий процесс завершился, например при сбое, не запускается повторно при возобновлении.
* Модель: при использовании `claude --resume` или `--continue` сессия продолжается на модели, которую она использовала, за исключением случаев, описанных в разделе [Какую модель использует возобновлённая сессия](https://code.claude.com/docs/ru/model-config.md#which-model-a-resumed-session-uses).
* Агент: сессия, запущенная с помощью [`--agent`](https://code.claude.com/docs/ru/sub-agents#invoke-subagents-explicitly) или настройки `agent`, продолжается как этот агент, сохраняя его ограничения инструментов и модель. Передайте `--agent` при возобновлении, чтобы выбрать другого агента; о системном промпте в обоих случаях см. [Флаги системного промпта в возобновлённых диалогах](https://code.claude.com/docs/ru/cli-reference.md#system-prompt-flags-in-resumed-conversations). Claude Code ищет агента в двух местах: в исходном каталоге сессии, при условии что вы [доверяете этому рабочему пространству](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust), а затем в каталоге, из которого вы возобновляете сессию, поэтому агент уровня проекта загружается и при возобновлении из другого каталога. Если Claude Code не находит агента ни в одном из этих мест, сессия возобновляется с инструментами по умолчанию и показывает [предупреждение с именем агента](https://code.claude.com/docs/ru/errors.md#session-agent-no-longer-available).
* Режим разрешений: если вы возобновляете сессию из терминала с помощью `claude --continue`, `claude --resume <session-id>` или `claude --resume <name>`, когда имя соответствует одной сессии, без `-p`, Claude Code восстанавливает режим разрешений, в котором находилась сессия, за исключением случаев, описанных в разделе [режим разрешений при возобновлении](#permission-mode-on-resume), который также охватывает средство выбора сессий, `/resume` и возобновление с помощью `claude -p`. Передайте `--permission-mode` или `--dangerously-skip-permissions`, чтобы переопределить восстановленный режим.
* Активная цель: [цель](https://code.claude.com/docs/ru/goal.md#resume-with-an-active-goal), которая всё ещё была активна при завершении сессии, переносится; её счётчик ходов, таймер и базовый уровень расхода токенов сбрасываются.
* Запланированные задачи уровня сессии: [задачи, срок которых не истёк](https://code.claude.com/docs/ru/scheduled-tasks.md#limitations), восстанавливаются. Фоновые задачи Bash и задачи мониторинга не восстанавливаются.
* Фоновая работа: [фоновый субагент](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background), фоновая команда Bash или [workflow](https://code.claude.com/docs/ru/workflows.md), завершившиеся вместе с предыдущим процессом, отображаются в возобновлённом транскрипте как примечание о том, что они не завершились. Claude Code не начинает ход по этим примечаниям; Claude читает их вместе с вашим следующим промптом.

#### Флаги, которые нужно передать снова при возобновлении

> [!NOTE]
>
> Не повторяйте флаги запуска, когда вы повторно открываете [фоновую сессию](https://code.claude.com/docs/ru/agent-view.md#what-persists-across-restarts), пока она выполняется, или когда вы возобновляете её по полному ID сессии с `--bg` после её остановки. В обоих случаях сессия сохраняет свои флаги.

Для любого другого `claude --continue` или `claude --resume` снова передайте [флаги](https://code.claude.com/docs/ru/cli-reference.md#cli-flags), например перечисленные ниже, поскольку Claude Code их не восстанавливает:

* **MCP-серверы**: `--mcp-config`
* **Плагины**: `--plugin-dir`
* **Каталоги**: `--add-dir`, как в `claude --continue --add-dir ../shared`. Используйте `--add-dir` и для каталогов, которые вы добавили с помощью `/add-dir`.
* **Дополнительные настройки**: `--settings`
* **Резервные модели**: `--fallback-model`

О `--system-prompt` и `--append-system-prompt` см. [Флаги системного промпта в возобновлённых диалогах](https://code.claude.com/docs/ru/cli-reference.md#system-prompt-flags-in-resumed-conversations).

#### Режим разрешений при возобновлении

Режим разрешений, в котором Claude Code запускает возобновлённую сессию, зависит от способа возобновления. Описанные ниже случаи применяются, когда Claude Code загружает диалог из его транскрипта; когда вы вместо этого [открываете фоновую сессию, которая всё ещё выполняется](#resume-a-running-background-session), эта сессия сохраняет свой текущий режим разрешений.

* Терминал: `claude --continue`, `claude --resume <session-id>` или `claude --resume <name>`, когда имя соответствует одной сессии, без `-p`. Claude Code восстанавливает режим разрешений, в котором находилась сессия, за исключением случаев, указанных в таблице. Передайте `--permission-mode` или `--dangerously-skip-permissions`, чтобы переопределить восстановленный режим.
* Неинтерактивный: `claude -p --resume` или `claude -p --continue`. Claude Code запускает выполнение в том режиме разрешений, в котором запустился бы новый запуск `claude -p`, за исключением того, что сессия, завершившаяся в режиме планирования, возобновляется в режиме планирования при [условиях ниже](#resume-in-plan-mode-with-p).
* VS Code: панель диалога расширения. Таблица охватывает только диалог, завершившийся в режиме планирования; об остальных случаях см. [возобновление прошлых диалогов](https://code.claude.com/docs/ru/vs-code.md#resume-past-conversations).
* Средство выбора сессий при запуске: сессия, которую вы выбираете в [средстве выбора сессий](#use-the-session-picker), независимо от того, открыли ли вы его с помощью одного `claude --resume`, `claude --from-pr` или имени, соответствующего нескольким сессиям. Claude Code запускает сессию в том режиме разрешений, в котором запустил бы новую сессию из той же командной строки, за исключением того, что сессия, завершившаяся в режиме планирования, возобновляется в режиме планирования. Если вы передаёте `--permission-mode`, `--dangerously-skip-permissions` или `--fork-session`, Claude Code не восстанавливает режим планирования. Никакой другой сохранённый режим разрешений не восстанавливается.
* `/resume` внутри сессии, с аргументом или без: диалог, на который вы переключаетесь, продолжается в режиме разрешений вашей текущей сессии, за исключением того, что диалог, завершившийся в режиме планирования, возобновляется в режиме планирования, даже если вы запустили Claude Code с `--permission-mode` или `--dangerously-skip-permissions`. Если этот диалог уже открывался ранее в текущем запуске Claude Code, например диалог, с которого вы начали, или диалог, который вы покинули с помощью `/clear` или `/resume`, он вместо этого продолжается в вашем текущем режиме разрешений.

Если [правило запрета](https://code.claude.com/docs/ru/permissions.md#manage-permissions) удаляет инструмент [`ExitPlanMode`](https://code.claude.com/docs/ru/tools-reference) или включён параметр [`permissions.denyInsteadOfPrompting`](https://code.claude.com/docs/ru/settings-reference#permissions-denyinsteadofprompting), Claude не может представить план на утверждение, поэтому Claude Code не восстанавливает режим планирования. Сессия запускается в том режиме разрешений, в котором запустилась бы новая сессия из той же командной строки. При использовании `/resume` диалог продолжается в вашем текущем режиме разрешений.

Для восстановления режима планирования в неинтерактивном пути и в VS Code требуется Claude Code v2.1.246 или более поздней версии. В каждой строке указаны режим разрешений, в котором завершилась сессия, путь возобновления (терминал, неинтерактивный или VS Code) и режим разрешений, в котором Claude Code запускает возобновлённую сессию.

| Сессия завершилась в | Как вы возобновляете | Режим разрешений после возобновления |
| :- | :- | :- |
| `bypassPermissions` | Терминал | Режим разрешений, в котором запустилась бы новая сессия. Чтобы снова [обходить разрешения](https://code.claude.com/docs/ru/permission-modes.md#skip-all-checks-with-bypasspermissions-mode), включите этот режим при запуске с помощью одного из его флагов запуска или `permissions.defaultMode: "bypassPermissions"` в [пользовательских настройках, `--settings` или управляемых настройках](https://code.claude.com/docs/ru/settings-reference#permissions-defaultmode) |
| `plan` | Терминал | Режим планирования. С `--fork-session` — режим разрешений, в котором запустилась бы новая сессия |
| `plan` | Терминал, когда правило запрета удаляет `ExitPlanMode` или включён `permissions.denyInsteadOfPrompting` | Режим разрешений, в котором запустилась бы новая сессия |
| `auto` | Терминал | `auto`, только если ваша учётная запись всё ещё соответствует [требованиям авторежима](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) |
| Manual | Терминал | Manual, если новая сессия запустилась бы в авторежиме согласно [встроенному значению по умолчанию](https://code.claude.com/docs/ru/permission-modes.md#which-mode-a-session-starts-in). Когда [вступает в силу](https://code.claude.com/docs/ru/permission-modes.md#which-mode-a-session-starts-in) `defaultMode` из файла настроек, Claude Code вместо этого запускает возобновлённую сессию в этом режиме |
| `plan` | Неинтерактивный, при [условиях ниже](#resume-in-plan-mode-with-p) | Режим планирования |
| Любой режим | Неинтерактивный, в любом другом случае | Режим разрешений, в котором запустился бы новый запуск `claude -p` |
| `plan` | VS Code | Режим планирования, с [исключениями, описанными на странице VS Code](https://code.claude.com/docs/ru/vs-code.md#resume-past-conversations) |

##### Возобновление в режиме планирования с `-p`

Запуск `claude -p --resume` или `claude -p --continue` возобновляется в режиме планирования, только если выполняются все следующие условия:

* Вы передаёте [`--permission-prompt-tool`](https://code.claude.com/docs/ru/cli-reference#cli-flags) и не передаёте [`--permission-prompts none`](https://code.claude.com/docs/ru/headless#turn-off-permission-prompts-in-unattended-runs), чтобы Claude Code мог представить план на утверждение
* Параметр [`permissions.denyInsteadOfPrompting`](https://code.claude.com/docs/ru/settings-reference#permissions-denyinsteadofprompting) не включён
* Вы не передаёте `--permission-mode` или `--dangerously-skip-permissions`
* Вы не передаёте `--fork-session`
* Запуск выполняется не через [каналы](https://code.claude.com/docs/ru/channels.md)
* Ни одно [правило запрета](https://code.claude.com/docs/ru/permissions.md#manage-permissions) не удаляет инструмент `ExitPlanMode`

### Диалоговое окно «Resume this conversation?»

Если при возобновлении сессии вы видите диалоговое окно «Resume this conversation?», его оценка показывает долю вашего 5-часового лимита использования, которую израсходует один только сохранённый диалог. Оценка не учитывает то, что вы уже использовали.

На планах Pro, Max и Ultra это диалоговое окно может появиться, когда вы возобновляете длинный диалог [после длительного перерыва](https://code.claude.com/docs/ru/prompt-caching.md#resuming-a-session) или на другой модели. Расчётный расход происходит, когда вы отправляете первое сообщение после **Resume**, а не в момент выбора этого варианта. Выбирайте в зависимости от того, нужен ли вашей следующей задаче сохранённый диалог:

* **Resume**: продолжить работу в сохранённом диалоге.
* **Start a new conversation**: переключиться на работу, которой не нужен сохранённый диалог. Чтобы позже снова открыть его, выполните [`/resume`](#use-the-session-picker) в промпте. Оценка не применяется к вашему первому сообщению в новом диалоге. Если в этом варианте указано, что Claude может найти этот диалог, вы всё равно можете ссылаться на предыдущую работу в новом диалоге.

### Где средство выбора сессий ищет сессии

Claude Code хранит сессии для каждого каталога проекта. По умолчанию средство выбора сессий показывает:

* Сессии из текущего worktree, включая [фоновые сессии](https://code.claude.com/docs/ru/agent-view.md), которые отмечены в списке как `bg`
* Сессии, запущенные в других местах, которые добавили текущий каталог с помощью `/add-dir`

Используйте `Ctrl+W`, чтобы расширить список на все worktrees репозитория, или `Ctrl+A`, чтобы расширить его на все проекты на этой машине.

#### `/loop`, `-p`, Agent SDK и фоновые сессии

Сессии, первым промптом которых была команда [`/loop`](https://code.claude.com/docs/ru/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop), не отображаются в средстве выбора, и `claude --continue` также их пропускает. Запуск `/loop` позже в диалоге не скрывает сессию.

Claude Code исключает сессии, созданные с помощью [`claude -p`](https://code.claude.com/docs/ru/headless) или [Agent SDK](https://code.claude.com/docs/ru/agent-sdk/overview.md), из средства выбора сессий и из `claude --continue`. Вы всё равно можете возобновить такую сессию, передав её ID в `claude --resume <session-id>`. Когда вы запускаете [`claude -p --continue`](https://code.claude.com/docs/ru/headless#continue-conversations), Claude Code учитывает сессии `-p`, SDK и `/loop`.

`claude --continue` открывает [фоновую сессию](https://code.claude.com/docs/ru/agent-view.md), которая завершилась, но не ту, которая всё ещё выполняется; для открытия завершённых фоновых сессий требуется Claude Code v2.1.257 или более поздней версии. Если ваш самый последний диалог — это тот, который вы [переместили в фон](https://code.claude.com/docs/ru/agent-view.md#send-the-session-to-the-background), и он всё ещё там выполняется, Claude Code завершается с сообщением `Your most recent conversation is running in the background` и ID этой сессии. Подключитесь к сессии из [`claude agents`](https://code.claude.com/docs/ru/agent-view#attach-to-a-session) или запустите `claude --resume`, чтобы выбрать другую.

#### Сессии в других worktrees и проектах

Когда вы выбираете сессию из другого worktree того же репозитория, Claude Code возобновляет её на месте; если собственный worktree сессии больше не существует, Claude Code [возобновляет её в вашем текущем каталоге](https://code.claude.com/docs/ru/worktrees.md#resume-a-worktree-session). Когда вы выбираете сессию из несвязанного проекта, Claude Code вместо этого копирует в буфер обмена команду `cd` и команду возобновления. Если каталог этого проекта больше не существует, Claude Code возобновляет сессию в вашем текущем каталоге, а не копирует команду `cd`, которая завершилась бы ошибкой.

Перемещение сессии с помощью [`/cd`](https://code.claude.com/docs/ru/commands) переносит её в хранилище проекта нового каталога, поэтому впоследствии она появляется в средстве выбора этого каталога.

#### Возобновление по ID сессии или имени

Вы можете запустить `claude --resume <session-id>` из любого каталога, поэтому можно возобновить сессию, которая началась в другом месте или была перемещена с помощью [`/cd`](https://code.claude.com/docs/ru/commands). Claude Code ищет ID в следующем порядке:

1. Каталог текущего проекта и его git worktrees
2. Все остальные проекты на этой машине

Поиск по проектам находит ID только тогда, когда ровно один другой проект содержит транскрипт с сообщениями для него, поэтому вручную скопированный дубликат приводит к тому, что Claude Code сообщает об отсутствии сессии, а не возобновляет произвольную копию. Если ни одна сохранённая сессия не соответствует ID, Claude Code сообщает `No conversation found with session ID: <session-id>`.

Возобновление по имени выполняет поиск в текущем репозитории и его worktrees. Обе формы ищут точное совпадение и возобновляют сессию напрямую, даже если она находится в другом worktree:

| Команда | Точное совпадение | Неоднозначное имя |
| :- | :- | :- |
| `claude --resume <name>` | Возобновляет напрямую | Открывает средство выбора сессий с именем, предварительно заполненным в качестве поискового запроса |
| `/resume <name>` | Возобновляет напрямую | Сообщает об ошибке; запустите `/resume` без аргумента, чтобы открыть средство выбора сессий |

## Назовите ваши сессии

Дайте сессиям описательные имена, чтобы их было легко найти в средстве выбора сессий и возобновить по имени. Это особенно важно, когда вы работаете над несколькими задачами параллельно.

| Когда | Как установить имя |
| :- | :- |
| При запуске | `claude -n auth-refactor` |
| Во время сессии | `/rename auth-refactor`. Имя также отображается на панели подсказок |
| Из средства выбора сессий | Выделите сессию и нажмите `Ctrl+R` |
| При принятии плана | Принятие плана в [режиме плана](https://code.claude.com/docs/ru/permission-modes.md#analyze-before-you-edit-with-plan-mode) дает сессии сгенерированное название на основе плана, если вы еще не назвали её |
| Из claude.ai или приложения Claude | Переименуйте [сессию удаленного управления](https://code.claude.com/docs/ru/remote-control.md#connect-from-another-device); Claude Code применяет то же имя в CLI. Требуется Claude Code v2.1.221 или позже |
| Из приложения для рабочего стола | Переименуйте сессию в [приложении для рабочего стола](https://code.claude.com/docs/ru/desktop.md#organize-and-find-sessions) |

После того как вы назовете сессию через маршрут CLI или из claude.ai, вернитесь к ней с помощью `claude --resume <name>` или `/resume <name>`; сессия приложения для рабочего стола возобновляется в [приложении для рабочего стола](https://code.claude.com/docs/ru/desktop.md#work-in-parallel-with-sessions). Смотрите [Возобновить сессию](#resume-a-session), чтобы узнать, как разрешение имен работает в worktrees.

Сессии, которые вы не назвали, все еще получают два ярлыка, которые назначает Claude Code. Только сгенерированное название работает как дескриптор возобновления:

* Имя отображения по умолчанию: интерактивные сессии, которые вы никогда не назвали, все еще получают имя отображения по умолчанию при запуске. Значение по умолчанию объединяет имя рабочего каталога с двухсимвольным суффиксом, например `my-app-3f`, и идентифицирует сессию в списках запущенных сессий, таких как [представление агента](https://code.claude.com/docs/ru/agent-view.md) и вывод `claude agents --json`. Значение по умолчанию не является дескриптором возобновления. Если вы передадите его в `claude --resume` или `/resume`, Claude Code не найдет сессию.
* Сгенерированное название: если вы не назовете сессию, Claude Code генерирует для неё название сессии. Название — это краткое резюме вашей первой подсказки, написанное фоновым запросом к небольшой/быстрой модели, обычно модели класса Haiku. Запуск `claude -p`, который вы запускаете непосредственно из оболочки или скрипта, не получает его.

  Если вы установите [`CLAUDE_CODE_DISABLE_TERMINAL_TITLE`](https://code.claude.com/docs/ru/env-vars#variables) в значение `1`, сессии в терминале и в Agent SDK не получают это название.

  Принятие плана заменяет сгенерированное название на название на основе плана. Вы можете передать любое из названий в `claude --resume` или `/resume`, и Claude Code разрешит его так же, как имя, которое вы установили.

## Использование средства выбора сеансов

Запустите `/resume` внутри сеанса или `claude --resume` без аргументов, чтобы открыть интерактивное средство выбора сеансов. Используйте эти сочетания клавиш для навигации, поиска и расширения списка:

| Сочетание клавиш | Действие |
| :- | :- |
| `↑` / `↓` или `k` / `j` | Навигация между сессиями |
| `→` / `←` | Развёртывание или свёртывание сгруппированных сеансов |
| `Enter` | Возобновление выделенного сеанса |
| `1`–`9` | Возобновление сессии на соответствующей позиции в списке |
| `Space` | Предпросмотр содержимого сеанса. `Ctrl+V` также работает на терминалах, которые не захватывают его как вставку |
| `Ctrl+R` | Переименование выделенного сеанса |
| `/` или любой печатный символ, кроме `Space`, `j`, `k` или цифры | Вход в режим поиска и фильтрация сессий. Вставьте URL pull или merge request GitHub, GitHub Enterprise, GitLab или Bitbucket, чтобы найти сессию, которая его создала |
| `Ctrl+A` | Показать сеансы из всех проектов на этой машине. Нажмите снова, чтобы вернуться к текущему репозиторию |
| `Ctrl+W` | Показать сеансы из всех worktrees текущего репозитория. Нажмите снова, чтобы вернуться к текущему worktree. Отображается только в репозиториях с несколькими worktrees |
| `Ctrl+B` | Фильтр к сеансам из текущей ветви git. Нажмите снова, чтобы показать все ветви |
| `Esc` | Выход из средства выбора сеансов или режима поиска |

Каждая строка показывает имя сессии, если оно установлено, в противном случае сгенерированное ИИ название сессии, сводку диалога или первый промпт, а также время с момента последней активности, ветку git и размер файла.

Сеансы, созданные с помощью `/branch` или `--fork-session`, получают свои собственные идентификаторы сеансов и отображаются как отдельные строки. Когда средство выбора находит более одной записи для одного и того же сеанса, оно группирует их под одной строкой. Нажмите `→` для развёртывания группы.

Если Claude Code не может загрузить выбранный вами сеанс из средства выбора `claude --resume`, он выводит [`Failed to resume the conversation`](https://code.claude.com/docs/ru/errors#failed-to-resume-the-conversation) с командой для повтора, а затем завершает работу с кодом 1. Из средства выбора `/resume` внутри сеанса Claude Code сообщает об ошибке, и ваш текущий диалог продолжает работать.

## Создание ветви сеанса

Создание ветви создаёт копию диалога до сих пор и переключает вас в неё, оставляя оригинал нетронутым. Используйте это, чтобы попробовать другой подход без потери пути, на котором вы были.

Из активного сеанса запустите `/branch` с необязательным именем:

```text theme={null}
/branch try-streaming-approach
```

Если вы опустите имя, Claude Code назовёт новую ветку по первому промпту в диалоге.

Из командной строки объедините `--continue` или `--resume` с `--fork-session`:

```bash theme={null}
claude --continue --fork-session
```

Подтверждение `/branch` выводит два ID сеанса: новую ветвь, в которой вы находитесь, и оригинал. Оригинал остаётся неизменным на диске и остаётся в средстве выбора сеансов; вернитесь к нему с помощью `/resume <original-name>` или передав его ID в `/resume`.

`/branch` копирует стенограмму и переключает запущенный процесс Claude Code на запись в неё. Это различие определяет, что наследует ветвь:

| Состояние | После `/branch` |
| :- | :- |
| История диалога | Скопирована в ветвь до момента, когда вы запустили `/branch` |
| Разрешения "Allow for this session" | Перенесены; ветвь работает в том же процессе, поэтому ваши существующие разрешения по-прежнему применяются. Если вы разветвляетесь в отдельный процесс с помощью `--fork-session`, новый процесс запускается без них, и вы повторно одобряете их там |
| Выполняющиеся [фоновые подагенты](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background) и [фоновые команды Bash](https://code.claude.com/docs/ru/interactive-mode.md#background-bash-commands) | Продолжают работать. Их вывод появляется в новой ветви, в которую вы переключились, а не в исходном сеансе |
| Соединение [Remote Control](https://code.claude.com/docs/ru/remote-control.md) | Остаётся подключённым. Телефон или браузер, подключённый к сеансу, следует за вами в ветвь и продолжает получать там новые сообщения |

Если вы одновременно возобновите одну и ту же сессию в двух терминалах или в двух запусках `claude -p`, оба будут записывать в один транскрипт. Когда вы позже возобновите эту сессию, сообщения от одного из них могут отсутствовать. Чтобы сохранить оба диалога, добавьте `--fork-session` к каждой команде `claude`. О перемотке на основе чекпоинтов в рамках одной сессии см. [Чекпоинты](https://code.claude.com/docs/ru/checkpointing.md).

## Управление контекстом в сеансе

Эти команды управляют тем, что находится в окне контекста, не покидая сеанс:

* **`/clear`**: начать заново с пустым контекстом. Claude Code сохраняет предыдущую сессию; возобновите её с помощью `/resume`, или, в том же процессе Claude Code, из [записи предыдущей сессии в меню перемотки](https://code.claude.com/docs/ru/checkpointing.md#rewind-past-a-cleared-conversation). Без аргумента новая сессия сохраняет имя, которое вы установили с помощью `--name` или `/rename`, но не название сессии, сгенерированное ИИ. Чтобы вместо этого назвать сессию, которую вы покидаете, передайте имя, как в `/clear release-prep`; новая сессия затем начинается без имени
* **`/compact [instructions]`**: заменить историю сводкой, опционально сосредоточенной на том, что вы указали
* **`/context`**: показать, что в настоящее время потребляет контекст

О том, как сжатие контекста взаимодействует с CLAUDE.md, скиллами и правилами, см. [руководство по контекстному окну](https://code.claude.com/docs/ru/context-window.md). Стратегии о том, когда очищать, а когда сжимать контекст, см. в разделе [Лучшие практики](https://code.claude.com/docs/ru/best-practices.md#keep-cost-and-context-down).

## Экспорт и поиск данных сеанса

Запустите `/export`, чтобы открыть меню, которое позволяет скопировать текущий диалог в буфер обмена или сохранить его как простой текстовый файл с сообщениями и выводом инструментов, отображаемыми как читаемый текст. Передайте имя файла для прямой записи в этот файл.

### Доступ к диалогам из скриптов

`/export` создает отформатированную стенограмму для чтения человеком. Интерфейсы ниже создают структурированные данные для анализа скриптом: результат JSON из запуска, путь к файлу стенограммы сеанса или живой поток событий. Выбирайте в зависимости от того, что запускает скрипт:

* **Запустить Claude один раз и захватить результат**: вызовите `claude -p` с [`--output-format json` или `stream-json`](https://code.claude.com/docs/ru/headless#get-structured-output), чтобы захватить результат, ID сеанса, использование и стоимость неинтерактивного запуска как структурированный JSON.
* **Задать вопрос существующему сеансу**: передайте ID сеанса в [`claude -p --resume`](https://code.claude.com/docs/ru/headless#continue-conversations), чтобы отправить дополнительный запрос, например запрос на резюме, и захватить структурированный ответ.
* **Реагировать на события сеанса**: прочитайте поле `transcript_path`, которое получают [hooks](https://code.claude.com/docs/ru/hooks.md#common-input-fields) и [команды строки состояния](https://code.claude.com/docs/ru/statusline.md#available-data) в качестве входных данных. Hook `SessionEnd` может архивировать стенограмму при завершении сеанса.
* **Встроить Claude в приложение TypeScript или Python**: используйте [Agent SDK](https://code.claude.com/docs/ru/agent-sdk/overview.md) для получения каждого сообщения программным способом.

Пример ниже использует второй интерфейс. Он отправляет дополнительный запрос существующему сеансу и читает ответ с помощью `jq`:

```bash theme={null}
claude -p --resume <session-id> --output-format json "summarize what we changed" | jq -r '.result'
```

### Где хранятся стенограммы

По умолчанию Claude Code хранит стенограммы как JSONL в `~/.claude/projects/<project>/<session-id>.jsonl`, где `<project>` — это путь вашего рабочего каталога с заменой не буквенно-цифровых символов на `-`. Для рабочего каталога, преобразованное имя которого превышает 200 символов, Claude Code усекает имя до 200 символов и добавляет хеш полного пути, чтобы имя каталога оставалось в пределах ограничений файловой системы.

Каждая строка — это объект JSON: сообщение, использование инструмента или его результат, запись о запросе, который Claude Code отправил модели, или запись метаданных. Формат записи является внутренним для Claude Code и изменяется между версиями, поэтому скрипты, которые анализируют эти файлы напрямую, могут сломаться при любом выпуске. Чтобы работать с данными сессии, используйте `/export` или [интерфейсы скриптов](#access-conversations-from-scripts) вместо этого.

Местоположение, сохранение и поведение записи настраиваются:

| Для | Установить | Где |
| - | - | - |
| Переместить хранилище с `~/.claude` | [`CLAUDE_CONFIG_DIR`](https://code.claude.com/docs/ru/env-vars) | Переменная окружения |
| [Назвать каталог `<project>` самостоятельно](#name-the-project-directory-yourself) | [`CLAUDE_CODE_PROJECT_DIR_NAME`](https://code.claude.com/docs/ru/env-vars) | Переменная окружения |
| Изменить 30-дневный срок хранения | [`cleanupPeriodDays`](https://code.claude.com/docs/ru/settings-reference#cleanupperioddays) | `settings.json` |
| Установить ограничение по возрасту для [стенограмм Claude Desktop и Cowork](https://code.claude.com/docs/ru/claude-directory.md#cleaned-up-automatically) | [`desktopSessionCleanupPeriodDays`](https://code.claude.com/docs/ru/settings-reference#desktopsessioncleanupperioddays) | Пользовательские параметры, управляемые параметры или `--settings` |
| Ограничить рост размера файла транскрипта сессии `-p` или Agent SDK | [`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC`](https://code.claude.com/docs/ru/env-vars) | Переменная окружения |
| Подавить запись стенограмм во всех режимах | [`CLAUDE_CODE_SKIP_PROMPT_HISTORY`](https://code.claude.com/docs/ru/env-vars) | Переменная окружения |
| Подавить запись для одного неинтерактивного запуска | [`--no-session-persistence`](https://code.claude.com/docs/ru/cli-reference) | Флаг CLI с `claude -p` |

### Удалить данные сеанса

Транскрипты удаляются в соответствии с [правилами очистки сохранения](https://code.claude.com/docs/ru/claude-directory.md#cleaned-up-automatically). Чтобы удалить транскрипты проекта и связанное состояние раньше, запустите [`claude purge`](https://code.claude.com/docs/ru/claude-directory#clear-local-data). Если вы удалите [фоновую сессию](https://code.claude.com/docs/ru/agent-view.md) с помощью [`claude rm <id>`](https://code.claude.com/docs/ru/agent-view#what-deleting-a-session-removes), ее транскрипт остается на диске и остается доступным через `claude --resume`.

### Назвать каталог проекта самостоятельно

По умолчанию Claude Code получает имя `<project>` из полного пути рабочего каталога. Чтобы выбрать имя самостоятельно, установите `CLAUDE_CODE_PROJECT_DIR_NAME` вместе с `CLAUDE_CONFIG_DIR`. Claude Code затем хранит стенограммы этого сеанса и [автоматическую память](https://code.claude.com/docs/ru/memory.md#auto-memory) под вашим именем. Это подходит для хоста, который встраивает Claude Code и дает каждому сеансу свой собственный каталог конфигурации. Требуется Claude Code v2.1.234 или позже.

Например, этот запуск хранит данные арендатора A в `/srv/tenant-a` и называет его каталог проекта `work`:

```bash theme={null}
CLAUDE_CONFIG_DIR=/srv/tenant-a CLAUDE_CODE_PROJECT_DIR_NAME=work claude
```

Claude Code записывает стенограммы сеанса в `/srv/tenant-a/projects/work/` и его автоматическую память в `/srv/tenant-a/projects/work/memory/`, независимо от того, какой рабочий каталог используется.

При установке применяются три правила:

* **Установите `CLAUDE_CONFIG_DIR` также**: имя не зависит от рабочего каталога, поэтому при использовании по умолчанию `~/.claude` оно объединит стенограммы и автоматическую память каждого проекта в один каталог. Claude Code игнорирует `CLAUDE_CODE_PROJECT_DIR_NAME`, когда `CLAUDE_CONFIG_DIR` не установлен.
* **Используйте 1-64 буквы, цифры, дефисы или подчеркивания**: не используйте имя устройства Windows, такое как `con`. Claude Code игнорирует любое другое значение и использует полученное имя.
* **Установите его в окружении оболочки, которая запускает `claude`**: Claude Code читает его один раз при запуске из этого окружения, поэтому блок `env` в файле параметров не может его установить.

После того как вы назвали каталог проекта каталога конфигурации, продолжайте запускать с этим именем. Если вы запустите Claude Code с тем же `CLAUDE_CONFIG_DIR`, но без `CLAUDE_CODE_PROJECT_DIR_NAME`, он снова прочитает и запишет полученный каталог. Сеансы, хранящиеся под вашим именем, остаются на диске: нажмите `Ctrl+A` в [средстве выбора сеанса](#use-the-session-picker), чтобы перечислить сеансы из каждого каталога проекта под этим каталогом конфигурации, включая закрепленный, и в любом случае [`claude --resume <session-id>`](#resume-a-session) находит сеанс, хранящийся под любым именем.
