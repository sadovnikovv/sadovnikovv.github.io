Расширение Claude Code #

Узнайте, когда использовать CLAUDE.md, Skills, subagents, hooks, MCP и plugins.

Claude Code объединяет модель, которая рассуждает о вашем коде, с встроенными инструментами для операций с файлами, поиска, выполнения и веб-доступа. Встроенные инструменты охватывают большинство задач кодирования. Это руководство охватывает уровень расширения: функции, которые вы добавляете для настройки того, что знает Claude, подключения его к внешним сервисам и автоматизации рабочих процессов.

[!NOTE]

Информацию о том, как работает основной цикл агента, см. в разделе How Claude Code works.

Новичок в Claude Code? Начните с CLAUDE.md для соглашений проекта, затем добавляйте другие расширения по мере возникновения конкретных триггеров.

Обзор #

Расширения подключаются к различным частям цикла агента:

  • CLAUDE.md добавляет постоянный контекст, который Claude видит в каждой сессии
  • Output styles устанавливают роль Claude, тон и формат ответа для каждого ответа в сессии
  • Skills добавляют переиспользуемые знания и вызываемые рабочие процессы
  • Code intelligence подключает Claude к языковому серверу для навигации на уровне символов и ошибок типов в реальном времени
  • MCP подключает Claude к внешним сервисам и инструментам
  • Subagents запускают свои собственные циклы в изолированном контексте, возвращая резюме
  • Dynamic workflows запускают множество subagents из скрипта, который пишет Claude, возвращая один результат
  • Cross-session messaging позволяет Claude передать сообщение из одной вашей сессии в другую
  • Hooks запускают ваш скрипт, HTTP запрос, вызов инструмента MCP, prompt или subagent, когда Claude Code достигает события жизненного цикла
  • Plugins и marketplaces упаковывают и распространяют эти функции

Skills — это наиболее гибкое расширение. Skill — это файл markdown, содержащий знания, рабочие процессы или инструкции. Вы можете вызывать skills с помощью команды типа /deploy, или Claude может загружать их автоматически, когда они релевантны. Skills могут работать в вашем текущем разговоре или в изолированном контексте через subagents.

Сопоставьте функции с вашей целью #

Функции варьируются от всегда включённого контекста, который Claude видит в каждой сессии, до функций по требованию, которые вы или Claude можете вызвать, до фоновой автоматизации, которая запускается при определённых событиях. В таблице ниже показано, что доступно и когда каждое имеет смысл.

| Функция | Что она делает | Когда её использовать | Пример | | - | - | - | - | | CLAUDE.md | Постоянный контекст, загружаемый в каждый разговор | Соглашения проекта, правила «всегда делай X» | «Используй pnpm, а не npm. Запускай тесты перед коммитом.» | | Output style | Инструкции, которые устанавливают роль Claude, тон и формат ответа для целой сессии | Голос, длину или формат, который вы хотите в каждом ответе, или Claude, работающий как что-то другое, чем инженер-программист | Встроенный стиль Concise для более коротких ответов; пользовательский стиль, который отвечает на каждый вопрос с диаграммой в первую очередь | | Skill | Инструкции, знания и рабочие процессы, которые может использовать Claude | Переиспользуемый контент, справочные документы, повторяющиеся задачи | /deploy запускает твой контрольный список развёртывания; skill с документацией API с шаблонами конечных точек | | Subagent | Изолированный контекст выполнения, который возвращает обобщённые результаты | Изоляция контекста, параллельные задачи, специализированные рабочие | Задача исследования, которая читает много файлов, но возвращает только ключевые выводы | | Dynamic workflow | Скрипт, который пишет Claude и запускает много subagent'ов в фоне | Работа, которая переросла несколько subagent'ов, или выводы, которые ты хочешь перепроверить | Проверь весь кодовую базу, со вторым набором агентов, проверяющих каждый вывод | | Cross-session messaging | Claude доставляет сообщение из одной из твоих сессий в другую | Сессии, которые ты запускаешь сам и которым нужны выводы друг друга в середине задачи | Одна сессия предупреждает другую, что изменение, которое она сделала, нарушает то, на чём строится другая | | Code intelligence | Навигация и диагностика языкового сервера | Типизированные языки, большие кодовые базы, где grep медленен или неточен | Перейди к определению символа вместо чтения всего файла | | MCP | Подключись к внешним сервисам | Внешние данные или действия | Запроси свою базу данных, опубликуй в Slack, управляй браузером | | Hook | Скрипт, HTTP-запрос, вызов инструмента MCP, подсказка или subagent, запущенные событиями | Автоматизация, которая должна запуститься при каждом совпадающем событии | Запусти ESLint после каждого редактирования файла | | Artifact | Опубликуй вывод сессии как приватную интерактивную веб-страницу | Вывод, который ты хочешь увидеть или поделиться визуально, а не как текст терминала | Временная шкала инцидента, которая обновляется по мере того, как Claude расследует |

Plugins — это уровень упаковки. Plugin объединяет skills, hooks, subagent'ов и MCP-серверы в один устанавливаемый модуль. Skills плагина имеют пространство имён (например /my-plugin:review), поэтому несколько плагинов могут сосуществовать. Используйте плагины, когда вы хотите переиспользовать одну и ту же настройку в нескольких репозиториях или распространять другим через marketplace.

Строй свою настройку со временем #

Тебе не нужно настраивать всё заранее. Каждая функция имеет узнаваемый триггер, и большинство команд добавляют их примерно в таком порядке:

| Триггер | Добавь | | :- | :- | | Claude дважды неправильно применяет соглашение или команду | Добавь это в CLAUDE.md | | Вы постоянно просите Claude быть короче, объяснять больше или отвечать в одном формате | Установите output style | | Ты постоянно печатаешь одну и ту же подсказку, чтобы начать задачу | Сохрани её как вызываемый пользователем skill | | Ты вставляешь один и тот же сценарий или многошаговую процедуру в чат в третий раз | Захвати это как skill | | Ты постоянно копируешь данные из вкладки браузера, которую Claude не видит | Подключи эту систему как MCP-сервер | | Claude читает много файлов, чтобы найти, где определён или используется символ | Установите плагин code intelligence для вашего языка | | Побочная задача заполняет твой разговор выводом, на который ты больше не будешь ссылаться | Маршрутизируй его через subagent | | Ты хочешь, чтобы что-то происходило каждый раз без просьбы | Напиши hook | | Второй репозиторий нуждается в одной и той же настройке | Упакуйте это как plugin |

Те же триггеры говорят тебе, когда обновить то, что у тебя уже есть. Повторяющаяся ошибка или повторяющийся комментарий при проверке — это редактирование CLAUDE.md, а не одноразовое исправление в чате. Рабочий процесс, который ты постоянно подправляешь вручную, — это skill, который нуждается в другой редакции.

Сравни похожие функции #

Некоторые функции могут казаться похожими. Для более глубокого разбора выбора между ними см. Steering Claude Code: when to use CLAUDE.md, skills, hooks, and subagents в блоге. Вот как их различить.

[tab] Skill vs Subagent

Skills и subagent'ы решают разные проблемы:

  • Skills — это переиспользуемый контент, который ты можешь загрузить в любой контекст
  • Subagent'ы — это изолированные рабочие, которые запускаются отдельно от твоего основного разговора

| Аспект | Skill | Subagent | | - | - | - | | Что это | Переиспользуемые инструкции, знания или рабочие процессы | Изолированный рабочий со своим собственным контекстом | | Ключевое преимущество | Поделись контентом между контекстами | Изоляция контекста. Работа происходит отдельно, возвращается только резюме | | Влияние на context window | Добавляется в твоё основное окно | Использует отдельное окно со своими входными и выходными токенами | | Лучше всего для | Справочный материал, вызываемые рабочие процессы | Задачи, которые читают много файлов, параллельная работа, специализированные рабочие |

Skills могут быть справочными или действенными. Справочные skills предоставляют знания, которые Claude использует на протяжении твоей сессии (например, твой справочник стиля API). Action skills говорят Claude сделать что-то конкретное (например, /deploy, который запускает твой рабочий процесс развёртывания).

Используй subagent, когда тебе нужна изоляция контекста или когда твоё окно контекста переполняется. Subagent может читать десятки файлов или запускать обширные поиски, но твой основной разговор получает только резюме. Поскольку работа subagent'а не потребляет твой основной контекст, это также полезно, когда тебе не нужна промежуточная работа, чтобы оставаться видимой. Пользовательские subagent'ы могут иметь свои собственные инструкции и могут предварительно загружать skills.

Они могут объединяться. Subagent может предварительно загружать определённые skills (поле skills:). Skill может запускаться в изолированном контексте, используя context: fork. Подробнее см. в Skills.

[tab] CLAUDE.md vs Skill

Оба хранят инструкции, но они загружаются по-разному и служат разным целям.

| Аспект | CLAUDE.md | Skill | | - | - | - | | Загружается | Каждая сессия, автоматически | По требованию | | Может включать файлы | Да, с импортами @path | Да, с импортами @path | | Может запускать рабочие процессы | Нет | Да, с /<name> | | Лучше всего для | Правила «всегда делай X» | Справочный материал, вызываемые рабочие процессы |

Поместите это в CLAUDE.md, если Claude должен всегда это знать: соглашения кодирования, команды сборки, структура проекта, правила «никогда не делай X».

Поместите это в skill, если это справочный материал, который Claude иногда нужен (документация API, справочники стилей) или рабочий процесс, который ты запускаешь с /<name> (развёртывание, проверка, выпуск).

Правило большого пальца: Держите CLAUDE.md под 200 строк. Если он растёт, переместите справочный контент в skills или разделите на файлы .claude/rules/.

[tab] CLAUDE.md vs Output style

Оба дают Claude постоянные инструкции. CLAUDE.md содержит то, что Claude должен знать, и output style устанавливает, как Claude отвечает.

| Аспект | CLAUDE.md | Output style | | - | - | - | | Содержит | Факты и правила о вашем проекте | Роль, тон и формат ответа | | Переключение | Всегда загружается | Один активный одновременно; переключайте стили когда угодно | | Лучше всего для | Команды сборки, соглашения, правила «никогда не делай X» | Более короткие ответы, объяснения рядом с кодом, роль, отличная от инженера |

Поместите это в CLAUDE.md, если это верно для проекта в любом стиле: соглашения кодирования, команды сборки, структура проекта.

Используйте output style, если это о самом ответе и вы можете захотеть его отключить: длина, формат, сколько Claude объясняет, или другая роль, такая как помощник по письму. Claude Code включает встроенные стили, и вы можете написать свои собственные.

Они объединяются. CLAUDE.md остаётся загруженным, какой бы стиль вы ни выбрали. Claude следует обоим как инструкциям, поэтому ни один не применяется принудительно. Для чего-либо, что должно происходить каждый раз, используйте hook.

[tab] CLAUDE.md vs Rules vs Skills

Все три хранят инструкции, но они загружаются по-разному:

| Аспект | CLAUDE.md | .claude/rules/ | Skill | | - | - | - | - | | Загружается | Каждая сессия | Каждая сессия, или когда открываются совпадающие файлы | По требованию, когда вызывается или релевантно | | Область | Весь проект | Может быть ограничена путями файлов | Специфична для задачи | | Лучше всего для | Основные соглашения и команды сборки | Рекомендации, специфичные для языка или каталога | Справочный материал, повторяющиеся рабочие процессы |

Используй CLAUDE.md для инструкций, которые каждая сессия нуждается: команды сборки, соглашения тестирования, архитектура проекта.

Используй rules, чтобы держать CLAUDE.md сосредоточенным. Rules с frontmatter paths загружаются только когда Claude работает с совпадающими файлами, экономя контекст.

Используй skills для контента, который Claude нужен только иногда, например документация API или контрольный список развёртывания, который ты запускаешь с /<name>.

[tab] Subagent vs Dynamic workflow

Оба выполняют работу вне твоего основного разговора. С subagent'ами Claude решает поворот за поворотом, что запускается дальше. В рабочем процессе скрипт решает:

  • Subagent'ы — это рабочие, которых Claude запускает, каждый возвращая резюме в разговор, который его запустил
  • Dynamic workflows — это скрипты, которые пишет Claude и запускают много subagent'ов в фоне и возвращают один результат

Используйте субагента, когда вам нужен быстрый, сфокусированный исполнитель: изучить вопрос, проверить утверждение, просмотреть файл. Субагент выполняет работу и возвращает резюме, поэтому ваш основной диалог остаётся чистым. Субагенты, которым Claude дал имена при запуске, также могут обмениваться сообщениями друг с другом.

Используй dynamic workflow, когда работа переросла несколько subagent'ов, или когда ты хочешь, чтобы выводы были перепроверены перед тем, как ты их увидишь, например аудит всей кодовой базы, крупная миграция или план, составленный с нескольких углов. Чтобы начать один, попроси рабочий процесс в своей подсказке.

Чтобы передать вывод из одной из твоих сессий в другую, попроси Claude первой сессии отправить его. Claude доставляет его с помощью cross-session messaging. Run agents in parallel сравнивает другие способы запуска более чем одного Claude одновременно, включая сессии, которые ты передаёшь и проверяешь позже.

[tab] MCP vs Skill

MCP подключает Claude к внешним сервисам. Skills расширяют то, что знает Claude, включая то, как эффективно использовать эти сервисы.

| Аспект | MCP | Skill | | - | - | - | | Что это | Протокол для подключения к внешним сервисам | Знания, рабочие процессы и справочный материал | | Предоставляет | Инструменты и доступ к данным | Знания, рабочие процессы, справочный материал | | Примеры | Интеграция Slack, запросы к базе данных, управление браузером | Контрольный список проверки кода, рабочий процесс развёртывания, справочник стиля API |

Они решают разные проблемы и хорошо работают вместе:

MCP даёт Claude специально разработанные инструменты для внешней системы, с подключением и аутентификацией, обработанными сервером.

Skills дают Claude знания о том, как эффективно использовать эти инструменты, плюс рабочие процессы, которые ты можешь запустить с /<name>. Skill может включать схему базы данных твоей команды и шаблоны запросов, или рабочий процесс /post-to-slack с правилами форматирования сообщений твоей команды.

[tab] Hook vs Skill

Claude Code запускает hook при событии жизненного цикла; он загружает skill в контекст для Claude, чтобы применить.

| Аспект | Hook | Skill | | - | - | - | | Запускает | Команду shell, HTTP-запрос, вызов инструмента MCP, подсказку LLM или subagent'а | Инструкции, которые Claude читает и следует | | Запущено | События жизненного цикла, такие как PostToolUse или SessionStart | Ты печатаешь /<name>, или Claude соответствует описанию твоей задаче | | Детерминированность | Срабатывает при своём событии без решения со стороны Claude | Claude интерпретирует инструкции; результат может различаться | | Стоимость контекста | Ноль, если hook не возвращает вывод | Описание загружается каждую сессию; полный контент загружается при использовании | | Лучше всего для | Линтинг после редактирования, блокирование небезопасных команд, логирование, уведомления | Рабочие процессы, которые нуждаются в рассуждении, справочный материал, многошаговые задачи |

Используй hook, когда действие должно происходить одинаково каждый раз и не нуждается в размышлении Claude. Например: форматирование при сохранении, отклонение rm -rf /, отправка сообщения Slack при завершении сессии.

Используй skill, когда Claude должен решить, как применить шаги, или когда контент — это знание, а не скрипт. Например: контрольный список /release, твой справочник стиля API, сценарий отладки.

Поместите guardrails в hooks. Инструкция типа «никогда не редактируй .env» в CLAUDE.md или skill — это просьба, а не гарантия. Hook PreToolUse, который блокирует редактирование, — это принуждение. Если правило должно выполняться каждый раз, сделай его hook, а не инструкцию подсказки.

Сочетайте хук со скиллом. Используйте хук PostToolUse, чтобы запускать ваш линтер и отправлять ошибки Claude. Чтобы дать Claude собственные правила исправления ошибок, напишите скилл, например /fix-lint.

Поймите, как функции слоятся #

Функции могут быть определены на нескольких уровнях: для всех пользователей, для каждого проекта, через плагины или через управляемые политики. Ты также можешь вложить файлы CLAUDE.md в подкаталоги или разместить skills в определённых пакетах монорепо. Когда одна и та же функция существует на нескольких уровнях, вот как они слоятся:

  • Файлы CLAUDE.md являются аддитивными: все уровни вносят контент в контекст Claude одновременно. Файлы из твоего рабочего каталога и выше загружаются при запуске; подкаталоги загружаются по мере того, как ты работаешь в них. Когда инструкции конфликтуют, Claude использует суждение, чтобы их согласовать. Подробнее см. в как загружаются файлы CLAUDE.md.
  • Skills и subagent'ы переопределяют по имени: когда одно и то же имя существует на нескольких уровнях, одно определение побеждает на основе приоритета (managed > user > project для skills; managed > CLI flag > project > user > plugin для subagent'ов). Skills плагина имеют пространство имён для избежания конфликтов. Подробнее см. в обнаружение skills и область subagent'а.
  • MCP-серверы переопределяют по имени: local > project > user. Подробнее см. в область MCP.
  • Hooks объединяются: все зарегистрированные hooks срабатывают для своих совпадающих событий независимо от источника. Подробнее см. в hooks.

Объедини функции #

Каждое расширение решает разную проблему: CLAUDE.md обрабатывает всегда включённый контекст, skills обрабатывают знания и рабочие процессы по требованию, MCP обрабатывает внешние подключения, subagent'ы обрабатывают изоляцию, и hooks обрабатывают автоматизацию. Реальные настройки объединяют их на основе твоего рабочего процесса.

Например, ты можешь использовать CLAUDE.md для соглашений проекта, skill для твоего рабочего процесса развёртывания, MCP для подключения к твоей базе данных и hook для запуска линтинга после каждого редактирования. Каждая функция обрабатывает то, в чём она лучше всего.

| Паттерн | Как это работает | Пример | | - | - | - | | Skill + MCP | MCP предоставляет подключение; skill учит Claude, как его хорошо использовать | MCP подключается к твоей базе данных, skill документирует твою схему и шаблоны запросов | | Skill + Subagent | Skill запускает subagent'ов для параллельной работы | Skill /audit запускает subagent'ов безопасности, производительности и стиля, которые работают в изолированном контексте | | CLAUDE.md + Skills | CLAUDE.md содержит всегда включённые правила; skills содержат справочный материал, загружаемый по требованию | CLAUDE.md говорит «следуй нашим соглашениям API», skill содержит полный справочник стиля API | | Hook + MCP | Hook запускает внешние действия через MCP | Hook после редактирования отправляет уведомление Slack, когда Claude изменяет критические файлы |

Поймите стоимость контекста #

Каждая функция, которую вы добавляете, потребляет часть контекста Claude. Слишком много может заполнить ваше окно контекста, но это также может добавить шум, который делает Claude менее эффективным; skills могут не срабатывать правильно, или Claude может потерять из виду ваши соглашения. Понимание этих компромиссов помогает вам построить эффективную настройку. Для интерактивного представления того, как эти функции объединяются в работающей сессии, см. Explore the context window.

Стоимость контекста по функциям #

Каждая функция имеет разную стратегию загрузки и стоимость контекста:

| Функция | Когда загружается | Что загружается | Стоимость контекста | | - | - | - | - | | CLAUDE.md | Начало сессии | Полный контент каждого файла, загружаемого в начале сессии | Каждый запрос | | Output styles | Начало сессии и снова при переключении стилей | Полные инструкции активного стиля; ничего для стиля Default | Каждый запрос | | Skills | Начало сессии + при использовании | Описания в начале, полный контент при использовании | Низкая (описания каждый запрос)\* | | MCP servers | Начало сессии | Имена инструментов; полные схемы по требованию | Низкая до использования инструмента | | Code intelligence | После редактирования файлов и по требованию | Диагностика после редактирования; расположение символов при поиске | Низкая; снижает чтение файлов в других местах | | Subagents | При запуске | Свежий контекст с указанными skills, или родительский разговор для fork | Изолирован от основной сессии | | Hooks | При срабатывании | Ничего (работает внешне) | Ноль, если hook не возвращает дополнительный контекст |

\*Установите disable-model-invocation: true во frontmatter скилла, чтобы его описание не попадало в контекст Claude. Для скилла, который вы не писали, установите skillOverrides в настройках, чтобы сделать то же самое без редактирования его файла.

Поймите, как загружаются функции #

Каждая функция загружается в разные точки вашей сессии. Вкладки ниже объясняют, когда загружается каждая и что входит в контекст.

[tab] CLAUDE.md

Когда: Начало сессии

Что загружается: Полный контент каждого файла CLAUDE.md, который загружается в начале сессии (управляемые, пользовательские и уровни проекта).

Наследование: Claude читает файлы CLAUDE.md из вашего рабочего каталога вверх до корня и обнаруживает вложенные в подкаталогах по мере доступа к этим файлам. Подробнее см. в разделе How CLAUDE.md files load. Если вложенный CLAUDE.md превышает ограничение размера для одного файла, Claude получает только начало файла.

[!TIP]

Держите CLAUDE.md под 200 строк. Переместите справочный материал в skills, которые загружаются по требованию. Чтобы получить предложения по сокращению зафиксированного в репозитории CLAUDE.md, запустите /doctor.

[tab] Skills

Skills — это дополнительные возможности в наборе инструментов Claude. Они могут быть справочным материалом (например, руководство по стилю API) или вызываемыми рабочими процессами, которые вы запускаете с помощью /<name> (например, /deploy). Claude Code поставляется с встроенными skills типа /code-review, /batch и /debug, которые работают из коробки. Вы также можете создавать свои собственные.

Когда: Зависит от конфигурации skill. По умолчанию описания загружаются в начале сессии, а полный контент загружается при использовании. Для skills только пользователя (disable-model-invocation: true) ничего не загружается до тех пор, пока вы их не вызовете.

Что загружается: Для skills, вызываемых моделью, Claude видит имена и описания в каждом запросе. Когда вы вызываете skill с помощью /<name> или Claude загружает его автоматически, полный контент загружается в ваш разговор.

Как Claude выбирает скиллы: Claude сопоставляет вашу задачу с описаниями скиллов, чтобы решить, какие релевантны. Если описания расплывчаты или перекрываются, Claude может загрузить неправильный скилл или пропустить тот, который помог бы. Чтобы сказать Claude использовать определённый скилл, вызовите его с помощью /<name>.

Стоимость контекста: Низкая до использования. Skills только пользователя имеют нулевую стоимость до вызова.

В субагентах: Полный контент скиллов, указанных в поле skills субагента, загружается в его контекст при запуске, а не по требованию. Субагенты по-прежнему могут обнаруживать и вызывать не указанные в списке скиллы проекта, пользователя и плагинов через инструмент Skill.

[!TIP]

Используйте disable-model-invocation: true для скиллов с побочными эффектами. Это экономит контекст и гарантирует, что они запускаются только тогда, когда вы называете их.

[tab] MCP servers

Когда: Начало сессии.

Что загружается: Имена инструментов и инструкции сервера из подключённых серверов. Полные JSON схемы остаются отложенными до тех пор, пока Claude не нуждается в конкретном инструменте.

Стоимость контекста: Tool search включён по умолчанию, поэтому неиспользуемые MCP инструменты потребляют минимальный контекст.

[!TIP]

Запустите /mcp, чтобы увидеть статус подключения каждого сервера. Запустите /context all, чтобы увидеть, сколько токенов использует каждый загруженный MCP инструмент. Claude Code автоматически переподключается к удалённым серверам, если они отключатся, и вы можете отключить серверы, которые вы не активно используете.

[tab] Code intelligence

Когда: После редактирования файлов и по требованию, когда Claude переходит по коду.

Что загружается: Ошибки типов и предупреждения после каждого редактирования файла. Информация об определении, ссылках и типах, когда Claude ищет символ.

Стоимость контекста: Низкая. Поиск символов часто заменяет широкое чтение файлов, поэтому общее использование контекста может снизиться.

[!TIP]

Инструмент LSP неактивен до тех пор, пока вы не установите плагин code intelligence для вашего языка.

[tab] Subagents

Когда: По требованию, когда вы или Claude запускаете один для задачи.

Что загружается: Свежий, изолированный контекст, содержащий:

  • Собственный системный промпт агента, а не системный промпт Claude Code
  • Полный контент skills, указанных в поле skills: агента
  • CLAUDE.md и статус git. Встроенные агенты Explore и Plan не получают ни того, ни другого, а агент, чьё определение устанавливает omitClaudeMd, запускается без пользовательского, проектного и локального файлов CLAUDE.md.
  • Любой контекст, который основной агент передаёт в промпте

Для fork, Claude Code загружает разговор родителя до сих пор, системный prompt и инструменты вместо.

Стоимость контекста: Изолирована от основной сессии.

[!TIP]

Используйте subagents для работы, которая не нуждается в вашем полном контексте разговора. Их изоляция предотвращает раздувание вашей основной сессии.

[tab] Hooks

Когда: При срабатывании. Claude Code запускает hooks при определённых событиях жизненного цикла, таких как выполнение инструмента, границы сессии, отправка prompt, запросы разрешений и компактирование. Подробный список см. в разделе Hooks.

Что загружается: Ничего по умолчанию. Hooks работают вне основного разговора.

Стоимость контекста: Ноль, если hook не возвращает вывод, который добавляется как сообщения в ваш разговор.

[!TIP]

Hooks идеальны для побочных эффектов (линтинг, логирование), которые не должны влиять на контекст Claude.
