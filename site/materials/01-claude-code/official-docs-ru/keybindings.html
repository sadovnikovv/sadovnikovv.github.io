Настройка сочетаний клавиш #

Настройте сочетания клавиш в Claude Code с помощью файла конфигурации keybindings.

Claude Code поддерживает настраиваемые сочетания клавиш. Запустите /keybindings для создания или открытия файла конфигурации в ~/.claude/keybindings.json.

Файл конфигурации #

Файл конфигурации сочетаний клавиш — это объект с массивом bindings. Каждый блок указывает контекст и карту нажатий клавиш на действия.

[!NOTE]

Изменения в файле сочетаний клавиш автоматически обнаруживаются и применяются без перезагрузки Claude Code.

| Поле | Описание | | :- | :- | | $schema | Необязательный URL JSON Schema для автодополнения редактора | | $docs | Необязательный URL документации | | bindings | Массив блоков привязок по контексту |

Этот пример привязывает Ctrl+E к открытию внешнего редактора в контексте чата и отменяет привязку Ctrl+S:

```json theme={null} { "$schema": "https://www.schemastore.org/claude-code-keybindings.json", "$docs": "https://code.claude.com/docs/en/keybindings", "bindings": [ { "context": "Chat", "bindings": { "ctrl+e": "chat:externalEditor", "ctrl+s": null } } ] }


## Contexts

Each binding block specifies a **context** where the bindings apply:

| Context | Description |
| :- | :- |
| `Global` | Применяется везде в приложении |
| `Chat` | Основная область ввода чата |
| `Autocomplete` | Меню автодополнения открыто |
| `Settings` | Меню параметров |
| `Confirmation` | Диалоги разрешений и подтверждений |
| `Tabs` | Компоненты навигации по вкладкам |
| `Help` | Меню справки видимо |
| `Transcript` | Средство просмотра стенограммы |
| `HistorySearch` | Режим поиска по истории (Ctrl+R) |
| `Task` | Задача выполняется на переднем плане |
| `ThemePicker` | Диалог выбора темы |
| `Attachments` | Навигация по вложениям изображений в диалогах выбора |
| `Footer` | Навигация по индикатору нижнего колонтитула (задачи, команды, diff, артефакты) |
| `MessageSelector` | Выбор сообщения в диалоге перемотки и резюме |
| `DiffDialog` | Навигация [средства просмотра diff](#diff-actions) |
| `DiffPanel` | [Панель diff](https://code.claude.com/docs/ru/interactive-mode.md#diff-panel) открыта |
| `ModelPicker` | Уровень усилий выбора модели |
| `EffortSlider` | Ползунок усилий, открытый с помощью `/effort` |
| `Select` | Универсальные компоненты выбора/списка |
| `Plugin` | Диалог плагина (обзор, обнаружение, управление) |
| `AbovePrompt` | [Полоса над промптом](#above-prompt-actions) или кнопка в ней находится в фокусе клавиатуры |
| `AbovePromptInput` | Поле ввода в полосе над промптом или на панели мода находится в фокусе клавиатуры |
| `AbovePromptSelect` | Список выбора в полосе над промптом или на панели мода находится в фокусе клавиатуры |
| `Pane` | Панель, отрисованная [модом](https://code.claude.com/docs/ru/plugins/mods/interface.md#know-which-keys-your-mod-can-receive), находится в фокусе клавиатуры |
| `PaneField` | Поле ввода или список выбора на панели мода находится в фокусе клавиатуры |
| `Agents` | [Представление агента](https://code.claude.com/docs/ru/agent-view.md) (`claude agents`) |
| `Scroll` | Прокрутка разговора и выделение текста в полноэкранном режиме |

До версии 2.1.205 контекст `Doctor` и действие `doctor:fix` существовали для экрана диагностики `/doctor`.

## Доступные действия

Действия следуют формату `namespace:action`, например `chat:submit` для отправки сообщения или `app:toggleTodos` для отображения списка задач. Каждый контекст имеет определённые доступные действия.

### Действия приложения

Действия, доступные в контексте `Global`:

| Действие | По умолчанию | Описание |
| :- | :- | :- |
| `app:interrupt` | Ctrl+C | Отменить текущую операцию |
| `app:exit` | Ctrl+D | Выход из Claude Code. Нажмите дважды в течение 800 мс для подтверждения |
| `app:redraw` | (не привязано) | Принудительно перерисовать терминал |
| `app:toggleTodos` | Ctrl+T | Переключить видимость списка задач Claude. Это не представление фоновых задач [`/tasks`](https://code.claude.com/docs/ru/commands) |
| `app:toggleTranscript` | Ctrl+O | Переключить подробную стенограмму |

### Действия истории

| :- | :- | :- |
| `history:search` | Ctrl+R | Открыть поиск истории |
| `history:previous` | Up | Предыдущий элемент истории |
| `history:next` | Down | Следующий элемент истории |

| :- | :- | :- |

| `chat:clearScreen` | Cmd+K | То же, что `chat:clearInput`. См. [Очистить диалог](https://code.claude.com/docs/ru/fullscreen.md#clear-the-conversation) для информации о поведении Cmd+K в iTerm2 |
| `chat:killAgents` | Ctrl+X Ctrl+K | Остановить всех работающих [фоновых субагентов](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background) в этой сессии и отключить [автоматические ответы артефактов](https://code.claude.com/docs/ru/artifacts.md#let-claude-reply-to-comments-on-its-own) на остаток сессии. Нажмите сочетание клавиш дважды в течение 3 секунд для подтверждения. Его можно нажать, пока открыт запрос разрешения фонового субагента |
| `chat:cycleMode` | Shift+Tab\* | Циклический перебор режимов разрешений |

| `chat:thinkingToggle` | Meta+T | Переключить расширенное мышление |
| `chat:submit` | Enter | Отправить сообщение |
| `chat:queueSubmit` | Ctrl+X Enter | Отправить сообщение, отмеченное для ожидания своей очереди: пока Claude работает, Claude Code [ставит его в очередь](https://code.claude.com/docs/ru/interactive-mode.md#queue-messages-while-claude-works) и никогда не прерывает ход. В отличие от `chat:submit`, он отправляет черновик даже если выделено предложение автодополнения. Требует v2.1.247 или более позднюю версию |
| `chat:sendNow` | Ctrl+Enter, Ctrl+X Ctrl+S | Отправить ваши [сообщения в очереди](https://code.claude.com/docs/ru/interactive-mode.md#queue-messages-while-claude-works) и ваш черновик с ними прямо сейчас. [Когда Claude Code отправляет то, что вы поставили в очередь](https://code.claude.com/docs/ru/interactive-mode.md#when-claude-code-sends-what-you-queued) описывает, что происходит с ходом, над которым работает Claude. Когда ничего не выполняется, клавиша отправляет черновик, а в [режиме shell](https://code.claude.com/docs/ru/interactive-mode.md#shell-mode-with-prefix) она ставит команду в очередь. Терминалы, которые не сообщают о расширенных клавишах, доставляют `Ctrl+Enter` как простой `Enter`, поэтому `Ctrl+X Ctrl+S` — это привязка, которая работает в любом терминале. Требует v2.1.275 или более позднюю версию |
| `chat:newline` | Ctrl+J | Вставить новую строку без отправки |
| `chat:undo` | Ctrl+\_, Ctrl+Shift+- | Отменить последнее действие |
| `chat:externalEditor` | Ctrl+G, Ctrl+X Ctrl+E | Открыть во внешнем редакторе. [Ввод диспетчера представления агента](https://code.claude.com/docs/ru/agent-view.md#keyboard-shortcuts) также следует сочетаниям клавиш этого действия |
| `chat:stash` | Ctrl+S | Спрятать текущий запрос |
| `chat:imagePaste` | Ctrl+V (Alt+V на Windows и WSL) | Вставить изображение из буфера обмена. На WSL оба сочетания клавиш привязаны по умолчанию |
| `command:<name>` | (не привязано) | Выполнить [команду](https://code.claude.com/docs/ru/commands.md) `/<name>`. Например, `"meta+g": "command:compact"` в блоке `Chat` заставляет `Meta+G` выполнять `/compact` |

\*На Windows без режима VT (Node \<24.2.0/\<22.17.0, Bun \<1.2.23) по умолчанию используется Meta+M.

### Действия подтверждения

Действия, доступные в контексте `Confirmation`:

| Действие | По умолчанию | Описание |
| :- | :- | :- |
| `confirm:yes` | Enter | Подтвердить действие |
| `confirm:no` | Escape | Отклонить действие |
| `confirm:previous` | Up | Предыдущий вариант |
| `confirm:next` | Down | Следующий вариант |
| `confirm:nextField` | Tab | В диалоговом окне `/fast` включить или отключить быстрый режим |
| `confirm:previousField` | (не привязано) | Claude Code не реагирует на это действие, и `keybindings.json`, в котором оно указано, остаётся действительным |
| `confirm:toggle` | Space | Переключить выбор |
| `confirm:cycleMode` | Shift+Tab\* | В запросе разрешения для файла закрывает открытое [поле комментария](https://code.claude.com/docs/ru/permissions.md#add-a-comment-when-you-answer-a-permission-prompt); если поле не открыто, выбирает вариант, который разрешает действие на остаток сессии, когда запрос предлагает этот вариант |

\*На Windows без режима VT (Node \<24.2.0/\<22.17.0, Bun \<1.2.23) по умолчанию используется Meta+M.

До v2.1.257 действие `confirm:toggleExplanation`, привязанное к `Ctrl+E` по умолчанию, показывало сгенерированное моделью объяснение команды в подсказках разрешений Bash и PowerShell.

Диалоги используют `confirm:yes` и `confirm:no` для принятия и отмены даже когда они не задают вопрос да или нет. Если вы привяжете простую букву, такую как `y` или `n`, в этом контексте, буква также действует на диалоги, которые никогда не показывают её как клавишу. Диалог, который показывает `y` и `n` как его клавиши, читает эти буквы сам и не требует привязки.

В большинстве диалогов нажатие `Ctrl+C` или `Ctrl+D` дважды закрывает диалог вместо выхода из Claude Code. Подсказка после первого нажатия говорит, закрывает ли второе нажатие диалог или выходит. Обе клавиши [зарезервированы](#reserved-shortcuts) и не могут быть переназначены.

Этот пример привязывает `y` к `confirm:yes` и `n` к `confirm:no`:

{ "bindings": [ { "context": "Confirmation", "bindings": { "y": "confirm:yes", "n": "confirm:no" } } ] }


С этими привязками `y` и `n` по-прежнему вводятся как буквы, пока [текстовое поле](#text-fields) имеет фокус.

До v2.1.280 `y` также была привязана к `confirm:yes` и `n` к `confirm:no` по умолчанию. Если вы создали свой `keybindings.json` с помощью `/keybindings` до v2.1.280, файл содержит обе привязки и они остаются в силе, пока вы не удалите эти две строки.

### Действия поиска истории

Действия, доступные в контексте `HistorySearch`:

| Действие | По умолчанию | Описание |
| :- | :- | :- |
| `historySearch:next` | Ctrl+R | Следующее совпадение |
| `historySearch:accept` | Escape, Tab | Принять выбор |
| `historySearch:cancel` | Ctrl+C | Отменить поиск |
| `historySearch:execute` | Enter | Выполнить выбранную команду |
| `historySearch:cycleScope` | Ctrl+S | Циклический перебор области: сеанс, проект, везде |

Значения по умолчанию `historySearch:next`, `historySearch:accept`, `historySearch:cancel` и `historySearch:execute` применяются к встроенному поиску истории в классическом рендерере, который всегда ищет подсказки из всех проектов. `historySearch:cycleScope` вступает в силу только в [полноэкранном рендеринге](https://code.claude.com/docs/ru/fullscreen.md), где `Ctrl+R` открывает диалог поиска вместо этого и `Ctrl+S` циклирует его область. Другие клавиши диалога фиксированы и не могут быть переназначены: `Enter` или `Tab` помещает выделенное совпадение в ввод подсказки и `Esc` отменяет.

Привязки `Chat` на клавишах, которые контекст `Footer` не привязывает, такие как `Shift+Tab` для `chat:cycleMode`, продолжают работать пока элемент выбран.

### Действия выбора сообщения

В списке сообщений [меню перемотки](https://code.claude.com/docs/ru/checkpointing.md) вы перемещаетесь по сообщениям и выбираете одно с помощью [действий выбора](#select-actions) и их клавиш по умолчанию. Ваши привязки `Select` для этих действий применяются там же. Контекст `MessageSelector` не имеет собственных действий или привязок по умолчанию. Используйте его для изменения клавиши только для этого списка, привязав действие Select, такое как `select:accept`, в блоке `MessageSelector`.

Этот пример привязывает `o` для выбора выделенного сообщения в меню перемотки, без изменения каких-либо других списков:

{ "bindings": [ { "context": "MessageSelector", "bindings": { "o": "select:accept" } } ] }


До v2.1.283 этот список игнорировал привязки `Select` и имел собственные действия: `messageSelector:up`, `messageSelector:down`, `messageSelector:top`, `messageSelector:bottom` и `messageSelector:select`. Если ваш `keybindings.json` привязывает одно из этих имён, привязка продолжает работать в этом списке как действие Select, которое делает то же самое. `Home` и `End` прыгают на любой конец списка; до v2.1.283 клавиши, такие как `Shift+K` и `Shift+J`, делали это по умолчанию.

### Действия diff

Эти действия работают только в прежнем средстве просмотра diff в Claude Code, которое `/diff` открывает вне [полноэкранного рендеринга](https://code.claude.com/docs/ru/fullscreen.md) после того, как вы отключите [мод `cc-plugin-diff`](https://code.claude.com/docs/ru/plugins/mods/overview#mods-built-into-claude-code) в `/plugin`. Пока этот мод включён, `/diff` вместо этого открывает [диалоговое окно diff](https://code.claude.com/docs/ru/interactive-mode.md#diff-dialog).

Действия, доступные в контексте `DiffDialog`:

| Действие | По умолчанию | Описание |
| :- | :- | :- |
| `diff:dismiss` | Escape | Закрыть средство просмотра diff; из представления деталей возвращает к списку файлов |
| `diff:previousSource` | Left | Предыдущий источник diff |
| `diff:nextSource` | Right | Следующий источник diff |
| `diff:previousFile` | Up, K | Предыдущий файл в списке файлов; прокрутка вверх на одну строку в представлении деталей |
| `diff:nextFile` | Down, J | Следующий файл в списке файлов; прокрутка вниз на одну строку в представлении деталей |
| `diff:back` | (не привязано) | Вернуться в средстве просмотра diff. Escape выполняет действие возврата через `diff:dismiss`. Предыдущое значение по умолчанию Left в представлении деталей было удалено в v2.1.203 |

Список файлов также реагирует на [действия выбора](#select-actions), через их клавиши по умолчанию и ваши привязки `Select`. `select:previous` и `select:next` перемещаются к предыдущему и следующему файлу, а `Enter` открывает diff выбранного файла через `select:accept`. Чтобы изменить одну из этих клавиш только для списка файлов, привяжите действие Select в блоке `DiffDialog`.

До v2.1.283 список файлов игнорировал привязки `Select`, и `Enter` открывал diff выбранного файла через отдельное действие `diff:viewDetails`. Если ваш `keybindings.json` привязывает `diff:viewDetails`, привязка продолжает работать в списке файлов как `select:accept`.

Представление деталей diff также привязывает клавиши в стиле пейджера к стандартным [действиям прокрутки](#scroll-actions). Эти привязки являются частью контекста `DiffDialog` и применяются только в представлении деталей; значения по умолчанию контекста `Scroll`, указанные в разделе [Действия прокрутки](#scroll-actions), остаются неизменными.

| Действие | По умолчанию | Описание |
| :- | :- | :- |
| `scroll:pageUp` | PageUp | Прокрутить вверх на половину окна просмотра |
| `scroll:pageDown` | PageDown | Прокрутить вниз на половину окна просмотра |
| `scroll:fullPageUp` | Shift+Space, B | Прокрутить вверх на полное окно просмотра |
| `scroll:fullPageDown` | Space | Прокрутить вниз на полное окно просмотра |
| `scroll:top` | G, Home | Перейти в начало |
| `scroll:bottom` | Shift+G, End | Перейти в конец |

## Синтаксис нажатия клавиш

### Модификаторы

Используйте клавиши-модификаторы с разделителем `+`:

* `ctrl` или `control` - клавиша Control
* `shift` - клавиша Shift
* `alt`, `opt`, `option` или `meta` - клавиша Alt в Windows и Linux, клавиша Option в macOS
* `cmd`, `command`, `super` или `win` - клавиша Command в macOS, клавиша Windows в Windows, клавиша Super в Linux

Группа `cmd` обнаруживается только в терминалах, которые сообщают о модификаторе Super, таких как те, которые поддерживают протокол клавиатуры Kitty или режим `modifyOtherKeys` xterm. Большинство терминалов его не отправляют, поэтому используйте `ctrl` или `meta` для привязок, которые вы хотите использовать везде.

Например:

ctrl+k Ctrl + K shift+tab Shift + Tab meta+p Option + P в macOS, Alt + P в других местах ctrl+shift+c Несколько модификаторов


### Прописные буквы

Claude Code анализирует названия клавиш без учёта регистра, поэтому `K` — это то же самое привязка, что и `k`, а `ctrl+K` — то же самое, что `ctrl+k`. Чтобы привязать Shift и букву, напишите `shift+k`.

### Раскладки клавиатуры, отличные от US

Пишите названия клавиш сочетаний Ctrl как латинские символы, даже если ваша активная раскладка клавиатуры вводит другие символы.

То, как Claude Code сопоставляет нажатую вами клавишу с привязкой, зависит от типа раскладки:

* При использовании нелатинской раскладки, такой как кириллица, Claude Code сопоставляет сочетания Ctrl по позиции клавиши в раскладке US, когда терминал использует протокол клавиатуры Kitty и сообщает эту позицию. В таком терминале с активной русской раскладкой нажатие Ctrl и физической клавиши W запускает `ctrl+w`. В терминале, который не сообщает позицию, Claude Code сопоставляет то, что отправляет терминал для нажатия клавиши: код управления ASCII запускает латинское сочетание, а нажатие клавиши, которое приходит как кириллический символ, не соответствует никакой привязке
* При использовании раскладок, которые переставляют латинские буквы, такие как AZERTY, Claude Code сопоставляет букву, которую вводит клавиша, поэтому нажатие Ctrl и клавиши с надписью A запускает `ctrl+a`

### Аккорды

Аккорды — это последовательности нажатий клавиш, разделённые пробелами:

ctrl+k ctrl+s Нажмите Ctrl+K, отпустите, затем Ctrl+S


Нажимайте каждое сочетание клавиш в течение 3 секунд после предыдущего. Если вы ждёте дольше, Claude Code отменяет аккорд и показывает краткое уведомление об этом.

### Специальные клавиши

* `escape` или `esc` - клавиша Escape
* `enter` или `return` - клавиша Enter
* `tab` - клавиша Tab
* `space` - пробел
* `up`, `down`, `left`, `right` - клавиши со стрелками
* `pageup`, `pagedown` - клавиши Page Up и Page Down
* `home`, `end` - клавиши Home и End
* `backspace`, `delete` - клавиши удаления
* `wheelup`, `wheeldown` - события прокрутки колеса мыши

## Отмена привязки сочетаний по умолчанию

Установите действие на `null` для отмены привязки сочетания по умолчанию:

{ "bindings": [ { "context": "Chat", "bindings": { "ctrl+s": null } } ] }


Это также работает для привязок аккордов. Отмена привязки каждого аккорда, который использует префикс, освобождает этот префикс для использования в качестве привязки с одной клавишей. Аккорд в любом активном контексте сохраняет свой префикс зарезервированным, поэтому вы должны отменить привязку каждого аккорда в контексте, который его определяет.

Claude Code привязывает следующие аккорды по умолчанию на префиксе `ctrl+x`, по контекстам:

* `Chat`: `ctrl+x ctrl+k`, `ctrl+x ctrl+e`, `ctrl+x enter`, `ctrl+x ctrl+a`, `ctrl+x ctrl+s`, `ctrl+x tab`, `ctrl+x ctrl+=`, `ctrl+x ctrl+-`, `ctrl+x ctrl+_`, `ctrl+x =` и `ctrl+x -`
* `Task`: `ctrl+x ctrl+b`
* `DiffPanel`: `ctrl+x b`
* `Pane`: `ctrl+x left`, `ctrl+x right`, `ctrl+x up`, `ctrl+x down` и `ctrl+x x`
* `PaneField`: `ctrl+x x`

Аккорд `ctrl+x enter` требует версии v2.1.247 или более поздней, `ctrl+x b`, `ctrl+x ctrl+a` и `ctrl+x tab` требуют версии v2.1.260 или более поздней, и `ctrl+x ctrl+s` требует версии v2.1.275 или более поздней.

Чтобы вернуть `ctrl+x` как привязку с одной клавишей, отмените привязку всех из них:

{ "bindings": [ { "context": "Task", "bindings": { "ctrl+x ctrl+b": null } }, { "context": "DiffPanel", "bindings": { "ctrl+x b": null } }, { "context": "Pane", "bindings": { "ctrl+x left": null, "ctrl+x right": null, "ctrl+x up": null, "ctrl+x down": null, "ctrl+x x": null } }, { "context": "PaneField", "bindings": { "ctrl+x x": null } }, { "context": "Chat", "bindings": { "ctrl+x ctrl+k": null, "ctrl+x ctrl+e": null, "ctrl+x enter": null, "ctrl+x ctrl+a": null, "ctrl+x ctrl+s": null, "ctrl+x tab": null, "ctrl+x ctrl+=": null, "ctrl+x ctrl+-": null, "ctrl+x ctrl+_": null, "ctrl+x =": null, "ctrl+x -": null, "ctrl+x": "chat:newline" } } ] }


Если вы отмените привязку некоторых, но не всех аккордов на префиксе, нажатие префикса всё ещё переводит в режим ожидания аккорда для оставшихся привязок.

## Зарезервированные сочетания клавиш

Эти сочетания клавиш не могут быть переназначены:

| Сочетание клавиш | Причина |
| :- | :- |
| Ctrl+C | Жёстко закодированное прерывание/отмена |
| Ctrl+D | Жёстко закодированный выход |
| Ctrl+M | Claude Code всегда получает его как Enter |
| Ctrl+\[ | Claude Code всегда получает его как Escape. В терминалах, использующих протокол клавиатуры Kitty, это требует версии 2.1.242 или более поздней |
| Ctrl+I | Claude Code всегда получает его как Tab |
| Ctrl+H | Отправляет байт ASCII backspace. [Как Claude Code читает его на Windows](https://code.claude.com/docs/ru/terminal-config.md#fix-backspace-deleting-a-whole-word-on-windows) зависит от вашего терминала и переменной окружения [`CLAUDE_CODE_BS_AS_CTRL_BACKSPACE`](https://code.claude.com/docs/ru/env-vars) |
| Caps Lock | Не передаётся в приложения терминала |

## Конфликты терминала

Некоторые сочетания клавиш могут конфликтовать с мультиплексорами терминала:

| Сочетание клавиш | Конфликт |
| :- | :- |
| Ctrl+B | Префикс tmux (нажмите дважды для отправки) |
| Ctrl+A | Префикс GNU screen |
| Ctrl+Z | Приостановка процесса Unix (SIGTSTP) |

## Текстовые поля

Если вы привяжете простую букву, цифру или пробел, вы все равно сможете вводить этот символ в текстовое поле внутри диалога или панели. Одно из таких полей — это ответ `Other` на вопрос, который задает Claude. Пока поле имеет фокус, печатаемая клавиша, которую вы нажимаете без Ctrl, Alt или Cmd, переходит в поле, и Claude Code не сопоставляет ее с вашими сочетаниями клавиш.

Эти клавиши все еще выполняют свои сочетания клавиш, пока поле имеет фокус:

* Клавиши, которые не вводят символ, такие как Enter, Escape, Tab и клавиши со стрелками
* Любая клавиша, нажатая с Ctrl, Alt или Cmd
* Второй нажим [chord](#chords), уже выполняемого

В основной подсказке Claude Code сопоставляет каждую клавишу с активными контекстами, такими как `Chat`, и вводит клавишу только когда никакое сочетание клавиш ее не перехватывает.

## Взаимодействие с режимом vim

Когда вы включаете режим vim с помощью настройки Editor mode в `/config`, сочетания клавиш и режим vim работают независимо:

* **Режим vim** обрабатывает ввод на уровне текстового ввода: движение курсора, режимы и движения
* **Сочетания клавиш** обрабатывают действия на уровне компонента, например переключение задач или отправку сообщения
* Клавиша Escape в режиме vim переключает режим INSERT в режим NORMAL; она не вызывает `chat:cancel`
* Большинство сочетаний Ctrl+клавиша проходят через режим vim в систему сочетаний клавиш
* Клавиши vim не переназначаются через файл сочетаний клавиш. Чтобы сопоставить двухклавишную последовательность в режиме INSERT, такую как `jj`, с клавишей Escape, используйте параметр [`vimInsertModeRemaps`](https://code.claude.com/docs/ru/interactive-mode#remap-insert-mode-key-sequences)
* В режиме vim NORMAL `?` показывает меню справки (поведение vim)
* В режиме vim NORMAL `/` открывает поиск по истории, то же самое, что Ctrl+R в стандартном режиме

В строке `Other` вопроса, который задает Claude, клавиша Escape в режиме vim не отменяет вопрос сразу. За исключением [режима программы чтения с экрана](https://code.claude.com/docs/ru/accessibility.md), строка переходит в режим INSERT каждый раз, когда вы переводите на нее фокус. Когда вы нажимаете Escape в строке `Other`, строка переключается в режим NORMAL или сбрасывает частично набранную команду vim, а вопрос остается открытым. Нажмите Escape еще раз в режиме NORMAL, чтобы отменить вопрос.

### Отмена вопроса одним нажатием клавиши

Чтобы отменять вопрос одним нажатием клавиши в режиме vim, назначьте другую клавишу действию `select:cancel` в контексте `Select`. Так можно отменить вопрос из строки `Other` в вопросе, где выбирается один вариант. В [режиме программы чтения с экрана](https://code.claude.com/docs/ru/accessibility.md) или в вопросе, где можно выбрать несколько вариантов, назначенная клавиша не отменяет вопрос, поэтому используйте для отмены Escape.

Выберите клавишу, которую вы нажимаете вместе с Ctrl или Alt. Одиночная буква или цифра [попадает в строку `Other`](#text-fields) и не доходит до ваших сочетаний клавиш. Например, чтобы назначить `Ctrl+Q`, добавьте следующее в `~/.claude/keybindings.json`:

{ "bindings": [ { "context": "Select", "bindings": { "ctrl+q": "select:cancel" } } ] }


После сохранения файла нажмите `Ctrl+Q` в строке `Other` вопроса, где выбирается один вариант. Вопрос закроется независимо от того, находится ли строка в режиме INSERT или NORMAL.

## Валидация

Claude Code проверяет ваши сочетания клавиш и записывает предупреждение в журнал отладки для:

* Неверного JSON
* Неправильно написанных модификаторов, таких как `ctl+k`. Claude Code игнорирует всю привязку. Исправьте модификатор, в этом примере на `ctrl+k`.
* Пробела рядом с `+` в строке клавиш, например `ctrl+ k`. Claude Code читает такую строку как [аккорд](#chords) из `ctrl+`, за которым следует `k`. Никакое нажатие клавиши не соответствует `ctrl+` само по себе, поэтому привязка никогда не срабатывает. Удалите пробел.
* Неверных имён контекстов
* Неизвестных имён действий, таких как опечатка зарегистрированного действия. Claude Code пропускает привязку и сохраняет любую привязку по умолчанию для этого ключа в силе.
* Конфликтов зарезервированных сочетаний
* Дублирующихся привязок в одном контексте

Запустите Claude Code с [`--debug`](https://code.claude.com/docs/ru/cli-reference#cli-flags) для просмотра деталей.
