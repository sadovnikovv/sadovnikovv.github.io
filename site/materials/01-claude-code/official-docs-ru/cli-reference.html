Если вы опечатаетесь в подкоманде, Claude Code предложит ближайшее совпадение и завершит работу без запуска сессии. Например, claude udpate выводит Did you mean claude update?.

claude --dangerously-skip-permissions daemon <subcommand> запускает подкоманду daemon, поэтому подкоманда работает, когда для claude задан псевдоним, включающий этот флаг. Только стоящий в начале --dangerously-skip-permissions или --allow-dangerously-skip-permissions направляет к daemon таким образом; если перед daemon стоит любой другой флаг, подкоманда не выполняется.

Флаги CLI #

Настройте поведение Claude Code с помощью этих флагов командной строки. claude --help не выводит каждый флаг, поэтому отсутствие флага в --help не означает, что он недоступен.

| Флаг | Описание | Пример | | :- | :- | :- | | --add-dir | Добавить дополнительные рабочие каталоги для Claude для чтения и редактирования файлов. Предоставляет доступ к файлам; Claude Code не обнаруживает большинство конфигурации .claude/ из этих каталогов. Проверяет, что каждый путь существует как каталог. Вы не можете добавить большинство сетевых путей, таких как \\server\share. Чтобы сохранить эти каталоги между сеансами, установите permissions.additionalDirectories в параметрах | claude --add-dir ../apps ../lib | | --advisor <model> | Включить инструмент advisor на стороне сервера для этого сеанса с псевдонимом модели fable, opus или sonnet, или полным ID модели. Имеет приоритет над параметром advisorModel для сеанса. fable требует доступ к Fable | claude --advisor opus | | --agent | Указать агента для текущего сеанса (переопределяет параметр agent) | claude --agent my-custom-agent | | --agents | Определить пользовательские subagents динамически через JSON. Принимает поля, указанные для subagents, определённых через CLI. С --print значение может быть вместо этого путём к файлу JSON, содержащему объект; форма файла требует Claude Code v2.1.281 или позже. Claude Code проверяет значение при запуске и выходит при недействительном; см. Invalid --agents configuration для сообщения и для флагов и переменной окружения, которые пропускают проверку. Проверка требует Claude Code v2.1.242 или позже | claude --agents '{"reviewer":{"description":"Reviews code","prompt":"You are a code reviewer"}}' | | --allow-dangerously-skip-permissions | Добавить bypassPermissions в цикл режима Shift+Tab без немедленной активации. См. режимы разрешения | claude --permission-mode plan --allow-dangerously-skip-permissions | | --allowedTools, --allowed-tools | Инструменты, которые выполняются без запроса разрешения, за исключением чтения из сетевых путей. Флаги системного приглашения #

Claude Code предоставляет пять флагов для настройки системного приглашения. Четыре устанавливают его текст, и с --system-prompt-snapshot вы контролируете, сохраняет ли беседа текст, с которым она началась. Все пять работают как в интерактивном, так и в неинтерактивном режимах.

| Флаг | Поведение | Пример | | :- | :- | :- | | --system-prompt | Заменяет весь запрос по умолчанию | claude --system-prompt "You are a Python expert" | | --system-prompt-file | Заменяет содержимым файла | claude --system-prompt-file ./prompts/review.txt | | --append-system-prompt | Добавляет к запросу по умолчанию | claude --append-system-prompt "Always use TypeScript" | | --append-system-prompt-file | Добавляет содержимое файла к запросу по умолчанию | claude --append-system-prompt-file ./style-rules.txt | | --system-prompt-snapshot | С off, перестраивает запрос при каждом запросе. С on, по умолчанию, повторно использует записанный запрос, где применяется запись | claude --append-system-prompt "Draft rules" --system-prompt-snapshot off |

Эти флаги можно комбинировать. Чтобы заменить промпт по умолчанию и при этом добавить собственный текст, передайте --append-system-prompt или --append-system-prompt-file вместе с --system-prompt или --system-prompt-file. В Claude Code v2.1.283 или новее можно также передать флаг вместе с его файловой формой, например --append-system-prompt с --append-system-prompt-file, и Claude Code использует оба.

Например, выполните следующую команду в оболочке, чтобы добавить и руководство по стилю из файла, и одну дополнительную инструкцию:

```bash theme={null} claude -p --append-system-prompt-file ./style.md --append-system-prompt "Always reply in French" "Summarize README.md"


Claude получает системный промпт по умолчанию, за которым следуют содержимое `style.md`, пустая строка и затем `Always reply in French`. Содержимое файла идёт первым, даже если вы передаёте `--append-system-prompt` перед `--append-system-prompt-file`.

Когда текст замены объединяет инструкции, которые одинаковы при каждом запуске, с контекстом, который изменяется при каждом запуске, добавьте строку, содержащую только `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` между инструкциями и контекстом. Claude Code разделяет приглашение в первой такой строке и удаляет эту строку, поэтому часть выше неё остаётся кэшированной, а часть ниже изменяется. Требует Claude Code v2.1.275 или позже. [Кэшировать статическую часть пользовательского приглашения](https://code.claude.com/docs/ru/agent-sdk/modifying-system-prompts.md#cache-the-static-part-of-a-custom-prompt) перечисляет конфигурации, где применяется разделение.

Выбирайте в зависимости от того, подходит ли стандартная идентичность Claude Code для вашей задачи. Используйте флаг добавления, когда Claude должен оставаться помощником по кодированию, который также следует вашим дополнительным правилам: инструкции для каждого вызова, форматирование вывода или контекст домена для скрипта `-p`. Добавление сохраняет стандартное руководство по инструментам, инструкции безопасности и соглашения кодирования, поэтому вы предоставляете только то, что отличается. Используйте флаг замены, когда поверхность, идентичность или модель разрешения отличаются от Claude Code, например некодирующий агент в конвейере, который не смотрит ни один человек. Замена удаляет весь стандартный запрос, включая руководство по инструментам и инструкции безопасности, поэтому вы берёте на себя ответственность за всё, что вашей задаче всё ещё нужно.

Для постоянных персон, которые вы можете переключать и делиться между проектом, используйте [стили вывода](https://code.claude.com/docs/ru/output-styles.md). Для соглашений проекта, которые Claude должен всегда соблюдать, используйте [CLAUDE.md](https://code.claude.com/docs/ru/memory.md). [Руководство Agent SDK по системным приглашениям](https://code.claude.com/docs/ru/agent-sdk/modifying-system-prompts.md#decide-on-a-starting-point) охватывает то же решение более подробно.

#### Флаги системного приглашения в возобновлённых беседах

По умолчанию Claude Code строит системное приглашение один раз, при первом запросе беседы, с текстом из любых флагов системного приглашения, применённых, и записывает его в сеанс. До компактирования беседы каждый более поздний запрос использует это записанное приглашение, включая после возврата к беседе с `--resume` или `--continue`. Если вы передаёте другой текст флага системного приглашения, или ничего, при этом более позднем запуске, он вступает в силу после компактирования беседы или когда вы начинаете новую беседу.

Вне [облачных сеансов](https://code.claude.com/docs/ru/cloud-environments.md), если вы запускаете Claude Code в [bare mode](https://code.claude.com/docs/ru/headless.md#start-faster-with-bare-mode), передав `--bare` или установив `CLAUDE_CODE_SIMPLE=1`, запись остаётся отключённой, если вы не передаёте `--system-prompt-snapshot on`. До v2.1.268 сеансы, которые не [получают флаги функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), включая сеансы на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry, перестраивали запрос при каждом запросе и `--system-prompt-snapshot` не имел эффекта.

Чтобы перестроить запрос при каждом запросе вместо этого, например, пока вы итерируете его формулировку через запуски `--continue`, передайте `--system-prompt-snapshot off`. До v2.1.265 передача любого из флагов системного приглашения также отключала запись, если вы не передавали `--system-prompt-snapshot on`.
