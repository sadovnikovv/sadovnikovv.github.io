Изучите директорию .claude #

Где Claude Code читает CLAUDE.md, settings.json, hooks, skills, commands, subagents, workflows, rules и auto memory. Изучите директорию .claude в вашем проекте и ~/.claude в вашей домашней директории.

Claude Code читает инструкции, параметры, skills, subagents и память из директории вашего проекта и из ~/.claude в вашей домашней директории. Зафиксируйте файлы проекта в git, чтобы поделиться ими с вашей командой; файлы в ~/.claude — это личная конфигурация, которая применяется ко всем вашим проектам.

На Windows ~/.claude разрешается в %USERPROFILE%\.claude. Если вы зададите CLAUDE_CONFIG_DIR, каждый путь ~/.claude на этой странице будет находиться в этом каталоге. То же относится к .claude.json, который в противном случае находится в ~/.claude.json.

Большинство пользователей редактируют только CLAUDE.md и settings.json. Если ваш репозиторий уже содержит AGENTS.md для других агентов кодирования, Claude Code может читать его вместо CLAUDE.md. Остальная часть директории опциональна: добавляйте skills, rules или subagents по мере необходимости.

Изучите директорию #

Нажимайте на файлы в дереве, чтобы увидеть, что каждый из них делает, когда он загружается и пример.

Configuration files

CLAUDE.md

When it loads: Загружается в контекст при запуске сессии

Инструкции для конкретного проекта, определяющие, как Claude работает в этом репозитории. Разместите здесь свои соглашения, часто используемые команды и архитектурный контекст.

.mcp.json

When it loads: В интерактивных сессиях MCP-серверы, которые вы одобрили, загружаются в начале сессии. Схемы инструментов по умолчанию откладываются и загружаются по требованию через поиск инструментов

Настраивает серверы Model Context Protocol (MCP), которые дают Claude доступ к внешним инструментам: базам данных, API, браузерам и многому другому. Этот файл содержит MCP-серверы уровня проекта, которые использует вся ваша команда. Личные серверы, которые вы хотите оставить только для себя, размещаются в ~/.claude.json.

.worktreeinclude

When it loads: Читается, когда Claude создаёт git worktree через --worktree, инструмент EnterWorktree или isolation: worktree субагента

Перечисляет игнорируемые git файлы, которые нужно скопировать из основного репозитория в каждый новый worktree. Worktree — это чистые checkout'ы, поэтому неотслеживаемые файлы, такие как .env, по умолчанию отсутствуют. Шаблоны здесь используют синтаксис .gitignore. Копируются только файлы, которые соответствуют шаблону и при этом игнорируются git.

.claude/

Настройки проекта, правила, скиллы, субагенты и другая конфигурация. Если вы используете git, добавляйте большинство этих файлов в коммиты, чтобы ваша команда имела к ним общий доступ, а личные файлы, такие как settings.local.json, не включайте в коммиты.

.claude/settings.json

When it loads: Читается при запуске сессии. Большинство изменений применяются к текущей сессии

Настройки, которые Claude Code применяет напрямую. Разрешения определяют, какие команды и инструменты может использовать Claude; хуки запускают ваши скрипты в определённые моменты сессии. В отличие от CLAUDE.md, который Claude читает как рекомендации, эти настройки применяются принудительно, независимо от того, следует ли им Claude.

В приоритете настроек этот файл стоит выше ~/.claude/settings.json и ниже .claude/settings.local.json, флага --settings и управляемых настроек. Для большинства ключей с одним значением, таких как model, Claude Code использует значение с наивысшим приоритетом. Большинство списков, таких как permissions.allow, объединяются между файлами.

.claude/settings.local.json

When it loads: Читается при запуске сессии. Большинство изменений применяются к текущей сессии

Ваши личные настройки для этого проекта. Тот же формат JSON, что и у settings.json; файл добавляется в gitignore, когда Claude Code сохраняет в него настройку.

В приоритете настроек этот файл стоит выше .claude/settings.json и ниже флага --settings и управляемых настроек. Для большинства ключей с одним значением, таких как model, Claude Code использует значение с наивысшим приоритетом. Большинство списков, таких как permissions.allow, объединяются между файлами.

.claude/rules/

When it loads: Правила без frontmatter paths: загружаются при запуске сессии. Правила с paths: загружаются, когда Claude читает, записывает или редактирует соответствующий файл

Инструкции проекта, разделённые на тематические файлы. Как и CLAUDE.md, правила — это рекомендации, которые Claude Code не применяет принудительно. Для принудительного поведения используйте хуки или разрешения.

.claude/skills/

When it loads: Вызывается с помощью /skill-name или когда Claude сопоставляет задачу со скиллом

Каждый скилл — это папка с файлом SKILL.md и любыми необходимыми вспомогательными файлами. По умолчанию скилл могут вызывать как вы, так и Claude. Используйте frontmatter, чтобы управлять этим: disable-model-invocation: true, чтобы Claude не мог самостоятельно вызвать скилл, такой как /deploy, или user-invocable: false, чтобы скилл мог вызывать только Claude.

.claude/commands/

When it loads: Вызывается с помощью /command-name или когда Claude сопоставляет задачу с командой

Содержит однофайловые команды: промпт, сохранённый как .claude/commands/deploy.md, запускается как /deploy. Для новой команды используйте скилл, который может включать справочную документацию, шаблоны или скрипты вместе с промптом.

.claude/output-styles/

When it loads: Читается при запуске в терминале, поэтому перезапустите Claude Code после добавления или редактирования стиля

Каждый Markdown-файл определяет стиль вывода — набор инструкций, который изменяет то, как работает Claude. Разместите стиль здесь, если ваша команда использует его совместно, например режим ревью, которым пользуются все. О том, как выбрать стиль, см. ~/.claude/output-styles/.

.claude/agents/

When it loads: Каждый субагент работает в собственном контекстном окне, когда вы или Claude его вызываете

Каждый Markdown-файл с frontmatter name и description определяет субагента с собственным системным промптом, доступом к инструментам и, при необходимости, собственной моделью. Полезно для параллельной работы или изолированных задач.

.claude/workflows/

When it loads: Загружается при запуске, когда рабочие процессы включены. Каждый сохранённый рабочий процесс запускается как команда /<name>

Каждый файл .js — это динамический рабочий процесс: скрипт, который среда выполнения исполняет для запуска и координации множества субагентов. Чтобы добавить его, попросите Claude написать рабочий процесс, затем выполните /workflows в сессии и сохраните его здесь.

.claude/agent-memory/

When it loads: Первые 200 строк файла MEMORY.md субагента, но не более 25 КБ, загружаются в его системный промпт при запуске субагента

Субагенты с memory: project во frontmatter получают здесь выделенную директорию памяти, пока включена автоматическая память. Каждый субагент читает и записывает собственный MEMORY.md, отдельный от автоматической памяти вашей основной сессии в ~/.claude/projects/.

.claude/agent-memory/<agent-name>/MEMORY.md

When it loads: Первые 200 строк, но не более 25 КБ, загружаются в системный промпт субагента при его запуске

Индекс заметок, сохранённых субагентом. Субагент сам создаёт и обновляет этот файл в том же формате, что и индекс вашей основной автоматической памяти.

~/.claude.json

When it loads: Читается при запуске сессии для получения ваших предпочтений и MCP-серверов. Claude Code записывает в него изменения, когда вы меняете глобальный параметр конфигурации в /config или доверяете папке проекта

Содержит данные учётной записи, решения о доверии для каждого проекта, ваши личные MCP-серверы и переключатели интерфейса.

~/.claude/

Глобальный аналог директории .claude/ вашего проекта. Файлы конфигурации в этой директории применяются к вам во всех проектах на этом компьютере.

~/.claude/CLAUDE.md

When it loads: Загружается при запуске сессии в каждом проекте на этом компьютере

Ваш глобальный файл инструкций. Загружается вместе с CLAUDE.md проекта. Если они противоречат друг другу, Claude может следовать любому из них. Храните в этом файле только предпочтения, которые применяются везде: стиль ответов, формат коммитов, личные соглашения.

~/.claude/settings.json

When it loads: Читается при запуске сессии. Большинство изменений применяются к текущей сессии

Тот же формат, что и у settings.json проекта: разрешения, хуки, модель и переменные окружения. Разместите здесь настройки, которые нужны вам в каждом проекте, например разрешающие правила, предпочитаемую модель или хук уведомлений.

В приоритете настроек этот файл стоит ниже файлов настроек проекта, флага --settings и управляемых настроек. Для большинства ключей с одним значением, таких как model, Claude Code использует значение с наивысшим приоритетом. Большинство списков, таких как permissions.allow, объединяются между файлами.

~/.claude/keybindings.json

When it loads: Читается при запуске сессии и перезагружается на лету при редактировании файла

Переназначайте сочетания клавиш в интерактивном CLI. Выполните /keybindings в сессии, чтобы создать или открыть этот файл. Прежде чем выбрать клавишу, проверьте зарезервированные сочетания клавиш.

~/.claude/themes/

When it loads: Читается при запуске сессии и перезагружается на лету при изменении файлов. Отображается в /theme

Каждый файл .json определяет пользовательскую цветовую тему: встроенный пресет base плюс карту overrides с цветовыми токенами. Выполните /theme в сессии, чтобы создать тему, или напишите JSON самостоятельно. При выборе пользовательской темы в качестве предпочитаемой темы сохраняется custom:<slug>.

~/.claude/projects/

When it loads: Файл memory/MEMORY.md текущего проекта загружается при запуске сессии, пока включена автоматическая память. Перечисленные в нём тематические файлы читаются по требованию

Содержит автоматическую память — заметки, которые Claude сохраняет между сессиями: вашу роль и предпочтения, ваши исправления, решения по проекту и то, где найти информацию за пределами проекта. Каждый проект получает собственную директорию памяти, привязанную к пути репозитория.

~/.claude/projects/<project>/memory/MEMORY.md

When it loads: Первые 200 строк, но не более 25 КБ, загружаются при запуске сессии, пока включена автоматическая память

Индекс, указывающий на тематические файлы с подробностями. Claude создаёт и обновляет этот файл в процессе работы. Вы можете редактировать или удалить его.

~/.claude/projects/<project>/memory/user_role.md

When it loads: Claude читает этот файл, когда возникает связанная задача

Пример тематического файла. Claude сохраняет каждое воспоминание в отдельном тематическом файле, выбирает имя файла и добавляет его в MEMORY.md.

~/.claude/rules/

When it loads: Правила без frontmatter paths: загружаются при запуске сессии. Правила с paths: загружаются, когда Claude читает, записывает или редактирует соответствующий файл

Тот же формат, что и у .claude/rules/ проекта, но применяется к каждому проекту на этом компьютере. Используйте для соглашений, которые нужны вам во всей вашей работе, например личного стиля кода или формата сообщений коммитов.

~/.claude/skills/

When it loads: Вызывается с помощью /skill-name или когда Claude сопоставляет задачу со скиллом

Скиллы, созданные вами для себя и доступные во всех ваших проектах на этом компьютере. Тот же формат, что и у .claude/skills/ проекта.

~/.claude/commands/

When it loads: Вызывается с помощью /command-name или когда Claude сопоставляет задачу с командой

Тот же формат, что и у .claude/commands/ проекта; доступны во всех ваших проектах на этом компьютере.

~/.claude/output-styles/

When it loads: Читается при запуске в терминале, поэтому перезапустите Claude Code после добавления или редактирования стиля

Каждый Markdown-файл определяет стиль вывода — набор инструкций, который изменяет то, как работает Claude. Используйте стиль, чтобы адаптировать Claude Code для задач за пределами программирования или добавить режимы обучения или ревью.

Выберите встроенный или пользовательский стиль с помощью /output-style или /config в сессии либо с помощью ключа outputStyle в настройках. Стили здесь доступны в каждом проекте на этом компьютере. Если у стиля проекта то же имя, Claude Code использует стиль проекта.

~/.claude/agents/

When it loads: Каждый субагент работает в собственном контекстном окне, когда вы или Claude его вызываете

Субагенты, определённые здесь, доступны во всех ваших проектах на этом компьютере. Тот же формат, что и у .claude/agents/ проекта.

~/.claude/workflows/

When it loads: Загружается при запуске, когда рабочие процессы включены. Каждый сохранённый рабочий процесс запускается как команда /<name>

Скрипты рабочих процессов, сохранённые здесь, доступны во всех ваших проектах на этом компьютере. Рабочий процесс проекта с тем же именем в .claude/workflows/ имеет приоритет.

~/.claude/agent-memory/

When it loads: Первые 200 строк файла MEMORY.md субагента, но не более 25 КБ, загружаются в его системный промпт при запуске субагента

Субагенты с memory: user во frontmatter хранят здесь знания, пока включена автоматическая память. Эти знания сохраняются во всех проектах. О памяти субагентов уровня проекта см. .claude/agent-memory/.

Что не показано #

Обозреватель охватывает файлы, которые вы создаёте и редактируете. Несколько связанных файлов находятся в других местах:

| Файл | Расположение | Назначение | | - | - | - | | managed-settings.json | Уровень системы, варьируется в зависимости от ОС | Настройки, применяемые предприятием, которые не могут переопределить ни ваши собственные файлы настроек, ни значения --settings, за исключением узких исключений. См. где сохранить файл и какой управляемый источник использует Claude Code. | | CLAUDE.local.md | Корень проекта | Ваши личные предпочтения для этого проекта, загружаемые вместе с CLAUDE.md. Создайте его вручную и добавьте в .gitignore. | | AGENTS.md | Корень проекта, .claude/ или любой каталог | Инструкции проекта, которые вы пишете для агентов AI кодирования. Claude Code может загрузить его вместо CLAUDE.md. | | Установленные плагины | ~/.claude/plugins | Клонированные маркетплейсы, установленные версии плагинов, запись установки installed_plugins.json и данные для каждого плагина, управляемые командами claude plugin. Плагины, синхронизированные с вашей учётной записью claude.ai, загружаются в ~/.claude/plugins/synced/. Для плагина, установленного из маркетплейса с источником command в режиме ссылки, Claude Code хранит здесь ссылки вместо копии, и файлы плагина остаются в каталоге, который выводит команда. Источник command требует Claude Code v2.1.229 или позже. Плагин, указанный относительным путём в маркетплейсе, который вы добавили из локального пути, также загружается на месте из своего исходного каталога, а не из копии в кэше. См. кэширование плагинов, чтобы узнать, как очищаются заброшенные версии. |

~/.claude также содержит данные, которые Claude Code записывает во время работы: стенограммы, историю подсказок, снимки файлов, кэши и журналы. См. данные приложения ниже.

Выберите правильный файл #

Различные виды настройки находятся в разных файлах. Используйте эту таблицу, чтобы найти, где должно быть изменение.

| Вы хотите | Редактировать | Область | Справочник | | :- | :- | :- | :- | | Дать Claude контекст проекта и соглашения | CLAUDE.md | проект или глобально | Memory | | Разрешить или заблокировать определённые вызовы инструментов | settings.json permissions или hooks | проект или глобально | Permissions, Hooks | | Запустить скрипт до или после вызовов инструментов | settings.json hooks | проект или глобально | Hooks | | Установить переменные окружения для сеанса | settings.json env | проект или глобально | Settings | | Сохранить личные переопределения вне git | settings.local.json | только проект | Области параметров | | Добавить подсказку или возможность, которую вы вызываете с /name | skills/<name>/SKILL.md | проект или глобально | Skills | | Определить специализированный subagent с его собственными инструментами | agents/*.md | проект или глобально | Subagents | | Организовать множество subagents из скрипта | workflows/*.js | проект или глобально | Dynamic workflows | | Подключить внешние инструменты через MCP | .mcp.json | только проект | MCP | | Изменить способ форматирования ответов Claude | output-styles/*.md | проект или глобально | Output styles |

Справочник файлов #

Эта таблица перечисляет каждый файл, который охватывает обозреватель. Файлы с областью действия проекта находятся в вашем репозитории под .claude/ (или в корне для CLAUDE.md, .mcp.json и .worktreeinclude). Файлы с глобальной областью действия находятся в ~/.claude/ и применяются ко всем проектам.

[!NOTE]

Несколько вещей могут переопределить то, что вы поместили в эти файлы:

  • Управляемые настройки, развёрнутые вашей организацией, имеют приоритет над всеми файлами настроек и значениями --settings, за исключением исключений, описанных в разделе «Приоритет настроек»
  • Флаги CLI, такие как --permission-mode или --settings, переопределяют settings.json для этого сеанса
  • Некоторые переменные окружения имеют приоритет над их эквивалентным параметром, но это варьируется: проверьте справочник переменных окружения для каждого из них

См. приоритет параметров для полного порядка.

Данные приложения #

Помимо конфигурации, которую вы создаёте сами, ~/.claude содержит данные, которые Claude Code записывает во время сессий. Эти файлы хранятся в открытом виде. Всё, что проходит через инструмент, записывается в транскрипт на диске: содержимое файлов, вывод команд, вставленный текст.

Транскрипт также может содержать то, что Claude Code отправляет модели вместе с вашими сообщениями:

  • Системный промпт
  • Определения инструментов
  • Параметры запросов
  • Загруженные им файлы инструкций, например CLAUDE.md

Файлы сессий в sessions/, автоматическая память и транскрипты Claude Desktop и Cowork подчиняются собственным правилам хранения:

  • sessions/: содержит по одному небольшому файлу на каждую запущенную сессию; используется для обнаружения параллельных сессий и сбоев. Этот каталог не входит в очистку по возрасту: Claude Code удаляет каждый файл при завершении его сессии и очищает остатки после сбоев при следующем запуске.
  • seed-admin/: временные git-каталоги, которые Claude Code создаёт при упаковке вашего репозитория для ultrareview или загрузки в облачную сессию. Когда загрузка завершается (или в одной из последующих сессий, если загрузка была прервана), Claude Code удаляет каталог этой загрузки, а сам seed-admin/ оставляет на месте.
  • Автоматическая память: очистка не удаляет файлы памяти в каталоге автоматической памяти проекта, projects/<project>/memory/. Claude Code удаляет этот каталог, только если он оставался пустым в течение всего срока хранения. До v2.1.228 очистка считала папки внутри каталога памяти данными сессий и могла удалять старые файлы в нём.
  • Транскрипты Claude Desktop и Cowork: Claude Code хранит транскрипт сессии, которую вы начали или последней продолжили в Claude Desktop или Cowork, независимо от её возраста. Чтобы задать для этих транскриптов ограничение по возрасту, установите desktopSessionCleanupPeriodDays. Требуется Claude Code v2.1.248 или новее; более ранние версии удаляют их по истечении cleanupPeriodDays.

Вместо этого Claude Code удаляет эти транскрипты по истечении cleanupPeriodDays, например, в следующих случаях:

  • Управляемые настройки задают cleanupPeriodDays
  • К вашим сессиям применяется конфигурация HIPAA

Claude Code пропускает очистку по возрасту в следующих случаях:

  • Режим bare: когда вы запускаете claude -p с --bare, Claude Code не выполняет очистку в этой сессии.
  • Приостановленная очистка: если Claude Code не может надёжно определить срок хранения, он приостанавливает очистку; событие retention_sweep перечисляет все конфигурации, которые её приостанавливают. Если причина — файл настроек, который не удаётся прочитать или разобрать, или ошибки настроек при заданных cleanupPeriodDays или desktopSessionCleanupPeriodDays, /status показывает предупреждение, пока вы не устраните причину.

Когда управляемые настройки задают cleanupPeriodDays, Claude Code выполняет очистку с управляемым значением, даже если в файле настроек с более низким приоритетом есть ошибки.

Чтобы убедиться, что компьютеры в вашей организации выполняют очистку с заданным вами сроком хранения, см. раздел Проверка очистки по сроку хранения.

Каталог черновиков сессии #

Каталог черновиков (scratchpad) — это отдельный для каждой сессии каталог, который Claude Code предоставляет Claude для временных файлов: промежуточных результатов, вспомогательных скриптов и черновиков, которым не место в вашем проекте. Когда Claude сообщает, что сохранил что-то «в scratchpad», файл находится именно там. Claude использует его вместо /tmp и может создавать, редактировать и читать в нём файлы без запроса разрешения.

Каталог черновиков находится во временном каталоге Claude Code, а не в ~/.claude. Путь для текущей сессии на вашей платформе:

  • macOS: /private/tmp/claude-<uid>/<project>/<session-id>/scratchpad/
  • Linux: /tmp/claude-<uid>/<project>/<session-id>/scratchpad/ или такой же путь внутри $TMPDIR, если он задан в вашей системе
  • Windows: %TEMP%\claude\<project>\<session-id>\scratchpad\

<project> — это путь к вашему рабочему каталогу, в котором каждый символ, кроме букв и цифр, заменён на -, например -Users-you-my-project. В Windows <project> — это 16-символьный хеш этой строки, например 73295dabccd14c56. В сессии приложения Desktop это может быть сама строка. Чтобы узнать точный путь, спросите Claude. Если вы задали CLAUDE_CODE_TMPDIR, всё дерево перемещается в этот каталог. Хуки получают путь текущей сессии в поле scratchpad_dir.

Файлы каталога черновиков хранятся столько же, сколько транскрипт сессии: очистка по сроку хранения удаляет каталог вместе с транскриптом, а claude purge не затрагивает временный каталог. Поскольку каталог находится в системном временном расположении, ваша операционная система также может очистить его, например при перезагрузке. Чтобы сохранить что-то, что Claude там записал, попросите Claude переместить это в ваш проект.

Каталог черновиков есть у сессии, только если выполнены все следующие условия:

  • Вы вошли с учётной записью claude.ai, а не с API-ключом
  • Сессия использует Anthropic API, а не Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry
  • enableArtifact не установлен в false

Файлы состояния, которые нужно сохранить #

В зависимости от используемых функций ~/.claude/ также содержит файлы, не перечисленные в таблицах раздела Данные приложения. Из них кэши и файлы блокировок можно безопасно удалять. Сохраните следующие файлы состояния:

  • .credentials.json: ваши учётные данные для входа
  • agent-memory/: память субагентов
  • jobs/ и daemon/: состояние фоновых сессий

Хранение в открытом виде #

Транскрипты и история не шифруются при хранении. Единственная защита — права доступа к файлам ОС. Если инструмент читает файл .env или команда выводит учётные данные, это значение записывается в projects/<project>/<session>.jsonl. Чтобы снизить риск:

  • Уменьшите cleanupPeriodDays, чтобы сократить срок хранения транскриптов в Claude Code
  • Установите desktopSessionCleanupPeriodDays, чтобы задать ограничение по возрасту и для транскриптов Claude Desktop и Cowork
  • Установите переменную окружения CLAUDE_CODE_SKIP_PROMPT_HISTORY, чтобы не записывать транскрипты и историю промптов в любом режиме. В неинтерактивном режиме вместо этого можно передать --no-session-persistence вместе с -p или установить persistSession: false в TypeScript Agent SDK; в Python SDK эквивалентного параметра нет.
  • Используйте правила разрешений, чтобы запретить чтение файлов с учётными данными

Очистка локальных данных #

Выполните claude purge, чтобы удалить состояние, которое Claude Code хранит для одного проекта. Команда удаляет:

  • Транскрипты и автоматическую память в projects/
  • Записи tasks/, debug/ и file-history/ для каждой сессии
  • Соответствующие строки промптов в history.jsonl
  • Запись проекта в ~/.claude.json

Изображения, которые вы вставляли или прикрепляли в сессиях проекта, и каталог черновиков каждой сессии хранятся во временном каталоге Claude Code, а не в ~/.claude, поэтому очистка их не удаляет. Очистка по сроку хранения по-прежнему удаляет изображения, когда они становятся старше cleanupPeriodDays; каталог черновиков очищенной сессии остаётся, пока вы его не удалите или ваша операционная система не очистит временный каталог.

Команда выводит полный план удаления и запрашивает подтверждение, прежде чем что-либо удалить.

До v2.1.288 команда называлась claude project purge.

План перечисляет каждый подходящий элемент и причину его включения:

Purge plan for /home/user/work/my-repo:

dir: /home/user/.claude/projects/-home-user-work-my-repo project transcripts (.jsonl) and memory/ config: projects["/home/user/work/my-repo"] project entry in ~/.claude.json (trust, history, MCP servers) filter: /home/user/.claude/history.jsonl 12 prompt(s) typed in this project

shell-snapshots/ are not project-scoped and will not be touched backups/ may still contain this project entry in old .claude.json snapshots (/home/user/.claude/backups); at most 5 are kept and they rotate out automatically Dry run: 3 item(s) would be deleted.


Удаление с одним запросом подтверждения:

claude purge ~/work/my-repo


Команда выводит тот же план, затем спрашивает `Delete 3 item(s) for /home/user/work/my-repo? This cannot be undone. [y/N]` и выполняет удаление, только если вы ответите `y`.

Не указывайте путь, чтобы выбрать проект из интерактивного списка.

Пропуск запроса подтверждения для использования в скриптах:

claude purge ~/work/my-repo --yes


Другие параметры:

* Передайте `--all` вместо пути, чтобы очистить состояние всех проектов сразу; в этом случае `history.jsonl` удаляется целиком, а не фильтруется.
* Передайте `-i`, чтобы пройти по плану удаления поэлементно.

Команда не трогает `shell-snapshots/` и `backups/`, поскольку они не привязаны к проекту, и предупреждает о них в выводе плана. Если кто-либо выполнял [`/heapdump`](https://code.claude.com/docs/ru/troubleshooting#high-cpu-or-memory-usage) на этом компьютере, удалите также записанные им файлы `.heapsnapshot`. Снимок кучи содержит весь диалог и все учётные данные, которые хранил процесс, и ни очистка по сроку хранения, ни команда purge его не затрагивают.

Вы также можете самостоятельно удалить любые из указанных выше путей данных приложения, за исключением [файлов состояния, которые нужно сохранить](#state-files-to-keep).

| Удалить | Что вы потеряете |
| - | - |
| `~/.claude/projects/` | Возобновление, продолжение и откат прошлых сессий, а также автоматическую память для всех проектов |
| `~/.claude/history.jsonl` | Вызов промптов по стрелке вверх, поиск по истории `Ctrl+R` и автодополнение shell-команд `!` |
| `~/.claude/paste-cache/` | Вставленный текст в вызванных промптах; см. [вставка большого содержимого](https://code.claude.com/docs/ru/terminal-config.md#paste-large-content) |
| `~/.claude/uploads/` | Вложения, на которые по пути ссылаются прошлые сессии [Remote Control](https://code.claude.com/docs/ru/remote-control.md) |
| `~/.claude/file-history/` | Восстановление чекпоинтов для прошлых сессий |
| `~/.claude/stats-cache.json` | Исторические итоги, отображаемые `/usage` |
| `~/.claude/usage-data/` | Прошлые отчёты [`/insights`](https://code.claude.com/docs/ru/costs#analyze-your-usage-patterns) и кэшированные данные анализа, использованные для их построения |
| `~/.claude/feedback-bundles/` | Архивы отзывов и отчётов об ошибках, которые вы ещё не отправили своей команде по работе с клиентами Anthropic |
| `~/.claude/feedback/drafts/` | [Отзывы, составленные Claude](https://code.claude.com/docs/ru/tools-reference.md#sendfeedback-tool-behavior), которые вы не отправили |
| `~/.claude/remote-settings.json` | Ничего. Загружается заново при следующем запуске. |
| `~/.claude/cache/changelog.md` | Ничего. Обновляется в фоновом режиме. |
| `~/.claude/policy-limits.json` | Ничего. Обновляется автоматически. |
| `~/.claude/tasks/` | Ваши [списки задач](https://code.claude.com/docs/ru/interactive-mode.md#task-list), включая те, что ещё используются |
| `~/.claude/skills/.trash/`, `~/.claude/plugins/.trash/` | Возможность восстановить [синхронизированные скиллы](https://code.claude.com/docs/ru/skills.md#how-synced-skills-behave) и [синхронизированные плагины](https://code.claude.com/docs/ru/plugins/loading.md#synced-plugins), удалённые Claude Code |
| `~/.claude/plugins/installed_plugins.set-aside.<date>.<hash>.json`, `~/.claude/plugins/installed_plugins.unreadable.<date>.<hash>.kept` | Копии записей об установке плагинов, которые Claude Code отбросил или не смог прочитать. Ничто их обратно не считывает |
| `~/.claude/debug/`, `~/.claude/plans/`, `~/.claude/session-env/`, `~/.claude/shell-snapshots/` | Ничего значимого для пользователя |
| `~/.claude/backups/` | Предыдущие копии, из которых можно [восстановить `~/.claude.json`](https://code.claude.com/docs/ru/errors#configuration-error-in-claude-json) |
| `~/.claude/todos/`, `~/.claude/statsig/`, `~/.claude/logs/`, `~/.claude/image-cache/` | Ничего. Устаревшие каталоги, которые текущие версии не записывают. |

Не удаляйте `~/.claude.json`, `~/.claude/settings.json` или `~/.claude/plugins/`: в них хранятся данные вашей учётной записи, ваши настройки и установленные плагины.
