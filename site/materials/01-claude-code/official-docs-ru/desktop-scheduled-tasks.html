Планирование повторяющихся задач в Claude Code Desktop #

Настройте запланированные задачи в Claude Code Desktop для автоматического запуска Claude на регулярной основе для ежедневных проверок кода, аудитов зависимостей или утренних брифингов.

Запланированные задачи автоматически запускают новый сеанс в выбранное вами время и с выбранной частотой. Используйте их для повторяющейся работы, такой как ежедневные проверки кода, проверки обновлений зависимостей или утренние брифинги, которые извлекают информацию из вашего календаря и входящих сообщений.

На странице Scheduled tasks приложения Desktop отображаются как локальные запланированные задачи, так и облачные запланированные задачи, ранее называвшиеся routines:

  • Локальная задача: запускается на вашем компьютере с прямым доступом к вашим файлам и инструментам, но срабатывает, только пока приложение открыто, а компьютер не находится в спящем режиме
  • Облачная задача: запускается даже при выключенном компьютере и может также срабатывать при вызовах API или событиях GitHub

На этой странице рассматриваются локальные запланированные задачи; для облачных запланированных задач и их параметров срабатывания см. Автоматизация работы с помощью запланированных задач.

[!NOTE]

Если в вашем приложении эта функция отображается под прежним названием, нажимайте Routines везде, где на этой странице указано Scheduled, и New routine там, где указано New task.

Сравнение параметров планирования #

Claude Code предлагает три способа планирования повторяющихся или одноразовых задач:

| | Cloud | Desktop | /loop | | :- | :- | :- | :- | | Запускается на | Cloud, управляется Anthropic по умолчанию | Ваша машина | Ваша машина | | Требует включенную машину | Нет | Да | Да | | Требует открытую сессию | Нет | Нет | Да | | Сохраняется после перезагрузки | Да | Да | Восстанавливается при --resume, с исключениями | | Доступ к локальным файлам | Нет (свежий клон) | Да | Да | | MCP servers | Connectors настроены для каждой задачи | Config files и connectors | Наследуется из сессии | | Запросы разрешений | Авторежим по умолчанию | Настраивается для каждой задачи | Наследуется из сессии | | Настраиваемое расписание | Да | Да | Да | | Минимальный интервал | 1 час | 1 минута, если его задаёт Claude, 1 час в формах | 1 минута |

[!TIP]

Используйте облачные задачи для работы, которая должна выполняться надежно без вашей машины. Используйте Desktop задачи, когда вам нужен доступ к локальным файлам и инструментам. Используйте /loop для быстрого опроса во время сессии.

[!NOTE]

По умолчанию локальные запланированные задачи запускаются в том состоянии, в котором находится ваш рабочий каталог, включая незафиксированные изменения. Чтобы вместо этого каждый запуск получал свой изолированный Git worktree, после создания задачи выберите Worktree в форме Edit этой задачи. Флажок доступен, если папка задачи является Git-репозиторием.

Создание запланированной задачи #

Для локальных запланированных задач требуется Claude Desktop версии 1.1.5368 или выше.

1. Откройте страницу запланированных задач

На вкладке Code нажмите Scheduled на боковой панели или в меню More боковой панели. Если на боковой панели вместо Scheduled отображается Routines, нажмите Routines, затем New routine и продолжите с раздела Полностраничная форма.

2. Создайте новую задачу

Нажмите New task, чтобы открыть диалоговое окно New scheduled task. Прежде чем продолжить, проверьте, не появился ли один из следующих экранов:

  • Если откроется меню с пунктами Create with Claude и Set up manually, выберите Set up manually, чтобы открыть диалоговое окно.
  • Если в верхней части диалогового окна находится Only on this computer, перейдите к разделу Диалоговое окно с Only on this computer вверху, прежде чем что-либо вводить.
  • Если откроется меню с пунктами Local и Cloud или вместо диалогового окна откроется целая страница, перейдите к разделу Полностраничная форма.

3. Задайте имя задачи

Введите имя в поле Name. Desktop преобразует его в нижний регистр kebab-case и использует как имя папки задачи на диске, поэтому имя должно быть уникальным среди ваших задач.

4. Напишите инструкции

В поле под именем введите, что должен делать Claude при запуске задачи.

5. Включите Only on this computer

Пока пропустите карточку Trigger и разверните расположенный под ней раздел Advanced settings. На вкладке General включите Only on this computer. Когда этот параметр включен, задача выполняется на вашем компьютере в локальной папке.

Если переключатель недоступен, уберите репозиторий или триггер события GitHub либо API, поскольку они превращают задачу в облачную запланированную задачу.

6. Выберите локальную папку

В строке Local folder выберите папку. Кнопка Create остается недоступной, пока вы ее не выберете.

7. Настройте расписание

Вернитесь к карточке Trigger и выберите пресет расписания.

8. Выберите режим разрешений и модель

На панели инструментов поля инструкций выберите режим разрешений и модель.

  • Режим разрешений: если оставить его без изменений, запуски будут использовать ваши настройки Claude Code.
  • Модель: если в меню модели указано Default · Set by admin и вы не выберете другую модель, запуски будут использовать модель, заданную вашей организацией в управляемых настройках. Запуск для наверстывания, который начинается при открытии приложения, может вместо этого использовать модель по умолчанию для вашей учетной записи во время выполнения.

9. Создайте задачу

Нажмите Create. Если вы еще не доверили эту папку, Desktop предложит вам доверить ее на этом этапе. Откроется страница с подробностями задачи.

Чтобы узнать, какой модели соответствует Default · Set by admin, нажмите Run now на странице с подробностями, чтобы сразу запустить задачу. Затем откройте сессию этого запуска: в строке под полем промпта отображается название модели.

На странице с подробностями нажмите значок карандаша, чтобы открыть форму Edit. В ней можно изменить Description, которое Desktop заполнил на основе ваших инструкций, выбрать Worktree или переключить расписание на Manual или Custom.

Вы также можете создать задачу, описав то, что вы хотите, в любой сессии. Например, "настрой ежедневное код-ревью, которое запускается каждое утро в 9:00" создает повторяющуюся задачу. Сообщение вроде "напомни мне завтра в 3 часа дня проверить развёртывание" создает одноразовую задачу, которая отключается после срабатывания.

Диалоговое окно с Only on this computer вверху #

Если при открытии диалогового окна New scheduled task в его верхней части находится Only on this computer, включите этот параметр, прежде чем что-либо вводить. Когда вы его включите, форма будет заменена отдельной пустой формой для локальной задачи.

Затем заполните поля локальной формы:

  • Name: введите имя, как описано в шагах по созданию запланированной задачи.
  • Description: введите описание. Кнопка Create остается недоступной, пока вы этого не сделаете.
  • Поле инструкций: введите, что должен делать Claude при запуске задачи. Выберите режим разрешений и модель в меню этого поля.
  • Working folder: выберите папку, в которой выполняется задача. Кнопка Create остается недоступной, пока вы ее не выберете.
  • Trigger: выберите расписание. Описание пресетов см. в разделе Параметры расписания.

Нажмите Create. Откроется страница с подробностями задачи.

Полностраничная форма #

Если откроется меню с пунктами Local и Cloud, выберите Local. Откроется страница с заголовком New local routine или New local scheduled task. Заполните ее поля:

  • Name: введите имя, уникальное среди ваших задач.
  • Description: введите описание.
  • Instructions: введите, что должен делать Claude при запуске задачи. В этом же поле выберите режим разрешений, модель и папку, в которой выполняется задача.
  • Schedule: выберите один из параметров расписания.

Если кнопка Create недоступна, наведите на нее указатель, чтобы увидеть, что еще требуется заполнить в форме. Нажмите Create, и откроется страница с подробностями задачи.

Параметры расписания #

Когда вы включаете Only on this computer в разделе Advanced settings, карточка Trigger предлагает варианты Hourly, Daily, Weekdays и Weekly. Чтобы получить Manual или Custom для такой задачи, откройте её форму Edit после создания. Эта форма, диалог с Only on this computer вверху и полностраничная форма предлагают следующие шесть вариантов:

  • Hourly: запускается каждый час
  • Daily: запускается каждый день в выбранное вами местное время
  • Weekdays: то же самое, что Daily, но пропускает субботу и воскресенье
  • Weekly: показывает средство выбора времени и средство выбора дня
  • Manual: без расписания, запускается только при нажатии Run now. Полезно для сохранения промпта, который вы запускаете по требованию
  • Custom: запускается по введённому вами cron-выражению, которое вычисляется в вашем местном времени, например 0 9 * * * для запуска в 9:00 каждый день. Указывайте дни недели и месяцы числами, так как их названия не принимаются. Воскресенье обозначается 0, а не 7. Форма отклоняет выражение, которое запускается чаще одного раза в час.

Вы также можете попросить Claude в любой сессии Desktop установить расписание. На Claude не распространяется ограничение в один запуск в час, и он может назначить однократный запуск на определённое время в будущем. Например, попросите "запускай набор тестов каждые 30 минут" или "в следующий понедельник в 9 утра подведи итоги по pull request, слитым с пятницы."

Как запускаются запланированные задачи #

Локальные запланированные задачи запускаются на вашем компьютере. Desktop проверяет расписание каждую минуту при открытом приложении и запускает новую сессию, когда наступает время задачи, независимо от любых открытых вами ручных сессий. Каждая задача получает небольшую задержку в несколько минут после запланированного времени для распределения трафика API. Задержка детерминирована: одна и та же задача всегда запускается с одинаковым смещением.

Задачи запускаются, только пока приложение Desktop работает, а компьютер не находится в спящем режиме. Если ваш компьютер находится в спящем режиме в запланированное время, запуск пропускается. Чтобы предотвратить переход в спящий режим при бездействии, включите Keep computer awake в Settings > Desktop app или Settings > This computer > System. Закрытие крышки ноутбука все равно переводит его в спящий режим.

[!NOTE]

Для задач, которые должны запускаться даже при выключенном компьютере или должны срабатывать при вызове API или событии GitHub, создайте вместо этого облачную запланированную задачу.

Поиск сессии запуска #

Чтобы открыть сессию, запущенную при выполнении задачи, перейдите на страницу сведений задачи и нажмите на строку этого запуска в списке History.

Список сессий на боковой панели также может отображать группу Scheduled с одной строкой для каждой задачи. Чтобы открыть сессию последнего запуска задачи, нажмите на строку задачи в этой группе. Чтобы отобразить группу, проверьте, какой у вас макет:

  • Текущий макет: откройте меню Group and sort, выберите Show, затем выберите Scheduled. Группа изначально свернута, поэтому нажмите на её заголовок, чтобы развернуть её.
  • Предыдущий макет: группа находится в списке сессий, и ничего включать не нужно

В сессии запуска, каким бы способом вы её ни открыли, вы можете увидеть, что сделал Claude, просмотреть изменения и ответить на запросы разрешений. Claude может редактировать файлы, запускать команды, создавать коммиты и открывать pull requests, так же как в сессии, которую вы запускаете сами.

Пропущенные запуски #

Когда приложение запускается или компьютер просыпается, Desktop проверяет, пропустила ли каждая задача какие-либо запуски за последние семь дней. Если да, Desktop запускает ровно один наверстывающий запуск для самого недавно пропущенного времени и отбрасывает все остальное. Ежедневная задача, которая пропустила шесть дней, запускается один раз при пробуждении. Desktop показывает уведомление при запуске наверстывающего запуска.

Помните об этом при написании промптов. Задача, запланированная на 9 утра, может запуститься в 11 вечера, если ваш компьютер спал весь день. Если время имеет значение, добавьте защиту в сам промпт, например: "Проверяй только сегодняшние коммиты. Если уже позже 5 вечера, пропусти проверку и опубликуй сводку того, что было пропущено."

Разрешения для запланированных задач #

Каждая задача имеет свой режим разрешений, который вы устанавливаете при создании или редактировании задачи. Разрешающие правила из ~/.claude/settings.json также применяются к сессиям запланированных задач. Если запуск завис на запросе разрешения, найдите сессию этого запуска и ответьте там на запрос.

Чтобы избежать зависания, нажмите Run now после создания задачи, следите за запросами разрешений и выберите "always allow" для каждого. Будущие запуски пропускают большинство этих запросов. Вы можете просмотреть и отозвать эти подтверждения со страницы деталей задачи. Если вы выберете "always allow" для редактирования файла в папке задачи, в режим Accept edits переключится только эта сессия, поэтому установите для задачи режим разрешений Accept edits.

Инструменты MCP, отмеченные requiresUserInteraction, запрашивают разрешение при каждом вызове и не предлагают опцию "always allow". Запуски, которые вызывают эти инструменты, зависают каждый раз.

Управление запланированными задачами #

На вкладке Code нажмите Scheduled на боковой панели, затем нажмите на задачу в списке, чтобы открыть ее страницу деталей. Отсюда вы можете:

  • Run now: запустить задачу немедленно без ожидания следующего запланированного времени
  • Status: переключаться между Active и Paused для приостановки или возобновления запланированных запусков без удаления задачи
  • Edit: изменить инструкции, расписание, папку или другие параметры
  • Review history: увидеть каждый прошлый запуск, включая пропущенные запуски. Наведите указатель на пропущенную запись, чтобы увидеть причину: ваш компьютер спал, предыдущий запуск все еще выполнялся, или другие запланированные задачи уже запускались. Нажмите Show more, чтобы загрузить более старые записи.
  • Review allowed permissions: увидеть и отозвать сохраненные одобрения инструментов для этой задачи из панели Always allowed
  • Delete: удалить задачу. Сессии, созданные задачей, архивируются, а не удаляются. Папка с файлом SKILL.md задачи остается на диске в ~/.claude/scheduled-tasks/<task-name>/ или в scheduled-tasks/<task-name>/ внутри CLAUDE_CONFIG_DIR, если вы задали эту переменную. Чтобы удалить эту папку, удалите ее самостоятельно.

Вы также можете управлять задачами, попросив Claude, позволив задаче обновлять саму себя или отредактировав промпт задачи на диске:

  • Попросить Claude: перечисляйте, создавайте, редактируйте и приостанавливайте задачи, попросив Claude в любой сессии Desktop. Например, «приостанови мою задачу dependency-audit» или «покажи мои запланированные задачи». Чтобы удалить задачу, используйте кнопку Delete на ее странице деталей.
  • Позволить задаче обновлять саму себя: чтобы задача могла изменить свое собственное расписание или промпт с помощью инструмента MCP update_scheduled_task, нажимайте Run now и подтверждайте вызов каждый раз
  • Отредактировать промпт на диске: откройте ~/.claude/scheduled-tasks/<task-name>/SKILL.md или scheduled-tasks/<task-name>/SKILL.md внутри CLAUDE_CONFIG_DIR, если вы задали эту переменную. Файл использует YAML frontmatter для name и description, с промптом в качестве тела. Изменения вступают в силу при следующем запуске. Расписание, папка и состояние включения не находятся в этом файле: измените их через форму Edit или попросите Claude.

Если локальная одноразовая задача, которая уже была выполнена, отсутствует на странице Scheduled tasks, нажмите значок сортировки над списком и выберите Include completed.

Связанные ресурсы #

  • Облачные запланированные задачи: запускайте задачи в облаке по расписанию, через вызов API или в ответ на события GitHub, даже при выключенном компьютере
  • Run prompts on a schedule: планирование с областью действия сеанса с /loop в CLI
  • Claude Code GitHub Actions: запускайте Claude по расписанию в CI вместо на вашем компьютере
  • Use Claude Code Desktop: полное руководство приложения Desktop
