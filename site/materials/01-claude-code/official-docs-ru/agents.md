# Запуск агентов параллельно

> Сравните способы, которыми Claude Code может выполнять несколько задач одновременно: подагенты, представление агентов, команды агентов, динамические рабочие процессы и проекты.

Claude Code имеет пять способов работать над несколькими задачами одновременно: [subagents](https://code.claude.com/docs/ru/sub-agents.md), [agent view](https://code.claude.com/docs/ru/agent-view.md), [agent teams](https://code.claude.com/docs/ru/agent-teams.md), [dynamic workflows](https://code.claude.com/docs/ru/workflows.md) и [projects](https://code.claude.com/docs/ru/claude-projects.md). Они отличаются тем, насколько вы остаетесь вовлечены, от управления каждым разговором самостоятельно до того, чтобы позволить Claude координировать группу работников, и тем, работает ли работа на вашей машине или в облаке.

| Подход | Что вы получаете | Используйте, когда |
| :- | :- | :- |
| [Subagents](https://code.claude.com/docs/ru/sub-agents.md) | Делегированные работники в одном сеансе, которые выполняют побочную задачу в своем собственном контексте и возвращают резюме | Побочная задача заполнит ваш основной разговор результатами поиска, логами или содержимым файлов, на которые вы больше не будете ссылаться |
| [Agent view](https://code.claude.com/docs/ru/agent-view.md) | Один экран для отправки и мониторинга сеансов, работающих в фоновом режиме, открывается с помощью `claude agents`. Предварительный просмотр исследования | У вас есть несколько независимых задач, и вы хотите их передать, проверить статус с первого взгляда и вмешаться только когда один из них нуждается в вас |
| [Agent teams](https://code.claude.com/docs/ru/agent-teams.md) | Несколько координируемых сеансов с общим списком задач и обменом сообщениями между агентами, управляемые лидером. Экспериментальная функция и отключена по умолчанию | Вы хотите, чтобы Claude разделил проект на части, назначил их и держал работников в синхронизации |
| [Projects](https://code.claude.com/docs/ru/claude-projects.md) | Один текущий диалог на claude.ai/code или в приложении для рабочего стола. Claude запускает параллельные сессии, называемые потоками, в облаке или, когда вы попросите, на вашем компьютере через Remote Control. Он дает каждой из них инструкции проекта и показывает вам, какие из них нуждаются в вас. Публичная бета-версия на Pro, Max и Ultra | Работа охватывает множество задач в течение дней или недель, должна продолжаться, когда ваша машина выключена, и вы предпочитаете описать ее один раз, чем отправлять и отслеживать каждую сессию |
| [Dynamic workflows](https://code.claude.com/docs/ru/workflows.md) | Скрипт, который запускает множество подагентов и проверяет их результаты, для работы, которая слишком велика для координации за один ход или которая требует более одного прохода | Задача слишком велика для нескольких подагентов, или вы хотите, чтобы результаты были проверены друг против друга: аудит всей кодовой базы, миграция 500 файлов, перепроверенное исследование или план, разработанный с нескольких углов |

В каждом подходе работники — это сеансы Claude. Чтобы задействовать другой инструмент, предоставьте его Claude как [MCP server](https://code.claude.com/docs/ru/mcp.md).

Три дополнительных инструмента поддерживают эту работу, не являясь способом запуска агентов:

* [Worktrees](https://code.claude.com/docs/ru/worktrees.md) дают каждой сессии отдельный git checkout, поэтому параллельные сессии редактируют каждая свою копию файлов. Используйте их для сессий, которые вы запускаете сами. Сессия, которую вы отправляете из agent view, [переходит в свой собственный worktree перед редактированием файлов](https://code.claude.com/docs/ru/agent-view.md#how-file-edits-are-isolated), и субагенты, которых вы порождаете, тоже могут получить каждый свой.
* [Cross-session messaging](https://code.claude.com/docs/ru/cross-session-messaging.md) позволяет Claude перечислять и отправлять сообщения вашим другим сеансам Claude Code на этой машине, на другой машине или [в облаке](https://code.claude.com/docs/ru/claude-code-on-the-web.md), поэтому сеансы, которые вы запускаете сами, могут передавать результаты и статус между собой.
* [`/batch`](https://code.claude.com/docs/ru/commands) — это [skill](https://code.claude.com/docs/ru/skills.md), который заставляет Claude разделить одно большое изменение на 5–30 worktree-изолированных подагентов. Это упакованное использование подагентов и worktrees, а не отдельный стиль координации.

Несколько других функций запускают Claude без того, чтобы вы управляли каждым шагом, но они решают другую проблему, чем разделение работы между агентами:

* [Фоновая bash команда](https://code.claude.com/docs/ru/interactive-mode.md#background-bash-commands) запускает одну команду оболочки без блокировки разговора. Она не порождает агента.
* [Разветвленный подагент](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation) — это подагент, который наследует полный контекст вашего разговора вместо того, чтобы начинать с нуля. Это способ порождения подагента, а не отдельная поверхность. Запустите его с помощью `/subtask`. Claude также порождает его сам, когда [режим fork](https://code.claude.com/docs/ru/sub-agents.md#turn-fork-mode-on-or-off) включен. Чтобы скопировать весь сеанс в новый [фоновый сеанс](https://code.claude.com/docs/ru/agent-view.md#from-inside-a-session), который работает параллельно с ним, используйте `/fork`. При [отключенном agent view](https://code.claude.com/docs/ru/agent-view.md#turn-off-agent-view) команда разветвленного подагента — это `/fork` вместо этого, и `/subtask` недоступна.
* [Облачная запланированная задача](https://code.claude.com/docs/ru/routines.md) запускает сессию по расписанию в облаке, а не параллельно на вашей машине.

> [!NOTE]
>
> Одновременный запуск нескольких сессий или субагентов многократно увеличивает расход токенов. Подробнее об использовании и ограничениях частоты запросов см. в разделе [Затраты](https://code.claude.com/docs/ru/costs.md).

## Выберите подход

Правильный подход зависит от того, кто координирует работу, нужны ли работникам общаться и редактируют ли они одни и те же файлы:

* **Кто координирует работу?**
  * Claude делегирует и собирает результаты в одном разговоре: [subagents](https://code.claude.com/docs/ru/sub-agents.md)
  * Вы передаёте независимые задачи и проверяете их позже: [agent view](https://code.claude.com/docs/ru/agent-view.md)
  * Claude планирует, назначает и контролирует группу работников: [agent teams](https://code.claude.com/docs/ru/agent-teams.md), экспериментальная функция, отключена по умолчанию
  * Скрипт держит координацию вместо пошагового суждения Claude: [dynamic workflows](https://code.claude.com/docs/ru/workflows.md). См. [как workflows сравниваются с subagents и skills](https://code.claude.com/docs/ru/workflows.md#when-to-use-a-workflow)
* **Нужны ли работникам общаться друг с другом?** Claude может передавать результаты с помощью [cross-session messaging](https://code.claude.com/docs/ru/cross-session-messaging.md) между сеансами, которые вы запускаете сами, включая сеансы, которые вы отправляете из agent view. Subagents сообщают результаты обратно в разговор, который их породил, а сеансы agent view сообщают результаты только вам. Товарищи по команде в команде агентов обмениваются сообщениями напрямую и, когда они [имеют инструменты Task](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability), делят список задач.
* **Затрагивают ли задачи одни и те же файлы?** Изолируйте работу с помощью [worktrees](https://code.claude.com/docs/ru/worktrees.md). Subagents и сеансы, которые вы запускаете сами, могут каждый использовать отдельный worktree. Agent teams не изолируют товарищей по команде в worktrees, поэтому [разделите работу](https://code.claude.com/docs/ru/agent-teams.md#avoid-file-conflicts) так, чтобы каждый товарищ по команде владел другим набором файлов.

## Проверьте выполняемую работу

Команда для проверки выполняемой работы зависит от того, какой подход вы использовали:

* Для фоновых сеансов `claude agents` открывает [agent view](https://code.claude.com/docs/ru/agent-view.md): один экран, показывающий каждый сеанс, его состояние и какие из них нуждаются в вашем вводе.
* Для субагентов в текущей сессии именованные фоновые субагенты появляются в typeahead @-упоминания с их статусом. Команда `/agents` выводит уведомление, указывающее на расположение файлов субагентов. Чтобы [создавать и редактировать пользовательские субагенты](https://code.claude.com/docs/ru/sub-agents.md#configure-subagents), попросите Claude или отредактируйте файлы напрямую. Несмотря на похожее имя, `/agents` отделена от `claude agents`.
* Для всего, что работает в фоновом режиме текущего сеанса, `/tasks` перечисляет каждый элемент и позволяет вам проверить, присоединиться или остановить его. Список также включает подагентов, которые завершили работу.
* Для динамических рабочих процессов `/workflows` перечисляет запущенные и завершенные запуски, фазу, в которой находится каждый из них, и сколько агентов завершило работу.

Для представления на рабочем столе всех ваших сеансов см. [параллельные сеансы в приложении для рабочего стола](https://code.claude.com/docs/ru/desktop.md#work-in-parallel-with-sessions).

## Узнайте больше

Каждое руководство ниже охватывает настройку и конфигурацию для одного подхода:

* [Create custom subagents](https://code.claude.com/docs/ru/sub-agents.md): определите переиспользуемых специалистов и контролируйте, какие инструменты они могут использовать.
* [Manage agents with agent view](https://code.claude.com/docs/ru/agent-view.md): отправляйте сеансы, наблюдайте их состояние и присоединяйтесь, когда один из них нуждается в вас.
* [Orchestrate agent teams](https://code.claude.com/docs/ru/agent-teams.md): установите лидера и товарищей по команде, назначьте задачи и проверьте их работу.
* [Orchestrate dynamic workflows](https://code.claude.com/docs/ru/workflows.md): запустите объединённый workflow или позвольте Claude написать один, который запускает множество subagents и проверяет их результаты друг против друга.
* [Run parallel sessions with worktrees](https://code.claude.com/docs/ru/worktrees.md): запустите Claude в изолированном checkout, контролируйте, что копируется, и очищайте после этого.
