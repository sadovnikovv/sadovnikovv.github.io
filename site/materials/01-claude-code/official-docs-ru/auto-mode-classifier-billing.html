Плата за запросы классификатора в авторежиме #

Разберитесь с уведомлением Claude Code о том, что эта сессия не подходит для бесплатных запросов классификатора в авторежиме: что это означает, почему оно появляется и что делать.

В режиме auto классификатор проверяет действия, такие как команды оболочки и сетевые запросы, перед их выполнением. Если включены проверки на стороне сервера, сервер выполняет эти проверки как часть собственных запросов модели сеанса, без взимания платы. Это уведомление означает, что проверки сервера не достигают вашего сеанса, поэтому Claude Code выполняет свои собственные запросы классификатора, и на вашем счёте эти запросы учитываются в использовании токенов:

```text theme={null} We're changing auto mode to no longer charge for classifier requests in Claude Code. However, this session isn't eligible.


Пока отображается это уведомление, Claude Code удерживает первое действие, которое он проверил бы таким образом, пока вы не ответите. Авторежим продолжает работать, а его запросы классификатора оплачиваются так же, как и раньше.

Наиболее частая причина — это LLM-шлюз или прокси между Claude Code и API, и когда Claude Code может идентифицировать его, уведомление называет его. Нажмите **Enter** для продолжения или см. [Сделать сессию подходящей](#make-the-session-eligible), чтобы предотвратить его появление в новых сессиях.

## Ответить на уведомление

Уведомление удерживает действие до тех пор, пока вы на него не ответите:

* **Enter** продолжает: удерживаемое действие и остальная часть сеанса используют собственные запросы классификатора Claude Code, которые выставляются счетом как использование токенов, как и раньше, и уведомление больше не появляется в этом сеансе. Когда уведомление назвало шлюз, его подтверждение предотвращает его повторное появление на этом компьютере в течение 24 часов. Когда оно этого не сделало, уведомление возвращается в следующий раз, когда сеанс переходит в режим отката.
* **Esc** или **Ctrl+C** отменяет: удерживаемое действие не выполняется и текущий ход останавливается, при этом сеанс остается в автоматическом режиме. Ничего не запоминается, поэтому уведомление появляется снова перед следующим проверяемым действием.

Чтобы вместо этого прекратить использование автоматического режима, переключите режимы разрешений с помощью `Shift+Tab` после того, как вы ответите.

В случаях, когда уведомление не может ждать ответа, Claude Code выводит тот же текст и сеанс продолжается в автоматическом режиме, если подтверждение шлюза на этом компьютере в течение последних 24 часов не отклонило его. В [неинтерактивном режиме](https://code.claude.com/docs/ru/headless.md) с `-p` он выводит текст в stderr, а в выводе `stream-json` он выдает сообщение предупреждения `system`, которое приложения Agent SDK могут читать из потока сообщений.

## Сделайте сеанс подходящим

Если шлюз не позволяет серверным проверкам авторежима доходить до ваших сессий и вы не управляете им, отправьте приведённые ниже требования администратору вашей компании или поставщику шлюза. Если [вышестоящий сервис принимает формат, который получает шлюз](https://code.claude.com/docs/ru/llm-gateway-protocol.md#format-mismatch-with-the-upstream), Claude Code ожидает, что шлюз будет пропускать запросы и ответы без изменений, как описано в [руководстве по совместимости шлюза](https://code.claude.com/docs/ru/llm-gateway-protocol.md#feature-pass-through):

* **Запросы**: чтобы пропустить проверки, шлюз пересылает без изменений и заголовок `anthropic-beta`, и поле тела `safeguards`, поскольку [они передаются в паре](https://code.claude.com/docs/ru/llm-gateway-protocol.md#beta-header-and-body-field-pairs). В [формате Amazon Bedrock InvokeModel](https://code.claude.com/docs/ru/llm-gateway-protocol.md#api-formats) шлюз вместо заголовка пересылает поле тела `anthropic_beta`.
* **Ответы**: шлюз возвращает ответы и события потоковой передачи, не удаляя поля и не переписывая идентификаторы использования инструментов. Чтобы пропустить результаты проверок, он сохраняет поле `safeguard_results`.

Как только ваш шлюз начнёт так работать, новые сессии снова будут использовать проверки сервера.

Если вы уже знаете, что ваш шлюз не может предоставить проверки сервера, скажите Claude Code не запрашивать их там, установив `CLAUDE_CODE_AUTO_MODE_SERVER` на `0` перед началом сеанса в вашей оболочке или в [ключе параметров `env`](https://code.claude.com/docs/ru/settings-reference#env):

export CLAUDE_CODE_AUTO_MODE_SERVER=0


Запросы классификатора затем всегда являются собственными Claude Code, выставляются счета таким же образом, и уведомление не появляется. При прямом подключении к API Anthropic переменная требует Claude Code v2.1.281 или более поздней версии. Установка `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` при неустановленном `CLAUDE_CODE_AUTO_MODE_SERVER` также отключает проверки сервера, за исключением случаев, описанных в разделе [Отключение предварительных возможностей](https://code.claude.com/docs/ru/llm-gateway-protocol.md#disable-pre-release-capabilities).

`CLAUDE_CODE_AUTO_MODE_SERVER` — это временный параметр и может быть удален в более поздней версии.

## Почему появляется уведомление

На планах Pro, Max, Ultra или Team вы никогда не увидите это уведомление. Чтобы узнать, какие сессии запрашивают у сервера проверки классификатора, см. [Проверка классификатора на стороне сервера](https://code.claude.com/docs/ru/permission-modes.md#server-side-classifier-review). Если вы видите уведомление, проверьте следующие распространённые причины:

* **На пути находится шлюз LLM или прокси**: тот, который удаляет или переписывает заголовки запроса, отбрасывает поля запроса, которые он не распознает, или редактирует ответы. Затем сервер никогда не получает запрос на проверки, или Claude Code никогда не получает результаты. Когда ваша конфигурация или ответы идентифицируют шлюз, уведомление его называет.
* **Проверки на стороне сервера еще не достигли вашей платформы, региона или учетных данных**: то, выполняет ли платформа или регион их, зависит от развертывания этой платформы. Если вы видите уведомление без шлюза или прокси на пути и оно продолжает появляться, это вероятная причина. Чтобы подтвердить, обратитесь в службу поддержки или администратора вашей компании, или сообщите об этом с помощью `/feedback`.

Чтобы проверить сеанс, находящийся в режиме auto, выполните `/status` в приглашении Claude Code: его строка **Auto mode server** читает `Enabled`, пока проверки сервера определяют действия сеанса, и `Disabled` после того, как сеанс вернулся в режим fallback.

Когда шлюз сокращает ответы или переписывает результаты в форму, которую Claude Code не может прочитать, вы получаете отказы без вердикта вместо этого уведомления; см. [Проверка классификатора на стороне сервера](https://code.claude.com/docs/ru/permission-modes.md#server-side-classifier-review).
