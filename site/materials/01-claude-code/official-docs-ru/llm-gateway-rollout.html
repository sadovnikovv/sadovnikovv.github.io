Развертывание LLM-шлюза для вашей организации #

Разверните продукт шлюза для Claude Code: настройте его для перенаправления того, что отправляет Claude Code, выдайте учетные данные разработчика, распределите конфигурацию через управляемые параметры и проверьте развертывание.

На этой странице администратор пройдет через развертывание LLM-шлюза для Claude Code. Предполагается, что у вас уже развернут продукт шлюза, соответствующий требованиям шлюза. Развертывание или эксплуатация какого-либо конкретного продукта здесь не рассматривается; разверните свой продукт, следуя документации его поставщика.

[!NOTE]

  • Чтобы подключить Claude Code на вашей машине к существующему шлюзу, см. Подключение Claude Code к LLM-шлюзу
  • Информацию о том, что Claude Code отправляет на шлюз и что перенаправлять, см. в справочнике протокола шлюза

Предварительные требования #

Для завершения развертывания вам потребуется:

  • Шлюз, развернутый на вашей инфраструктуре, обслуживающий HTTPS по точному адресу, который вы будете распределять разработчикам, а не адресу, который перенаправляет на него, и настроенный для маршрутизации имен моделей Claude к вашему поставщику
  • Учетные данные поставщика для шлюза для перенаправления:
  • Для Anthropic API: ключ API из Claude Console
  • Для облачного поставщика: облачные учетные данные с доступом к моделям. См. предварительные требования на странице Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry
  • Способ доставки файлов параметров на машины разработчиков, например MDM или управление конфигурацией
  • Если у вас его еще нет, как параметры достигают устройств сравнивает варианты

Требования к шлюзу #

Какой бы продукт ни предоставлял шлюз, он должен:

  • Принимать поддерживаемый формат API: один из форматов в таблице форматов API. Шаги развертывания ниже предполагают Anthropic Messages API в POST /v1/messages, который обслуживает большинство шлюзов
  • Потоковая передача ответов: передавать события, отправляемые сервером, по мере их поступления, включая пинги для поддержания соединения, вместо буферизации всего ответа; потоковая передача охватывает то, что буферизация или удаленные пинги нарушают
  • Маршрутизация имен моделей Claude: сопоставлять каждое имя, которое используют разработчики, с восходящей моделью. Claude Code отправляет имя модели, такое как claude-sonnet-4-6, в каждом запросе; в большинстве продуктов шлюза сопоставление представляет собой список моделей или таблицу маршрутизации в собственной конфигурации шлюза
  • Перенаправлять заголовки и тело без изменений: передавать anthropic-beta, anthropic-version и тело запроса в обоих направлениях; таблица сквозной передачи функций сопоставляет каждый с функцией, которая нарушается без него
  • Возвращать ошибки восходящего потока без изменений: автоматическое восстановление Claude Code соответствует формулировке ошибки, поэтому обертывание ошибок в собственный конверт шлюза нарушает его, если только сообщение конверта не содержит один из токенов capability_rejected:, которые шлюз Claude apps заменяет на формулировки ошибок облачных поставщиков
  • Исключить путь из проверки тела запроса WAF: подсказки Claude Code содержат исходный код и теги в стиле XML, которые соответствуют правилам тела для межсайтовых скриптов; WAF перед шлюзом возвращает 403 на реальных сеансах, в то время как короткие тестовые запросы проходят

Опционально обслуживайте GET /v1/models, чтобы Claude Code мог заполнить средство выбора модели из вашего шлюза с помощью обнаружения моделей.

Шаги развертывания #

Развертывание состоит из пяти шагов, каждый с контрольной точкой:

  1. Подтвердить маршрутизацию моделей шлюзом
  2. Выдать каждому разработчику учетные данные
  3. Протестировать Claude Code против шлюза
  4. Распределить базовый URL и учетные данные
  5. Проверить с машины разработчика

Шаги включают три различных учетных данных, и контрольные точки называют их по заполнителю, чтобы вы могли определить, какой из них виноват, когда что-то не работает:

| Учетные данные | Кто их держит | Заполнитель в контрольных точках | | :- | :- | :- | | Учетные данные поставщика | Шлюз, который перенаправляет их восходящему поставщику | Настроены на шлюзе; никогда не появляются в командах клиента | | Административные учетные данные шлюза | Вы, если ваш продукт шлюза выдает их для своего интерфейса администратора или тестирования | <gateway-key> | | Ключ разработчика | Каждый разработчик, выданный шлюзом в Выдать учетные данные разработчика | <developer-key> |

Подтвердить маршрутизацию моделей шлюзом #

Ваш шлюз уже должен быть настроен с учетными данными вашего поставщика, прослушивающий на его базовом URL и перенаправляющий запросы к API вашего поставщика. Протестируйте, что путь работает от конца к концу с минимальным запросом, подставив два значения из вашего развертывания:

  • <gateway-key> — это любые учетные данные, которые позволяют вам вызывать шлюз прямо сейчас: административный ключ, тестовый ключ или ваш собственный ключ разработчика, если вы уже выдали его. Не каждый продукт шлюза имеет отдельные административные учетные данные; если у вас их нет, сначала выдайте себе ключ разработчика в Выдать учетные данные разработчика
  • model — это имя модели Claude, которое ваш шлюз настроен маршрутизировать. В примере используется claude-sonnet-4-6; подставьте имя, которое вы настроили

[tab] Bash или Zsh

```bash theme={null} curl -X POST "https://llm-gateway.example.com/v1/messages" \ -H "Authorization: Bearer <gateway-key>" \ -H "anthropic-version: 2023-06-01" \ -H "content-type: application/json" \ -d '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [{"role": "user", "content": "."}]}'

[tab] PowerShell

```powershell theme={null} Invoke-RestMethod -Method Post -Uri "https://llm-gateway.example.com/v1/messages" ` -Headers @{ "Authorization" = "Bearer <gateway-key>"; "anthropic-version" = "2023-06-01" } ` -ContentType "application/json" ` -Body '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [{"role": "user", "content": "."}]}'

Контрольная точка: 200 с полем content означает, что шлюз достиг поставщика с этим именем модели. 404 означает, что это имя не маршрутизируется на шлюзе; 401 от поставщика означает, что учетные данные поставщика шлюза неправильные.

Повторите запрос один раз для каждого имени модели Claude в конфигурации маршрутизации вашего шлюза. Имя, которое шлюз не маршрутизирует, возвращает 404 любому разработчику, который его выбирает, поэтому протестируйте каждое имя перед развертыванием.

[!NOTE]

Избегайте обслуживания шлюза за перенаправлением. Перенаправление может отбросить тело запроса или удалить заголовок учетных данных на запросах вывода, и обнаружение моделей рассматривает любое перенаправление как сбой, поэтому учетные данные не могут утечь на цель перенаправления.

Выдать учетные данные разработчика #

Каждому разработчику нужен свой собственный ключ шлюза для аутентификации. Создайте учетные данные для каждого разработчика на шлюзе, следуя документации управления учетными данными вашего продукта.

Подтвердите, что недавно выданный ключ работает против шлюза с тем же запросом, что и Подтвердить маршрутизацию моделей шлюзом, заменив <gateway-key> на новый <developer-key>:

[tab] Bash или Zsh

```bash theme={null} curl -X POST "https://llm-gateway.example.com/v1/messages" \ -H "Authorization: Bearer <developer-key>" \ -H "anthropic-version: 2023-06-01" \ -H "content-type: application/json" \ -d '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [{"role": "user", "content": "."}]}'

[tab] PowerShell

```powershell theme={null} Invoke-RestMethod -Method Post -Uri "https://llm-gateway.example.com/v1/messages" ` -Headers @{ "Authorization" = "Bearer <developer-key>"; "anthropic-version" = "2023-06-01" } ` -ContentType "application/json" ` -Body '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [{"role": "user", "content": "."}]}'

Контрольная точка: 200 с полем content означает, что ключ разработчика достигает шлюза и шлюз его перенаправляет. 401 здесь, когда предыдущий шаг был успешным, означает, что ключ разработчика неправильный или еще не вступил в силу на шлюзе.

Выдача одного ключа на разработчика вместо общего ключа — это то, что делает возможной атрибуцию использования для каждого разработчика и отдельное удаление. Переменная окружения, которая содержит ключ, зависит от того, какой заголовок читает шлюз. Для шлюза, который проверяет учетные данные в заголовке Authorization: Bearer, разработчики устанавливают свой ключ в ANTHROPIC_AUTH_TOKEN. Для шлюза, который читает ключи из заголовка x-api-key, разработчики вместо этого устанавливают ANTHROPIC_API_KEY; таблица учетных данных охватывает сопоставление.

Протестировать Claude Code против шлюза #

Запустите Claude Code через шлюз самостоятельно перед распределением чего-либо, используя ту же конфигурацию, которую развертывание будет доставлять по всему парку. Введите их непосредственно в терминал, а не в файл .env или файл параметров; они действуют только для этого сеанса терминала, поэтому закрытие его возвращает вашу машину в нормальное состояние. Используйте ANTHROPIC_API_KEY вместо ANTHROPIC_AUTH_TOKEN, если ваш шлюз читает заголовок x-api-key:

[tab] Bash или Zsh

```bash theme={null} export ANTHROPIC_BASE_URL=https://llm-gateway.example.com export ANTHROPIC_AUTH_TOKEN="<developer-key>"

[tab] PowerShell

```powershell theme={null} $env:ANTHROPIC_BASE_URL = "https://llm-gateway.example.com" $env:ANTHROPIC_AUTH_TOKEN = "<developer-key>"

Затем отправьте одноразовую подсказку через шлюз:

```bash theme={null} claude -p "Reply with one word: connected"


**Контрольная точка**: промпт возвращает ответ, и запрос появляется в логе шлюза как `POST` к пути `/v1/messages` со статусом `200`. Claude Code добавляет строку запроса, такую как `?beta=true`, поэтому сопоставляйте по пути, а не по полному URL. Проверьте сообщение об ошибке:

* `Not logged in`: проверьте лог шлюза. Если он пуст, никакие учётные данные не достигли сессии и никакой запрос не покинул машину; повторно запустите экспорты в оболочке, из которой вы тестируете. Если он показывает `401` от шлюза с упоминанием `x-api-key`, шлюз ожидает ключи в этом заголовке; переключитесь на `ANTHROPIC_API_KEY`. Если он показывает `401` от `api.anthropic.com` или эндпоинта вашего поставщика, исправьте учётные данные поставщика, которые держит шлюз
* `Failed to authenticate. API Error: 401` означает, что учетные данные были отправлены и отклонены, и журнал шлюза говорит где: `401`, называющий `api.anthropic.com` или конечную точку вашего поставщика, означает, что шлюз достиг восходящего потока, но его учетные данные поставщика были отклонены, поэтому ключ разработчика работал и учетные данные поставщика, которые держит шлюз, неправильные или заполнитель

Неправильный или недостижимый базовый URL производит другой симптом: Claude Code [повторяет попытку подключения с отступом](https://code.claude.com/docs/ru/errors.md#automatic-retries) и может сидеть без вывода в течение нескольких минут перед сообщением об ошибке. Если команда кажется зависшей, проверьте журнал шлюза вместо ожидания; отсутствие поступающего запроса означает, что `ANTHROPIC_BASE_URL` не указывает на шлюз.

### Распределить конфигурацию

Каждой машине разработчика нужны адрес шлюза и учетные данные. Вы можете распределять их централизованно через [управляемые параметры](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), чтобы разработчики ничего не настраивали, или передать разработчикам значения для самостоятельной установки.

#### Что распределять

Один и тот же набор переменных применяется независимо от выбранного пути. Большинство развертываний требуют только `ANTHROPIC_BASE_URL` и учетные данные; включите условные строки, когда ваша настройка шлюза требует их.

| Переменная или параметр | Что она делает | Включить когда |
| :- | :- | :- |
| `ANTHROPIC_BASE_URL` | Отправляет запросы API Claude Code на шлюз вместо `api.anthropic.com` | Всегда |
| `apiKeyHelper`, или учетные данные в `ANTHROPIC_AUTH_TOKEN` или `ANTHROPIC_API_KEY` | Аутентифицирует каждый запрос к шлюзу. Помощник запускает команду для получения ключа; переменные содержат статический ключ, отправляемый как `Authorization: Bearer` и `x-api-key` соответственно | Всегда; один из трех |
| `ANTHROPIC_CUSTOM_HEADERS` | Добавляет дополнительные HTTP-заголовки к каждому запросу API | Ваш шлюз требует заголовок клиента или маршрутизации на каждом запросе |
| `CLAUDE_CODE_GATEWAY_HINT_HEADERS` | Отправляет [заголовки подсказок шлюза](https://code.claude.com/docs/ru/llm-gateway-protocol.md#gateway-hint-headers), которые классифицируют каждый запрос для решений маршрутизации и планирования на шлюзе. Требует Claude Code v2.1.273 или позже | Ваш шлюз читает заголовки подсказок |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | Запрашивает `/v1/models` шлюза при запуске и добавляет возвращаемые имена в средство выбора `/model` | Ваш шлюз обслуживает `/v1/models` и вы хотите, чтобы средства выбора разработчиков были заполнены из него |
| `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` | Останавливает отправку Claude Code заголовков и полей тела предварительного выпуска. [Отключить предварительные возможности](https://code.claude.com/docs/ru/llm-gateway-protocol.md#disable-pre-release-capabilities) охватывает точный объем | Ваш шлюз перенаправляет на восходящий Amazon Bedrock или Google Cloud's Agent Platform, который отклоняет поля бета-версии. См. [Требования к шлюзу](#gateway-requirements) |
| `CLAUDE_CODE_SKIP_FAST_MODE_NETWORK_ERRORS` или `CLAUDE_CODE_SKIP_FAST_MODE_ORG_CHECK` | Восстанавливает [быстрый режим](https://code.claude.com/docs/ru/fast-mode.md), когда его проверка доступности, которая вызывает `api.anthropic.com` напрямую, а не следует `ANTHROPIC_BASE_URL`, не работает, перехватывается или пропускается из-за отсутствия учетных данных Anthropic | Ваша организация использует быстрый режим, и разработчики аутентифицируются только с `ANTHROPIC_AUTH_TOKEN`, с ключом, выданным шлюзом в `ANTHROPIC_API_KEY` или из `apiKeyHelper`, или ваша сеть блокирует или перехватывает прямые запросы к `api.anthropic.com`; [использовать быстрый режим за прокси и LLM шлюзами](https://code.claude.com/docs/ru/fast-mode.md#use-fast-mode-behind-proxies-and-llm-gateways) охватывает, какая из двух переменных соответствует вашей конфигурации |
| `ANTHROPIC_MODEL` или [`ANTHROPIC_DEFAULT_HAIKU_MODEL`](https://code.claude.com/docs/ru/model-config) | Задают, какое имя модели Claude Code запрашивает для основной сессии и для фонового трафика | Ваш шлюз маршрутизирует имена моделей, которые не совпадают со значениями по умолчанию Claude Code, или вы направляете [фоновую функциональность](https://code.claude.com/docs/ru/model-config.md#environment-variables) на другую модель. Маршрутизируйте как имена переопределений, так и встроенные идентификаторы моделей, которые Claude Code запрашивает, когда переопределение не задано, поскольку некоторые фоновые подвызовы запрашивают встроенный идентификатор независимо от переопределения |
| `ANTHROPIC_BEDROCK_BASE_URL`, `ANTHROPIC_VERTEX_BASE_URL`, `ANTHROPIC_FOUNDRY_BASE_URL` или `ANTHROPIC_AWS_BASE_URL` с [переменными для этого поставщика](https://code.claude.com/docs/ru/llm-gateway-connect.md#route-to-a-cloud-provider-through-a-gateway) | Указать Claude Code на шлюз через базовый URL, специфичный для поставщика. Amazon Bedrock и Google Cloud's Agent Platform также переключаются на собственный формат запроса этих поставщиков | Ваш шлюз находится перед Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry или Claude Platform на AWS; см. [Форматы API](https://code.claude.com/docs/ru/llm-gateway-protocol.md#api-formats) |

#### Распределить через управляемые параметры

Доставляйте переменные через блок `env` [файла управляемых параметров](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), отправляемого MDM, политикой реестра или управлением конфигурацией:

{ "env": { "ANTHROPIC_BASE_URL": "https://llm-gateway.example.com" }, "apiKeyHelper": "/usr/local/bin/get-gateway-key" }


Добавьте условные переменные из таблицы в тот же блок `env`. Управляемый `ANTHROPIC_BASE_URL` применяется и не может быть переопределен экспортом оболочки разработчика, так как Claude Code применяет его над переменными процесса и параметрами с более низким приоритетом.

Не включайте `forceLoginMethod`, `forceLoginOrgUUID` или `forceLoginGatewayUrl` в управляемые параметры вместе с учетными данными шлюза. `forceLoginMethod` или `forceLoginOrgUUID`, с любым значением, блокирует `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` и `apiKeyHelper` при запуске, и разработчики не могут продолжить. Они видят `This machine's managed settings require a first-party login` или [`Administrator policy requires a Cloud gateway sign-in`](https://code.claude.com/docs/ru/errors#administrator-policy-requires-a-cloud-gateway-sign-in) когда файл устанавливает `forceLoginMethod` на `"gateway"` или устанавливает `forceLoginGatewayUrl`.

[Доставка управляемых параметров на сервере](https://code.claude.com/docs/ru/server-managed-settings.md#platform-availability) требует прямого подключения к `api.anthropic.com`, поэтому она не достигает сеансов, маршрутизируемых через шлюз. Развертывания шлюза используют этот путь управляемых параметров на основе файлов, который применяет те же ключи.

Для учетных данных распределите одну команду [`apiKeyHelper`](https://code.claude.com/docs/ru/llm-gateway-connect#rotate-credentials-with-apikeyhelper) в файле управляемых параметров, как показано выше; команда аутентифицируется в вашем хранилище секретов как локальный разработчик, поэтому каждая машина получает свой собственный ключ. Альтернативно, доставляйте каждому разработчику его ключ через ваш существующий процесс секретов и попросите их установить `ANTHROPIC_AUTH_TOKEN` самостоятельно.

Некоторые окружения требуют отдельной доставки:

* Настольное приложение читает маршрутизацию шлюза из своей конфигурации вывода третьей стороны, не из управляемых параметров; разверните этот файл через MDM вместе с управляемыми параметрами, чтобы сеансы рабочего стола также маршрутизировались через шлюз. См. [документацию конфигурации рабочего стола](https://claude.com/docs/third-party/claude-desktop/configuration) и [документацию шлюза рабочего стола](https://claude.com/docs/third-party/claude-desktop/gateway)
* Бегуны CI нуждаются в `ANTHROPIC_BASE_URL` и учетных данных, установленных в [окружении бегуна](https://code.claude.com/docs/ru/llm-gateway-connect.md#configure-each-surface)
* WSL на управляемых машинах Windows читает управляемые параметры Windows только когда [`wslInheritsWindowsSettings`](https://code.claude.com/docs/ru/settings-reference#wslinheritswindowssettings) имеет значение `true`

#### Конфигурация HIPAA за шлюзом

Сессии, проходящие через шлюз, не подходят для конфигурации HIPAA. В разделе [Проверка того, как разработчики входят и подключаются](https://code.claude.com/docs/ru/hipaa-setup.md#check-how-developers-sign-in-and-connect) перечислены способы входа и подключения, которые подходят.

Чтобы ограничить функции для таких сессий в файле управляемых настроек, используйте ключи из раздела [Сопоставление путей исходящего трафика с управляемыми элементами контроля и событиями](https://code.claude.com/docs/ru/monitoring-usage.md#map-egress-paths-to-managed-controls-and-events). Эти ключи не делают сессию подходящей для конфигурации HIPAA и не охватывают всё, что изменяет эта конфигурация. Например:

* **Облачные сессии**: никакой управляемый ключ их не отключает. См. [Элементы управления в консоли администратора](https://code.claude.com/docs/ru/desktop.md#admin-console-controls)
* **Учётные данные Anthropic в дочерних процессах**: конфигурация [удаляет их](https://code.claude.com/docs/ru/hipaa-setup.md#anthropic-credentials-in-commands-hooks-and-mcp-servers) из процессов, которые запускает Claude Code, и ни один ключ настроек не делает только это

Не используйте `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` вместо этих ключей. Она отключает некоторые из этих функций, но также отключает автообновление и оставляет WebFetch включённым.

#### Передать разработчикам значения для самостоятельной установки

Если у вас нет распределения управляемых параметров, отправьте каждому разработчику то, что ему нужно, чтобы следовать [странице подключения](https://code.claude.com/docs/ru/llm-gateway-connect.md#configure-claude-code-yourself):

* URL шлюза
* Их личные учетные данные
* **Какую переменную поместить учетные данные в**: `ANTHROPIC_AUTH_TOKEN` для шлюза с токеном-носителем или `ANTHROPIC_API_KEY` для шлюза `x-api-key`. Сообщение разработчикам, какой из них, экономит им метод проб и ошибок, описанный на [странице подключения](https://code.claude.com/docs/ru/llm-gateway-connect.md#set-the-credential-variable)
* Любые условные переменные из [таблицы Что распределять](#what-to-distribute), с их значениями

[Страница подключения](https://code.claude.com/docs/ru/llm-gateway-connect.md#configure-claude-code-yourself) проводит разработчиков через установку каждой.

**Контрольная точка**: на машине разработчика `claude` запускает сеанс без отображения экрана входа, так как распределенные учетные данные удовлетворяют аутентификацию. Затем запустите `/status` и откройте вкладку **Status**: строка `Anthropic base URL` показывает адрес шлюза, а для управляемого распределения строка `Setting sources` включает управляемые параметры. Экран входа или отсутствующая строка `Anthropic base URL` означает, что конфигурация не достигла машины.

### Проверить развертывание

Подтвердите, что все работает с машины разработчика, а не хоста шлюза, чтобы тест охватывал сетевой путь, который используют разработчики. Отправьте потоковый запрос, который проверяет конечную точку, сквозную передачу потока и маршрутизацию модели одновременно:

> [tab] Bash или Zsh
>
> ```bash theme={null}
> curl -N -X POST "https://llm-gateway.example.com/v1/messages" \
>   -H "Authorization: Bearer <developer-key>" \
>   -H "anthropic-version: 2023-06-01" \
>   -H "content-type: application/json" \
>   -d '{"model": "claude-sonnet-4-6", "max_tokens": 16, "stream": true, "messages": [{"role": "user", "content": "count to 3"}]}'
> ```

> [tab] PowerShell
>
> ```powershell theme={null}
> $body = '{"model": "claude-sonnet-4-6", "max_tokens": 16, "stream": true, "messages": [{"role": "user", "content": "count to 3"}]}'
> $body | curl.exe -N -X POST "https://llm-gateway.example.com/v1/messages" `
>   -H "Authorization: Bearer <developer-key>" `
>   -H "anthropic-version: 2023-06-01" `
>   -H "content-type: application/json" `
>   --data-binary '@-'
> ```

Вы должны видеть строки `data:`, поступающие постепенно. Весь ответ, поступающий сразу после паузы, означает, что шлюз буферизирует, что замораживает Claude Code; `404` означает, что имя модели не маршрутизируется. Повторите для каждого имени модели.

Затем запустите `claude`, отправьте сообщение и сопоставьте то, что видите:

* Экран входа или `Not logged in` без новых записей в логе шлюза означает пробел в учётных данных. Запустите `/status` и откройте вкладку **Status**: когда строка `Setting sources` не включает управляемые настройки, распределение не достигло машины; когда включает, учётные данные разработчика не были доставлены, поэтому установите `ANTHROPIC_AUTH_TOKEN` или `apiKeyHelper`
* `Please run /login · API Error: 401`, `Not logged in` или `Invalid API key` с `401` в логе шлюза: проверьте, кто выдал `401`. Исправьте ключ разработчика или его заголовок, если его выдал шлюз, или учётные данные поставщика, которые держит шлюз, если он пришёл от `api.anthropic.com` или эндпоинта вашего поставщика
* Одноразовый запрос подтверждения для ключа ожидается при первом использовании, когда шлюз ожидает ключи в заголовке `x-api-key`, установленном как `ANTHROPIC_API_KEY`

Если ваша организация использует [быстрый режим](https://code.claude.com/docs/ru/fast-mode.md), запустите `/fast` здесь тоже: проверка доступности вызывает `api.anthropic.com` напрямую, а не следует базовому URL шлюза, поэтому сеанс, маршрутизируемый через шлюз, может сообщить быстрый режим как недоступный или отключенный, даже если вывод работает. [Использовать быстрый режим за прокси и LLM шлюзами](https://code.claude.com/docs/ru/fast-mode.md#use-fast-mode-behind-proxies-and-llm-gateways) сопоставляет каждое сообщение с переменной, которая его восстанавливает, распределяемой с [остальной конфигурацией](#distribute-the-configuration).

Наконец, проверьте журналы шлюза на предмет отправленного вами сообщения: учетные данные идентифицируют разработчика, и [заголовок `x-claude-code-session-id`](https://code.claude.com/docs/ru/llm-gateway-protocol#request-headers) группирует запросы по сеансам. Если функции не работают с [симптомами устранения неполадок](https://code.claude.com/docs/ru/llm-gateway-connect.md#troubleshoot-gateway-errors), шлюз удаляет заголовки или переписывает ошибки; см. [требования к шлюзу](#gateway-requirements) выше.

## Поддерживать шлюз

После развертывания три вида изменений достигают шлюза с течением времени. Каждый имеет симптом, на который нужно обратить внимание, и действие, которое нужно предпринять.

| Изменение | Симптом, когда шлюз не в курсе | Действие |
| :- | :- | :- |
| Новые выпуски Claude Code добавляют значения `anthropic-beta` и поля тела запроса | Разработчики сообщают об ошибках `400`, называющих новое поле после обновления Claude Code; см. [сквозная передача функций](https://code.claude.com/docs/ru/llm-gateway-protocol.md#feature-pass-through) | Перенаправляйте заголовки `anthropic-*` и тела запроса дословно вместо внесения в список разрешений; протестируйте новые выпуски Claude Code против шлюза перед тем, как они достигнут разработчиков, проверяя области в [Планирование обновлений версии Claude Code](#plan-claude-code-version-upgrades) |
| Становятся доступны новые модели Claude | Разработчики, выбирающие новое имя модели, получают `404`; средство выбора `/model` его не перечисляет | Добавьте имя модели в конфигурацию маршрутизации шлюза, затем повторно запустите [проверку маршрутизации](#confirm-the-gateway-routes-your-models). Если вы распределяете `ANTHROPIC_MODEL` или переменные модели по умолчанию, обновите управляемые параметры |
| Учетные данные истекают или требуют ротации | Все запросы разработчика начинают не работать с `401` от восходящего потока | Ротируйте учетные данные поставщика шлюза по его собственному расписанию; ключи разработчика ротируются на шлюзе, и [`apiKeyHelper`](https://code.claude.com/docs/ru/llm-gateway-connect#rotate-credentials-with-apikeyhelper) обрабатывает ротацию для каждого разработчика без перераспределения параметров |

При определении размера ограничений скорости для каждого ключа учитывайте [повторные попытки клиента при переходящих сбоях](https://code.claude.com/docs/ru/errors.md#automatic-retries), включая ответы `429`, до 10 раз с отступом, соблюдая `Retry-After`. Держите [справочник совместимости](https://code.claude.com/docs/ru/llm-gateway-protocol.md) как контракт для того, что отправляет каждый выпуск Claude Code.

### Планирование обновлений версии Claude Code

Некоторое поведение Claude Code встроено в установленную версию, а не установлено на вашем шлюзе, поэтому перемещение разработчиков на новый выпуск может изменить поведение во всем развертывании даже когда конфигурация шлюза не изменилась. Чтобы контролировать, когда это происходит, закрепите разработчиков на протестированной версии с помощью [`requiredMaximumVersion`](https://code.claude.com/docs/ru/settings-reference#requiredmaximumversion), или с помощью [`DISABLE_UPDATES`](https://code.claude.com/docs/ru/setup#disable-auto-updates), если вы распределяете Claude Code через свой собственный канал. Перед тем как повысить закрепление, прочитайте запись [журнала изменений](https://code.claude.com/docs/en/changelog.md) нового выпуска и [протестируйте его против шлюза](#test-claude-code-against-the-gateway).

Когда вы тестируете выпуск, новые заголовки или поля запроса, которые шлюз отклоняет, появляются как ошибки `400`, описанные в [Поддерживать шлюз](#maintain-the-gateway). Таблица ниже охватывает зависящие от версии изменения, которые не производят ошибку, с параметром, который сохраняет каждое из них постоянным при обновлениях.

| Область | Что может измениться при обновлении разработчиками | Параметр, который сохраняет это постоянным |
| :- | :- | :- |
| Значения по умолчанию флагов функций | Сеансы, которые [не получают флаги функций от Anthropic](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), такие как сеансы на облачном поставщике или с отключенной телеметрией, используют значения по умолчанию флагов, встроенные в установленную версию. Когда выпуск изменяет одно из этих значений по умолчанию, поведение изменяется для этих разработчиков, как только они обновляются | Само закрепление версии, `requiredMaximumVersion` или `DISABLE_UPDATES` |
| Предположения о возможностях модели | ID модели, который установленная версия не распознает, такой как псевдоним шлюза `prod-opus`, работает на предположениях по умолчанию для [адаптивного рассуждения](https://code.claude.com/docs/ru/model-config.md#adaptive-reasoning-and-fixed-thinking-budgets), параметра усилия и [окна контекста](https://code.claude.com/docs/ru/model-config.md#correct-the-window-for-a-gateway-or-custom-model-id) до тех пор, пока более поздняя версия не распознает ID или вы его не сопоставите | Маршрутизируйте ID моделей Anthropic на шлюзе, или добавьте запись [`modelOverrides`](https://code.claude.com/docs/ru/model-config#override-model-ids-per-version), которая сопоставляет ID модели Anthropic с вашим псевдонимом. На подключении облачного поставщика вы можете вместо этого [объявить возможности закрепленной модели](https://code.claude.com/docs/ru/model-config.md#customize-pinned-model-display-and-capabilities) |
| Модель по умолчанию и псевдонимы | Модель, на которой новые сеансы начинаются по умолчанию, и модели, на которые разрешаются псевдонимы, такие как `opus` и `sonnet`, [встроены в каждую версию](https://code.claude.com/docs/ru/model-config.md#pin-models-for-third-party-deployments) и могут измениться при обновлении разработчиками | [`ANTHROPIC_DEFAULT_MODEL`](https://code.claude.com/docs/ru/model-config#set-a-default-model-for-new-sessions) для модели, на которой новые сеансы начинаются, и переменные [`ANTHROPIC_DEFAULT_*_MODEL`](https://code.claude.com/docs/ru/model-config#environment-variables), такие как `ANTHROPIC_DEFAULT_OPUS_MODEL`, для того, на что разрешается каждый псевдоним. `ANTHROPIC_DEFAULT_MODEL` требует Claude Code v2.1.236 или позже |
