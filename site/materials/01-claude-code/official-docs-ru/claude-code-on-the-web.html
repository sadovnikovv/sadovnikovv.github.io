Использование Claude Code в облаке #

Запускайте сессии Claude Code в облаке из браузера, телефона, настольного приложения или терминала, перемещайте их с помощью --cloud и --teleport, а также автоматически исправляйте pull requests.

[!NOTE]

Облачные сессии доступны в планах Pro, Max, Ultra и Team, а также для пользователей Enterprise с премиум-местами или местами Chat + Claude Code. Если вашим доступом управляют пользовательские роли, вам также нужна роль с разрешением на облачные сессии, чтобы запускать сессии на инфраструктуре Anthropic из браузера, приложений или терминала. Попросите владельца (Owner) добавить это разрешение в одну из ваших ролей в Organization settings > Roles.

Облачная сессия — это сессия Claude Code, которая запускается на облачной инфраструктуре вместо вашей машины. По умолчанию она запускается на инфраструктуре, управляемой Anthropic, или в самостоятельно размещённом окружении вашей организации, когда маршрутизируется туда. Сессия продолжает работать после того, как вы закроете ноутбук, и вы можете проверить её или управлять ею с любого устройства. Она учитывается в лимитах использования вашего плана наряду с остальным использованием Claude и Claude Code, а отдельная плата за облачную виртуальную машину не взимается.

Чтобы облачные сессии могли клонировать ваш код из GitHub и отправлять ветки, подключите GitHub одним из способов подключения GitHub. Если ваш репозиторий размещён в GitLab, Bitbucket или на другом хостинге, см. раздел Ограничения платформы, чтобы узнать, что работает.

Вы можете запустить облачную сессию с любой из этих поверхностей:

  • Браузер: claude.ai/code, также называется Claude Code в веб-интерфейсе
  • Мобильное устройство: вкладка Code в приложении Claude
  • Настольное приложение: выберите окружение в разделе Cloud в селекторе окружений при запуске сессии
  • Терминал: claude --cloud
  • Облачные запланированные задачи: запланированные и активируемые запуски — каждый запуск выполняется как облачная сессия

После настройки используйте эту страницу, чтобы перемещать работу между терминалом и облаком, управлять сессиями и делиться ими, включать автоматическое исправление pull requests и устранять неполадки.

[!NOTE]

Эти случаи рассматриваются на других страницах:

  • Запуск первой облачной сессии: Начало работы с облачными сессиями — подключение GitHub и пошаговое выполнение задачи в браузере
  • Множество облачных сессий для одного набора работ: в проекте Claude запускает их и отслеживает за вас
  • Управление локальной сессией с другого устройства: сессии в вашем терминале, IDE или настольном приложении с выбранным Local запускаются на вашей машине, а Remote Control позволяет обращаться к ним с телефона или из браузера

Облачные окружения #

Каждая облачная сессия запускается в облачном окружении, сохранённой конфигурации, которая контролирует сетевой доступ, переменные окружения и скрипты установки.

  • Ваше первое окружение: если у вас ещё нет окружения, подключение настраивает окружение Default с Limited сетевым доступом. См. The Default environment, чтобы узнать, как это работает на вашем плане
  • Какое окружение использует сессия: см. The Default environment, чтобы узнать, как сессии выбирают окружение, когда у вас есть более одного
  • Изменение того, к чему сессии могут обращаться или что они запускают при старте: см. Configure cloud environments
  • Что установлено без какой-либо конфигурации: см. Installed tools

Варианты аутентификации GitHub #

Облачным сессиям нужен доступ к вашим репозиториям GitHub для клонирования кода и отправки веток. Вы можете предоставить доступ двумя способами:

| Метод | Как вы подключаетесь | Репозитории, к которым могут получить доступ сессии | Лучше всего для | | :- | :- | :- | :- | | GitHub App | Авторизуйте приложение Claude GitHub во время веб-подключения | Любой открытый репозиторий и приватные репозитории, на которых установлено приложение Claude GitHub | Веб-подключение в браузере; команды, которые хотят Auto-fix | | /web-setup | Запустите /web-setup в вашем терминале для отправки вашего локального токена gh CLI на ваш аккаунт Claude | Любой репозиторий, к которому может получить доступ ваш токен gh, независимо от того, установлено ли приложение Claude GitHub | Отдельные разработчики, которые уже используют gh |

Следующие функции зависят от того, установлено ли приложение Claude GitHub на репозитории:

  • Auto-fix: установка приложения Claude GitHub на репозиторий также включает Auto-fix для pull request в нём
  • Проекты: потоки в проекте требуют установки приложения Claude GitHub на каждом репозитории, который они клонируют, независимо от того, каким методом вы подключились. См. Настройка доступа GitHub

В среде, размещённой на серверах Anthropic, ваши учётные данные GitHub остаются зашифрованными на серверах Anthropic и никогда не попадают в виртуальную машину сессии. Операции GitHub из виртуальной машины проходят через GitHub proxy, который прикрепляет учётные данные на стороне сервера.

См. Подключение из терминала для пошагового руководства /web-setup, включая то, что хранит /web-setup и как его удалить.

[!NOTE]

Организации с включённым Zero Data Retention или с применённой конфигурацией HIPAA не могут использовать /web-setup или другие функции облачных сессий. Организации, использующие ключи шифрования, управляемые клиентом (CMEK), также не могут запускать облачные сессии.

Quick setup для Team и Enterprise #

Quick setup — это настройка организации, которая убирает часть шагов при настройке GitHub и окружения для участников. На планах Team и Enterprise она отключена по умолчанию.

Вот что меняется для участников, когда она включена:

  • /web-setup: участники могут подключать GitHub с помощью /web-setup. Пока настройка отключена, эта команда скрыта
  • Промпт GitHub App: веб-подключение в браузере пропускает промпт установки приложения Claude GitHub
  • Первое окружение: веб-подключение в браузере создаёт для участников окружение Default вместо отображения формы окружения

Owner включает её с помощью переключателя Quick setup в Organization settings > Claude Code.

Перемещение задач между терминалом и облаком #

Эти рабочие процессы требуют Claude Code CLI, вошедшего в один и тот же аккаунт claude.ai. Вы можете запускать новые облачные сессии из вашего терминала или вытягивать облачные сессии в ваш терминал для продолжения локально. Облачные сессии сохраняются даже если вы закроете ваш ноутбук, и вы можете мониторить их откуда угодно, включая мобильное приложение Claude.

[!NOTE]

Из CLI передача сессии односторонняя: вы можете вытягивать облачные сессии в ваш терминал с помощью --teleport, но вы не можете отправить существующую сессию терминала в облако. Флаг --cloud с описанием задачи создаёт новую облачную сессию для вашего текущего репозитория; с -p и ID сессии или URL claude.ai/code он вместо этого ставит сообщение в очередь в эту существующую сессию. Desktop app может отправить локальную сессию со своей вкладки Code в облако через меню Open in.

Запуск облачной сессии из терминала #

Запустите облачную сессию из командной строки с флагом --cloud:

```bash theme={null} claude --cloud "Fix the authentication bug in src/auth/login.ts"


Это создаёт новую облачную сессию на claude.ai. Облачная виртуальная машина клонирует удалённый GitHub вашего текущего каталога в вашей текущей ветке, а не ваш локальный checkout, поэтому сначала отправьте, если у вас есть локальные коммиты. См. [Отправляйте локальные репозитории без GitHub](#send-local-repositories-without-github) для случаев, когда Claude Code загружает ваш локальный репозиторий вместо клонирования. Если терминал выводит `Branch <name> is not on GitHub`, см. [Branch is not on GitHub](#branch-is-not-on-github).

`--cloud` работает с одним репозиторием за раз. Задача запускается в облаке, пока вы продолжаете работать локально. Старое написание `--remote` всё ещё работает как устаревший псевдоним для `--cloud`.

Пока облачный контейнер запускается, CLI показывает живой чек-лист шагов настройки, таких как клонирование репозитория и запуск вашего [скрипта установки](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts). Он ставит в очередь сообщения, которые вы вводите во время подготовки, и отправляет их после того, как сессия будет готова.

> [!NOTE]
>
> `--cloud` создаёт облачные сессии. `--remote-control` не связан: он позволяет вам мониторить и управлять локальной сессией CLI из claude.ai или приложения Claude. См. [Remote Control](https://code.claude.com/docs/ru/remote-control.md).

Откройте сессию на claude.ai или в мобильном приложении Claude для проверки прогресса или прямого взаимодействия. Оттуда вы можете управлять Claude, предоставлять обратную связь или отвечать на вопросы, как в любом другом разговоре.

Если Claude задаёт вопрос и сессия остаётся неактивной, вы всё ещё можете ответить, когда вернётесь, вплоть до [истечения окружения](#environment-expired), и сессия продолжится с вашего ответа.

#### Советы для облачных задач

**Планируйте локально, выполняйте в облаке**: для сложных задач начните Claude в режиме плана для совместной работы над подходом, затем отправьте работу в облако:

claude --permission-mode plan


В режиме плана Claude читает файлы, запускает команды для исследования и предлагает план без редактирования исходного кода. Когда вы будете довольны, сохраните план в репозиторий, зафиксируйте и отправьте, чтобы облачная виртуальная машина могла его клонировать. Затем запустите облачную сессию для автономного выполнения:

claude --cloud "Execute the migration plan in docs/migration-plan.md"


**Запускайте задачи параллельно**: каждая команда `--cloud` создаёт свою собственную облачную сессию, которая запускается независимо. Вы можете запустить несколько задач, и они все будут запускаться одновременно в отдельных сессиях:

claude --cloud "Fix the flaky test in auth.spec.ts" claude --cloud "Update the API documentation" claude --cloud "Refactor the logger to use structured output"


Когда сессия завершится, вы можете создать PR из claude.ai/code или [телепортировать](#from-cloud-to-terminal) сессию в ваш терминал для продолжения работы.

#### Отправляйте локальные репозитории без GitHub

Когда вы запускаете `claude --cloud` из репозитория, который не имеет git remote, или из репозитория github.com, на котором Claude GitHub App не установлено, Claude Code упаковывает ваш локальный репозиторий и загружает его непосредственно в облачную сессию. Это применяется даже если вы подключили GitHub с помощью `/web-setup`.

Для полного клона пакет включает историю вашего репозитория во всех ветках, плюс незафиксированные изменения отслеживаемых файлов.

Что происходит с незафиксированными изменениями в чувствительных файлах, зависит от вашей платформы:

* **macOS, Linux и WSL**: Claude Code исключает из загрузки незафиксированные изменения файлов, названных как учётные данные или ключи. Это охватывает файлы `.env`, файлы Terraform `*.tfvars` и файлы ключей, такие как `id_rsa` и `*.pem`. Также исключаются незафиксированные изменения файлов, которыми управляет git-фильтр, например Git LFS. Уведомление `Left on this machine:` называет исключённые файлы, и сессия начинается с зафиксированной версии каждого из них или без файла, если ничего не зафиксировано.
* **Нативный Windows**: незафиксированные изменения отслеживаемых файлов загружаются как есть, независимо от имени файла. Спрячьте (stash) или отмените правку, которую вы не хотите видеть в облачной сессии, перед её запуском.

Чтобы загрузить пакет даже когда Claude Code иначе клонировал бы с удалённого сервера, установите `CCR_FORCE_BUNDLE=1`:

CCR_FORCE_BUNDLE=1 claude --cloud "Run the test suite and fix any failures"


Упакованные репозитории должны соответствовать этим ограничениям:

* Каталог должен быть git репозиторием с по крайней мере одним коммитом
* Упакованный репозиторий должен быть менее 100 МБ. Большие репозитории переходят к упаковке только текущей ветки, затем к одному сжатому снимку рабочего дерева и не пройдут только если снимок всё ещё слишком большой
* Неотслеживаемые файлы не включены; запустите `git add` на файлы, которые вы хотите, чтобы облачная сессия видела
* На macOS, Linux и WSL Claude Code отказывает в загрузке, когда он не может следовать параметру git, который влияет на то, какие правила атрибутов применяются к вашим файлам, такие как `core.attributesFile`, установленный в включённом файле конфигурации. [Сообщение об отказе](https://code.claude.com/docs/ru/errors.md#the-repository-upload-cant-follow-a-git-setting) называет параметр и исправление
* Сессии, созданные из пакета, могут отправляться обратно на удалённый GitHub только когда ваше [подключение GitHub](#github-authentication-options) имеет доступ на отправку к этому репозиторию

На macOS, Linux и WSL для загрузки также нужны git 2.31 или новее и поддерживаемая структура checkout, тогда как на нативном Windows Claude Code загружает без обеих проверок. Когда checkout не соответствует этим требованиям, Claude Code не запускает сессию. Он выводит ошибку, содержащую `Not uploading this working tree:`, называет причину и сообщает, что нужно изменить. Типичные причины:

* **Старая версия git**: установленный git старше 2.31. Обновите git, затем повторите попытку.
* **Структура checkout, которую загрузка не поддерживает**: вы запустили из подмодуля, из клона, созданного с помощью `git clone --separate-git-dir`, `--shared` или `--reference`, из checkout с установленным `core.worktree` или из репозитория, который хранит свои ссылки в формате reftable. Вместо этого запустите из основного checkout клона, созданного обычной командой `git clone`.
* **Связанный worktree с sparse checkout**: `git sparse-checkout` записывает настройки в собственный файл `config.worktree` этого worktree, который загрузка не принимает, поэтому worktree с такими настройками не загружается, как и worktree, созданный Claude Code с помощью [`worktree.sparsePaths`](https://code.claude.com/docs/ru/settings-reference#worktree-sparsepaths). Вместо этого запустите из основного checkout репозитория.
* **Конфигурация git, хранящаяся внутри рабочего дерева**: ваша конфигурация git подключает файл, расположенный внутри checkout, например запись `include.path`, указывающую внутрь репозитория. Переместите этот файл за пределы рабочего дерева или удалите подключение, затем повторите попытку.

На macOS, Linux и WSL частичный клон, созданный с помощью `git clone --filter`, загружается как снимок рабочего дерева без истории, при условии что клон содержит локально все отслеживаемые файлы.

Для `claude --cloud`, если репозиторий находится на GitHub, вы можете избежать загрузки и её требований: отправьте свою ветку, установите Claude GitHub App в репозиторий и снова запустите сессию, чтобы она клонировала с GitHub.

### Отправляйте follow-ups из CLI

Когда облачная сессия запущена, где бы она ни выполнялась, отправьте ей follow-up сообщение из CLI `claude` на любой машине, где вы вошли с помощью `claude auth login`. CLI аутентифицируется с помощью учётных данных вашего аккаунта Anthropic и не отправляет локальное состояние сессии, поэтому команду не обязательно запускать с машины, которая запустила сессию.

Команда публикует одно сообщение и выходит:

claude -p "your message" --cloud <session-id>


CLI ставит сообщение в очередь в сессию и выходит без ожидания ответа. Используйте это для управления долгоживущей сессией, постановки в очередь следующего шага, пока текущий всё ещё завершается, или отправки follow-ups из [CI скрипта](https://code.claude.com/docs/ru/self-hosted-environments-testing.md#run-the-test-loop). Вы также можете передать сообщение на stdin вместо передачи его в качестве аргумента: `echo "your message" | claude -p --cloud <session-id>`.

Для `<session-id>` передайте голый ID, такой как `session_...` или `cse_...`, или URL сессии `claude.ai/code/<id>`, с или без схемы или строки запроса. Найдите ID в списке сессий на claude.ai/code.

> [!NOTE]
>
> `--cloud` требует аккаунта Anthropic. Он недоступен, когда Claude Code настроен для Amazon Bedrock, Google Cloud's Agent Platform или другого поставщика третьей стороны. [LLM gateway](https://code.claude.com/docs/ru/llm-gateway), настроенный только через `ANTHROPIC_BASE_URL`, не считается поставщиком третьей стороны для этой проверки, но вам всё ещё нужно войти с помощью `claude auth login`. Политика `allow_remote_sessions` вашей организации также должна быть включена. Owner может включить её в параметрах администратора Claude Code на claude.ai/admin-settings/claude-code.

#### Вывод

При успехе команда выводит ID сессии и ссылку для просмотра сессии:

Sent to cloud session. Session ID: session_01HJKLMNOPQRSTUVWXYZ View: https://claude.ai/code/session_01HJKLMNOPQRSTUVWXYZ?from=cli&m=0


Передайте `--output-format json` для машиночитаемого результата: `{ok, session_id, url}` при успехе, или `{ok: false, session_id, error}` когда отправка не пройдёт, например когда сессия отсутствует или архивирована. Ошибки конфигурации, такие как неподдерживаемый поставщик или отключённая политика организации, выводятся в stderr без JSON. `--output-format stream-json` не поддерживается с `--cloud <session-id>`.

Если отправка не удалась, см. [Ошибки при отправке в облачную сессию](#errors-when-sending-to-a-cloud-session).

### Продолжение облачной сессии в терминале

Вытягивайте облачную сессию в ваш терминал, используя любое из этих:

* **Используя `--teleport`**: из командной строки запустите `claude --teleport` для интерактивного выбора сессии, или `claude --teleport <session-id>` для прямого возобновления конкретной сессии. Если у вас есть незафиксированные изменения, вам будет предложено сначала их спрятать. [`--resume`](https://code.claude.com/docs/ru/sessions#resume-a-session) переоткрывает диалог из локальной истории этой машины и не показывает облачные сессии.
* **Используя `/teleport`**: внутри существующей сессии CLI запустите `/teleport` или `/tp` для открытия того же выбора сессии без перезагрузки Claude Code.
* **Из `/tasks`**: запустите `/tasks` для просмотра ваших фоновых сессий, затем нажмите `t` для телепортирования в одну из них.
* **Из claude.ai/code**: выберите **Open in > Terminal** из меню сессии для копирования команды, которую вы можете вставить в ваш терминал.
* **Из облачной сессии**: введите `/teleport` и Claude Code ответит точной командой `claude --teleport <session-id>` для этой сессии, готовой к запуску из checkout репозитория.

Когда вы телепортируете сессию, Claude проверяет, что вы находитесь в правильном репозитории, получает и извлекает ветку из облачной сессии и загружает диалог в ваш терминал.

> [!NOTE]
>
> Если Claude Code [сжал](https://code.claude.com/docs/ru/context-window.md#what-survives-compaction) облачную сессию, что происходит автоматически в длинной сессии, более ранние сообщения, которые он кратко изложил в сводке, не копируются в ваш терминал. Claude продолжает работу на основе сводки. Чтобы прочитать исходные сообщения, прокрутите вверх в облачной сессии на claude.ai или в мобильном приложении Claude.

Терминал получает свою собственную копию сессии: новая работа там остаётся локальной и не появляется в облачной сессии на claude.ai или в мобильном приложении Claude. Чтобы продолжить управление со своего телефона после телепортирования, запустите [`/remote-control`](https://code.claude.com/docs/ru/remote-control) в локальной сессии.

#### Требования для телепортирования

Телепортирование проверяет эти требования перед возобновлением сессии. Если какое-либо требование не выполнено, вы увидите ошибку или будете приглашены разрешить проблему.

| Требование | Детали |
| - | - |
| Чистое состояние git | Ваш рабочий каталог должен не иметь незафиксированных изменений. Телепортирование предложит вам спрятать изменения, если необходимо. |
| Правильный репозиторий | Вы должны запустить `--teleport` из checkout того же репозитория, не форка. Если вы запустите его из checkout другого репозитория, Claude Code показывает ошибку, которая называет как репозиторий сессии, так и репозиторий вашего checkout. Если Claude Code не может разобрать ваш удалённый сервер в имя хоста, например псевдоним SSH хоста, такой как `git@work:owner/repo.git`, он просит вас подтвердить, и принимает checkout, когда владелец и имя репозитория удалённого сервера совпадают с репозиторием сессии. |
| Доступность ветки | Ветка из облачной сессии должна быть отправлена на удалённый сервер. Телепортирование автоматически получает и извлекает её. |
| Один и тот же аккаунт | Вы должны быть аутентифицированы на том же аккаунте claude.ai, который использовался в облачной сессии. |

Когда телепортирование получает ветку сессии, операция fetch никогда не ожидает ввода в вашем терминале. Если git или ssh запросили бы пароль, парольную фразу ключа или подтверждение нового SSH-хоста, fetch завершается неудачей, и тогда checkout сработает, только если в вашем локальном клоне уже есть эта ветка. Для двух случаев, связанных с SSH, загрузите ключ в `ssh-agent` и предварительно один раз запустите `git fetch` вручную, чтобы записать хост.

#### `--teleport` недоступен

Телепортирование требует аутентификации подписки claude.ai. Найдите случай, соответствующий вашему:

* **Вы вошли с помощью API-ключа или аккаунта Console**: запустите `claude auth login` в вашей оболочке, затем войдите через claude.ai
* **Ошибка называет вашего поставщика**: облачные сессии недоступны через поставщиков третьей стороны. См. [таблицу ошибок](#errors-when-sending-to-a-cloud-session)
* **Вы уже вошли через claude.ai**: ваша организация может отключить облачные сессии

## Работа с сеансами

Сеансы отображаются на боковой панели на claude.ai/code. Оттуда вы можете просмотреть изменения, поделиться с коллегами, архивировать завершённую работу или окончательно удалить сеансы.

### Режимы разрешений в облачных сессиях

Вы выбираете [режим разрешений](https://code.claude.com/docs/ru/permission-modes.md) облачной сессии из [раскрывающегося списка режима](https://code.claude.com/docs/ru/permission-modes.md#switch-permission-modes), как при создании задачи, так и во время выполнения сессии.

Claude Code возобновляет сессию в том режиме разрешений, в котором она находилась, когда вы делаете одно из следующего:

* Повторно открываете сессию, чьё размещённое на Anthropic [окружение истекло](#environment-expired)
* Отправляете сообщение в сессию, которую самостоятельно размещённый runner [освободил во время простоя](https://code.claude.com/docs/ru/self-hosted-environments-reference.md#runner-cli-flags)

### Просмотр изменений

После того как Claude отправит свои изменения в ветку, карточка **Changes** на панели рядом с чатом показывает добавленные и удалённые строки, например `+42 -18`. Нажмите на счётчики строк на карточке **Changes**, чтобы открыть представление diff.

* Вы также можете нажать **Changes** в строке заголовка сессии или в меню **⋮** этой строки.
* Чтобы показать панель, когда она скрыта, нажмите значок **Show session rail** в строке заголовка сессии или в меню **⋮** этой строки.

В представлении diff вы можете комментировать строки и сравнивать изменения с другой веткой:

* **Comment**: оставляйте встроенные комментарии к определённым строкам, затем отправьте комментарии Claude со следующим сообщением
* **Compare**: представление diff по умолчанию сравнивает изменения сессии с её базовой веткой. Чтобы сравнить с любой другой веткой в репозитории, выберите **Compare against** и укажите нужную

Claude Code вычисляет эти diff из необработанного содержимого git blob, поэтому драйверы diff и фильтры `textconv`, настроенные в репозитории, не применяются.

Эти шаги описаны в других разделах:

* **Полное пошаговое руководство, включая создание PR**: см. [Просмотр и итерация](https://code.claude.com/docs/ru/web-quickstart.md#review-and-iterate)
* **Автоматическое отслеживание Claude сбоев CI и комментариев рецензии в PR**: см. [Автоматическое исправление pull requests](#auto-fix-pull-requests)

#### Устранение проблемы с отсутствующим файлом в представлении diff

Ожидаемый файл может отсутствовать в списке файлов представления diff при сравнении с базовой веткой, независимо от того, отправила ли сессия изменения:

* **Изменения ещё не отправлены**: список содержит собственные правки Claude, но не изменения, внесённые командами, которые запускал Claude, например средством форматирования
* **Изменения отправлены**: список содержит отправленные коммиты, но не изменения, внесённые после последней отправки

Чтобы добавить отсутствующее изменение в список, попросите Claude сделать коммит и отправить изменения.

### Управление контекстом

Облачные сеансы поддерживают [встроенные команды](https://code.claude.com/docs/ru/commands.md), которые выводят текстовый результат. Команды, которые работают только в интерфейсе терминала, такие как `/plugin` или `/resume`, недоступны. Команды, которые открывают средство выбора или панель в терминале, ведут себя иначе в облачных сеансах:

* **`/model`, `/effort`, `/color` и `/rename`**: передайте значение как аргумент, например `/model sonnet`, вместо открытия средства выбора терминала или ползунка. Формы аргументов следуют [примечаниям доступности](https://code.claude.com/docs/ru/commands.md#all-commands) каждой команды.
* **`/fast`**: переключает [быстрый режим](https://code.claude.com/docs/ru/fast-mode.md#use-fast-mode-in-cloud-sessions) для сеанса, когда быстрый режим [доступен в вашей учётной записи](https://code.claude.com/docs/ru/fast-mode.md#requirements). Требует Claude Code v2.1.271 или более поздней версии в окружении сеанса.
* **`/config`**: в браузере на claude.ai/code открывает **Settings > Code** или **Settings > Claude Code** вместо задания значения. Чтобы изменить настройку облачной сессии, задайте [переменную окружения](https://code.claude.com/docs/ru/cloud-environments.md#set-environment-variables) в окружении. В сессии с одним репозиторием вне тредов [проекта](https://code.claude.com/docs/ru/claude-projects.md) вместо этого сделайте коммит ключа в файл `.claude/settings.json` этого репозитория. [Настройки в облачных сессиях](https://code.claude.com/docs/ru/settings.md#settings-in-cloud-sessions) перечисляют, что читает каждая сессия.

Для управления контекстом в облачной сессии вне [тредов проекта](https://code.claude.com/docs/ru/claude-projects.md#choose-models-and-let-claude-manage-context):

| Команда | Работает в облачных сеансах | Примечания |
| :- | :- | :- |
| `/compact` | Да | Суммирует беседу для освобождения контекста. Принимает необязательные инструкции фокуса, такие как `/compact keep the test output` |
| `/context` | Да | Показывает, что находится в окне контекста |
| `/clear` | Да | Начинает новый диалог с пустым контекстом в той же облачной сессии |

Автоматическое сжатие выполняется автоматически, когда окно контекста приближается к ёмкости. Облачные сеансы устанавливают [`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`](https://code.claude.com/docs/ru/env-vars) самостоятельно, поэтому сжатие срабатывает на полпути через [окно автоматического сжатия](https://code.claude.com/docs/ru/model-config.md#set-the-auto-compact-window), а не когда окно заполняется. Это значение переопределяет то, которое вы добавляете в ваши [переменные окружения](https://code.claude.com/docs/ru/cloud-environments.md#set-environment-variables), поэтому добавление переменной туда не изменяет, когда срабатывает сжатие.

Чтобы вместо этого изменить окно автоматического сжатия, установите [`CLAUDE_CODE_AUTO_COMPACT_WINDOW`](https://code.claude.com/docs/ru/env-vars) в ваши переменные окружения или запустите [`/autocompact`](https://code.claude.com/docs/ru/commands#all-commands) с количеством токенов в сеансе, где переменная не установлена.

[Субагенты](https://code.claude.com/docs/ru/sub-agents.md) работают так же, как локально. Claude может порождать их с помощью инструмента Agent для разгрузки исследований или параллельной работы в отдельное контекстное окно, сохраняя основной диалог более лёгким. За пределами тредов [проекта](https://code.claude.com/docs/ru/claude-projects.md#what-threads-pick-up-from-your-repositories) субагенты, определённые в `.claude/agents/` вашего репозитория, загружаются автоматически.

[Команды агентов](https://code.claude.com/docs/ru/agent-teams.md) отключены по умолчанию, но могут быть включены путём добавления `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` в ваши [переменные окружения](https://code.claude.com/docs/ru/cloud-environments.md#set-environment-variables).

### Предложения плагинов в диалоге

Карточка в диалоге со списком из одного или нескольких [плагинов](https://code.claude.com/docs/ru/plugins/overview.md) и кнопкой **Add** означает, что Claude предлагает плагины для вашей задачи. Claude может делать такие предложения без вашего запроса. Отвечать не обязательно: Claude в любом случае продолжит выполнять задачу.

#### Добавление или удаление предложенного плагина

Выберите **Add** у плагина, чтобы включить его для вашей учётной записи claude.ai, где он останется включённым и после завершения сессии. Чтобы отменить это, откройте добавленный плагин из карточки, выберите **Manage**, чтобы перейти на страницу плагина на claude.ai, и удалите плагин на этой странице.

#### Отключение предложений плагинов

Чтобы Claude перестал предлагать плагины, запретите инструменты `SearchPlugins` и `SuggestPluginInstall` с помощью [правил разрешений](https://code.claude.com/docs/ru/permissions.md#manage-permissions). В сессии с одним репозиторием вне [проекта](https://code.claude.com/docs/ru/claude-projects.md) сделайте коммит этих правил в файл `.claude/settings.json` этого репозитория, указав оба имени инструментов в `permissions.deny`:

{ "permissions": { "deny": ["SearchPlugins", "SuggestPluginInstall"] } }


Claude Code игнорирует правила разрешений в файле `.claude/settings.json` репозитория, включая эти запрещающие правила, когда [управляемые настройки](https://code.claude.com/docs/ru/managed-settings.md), применяемые к сессии, задают [`allowManagedPermissionRulesOnly`](https://code.claude.com/docs/ru/settings-reference#allowmanagedpermissionrulesonly). В этом случае поместите правила в эти управляемые настройки. Для других конфигураций, например сессии с несколькими репозиториями или облачного треда в проекте, см., какие [настройки попадают в облачную сессию](https://code.claude.com/docs/ru/settings.md#settings-in-cloud-sessions).

### Отмена поставленного в очередь сообщения

Если вы отправляете сообщение, пока Claude работает, сообщение ставится в очередь до тех пор, пока Claude его не прочитает. Чтобы отменить поставленное в очередь сообщение, нажмите на ✕ на нём. Текст вернётся в поле сообщения, чтобы вы могли его отредактировать или отправить что-то другое.

Если Claude уже прочитал сообщение, оно остаётся в диалоге.

### Совместное использование сеансов

Чтобы поделиться сеансом, переключите его видимость в соответствии с типами учётных записей ниже. После этого поделитесь ссылкой на сеанс как есть. Получатели видят последнее состояние при открытии ссылки, но их представление не обновляется в реальном времени.

#### Совместное использование из учётной записи Enterprise или Team

Для учётных записей Enterprise и Team совместное использование работает следующим образом:

* **Варианты видимости**: **Private** и **Team**. Видимость Team делает сессию видимой для других членов вашей организации claude.ai
* **Доступ к репозиторию**: проверка включена по умолчанию на основе учётной записи GitHub, подключённой к учётной записи получателя
* **Ваше имя**: отображаемое имя вашей учётной записи видно всем получателям с доступом
* **Сессии Slack**: сессии [Claude в Slack](https://code.claude.com/docs/ru/slack.md) автоматически становятся общими с видимостью Team

#### Совместное использование из учётной записи Max, Ultra или Pro

* **Варианты видимости**: **Private** и **Public**. Видимость Public делает сессию видимой для любого пользователя, вошедшего в claude.ai
* **Доступ к репозиторию**: проверка не включена по умолчанию
* **Конфиденциальное содержимое**: проверьте свою сессию перед тем, как поделиться ею. Сессии могут содержать код и учётные данные из приватных репозиториев GitHub

Чтобы потребовать от получателей наличие доступа к репозиторию или скрыть своё имя из совместно используемых сессий, откройте Settings на claude.ai, затем:

* **Если в меню Settings отображается Code вместо Claude Code**: перейдите в [**Privacy**](https://claude.ai/settings/data-privacy-controls), где находятся эти настройки
* **В противном случае**: перейдите в [**Claude Code > Sharing settings**](https://claude.ai/settings/claude-code)

### Архивирование сеансов

Архивируйте сессию, чтобы убрать её из списка сессий на боковой панели. Чтобы архивировать сессию, наведите на неё указатель на боковой панели, откройте её меню **⋯** и выберите **Archive**.

#### Поиск архивированной сессии

Чтобы увидеть архивированные сессии, перейдите на [claude.ai/code/sessions](https://claude.ai/code/sessions) и откройте вкладку **Archived**. Чтобы вернуть сессию в список сессий на боковой панели, наведите на неё указатель на этой вкладке, откройте её меню **⋮** и выберите **Unarchive**.

### Удаление сеансов

Удаление сессии окончательно удаляет сессию и её данные. Это действие невозможно отменить. Удалите сессию с боковой панели, из меню сессии или со вкладки **Archived**, если вы её уже архивировали:

* **С боковой панели**: наведите указатель на сессию, откройте её меню **⋯** и выберите **Delete**
* **Из меню сеанса**: откройте сеанс, выберите раскрывающееся меню рядом с названием сеанса и выберите **Delete**
* **Со вкладки Archived**: наведите указатель на сессию на [вкладке **Archived**](#find-an-archived-session), откройте её меню **⋮** и выберите **Delete**

Вам будет предложено подтвердить перед удалением сеанса.

## Auto-fix pull requests

Claude может наблюдать за pull request и автоматически реагировать на сбои CI и комментарии рецензентов. Claude подписывается на активность GitHub в PR, и когда проверка не пройдена или рецензент оставляет комментарий, Claude исследует и отправляет исправление, если оно очевидно.

> [!NOTE]
>
> Auto-fix требует установки приложения Claude GitHub в вашем репозитории. Если вы ещё этого не сделали, установите его со [страницы приложения GitHub](https://github.com/apps/claude).

Есть несколько способов включить auto-fix в зависимости от того, откуда пришёл PR и какое устройство вы используете:

* **PR, созданные в облачной сессии**: откройте сессию на claude.ai/code и найдите pull request в [карточке **Changes**](#review-changes). Откройте меню **⋮** рядом с заголовком pull request и включите **Auto-fix**
* **Из вашего терминала**: запустите [`/autofix-pr`](https://code.claude.com/docs/ru/commands) на ветке PR. Claude Code обнаруживает открытый PR с помощью `gh`, порождает облачную сессию и включает auto-fix в один шаг
* **Из мобильного приложения**: скажите Claude автоматически исправить PR, например "watch this PR and fix any CI failures or review comments"
* **Любой существующий PR**: вставьте URL PR в сессию и скажите Claude автоматически исправить его

Чтобы остановить мониторинг, отключите **Auto-fix** в меню **⋮** pull request в [карточке **Changes**](#review-changes) сессии или скажите Claude прекратить наблюдение за PR.

### Как Claude реагирует на активность PR

Когда auto-fix активен, Claude получает события GitHub для PR, включая новые комментарии рецензентов и сбои проверок CI. Для каждого события Claude исследует и решает, как действовать:

* **Очевидные исправления**: если Claude уверен в исправлении и оно не конфликтует с более ранними инструкциями, Claude вносит изменение, отправляет его и объясняет, что было сделано в сессии
* **Неоднозначные запросы**: если комментарий рецензента может быть интерпретирован несколькими способами или касается чего-то архитектурно значимого, Claude спрашивает вас перед действием
* **Дублирующиеся или события без действия**: если событие является дубликатом или не требует изменений, Claude отмечает это в сессии и продолжает

GitHub не отправляет webhook, когда базовая ветка продвигается вперёд и создаёт конфликт слияния, поэтому auto-fix не может реагировать на конфликты самостоятельно. Чтобы разрешить конфликт, откройте сессию и попросите Claude выполнить rebase.

Claude может отвечать на потоки комментариев рецензентов на GitHub как часть их разрешения. Эти ответы публикуются с использованием вашего аккаунта GitHub, поэтому они появляются под вашим именем пользователя, но каждый ответ помечен как исходящий от Claude Code, чтобы рецензенты знали, что он был написан агентом, а не вами напрямую.

> [!WARNING]
>
> Если ваш репозиторий использует автоматизацию, запускаемую комментариями, такую как Atlantis, Terraform Cloud или пользовательские GitHub Actions, которые запускаются на событиях `issue_comment`, имейте в виду, что Claude может отвечать от вашего имени, что может запустить эти рабочие процессы. Проверьте автоматизацию вашего репозитория перед включением auto-fix и рассмотрите отключение auto-fix для репозиториев, где комментарий PR может развернуть инфраструктуру или запустить привилегированные операции.

## Безопасность и изоляция

Каждая облачная сессия отделена от вашей машины и от других сессий через несколько слоёв:

* **Изолированные виртуальные машины**: каждая сессия запускается в изолированной, управляемой Anthropic виртуальной машине. Сессии, которые ваша организация маршрутизирует в [самостоятельно размещённое окружение](https://code.claude.com/docs/ru/self-hosted-environments), запускаются на вашей собственной инфраструктуре вместо этого, где изоляция — это ответственность вашего развёртывания
* **Элементы управления сетевым доступом**: в окружениях, размещённых Anthropic, сетевой доступ ограничен по умолчанию и может быть отключен. См. [Сетевой доступ](https://code.claude.com/docs/ru/cloud-environments.md#network-access) для уровней доступа, [доменов, разрешённых по умолчанию](https://code.claude.com/docs/ru/cloud-environments.md#default-allowed-domains), и трафика, который не проходит через список разрешений. В самостоятельно размещённом окружении вы ограничиваете исходящий трафик сессии на вашей собственной границе сети. При запуске с отключённым сетевым доступом Claude Code всё ещё может общаться с API Anthropic, что может позволить данным выйти из виртуальной машины.
* **Защита учётных данных**: в окружениях, размещённых Anthropic, учётные данные git и ключи подписи остаются вне песочницы, и прокси аутентифицирует от имени сессии с ограниченными учётными данными. В самостоятельно размещённом окружении ваше развёртывание предоставляет учётные данные git; см. [Configure git](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#configure-git)
* **Сетевые секреты**: в окружениях, размещённых Anthropic, ключи, которые вы [добавляете в облачное окружение](https://code.claude.com/docs/ru/cloud-environments.md#add-network-secrets), остаются вне песочницы так же, прикреплённые к совпадающим запросам после того, как они покидают сессию. Самостоятельно размещённое окружение не имеет сетевых секретов
* **Безопасный анализ**: код анализируется и изменяется в изолированной среде сессии перед созданием PR

## Устранение неполадок

Для ошибок API времени выполнения, которые появляются в разговоре, такие как `API Error: 500`, `529 Overloaded`, `429` или `Prompt is too long`, см. [Error reference](https://code.claude.com/docs/ru/errors.md). Эти ошибки и их исправления общие с CLI и Desktop app. Разделы ниже охватывают проблемы, специфичные для облачных сессий.

### Session creation failed

Если новая сессия не запускается с `Session creation failed` или зависает при подготовке, Claude Code не смог выделить виртуальную машину для сессии.

* Проверьте [status.claude.com](https://status.claude.com) на предмет инцидентов облачных сессий
* Повторите попытку через минуту, так как ёмкость подготавливается по требованию
* Подтвердите, что ваше подключение GitHub может достичь репозитория, следуя [No repositories appear after connecting GitHub](https://code.claude.com/docs/ru/web-quickstart.md#no-repositories-appear-after-connecting-github)

### Your new session couldn't start

Ваш промпт возвращён в поле, из которого вы его отправили.

* **Соединение потеряно**: проверьте подключение к интернету, а также используемые VPN или прокси, затем отправьте промпт снова
* **Ошибка сервера**: подождите немного, затем отправьте промпт снова. Если уведомление появится снова, проверьте [status.claude.com](https://status.claude.com)

### Can't rewind to this message

**Rewind to here** завершается с этой ошибкой для любого сообщения, кроме самого нового, если ваша сессия работает на [self-hosted runner](https://code.claude.com/docs/ru/self-hosted-environments) с Claude Code версии ниже v2.1.246. Попросите того, кто управляет раннерами вашей организации, [обновить их](https://code.claude.com/docs/ru/self-hosted-environments-deploy.md#pin-the-version).

### Unable to get organization UUID

`claude --cloud` и `claude --teleport` требуют входа с аккаунтом claude.ai. Если вместо этого вы аутентифицируетесь с помощью API-ключа или входа через Console либо ваши сохранённые данные аккаунта устарели, вы увидите сообщение, например:

* `Unable to get organization UUID`
* ``Cloud sessions need a claude.ai sign-in. Run `claude auth login` (or /login in a local session), then try again.``
* ``Cloud sessions aren't available with this Console sign-in. They need a claude.ai sign-in. Run `claude auth login` (or /login in a local session), then try again.``
* `Error loading Claude Code sessions` в окне выбора сессии, если вы запускаете `claude --teleport` без ID сессии

Запустите [`claude auth login`](https://code.claude.com/docs/ru/cli-reference#cli-commands) в оболочке, чтобы войти с вашим аккаунтом claude.ai, затем повторите команду. Внутри запущенной сессии то же самое делает `/login`. Если вместо этого в ошибке указан ваш поставщик, см. [таблицу ошибок](#errors-when-sending-to-a-cloud-session): облачные сессии недоступны через сторонних поставщиков.

В версиях с v2.1.274 по v2.1.289 сообщение о входе было таким: `Claude Code cloud sessions require authentication with a Claude.ai account. API key authentication is not sufficient. Please run /login to authenticate, or check your authentication status with /status.`

### Branch is not on GitHub

Когда `claude --cloud` выводит строку, начинающуюся с `Branch <name> is not on GitHub`, облачная сессия всё равно запускается, но не из вашей ветки. В строке указано, откуда вместо этого запускается сессия: с отправленного коммита из истории вашей ветки или с ветки по умолчанию репозитория. Коммиты, которые существуют только на вашем компьютере, и незакоммиченные изменения в сессию не попадают.

Вы видите эту строку, например, если вы ни разу не отправляли ветку или GitHub удалил её после слияния её pull request. Если в указанной в строке начальной точке есть всё, что нужно для вашей задачи, используйте сессию как есть. В противном случае отправьте ветку и начните новую сессию, чтобы она клонировала вашу ветку.

### Remote Control session expired or access denied

`--teleport` подключается через ту же инфраструктуру сессии Remote Control, которую используют облачные сессии, поэтому ошибки аутентификации и истечения сессии появляются с формулировкой Remote Control. Вы можете увидеть `Remote Control session expired` или `Access denied`. Токен соединения имеет короткий срок действия и ограничен вашим аккаунтом.

* Запустите `/login` локально для обновления ваших учётных данных, затем переподключитесь
* Подтвердите, что вы вошли в один и тот же аккаунт, который владеет сессией
* Если вы видите `Remote Control may not be available for this organization`, Owner не включил облачные сессии для вашей организации

### Ошибки при отправке в облачную сессию

Эти ошибки возникают при запуске `claude` с [`--cloud <session-id>`](#send-follow-ups-from-the-cli), с `-p` или без него. CLI добавляет к ошибкам префикс `Error: `. Неудачная доставка оборачивается в `failed to send message to cloud session <id>: <reason>`.

| Сообщение | Что оно означает |
| - | - |
| `Cloud sessions aren't available with <provider>. They run on Anthropic's infrastructure and require an Anthropic account.` | Claude Code настроен на использование стороннего поставщика. В сообщении поставщик указан под тем названием, которое используется в вашей конфигурации, например `Amazon Bedrock` или `Google Vertex AI`. Удалите конфигурацию этого поставщика, например, сбросив `CLAUDE_CODE_USE_BEDROCK`, и войдите с аккаунтом Anthropic (`claude auth login`). |
| `Cloud sessions are disabled by your organization's policy. Contact your organization admin to enable them.` | Политика организации `allow_remote_sessions` отключена; см. [Cloud sessions are disabled by your organization's policy](https://code.claude.com/docs/ru/errors.md#cloud-sessions-are-disabled-by-your-organizations-policy). Если вместо этого в сообщении указаны учётные данные, которые использует эта сессия, см. [Cloud sessions use your claude.ai login](https://code.claude.com/docs/ru/errors.md#cloud-sessions-use-your-claude-ai-login). |
| `Couldn't verify your organization's policy for cloud sessions. Check your network connection and try again.` | Claude Code ещё не завершил загрузку политики вашей организации, поэтому отклоняет отправку, а не предполагает, что облачные сессии разрешены. Проверьте сетевое подключение и повторите попытку. |
| `Cloud sessions aren't available:`, за которым следует причина | Не удалось загрузить политику вашей организации, и оставшаяся часть сообщения объясняет, почему. Устраните указанную в нём причину; см. [Couldn't verify your organization's policy for cloud sessions](https://code.claude.com/docs/ru/errors.md#couldnt-verify-your-organizations-policy-for-cloud-sessions). |
| `Attaching to an existing cloud session is not enabled for your account.` | Вы запустили `--cloud <session-id>` без `-p`. Отправьте сообщение с помощью `claude -p "your message" --cloud <session-id>`. |
| `Session not found: <id>` | ID или URL не соответствует сессии, к которой у вас есть доступ. Сверьте его с URL сессии claude.ai/code. |
| `cloud session <id> is archived and cannot accept new messages` | Сессия была заархивирована. Вместо этого начните новую сессию. |

### Environment expired

Облачные сессии останавливаются после периода неактивности и виртуальная машина сессии отзывается. Сессия считается неактивной, пока она ждёт вас для одобрения вызова инструмента [MCP connector](https://code.claude.com/docs/ru/cloud-environments.md#network-access) или для входа на сервер MCP, и она может истечь во время этого ожидания.

Переоткройте сессию из [claude.ai/code](https://claude.ai/code), чтобы подготовить новую виртуальную машину:

* **Восстанавливается**: история вашего диалога
* **Не восстанавливается**: фоновая работа, которая всё ещё выполнялась или ожидала выполнения, когда виртуальная машина была отозвана, в том числе:
  * **Shell-команды**: Claude Code сообщает Claude, какие команды были остановлены. Попросите Claude повторно запустить те, которые вам всё ещё нужны.
  * **Субагенты**: Claude Code сообщает Claude, какие субагенты были остановлены и какие из них можно [возобновить](https://code.claude.com/docs/ru/sub-agents.md#resume-subagents), а не запускать заново. Попросите Claude продолжить их работу.
  * **Запланированные задачи в рамках сессии**: задачи, которые вы [запланировали в сессии](https://code.claude.com/docs/ru/scheduled-tasks.md), и `/loop`, ожидающий следующей итерации, не переносятся в переоткрытую сессию. Попросите Claude снова запланировать задачи или снова выполните `/loop`, чтобы перезапустить цикл.

## Ограничения

Перед использованием облачных сеансов в рабочем процессе учитывайте следующие ограничения:

* **Ограничения частоты запросов**: облачные сессии используют общие ограничения частоты запросов со всеми остальными использованиями Claude и Claude Code в вашей учётной записи. Запуск нескольких задач параллельно потребляет больше ограничений частоты запросов пропорционально.
* **Ограничения по времени**: команды, которые запускает Claude, и hooks SessionStart имеют стандартные тайм-ауты, которые вы можете изменить, а скрипт настройки кэшируется только при завершении примерно за пять минут. См. [Time limits](https://code.claude.com/docs/ru/cloud-environments.md#time-limits)
* **Аутентификация репозитория**: вы можете извлечь облачный сеанс в свой терминал только при аутентификации в одной и той же учётной записи
* **Ограничения платформы**: клонирование репозитория в средах, размещённых в Anthropic, и создание pull request требуют GitHub. Экземпляры [GitHub Enterprise Server](https://code.claude.com/docs/ru/github-enterprise-server.md) с собственным размещением поддерживаются для планов Team и Enterprise. Вы можете отправить репозиторий GitLab, Bitbucket или другой репозиторий, не являющийся GitHub, в облачную сессию как [локальный пакет](#send-local-repositories-without-github), установив `CCR_FORCE_BUNDLE=1`, но сессия не сможет отправить результаты обратно на этот удалённый сервер
  * **Самостоятельно размещённые среды**: для репозитория на другом Git-хостинге см. [требования для запуска сессии с `--environment`](https://code.claude.com/docs/ru/self-hosted-environments-deploy#start-a-session-on-a-repository-outside-github).
