# Начало работы с Claude Code в облаке

> Запустите Claude Code в облаке из браузера или мобильного приложения. Подключите репозиторий GitHub, отправьте задачу и просмотрите PR без локальной настройки.

> [!NOTE]
>
> Облачные сессии доступны в планах Pro, Max, Ultra и Team, а также для пользователей Enterprise с премиум-местами или местами Chat + Claude Code.

Облачный сеанс запускает Claude Code на облачной инфраструктуре вместо вашей машины, управляемой Anthropic по умолчанию. Этот краткий старт запускает один с [claude.ai/code](https://claude.ai/code) в вашем браузере. Вы также можете запустить один из мобильного приложения Claude, приложения Desktop или вашего терминала с помощью `claude --cloud`.

Claude клонирует выбранный вами [репозиторий GitHub](#connect-github) в изолированную виртуальную машину, вносит изменения и отправляет ветку для вашего просмотра. Сессии сохраняются на всех устройствах, поэтому задача, которую вы начали на ноутбуке, готова к просмотру с телефона позже. Каждая сессия учитывается в лимитах использования вашего плана наряду с остальным использованием Claude и Claude Code, а за облачную виртуальную машину отдельная плата не взимается.

Облачные сеансы хорошо подходят для:

* **Параллельные задачи**: запускайте несколько независимых задач одновременно, каждую в своем сеансе и ветке, без управления несколькими worktrees
* **Репозитории, которые у вас нет локально**: Claude клонирует репозиторий заново в каждом сеансе, поэтому вам не нужно его проверять
* **Задачи, которые не требуют частого управления**: отправьте четко определенную задачу, займитесь чем-то другим и просмотрите результат, когда Claude закончит
* **Вопросы о коде и исследование**: поймите кодовую базу или проследите, как реализована функция, без локального клона

Для работы, которая требует вашей локальной конфигурации, инструментов или окружения, запуск Claude Code локально или использование [Remote Control](https://code.claude.com/docs/ru/remote-control.md) — лучший вариант.

## Как работают сеансы

Описанные ниже шаги относятся к сеансам, размещённым на серверах Anthropic. В [самостоятельно размещённой среде](https://code.claude.com/docs/ru/self-hosted-environments) клонирование и всё остальное выполняется на собственных средствах выполнения вашей организации, где границы сети, настройка и поведение отправки настраиваются оператором. Когда вы отправляете задачу:

1. **Клонирование и подготовка**: ваш репозиторий клонируется на управляемую Anthropic ВМ, и ваш [скрипт настройки](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts) запускается, если он настроен.
2. **Настройка сети**: доступ в интернет устанавливается на основе [уровня доступа](https://code.claude.com/docs/ru/cloud-environments.md#access-levels) вашего окружения.
3. **Работа**: Claude анализирует код, вносит изменения, запускает тесты и проверяет свою работу. Вы можете наблюдать и управлять на протяжении всего процесса или отойти и вернуться, когда это будет сделано.
4. **Отправка ветки**: когда Claude достигает точки остановки, он отправляет свою ветку на GitHub. Вы просматриваете diff, оставляете встроенные комментарии, создаете PR или отправляете еще одно сообщение, чтобы продолжить.

Сеанс не закрывается при отправке ветки. Создание PR и дальнейшие правки происходят в одном и том же разговоре.

## Сравнение способов запуска Claude Code

Claude Code работает одинаково везде. Различается лишь то, где выполняется сессия и доступна ли ваша локальная конфигурация:

| | Облачная сессия | Локальная сессия | Локальная сессия с [Remote Control](https://code.claude.com/docs/ru/remote-control.md) |
| :- | :- | :- | :- |
| **Где выполняется код** | Облачная VM, по умолчанию управляемая Anthropic | Ваш компьютер | Ваш компьютер |
| **Откуда вы её запускаете** | claude.ai/code, мобильное приложение Claude, приложение Desktop с выбранным режимом **Cloud** или `claude --cloud` | Ваш терминал, ваша IDE или приложение Desktop с выбранным режимом **Local** | Ваш терминал, расширение VS Code или приложение Desktop |
| **Откуда вы общаетесь** | claude.ai, мобильное приложение или приложение Desktop | Там, где вы её запустили | claude.ai или мобильное приложение, а также там, где вы её запустили |
| **Использует вашу локальную конфигурацию** | Нет, только репозиторий | Да | Да |
| **Требует GitHub** | Да, для репозитория GitHub, если только `--cloud` не [упаковывает ваш локальный репозиторий](https://code.claude.com/docs/ru/claude-code-on-the-web.md#send-local-repositories-without-github) | Нет | Нет |
| **Продолжает работу при отключении** | Да | Нет | Пока сессия остаётся открытой на вашем компьютере |
| **[Режимы разрешений](https://code.claude.com/docs/ru/permission-modes.md)** | Accept edits, Plan, Auto | Все режимы в терминале; для IDE и приложения Desktop см. [Переключение режимов разрешений](https://code.claude.com/docs/ru/permission-modes.md#switch-permission-modes) | Manual, Accept edits, Plan или Auto из claude.ai и мобильного приложения |
| **Доступ к сети** | Настраивается для каждого окружения | Сеть вашего компьютера | Сеть вашего компьютера |

Чтобы настроить локальные сессии, см. документацию по [быстрому старту в терминале](https://code.claude.com/docs/ru/quickstart.md), [приложению Desktop](https://code.claude.com/docs/ru/desktop.md) или [Remote Control](https://code.claude.com/docs/ru/remote-control.md).

## Подключение GitHub

Подключение GitHub — это одноразовый процесс. Если вы уже используете GitHub CLI, вы можете [сделать это из терминала](#connect-from-your-terminal) вместо браузера.

> [!NOTE]
>
> На планах Team и Enterprise шаг **Sign in with GitHub** работает только после того, как [Owner](https://code.claude.com/docs/ru/server-managed-settings.md#access-control) вашей организации Claude включит коннектор GitHub в [**Organization settings > Connectors**](https://claude.ai/admin-settings/connectors). До этого момента этот шаг показывает "GitHub access is required for Claude Code cloud sessions" вместо кнопки входа. После включения коннектора перезагрузите [claude.ai/code](https://claude.ai/code) и начните заново с первого шага. Второй переключатель, [Quick setup](https://code.claude.com/docs/ru/claude-code-on-the-web.md#quick-setup-for-team-and-enterprise) в [**Organization settings > Claude Code**](https://claude.ai/admin-settings/claude-code), является необязательным: при его включении `/web-setup` работает и встроенная настройка создаёт окружение для участников.

**1. Посетите claude.ai/code**

Перейдите на [claude.ai/code](https://claude.ai/code) и войдите со своей учётной записью claude.ai.

**2. Войдите с помощью GitHub**

После входа claude.ai/code предложит вам подключить GitHub. Следуйте промпту, и claude.ai/code отправит вас на страницу авторизации GitHub. Одобрите запрос авторизации, и GitHub вернёт вас на claude.ai/code. Облачные сессии работают с существующими репозиториями GitHub. Чтобы запустить новый проект, сначала [создайте репозиторий с README на GitHub](https://github.com/new).

С этим подключением сеанс может клонировать любой открытый репозиторий, но может работать в приватном репозитории только когда приложение Claude GitHub установлено на нем. [Установите приложение Claude GitHub](https://github.com/apps/claude/installations/new) на каждую учетную запись GitHub или организацию, чьи приватные репозитории вы хотите использовать. В организации GitHub владелец организации может потребоваться одобрить установку. Установка приложения также включает [Auto-fix](https://code.claude.com/docs/ru/claude-code-on-the-web.md#auto-fix-pull-requests), который позволяет Claude реагировать на сбои CI и комментарии рецензентов в pull requests в этих репозиториях.

При подключении Claude также привязывает принадлежащие вам учётные записи GitHub к вашей организации Claude, если на них установлено приложение Claude GitHub. На планах Team и Enterprise пользователи с ролью Owner в вашей организации Claude видят эти учётные записи в [списке подключённых учётных записей GitHub](https://code.claude.com/docs/ru/admin-setup.md#connected-github-accounts).

Если встроенная настройка предложит вам установить приложение Claude GitHub на этом этапе и вы предпочитаете сделать это позже, нажмите **Skip**.

**3. Настройте ваше окружение по умолчанию**

[Облачное окружение](https://code.claude.com/docs/ru/cloud-environments.md) — это сохраненная конфигурация, которая контролирует, какой доступ в сеть имеет Claude во время сеансов и что запускается при запуске сеанса. То, что происходит после подключения GitHub, зависит от вашего плана:

* **Pro, Max и Ultra**: вы автоматически получаете окружение с именем **Default**.
* **Team и Enterprise**: встроенная настройка показывает форму **Create your first cloud environment**. Оставьте предзаполненное имя и доступ в сеть без изменений и нажмите **Create & finish**, чтобы создать окружение **Default**. Если Owner включил [Quick setup](https://code.claude.com/docs/ru/claude-code-on-the-web.md#quick-setup-for-team-and-enterprise), встроенная настройка создаёт **Default** для вас вместо этого.

**Default** использует [доступ в сеть **Limited**](https://code.claude.com/docs/ru/cloud-environments.md#access-levels): сессии получают доступ к [общим реестрам пакетов](https://code.claude.com/docs/ru/cloud-environments.md#default-allowed-domains) и другим доменам в списке разрешённых. Смотрите [Installed tools](https://code.claude.com/docs/ru/cloud-environments.md#installed-tools) для того, что доступно без какой-либо конфигурации.

Для первого проекта окружение **Default** работает как есть. Чтобы изменить его доступ в сеть, добавить переменные окружения или запустить [скрипт настройки](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts) перед запуском сеансов, [отредактируйте его или создайте дополнительные окружения](https://code.claude.com/docs/ru/cloud-environments.md#configure-your-environment).

### Подключение из терминала

Если вы уже используете GitHub CLI (`gh`), вы можете подключить GitHub для облачных сессий из терминала. Это требует [Claude Code CLI](https://code.claude.com/docs/ru/quickstart.md). На планах Team и Enterprise `/web-setup` доступен только после того, как Owner включит [Quick setup](https://code.claude.com/docs/ru/claude-code-on-the-web.md#quick-setup-for-team-and-enterprise).

Когда вы запускаете `/web-setup`, Claude Code читает токен, который выводит `gh auth token`, просит вас подтвердить и отправляет токен в Anthropic. Anthropic хранит его в зашифрованном виде с вашей учетной записью claude.ai, и ваши облачные сеансы используют его для доступа к GitHub до тех пор, пока вы не [удалите его](#remove-the-web-setup-token). Облачный сеанс, который вы запускаете сами, может затем получить доступ к любому репозиторию, к которому может получить доступ этот токен, без установки приложения Claude GitHub. Потоки в [проекте](https://code.claude.com/docs/ru/claude-projects.md#set-up-github-access) по-прежнему требуют приложение Claude GitHub.

Если вы уже подключили GitHub в браузере, `/web-setup` предупредит вас, что продолжение заменит это подключение для ваших облачных сеансов.

> [!NOTE]
>
> Организации с включённым [Zero Data Retention](https://code.claude.com/docs/ru/zero-data-retention.md) или с применённой [конфигурацией HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md) не могут использовать `/web-setup` или другие функции облачных сессий. Организации, использующие [ключи шифрования, управляемые клиентом](https://platform.claude.com/docs/en/manage-claude/cmek) (CMEK), также не могут запускать облачные сессии. Если GitHub CLI не установлен или не аутентифицирован, Claude Code открывает поток встроенной настройки в браузере вместо этого.

**1. Аутентификация с помощью GitHub CLI**

В вашей оболочке аутентифицируйте GitHub CLI, если вы еще этого не сделали:

```bash theme={null}
gh auth login
```

**2. Войдите в Claude**

В Claude Code CLI запустите `/login` для входа со своей учетной записью claude.ai. Пропустите этот шаг, если вы уже вошли со своей учетной записью claude.ai. Аутентификация с помощью ключа API не считается. Чтобы проверить, запустите `/status` и подтвердите, что строка **Login method** показывает учетную запись claude.ai.

**3. Запустите /web-setup**

В Claude Code CLI запустите:

```text theme={null}
/web-setup
```

Подтвердите запрос на отправку вашего токена `gh` в вашу учётную запись Claude. При успехе Claude Code выводит `Connected as <your-github-username>` и открывает [claude.ai/code](https://claude.ai/code) в вашем браузере.

Если у вас ещё нет облачного окружения, `/web-setup` создаёт его с доступом в сеть по умолчанию **Limited** и без скрипта настройки. Вы можете [отредактировать окружение или добавить переменные](https://code.claude.com/docs/ru/cloud-environments.md#configure-your-environment) позже. После завершения `/web-setup` вы можете запускать облачные сессии из терминала с помощью [`--cloud`](https://code.claude.com/docs/ru/claude-code-on-the-web#from-terminal-to-cloud) или настроить повторяющиеся задачи с помощью [`/schedule`](https://code.claude.com/docs/ru/routines).

#### Удалите токен `/web-setup`

Чтобы удалить токен из вашей учетной записи Claude, отключите GitHub в [claude.ai/customize/connectors](https://claude.ai/customize/connectors). Отключение удаляет учетные данные GitHub, которые используют ваши облачные сеансы, независимо от того, поступили ли они из браузера или из `/web-setup`, поэтому облачные сеансы теряют доступ к GitHub до тех пор, пока вы не подключитесь снова. Ваш локальный `gh` остается вошедшим, и токен остается действительным на GitHub.

Чтобы аннулировать сам токен, отозвите его на GitHub. Если вы вошли в `gh` через браузер, токен принадлежит записи **GitHub CLI** в разделе [**Settings > Applications > Authorized OAuth Apps**](https://github.com/settings/applications) на GitHub, и отзыв этой записи также выходит из GitHub CLI на ваших машинах. Облачные сеансы затем теряют доступ к GitHub до тех пор, пока вы не запустите `gh auth login` и `/web-setup` снова.

## Начните задачу

С подключенным GitHub и созданным окружением вы готовы отправлять задачи.

**1. Выберите репозиторий и ветку**

На [claude.ai/code](https://claude.ai/code) или на вкладке Code в мобильном приложении Claude нажмите селектор репозитория под полем ввода и выберите репозиторий для работы Claude. Вы можете добавить несколько репозиториев для работы с ними в одной сессии.

На claude.ai/code, чтобы запустить Claude с ветки функции вместо ветки по умолчанию, измените ветку в элементе управления после селектора репозитория.

**2. Выберите режим разрешений**

[Элемент управления режимом разрешений](https://code.claude.com/docs/ru/permission-modes.md#switch-permission-modes) показывает режим разрешений, в котором будет работать сессия:

* **Auto**: классификатор проверяет действия Claude вместо того, чтобы спрашивать вас. Отображается, если ваша организация не отключила [авторежим](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode). Если на claude.ai/code этот вариант неактивен, выберите модель, которая поддерживает авторежим
* **Accept edits**: Claude вносит изменения и отправляет ветку без остановки для одобрения
* **Plan**: Claude предлагает подход и ждет вашего одобрения перед редактированием файлов

Облачные сеансы не предлагают разрешения Manual или разрешения Bypass. Смотрите [полный список режимов разрешений](https://code.claude.com/docs/ru/permission-modes.md#available-modes) для того, что позволяет каждый из них.

**3. Опишите задачу и отправьте**

Введите описание того, что вы хотите, и нажмите Enter. Будьте конкретны:

* Назовите файл или функцию: "Add a README with setup instructions" или "Fix the failing auth test in `tests/test_auth.py`" лучше, чем "fix tests"
* Вставьте вывод ошибки, если у вас он есть
* Опишите ожидаемое поведение, а не просто симптом

Claude клонирует репозитории, запускает ваш скрипт настройки, если он настроен, и начинает работать. Каждая задача получает свой сеанс и свою ветку, поэтому вам не нужно ждать, пока одна закончится, прежде чем начать другую.

## Предварительное заполнение сеансов

Вы можете предварительно заполнить подсказку, репозитории и окружение для нового сеанса, добавив параметры запроса к URL [claude.ai/code](https://claude.ai/code). Используйте это для создания интеграций, таких как кнопка в вашем трекере проблем, которая открывает Claude Code с описанием проблемы в качестве подсказки.

| Параметр | Описание |
| :- | :- |
| `prompt` | Текст подсказки для предварительного заполнения в поле ввода. Также принимается псевдоним `q`. |
| `prompt_url` | URL для получения текста подсказки, для подсказок, которые слишком длинные для встраивания в строку запроса. URL должен разрешать кросс-источниковые запросы. Игнорируется, когда также установлен `prompt`. |
| `repositories` | Разделенный запятыми список слагов `owner/repo` для предварительного выбора. Также принимается псевдоним `repo`. |
| `environment` | Имя или ID [окружения](#connect-github) для предварительного выбора. |

URL-кодируйте каждое значение. Пример ниже открывает форму с уже выбранной подсказкой и репозиторием:

```text theme={null}
https://claude.ai/code?prompt=Fix%20the%20login%20bug&repositories=acme/webapp
```

## Просмотр и итерация

Когда Claude закончит, просмотрите изменения, оставьте отзыв на конкретных строках и продолжайте, пока diff не будет выглядеть правильно.

**1. Откройте представление diff**

После того как Claude отправит свои изменения в ветку, карточка **Changes** на панели рядом с чатом показывает добавленные и удаленные строки во всей сессии, например `+42 -18`. Нажмите на эти числа, чтобы открыть представление diff.

* Также можно нажать **Changes** в строке заголовка сессии или в меню **⋮** этой строки.
* Чтобы показать панель, когда она скрыта, нажмите значок **Show session rail** в строке заголовка сессии или в меню **⋮** этой строки.

Diff по умолчанию сравнивает изменения сессии с ее базовой веткой. Чтобы сравнить с другой веткой, выберите **Compare against** и выберите одну. При сравнении с базовой веткой diff может [не включать изменения, которые еще не отправлены](https://code.claude.com/docs/ru/claude-code-on-the-web.md#troubleshoot-a-missing-file-in-the-diff-view).

**2. Оставляйте встроенные комментарии**

Наведите указатель на строку в diff и нажмите **+**, который появляется рядом с номером строки, чтобы открыть поле комментария, затем введите свой отзыв и нажмите Enter. Комментарии накапливаются до тех пор, пока вы не отправите следующее сообщение, затем они объединяются с ним. Claude видит "at `src/auth.ts:47`, don't catch the error here" вместе с вашей основной инструкцией, поэтому вам не нужно описывать, где проблема.

**3. Создайте pull request**

Когда diff выглядит правильно, [снова покажите панель](https://code.claude.com/docs/ru/claude-code-on-the-web.md#review-changes), если карточка **Changes** не видна, а затем создайте pull request или черновик из карточки:

* Нажмите **Create PR**. Claude Code создаст pull request со сгенерированным названием и описанием.
* Чтобы вместо этого открыть черновик, щелкните правой кнопкой мыши **Create PR**, выберите **Create draft PR**, чтобы изменить действие кнопки, затем нажмите на кнопку

**4. Продолжайте итерацию после PR**

Сессия остается активной после создания PR. Вставьте вывод ошибки CI или комментарии рецензента в чат и попросите Claude их решить. Чтобы Claude автоматически отслеживал PR, смотрите [Auto-fix pull requests](https://code.claude.com/docs/ru/claude-code-on-the-web.md#auto-fix-pull-requests).

## Устранение неполадок при настройке

### После подключения GitHub не появляются репозитории

Если вы подключили GitHub в браузере, сеансы могут клонировать любой публичный репозиторий, но приватный репозиторий появляется только когда приложение Claude GitHub установлено на учетной записи или организации, которая его владеет, и доступ к репозиториям в установке включает его. [Установите приложение Claude GitHub](https://github.com/apps/claude/installations/new) там или попросите владельца организации установить или одобрить его.

Если вы подключились с помощью `/web-setup`, сеансы получают доступ к каждому репозиторию, который может видеть ваш токен `gh`. Запустите `gh repo view OWNER/REPO` в вашей оболочке, чтобы проверить, что ваш вход GitHub CLI может видеть репозиторий, и запустите `/web-setup` снова, если вы переключили учетные записи `gh` с момента подключения.

### На странице отображается только кнопка входа GitHub

Чтобы работать с репозиторием GitHub в облачной сессии, [подключите свою учетную запись GitHub](#connect-github) или запустите `/web-setup` из терминала, если вы используете GitHub CLI. Если вы предпочитаете вообще не подключать GitHub, смотрите [Remote Control](https://code.claude.com/docs/ru/remote-control.md) для запуска Claude Code на вашей машине и мониторинга его из браузера или телефона.

### "Claude Code isn't available on your account"

Ваше место в выбранной организации не включает Claude Code. Если вы принадлежите другой организации, нажмите **Switch organization** на этой странице. В противном случае попросите владельца организации назначить вам [место, которое включает Claude Code](https://support.claude.com/en/articles/11845131-use-claude-code-with-your-team-or-enterprise-plan).

### `/web-setup` говорит "Not signed in to Claude"

Если `/web-setup` отвечает "Not signed in to Claude. Run /login first.", CLI не имеет действительного входа в claude.ai. Это также может произойти, когда предыдущий вход истек. Запустите `/login`, войдите со своей учетной записью claude.ai, затем снова запустите `/web-setup`.

### `/web-setup` предупреждает, что ваш токен не имеет области `workflow`

Если `/web-setup` говорит, что ваш токен GitHub CLI не имеет области `workflow`, вы можете продолжить, но GitHub может отклонить некоторые отправки, сделанные с этим токеном, такие как отправки, которые изменяют файлы рабочих процессов GitHub Actions. Чтобы добавить область, запустите `gh auth refresh -s workflow` в вашей оболочке, затем снова запустите `/web-setup`.

### `/web-setup` показывает "No commands match" или "Unknown command"

`/web-setup` работает внутри Claude Code CLI, а не в вашей оболочке. Сначала запустите `claude`, затем введите `/web-setup` в подсказке.

Если вы ввели его внутри Claude Code и меню команд показывает `No commands match "/web-setup"`, или отправка возвращает `Unknown command: /web-setup`, команда скрыта, потому что требование не выполнено. Причина обычно в том, что вы аутентифицированы с помощью ключа API или поставщика третьей стороны вместо подписки claude.ai. Запустите `/login` для входа со своей учетной записью claude.ai.

На планах Team и Enterprise команда скрыта по умолчанию: [переключатель быстрой настройки](https://code.claude.com/docs/ru/claude-code-on-the-web.md#quick-setup-for-team-and-enterprise) отключен, пока владелец его не включит. Пока он отключен, вместо этого [подключите GitHub из браузера](#connect-github).

Команда также скрыта в двух других случаях:

* Администратор отключил облачные сеансы для вашей организации. В этом случае отправка `/web-setup` возвращает [`Cloud sessions are disabled by your organization's policy`](https://code.claude.com/docs/ru/errors#cloud-sessions-are-disabled-by-your-organizations-policy). До версии 2.1.268 этот случай также возвращал `Unknown command: /web-setup`.
* В вашей организации Enterprise включен [Zero Data Retention](https://code.claude.com/docs/ru/zero-data-retention.md) или применена [конфигурация HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md). Любой из этих вариантов делает облачные сессии недоступными.

### "Could not create a cloud environment" или "No cloud environment available" при использовании `--cloud`

Функции облачного сеанса автоматически создают облачное окружение по умолчанию, если у вас его нет. Если вы видите "Could not create a cloud environment", автоматическое создание не удалось. Если вы видите "No cloud environment available", ваш CLI предшествует автоматическому созданию. В любом случае запустите `/web-setup` в Claude Code CLI, или добавьте окружение из [селектора окружения](https://code.claude.com/docs/ru/cloud-environments.md#configure-your-environment) на [claude.ai/code](https://claude.ai/code).

### Скрипт настройки не удался

[Скрипт настройки](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts) завершился с ненулевым статусом, поэтому сессия не запустилась или запустилась без того, что скрипт не смог установить. Если сессия запустилась, вы можете продолжать работать в ней.

Распространенные причины:

* Установка пакета не удалась, потому что реестр не входит в ваш [уровень доступа к сети](https://code.claude.com/docs/ru/cloud-environments.md#access-levels). **Limited** с включенным флажком **Allow package managers** охватывает большинство менеджеров пакетов; **None** блокирует их все.
* Скрипт ссылается на файл или путь, который не существует в свежем клоне.
* Команда, которая работает локально, требует другого вызова на Ubuntu.

Для отладки добавьте `set -x` в начало скрипта, чтобы увидеть, какая команда не удалась. Для некритических команд добавьте `|| true`, чтобы они не приводили к сбою скрипта. После устранения причины запустите новую сессию, чтобы скрипт выполнился снова. Если не удалось запустить выполнение [облачной запланированной задачи](https://code.claude.com/docs/ru/routines.md), нажмите **Run now** на странице сведений о задаче вместо запуска новой сессии.

### Новые сеансы зависают или истекает время ожидания во время настройки

Если новые сеансы зависают на шаге скрипта настройки или не удаются с общей ошибкой контейнера перед завершением скрипта, скрипт, вероятно, превышает примерно пятиминутный бюджет времени для построения [кэша окружения](https://code.claude.com/docs/ru/cloud-environments.md#environment-caching). Тяжелые шаги, такие как извлечение больших образов Docker, синхронизация полных деревьев зависимостей или загрузка весов модели, часто превышают лимит, особенно когда они выполняются один за другим.

Чтобы исправить это, обрежьте скрипт так, чтобы он надежно завершался менее чем за пять минут:

* Запускайте независимые установки параллельно с `&` и финальным `wait` вместо их последовательного выполнения.
* Переместите самые большие загрузки из скрипта настройки в [SessionStart hook](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts-vs-sessionstart-hooks), который запускает их в фоновом режиме, чтобы сеанс стал пригодным для использования, пока они завершаются.
* Удалите длинные повторные попытки сна из скрипта настройки, так как зависший цикл повторных попыток учитывается в бюджете.

### Сеанс продолжает работать после закрытия вкладки

Это сделано специально. Закрытие вкладки или навигация не останавливает сеанс. Он продолжает работать в фоновом режиме до тех пор, пока Claude не закончит текущую задачу, затем переходит в режим ожидания. На боковой панели вы можете [архивировать сеанс](https://code.claude.com/docs/ru/claude-code-on-the-web.md#archive-sessions), чтобы скрыть его из списка, или [удалить его](https://code.claude.com/docs/ru/claude-code-on-the-web.md#delete-sessions), чтобы удалить его навсегда.

## Следующие шаги

Теперь, когда вы можете отправлять и просматривать задачи, эти страницы охватывают, что дальше: запуск облачных сеансов из терминала, планирование повторяющейся работы и предоставление Claude постоянных инструкций.

* [Использование Claude Code в веб-версии](https://code.claude.com/docs/ru/claude-code-on-the-web.md): полный справочник, включая телепортацию сеансов в ваш терминал, совместное использование сеансов и автоматическое исправление pull-запросов
* [Настройка облачных окружений](https://code.claude.com/docs/ru/cloud-environments.md): уровни сетевого доступа, переменные окружения и скрипты настройки для облачных сеансов
* [Облачные запланированные задачи](https://code.claude.com/docs/ru/routines.md): автоматизируйте работу по расписанию, через вызов API или в ответ на события GitHub
* [CLAUDE.md](https://code.claude.com/docs/ru/memory.md): дайте Claude постоянные инструкции и контекст, которые загружаются в начале каждого сеанса
* Установите мобильное приложение Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) или [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude) для мониторинга сеансов с телефона. Из Claude Code CLI `/mobile` показывает QR-код для [claude.ai/mobile](https://claude.ai/mobile), который открывает правильный магазин приложений для вашего телефона.
