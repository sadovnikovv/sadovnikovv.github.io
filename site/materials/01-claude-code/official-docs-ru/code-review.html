Code Review #

Находите ошибки в pull request на GitHub с помощью Code Review: Claude проводит ревью каждого изменения, проверяет свои результаты и оставляет встроенные комментарии. Для планов Team и Enterprise

С Code Review Claude проводит ревью pull request в ваших репозиториях GitHub. Несколько агентов читают каждое изменение вместе с окружающим кодом и ищут такие проблемы, как логические ошибки, уязвимости безопасности или нарушенные граничные случаи. Прежде чем о результатах будет сообщено, этап верификации сверяет их с кодом.

Результаты поступают в виде встроенных комментариев на соответствующих строках, ранжированные по степени серьёзности, вместе со сводкой и check run на pull request. Ревью никогда не одобряет и не блокирует pull request, поэтому решение о слиянии остаётся за вашей командой.

[!NOTE]

Code Review использует ИИ для ревью кода и может пропустить ошибки, уязвимости безопасности или другие проблемы. Ревью без результатов не означает, что ваш код не содержит ошибок или безопасен.

Чтобы включить Code Review, пользователь с ролью Owner в вашей организации Claude выполняет инструкции из раздела Настройка Code Review. Claude также может проводить ревью кода без этого сервиса. Запустите /code-review в своей сессии Claude Code на любом плане или сравните все варианты.

Доступность #

Прежде чем настраивать Code Review, убедитесь, что ваша организация соответствует требованиям:

  • Планы: Team и Enterprise
  • Хостинги кода: репозитории, размещённые на GitHub, включая GitHub Enterprise Server и GitHub Enterprise Cloud с резидентностью данных. Для резидентности данных попросите пользователя с ролью Owner выполнить настройку администратора GitHub Enterprise Server и указать имя хоста ghe.com вашего предприятия.
  • Хранение данных: Code Review недоступен для организаций с включённым Zero Data Retention или с применённой конфигурацией HIPAA, и на него не распространяется Business Associate Agreement (BAA) Anthropic.
  • Ключи шифрования: Code Review пока недоступен для организаций, использующих ключи шифрования, управляемые клиентом (CMEK).
  • Облачные провайдеры: вам нужна организация Claude на одном из этих планов, даже если ваши разработчики используют Claude Code через Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry

Настройка и использование Code Review #

Выберите страницу в зависимости от того, что вам нужно сделать:

[card] Настройка Code Review

Проверьте требования, установите Claude GitHub App и выберите репозитории, уровень ревью и момент запуска ревью

[card] Кастомизация Code Review

Настройте, что помечается, с помощью файлов REVIEW.md и CLAUDE.md в вашем репозитории

[card] Чтение и запрос ревью на pull request

Читайте результаты и их степени серьёзности и запрашивайте повторное ревью с помощью комментария

[card] Устранение неполадок Code Review

Исправьте ревью, которое не запустилось, завершилось сбоем или было пропущено из-за бюджета

[card] Стоимость и использование Code Review

Узнайте, как тарифицируются ревью, оцените расходы, установите ежемесячный лимит расходов и отслеживайте активность ревью

Как работают ревью #

По умолчанию Code Review сосредоточен на корректности: ошибках, которые нарушат работу production, а не на предпочтениях форматирования или отсутствии покрытия тестами. Чтобы изменить то, что он помечает, добавьте файлы с руководствами в ваш репозиторий.

Ревью выполняется на инфраструктуре Anthropic в четыре этапа:

  1. Поиск: несколько агентов параллельно изучают diff и окружающий код.
  2. Верификация: этап верификации сверяет кандидатов в результаты с кодом и отфильтровывает ложные срабатывания.
  3. Ранжирование: оставшиеся результаты дедуплицируются и ранжируются по степени серьёзности.
  4. Публикация: ревью публикует свои результаты на pull request.

Каждое ревью оставляет на pull request следующее:

  • Результаты: встроенные комментарии на соответствующих строках со сводкой в теле ревью
  • Check run: с именем Claude Code Review, с результатами, перечисленными в его подробностях. Check run не завершается со статусом сбоя.
  • Заметка вместо результатов: публикуется, когда заголовок check run гласит Code review found no issues

Code Review сам выбирает модели Claude, на которых выполняются ревью, и его настройки администратора не предлагают выбора модели. Чтобы сделать ревью более или менее тщательными, измените уровень ревью.

После того как пользователь с ролью Owner включит Code Review, у каждого репозитория появляется настройка момента запуска ревью: один раз при открытии pull request, после каждого push или только по запросу. Независимо от выбранного варианта, любой пользователь с доступом на запись к репозиторию может оставить комментарий @claude review на pull request, чтобы запустить ревью.

Уровни ревью #

Уровень ревью определяет, насколько тщательным будет каждое ревью, и более тщательное ревью стоит дороже:

  • Quick: более лёгкий проход. Самый быстрый уровень с наименьшей стоимостью.
  • Standard: сбалансированные глубина, скорость и стоимость. Уровень по умолчанию.
  • Deep: самый тщательный проход. Занимает больше всего времени и стоит дороже всего.

Пользователь с ролью Owner выбирает один уровень для организации и может задать отдельному репозиторию собственный уровень, например Quick для рутинной кодовой базы и Deep для критически важной. О том, что ещё влияет на стоимость каждого ревью, см. Стоимость и использование Code Review.

К чему у ревью есть доступ #

Ревью получает доступ к вашему репозиторию через Claude GitHub App, которое пользователь с ролью Owner устанавливает во время настройки:

  • Где оно выполняется: на инфраструктуре Anthropic, в управляемом окружении. Ревью не выполняются в self-hosted окружениях.
  • Что оно читает и записывает: внутри ревью доступ к вашему репозиторию только для чтения, и ревью не отправляет коммиты. На pull request оно публикует комментарии и check run, разрешает собственные более ранние ветки комментариев и может отреагировать на команду в комментарии с помощью 👀. Само приложение обладает более широким набором разрешений, который используется и другими функциями Claude.
  • Как оно изучает ваш код: ревью работает, читая diff и окружающий код, без сборки или запуска вашего кода.

Кто управляет ревью #

  • Кто может его запустить: там, где ревью запускаются автоматически, открытие pull request или push в него запускает ревью, кроме черновиков и форков. После некоторых push Code Review вместо этого сохраняет предыдущий результат. Команда в комментарии запускает ревью, только если она исходит от человека с доступом на запись к репозиторию.
  • Каким инструкциям оно следует: REVIEW.md из базовой ветки или ветки по умолчанию и никогда не из изменений самого pull request.
