Продолжайте локальные сеансы с любого устройства с помощью Remote Control #

Продолжайте локальный сеанс Claude Code со своего телефона, планшета или любого браузера, используя Remote Control. Работает с claude.ai/code и мобильным приложением Claude.

Remote Control подключает claude.ai/code или приложение Claude для iOS и Android к сеансу Claude Code, работающему на вашем компьютере. Начните задачу за столом, а затем продолжите её со своего телефона на диване или в браузере на другом компьютере.

Когда вы запускаете сеанс Remote Control на своем компьютере, Claude продолжает работать локально всё время, поэтому выполнение кода и доступ к файловой системе остаются на вашем компьютере. С помощью Remote Control вы можете:

  • Использовать полную локальную среду удалённо: ваша файловая система, MCP servers, инструменты и конфигурация проекта остаются доступными, и ввод @ автоматически дополняет пути файлов из вашего локального проекта.
  • Работать с обеих поверхностей одновременно: беседа и прогресс subagents и dynamic workflows остаются синхронизированными на всех подключённых устройствах, поэтому вы можете отправлять сообщения из терминала, браузера и телефона взаимозаменяемо.
  • Отправлять изображения и файлы со своего телефона или браузера: прикрепляйте фотографию или файл в приложение Claude или на claude.ai/code с подписью или без неё. Claude видит прикреплённые фотографии непосредственно как часть вашего сообщения. Claude Code загружает другие файлы на ваш компьютер и передаёт их Claude как ссылки на файлы @.
  • Пережить перебои: если ваш ноутбук перейдёт в режим сна или сетевое соединение разорвётся, Claude Code автоматически переподключится, когда ваш компьютер вернётся в сеть.

В отличие от cloud sessions, которые работают на облачной инфраструктуре, сеансы Remote Control работают непосредственно на вашем компьютере и взаимодействуют с вашей локальной файловой системой. Веб- и мобильные интерфейсы — это просто окно в этот локальный сеанс, поэтому ваш компьютер должен оставаться включённым и процесс claude должен продолжать работать.

[!NOTE]

Remote Control — это функция Claude Code. Сведения о диалогах в других продуктах Claude см. в Справочном центре Claude.

Требования #

Перед использованием Remote Control убедитесь, что ваша среда соответствует этим условиям:

  • Подписка: доступна на планах Pro, Max, Ultra, Team и Enterprise. API-ключи не поддерживаются. На планах Team и Enterprise Owner должен сначала включить переключатель Remote Control в настройках администратора Claude Code.
  • Пользовательские роли: если ваша организация Enterprise управляет вашим доступом с помощью пользовательских ролей, ваши роли должны предоставлять вам как разрешение на облачные сессии, так и разрешение Claude Code remote control. Если любого из них нет, при запуске Remote Control отображается Remote Control is disabled by your organization's policy. Попросите Owner проверить ваши роли и добавить недостающее в Organization settings > Roles.
  • Аутентификация: запустите claude и используйте /login для входа через claude.ai, если вы ещё этого не сделали. Без подходящей учётной записи claude remote-control завершится с ошибкой, в то время как claude --remote-control всё ещё запустит интерактивный сеанс и покажет уведомление об ошибке Remote Control вскоре после запуска.
  • Конечная точка API: недоступна в любой из этих конфигураций:
  • Вы используете Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry.
  • Вы указываете ANTHROPIC_BASE_URL на хост, отличный от api.anthropic.com, например на LLM gateway или прокси. Отключите переменную, чтобы использовать Remote Control.
  • Вы входите через корпоративный Claude apps gateway.
  • Оценка флага функции: если вы установили переменную окружения, которая отключает оценку флага функции, доступность Remote Control зависит от того, какую именно:
  • Если вы установили CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC или CLAUDE_CODE_DISABLE_FEATURE_FLAGS, Remote Control недоступен. Отключите переменную везде, где она установлена, в переменных окружения вашей оболочки или в блоке env файла settings.json, чтобы использовать Remote Control.
  • Если вы установили только DISABLE_TELEMETRY или DO_NOT_TRACK, Remote Control остаётся доступным, если только ваша организация не требует Trusted Devices. Если требует, отключите переменную, чтобы использовать Remote Control. Использование Remote Control с любой из этих переменных требует Claude Code версии 2.1.283 или позже либо версии 2.1.304 или позже в приложении Claude Desktop.
  • Доверие рабочей области: в каталоге, который вы ещё не доверили, claude remote-control выводит информацию о том, что включает доверие, и спрашивает Trust <directory>? [y/N] перед запуском. Ответ y сохраняет выбор, за исключением вашего домашнего каталога, где доверие никогда не сохраняется и вопрос повторяется при каждом запуске. Когда стандартный ввод или вывод команды не является терминалом, команда не может спросить и завершается с ошибкой Workspace not trusted.

Запуск сеанса Remote Control #

Вы можете запустить сеанс Remote Control из CLI, приложения Claude Desktop или расширения VS Code. CLI предлагает три режима вызова; приложение Desktop и VS Code используют команду /remote-control.

[tab] Режим сервера

В каталоге вашего проекта выполните:

```bash theme={null} claude remote-control


`claude rc` — псевдоним этой команды.

До тех пор, пока вы не примете одноразовое подтверждение Remote Control, `claude remote-control` объясняет, что он делает, и спрашивает `Enable Remote Control? (y/n)` перед запуском сервера. Ответьте `y`, чтобы принять и запустить сервер. Если вы откажетесь, Claude Code завершит работу без запуска сервера и снова спросит при следующем запуске команды.

Процесс продолжает работать в вашем терминале в режиме сервера, ожидая удаленных подключений. Он отображает URL, который вы можете использовать для [подключения с другого устройства](#connect-from-another-device), и вы можете нажать пробел, чтобы показать QR-код для быстрого доступа с телефона. Пока активна удаленная сессия, терминал показывает статус подключения и активность инструментов.

Передавайте любые из этих флагов после `remote-control`:

| Флаг | Описание |
| - | - |
| `--name "My Project"` | Установите пользовательское название сеанса, видимое в списке сеансов на claude.ai/code. |
| `--remote-control-session-name-prefix <prefix>` | Префикс для автоматически генерируемых названий сеансов, когда явное имя не установлено. По умолчанию используется имя хоста вашей машины, создавая названия вроде `myhost-graceful-unicorn`. Установите `CLAUDE_REMOTE_CONTROL_SESSION_NAME_PREFIX` для того же эффекта. |
| `-c`, `--continue` | Восстановите сеанс, который последний сервер в этом каталоге запустил, вместо создания нового. См. [Возобновление сеансов после остановки сервера](#resume-sessions-after-stopping-the-server). Не может быть объединено с `--session-id`, `--spawn`, `--capacity` или `--create-session-in-dir`. Требуется Claude Code v2.1.200 или позже. |
| `--session-id <id>` | Восстановите один сеанс по его ID. См. [Возобновление сеансов после остановки сервера](#resume-sessions-after-stopping-the-server). Не может быть объединено с `--continue`, `--spawn`, `--capacity` или `--create-session-in-dir`. Требуется Claude Code v2.1.200 или позже. |
| `--spawn <mode>` | Как сервер создает сессии. • `same-dir` (по умолчанию, если режим не сохранен): все сессии используют текущий рабочий каталог, поэтому они могут конфликтовать при редактировании одних и тех же файлов. • `worktree`: каждая сессия по требованию получает собственный [git worktree](https://code.claude.com/docs/ru/worktrees.md). Требуется Git-репозиторий или [хук `WorktreeCreate`](https://code.claude.com/docs/ru/hooks#worktreecreate). • `session`: режим одной сессии. Обслуживает ровно одну сессию и отклоняет дополнительные подключения. Задается только при запуске. Нажмите `w` во время работы, чтобы переключаться между `same-dir` и `worktree`. Режим, на который вы переключились, становится [режимом по умолчанию для этого проекта](#set-the-default-spawn-mode-for-a-project). |
| `--capacity <N>` | Максимальное количество одновременных сеансов. По умолчанию 32. Не может использоваться с `--spawn=session`. |
| `--[no-]create-session-in-dir` | Предварительно создайте один сеанс в текущем каталоге при запуске сервера, чтобы у вас было место для ввода сразу. В режиме `worktree` этот сеанс остается в текущем каталоге, а сеансы по требованию получают изолированные worktrees. Включено по умолчанию. Если вы передадите `--no-create-session-in-dir` для запуска без него, Claude Code архивирует сеансы сервера при его остановке, поэтому нечего [возобновлять](#resume-sessions-after-stopping-the-server). |
| `--permission-mode <mode>` | Установите начальный [режим разрешений](https://code.claude.com/docs/ru/permission-modes.md) для сеансов сервера, например `acceptEdits`. Принимает `manual` как псевдоним для `default`; неузнанный режим останавливает сервер при запуске и выводит список допустимых режимов. |
| `--settings <file>` | Применяет JSON-файл настроек к сессиям сервера с тем же [приоритетом](https://code.claude.com/docs/ru/settings.md#settings-precedence), что и `claude --settings`. Укажите путь к файлу, а не JSON-строку. Требуется Claude Code v2.1.321 или новее. |
| `--chrome` / `--no-chrome` | Включите или отключите [интеграцию Chrome](https://code.claude.com/docs/ru/chrome.md) в сеансах, которые создает сервер, чтобы Claude мог использовать Chrome на вашей машине, пока вы работаете с другого устройства. Без любого из флагов сеанс, который сервер предварительно создает, и любой сеанс, который вы запускаете сами с claude.ai/code или приложения Claude, начинаются с отключенным Chrome, даже если вы [включили Chrome по умолчанию](https://code.claude.com/docs/ru/chrome.md#enable-chrome-by-default). Сеанс, который сервер запускает для одного из ваших потоков [проекта](https://code.claude.com/docs/ru/claude-projects.md), следует этому параметру вместо этого, за исключением режима `bypassPermissions`. Требуется Claude Code v2.1.273 или позже. |
| `-d`, `--debug[=<filter>]` | Включите отладочное логирование для сервера, опционально отфильтрованное по категориям. Передайте фильтр только в форме `=`, например `--debug=api,hooks`. Требуется Claude Code v2.1.282 или позже. |
| `--debug-file <path>` | Запишите отладочные логи в указанный файл. |
| `--verbose` | Показывайте подробные логи подключения и сеанса. |
| `--sandbox`, `--no-sandbox` | Удалены в v2.1.300. Если вы передадите любой из этих флагов, сервер [завершится с ошибкой](https://code.claude.com/docs/ru/errors.md#sandbox-is-not-supported-by-claude-remote-control) вместо запуска. |

Если вы передадите глобальный флаг `claude` перед `remote-control` или его добавит скрипт-обертка, Claude Code не переносит этот флаг в сессии, которые создает сервер. С некоторыми флагами, например `--verbose` или `--model`, сервер все равно запускается. С любым другим флагом сервер [не запускается](https://code.claude.com/docs/ru/errors.md#not-carried-over-to-the-sessions-remote-control-starts). Чтобы передать файл настроек, укажите `--settings` после `remote-control`.

Чтобы изолировать сеансы, которые запускает сервер, включите [изоляцию](https://code.claude.com/docs/ru/sandboxing.md) в файле параметров.

Чтобы вывести флаги `remote-control` в терминале, выполните `claude remote-control --help`. До v2.1.302 без входа с подходящей учетной записью команда вместо этого возвращала одну из ошибок, описанных в разделе [Устранение неполадок](#troubleshooting).

[tab] Интерактивная сессия

Чтобы запустить обычную интерактивную сессию Claude Code с включенным Remote Control, используйте флаг --remote-control (или --rc):

```bash theme={null} claude --remote-control


Опционально передайте имя для сеанса:

claude --remote-control "My Project"


Это дает вам полный интерактивный сеанс в вашем терминале, который вы также можете контролировать с claude.ai или приложения Claude. В отличие от `claude remote-control` (режим сервера), вы можете вводить сообщения локально, пока сеанс также доступен удаленно.

[tab] Из существующего сеанса

Если вы уже находитесь в сеансе Claude Code и хотите продолжить его удаленно, используйте команду /remote-control (или /rc):

```text theme={null} /remote-control


Передайте имя в качестве аргумента, чтобы установить пользовательское название сеанса:

/remote-control My Project


Это запускает сеанс Remote Control, который переносит историю вашего текущего разговора.

До тех пор, пока вы не примете одноразовое подтверждение Remote Control, диалог появляется перед подключением `/remote-control`. Выберите **Enable Remote Control**, чтобы принять и подключиться. Если вы выберете **Never mind** или нажмете Esc, Claude Code не подключится и снова спросит при следующем запуске `/remote-control`.

Флаг `--verbose` недоступен с этой командой.

[tab] VS Code

В расширении Claude Code VS Code введите /remote-control или /rc в поле подсказки.

```text theme={null} /remote-control


Пока Remote Control включен, Claude Code показывает индикатор **Remote Control** в нижней части поля подсказки. После подключения сеанса нажмите на индикатор, чтобы перейти непосредственно к сеансу, или найдите его в списке сеансов на [claude.ai/code](https://claude.ai/code). Claude Code также публикует URL сеанса в разговоре. Чтобы отключиться, запустите `/remote-control` снова.

В отличие от CLI, команда VS Code не принимает аргумент имени и не отображает QR-код. Название сеанса выводится из истории вашего разговора или первой подсказки.

[tab] Приложение Desktop

В локальном сеансе на вкладке Code приложения Claude Desktop введите /remote-control или /rc в поле подсказки.

```text theme={null} /remote-control


После подключения сеанса найдите его в списке сеансов на [claude.ai/code](https://claude.ai/code). Чтобы отключиться, запустите `/remote-control` снова.

Чтобы вместо этого включить Remote Control для каждого сеанса по умолчанию, см. [Включение Remote Control для всех сеансов](#enable-remote-control-for-all-sessions).

Проверка статуса подключения #

В интерактивном сеансе, пока Remote Control подключен, терминал показывает индикатор /rc active, который ссылается на сеанс на claude.ai. Индикатор скрывается, когда терминал слишком узкий, чтобы его вместить. Чтобы увидеть URL сеанса и QR-код для подключения с другого устройства, запустите /remote-control снова, чтобы открыть панель статуса. Панель также позволяет вам отключить Remote Control, пока ваш локальный сеанс продолжает работать.

Если подключение не удается в интерактивном сеансе, индикатор изменяется, чтобы показать сбой, и Claude Code показывает причину в уведомлении и добавляет ее в разговор. Запустите /remote-control для переподключения, если только причина не говорит, что сеанс изменился где-то еще:

  • Another connection took over this session: другое устройство или сеанс Claude Code теперь его имеет. Запустите /remote-control только если вы хотите его вернуть.
  • This session was ended or archived from another device or app: запустите /remote-control только если вы хотите сеанс вернуть. Claude Code повторно открывает архивированный сеанс.
  • The server no longer reports this session: он может быть удален с другого устройства или приложения.

Если /remote-control открывает диалоговое окно с сообщением Remote Control isn't connected., выполните шаг, который указан в диалоговом окне, например запустите /login или выберите Continue и повторите попытку.

Подключение с другого устройства #

После активации сеанса Remote Control у вас есть несколько способов подключиться с другого устройства:

  • Откройте URL, который отображает Claude Code, в любом браузере, чтобы перейти на claude.ai/code.
  • Отсканируйте QR-код, показанный рядом с URL, чтобы открыть его в приложении Claude. С claude remote-control нажмите пробел, чтобы переключить отображение QR-кода.
  • Откройте claude.ai/code или приложение Claude и найдите сеанс по имени в списке сеансов. В мобильном приложении Claude нажмите Code в навигации, чтобы достичь списка сеансов. Сеансы Remote Control показывают значок компьютера с зеленой точкой статуса при подключении.

Когда вы подключаетесь, устройство показывает любых подагентов и рабочие процессы, которые сеанс уже запустил в фоновом режиме. Остановите один из них с устройства, и Claude Code остановит эту задачу на вашей машине.

Название удаленного сеанса выбирается в этом порядке:

  1. Имя, которое вы передали в --name, --remote-control или /remote-control
  2. Название, которое вы установили с помощью /rename
  3. Последнее значимое сообщение в существующей истории разговора
  4. Автоматически сгенерированное имя вроде myhost-graceful-unicorn, где myhost — это имя хоста вашей машины или префикс, который вы установили с помощью --remote-control-session-name-prefix

Если вы не установили явное имя, Claude Code обновляет название, чтобы отразить вашу подсказку после того, как вы отправите одну. Когда вы переименовываете сеанс с claude.ai или приложения Claude, Claude Code также обновляет локальное название, показанное в claude --resume.

Если у вас еще нет приложения Claude, запустите /mobile внутри Claude Code, чтобы показать QR-код для claude.ai/mobile, который открывает правильный магазин приложений для вашего телефона.

Что видят подключенные устройства #

Подключенное устройство показывает разговор в вашем терминале по мере его происхождения. Эти случаи выходят за рамки обычных сообщений:

  • Компактирование и /clear: пока Claude Code компактирует разговор, подключенные устройства показывают прогресс, а затем где был компактирован разговор. Когда вы запускаете /clear, разговор также сбрасывается на подключенных устройствах.
  • Отключение после /resume или /teleport: если у подключенной сессии есть ссылка для общего доступа или Claude Code не может это проверить, Remote Control отключается, когда любая из этих команд открывает другой диалог. Иначе люди со ссылкой увидели бы этот диалог. Чтобы подключить новый диалог, запустите /remote-control в терминале. Для проверки ссылки для общего доступа требуется Claude Code v2.1.324 или новее.
  • Переключение разговоров с помощью /resume: подключенное устройство не получает название переключенного разговора или более раннюю историю, но новые сообщения в обе стороны идут к и от того разговора, который открыт в вашем терминале. Чтобы снова работать с исходным разговором с устройства, запустите /resume в вашем терминале и переключитесь обратно на него.
  • Извлечение сеанса с помощью /teleport: когда вы извлекаете облачный сеанс в ваш терминал с помощью /teleport, подключенное устройство не получает более раннюю историю извлеченного разговора. Новые сообщения в обе стороны идут к и от извлеченного разговора, который теперь открыт в вашем терминале.
  • Сообщения из ваших других сессий: с межсессионной передачей сообщений одно и то же подключение переносит сообщения между вашими собственными сессиями на разных машинах.
  • Diff ваших изменений: когда каталог сеанса находится в git репозитории, панель diff подключенного устройства показывает ваши изменения. На ветке, которая имеет коммиты впереди ветки по умолчанию репозитория, панель показывает изменения с момента разделения ветки, включая ваши незафиксированные правки. На самой ветке по умолчанию или на ветке, которая не впереди, панель показывает только ваши незафиксированные изменения.
  • Модель: когда вы выбираете модель с подключенного устройства, Claude Code запускает сеанс на этой модели. Требуется Claude Code v2.1.238 или позже. Модель, которую вы выбираете с элемента управления моделью устройства, применяется только к текущему сеансу. Когда вы отправляете /model <name> с устройства в интерактивный сеанс, Claude Code также устанавливает ваше значение по умолчанию для новых сеансов.
  • Уровень effort: когда вы задаете уровень effort с подключенного устройства с помощью /effort или элемента управления effort на устройстве, Claude Code применяет его к сессии на вашей машине. Если вы закрепили уровень с помощью CLAUDE_CODE_EFFORT_LEVEL, сессия сохраняет этот уровень. Для выбора уровня в элементе управления effort требуется Claude Code v2.1.234 или новее на вашей машине.
  • Переподключение после сбоя подключения: выполните /remote-control для переподключения. Если за это время сжатие контекста переписало диалог или вы переключили диалоги с помощью /resume, Claude Code архивирует серверную сессию, которую он использовал, вместо того чтобы оставлять ее в списке сессий. Вы по-прежнему можете найти эту сессию среди ваших архивированных сессий на claude.ai/code. Переключение диалогов, пока устройство все еще подключено, не архивирует сессию.

Создание ответвления сессии из браузера #

Чтобы попробовать другое направление, не прерывая сессию, откройте ее на claude.ai/code и выберите Fork в меню сессии или создайте ответвление от более раннего сообщения в транскрипте. Ответвление открывается как новая сессия в вашем списке сессий и продолжает диалог с этой точки, пока исходная сессия продолжает работать. Для создания ответвлений требуется Claude Code v2.1.277 или новее на вашей машине.

Сервер claude remote-control, запущенный с --spawn session, вмещает только свою единственную сессию, поэтому не может запустить ответвление.

Claude Code отклоняет создание ответвления, например, в следующих случаях:

  • Сессия занята. Создайте ответвление, когда она простаивает.
  • Сессия размещена в расширении VS Code или другом приложении, построенном на Agent SDK.

Включение Remote Control для всех сеансов #

Remote Control активируется только при явном запуске claude remote-control, claude --remote-control или /remote-control, если не включено автоподключение. Чтобы включить автоподключение для каждого интерактивного сеанса, запустите /config внутри Claude Code и установите Enable Remote Control for all sessions. Переключатель принимает три значения:

  • true: автоматически подключаться при запуске интерактивного сеанса.
  • false: отключить автоподключение, однако true из управляемых настроек имеет приоритет, потому что Claude Code сохраняет выбор в ваши пользовательские настройки. false в настройках проекта или локальных настройках (.claude/settings.json, .claude/settings.local.json) отключает автоподключение даже при управляемом true.
  • default: очистить ваш выбор и следовать значению по умолчанию, заданному администратором вашей организации, если оно установлено, иначе текущему значению по умолчанию Claude Code. Если вы задали DISABLE_TELEMETRY или DO_NOT_TRACK, см. Автоподключение при заданных DISABLE_TELEMETRY или DO_NOT_TRACK.

Расширение VS Code и приложение Desktop также имеют переключатель автоподключения:

  • Расширение VS Code: Enable Remote Control for all sessions в разделе Settings меню команд.
  • Приложение Desktop: Connect new sessions to Remote Control в Settings > Code или Settings > Claude Code. См. Управление тем, какие сессии появляются на других ваших устройствах.

Чтобы вместо этого включить автоподключение из файла настроек, задайте для remoteControlAtStartup значение true в вашем пользовательском файле ~/.claude/settings.json или в управляемых настройках. В настройках проекта или локальных настройках (.claude/settings.json, .claude/settings.local.json) Claude Code учитывает false и отключает автоподключение для этого репозитория. Значение true там игнорируется, поэтому вы не можете использовать файл, добавленный в репозиторий, чтобы включить Remote Control для всех, кто открывает репозиторий.

Автоподключение входит с вашей собственной учетной записью claude.ai, поэтому сеанс, который оно запускает, появляется только в приложениях Claude вашей собственной учетной записи и не предоставляет доступ никому другому.

С этим параметром включенным, каждый интерактивный процесс Claude Code регистрирует один удаленный сеанс. Если вы запускаете несколько экземпляров, каждый получает свой собственный удаленный сеанс. Чтобы запустить несколько одновременных сеансов из одного процесса, используйте вместо этого режим сервера.

Автоподключение при заданных DISABLE_TELEMETRY или DO_NOT_TRACK #

Если задана только DISABLE_TELEMETRY или DO_NOT_TRACK, ваши сессии не подключаются автоматически через значение по умолчанию, заданное администратором вашей организации, или собственное значение по умолчанию Claude Code. Если Remote Control недоступен для вас по другой причине, например из-за CLAUDE_CODE_DISABLE_FEATURE_FLAGS или LLM-шлюза, начните вместо этого с раздела Требования.

Прежде чем включать автоподключение, когда задана только DISABLE_TELEMETRY или DO_NOT_TRACK, убедитесь, что ваша версия Claude Code соответствует требованию для этих переменных. Затем проверьте, требует ли ваша организация Trusted Devices:

  • Не требует: установите Enable Remote Control for all sessions в true в /config.
  • Требует: Remote Control недоступен, пока задана DISABLE_TELEMETRY или DO_NOT_TRACK. Удалите ту из двух переменных, которую вы задали. Если ваши сессии по-прежнему не подключаются автоматически, установите Enable Remote Control for all sessions в true в /config.

Возобновление сеансов после остановки сервера #

Когда вы останавливаете claude remote-control с помощью Ctrl+C, сеансы, которые он обслуживал, перестают отвечать с вашего телефона или браузера. Пока вы не запускали другой claude remote-control в том же каталоге и не запустили этот с --no-create-session-in-dir, Claude Code их не архивирует. Чтобы их вернуть, запустите одну из этих команд в том же каталоге:

  • claude remote-control: возвращает каждый сеанс, который обслуживал сервер.
  • claude remote-control --continue: возвращает только сеанс, с которого сервер начал, и выходит, когда этот сеанс заканчивается. Если в этом каталоге нет записи, Claude Code использует самый новый из других git worktrees этого репозитория.
  • claude remote-control --session-id <id>: возвращает только сеанс, чей ID вы передали, и выходит, когда этот сеанс заканчивается. ID — это часть URL сеанса на claude.ai/code между /code/ и любым ?.

Эти команды работают примерно четыре часа после остановки сервера. После этого запустите claude remote-control для запуска нового сеанса. Если вы архивировали сеанс в то же время, --continue и --session-id разархивируют его на Claude Code v2.1.228 или позже.

Чтобы вернуть сессию, которую вы запустили с помощью claude --remote-control или /remote-control, возобновите диалог с помощью claude --continue или claude --resume. О режиме разрешений, в котором запускается возобновленный диалог, см. режим разрешений при возобновлении. Если Remote Control не переподключится, см. Не удалось переподключиться к вашей сессии Remote Control.

Если вы возобновляете разговор во втором терминале, пока первый все еще имеет Remote Control включенным, Claude Code выводит уведомление Remote Control not started here во втором терминале и оставляет Remote Control отключенным там вместо того, чтобы забирать сеанс у первого. Запустите /remote-control во втором терминале, чтобы переместить Remote Control на него.

Когда вы возобновляете разговор в Claude Desktop или расширении IDE, которое имело Remote Control включенным, Claude Code переподключает его к существующему сеансу claude.ai вместо добавления нового в список сеансов.

Установка режима запуска по умолчанию для проекта #

Если claude remote-control выводит при запуске Spawn mode: <mode> (saved for this folder; press w to change), сервер запускается в режиме запуска, ранее сохраненном для этого проекта.

Сохраненный режим берется из выбора, который вы сделали в своем собственном терминале. Если claude remote-control спросил там Spawn mode for this project:, Claude Code сохранил ваш ответ: 1 для same-dir или 2 для worktree. Если вы нажали w во время его работы, Claude Code сохранил режим, на который вы переключились, даже при запуске с --spawn same-dir или --spawn worktree.

  • Пока сервер работает в режиме same-dir или worktree, нажмите w в терминале сервера, чтобы переключиться на другой режим. Для переключения требуется Git-репозиторий или хук WorktreeCreate.
  • Чтобы использовать другой режим для одного запуска, передайте --spawn <mode>.

Подключение и безопасность #

Ваш локальный сеанс Claude Code выполняет только исходящие HTTPS запросы и никогда не открывает входящие порты на вашем компьютере. Когда вы запускаете Remote Control, он регистрируется в API Anthropic и опрашивает работу. Когда вы подключаетесь с другого устройства, сервер маршрутизирует сообщения между веб-клиентом или мобильным клиентом и вашим локальным сеансом через потоковое соединение.

Весь трафик проходит через API Anthropic через TLS, тот же транспортный протокол безопасности, что и любой сеанс Claude Code. Соединение использует несколько краткосрочных учётных данных, каждое из которых ограничено одной целью и истекает независимо.

Пока Remote Control подключен, стенограмма сеанса, включая ваши сообщения, ответы Claude и активность инструментов, хранится на серверах Anthropic. Сохраненная стенограмма синхронизирует беседу на всех ваших устройствах и позволяет сеансу переподключиться после разрыва сети. Выполнение и доступ к файловой системе остаются на вашем компьютере, а сохраненные стенограммы хранятся в соответствии с политикой Использование данных.

Чтобы полностью отключить Remote Control, используйте параметр disableRemoteControl. Организации с включённым Zero Data Retention или с применённой конфигурацией HIPAA не могут включить Remote Control.

Доверенные устройства #

[!NOTE]

Доверенные устройства в настоящее время находятся в бета-версии. Функции и возможности могут развиваться по мере совершенствования опыта.

Доверенные устройства доступны на планах Pro, Max, Ultra, Team и Enterprise и отключены по умолчанию. На планах Team и Enterprise Owner включает эту функцию для организации. На планах Pro, Max и Ultra вы сами включаете Require trusted devices в своих настройках на странице Cowork или Account.

Доверенные устройства требуют проверенного устройства, прежде чем вы сможете просматривать сессии Remote Control или управлять ими из claude.ai, мобильных приложений Claude или Claude Desktop. Это требование распространяется на каждого члена вашей организации или только на вас на плане Pro, Max или Ultra. Это связывает доступ Remote Control с известным устройством и недавней аутентификацией, а не просто с учётной записью, в которую выполнен вход.

Когда параметр включен, взаимодействие с сеансом Remote Control требует обоих следующих условий:

  • Зарегистрированное устройство: каждый браузер, телефон или приложение для рабочего стола, которое член использует для Remote Control, регистрирует свои собственные учётные данные. Регистрация предлагается только вскоре после полного входа, поэтому устройство присоединяется к списку доверенных как часть реальной аутентификации, а не молча в фоновом режиме.
  • Недавний вход: вход члена должен быть не старше 18 часов. Вместо входа каждый день члены подтверждают присутствие с помощью Face ID, Touch ID, Windows Hello или passkey. Этот биометрический шаг повышения уровня немедленно обновляет сеанс.

Биометрические проверки выполняются на устройстве через операционную систему или браузер, тот же механизм, что и вход с passkey. Anthropic никогда не получает и не хранит отпечатки пальцев, данные лица или любую другую биометрическую информацию. Хранятся только открытый ключ устройства и основные метаданные, такие как отображаемое имя, платформа и время регистрации.

Настройка применяется к Remote Control в Claude Code и к Computer access в Cowork. На этой странице рассматривается сторона Claude Code. Обычный чат Claude, Claude Code в терминале и использование API не затронуты.

Включение доверенных устройств для организации Team или Enterprise #

Владелец включает параметр из параметров организации claude.ai.

1. Перейдите на страницу Capabilities

Перейдите на Organization settings > Capabilities > Remote sessions. Переключатель Require trusted devices появляется в этом разделе.

2. Включите Require trusted devices

Параметр применяется к каждому члену организации и к сеансам Remote Control, запущенным после включения переключателя. Сеансы, которые уже работали до включения переключателя, не защищены задним числом и продолжают работать без требования устройства до их завершения. Область действия для каждой команды или проекта недоступна.

3. Сообщите членам, чего ожидать

В первый раз, когда член просматривает или управляет новым сеансом Remote Control из браузера, телефона или приложения для рабочего стола после включения параметра, ему предлагается зарегистрировать это устройство. Предварительное уведомление избегает путаницы.

Что видят члены #

Регистрация — это одноразовый шаг для каждого устройства. После этого единственное видимое изменение — это случайный биометрический запрос.

  • Первое использование на каждом устройстве: члену предлагается зарегистрировать устройство. Если его вход не свежий, он сначала входит через ваш обычный процесс, включая SSO, если настроен, а затем подтверждает регистрацию.
  • День за днём: члены с зарегистрированным устройством и свежим входом не видят никаких запросов. Когда вход становится старше 18 часов, следующее взаимодействие Remote Control показывает один запрос Face ID, Touch ID, Windows Hello или passkey.
  • Незарегистрированные устройства: сеансы Remote Control не могут быть просмотрены или управляться до регистрации устройства. Обычный чат Claude на этом устройстве не затронут.
  • Без аутентификатора платформы: члены на машине без Face ID, Touch ID или Windows Hello могут использовать аппаратный ключ безопасности или войти снова вместо повышения уровня.
  • В терминале: машина, на которой работает Claude Code, получает свои собственные учётные данные автоматически, когда разработчик входит в CLI. В терминале нет отдельного шага регистрации.

Управление зарегистрированными устройствами #

Члены могут просматривать и отзывать свои собственные устройства из параметров учётной записи.

Откройте claude.ai/settings/account и найдите раздел Trusted devices, чтобы увидеть каждое зарегистрированное устройство с его именем, платформой и датой регистрации. Удаление устройства немедленно отзывает его учётные данные, и устройство может повторно зарегистрироваться позже после свежего входа. Учётные данные также истекают самостоятельно, если не обновляются, поэтому неиспользуемое устройство автоматически исчезает из списка доверенных.

Для потерянного или украденного устройства член удаляет его с этой страницы. Если член не может войти, администратор может использовать Sign out everywhere в консоли администратора, чтобы отозвать каждый сеанс и зарегистрированное устройство для этого члена, после чего член повторно регистрирует устройства, которые он всё ещё держит.

Remote Control и облачные сеансы #

Remote Control и облачные сеансы используют интерфейс claude.ai/code. Ключевое различие заключается в том, где выполняется сеанс: Remote Control выполняется на вашем компьютере, поэтому ваши локальные MCP серверы, инструменты и конфигурация проекта остаются доступными. Облачный сеанс выполняется на облачной инфраструктуре, управляемой Anthropic по умолчанию.

Используйте Remote Control, когда вы находитесь в процессе локальной работы и хотите продолжить с другого устройства. Используйте облачный сеанс, когда вы хотите начать задачу без какой-либо локальной настройки, работать с репозиторием, который у вас не клонирован, или запускать несколько задач параллельно. Проект объединяет оба подхода: его потоки выполняются в облаке, и он использует Remote Control для запуска потока на вашем компьютере, когда вы просите это там.

Claude Code предлагает несколько способов работы, когда вы находитесь не у терминала. Они отличаются тем, что запускает работу, где работает Claude, и сколько настроек вам нужно выполнить.

Мобильные push-уведомления #

Когда Remote Control активен, Claude может отправлять push-уведомления на ваш телефон.

Push-уведомление может прийти, когда завершается долгоживущая задача или когда Claude нужно ваше решение. Вы также можете запросить push-уведомление в своем промпте, например notify me when the tests finish. Помимо двух переключателей включения/выключения ниже, нет конфигурации для отдельных событий.

Чтобы настроить мобильные push-уведомления:

1. Установите мобильное приложение Claude

Загрузите приложение Claude для iOS или Android.

2. Войдите с помощью своей учетной записи Claude Code

Используйте ту же учетную запись и организацию, которые вы используете для Claude Code в терминале.

3. Разрешите уведомления

Примите запрос разрешения на уведомления от операционной системы.

4. Включите push в Claude Code

В вашем терминале запустите /config и включите Push when Claude decides для проактивных уведомлений, Push when actions required для запросов разрешений и вопросов, или оба варианта.

Если уведомления не приходят:

  • Если /config показывает No mobile registered, откройте приложение Claude на вашем телефоне, чтобы оно могло обновить свой push-токен. Предупреждение исчезает при следующем подключении Remote Control.
  • На iOS режимы Focus и сводки уведомлений могут подавлять или задерживать push-уведомления. Проверьте Settings → Notifications → Claude.
  • На Android агрессивная оптимизация батареи может задержать доставку. Исключите приложение Claude из оптимизации батареи в системных параметрах.

Claude Code пропускает мобильные push-уведомления, пока вы печатаете или сосредоточены на подключенном терминале. Чтобы расширить это на любое время, когда вы находитесь у машины, даже в другом окне, установите CLAUDE_CLIENT_PRESENCE_FILE на путь файла-маркера: уведомления пропускаются, пока файл существует. Настройте прослушиватель блокировки экрана или аналогичный инструмент для создания файла при разблокировке экрана и удаления его при блокировке экрана.

Ограничения #

  • Одна удалённая сессия на интерактивный процесс: вне серверного режима каждый экземпляр Claude Code поддерживает только одну удалённую сессию одновременно. Используйте серверный режим, чтобы запускать несколько параллельных сессий из одного процесса.
  • Локальный процесс должен продолжать работать: Remote Control работает как локальный процесс. Если вы закроете терминал, выйдете из приложения Desktop или VS Code, в котором сессия выполняется на вашей машине, либо иным образом остановите процесс claude, сессия перейдёт в офлайн, пока вы не вернёте её. Если вы запускаете claude из терминала на удалённой машине, запускайте его внутри tmux или screen, чтобы сессия продолжала работать после отключения от SSH.
  • Аварийно завершившиеся сессии в серверном режиме: если сессия, обслуживаемая claude remote-control, аварийно завершилась, отправьте ей сообщение с подключённого устройства. Claude Code снова начнёт её обслуживать. Перезапускать сервер не нужно. Требуется Claude Code v2.1.238 или новее.
  • Отказы HTTP 403 в подключённой сессии: после подключения интерактивной сессии Claude Code продолжает повторять попытки в течение трёх минут, если что-то между вашей машиной и серверами Anthropic отвечает HTTP 403, что может произойти после смены VPN или сети. Если отказы продолжаются дольше, Claude Code отключается, а в причине указывается, что именно отказало: пограничный узел сети либо прокси, VPN или файрвол в вашей собственной сети.
  • Длительный сбой сети: если ваша машина не спит, но не может подключиться к сети, дальнейшие действия зависят от режима:
  • Серверный режим: Claude Code прекращает попытки примерно через 10 минут, и процесс claude remote-control завершается. Чтобы перезапустить сервер, см. Возобновление сессий после остановки сервера.
  • Интерактивная сессия: продолжайте работать локально. Claude Code повторяет попытки всё время, пока длится сбой, и переподключается сам, когда сеть восстанавливается.
  • Вложения, которые не загружаются: если файл, прикреплённый вами с телефона или в браузере, не удаётся загрузить на вашу машину, Claude всё равно получает ваше сообщение и загруженные файлы. Вместо отсутствующих файлов Claude Code добавляет к сообщению примечание, например [1 of 3 attachments did not arrive].
  • Сбой сигналов присутствия: если интерактивная сессия отключается с сообщением could not reach the Remote Control server for about 30 minutes, выполните /remote-control, чтобы переподключиться.
  • Пересылаемые диалоги истекают: Claude Code держит запросы разрешений и вопросы AskUserQuestion открытыми, пока вы на них не ответите. Когда Claude Code пересылает в удалённую сессию диалог другого типа, например промпт выбора модели, показываемый после отказа по соображениям безопасности, он по умолчанию ждёт пять минут, затем закрывает диалог и продолжает с вариантом диалога по умолчанию, не предполагающим действий. Задайте dialogExpiry, чтобы изменить или отключить этот срок. Требуется Claude Code v2.1.224 или новее.
  • Неотвеченные промпты согласия на кредиты использования Fable завершают ход: если никто не ответит на промпт согласия на кредиты использования Fable до истечения срока dialogExpiry, ход завершается и ничего не отправляется; см. The prompt to confirm went unanswered. В интерактивной сессии в терминале этот промпт также может появиться на вашем подключённом устройстве, и вы можете ответить на него там. Требуется Claude Code v2.1.323 или новее.
  • Некоторые команды доступны только локально: команды, которые работают только в терминальном интерфейсе, например /plugin или /resume, работают только из локального CLI, независимо от того, передаёте ли вы аргумент. /claude-api также недоступна, если вводить её с мобильного устройства или в вебе. Claude всё же может загрузить этот скилл самостоятельно и там. С мобильного устройства и в вебе работают следующие команды:
  • Команды с текстовым выводом: /compact, /clear, /context, /usage, /exit, /usage-credits, /recap и /reload-plugins. /usage-credits отвечает текстом, например сообщает, где управлять кредитами использования. /reload-plugins работает, только когда сессия выполняется в интерактивном терминале; сессия без него отклоняет эту команду.
  • /model, /effort, /fast, /color и /rename: передайте значение как аргумент, например /model sonnet или /effort high. С мобильного устройства и в вебе /model и /effort принимают аргумент вместо терминального меню выбора или ползунка.
  • /mcp: в мобильном приложении возвращает текстовую сводку состояния серверов вместо открытия меню выбора. В вебе /mcp без аргументов открывает каталог коннекторов claude.ai вместо возврата сводки. Подкоманды reconnect, enable и disable работают в обоих случаях, когда сессия выполняется в интерактивном терминале. /mcp reconnect без имени сервера повторяет попытку для каждого сервера, который дал сбой или требует аутентификации. Чтобы авторизовать коннектор claude.ai без меню выбора, см. Повторная авторизация коннектора из оболочки.
  • /config: в мобильном приложении передайте key=value, чтобы задать настройку, или выполните команду без аргумента, чтобы вывести список ключей, которые можно задать. В вебе /config вместо этого открывает Settings > Code или Settings > Claude Code.
  • Если вы участник Team или Enterprise без доступа к биллингу, команда /usage-credits с мобильного устройства или в вебе не отправляет запрос кредитов использования вашему администратору. Для отправки требуется подтверждение, которое появляется только в интерактивном CLI, поэтому команда предлагает вам выполнить её там.
  • /autocompact, начиная с v2.1.221: передайте размер окна как аргумент, например /autocompact 500k. Без аргумента команда выводит текущий размер окна в виде текста вместо открытия диалога, который она показывает в терминальной сессии.
  • /advisor, начиная с v2.1.260: передайте модель как аргумент, например /advisor opus, или передайте off, чтобы отключить советника. Обе формы применяются только к текущей сессии и не меняют сохранённое значение по умолчанию. Без аргумента команда выводит текущего советника в виде текста вместо открытия меню выбора.
  • /output-style, начиная с v2.1.269: передайте имя стиля как аргумент, например /output-style concise, или выполните команду без аргумента, чтобы вывести список стилей. С мобильного устройства и в вебе можно просматривать и выбирать только встроенные стили. Чтобы использовать пользовательский стиль, выберите его в самой сессии.
  • /focus, начиная с v2.1.281: передайте on или off как аргумент, например /focus on, или выполните команду без аргумента, чтобы переключить режим фокуса. Обе формы применяются только к текущей сессии и не меняют сохранённый выбор.

Повторная авторизация коннектора из оболочки #

Когда коннектору claude.ai требуется аутентификация в сессии, которой вы управляете через Remote Control, панель /mcp недоступна в мобильном приложении или в веб-версии. Получите ссылку для авторизации в терминале на машине, где выполняется сессия, а затем откройте ссылку на устройстве, которое вы используете. Запустить команду из мобильного приложения или веб-версии нельзя. Строка, которую вы отправляете оттуда и которая начинается с !, передаётся Claude как сообщение и не выполняется в режиме оболочки.

1. Получите ссылку для авторизации

В терминале на машине, где выполняется сессия, например через SSH, выполните claude mcp login, указав имя коннектора в кавычках. Имя коннектора начинается с claude.ai, например claude.ai Slack для коннектора Slack. Следующая команда получает ссылку для коннектора Slack:

```bash theme={null} claude mcp login "claude.ai Slack" --no-browser


Команда выводит ссылку на claude.ai и завершает работу. Откройте ссылку в браузере и завершите авторизацию на claude.ai. `--no-browser` не даёт команде открыть браузер на этой машине, которая может не быть устройством, которое вы используете.

**2. Используйте коннектор в сессии**

Запустите новую сессию или переподключите коннектор в уже работающей сессии:

* **Новая сессия**: сессия, которую вы запускаете после авторизации, подключается к коннектору без каких-либо дополнительных действий.
* **Работающая сессия**: выполните `/mcp reconnect` с тем же именем без кавычек в промпте Claude Code или из мобильного приложения или веб-версии. Чтобы проверить, принимает ли ваша сессия эту команду оттуда, см. пункт `/mcp` в разделе [какие команды работают из мобильного приложения и веб-версии](#limitations).

Следующая команда переподключает коннектор Slack:

/mcp reconnect claude.ai Slack


В терминале Claude Code выводит `Successfully reconnected to claude.ai Slack`. В мобильном приложении или веб-версии ответ будет `Reconnected "claude.ai Slack".`

## Устранение неполадок

### "Remote Control disconnected" or "Can't reach"

На [claude.ai/code](https://claude.ai/code) или в приложении Desktop сообщение **Remote Control disconnected** или **Can't reach** означает, что ваш браузер или приложение потеряли связь с Claude Code на вашем компьютере. Ни одно из этих сообщений не говорит о том, продолжает ли Claude или субагент, за которым вы следили, работать на вашем компьютере. На этом компьютере проверьте, в каком состоянии находится Claude Code, и выполните соответствующий шаг для повторного подключения:

* **Интерактивная сессия показывает `Remote Control disconnected`**: выполните [шаги повторного подключения для причины, указанной в этой строке](#session-ended-elsewhere)
* **Claude Code работает и не показывает ошибок**: интерактивная сессия переподключается сама, как только машина выходит из спящего режима и подключается к сети, поэтому вам не нужно ничего делать. Если вы использовали `claude remote-control`, см. **Extended network outage** в разделе [Ограничения](#limitations)
* **Claude Code не запущен**: [запустите его снова и верните сессию](#resume-sessions-after-stopping-the-server)

### "Remote Control requires a claude.ai subscription"

Вы не вошли с учётной записью claude.ai, или другие учётные данные имеют приоритет над вашим входом. Сообщение имеет одну из следующих форм:

* Вы не вошли, запуск через `/remote-control` или `--remote-control`: `Remote Control requires a claude.ai subscription.` или `/remote-control requires a claude.ai subscription.`
* Вы не вошли, запуск через `claude remote-control`: `You must be logged in to use Remote Control. Remote Control is only available with claude.ai subscriptions.`
* Вы вошли, но используется API-ключ или токен: `Remote Control requires claude.ai subscription auth.`, за которым следуют используемые учётные данные, например `ANTHROPIC_API_KEY is set, so this session is using API-key auth`. Настройка `apiKeyHelper` и `ANTHROPIC_AUTH_TOKEN` указываются таким же образом.

Выполните `claude auth login` и выберите вариант claude.ai. Если в сообщении указан `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN`, удалите эту переменную везде, где она задана: в окружении вашей оболочки или в блоке `env` [файла настроек](https://code.claude.com/docs/ru/settings-reference.md#env). Если указан `apiKeyHelper`, удалите эту настройку.

### "Remote Control requires a full-scope login token"

Вы прошли аутентификацию с помощью долгоживущего токена из `claude setup-token` или переменной окружения `CLAUDE_CODE_OAUTH_TOKEN`. Такие токены могут только отправлять запросы к модели, поэтому не могут устанавливать сессии Remote Control. Вместо этого выполните `claude auth login`, чтобы пройти аутентификацию с сессионным токеном полного доступа.

### "Unable to determine your organization for Remote Control eligibility"

Кешированная информация о вашей учётной записи устарела или неполна. Выполните `claude auth login`, чтобы обновить её.

### "Remote Control isn't enabled for this account"

Claude Code проверил доступность Remote Control для учётной записи, под которой вы вошли, и проверка показала, что функция отключена. Обычная причина — устаревшие кешированные права доступа после смены тарифа. Выполните `claude auth logout`, затем `claude auth login`, чтобы обновить их, и обновите Claude Code, если у вас старая версия.

Выполните `claude doctor`, чтобы увидеть, какая именно проверка доступности не прошла. Конфликты переменных окружения, недоступность проверок и настройка Remote Control вашей организации выдают каждая своё сообщение, поэтому эта ошибка относится именно к проверке на уровне учётной записи.

До v2.1.239 это сообщение звучало как "Remote Control is not yet enabled for your account".

### "Couldn't verify Remote Control eligibility"

Claude Code не смог связаться со службой feature-флагов, чтобы проверить, включён ли Remote Control для вашей учётной записи, — обычно потому, что вы не в сети или прокси блокирует запрос. Повторите попытку, когда появится доступ к сети, или выполните `claude doctor` для получения подробностей. Связанное сообщение "Couldn't verify your organization's Remote Control policy" означает, что Claude Code столкнулся с ошибкой при чтении этой политики; решение то же самое.

### "Remote Control requires feature-flag evaluation"

Задана [переменная окружения](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), отключающая вычисление feature-флагов, и полное сообщение называет переменную, которую обнаружил Claude Code. В версиях до 2.1.154 та же конфигурация вместо этого выдаёт "Remote Control is not yet enabled for your account". Что делать, зависит от переменной, указанной в сообщении:

* **`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` или `DISABLE_GROWTHBOOK`**: удалите (unset) переменную везде, где она задана, — в окружении вашей оболочки или в блоке `env` [файла `settings.json`](https://code.claude.com/docs/ru/settings-reference#all-settings).
* **`DISABLE_TELEMETRY` или `DO_NOT_TRACK`**: на тарифе Pro, Max, Ultra, Team или Enterprise при незаданных `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` и `DISABLE_GROWTHBOOK` эти переменные оставляют Remote Control доступным, если только ваша организация не требует [Trusted Devices](#trusted-devices). Если требует, удалите (unset) переменную везде, где она задана, чтобы использовать Remote Control. В версиях с v2.1.154 по v2.1.282 это сообщение появляется при заданной любой из этих переменных, поэтому обновите Claude Code до версии, соответствующей [требованию для этих переменных](#requirements).

### "Remote Control is only available when using Claude via api.anthropic.com"

Сессия взаимодействует с Anthropic API не напрямую, а Remote Control этого требует. Так происходит на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry. Это также происходит, когда [`ANTHROPIC_BASE_URL`](https://code.claude.com/docs/ru/env-vars) указывает на хост, отличный от `api.anthropic.com`, например на [LLM-шлюз](https://code.claude.com/docs/ru/llm-gateway) или прокси, даже если вы входите через claude.ai. Полный список причин см. в [справочнике ошибок](https://code.claude.com/docs/ru/errors.md#remote-control-requires-the-anthropic-api).

В сообщении указано, что направило сессию в обход Anthropic API, например `CLAUDE_CODE_USE_BEDROCK` или пользовательский `ANTHROPIC_BASE_URL`. Если у вас есть подходящий вход через claude.ai, удалите указанную переменную, уберите её из ключа `env` в [настройках](https://code.claude.com/docs/ru/settings.md), если вы задавали её там, и перезапустите сессию.

### "Remote Control is disabled by your organization's policy"

Remote Control заблокирован политикой. Проверьте следующие причины по порядку:

* **В ошибке упоминается `disableRemoteControl`**: ваш ИТ-администратор отключил Remote Control на этом устройстве через [управляемые настройки](https://code.claude.com/docs/ru/managed-settings.md), независимо от переключателя на уровне организации и от того, как вы вошли.
* **Ваш тариф claude.ai — Pro, Max или Ultra**: Claude Code всё ещё авторизован под организацией Team или Enterprise после предыдущего входа, поэтому проверяет политику Remote Control этой организации. Выполните `/status`, чтобы увидеть, какой тариф и организацию использует ваш вход. Выполните `claude auth logout`, затем `claude auth login`, чтобы войти заново под текущим тарифом.
* **Сообщение не предлагает обратиться к администратору организации**: к вашей организации применена [конфигурация HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md), которая отключает Remote Control. Чтобы убедиться в этом, выполните `/status` и найдите `HIPAA` в строке `Organization configuration`. Owner видит переключатель **Remote Control** неактивным в [настройках администратора](https://claude.ai/admin-settings/claude-code) и не может его включить. Если у вас есть вопросы о конфигурации, обратитесь к Owner, который может связаться с командой Anthropic, обслуживающей вашу организацию. До v2.1.267 в этом случае вместо этого показывалось "Remote Control isn't available for your organization due to its compliance policy".
* **Remote Control работает у других сотрудников вашей организации, но не у вас**: если ваша организация Enterprise управляет вашим доступом с помощью [пользовательских ролей](https://support.claude.com/en/articles/13930452), причиной могут быть ваши роли. Для Remote Control нужны и разрешение на облачные сессии, и разрешение **Claude Code remote control**. Попросите Owner проверить, включают ли ваши роли оба разрешения, и добавить недостающее в [**Organization settings > Roles**](https://claude.ai/admin-settings/roles).
* **Owner видит баннер [Zero Data Retention](https://code.claude.com/docs/ru/zero-data-retention.md) в [настройках администратора](https://claude.ai/admin-settings/claude-code)**: Remote Control недоступен для вашей организации, и Owner не может его включить.
* **В остальных случаях Owner не включил его для вашей организации**: на тарифах Team и Enterprise Remote Control по умолчанию отключён. Owner может включить его на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code), включив переключатель **Remote Control**. Этот переключатель — серверная настройка организации.

До v2.1.281 это сообщение также появлялось, когда Claude Code не загрузил политику вашей организации на этой машине, например после запуска без сети. Более поздние версии сообщают об этом состоянии как [`Couldn't verify your organization's policy for remote control`](#couldnt-verify-your-organizations-policy-for-remote-control).

### "Remote Control was turned off by your organization's policy"

Политика вашей организации перестала разрешать Remote Control, пока сессия была подключена, поэтому Claude Code отключил её. Что происходит с сессией, зависит от того, как вы запустили Remote Control:

* **Через `/remote-control`, `claude --remote-control` или [автоподключение](#enable-remote-control-for-all-sessions)**: сессия продолжает работать без Remote Control, а Claude Code архивирует её на claude.ai
* **Через `claude remote-control`**: сервер останавливается и архивирует обслуживаемые им сессии, затем завершает работу

Чтобы снова найти одну из этих сессий, откройте [архивированные сессии](https://code.claude.com/docs/ru/claude-code-on-the-web.md#find-an-archived-session) на claude.ai/code.

Remote Control не переподключается сам. Чтобы снова включить его после того, как ваша организация снова его разрешит, выполните `/remote-control` в сессии или `claude remote-control` в оболочке. Любая из этих команд завершается с ошибкой [`Remote Control is disabled by your organization's policy`](#remote-control-is-disabled-by-your-organizations-policy), пока Claude Code на этой машине не получит изменённую политику. Открытая сессия получает её примерно раз в час. Чтобы выяснить, что блокирует Remote Control, сопоставьте полный текст, который выводит команда, с этим разделом.

### "Couldn't verify your organization's policy for remote control"

Claude Code не смог получить политику вашей организации, и на этой машине нет её сохранённой копии, которую можно было бы использовать вместо неё, поэтому он держит Remote Control отключённым, пока не сможет подтвердить, что ваша организация его разрешает. Обычно это происходит, когда вы запускаете Claude Code без сети или до подключения VPN, либо когда прокси мешает запросу. При медленном соединении сообщение также может появиться, пока первый запрос ещё выполняется.

Сообщение имеет одну из следующих форм:

* Из `/remote-control`, `claude remote-control` или `claude --remote-control`: `Couldn't verify your organization's policy for remote control. Check your network connection and try again.`
* Из [автоподключения](#enable-remote-control-for-all-sessions) при запуске сессии: `couldn't verify your organization's policy — check your network connection and try again` с префиксом `Remote Control failed` в уведомлении и `Remote Control disconnected` в диалоге. После этого сессия оставляет Remote Control отключённым.

Восстановите сетевое подключение, затем выполните `/remote-control` или запустите команду снова. Каждая попытка заново проверяет политику, поэтому перезапускать Claude Code не нужно. Если сообщение продолжает появляться, выполните `claude doctor` и посмотрите строку `Organization policy`, в которой указано, почему политика не загрузилась.

До v2.1.281 в этом состоянии вместо этого показывалось `Remote Control is disabled by your organization's policy`.

### "Remote credentials fetch failed"

Claude Code не смог получить краткосрочные учётные данные от Anthropic API для установки соединения. Чтобы увидеть полную ошибку, запустите сессию из оболочки с отладочным логом, затем найдите в логе `code-session`:

claude --remote-control --debug-file claude-debug.log


Распространённые причины:

* Проблема с сетью или прокси: брандмауэр или прокси может блокировать исходящий HTTPS-запрос. Remote Control требует доступа к Anthropic API через порт 443.
* Не удалось создать сессию: если вы также видите `Session creation failed — see debug log`, сбой произошёл на более раннем этапе настройки. Выполните тот же поиск, чтобы найти ошибку.

### "working folder not found"

В терминале, где запущен [`claude remote-control`](#start-a-remote-control-session), сообщение `Session failed: working folder not found:`, за которым следует путь в кавычках, означает, что сессию не удалось запустить, потому что по этому пути нет папки.

* **Сервер всё ещё работает**: восстановите папку и снова запустите сессию или остановите сервер
* **Сервер завершил работу**: снова выполните `claude remote-control` из существующей папки

До v2.1.318 сессия, завершившаяся таким сбоем, показывала `Session failed: spawn error:` и сообщение `ENOENT`, в котором вместо отсутствующей папки был указан файл программы.

### "The program file this Remote Control started from is gone"

Это предупреждение в терминале, где запущен [`claude remote-control`](#start-a-remote-control-session), означает, что файл программы, из которого был запущен сервер, отсутствует, и новые сессии запускаются на более новой версии, которая его заменила. Чтобы перевести на эту версию и сам сервер, остановите его и снова выполните `claude remote-control`. Если Claude Code установлен в сетевом хранилище, перезапустите сервер сейчас и следуйте разделу [Установка в сетевое хранилище](https://code.claude.com/docs/ru/setup.md#install-on-network-storage). В противном случае новые сессии запускаются без перезапуска.

Когда файл программы отсутствует и Claude Code не находит более новой версии для запуска, новые сессии завершаются сбоем. В терминале отображается ошибка, например `Session failed: spawn error:`, за которой следует сообщение `ENOENT`. Остановите сервер, снова [установите Claude Code](https://code.claude.com/docs/ru/setup.md#install-claude-code), если `claude` не запускается в вашей оболочке, и снова выполните `claude remote-control`. До v2.1.318 новые сессии завершались таким сбоем, даже если была установлена более новая версия.

### "Couldn't reconnect to your Remote Control session"

Когда вы возобновляете диалог с помощью `claude --resume` или `claude --continue`, Claude Code переподключается к сессии Remote Control, записанной в этом диалоге. Это сообщение означает, что переподключение не удалось по причине, которая может быть временной, например из-за прерывания сети или ошибки сервера, поэтому Claude Code не может подтвердить, существует ли ещё удалённая сессия.

Выполните `/remote-control`, чтобы повторить попытку подключения, или запустите новую сессию с `claude --remote-control`, чтобы создать новую сессию Remote Control. Тем временем ваша локальная сессия продолжает работать без Remote Control.

### "Previous session is unavailable — run /remote-control to start a new one"

Claude Code не смог вернуть предыдущую сессию Remote Control и остановился, вместо того чтобы самостоятельно запустить новую. Вы можете увидеть это сообщение после возобновления диалога с помощью `claude --resume` или `claude --continue` либо после того, как Claude Code [самостоятельно переподключится после разрыва соединения](https://code.claude.com/docs/ru/errors.md#remote-control-couldnt-refresh-your-login).

Выполните `/remote-control`, чтобы запустить новую сессию Remote Control под текущим входом; тем временем ваша локальная сессия продолжает работать без Remote Control. Для связанного сообщения `Remote Control could not verify the signed-in account — run /remote-control to reconnect` решение то же самое. Если вы выполните `/remote-control` после `Previous session is unavailable`, не перезапустив предварительно Claude Code, Claude Code не включит более ранние сообщения диалога в новую сессию.

### "Remote Control got an unexpected server response"

Сервер Remote Control принял запрос, но ответил в форме, которую эта версия Claude Code не смогла прочитать, при создании удалённой сессии или получении её учётных данных. Повторная попытка на той же версии завершится так же. Выполните `claude update`, затем `/remote-control`, чтобы переподключиться.

### "Your organization requires Trusted Devices for Remote Control, but this device is not enrolled"

В вашей организации включены [Trusted Devices](#trusted-devices), а эта машина ещё не зарегистрирована. Выполните `/login` в Claude Code. Регистрация происходит в рамках входа, отдельной команды для регистрации нет.

### "session expired for trusted-device check"

Вашему входу более 18 часов. Выполните `/login` в Claude Code или подтвердите вход с помощью Face ID, Touch ID, Windows Hello или ключа доступа, когда claude.ai или мобильное приложение попросят вас об этом. См. [Trusted Devices](#trusted-devices).
