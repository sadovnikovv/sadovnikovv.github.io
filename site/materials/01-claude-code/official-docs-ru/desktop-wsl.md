# Claude Code Desktop в WSL

> Запуск сеансов Code внутри дистрибутива WSL 2 на Windows

На Windows вкладка Code может запускать сеанс внутри дистрибутива WSL 2 вместо самой Windows. Процесс Claude Code сеанса, его инструменты и git выполняются внутри дистрибутива, используя его цепочку инструментов Linux и собственные пути Linux, ту же среду, на которую нацелен ваш проект.

Используйте сеанс WSL, когда ваш репозиторий находится в файловой системе дистрибутива. Работа с этими файлами из Windows проходит через сетевую файловую систему, что медленно и нарушает отслеживание файлов; запуск сеанса внутри дистрибутива избегает обоих этих проблем.

## Требования

* Windows 10 или 11 с [WSL 2](https://learn.microsoft.com/windows/wsl/install). WSL 1 не поддерживается.
* По крайней мере один установленный дистрибутив (например, Ubuntu).
* `git` установлен внутри дистрибутива.

## Запуск сеанса WSL

**1. Выберите дистрибутив**

Запустите новую сессию на вкладке Code и откройте [средство выбора среды](https://code.claude.com/docs/ru/desktop.md#start-a-session) под полем ввода промпта или над ним в [более раннем макете](https://code.claude.com/docs/ru/desktop.md#check-which-layout-you-have). Ваши установленные дистрибутивы WSL 2 появляются в разделе **WSL**. Выберите один.

**2. Выберите папку**

Сессия запускается в домашнем каталоге дистрибутива. Используйте средство выбора папок для выбора папки проекта. Просмотр происходит внутри дистрибутива с путями Linux, такими как `/home/you/project`.

**3. Доверьте папке**

Первая сессия в папке показывает диалог доверия рабочему пространству. Доверие предоставляется для каждого дистрибутива и папки. Папка, которой вы доверяете в одном дистрибутиве, не является доверенной в другом дистрибутиве или по тому же пути на Windows.

Первый сеанс в дистрибутиве занимает немного больше времени, пока Claude настраивается внутри него. Вы также можете открыть папку `\\wsl.localhost\...` из обычного средства выбора папок, и она снова откроется внутри этого дистрибутива.

## Что работает в сеансе WSL

Параллельные сеансы, боковые чаты, визуальный просмотр различий, статус ветви и запроса на слияние, а также worktrees работают, поддерживаемые git и цепочкой инструментов внутри дистрибутива. "Открыть в редакторе" открывает VS Code, подключенный к дистрибутиву через [Remote - WSL](https://code.visualstudio.com/docs/remote/wsl).

Если функция Desktop недоступна или ограничена в сессии WSL, проверьте, не относится ли она к следующим:

* **Терминал и коннекторы**: в вашей сессии может отсутствовать [встроенный терминал](https://code.claude.com/docs/ru/desktop.md#run-commands-in-the-terminal), [коннекторы](https://code.claude.com/docs/ru/desktop.md#connect-external-tools) или и то, и другое. См. раздел [Если терминал или коннекторы недоступны](#check-for-the-terminal-and-connectors).
* **[Плагины](https://code.claude.com/docs/ru/desktop.md#install-plugins)**: недоступны в сессиях WSL
* **Редактирование файлов**: вы можете просматривать файлы в [панели файлов](https://code.claude.com/docs/ru/desktop.md#open-and-edit-files), но не можете редактировать их там, поэтому попросите Claude внести изменения
* **Вложения**: если в меню **+** вместо **Add files or photos** отображается **Add image**, вы можете прикреплять только изображения. См. раздел [Добавление файлов и контекста в промпты](https://code.claude.com/docs/ru/desktop.md#add-files-and-context-to-prompts).

### Если терминал или коннекторы недоступны

Вы не можете самостоятельно включить встроенный терминал или коннекторы для сессии WSL:

* **Аккаунт Claude**: эти две функции развертываются по отдельности. Выберите **Help > Check for Updates…**, и если после обновления функция по-прежнему отсутствует, ничего делать не нужно.
* **[Сторонний провайдер](https://code.claude.com/docs/ru/third-party-integrations.md)**: сессии WSL не получают терминал и коннекторы, и обновление Desktop этого не меняет

## Управляемые устройства

На устройствах, управляемых организацией, сеансы WSL могут быть недоступны. Если запуск сеанса завершается с сообщением об управлении устройством, это контролируется вашим администратором. Администраторы: см. [как параметры достигают устройств](https://code.claude.com/docs/ru/admin-setup.md#decide-how-settings-reach-devices) в руководстве по развертыванию.
