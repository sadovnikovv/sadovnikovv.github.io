# Интерактивный режим

> Полный справочник по сочетаниям клавиш, режимам ввода и интерактивным функциям в сессиях Claude Code.

## Сочетания клавиш

> [!NOTE]
>
> Сочетания клавиш могут различаться в зависимости от платформы и терминала. В [полноэкранном режиме](https://code.claude.com/docs/ru/fullscreen.md) нажмите `?` в средстве просмотра стенограммы, чтобы увидеть доступные там сочетания клавиш.
>
> **Пользователи macOS**: сочетания клавиш с клавишей Option/Alt (`Alt+B`, `Alt+F`, `Alt+D`, `Alt+Y`, `Alt+P`) требуют настройки Option как Meta в вашем терминале. См. [Включение сочетаний клавиш Option на macOS](https://code.claude.com/docs/ru/terminal-config.md#enable-option-key-shortcuts-on-macos) для параметра в каждом терминале.

### Общие элементы управления

| Сочетание клавиш | Описание | Контекст |
| :- | :- | :- |
| `Ctrl+C` | Прерывание или очистка ввода | Прерывает выполняемую операцию. Если ничего не выполняется, первое нажатие очищает ввод промпта, а второе нажатие завершает Claude Code. Чтобы вернуть очищенный черновик, см. [Возврат очищенного черновика](#bring-back-a-cleared-draft) |
| `Ctrl+X Ctrl+K` | Остановить все работающие [фоновые субагенты](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background) в этой сессии и отключить [автоматические ответы на комментарии к артефактам](https://code.claude.com/docs/ru/artifacts.md#let-claude-reply-to-comments-on-its-own) до конца сессии. Нажмите дважды в течение 3 секунд для подтверждения. Сочетание можно нажать, даже когда открыт запрос разрешения фонового субагента | Управление субагентами |
| `Ctrl+D` | Выход из сеанса Claude Code | Первое нажатие показывает подсказку подтверждения, а второе нажатие в течение 800 мс завершает работу. Когда подсказка содержит текст, `Ctrl+D` удаляет символ после курсора |
| `Ctrl+G` или `Ctrl+X Ctrl+E` | Открыть в текстовом редакторе по умолчанию | Отредактируйте свою подсказку или пользовательский ответ в текстовом редакторе по умолчанию. `Ctrl+X Ctrl+E` — это встроенное в readline сочетание. Включите **Show last response in external editor** в `/config`, чтобы добавить предыдущий ответ Claude в виде контекста с комментариями `#` выше вашей подсказки; Claude Code удаляет блок комментариев при сохранении |
| `Ctrl+L` | Перерисовка экрана | Принудительно выполняет полную перерисовку терминала, сохраняя ввод и историю разговора. Используйте это для восстановления, если дисплей становится искаженным или частично пустым. См. [Очистить разговор](https://code.claude.com/docs/ru/fullscreen.md#clear-the-conversation) для полноэкранного режима |
| `Ctrl+O` | Переключение средства просмотра стенограммы | Показывает подробное использование инструментов и выполнение с временной меткой и используемой моделью в каждом сообщении помощника. Также расширяет строки, которые по умолчанию сворачиваются, такие как вызовы MCP, отображаемые как одна строка `Called slack 3 times`, и [сообщения из ваших других сеансов](https://code.claude.com/docs/ru/cross-session-messaging.md#what-a-message-looks-like), отображаемые как предпросмотр в одну строку `Message from @<sender>` |
| `Ctrl+R` | Поиск в истории команд в обратном порядке | Интерактивный поиск по предыдущим командам |
| `Ctrl+V` или `Cmd+V` (iTerm2) или `Alt+V` (Windows и WSL) | Вставить изображение из буфера обмена | Вставляет чип `[Image #N]` в позицию курсора, чтобы вы могли ссылаться на него позиционно в своей подсказке. На WSL привязаны оба `Ctrl+V` и `Alt+V`; используйте `Alt+V`, если ваш терминал перехватывает `Ctrl+V` |
| `Ctrl+B` | Фоновые выполняемые задачи | Переводит команды Bash и агентов в фоновый режим. Пользователи Tmux нажимают дважды |
| `Ctrl+T` | Переключение контрольного списка задач Claude | Показать или скрыть [контрольный список задач Claude](#task-list) в области состояния. Это не представление фоновых задач; используйте [`/tasks`](https://code.claude.com/docs/ru/commands) для просмотра работающих оболочек и подагентов |
| `Ctrl+S` | Сохранить или восстановить подсказку | Если в вводе есть текст, сохраняет его и очищает подсказку. При нажатии снова на пустой подсказке восстанавливает сохраненный текст, позицию курсора, вставленное содержимое и режим ввода, поэтому сохраненная команда shell `!` [shell command](#shell-mode-with-prefix) возвращается в режиме shell |
| `Ctrl+Z` | Приостановить Claude Code | Только Unix. Приостанавливает процесс в вашу оболочку; запустите `fg` для возобновления |
| `Left/Right arrows` | Циклический переход по вкладкам диалога | Навигация между вкладками в диалогах разрешений и меню. В диалоге с вкладками клавиши переключают вкладки, пока строка вкладок имеет фокус. См. [Действия вкладок](https://code.claude.com/docs/ru/keybindings.md#tabs-actions) для информации о том, как перемещается фокус |
| `Tab` | Принять предложение автодополнения или добавить комментарий к ответу разрешения | Пока в вводе подсказки отображаются предложения автодополнения, принимает выбранное предложение. В большинстве подсказок разрешений с сфокусированным **Yes** или **No** открывает поле комментария для этого параметра, а повторное нажатие закрывает поле. См. [добавить комментарий при ответе на подсказку разрешения](https://code.claude.com/docs/ru/permissions.md#add-a-comment-when-you-answer-a-permission-prompt) |
| `Up/Down arrows` или `Ctrl+P`/`Ctrl+N` | Перемещение курсора или навигация по истории команд | Когда ввод занимает более одной визуальной строки, будь то обернутый или многострочный, сначала перемещает курсор в подсказке. Когда курсор находится на первой или последней визуальной строке, повторное нажатие переходит по истории команд. Пока у вас есть очередные сообщения, `Up` с первой строки вместо этого [берет их обратно](#take-back-what-you-queued) |
| `Esc` | Прерывание Claude или закрытие диалога | Остановить текущий ответ или вызов инструмента в середине хода, чтобы вы могли перенаправить. Claude сохраняет выполненную работу. Если у вас есть [очередные сообщения](#queue-messages-while-claude-works), Claude Code отправляет их дальше. Когда диалог открыт, `Esc` закрывает диалог. Пока элемент нижнего колонтитула выбран, такой как строка в [панели подагента](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background) ниже подсказки, `Esc` [отменяет его выбор](https://code.claude.com/docs/ru/keybindings.md#footer-actions) вместо прерывания. На подсказке разрешения `Esc` отклоняет действие, то же самое, что [**No** без комментария](https://code.claude.com/docs/ru/permissions.md#add-a-comment-when-you-answer-a-permission-prompt) |
| `Esc` + `Esc` | Очистить черновик ввода или перемотать | Когда ввод подсказки содержит текст, двойной `Esc` очищает его и сохраняет черновик в историю, чтобы `Up` его вспомнил. Когда ввод пуст, двойной `Esc` открывает [меню перемотки](https://code.claude.com/docs/ru/checkpointing.md) для восстановления или суммирования кода и разговора с предыдущей точки |
| `Ctrl+Enter` или `Ctrl+X Ctrl+S` | Отправить очередные сообщения сейчас | Отправляет ваши [очередные сообщения](#queue-messages-while-claude-works) и ваш черновик с ними прямо сейчас. [Когда Claude Code отправляет то, что вы поставили в очередь](#when-claude-code-sends-what-you-queued) охватывает то, что происходит с ходом, над которым работает Claude. В [режиме shell](#shell-mode-with-prefix) клавиша ставит вашу команду в очередь. В терминалах, которые не сообщают о расширенных клавишах, `Ctrl+Enter` приходит как простой `Enter`; `Ctrl+X Ctrl+S` работает в любом терминале. Требует Claude Code v2.1.275 или более поздней версии |
| `Shift+Tab`, или `Alt+M` на Windows, когда среда выполнения Node или Bun не включает режим ввода VT | Циклический переход по режимам разрешений | Циклический переход через `default` (помечен как Manual в индикаторе режима), `acceptEdits` и `plan`, а затем `bypassPermissions` и `auto`, если они доступны. См. [режимы разрешений](https://code.claude.com/docs/ru/permission-modes.md). В запросе разрешения для файла та же клавиша закрывает открытое [поле комментария](https://code.claude.com/docs/ru/permissions.md#add-a-comment-when-you-answer-a-permission-prompt). Если поле не открыто, она выбирает вариант, разрешающий действие до конца сессии, когда запрос предлагает такой вариант. В запросе на утверждение плана она утверждает план |
| `Option+P` (macOS) или `Alt+P` (Windows/Linux) | Переключение модели | Переключение моделей без очистки подсказки |
| `Option+T` (macOS) или `Alt+T` (Windows/Linux) | Переключение расширенного мышления | Включение или отключение режима расширенного мышления. Не влияет на Opus 5.5, Sonnet 5.5, Haiku 5.5 или модели Fable, которые всегда используют расширенное мышление. Работает на macOS без настройки Option как Meta |
| `Option+O` (macOS) или `Alt+O` (Windows/Linux) | Переключение быстрого режима | Включение или отключение [быстрого режима](https://code.claude.com/docs/ru/fast-mode.md) |

| `Ctrl+E` | Переместить курсор в конец текущей строки | В многострочном вводе перемещает в конец текущей логической строки |

| `Ctrl+W` | Удалить назад до предыдущего пробела | Сохраняет удаленный текст для вставки. Одно нажатие удаляет весь путь или `--flag=value`. Чтобы удалить только предыдущее слово, нажмите `Option+Delete` на macOS или `Ctrl+Backspace` на Windows |

| `Alt+Y` (после `Ctrl+Y`) | Циклический переход по истории вставок | После вставки циклический переход по ранее удаленному тексту. Требует [Option как Meta](#keyboard-shortcuts) на macOS |

| `Alt+F` | Переместить курсор на одно слово вперед | Перемещает в конец текущего слова или в конец следующего слова, когда курсор находится между словами. Требует [Option как Meta](#keyboard-shortcuts) на macOS |
| `Alt+D` | Удалить до конца слова | Удаляет до конца текущего слова или до конца следующего слова, когда курсор находится между словами. Сохраняет удаленный текст для вставки. Требует [Option как Meta](#keyboard-shortcuts) на macOS |
| `Ctrl+_` или `Ctrl+Shift+-` | Отменить последнее редактирование ввода | Восстанавливает предыдущий текст ввода и позицию курсора |

### Границы слов в сочетаниях редактирования

Сочетания слов `Alt+B`, `Alt+F`, `Alt+D`, `Option+Delete` и `Ctrl+Backspace` рассматривают слово как последовательность букв и цифр, поэтому пунктуация, такая как `_`, `.` и `/`, разделяет слова. С `src/utils/foo.ts` в подсказке повторные нажатия `Alt+B` останавливаются в начале `ts`, `foo`, `utils` и `src`.

`Ctrl+W` отличается: он игнорирует пунктуацию и удаляет назад до предыдущего пробела, поэтому одно нажатие удаляет все `src/utils/foo.ts`.

В тексте, написанном без пробелов, таком как китайский или японский, сочетания слов по-прежнему перемещают или удаляют одно слово за раз.

Эти соглашения readline применяются в Claude Code v2.1.261 и более поздних версиях. Параметр [`keybindingFlavor`](https://code.claude.com/docs/ru/settings-reference#keybindingflavor), который включал их в более ранних версиях, устарел и не имеет эффекта.

Вы не можете переназначить эти сочетания в [файле конфигурации сочетаний клавиш](https://code.claude.com/docs/ru/keybindings.md), в котором нет действий для них.

## Команды

Введите `/` в Claude Code, чтобы увидеть доступные вам команды, или введите `/` с последующими буквами для фильтрации. Меню `/` содержит встроенные команды, включённые и созданные пользователем [skills](https://code.claude.com/docs/ru/skills.md), а также команды, предоставленные [plugins](https://code.claude.com/docs/ru/plugins/overview.md) и [MCP servers](https://code.claude.com/docs/ru/mcp.md#use-mcp-prompts-as-commands). Не все встроенные команды видны каждому пользователю, так как некоторые зависят от вашей платформы или плана, и [несколько доступных команд скрыты из меню по замыслу](https://code.claude.com/docs/ru/commands.md#how-the-command-menu-matches-what-you-type) и запускаются при вводе их полного имени.

В [полноэкранном режиме отображения](https://code.claude.com/docs/ru/fullscreen.md#use-the-mouse) команда `/` и списки предложений файлов `@` также реагируют на мышь: наведение выделяет строку, а клик принимает её.

Полный список команд, включённых в Claude Code, см. в [справочнике команд](https://code.claude.com/docs/ru/commands.md).

### Завершение команды в середине подсказки

Завершение команды также работает в середине подсказки: введите `/` после пробела, затем первые буквы имени, как в `run the tests, then /com`. Совпадают только команды, имена которых начинаются с этих букв, поэтому путь файла, такой как `/tmp/notes.md`, не открывает список. Claude Code запускает команду только когда команда [начинает ваше сообщение](https://code.claude.com/docs/ru/commands.md).

* **В [полноэкранном режиме отображения](https://code.claude.com/docs/ru/fullscreen.md)**: совпадения открываются в виде списка во время ввода, без выделенной строки, поэтому `Enter` по-прежнему отправляет вашу подсказку в том виде, в котором она введена. Нажмите `Tab` для вставки верхнего совпадения или выберите строку стрелками и `Enter`.
* **Вне полноэкранного режима**: остаток верхнего совпадения появляется как призрачный текст в вашем курсоре с подсчётом, например `+2`, когда совпадают несколько команд. Нажмите `Tab` для вставки единственного совпадения или для открытия списка, когда совпадают несколько, затем выберите строку стрелками и `Enter`.

В обоих режимах нажмите `Tab` на голом `/` в середине подсказки, чтобы вывести список всех команд.

Skill плагина совпадает и по его простому имени, поэтому `/deploy` находит skill с именем `myplugin:deploy-app`. Когда вы вставляете совпадение, Claude Code записывает полный `/myplugin:deploy-app`.

| Команда | Действие | Из режима |
| :- | :- | :- |
| `Esc` или `Ctrl+[` | Перейти в режим NORMAL. В терминалах, использующих протокол клавиатуры Kitty, `Ctrl+[` требует v2.1.242 или более позднюю версию | INSERT, VISUAL |
| `i` | Вставить перед курсором | NORMAL |
| `I` | Вставить в начало строки | NORMAL |
| `a` | Вставить после курсора | NORMAL |
| `A` | Вставить в конец строки | NORMAL |
| `o` | Открыть строку ниже | NORMAL |
| `O` | Открыть строку выше | NORMAL |
| `v` | Начать выделение по символам | NORMAL |
| `V` | Начать выделение по строкам | NORMAL |

### Переназначение последовательностей клавиш в режиме INSERT

Параметр [`vimInsertModeRemaps`](https://code.claude.com/docs/ru/settings-reference#viminsertmoderemaps) отображает двухклавишную последовательность режима INSERT на Escape, поэтому отображение, такое как `jj`, возвращает вас в режим NORMAL.

Следующий пример `~/.claude/settings.json` включает режим vim и отображает `jj` на Escape:

```json theme={null}
{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}
```

Каждый ключ состоит ровно из двух печатаемых символов, введённых последовательно, и `"<Esc>"` — единственная поддерживаемая цель. Записи с другой длиной или целью игнорируются.

Ввод первого символа последовательности вставляет его обычным образом. Нажатие второго символа в течение одной секунды удаляет этот ожидающий символ и переключается в режим NORMAL, не оставляя ни одного символа в вашем вводе. После истечения окна в одну секунду или если следует другая клавиша, оба символа остаются как буквальный текст, поэтому вы всё ещё можете ввести слово, содержащее последовательность, сделав паузу между двумя клавишами.

Claude Code читает этот параметр из файла пользовательских параметров, флага `--settings` и [управляемых параметров](https://code.claude.com/docs/ru/managed-settings.md) только. Записи в `.claude/settings.json` или `.claude/settings.local.json` проекта игнорируются, поэтому проверенный репозиторий не может переназначить ваши нажатия клавиш.

## История команд

Claude Code сохраняет историю введённых вами подсказок, и вызов с помощью стрелки вверх позволяет получить подсказки из предыдущих сеансов одного проекта:

* История ввода хранится для каждого рабочего каталога
* Выполнение `/clear` начинает новый сеанс: при вызове истории сначала отображаются подсказки нового сеанса, а затем подсказки из более ранних сеансов. Разговор из предыдущего сеанса сохраняется и может быть возобновлен.
* Если вы отправите одну и ту же подсказку дважды подряд, будет записана одна запись в истории, поэтому нажатие стрелки вверх переходит к предыдущей отличающейся подсказке
* Когда вы вызываете промпт, который включал вставленный текст, Claude Code отправляет полное содержимое вставки при повторной отправке. Если содержимое было [очищено](https://code.claude.com/docs/ru/claude-directory.md#cleaned-up-automatically), Claude Code не отправляет буквальную строку `[Pasted text #N]`; см. [Вставка большого содержимого](https://code.claude.com/docs/ru/terminal-config.md#paste-large-content) для информации о том, что происходит с промптом
* Расширение истории с помощью `!` отключено по умолчанию

### Восстановление очищенного черновика

Чтобы вернуть черновик, который вы очистили с помощью `Ctrl+C`, нажмите `Up` — сразу же или после отправки сообщения или команды:

* **Сразу после очистки черновика**: нажмите `Up` один раз, пока поле промпта ещё пусто. Требуется Claude Code v2.1.288 или более поздней версии.
* **После отправки сообщения или команды**: нажмите `Up`, чтобы вернуться к черновику. Claude Code хранит десять последних очищенных черновиков для текущей сессии вместе с их вставленным текстом и изображениями и удаляет их при выходе. Требуется Claude Code v2.1.292 или более поздней версии.

### Обратный поиск с помощью Ctrl+R

Нажмите `Ctrl+R` для интерактивного поиска в истории команд. В [полноэкранном режиме](https://code.claude.com/docs/ru/fullscreen.md) `Ctrl+R` вместо этого открывает диалоговое окно поиска. Вводите текст для фильтрации в диалоговом окне и нажимайте `Up` и `Down` для перемещения по списку совпадений; панель предпросмотра показывает начало выделенного совпадения.

В диалоговом окне нажимайте `Ctrl+S` для переключения области действия поиска между этой сессией, этим проектом и всеми проектами. Нажмите `Enter` или `Tab` для размещения совпадения в поле ввода промпта или `Esc` для отмены. Шаги ниже описывают встроенный поиск классического средства визуализации:

1. **Начать поиск**: нажмите `Ctrl+R` для активации обратного поиска по истории
2. **Введите запрос**: введите текст для поиска в предыдущих командах. Текущее совпадение отображается в поле ввода промпта.
3. **Навигация по совпадениям**: нажмите `Ctrl+R` снова для перемещения по более старым совпадениям
4. **Область поиска**: встроенный поиск всегда ищет подсказки из всех проектов
5. **Принять совпадение**:
   * Нажмите `Tab` или `Esc` для принятия текущего совпадения и продолжения редактирования
   * Нажмите `Enter` для принятия и немедленного выполнения команды
6. **Отмена поиска**:
   * Нажмите `Ctrl+C` для отмены и восстановления исходного ввода
   * Нажмите `Backspace` при пустом поиске для отмены

Чтобы найти более ранний промпт, когда вы помните только что-то длинное, что вставляли в него, например лог ошибок, нажмите `Ctrl+R` и введите слово из вставленного текста. Требуется Claude Code v2.1.314 или более поздней версии.

## Фоновые команды Bash

Claude Code поддерживает запуск команд Bash в фоне, позволяя вам продолжать работу, пока выполняются долгоживущие процессы.

### Как работает фоновое выполнение

Когда Claude Code запускает команду в фоне, она выполняется асинхронно и немедленно возвращает ID фоновой задачи. Claude Code может отвечать на новые запросы, пока команда продолжает выполняться в фоне.

Для запуска команд в фоне вы можете:

* Попросить Claude Code запустить команду в фоне
* Нажать `Ctrl+B` для перемещения обычного вызова инструмента Bash в фон. Пользователи Tmux должны нажать `Ctrl+B` дважды из-за префиксного ключа tmux.

Когда команда достигает своего времени ожидания до завершения, Claude Code автоматически [перемещает её в фон](https://code.claude.com/docs/ru/tools-reference.md#foreground-commands-that-move-to-the-background) вместо остановки, если только команда не начинается с `sleep`. Если вы отключили фоновые команды с помощью [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`](https://code.claude.com/docs/ru/env-vars#variables) или запустив в [режиме bare](https://code.claude.com/docs/ru/headless.md#start-faster-with-bare-mode), команда останавливается при достижении времени ожидания. Чтобы изменить время ожидания, установите [переменные окружения для времени ожидания Bash](https://code.claude.com/docs/ru/tools-reference.md#timeout-and-output-limits).

**Ключевые возможности:**

* Вывод записывается в файл, и Claude может получить его с помощью инструмента Read
* Фоновые задачи имеют уникальные ID для отслеживания и получения вывода
* Фоновые задачи автоматически очищаются при выходе из Claude Code. На macOS и Linux, когда вы останавливаете фоновую задачу из [`/tasks`](https://code.claude.com/docs/ru/commands) или Claude Code останавливает её при выходе, процессы, отделённые от оболочки задачи, такие как запущенные под `setsid` или `timeout`, также останавливаются
* Если вы переводите сеанс в фон вместо выхода, ваши фоновые задачи продолжают работать в фоновом сеансе. См. [перевод работающего сеанса в фон](https://code.claude.com/docs/ru/agent-view.md#from-inside-a-session)
* Фоновые задачи автоматически завершаются, если вывод превышает 5 ГБ, с примечанием в stderr, объясняющим причину
* На macOS и Linux Claude Code останавливает ваши работающие фоновые задачи, когда операционная система сообщает о критическом давлении на оперативную память, при условии, что сессия была неактивна не менее 30 минут и не выполняется ни один ход или субагент
  * [Лог отладки](https://code.claude.com/docs/ru/debug-your-config.md) указывает, почему задачи были остановлены или почему событие давления оставило их работающими
  * Установите [`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`](https://code.claude.com/docs/ru/env-vars) в `1`, чтобы отключить остановки из-за давления на память
* Фоновые команды в локальной сессии, с которой вы работаете из терминала, десктопного приложения или расширения VS Code, не имеют ограничения по времени. В сессии, которая выполняется без присмотра, например при запуске с `-p` или в облачной сессии, Claude Code останавливает фоновую команду по достижении её [ограничения по времени](https://code.claude.com/docs/ru/tools-reference.md#time-limit-for-background-commands)
* Фоновая команда, запущенная переднеплановым [подагентом](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background), заканчивается, когда заканчивается выполнение этого подагента, независимо от того, завершилась ли она, не удалась или была прервана; см. [Когда фоновая команда останавливается](https://code.claude.com/docs/ru/tools-reference.md#when-a-background-command-stops) в справочнике инструментов

Чтобы отключить фоновые команды, установите переменную окружения [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`](https://code.claude.com/docs/ru/env-vars#variables) в `1`. При этом вы также теряете сочетание клавиш `Ctrl+B` и [другие фоновые возможности](https://code.claude.com/docs/ru/env-vars.md#variables), например [запуск скиллов в фоне](https://code.claude.com/docs/ru/skills.md#run-skills-in-a-subagent). Запуск в [режиме bare](https://code.claude.com/docs/ru/headless.md#start-faster-with-bare-mode) даёт тот же эффект.

**Часто используемые фоновые команды:**

* Инструменты сборки (webpack, vite, make)
* Менеджеры пакетов (npm, yarn, pnpm)
* Средства запуска тестов (jest, pytest)
* Серверы разработки
* Долгоживущие процессы (docker, terraform)

### Режим оболочки с префиксом `!`

Запускайте команды оболочки напрямую без участия Claude, добавляя префикс `!` к вашему вводу:

```bash theme={null}
! npm test
! git status
! ls -la
```

Режим оболочки:

* Добавляет команду и её вывод в контекст разговора
* Показывает прогресс и вывод в реальном времени
* Поддерживает то же самое `Ctrl+B` фоновое выполнение для долгоживущих команд
* Не требует от Claude интерпретации или одобрения команды
* Поддерживает автодополнение на основе истории: введите частичную команду и нажмите `Tab` для завершения из предыдущих команд `!` в текущем проекте
* Поддерживает автодополнение пути к файлу в реальном времени: введите токен, содержащий косую черту, такой как `./src/` или `~/`, чтобы увидеть раскрывающийся список совпадающих файлов и каталогов, затем нажмите `Tab` для принятия. Используйте косые черты и на Windows; раскрывающийся список срабатывает на `/`, а не на `\`
* Выход с `Escape`, `Backspace` или `Ctrl+U` на пустой подсказке
* Вставка текста, начинающегося с `!` в пустую подсказку, автоматически входит в режим оболочки, соответствуя поведению введённого `!`

Если ваша сессия не входит в список тех, что указаны в разделе [режим строгой песочницы](https://code.claude.com/docs/ru/sandboxing.md#turn-off-the-retry-with-strict-sandbox-mode), команды, которые вы вводите в режиме оболочки, выполняются вне [песочницы](https://code.claude.com/docs/ru/sandboxing.md) даже если вы включили изоляцию в песочнице, потому что песочница применяется к командам, которые запускает Claude.

Claude автоматически отвечает на вывод команды, как только он попадает в транскрипт, поэтому вы можете запустить `! npm test` и получить объяснение сбоев без второго промпта. Ответ стоит столько же, сколько отправка обычного промпта. Чтобы вместо этого добавлять вывод в контекст без ответа, установите [`respondToBashCommands`](https://code.claude.com/docs/ru/settings-reference#respondtobashcommands) в `false` в `settings.json`.

## Ставьте сообщения в очередь, пока Claude работает

Введите сообщение и нажмите `Enter` пока Claude работает. Claude Code ставит сообщение в очередь вместо прерывания хода, и отображает записи в очереди в диалоге до их отправки. Вы можете ставить в очередь `!` [команды оболочки](#shell-mode-with-prefix) и большинство [команд](https://code.claude.com/docs/ru/commands.md) таким же образом, за исключением команд, таких как `/status`, которые Claude Code выполняет сразу же при их отправке.

Отправленные и поставленные в очередь сообщения отображаются серым цветом до тех пор, пока Claude не начнет на них отвечать, поэтому вы можете видеть, какие сообщения Claude еще не начинал обрабатывать.

Если вы поставите в очередь сообщение с выделением, прикрепленным из [подключенной IDE](https://code.claude.com/docs/ru/vs-code.md#the-built-in-ide-mcp-server), оно сохранит выделение, которое у вас было при нажатии `Enter`, независимо от того, что вы выберете впоследствии.

### Когда Claude Code отправляет то, что вы поставили в очередь

Когда Claude Code отправит запись из очереди, зависит от того, что вы поставили в очередь.

* Сообщения: если вы поставите сообщение в очередь, пока Claude выполняет вызовы инструментов, Claude Code передаст его Claude сразу же после завершения этих вызовов в рамках одного хода. Когда ход заканчивается с оставшимися в очереди сообщениями, они отправляются без дополнительного нажатия клавиши в порядке, в котором вы их набрали
* Команды и команды оболочки: Claude Code удерживает их до конца хода, затем выполняет их по одной, сохраняя порядок, в котором вы их поставили в очередь

Чтобы отправить то, что вы поставили в очередь, не дожидаясь завершения хода, нажмите `Ctrl+Enter`. Ваши сообщения из очереди отправляются сразу же, с вашим черновиком в очереди позади них, если вы что-то набрали. Требуется Claude Code v2.1.275 или позже.

Если вы поставили в очередь команду `!` оболочки перед вашими сообщениями, клавиша прерывает ход. В противном случае, что происходит с ходом, зависит от того, что Claude делает при нажатии клавиши:

* Выполнение команд оболочки, субагентов или другой работы, которая может перейти в [фоновый режим](#background-bash-commands): эта работа переходит в фоновый режим и продолжает выполняться, а Claude читает ваши сообщения в том же ходе
* Только написание ответа или выполнение чего-то, что не может перейти в фоновый режим: Claude Code прерывает ход и отправляет ваши сообщения дальше. До версии v2.1.281 клавиша прерывала ход в обоих случаях

В [режиме оболочки](#shell-mode-with-prefix) клавиша только ставит вашу команду в очередь. В терминалах, которые не сообщают о расширенных клавишах, `Ctrl+Enter` поступает как обычный `Enter` и ставит черновик в очередь; `Ctrl+X Ctrl+S` работает в любом терминале. Обе клавиши являются привязками действия [`chat:sendNow`](https://code.claude.com/docs/ru/keybindings#chat-actions).

Нажмите `Esc` для прерывания хода без отправки вашего черновика. Claude Code сохраняет то, что вы поставили в очередь, и отправляет это сразу же.

Claude Code выполняет некоторые команды сразу же при их отправке вместо того, чтобы ставить их в очередь, в том числе `/model`, `/effort` и `/fast`. Каждая из трех команд изменяет настройку: модель, уровень усилий или быстрый режим. То, применяет ли Claude Code новую настройку к ходу, над которым Claude уже работает, или только с вашего следующего хода, отличается в зависимости от команды:

* [`/model`](https://code.claude.com/docs/ru/model-config#setting-your-model): после подтверждения [предупреждения о кэше](https://code.claude.com/docs/ru/prompt-caching.md#switching-models), если Claude Code его показывает, Claude Code использует новую модель начиная со следующего запроса, который он делает в этом ходе
* `/effort`: следующее отправленное вами сообщение выполняется с новым уровнем. Чтобы [начать применять его в ходе, над которым Claude уже работает](https://code.claude.com/docs/ru/model-config.md#when-a-new-effort-level-starts), поставьте сообщение в очередь, пока Claude выполняет вызовы инструментов
* [`/fast`](https://code.claude.com/docs/ru/fast-mode#toggle-fast-mode): Claude Code сохраняет настройку быстрого режима, которая была активна при начале хода, поэтому ваше изменение скорости применяется с вашего следующего хода. Если ваша текущая модель не поддерживает быстрый режим, его включение также [переключает вашу модель](https://code.claude.com/docs/ru/prompt-caching.md#turning-on-fast-mode), и Claude Code использует новую модель с ее следующего запроса в этом ходе

### Перевод сессии с сообщениями в очереди в фоновый режим

Когда сессия переходит в фоновый режим после того, как вы [нажмете `←`](https://code.claude.com/docs/ru/agent-view#switch-sessions-without-leaving-the-terminal), сообщения, которые вы поставили в очередь, переходят вместе с ней. Claude читает их там в том порядке, в котором вы их отправили.

Команды и команды оболочки `!` не могут быть перенесены, как и некоторые сообщения, например сообщение с прикрепленным [выделением из IDE](https://code.claude.com/docs/ru/vs-code.md#the-built-in-ide-mcp-server). Если вы нажмете `←`, пока одно из них находится в очереди, сессия остается на переднем плане и появляется уведомление, начинающееся с `Cannot open agents`. Чтобы перевести сессию в фоновый режим, уберите запись из очереди, а затем снова нажмите `←`:

* **Команды и команды оболочки `!`**: дождитесь их выполнения в конце хода или [отмените их](#take-back-what-you-queued) и очистите поле ввода. Пока в очереди есть что-либо еще, вы не можете отменить команды оболочки `!`, поэтому дождитесь их выполнения.
* **Сообщения, которые не могут быть перенесены**: дождитесь, пока Claude их прочитает

### Отмените то, что вы поставили в очередь

Нажмите `Up` с первой строки поля ввода, чтобы отменить сообщения и команды из очереди. Claude Code удаляет их из очереди и помещает в поле ввода, по одному на строку, перед любым текстом, который вы набрали. Отредактируйте текст и нажмите `Enter`, чтобы поставить его в очередь снова как одну запись, или очистите поле ввода, чтобы удалить его.

Claude Code отменяет команды оболочки из очереди только когда поле ввода пусто и у вас нет ничего другого в очереди, и оно переключает поле ввода в режим оболочки при этом. В противном случае оно оставляет их в очереди, перечисленными с префиксом `!`, и выполняет их после завершения хода.

Если вы забираете текст из очереди, пока `←` [ожидает перевода сессии в фоновый режим](https://code.claude.com/docs/ru/agent-view.md#switch-sessions-without-leaving-the-terminal), текст остается в поле ввода, а Claude Code отменяет переключение. Если вы забираете его в момент перемещения сессии, текст исчезает вместе с экраном переднего плана: он не был отправлен. Каждое забранное вами сообщение сохраняется как отдельная запись в [истории команд](#command-history). Чтобы восстановить его, снова откройте сессию и нажмите `Up` в пустом промпте, когда в очереди ничего нет.

## Предложения подсказок

Когда вы впервые открываете сеанс, Claude Code показывает затемненный пример команды в поле ввода подсказки, чтобы помочь вам начать работу. Он выбирает это из истории git вашего проекта, поэтому пример отражает файлы, над которыми вы недавно работали.

После ответа Claude Code может предложить вашу следующую подсказку на основе истории вашего разговора, например следующий шаг из многоэтапного запроса или естественное продолжение вашего рабочего процесса.

* Нажмите `Tab` или `Right arrow`, чтобы поместить предложение в поле ввода подсказки, затем `Enter` для отправки
* Начните вводить текст, чтобы отклонить его

Claude Code генерирует каждое из этих предложений следующей подсказки с помощью фоновой заявки к той же модели, которую использует ваш сеанс. Заявка учитывается в пределах использования вашего плана или в ваших затратах на API. Поскольку она повторно использует кэш подсказок разговора, это в основном чтение из кэша плюс несколько выходных токенов, поэтому дополнительные затраты минимальны.

### Когда Claude Code пропускает предложения

В интерактивном режиме Claude Code по умолчанию отключает предложения подсказок и скрывает переключатель **Prompt suggestions** в `/config` в [сеансе, который не получает флаги функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), например на стороннем поставщике или через шлюз приложений Claude, и в [первом сеансе после установки или обновления](https://code.claude.com/docs/ru/env-vars.md#first-session-after-an-install-or-upgrade), флаги которого еще не поступили.

Claude Code также пропускает отдельные предложения в нескольких ситуациях, включая:

* Кэш подсказок холодный, чтобы избежать ненужных затрат
* После первого хода разговора в некоторых сеансах
* Предыдущий ответ закончился ошибкой
* Пока вы находитесь в Plan Mode
* Ваш аккаунт близок к лимиту использования или достиг его. Чтобы этот пропуск не применялся до достижения лимита, установите [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](https://code.claude.com/docs/ru/env-vars) в `true`. До версии 2.1.238 Claude Code пропускал предложения рядом с лимитом даже с переменной, установленной в `true`
* В [команде агентов](https://code.claude.com/docs/ru/agent-teams.md), в сеансах товарищей по команде по умолчанию. Сеанс лидера показывает предложения

Уведомление `Showing fewer prompt suggestions · use one to bring them back` означает, что Claude Code показывает предложения реже, потому что вы оставили много предложений подряд неиспользованными. Чтобы вернуть обычную частоту, воспользуйтесь предложением или установите [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](https://code.claude.com/docs/ru/env-vars) в `true`.

В режиме печати Claude Code по умолчанию не генерирует предложения. Передайте [`--prompt-suggestions`](https://code.claude.com/docs/ru/cli-reference#cli-flags) с `-p "<prompt>" --output-format stream-json --verbose`, чтобы Claude Code выдал сообщение `prompt_suggestion` после каждого хода, который генерирует его. Генератор также пропускает очень короткие разговоры и холодные кэши подсказок здесь, поэтому один короткий запрос `-p` может не выдать ничего.

### Отключение предложений подсказок

Чтобы полностью отключить предложения подсказок, используйте любое из следующего:

* Отключите **Prompt suggestions** в `/config`
* Установите [`promptSuggestionEnabled`](https://code.claude.com/docs/ru/settings-reference#promptsuggestionenabled) в `false` в файле параметров
* Установите переменную окружения [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](https://code.claude.com/docs/ru/env-vars) в `false`, которая имеет приоритет над параметром:
  ```bash theme={null}
  export CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
  ```

Чтобы отключить предложения подсказок во всей организации, установите `promptSuggestionEnabled` в `false` в [управляемых параметрах](https://code.claude.com/docs/ru/managed-settings.md). Также установите `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` в `false` под управляемым ключом [`env`](https://code.claude.com/docs/ru/settings-reference#env), чтобы пользователи не могли повторно включить их с помощью собственной переменной окружения.

## Подсказки You should know

«You should know» ищет что-то одно, что вам следует знать, но что вы могли упустить, например компромисс, который Claude выбрал, не упомянув его явно, или результат, который может быть неверным. Обнаружив такое, он показывает короткую заметку над полем ввода промпта:

```text theme={null}
✦ Heads up · There was a change to how folder sharing starts in June, which may have bumped usage metrics artificially.
  1: Learn more   2: Knew this already   0: Dismiss
```

Это один из [встроенных модов](https://code.claude.com/docs/ru/plugins/mods/overview.md#mods-built-into-claude-code) Claude Code — плагин, встроенный в Claude Code и по умолчанию отключённый. Требуется Claude Code v2.1.287 или новее.

Пока мод включён, побочный агент время от времени перечитывает диалог, пока Claude работает над более длительной задачей. Побочный агент — это отдельный запрос к той же модели без инструментов, поэтому он не может читать файлы, выполнять команды или изменять действия Claude.

Если мод доступен для вашей организации, `/plugin` показывает его в списке, когда вы подключаетесь к Claude API напрямую с учётной записью claude.ai или API-ключом Console. Он не отображается, если вы подключаетесь через [LLM-шлюз](https://code.claude.com/docs/ru/llm-gateway) или [шлюз приложений Claude](https://code.claude.com/docs/ru/claude-apps-gateway) либо получаете ключ из [`apiKeyHelper`](https://code.claude.com/docs/ru/settings-reference#apikeyhelper). Даже при прямом подключении он не отображается в следующих сессиях:

* Сессия, которая [не загружает флаги функций](https://code.claude.com/docs/ru/env-vars.md#features-that-need-feature-flag-fetching), от которых зависит мод, например сессия с установленной переменной `DISABLE_TELEMETRY`
* [Первая сессия после установки или обновления](https://code.claude.com/docs/ru/env-vars.md#first-session-after-an-install-or-upgrade), флаги которой ещё не получены

Чтобы включить его, выполните в промпте Claude Code:

```text theme={null}
/plugin enable cc-plugin-you-should-know@builtin
```

Если `/plugin` не показывает мод, команда включения отвечает `Plugin "cc-plugin-you-should-know@builtin" is not installed in this project`.

### Стоимость проверок

Пока мод включён, проверки выполняются как фоновые запросы к той же модели, которую использует ваша сессия, и учитываются в лимитах использования вашего плана или в расходах на API. Каждая проверка отправляет то, что уже находится в контексте Claude, то есть диалог на текущий момент вместе с результатами инструментов, а затем собственные инструкции мода и текст ваших недавних заметок. Часть с диалогом считывается из [кэша промптов](https://code.claude.com/docs/ru/prompt-caching.md) сессии на тех же условиях, что и следующий запрос самого Claude. Инструкции объёмом в несколько тысяч токенов и ответ побочного агента оплачиваются полностью при каждой проверке.

Чтобы наблюдать за проверками, установите [`CLAUDE_CODE_YOU_SHOULD_KNOW_DEBUG=1`](https://code.claude.com/docs/ru/env-vars) в оболочке перед запуском Claude Code.

### Ответ на заметку

Введите цифру варианта отдельно в пустое поле ввода промпта. Заметка предлагает следующие варианты:

* **Learn more**: открывает краткое пояснение под заметкой с собственными вариантами:
  * **Understood**: закрывает его и помечает тему как известную
  * **Chat in main session**: цитирует заметку в поле ввода промпта, чтобы вы могли добавить вопрос и отправить его Claude
  * **Dismiss**: закрывает его, не помечая тему как известную
* **Knew this already**: закрывает заметку и помечает тему как известную.
* **Dismiss**: закрывает заметку.

Основной агент не видит заметку, если вы не отправите её с помощью **Chat in main session**.

Claude Code хранит ваши недавние заметки и темы, помеченные как известные, в файле, имя которого начинается с `cc-plugin-you-should-know`, в каталоге `~/.claude/plugins/store/`. Каждая проверка в этой и последующих сессиях передаёт их побочному агенту как те, которые не следует повторять. Claude Code удаляет этот файл, если в течение [`cleanupPeriodDays`](https://code.claude.com/docs/ru/settings-reference#cleanupperioddays) ни одна сессия не читала и не записывала его. Чтобы очистить их раньше, удалите этот файл, когда ни одна сессия не запущена.

### Отключение You should know

Чтобы отключить You should know, воспользуйтесь одним из следующих способов:

* В промпте Claude Code выполните `/plugin disable cc-plugin-you-should-know@builtin` или отключите его на вкладке **Installed** в `/plugin`
* После того как вы выберете **Dismiss** в заметке, не открывая сначала **Learn more**, выберите **Turn off suggestions** в строке `Dismissed.`, которая исчезает через 20 секунд

## Emoji shortcodes

Введите `:` с последующим кодом emoji в поле ввода промпта для вставки emoji.

* Введите полный код, например `:heart:`, и Claude Code заменит его на ❤️ сразу же после ввода закрывающего `:`
* Введите `:` плюс минимум два символа названия, например `:hea`, чтобы открыть всплывающее окно предложений, затем нажмите `Tab` или `Enter` для вставки выделенного emoji

Код должен начинаться с начала ввода или следовать за пробелом, поэтому `:` внутри слова или URL не открывает предложения.

Чтобы отключить эту функцию, установите [`emojiCompletionEnabled`](https://code.claude.com/docs/ru/settings-reference#emojicompletionenabled) на `false` в `settings.json`. Это отключит как всплывающее окно предложений, так и встроенную замену.

## Проверка орфографии во время ввода

Claude Code может подчеркивать неправильно написанные слова в поле ввода подсказки во время ввода. Он проверяет только текст в поле ввода, никогда ответы Claude или ваши файлы. Он также ничего не проверяет, пока поле ввода находится в [режиме shell](#shell-mode-with-prefix), поиске истории `Ctrl+R` или [голосовом диктовании](https://code.claude.com/docs/ru/voice-dictation.md).

Проверка орфографии отключена по умолчанию, и Claude Code ничего не проверяет в [режиме чтения с экрана](https://code.claude.com/docs/ru/accessibility.md). Требуется Claude Code v2.1.235 или более поздняя версия.

### Предварительные требования

* Установите [aspell](https://github.com/GNUAspell/aspell), [hunspell](https://github.com/hunspell/hunspell) или [ispell](https://en.wikipedia.org/wiki/Ispell) и убедитесь, что он находится в вашем `PATH`. Claude Code запускает первый из трех найденных им на каждой платформе, включая `.cmd` shim, который установщик пакетов устанавливает на Windows.
* Чтобы проверить, находится ли программа в вашем `PATH`, запустите `aspell --version`, `hunspell --version` или `ispell -v` в вашем терминале. Ошибка "command not found" означает, что она еще не находится в вашем `PATH`.

### Включение или отключение проверки орфографии

Claude Code читает параметр [`spellcheck`](https://code.claude.com/docs/ru/settings-reference#spellcheck) из трех мест и игнорирует его в файлах `.claude/settings.json` и `.claude/settings.local.json` проекта. Включите его в том месте, которое вы используете:

> [tab] User settings
>
> Добавьте `spellcheck` в `~/.claude/settings.json`. Это применяется в каждом проекте, который вы открываете, как и остальные ваши [пользовательские параметры](https://code.claude.com/docs/ru/settings.md#where-settings-live):
>
> ```json theme={null}
> {
>   "spellcheck": { "enabled": true }
> }
> ```

> [tab] Command line
>
> Сохраните `spellcheck` в JSON файл, например `spellcheck.json`:
>
> ```json theme={null}
> {
>   "spellcheck": { "enabled": true }
> }
> ```
>
> Затем передайте файл в `--settings`. Это применяется только к этому сеансу:
>
> ```bash theme={null}
> claude --settings spellcheck.json
> ```

> [tab] Managed settings
>
> Добавьте `spellcheck` в один из [источников управляемых параметров](https://code.claude.com/docs/ru/permissions.md#managed-settings) вашей организации. Это применяется ко всем пользователям, которые получают эти параметры, и они не могут их отключить:
>
> ```json theme={null}
> {
>   "spellcheck": { "enabled": true }
> }
> ```

Чтобы проверить, включена ли проверка орфографии, введите неправильно написанное слово и пробел. Claude Code подчеркнет слово. Если этого не произойдет, см. [Когда Claude Code ничего не подчеркивает](#when-claude-code-underlines-nothing). Чтобы снова отключить проверку орфографии, установите `enabled` на `false` в том же месте или удалите `spellcheck`.

Чтобы выбрать, какую из трех программ запускает Claude Code, какой словарь он использует или цвет подчеркивания, добавьте любое из этих полей рядом с `enabled` в том же месте:

* `checker`: `aspell`, `hunspell` или `ispell`. Claude Code не переходит на другой checker, который вы назвали, и рассматривает любое другое значение как `auto`.
* `language`: имя словаря в форме вашего checker, например `en_GB`. Claude Code игнорирует любое значение, которое не является простым именем словаря, например путь или имя с пробелами, и checker использует свой словарь по умолчанию.
* `color`: имя цвета, например `yellow`, или значение `#rrggbb`, `#rgb`, `rgb(r,g,b)`, `ansi256(n)` или `ansi:<name>`. Claude Code использует цвет ошибки вашей темы по умолчанию и для любого значения, которое он не распознает.

Например, этот параметр `spellcheck` запускает hunspell со словарем `en_GB` и подчеркивает слова желтым цветом. Это работает одинаково в `~/.claude/settings.json`, в файле, который вы передаете в `--settings`, и в управляемых параметрах:

```json theme={null}
{
  "spellcheck": {
    "enabled": true,
    "checker": "hunspell",
    "language": "en_GB",
    "color": "yellow"
  }
}
```

Если в двух или более из трех мест есть параметр `spellcheck`, Claude Code использует только один из них: сначала управляемые параметры, затем `--settings`, затем пользовательские параметры. Он не объединяет поля из двух мест. Например, когда `--settings` устанавливает `spellcheck`, `language` в ваших пользовательских параметрах не имеет никакого эффекта.

### Что Claude Code подчеркивает

Вскоре после того, как вы прекратите ввод, Claude Code подчеркивает слова, которые словарь не знает. Он оставляет слово, которое вы все еще вводите, в покое, пока вы не перейдете дальше. Он также пропускает текст, который выглядит как код:

* Команды, такие как `/help`, упоминания `@`, URL-адреса, пути к файлам и флаги, такие как `--verbose`
* Слова с цифрами, подчеркиваниями или заглавной буквой после первой, и текст в обратных кавычках

Claude Code также пропускает китайский, японский, корейский, тайский, лаосский, кхмерский и мьянманский текст.

Claude Code не имеет собственного списка слов: слово считается неправильно написанным, когда это говорит ваш checker. Чтобы Claude Code перестал подчеркивать слово, добавьте слово в личный словарь вашего checker, следуя документации checker. Claude Code подхватит новое слово после перезагрузки.

### Когда Claude Code ничего не подчеркивает

Claude Code ничего не подчеркивает, когда не может запустить checker:

* Checker не установлен, или тот, который вы назвали в `checker`, отсутствует
* Checker дважды подряд дает сбой при запуске или позже в сеансе. Claude Code перезапускает его после первого сбоя и прекращает проверку после второго, пока вы не перезагрузите Claude Code
* Checker требует более 15 секунд для ответа три раза. Каждый раз Claude Code оставляет слова, на которые он ждал, без отметок; после третьего раза он прекращает проверку, пока вы не перезагрузите Claude Code

Чтобы узнать, что произошло, запустите `claude --debug` с включенной проверкой орфографии и введите слово. Затем найдите строки `[spellcheck]` в журнале отладки в `~/.claude/debug/<session-id>.txt`. Одна строка называет программу, которую запустил Claude Code, или перечисляет те, которые он искал и не нашел. Более поздние строки говорят, почему он остановился. Ошибка отсутствующего словаря там означает, что checker не имеет словаря для вашего значения `language`, или нет словаря по умолчанию, когда `language` не установлен. Установите один или установите `language` на словарь, который у вас есть.

## Невидимые символы в промптах

Вставленный текст может содержать символы Unicode, которые терминал не отображает вообще, такие как символы тегов, двунаправленные управляющие символы и пробелы нулевой ширины, поэтому промпт может содержать текст, который вы никогда не видите. Чтобы скопированный текст не содержал инструкций, которые ваш терминал не отображает, Claude Code удаляет эти символы при нажатии Enter, прежде чем что-либо отправлять. Он очищает как сам промпт, так и содержимое любой свёрнутой [ссылки на вставленный текст](https://code.claude.com/docs/ru/terminal-config.md#paste-large-content), которую включает промпт. Claude Code сохраняет соединители, которые используют персидский и индийский шрифты, а также селекторы внутри последовательностей эмодзи.

Если Claude Code что-то удалил, он либо отправляет очищенный промпт, либо возвращает его вам для проверки. Чтобы понять, что именно произошло, посмотрите на уведомление:

* **`Removed 3 invisible characters from your prompt`**: если поле ввода пустое, ваш промпт был отправлен без этих символов. Если промпт всё ещё там, он не был отправлен, поэтому нажмите Enter ещё раз.
* **`Removed 3 invisible characters · review and press Enter to send`**: ничего не было отправлено. Прочитайте очищенный промпт в поле ввода, затем нажмите Enter, чтобы отправить его в том виде, в котором он показан.

Когда вы передаёте промпт в командной строке, например `claude "fix the login bug"`, Claude Code удаляет символы, показывает уведомление и отправляет очищенный промпт. Если очищенный промпт начинался бы с `/`, Claude Code вместо этого помещает его в поле ввода для вашего просмотра и отправки.

## Просмотр изменений с помощью /diff

Запустите `/diff`, чтобы просмотреть изменения в вашем рабочем дереве, не покидая Claude Code. Вы видите правки, которые Claude уже внёс, наряду со всем остальным, что вы ещё не зафиксировали. Что именно открывает `/diff`, зависит от активного рендерера:

* **[Полноэкранный режим](https://code.claude.com/docs/ru/fullscreen.md)**: [панель diff](#diff-panel) открывается рядом с диалогом. Она остаётся открытой и обновляется, пока вы продолжаете работать.
* **Классический рендерер**: [диалоговое окно diff](#diff-dialog) открывается над промптом, и вы закрываете его, когда закончите читать.

И панель, и диалоговое окно предоставляются `cc-plugin-diff` — одним из [модов, встроенных в Claude Code](https://code.claude.com/docs/ru/plugins/mods/overview.md#mods-built-into-claude-code). Если вы отключите этот мод в `/plugin`, `/diff` вместо них откроет прежнюю панель Claude Code и [средство просмотра diff](https://code.claude.com/docs/ru/keybindings.md#diff-actions).

В изменениях, которые `/diff` читает из git, подмодуль отображается как одна запись, и только когда изменяется коммит, на который он указывает; правки файлов внутри подмодуля там не отображаются. Панель и диалоговое окно также предлагают представление правок каждого хода, как только Claude отредактировал файлы. Эти представления ходов создаются из правок файлов Claude, а не из git, поэтому изменение, которое Claude вносит через shell-команду, отображается только в `Current` — представлении рабочего дерева.

### Diff panel

Панель diff отображает изменённые файлы с количеством добавленных и удалённых строк и показывает diff каждого файла под списком. Claude Code обновляет её каждый раз, когда Claude редактирует файл или запускает shell-команду. Чтобы закрыть панель, запустите `/diff` снова или нажмите `✕` в её заголовке.

Для использования панели вам нужно:

* [Полноэкранный режим](https://code.claude.com/docs/ru/fullscreen.md)
* Репозиторий git
* Терминал шириной не менее 110 столбцов
* Claude Code версии 2.1.287 или позже

Панель также открывается самостоятельно, как только Claude начинает редактировать файлы, если ваш терминал имеет ширину не менее 144 столбцов. После того как вы открыли её сами с помощью `/diff`, в последующих сессиях она открывается сразу же, как только Claude редактирует файл в любом терминале, достаточно широком для её размещения. Закройте панель, и она останется закрытой в этой сессии и в последующих, пока вы снова не запустите `/diff`.

Пока панель открыта, вы можете:

* **Перейти к файлу**: нажмите на его строку в списке. Прокручивайте панель колесом мыши. Когда сам список файлов слишком длинный, чтобы поместиться, прокручивайте его с помощью `Alt+Up` и `Alt+Down`, или `Ctrl+Up` и `Ctrl+Down`.
* **Спросить Claude об изменениях в файле**: нажмите `ask` справа от имени файла над его diff. Claude Code прикрепляет diff этого файла к вашему следующему промпту, и на кнопке отображается `asked ✓`, пока вы не отправите этот промпт. Запрос по второму файлу заменяет первый.
* **Показать правки одного хода**: нажмите на селектор `source` в заголовке панели, затем выберите ход с помощью `Up` и `Down` и нажмите `Enter`. Ходы обозначаются `T1`, `T2` и так далее. Селектор появляется, как только Claude отредактировал файлы, а `Current` возвращает вас к рабочему дереву.
* **Показать файлы, которые панель пропускает**: список пропускает тестовые файлы и сгенерированные файлы и сворачивает изменения, сделанные до этой сессии, в одну строку внизу. Нажмите на любую строку счётчика, чтобы развернуть её.
* **Изменить, с чем панель сравнивает**: нажмите `Ctrl+X B`, чтобы переключаться между изменениями этой сессии, вашими незафиксированными изменениями как одним списком и всем, что было с момента ответвления вашей ветки от ветки по умолчанию. Claude Code запоминает выбор для каждого репозитория.

Чтобы переназначить клавиши, которые прокручивают список файлов или меняют сравнение, см. [Действия панели diff](https://code.claude.com/docs/ru/keybindings.md#diff-panel-actions).

Во время незавершённого слияния, rebase, cherry-pick или revert панель продолжает показывать изменения, которые она в последний раз прочитала из git, чтобы не заполняться входящими изменениями этой операции. Она обновляется при первом обновлении после завершения операции, например когда Claude в следующий раз редактирует файл.

### Diff dialog

Диалоговое окно diff открывается в виде блока с рамкой над промптом и отображает изменённые файлы с количеством добавленных и удалённых строк. Оно сравнивает их с `HEAD` или с тем, что вы в последний раз [выбрали в панели diff](#diff-panel) для этого репозитория.

Как только Claude отредактировал файлы, над списком появляется селектор `source`. Он предлагает по одному представлению хода, обозначенному `T1`, `T2` и так далее, для каждого вашего промпта, после которого Claude редактировал файлы. Представление хода показывает только правки этого хода, а `Current` возвращает вас к рабочему дереву.

Используйте эти клавиши в диалоговом окне:

* **Up и Down**: выбор файла.
* **Enter**: открыть diff выбранного файла. Прокручивайте его с помощью Up и Down, или PageUp и PageDown.
* **Esc**: вернуться из diff файла в список или закрыть диалоговое окно из списка.
* **Tab**: перейти к селектору `source`, затем выбрать `Current` или представление хода с помощью Up и Down и нажать Enter. В diff файла Tab переводит фокус на кнопку `ask`. Нажмите Enter, чтобы прикрепить diff этого файла к вашему следующему промпту.

## Побочные вопросы с /btw

Используйте `/btw`, чтобы задать вопрос о текущей работе, не добавляя его в историю диалога.

```
/btw what was the name of that config file again?
```

Claude отвечает на побочный вопрос на основе того, что уже есть в диалоге: ваших сообщений, своих ответов и собранных результатов инструментов. Вы можете спросить о коде, который Claude уже прочитал, о решениях, принятых им ранее, или о чём-либо ещё из сессии. Следующий побочный вопрос также видит ваши предыдущие побочные вопросы: Claude Code воспроизводит 20 последних обменов при каждом запросе, пока вы их не очистите. Вопрос и ответ никогда не попадают в историю диалога. В терминале они отображаются в закрываемом оверлее. Терминал хранит эту ветку в памяти: нажмите `x`, чтобы очистить предыдущие обмены, а при выходе из Claude Code она исчезает.

В панели чата [расширения VS Code](https://code.claude.com/docs/ru/vs-code.md#use-the-prompt-box) команда `/btw` открывает панель, а не оверлей, описанный в этом разделе, и уточняющие вопросы задаются прямо в панели. Ветка в панели сохраняется при перезагрузке окна в соответствии с графиком хранения, описанным на той странице. Требуется расширение версии v2.1.227 или новее. Более ранние версии расширения не поддерживают `/btw`.

* **Доступно, пока Claude работает**: вы можете выполнить `/btw`, даже когда Claude обрабатывает ответ. Побочный вопрос выполняется независимо и не прерывает основной ход. Он видит всё, что есть в диалоге к этому моменту, кроме ответа, который Claude ещё пишет.
* **Без доступа к инструментам**: побочные вопросы отвечаются только на основе того, что уже есть в контексте. Отвечая на побочный вопрос, Claude не может читать файлы, выполнять команды или выполнять поиск. Если Claude всё же выпишет вызовы инструментов в виде текста, ответ завершится примечанием о том, что ничего не было выполнено.
* **Один ответ**: в оверлее нет последующих ходов. Чтобы продолжить ветку, задайте ещё один вопрос через `/btw`. Чтобы продолжить с полным доступом к инструментам в локальной сессии, нажмите `f` и ответвите этот вопрос и ответ в [фоновый субагент](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation).
* **Низкая стоимость**: пока [кэш промптов](https://code.claude.com/docs/ru/prompt-caching.md) диалога «тёплый», побочный вопрос почти ничего не стоит сверх стоимости самого ответа.

Пять ваших последних предыдущих побочных вопросов отображаются затемнённым списком над текущим ответом вместе с количеством более старых. Они не попадают в историю диалога.

Чтобы вернуться к оверлею после его закрытия, выполните `/btw` без вопроса. Оверлей снова откроется на вашем последнем обмене.

Когда ответ появится, оверлей принимает следующие клавиши.

| Клавиша | Действие |
| :- | :- |
| `Space`, `Enter`, `Escape` | Закрыть ответ и вернуться к промпту |
| `Up` / `Down` | Прокрутить ответ |
| `Shift+Left` / `Shift+Right` | Переключаться между этим ответом и предыдущими ответами `/btw`. `Shift+Left` переходит к более старым ответам, а `Shift+Right` возвращает к текущему. `[` и `]` делают то же самое — для терминалов, которые не передают `Shift` вместе с клавишами-стрелками. `Tab` / `Shift+Tab` циклически перебирают те же ответы. Требуется Claude Code v2.1.257 или новее. В версиях с v2.1.187 по v2.1.256 использовались обычные `Left` / `Right` |
| `c` | Скопировать ответ в буфер обмена в виде исходного Markdown. Используйте это вместо выделения мышью, которое захватывает отрисовку терминала с жёсткими переносами строк, а не исходный текст |
| `f` | Запустить [ответвлённый субагент](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation), который наследует родительский диалог вместе с этим вопросом и ответом, чтобы продолжить работу с полным доступом к инструментам. Вы остаётесь в текущей сессии и найдёте ответвление на [панели под промптом](https://code.claude.com/docs/ru/sub-agents.md#observe-and-steer-running-forks). Доступно только в локальных сессиях |
| `x` | Очистить список предыдущих обменов `/btw`, отображаемый над текущим ответом |

В подключённой [фоновой сессии](https://code.claude.com/docs/ru/agent-view.md#attach-to-a-session) клавиша `Left` отключает вас от сессии и возвращает в представление агентов, даже пока ответ ещё поступает. Побочный вопрос продолжает выполняться, пока вас нет. При следующем подключении к сессии оверлей снова откроется с побочным вопросом или с ответом на него. До v2.1.257 клавиша `Left` там не выполняла отключение.

`/btw` видит весь ваш диалог или [открытый вами транскрипт субагента](#ask-btw-about-a-subagent), но не имеет инструментов. [Субагент](https://code.claude.com/docs/ru/sub-agents.md) имеет инструменты и начинает с полученного промпта. [Ответвление](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation) начинает с копии этого диалога. Используйте `/btw`, чтобы спросить о том, что Claude уже знает из этой сессии; используйте субагент, чтобы выяснить что-то новое.

### Вопрос /btw о субагенте

Когда открыт [транскрипт субагента](https://code.claude.com/docs/ru/sub-agents.md#observe-and-steer-running-forks), Claude отвечает на `/btw` на основе этого транскрипта, а не основного диалога, поэтому вы можете спросить, что сделал субагент. Следующий `/btw` из этого транскрипта видит только побочные вопросы, заданные из него. Требуется Claude Code v2.1.314 или новее.

Из транскрипта участника [команды агентов](https://code.claude.com/docs/ru/agent-teams.md) Claude отвечает на основе основного диалога.

## Список задач

Список задач — это контрольный список Claude: элементы, которые Claude создал для планирования многоэтапной работы, с индикаторами, показывающими, что ожидает выполнения, находится в процессе или завершено. Это отдельно от представления фоновых задач. Чтобы увидеть запущенные оболочки и подагентов, используйте [`/tasks`](https://code.claude.com/docs/ru/commands) вместо этого.

Список заполняется только в сессиях, которые имеют инструменты отслеживания задач, которые Claude Code предоставляет по умолчанию на [Opus 4.7, Sonnet 4.6, Haiku 4.5 и более ранних моделях](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability). На любой другой модели, включая ID модели, который Claude Code не распознает, список остается пустым, если вы не согласитесь с `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` или одним из других способов в разделе [Доступность инструмента Task](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability). Когда сессия имеет инструменты, список задач работает следующим образом:

* Нажмите `Ctrl+T` для переключения представления списка задач. Дисплей показывает до пяти задач одновременно. Когда Claude еще не создал никаких элементов контрольного списка, переключение не имеет видимого эффекта, потому что нечего отображать
* Если вы оставите список развернутым, Claude Code восстановит развернутое представление при следующем запуске в сеанс, который все еще содержит задачи, например с `--resume` или `--continue`. Когда список задач пуст, Claude Code запускает его в свернутом состоянии
* Чтобы увидеть все задачи или очистить их, попросите Claude напрямую: "show me all tasks" или "clear all tasks"
* Задачи сохраняются при сжатии контекста, помогая Claude оставаться организованным в более крупных проектах
* Чтобы поделиться списком задач между сеансами, установите `CLAUDE_CODE_TASK_LIST_ID` для использования именованного каталога в `~/.claude/tasks/`: `CLAUDE_CODE_TASK_LIST_ID=my-project claude`

## Краткое резюме сеанса

Когда вы возвращаетесь в терминал после перерыва, Claude Code показывает однострочное резюме того, что произошло в сеансе до сих пор. Резюме генерируется в фоновом режиме после того, как прошло не менее трёх минут с момента последнего завершённого хода и терминал не в фокусе, поэтому оно готово, когда вы переключитесь обратно. Резюме появляются только после того, как в сеансе будет не менее трёх ходов, и никогда не появляются два раза подряд.

Запустите `/recap` для создания резюме по требованию. Команда выполняется, только когда вы запрашиваете её сами. Если она приходит в сообщении, переданном из треда Slack, Teams или проекта, вместо резюме вы получите [уведомление](https://code.claude.com/docs/ru/errors.md#recap-only-runs-when-you-ask-for-it-yourself). Вы также получите это уведомление, если `/recap` приходит в промпте, отправленном облачной запланированной задачей.

Краткое резюме сессии включено по умолчанию для каждого плана и поставщика. Чтобы отключить автоматические резюме, откройте `/config` и отключите **Session recap**. Автоматическое резюме никогда не появляется в неинтерактивном режиме. Claude Code ограничивает как автоматические резюме, так и вывод `/recap` до 400 символов.

## Ожидание сброса лимита использования

Когда [лимит использования](https://code.claude.com/docs/ru/errors.md#youve-hit-your-session-limit) claude.ai останавливает Claude в середине задачи, Claude Code ждёт в открытой сессии и продолжает задачу самостоятельно после сброса лимита. Автоматическое продолжение включено по умолчанию в интерактивных сессиях, вошедших в систему с подпиской claude.ai. Требуется Claude Code v2.1.234 или позже.

Пока Claude Code ждёт, строки в нижней части сессии показывают, когда сбросится ваш лимит и когда Claude продолжит:

```text theme={null}
Usage limit reached · limit resets 3:45pm
Continuing automatically at 3:45pm · Esc to cancel
```

После этих слов любая из строк может содержать дополнительный текст, например ссылку на справку в первой строке или `/usage-credits to continue now` во второй. Когда ожидание начинается само, в диалоге это также фиксируется строкой `Usage limit reached · continuing automatically at 3:45pm · esc to cancel`.

Держите сессию открытой. Что произойдёт дальше, зависит от того, как закончится ожидание:

* **При сбросе**: вторая строка меняется на `Continuing shortly · Esc to cancel`. Затем в диалоге появляется `Usage limit reset · Continuing automatically`, и Claude Code отправляет Claude промпт продолжить задачу там, где она остановилась. Он не переотправляет ваше последнее сообщение.
* **После сна вашего компьютера**: если он спал более чем примерно 30 минут и лимит сбросился во время сна, первая строка читается как `Your usage limit has reset`, а вторая — `Press enter to continue`. Нажмите `Enter` для продолжения. После более короткого сна или сна, закончившегося до сброса, Claude Code продолжает самостоятельно.
* **Раньше**: когда вы закончите добавлять [кредиты использования](https://code.claude.com/docs/ru/costs.md#add-usage-credits-to-your-subscription) с помощью `/usage-credits`, снова войдёте в систему после `/upgrade` или переключите модели с помощью `/model` во время ожидания, Claude Code проверяет, доступно ли использование снова, и продолжает немедленно, если оно доступно. Он не проверяет после обновления или покупки, которые вы совершаете в браузере самостоятельно. В разделе [`opusplan`](https://code.claude.com/docs/ru/model-config#opusplan-model-setting) и других параметрах модели, которые запускают режим плана на другой модели, Claude Code ждёт сброса вместо этого.

В продолженной задаче Claude Code по-прежнему запрашивает [разрешения](https://code.claude.com/docs/ru/permissions.md) как обычно, поэтому задача может остановиться на запросе разрешения, пока вас нет. Если задача снова достигнет лимита, ожидание начнётся снова.

После трёх автоматических продолжений автоматическое продолжение прекращается и появляется уведомление `Automatic continue stopped after repeated usage-limit hits`. Запустите `/rate-limit-options`, чтобы выбрать, что делать дальше. Когда вы отправляете другой промпт или выбираете ожидание в этом меню, счётчик начинается заново. Автоматическое продолжение также прекращается после трёх продолжений для [`/goal`](https://code.claude.com/docs/ru/goal) или [запланированной задачи в рамках сессии](https://code.claude.com/docs/ru/scheduled-tasks.md), которая проходит через несколько окон сброса.

### Отмена ожидания

Нажмите `Esc` при пустом промпте или `Ctrl+C`, пока отображаются строки, или запустите [`/rate-limit-options`](https://code.claude.com/docs/ru/commands#all-commands) и выберите **Don't continue automatically**. Claude Code подтверждает строкой, которая начинается с `Automatic continue cancelled`.

После отмены ничего не продолжается, пока вы не отправите запрос или не выберете строку, которая начинается с **Wait here, then continue automatically** из `/rate-limit-options` снова. Claude Code не запускает ожидание самостоятельно снова для этого окна сброса; следующее окно сброса начинается заново.

Ожидание также заканчивается без продолжения задачи в этих случаях:

* **Вы отправляете промпт**: Claude Code отправляет ваш промпт вместо ожидания. Если ваш промпт тоже упирается в лимит, он остаётся в диалоге, и Claude Code снова начинает ожидание.
* **Вы выходите из Claude Code**: ожидание не перезапускается при возобновлении сессии.
* **Диалог переходит в другие руки**: вы переключаете учётные записи с помощью `/login`, очищаете или отматываете диалог, открываете другую сессию через `/resume`, переносите сессию с помощью `/teleport`, перезапускаете с помощью `/tui` или [`/restart`](https://code.claude.com/docs/ru/commands#all-commands) либо передаёте сессию Claude Desktop, фоновой сессии или облаку.
* **Параметр отключается или сброс выходит за пределы 24 часов**: это заканчивает только ожидание, которое Claude Code запустил самостоятельно. Ожидание, которое вы выбрали из `/rate-limit-options`, продолжает отсчитываться.
* **Продолжение заблокировано**: [`UserPromptSubmit` hook](https://code.claude.com/docs/ru/hooks#userpromptsubmit), который блокирует запрос продолжения, или сбой перед его достижением модели, заканчивает ожидание. Claude Code сообщает вам, что продолжение не выполнилось. Отправьте запрос для продолжения.

### Начните ожидание самостоятельно

Claude Code не запускает ожидание самостоятельно в этих случаях:

* **Сессии Remote Control и товарищей команды агентов**: человек у этого терминала всё ещё может запустить одну.
* **Сброс более чем на 24 часа в будущем**: еженедельный лимит может сброситься через дни.
* **Лимит Opus или Sonnet, пока вы запускаете модель вне этого семейства**: ваш следующий ход может не достичь этого лимита. [`opusplan`](https://code.claude.com/docs/ru/model-config#opusplan-model-setting) и другие параметры модели, которые запускают режим плана на ограниченном семействе, не получают это исключение.

В этих случаях и всякий раз, когда автоматическое продолжение отключено, Claude Code открывает меню параметров лимита использования один раз за окно сброса, когда вы достигаете лимита на своём собственном терминале. Выберите строку, которая начинается с **Wait here, then continue automatically**, чтобы начать ожидание. В сессии [Remote Control](https://code.claude.com/docs/ru/remote-control.md) или [команды агентов](https://code.claude.com/docs/ru/agent-teams.md) товарища запустите `/rate-limit-options` самостоятельно, чтобы открыть меню.

Claude Code вообще не предлагает ожидание в этих случаях:

* **Фоновые сессии и запуски `-p`**: строка меню недоступна.
* **Ключи API, облачные поставщики и выставление счётов на основе использования**: использование там измеряется за запрос, поэтому нет сброса для ожидания.
* **[LLM gateway](https://code.claude.com/docs/ru/llm-gateway#subscriptions-and-gateways) без сохранённого входа claude.ai**: Claude Code предлагает ожидание только при сохранённом входе claude.ai в качестве активного учётного данного.

### Отключите автоматическое продолжение

В `/config` отключите **Continue automatically at usage limit** или установите [`autoContinueAtUsageLimit`](https://code.claude.com/docs/ru/settings-reference#autocontinueatusagelimit) на `false` в ваших пользовательских параметрах. `/config autoContinueAtUsageLimit=false` также работает, включая с `-p`, но форма `key=value` не может включить его обратно, потому что параметр предоставляет автоматическое выполнение. Какие файлы параметров Claude Code читает для этого ключа, указано в [справочнике параметров](https://code.claude.com/docs/ru/settings-reference.md#autocontinueatusagelimit).

## Статус PR

При работе над веткой с открытым pull request Claude Code отображает кликабельную ссылку PR в нижнем колонтитуле, например "PR #446". Ссылка имеет цветное подчеркивание, указывающее на состояние рецензии:

* Зелёный: одобрено
* Жёлтый: ожидание рецензии
* Красный: запрошены изменения
* Серый: черновик

Значок исчезает после слияния или закрытия pull request.

`Cmd+click` (macOS) или `Ctrl+click` (Windows/Linux) на ссылку, чтобы открыть pull request в браузере.

Статус обновляется сразу же после успешного выполнения `git push` или команды `gh pr`, которая изменяет pull request, такой как `gh pr create` или `gh pr merge`, в текущей сессии.

Claude Code отображает значок как гиперссылку даже когда не может обнаружить поддержку гиперссылок в вашем терминале, что часто происходит при подключении по SSH или в tmux. Установите [`FORCE_HYPERLINK=0`](https://code.claude.com/docs/ru/env-vars), чтобы отображать значок как обычный текст.

Когда вы установите [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](https://code.claude.com/docs/ru/env-vars), Claude Code не проверяет статус pull request или merge request.

> [!NOTE]
>
> Статус PR для репозиториев GitHub требует токена GitHub. Claude Code находит его на основе хоста удалённого репозитория:
>
> * **github.com**: `GH_TOKEN` или `GITHUB_TOKEN`, или токен, сохранённый командой `gh auth login`. Без него нижний колонтитул показывает `install gh for PR status`, если CLI `gh` не установлен, или `gh auth login for PR status`, если установлен
> * **Хост GitHub Enterprise, установленный как `GH_HOST`**: `GH_ENTERPRISE_TOKEN` или `GITHUB_ENTERPRISE_TOKEN`, или токен, сохранённый командой `gh auth login --hostname <host>`. Без него нижний колонтитул показывает те же подсказки
> * **Любой другой хост GitHub**: токен, сохранённый командой `gh auth login --hostname <host>`. Без него Claude Code не показывает значок и не показывает подсказку

### GitLab merge requests

Когда вы работаете над веткой с открытым GitLab merge request, Claude Code показывает кликабельный значок `MR !N` в нижнем колонтитуле на месте, где обычно находится ссылка на GitHub PR. `!N` — это собственный синтаксис GitLab для ссылки на merge request номер N. Цветное подчеркивание показывает состояние merge request:

* Зелёный: GitLab сообщает, что merge request можно объединить
* Жёлтый: любое другое открытое состояние
* Серый: черновик

Значок исчезает после слияния или закрытия merge request.

Он обновляется сразу же после успешного выполнения `git push` или команды `glab mr`, которая изменяет merge request, такой как `glab mr create` или `glab mr merge`, в текущей сессии.

Чтобы получить значок, вам нужно:

* Claude Code v2.1.234 или позже
* Удалённый репозиторий, который указывает на ваш хост GitLab, либо gitlab.com, либо самостоятельно управляемый экземпляр
* [`glab` CLI](https://gitlab.com/gitlab-org/cli) в вашем `PATH`, аутентифицированный с помощью `glab auth login`

Claude Code игнорирует переменные окружения токена `glab`, такие как `GITLAB_TOKEN`, при проверке статуса, поэтому вы не получите значок только от экспортированного токена. Claude Code также ищет `glab` и его вход один раз за сессию, поэтому перезагрузите Claude Code после установки `glab` или запуска `glab auth login`.

## Ссылки на ссылки проблем

Когда Claude упоминает проблему как `owner/repo#123`, вы можете щелкнуть ссылку, чтобы открыть её, при условии, что ваш терминал поддерживает гиперссылки. Если Claude Code не обнаружит поддержку гиперссылок в вашем терминале, установите [`FORCE_HYPERLINK`](https://code.claude.com/docs/ru/env-vars) на `1`, чтобы включить ссылки, или на `0`, чтобы оставить ссылки в виде обычного текста.

Вы получаете ссылку только для двухчастной формы `owner/repo#123`. Эти ссылки остаются обычным текстом:

* Простая `#123`
* Вложенный путь GitLab, такой как `group/subgroup/project#123`
* Любая ссылка внутри диапазона кода или блока кода
* Любая ссылка в ответе длиннее примерно 1 000 строк или 100 000 символов

Claude Code создаёт ссылку для хоста репозитория, который он определяет из вашего git remote, а не для репозитория, который называет ссылка:

| Хост вашего репозитория | Где ссылается `owner/repo#123` |
| :- | :- |
| github.com, хост GitHub Enterprise или любой хост, не указанный ниже | `https://<host>/owner/repo/issues/123` |
| gitlab.com | `https://gitlab.com/owner/repo/-/issues/123` |
| bitbucket.org, codeberg.org или gitea.com | Нет ссылки; ссылка остаётся обычным текстом |
