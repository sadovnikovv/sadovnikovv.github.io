Другие LLM gateways #

Маршрутизируйте Claude Code через LLM gateway, который уже запускает ваша организация. Охватывает подключение Claude Code к шлюзу, развертывание шлюза для вашей организации и то, что Claude Code отправляет на шлюз.

В этом разделе рассматривается использование продукта шлюза, который уже запускает ваша организация, а не Claude apps gateway. Для получения информации о том, что такое шлюз, как он находится между Claude Code и вашим поставщиком, и как выбрать между Claude apps gateway и другим продуктом, см. обзор шлюза.

[!NOTE]

  • Если вы разработчик, подключающийся к существующему шлюзу: подключите Claude Code к вашему шлюзу
  • Если вы администратор, развертывающий шлюз для вашей организации: разверните и распределите шлюз
  • Если вы настраиваете продукт шлюза: справочник протокола шлюза

Любой шлюз, который предоставляет поддерживаемый формат API, работает. Anthropic не одобряет, не поддерживает и не проверяет продукты шлюзов третьих сторон, и не поддерживает маршрутизацию Claude Code на модели, отличные от Claude, через какой-либо шлюз. Разверните шлюз, следуя его собственной документации, затем завершите сторону Claude Code с помощью этапов развертывания ниже.

Что предоставляет шлюз #

Шлюз дает вашей организации одно место для управления:

  • Учетные данные: ключ поставщика остается на стороне сервера; разработчики вместо этого используют учетные данные шлюза
  • Отслеживание использования: атрибутируйте использование по разработчику или команде, независимо от того, какой поставщик обслуживает запрос
  • Контроль затрат: применяйте бюджеты и ограничения скорости в одном месте
  • Логирование аудита: логируйте каждый запрос модели для соответствия требованиям
  • Переключение поставщика: измените поставщика в конфигурации шлюза, не трогая машины разработчиков

Все эти функции, кроме переключения поставщика, применяются независимо от того, является ли upstream API Anthropic или облачный поставщик. Переключение поставщика без переконфигурации машин разработчиков также зависит от того, предоставляет ли шлюз одну конечную точку в формате Anthropic независимо от upstream. Шлюз, который предоставляет собственный формат поставщика, привязывает конфигурацию клиента к этому поставщику и изменяет то, что отправляет Claude Code и какие значения по умолчанию он применяет.

Компромисс заключается в том, что шлюз становится инфраструктурой, которую управляет ваша организация. Claude Code добавляет возможности с каждым выпуском, и шлюз, который не перенаправляет их, нарушает соответствующие функции, поэтому продукт шлюза должен быть обновлен по мере развития Claude Code. Справочник протокола шлюза охватывает то, что нужно перенаправлять.

Развертывание шлюза #

Когда вы готовы развернуть LLM gateway для вашей организации, последовательность одинакова независимо от того, какой продукт шлюза вы выберете:

  1. Разверните шлюз и дайте ему учетные данные вашего поставщика, чтобы он мог аутентифицировать запросы, которые он перенаправляет.
  2. Выдайте каждому разработчику учетные данные шлюза, чтобы использование было отнесено разработчику и отключение отзывает одно учетное данные.
  3. Распределите конфигурацию через управляемый файл параметров и ваши инструменты управления секретами, чтобы каждая машина получила базовый URL и учетные данные. Когда оба распределены, разработчики ничего не настраивают. Если у вас нет распределения параметров, разработчики следуют странице подключения для установки переменных самостоятельно.
  4. Попросите каждого разработчика проверить конфигурацию в Claude Code, чтобы проблемы распределения выявились до того, как они будут зависеть от шлюза.

Развертывание LLM gateway для вашей организации проходит каждый шаг и показывает файлы конфигурации для распределения на каждом. Шлюз — это одна часть организационной настройки; для применения политики, видимости использования и решений по обработке данных см. Настройка Claude Code для вашей организации.

Чтобы сделать шлюз, доступный через ANTHROPIC_BASE_URL, единственным пунктом назначения, который может использовать управляемая машина, установите allowedProviders на ["customEndpoint"] в том же управляемом файле параметров и поместите ANTHROPIC_BASE_URL шлюза в блок env этого файла. Claude Code затем отказывает в сеансе, направленном куда-либо еще, включая непосредственно в Anthropic или на собственный прокси разработчика, и принимает ANTHROPIC_BASE_URL только со значением, которое вы там установили. Для шлюза, доступного через переменную конечной точки, специфичную для поставщика, такую как ANTHROPIC_BEDROCK_BASE_URL, запись allowedProviders указывает, какую переменную закрепить. Требуется Claude Code v2.1.285 или более поздняя версия.

[!NOTE]

Когда в Desktop выполнен вход в claude.ai, сессия Cowork на машине пользователя считается "anthropic". Если вы не включите это значение в данный список в политике MDM или файле управляемых настроек, такая сессия будет отклонена. Если же включите, то сессии, отправляемые непосредственно в Anthropic, также пройдут проверку по этому списку.

Подписки и шлюзы #

Пока активна переменная учетных данных шлюза или apiKeyHelper, запросы несут эти учетные данные вместо входа подписки claude.ai разработчика, и ограничения использования подписки не применяются к ним. Claude Code сохраняет вход claude.ai на машине, но не отправляет его с этими запросами. Этот трафик выставляется счетом за токен тому, кто владеет учетными данными, которые перенаправляет шлюз, например вашей учетной записи Anthropic Console организации, или вашей учетной записи Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry, когда шлюз маршрутизирует туда.

ANTHROPIC_BASE_URL — это переменная, которая указывает Claude Code на шлюз. Если задать только эту переменную без учётных данных шлюза, подписка не заменяется. Запросы по-прежнему маршрутизируются через шлюз, но сохранённый вход claude.ai остаётся активными учётными данными, поэтому применяются его лимиты использования и биллинг. Шлюзы, которые передают этот трафик в Anthropic, должны перенаправлять Authorization и возможность OAuth в anthropic-beta; см. справочник заголовков запроса.
