Эффективное управление затратами #

Отслеживайте использование токенов, устанавливайте лимиты расходов команды и снижайте затраты Claude Code с помощью управления контекстом, выбора модели, настроек расширенного мышления и предварительной обработки hooks.

Claude Code взимает плату в зависимости от потребления API токенов. Для информации о ценах плана подписки (Pro, Max, Ultra, Team, Enterprise) см. claude.com/pricing. Затраты на разработчика сильно варьируются в зависимости от выбора модели, размера кодовой базы и паттернов использования, таких как запуск нескольких экземпляров или автоматизация.

В масштабах корпоративных развёртываний средняя стоимость составляет около \$13 на разработчика в активный день и \$150-250 на разработчика в месяц, при этом затраты остаются ниже \$30 в активный день для 90% пользователей. Чтобы оценить расходы для вашей команды, начните с небольшой пилотной группы и используйте инструменты отслеживания ниже для установления базовой линии перед более широким развёртыванием.

На этой странице рассматривается только использование Claude Code: как отслеживать ваши затраты, управлять затратами для вашей организации и снижать использование токенов. Сведения о лимитах использования в других продуктах Claude см. в Справочном центре Claude.

Отслеживание ваших затрат #

Использование команды /usage #

[!NOTE]

Блок Session в /usage показывает использование токенов API и предназначен для пользователей API. Для подписчиков Claude Pro, Max и Ultra использование включено в подписку, поэтому цифра стоимости сессии не имеет значения для целей биллинга. Подписчики видят полосы использования плана, статистику активности и разбивку использования на том же экране.

Выполните /usage в промпте Claude Code и посмотрите под заголовком Session использование токенов в вашей текущей сессии.

Claude Code вычисляет цифру в долларах локально на основе количества токенов по цене списка, если только не действует таблица modelPricing. Администратор устанавливает её в управляемых настройках вашей организации, чтобы цифра использовала ваши договорные ставки, и пока таблица действует, строка Total cost содержит примечание at your organization's configured rates. Цифра является оценкой, поэтому для точных данных биллинга см. Управление затратами для вашей организации.

```text theme={null} Total cost: $0.55 Total duration (API): 6m 20s Total duration (wall): 6h 33m 10s Total code changes: 0 lines added, 0 lines removed Usage by model: claude-sonnet-4-6: 1.2k input, 5.3k output, 940.0k cache read, 50.0k cache write ($0.55)


Эти итоги сбрасываются, когда `/clear` начинает новую сессию, поэтому общая стоимость следующей сессии начинается с \$0. До версии v2.1.211 они продолжали накапливаться в `/clear` на протяжении всего времени жизни процесса Claude Code.

Для ответа от Claude API, тарифицированного по [ставке резидентности данных](https://platform.claude.com/docs/en/about-claude/pricing#data-residency-pricing) 1,1×, Claude Code умножает цену списка токенов этого ответа на 1,1 в цифре стоимости сессии. Та же сумма отображается в [поле стоимости строки состояния](https://code.claude.com/docs/ru/statusline.md#cost-and-duration-tracking), а умноженная цифра также учитывается в [`--max-budget-usd`](https://code.claude.com/docs/ru/cli-reference#cli-flags).

#### Статистика кэша подсказок

После первого ответа API основного разговора Claude Code также добавляет строку `Prompt cache (main)` в блок Session, суммируя использование [кэша подсказок](https://code.claude.com/docs/ru/prompt-caching.md) сессии: количество запросов, доля входных токенов, обслуживаемых из кэша, промахи кэша и находится ли кэш в горячем состоянии прямо сейчас. Требуется Claude Code v2.1.251 или более поздняя версия.

Prompt cache (main): 14 requests · 91% of input tokens from cache · 2 misses (last 6m 10s ago, 310.2k tokens re-cached) · 1 expected rebuild (compaction or tool-result clearing) · warm (1h TTL, last activity 40s ago)


Промахи, ожидаемые перестроения и горячие или холодные части строки означают следующее:

* **Misses**: запросы, которые повторно обработали содержимое, которое кэш уже содержал, с временем последнего промаха и количеством токенов, которые эти запросы записали обратно в кэш. [Действия, которые инвалидируют кэш](https://code.claude.com/docs/ru/prompt-caching.md#actions-that-invalidate-the-cache), перечисляют обычные причины. Когда Claude Code может определить вероятную причину последнего промаха, строка её называет, например `likely cause: tool definitions changed`. Текст вероятной причины требует Claude Code v2.1.260 или более поздней версии.
* **Expected rebuilds**: когда Claude Code сам только что переписал разговор, путём [компактирования](https://code.claude.com/docs/ru/prompt-caching.md#compacting-the-conversation) или путём очистки старых результатов инструментов из контекста, он считает тот же вид промаха как ожидаемое перестроение вместо этого. Эта часть появляется только после того, как произошло по крайней мере одно ожидаемое перестроение.
* **Warm or cold**: находится ли кэшированный префикс всё ещё в пределах своего [времени жизни кэша](https://code.claude.com/docs/ru/prompt-caching.md#cache-lifetime), с действующим TTL. Когда кэш холодный, строка показывает, как долго сессия была неактивна. Когда ни один ответ не сообщил о токенах кэша, строка заканчивается `no prompt caching reported by the API` вместо этого.

Подсчёты поступают из полей токенов кэша в ответах API, поэтому строка работает на каждом поставщике и шлюзе. Она охватывает только основной разговор, а не подагентов. `/clear` сбрасывает её вместе с остальной частью блока Session.

Скрипты строки состояния могут читать те же числа из объекта [`prompt_cache`](https://code.claude.com/docs/ru/statusline#prompt-cache-fields).

#### Разбивка использования плана

На плане Pro, Max, Ultra, Team или Enterprise `/usage` также показывает разбивку того, что учитывается в пределах ваших лимитов плана, с рекомендациями:

* **Attribution**: недавнее использование, отнесённое к skills, subagents, plugins и отдельным MCP серверам, каждый показан в процентах от общего объёма. Доля MCP сервера учитывает только запросы, которые потребили один из результатов его инструментов. До версии v2.1.222 после одного вызова MCP сервера Claude Code относил каждый последующий запрос к этому серверу, завышая его долю.
* **Recommendations**: предлагаемые изменения, по одному на строку. Каждая строка начинается с доли вашего недавнего использования, не менее 10%, как в `25%  Trim ~/code/api/CLAUDE.md · 49k tokens per request`.
  * **Как читать долю**: она показывает, к какой части вашего использования относится строка, а не сколько сэкономит изменение. Один запрос может учитываться в нескольких строках, поэтому сумма долей может превышать 100%.
  * **Как применить рекомендации**: чтобы Claude Code применил те из них, которые может, см. [Применение рекомендаций с помощью сочетания клавиш исправления](#apply-recommendations-with-the-fix-shortcut)
* **Loops**: строка для каждой из самых тяжёлых [`/loop` или других запланированных задач уровня сессии](https://code.claude.com/docs/ru/scheduled-tasks), которые недавно выполнялись, упорядоченных по общему количеству токенов, с подсчётом остальных. Требуется Claude Code v2.1.242 или более поздняя версия.
  * **Что сообщает каждая строка**: как часто срабатывает задача, сколько раз она выполнялась, её общее количество токенов и количество токенов на один запуск, а также когда она выполнялась в последний раз
  * **Остановленные и пересозданные циклы**: Claude Code идентифицирует строку по промпту задачи, поэтому цикл, который вы остановили и пересоздали, остаётся одной строкой

Нажмите `d` или `w` для переключения между последними 24 часами и последними 7 днями. Цифры являются приблизительными и вычисляются из локальной истории сессии на этом устройстве, поэтому использование с других устройств или claude.ai не включено.

В [расширении VS Code](https://code.claude.com/docs/ru/vs-code.md#check-account-and-usage) доли атрибуции и рекомендации появляются в диалоговом окне Account & usage с переключателем Day и Week, без строк Loops.

#### Применение рекомендаций с помощью сочетания клавиш исправления

Когда в нижней строке `/usage` отображается подсказка, например `f to fix 2 of 3`, нажмите `f`, чтобы Claude Code выполнил те рекомендации, которые может. Сочетание клавиш `f` требует Claude Code v2.1.305 или более поздней версии.

1. После завершения текущего хода Claude Code выполняет каждую команду [`/effort`](https://code.claude.com/docs/ru/model-config#adjust-effort-level), показанную в строке без `run`.
2. Затем Claude получает один промпт с шагом для каждой из остальных строк, по которым он может действовать. Промпт просит Claude показывать вам каждое изменение перед его внесением.

Чтобы узнать, что делает нажатие `f` с каждой из ваших строк, найдите вид строки в первом столбце:

| Вид строки | Пример строки | Когда вы нажимаете `f` |
| :- | :- | :- |
| Заканчивается командой `/effort` без `run` перед ней | `40%  Switch from max to high effort · /effort high` | Claude Code выполняет команду |
| Заканчивается `run` и командой | `30%  Compact before you step away · run /compact` | Для этой строки ничего не происходит. Выполните команду самостоятельно в промпте Claude Code |
| Заканчивается чем-то другим | `25%  Trim ~/code/api/CLAUDE.md · 49k tokens per request` | Для некоторых из этих строк Claude получает шаг в промпте, а для остальных ничего не происходит. Если Claude не показывает вам изменений для строки, выполните эту рекомендацию самостоятельно |

В `f to fix 2 of 3` первое число — это количество строк, по которым Claude Code действует при нажатии `f`, а второе — количество показанных строк. Подсказка без `of`, например `f to fix both`, означает, что Claude Code действует по всем показанным строкам.

Пока [Remote Control](https://code.claude.com/docs/ru/remote-control.md) подключён, в нижней строке нет подсказки `f`. Если нажатие `f` закрывает `/usage` с сообщением `Nothing was sent. Turn off Remote Control to use fixes.`, значит, Remote Control подключился, пока `/usage` был открыт. Чтобы снова использовать `f`, [отключите Remote Control](https://code.claude.com/docs/ru/remote-control.md#check-connection-status), затем выполните `/usage` в промпте Claude Code и снова нажмите `f`.

#### Проверка расходов кредитов использования

`/usage` также показывает строку кредитов использования, пока [кредиты использования](#add-usage-credits-to-your-subscription) включены. То, что показывает строка, зависит от вашего плана:

* **Pro, Max и Ultra**: ваши расходы за текущий месяц в сравнении с вашим ежемесячным лимитом расходов, если вы его установили. Если вы не установили лимит, строка показывает `Unlimited` без цифры расходов.
* **Team and Enterprise**: ваши собственные расходы за текущий месяц, измеренные в сравнении с любым [лимитом, установленным вашей организацией](#claude-for-teams-and-enterprise), который к вам применяется. Лимит, который охватывает всю организацию, не появляется в строке. Когда у вас нет собственного лимита, строка показывает ваши расходы без лимита рядом с ним. Пока кредиты использования отключены для вас, `/usage` не показывает строку кредитов использования.

Когда у вас есть лимит расходов, строка появляется, как только кредиты использования включены, и показывает 0% до тех пор, пока вы не потратите кредиты использования в первый раз. До версии v2.1.236 `/usage` показывал строку только на планах Pro, Max и Ultra, и строка с лимитом расходов оставалась скрытой до тех пор, пока вы не потратили что-то.

#### Когда запрос использования не удаётся

Когда запрос к пределам вашего плана не удаётся, чаще всего потому, что конечная точка использования имеет ограничение по частоте запросов, `/usage` показывает последние полосы использования, которые она загрузила на этом устройстве в течение последних 60 минут, вместе с примечанием `Showing last-known usage`, указывающим, как давно эти данные были получены. Нажмите `r` для повторной попытки; успешная повторная попытка заменяет последние известные полосы свежими данными. Без снимка из последних 60 минут `/usage` сообщает, что конечная точка использования имеет ограничение по частоте запросов и предлагает тот же ярлык повторной попытки. До версии v2.1.208 ограниченный по частоте запрос в сессии, которая ещё не загружала использование, всегда показывал ошибку без полос.

Сообщение вроде `rate limited until 3:14am` в `/usage` означает, что Claude Code не может снова получить лимиты вашего плана до этого времени, а не то, что ваша работа с Claude ограничена. Если вы нажмёте `r` раньше, ожидайте то же сообщение. Нажмите `r` после этого времени, чтобы получить свежие данные.

### Чтение счётчика токенов рядом со спиннером

Пока Claude работает в основном диалоге, строка рядом со спиннером может заканчиваться прошедшим временем и количеством токенов, как в `Deciphering… (10m 27s · ↓ 5.5k tokens)`. Это приблизительный счётчик в реальном времени для вывода, который текущий ход сгенерировал на данный момент. Стрелка рядом со счётчиком направлена вниз, пока поступает вывод или выполняются инструменты.

* **Что он учитывает**: вывод, который генерирует ход, например текст и вызовы инструментов, которые Claude передаёт потоком, его размышления и вывод субагентов, работающих на [переднем плане](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background)
* **Что он не учитывает**: то, что Claude Code отправляет модели, поэтому ваш промпт, история диалога и остальной контекст на него не влияют
* **Когда он сбрасывается**: в начале каждого хода и когда Claude Code [сжимает диалог](https://code.claude.com/docs/ru/prompt-caching.md#compacting-the-conversation)
* **Когда он скрыт**: пока не начнёт поступать вывод, когда строка слишком узкая, чтобы его вместить, и в [режиме программы чтения с экрана](https://code.claude.com/docs/ru/accessibility.md)

Он не совпадёт с цифрами вывода `Usage by model` в блоке Session команды `/usage`, которые суммируют всю сессию, а не один ход. Он также отличается от счётчика токенов, который [добавляет подробный режим](https://code.claude.com/docs/ru/statusline.md#notifications-share-the-status-line-row), потому что тот счётчик измеряет размер вашего контекста, а не вывод одного хода.

### Анализ ваших моделей использования

Запустите [`/insights`](https://code.claude.com/docs/ru/commands#all-commands) для отчёта о том, как вы работаете, а не о том, сколько токенов вы использовали. Он анализирует ваши недавние сессии на этом устройстве и пишет отчёт HTML, охватывающий то, над чем вы работаете, точки трения, такие как неправильно понятые запросы или ошибочный код, и предложения по более эффективному использованию Claude Code. Один запуск анализирует до 200 сессий, которые он ещё не видел, и пропускает очень короткие. Когда сессии исключены, заголовок отчёта показывает проанализированное количество с общим количеством в скобках, например `200 sessions (412 total)`.

Когда [автоматический режим](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) доступен для сессии и ваши недавние сессии в основном выполнялись без него, отчёт также может включать оценку того, сколько подсказок разрешений автоматический режим мог бы обработать в этих сессиях.

Claude Code пишет последний отчёт в `~/.claude/usage-data/report.html` и сохраняет копию с временной меткой каждого запуска в том же каталоге, поэтому более ранние отчёты не перезаписываются. Claude Code удаляет отчёты по тому же расписанию, что и остальные данные вашей сессии: при запуске он удаляет файлы старше [`cleanupPeriodDays`](https://code.claude.com/docs/ru/claude-directory#cleaned-up-automatically), 30 дней по умолчанию.

Вы можете запустить `/insights` на любом плане и с любым поставщиком. Анализ выполняется через того же поставщика и аккаунт, что и ваши обычные сессии, и токены учитываются в вашем плане или использовании API. Сессии с других устройств и claude.ai не включены.

### Добавление кредитов использования к вашей подписке

[Кредиты использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) позволяют вам продолжать работу после лимита использования вашего плана. Для управления ими запустите `/usage-credits` после входа с вашей подпиской claude.ai через `/login`; команда недоступна при аутентификации по ключу API. В самообслуживаемых организациях Enterprise, пробных версиях Enterprise и организациях Enterprise, выставленных через AWS Marketplace, команда требует Claude Code v2.1.248 или более поздней версии; более ранние версии отклоняют её с [`Unknown command: /usage-credits`](https://code.claude.com/docs/ru/errors#unknown-command). То, что она открывает, зависит от вашей роли:

| Ваша роль | Что делает `/usage-credits` |
| :- | :- |
| Подписчик Pro, Max или Ultra | Открывает [**Settings > Usage**](https://claude.ai/settings/usage) на claude.ai в браузере. В его разделе **Usage credits** вы можете включить или отключить кредиты использования и проверить баланс кредитов, расходы этого месяца и ежемесячный лимит расходов |
| Участник Team или Enterprise с доступом к биллингу | Открывает настройки использования вашей организации, [**Organization settings > Usage**](https://claude.ai/admin-settings/usage), в браузере |
| Член Team или Enterprise без доступа к выставлению счётов | Просит вас подтвердить, затем отправляет запрос администраторам вашей организации. До версии v2.1.211 Claude Code отправлял запрос без шага подтверждения |

Для членов Team и Enterprise без доступа к выставлению счётов подтверждение появляется только в интерактивных сессиях: в неинтерактивном режиме с флагом `-p` и из [Remote Control](https://code.claude.com/docs/ru/remote-control.md) команда не отправляет запрос и говорит вам запустить её в интерактивной сессии вместо этого.

Если вы запустите `/usage-credits` снова, пока ваш более ранний запрос ожидает администратора, Claude Code говорит вам, что запрос уже был отправлен, а не отправляет дубликат. После того как администратор отклонит ваш запрос, запуск команды снова отправляет новый. До версии v2.1.222 отклонённый запрос также блокировал новые запросы.

На планах Pro, Max и Ultra, когда вы достигнете лимита расходов с доступными кредитами использования, Claude Code предлагает вам увеличить или удалить лимит без выхода из CLI. Если сервер отклоняет изменение, см. [Could not update your spend limit](https://code.claude.com/docs/ru/errors.md#could-not-update-your-spend-limit).

## Управление затратами для вашей организации

Какие элементы управления у вас есть, зависит от того, как ваша организация получает доступ к Claude Code: через план Claude for Teams или Enterprise, Claude Console или облачного провайдера. На планах Teams и Enterprise использование берётся из лимита каждого члена команды. На Console и у облачных провайдеров использование оплачивается за токен вашей организацией. Если ваша организация использует смешанные методы входа, каждый разработчик учитывается в соответствии с тем, с помощью которого он прошёл аутентификацию.

В таблице указано, где вы видите расходы, где их ограничиваете и как получить данные по пользователям для каждой конфигурации. На индивидуальном плане Pro, Max или Ultra у вас нет организации для управления, поэтому отслеживайте собственные расходы на кредиты использования, включая [быстрый режим](https://code.claude.com/docs/ru/fast-mode.md#see-where-fast-mode-spend-appears), в разделе [Добавление кредитов использования в вашу подписку](#add-usage-credits-to-your-subscription).

| Ваша конфигурация | Просмотр расходов | Ограничение расходов | Отчётность по пользователям |
| :- | :- | :- | :- |
| [Claude for Teams или Enterprise](#claude-for-teams-and-enterprise) | [Отчёт о расходах в аналитике организации](https://support.claude.com/en/articles/12883420-view-usage-analytics-for-team-and-enterprise-plans) | Лимиты расходов в параметрах администратора | [CSV отчёт о расходах](https://support.claude.com/en/articles/12883420-view-usage-analytics-for-team-and-enterprise-plans); [Enterprise Analytics API](https://platform.claude.com/docs/en/api/admin/analytics) на Enterprise |
| [Claude Console (API)](#claude-console) | [Страница Cost в Console](https://platform.claude.com/cost) | Лимиты расходов рабочего пространства | [Панель управления Console](https://platform.claude.com/claude-code), [Claude Code Analytics API](https://platform.claude.com/docs/en/build-with-claude/claude-code-analytics-api) |
| [Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry](#cloud-providers) | Ваша консоль биллинга облака | Элементы управления бюджетом вашего облака | [OpenTelemetry](https://code.claude.com/docs/ru/monitoring-usage.md) или [LLM gateway](https://code.claude.com/docs/ru/llm-gateway) |

[Экспорт OpenTelemetry](https://code.claude.com/docs/ru/monitoring-usage.md) работает на каждой конфигурации и является единственным вариантом, который передаёт метрики токенов и затрат по пользователям в ваш собственный стек наблюдаемости практически в реальном времени.

### Отчётность о расходах по вашим договорным ставкам

По умолчанию Claude Code вычисляет каждую цифру затрат, которую он показывает разработчикам, по прейскурантной цене, поэтому если ваша организация платит по договорным ставкам, цифры в `/usage`, строке статуса и OpenTelemetry не совпадают с вашим счётом. Чтобы они совпадали, установите управляемый параметр [`modelPricing`](https://code.claude.com/docs/ru/settings-reference#modelpricing) на ваши ставки. Параметр изменяет то, что Claude Code сообщает, а не то, что Anthropic взимает. Требуется Claude Code v2.1.242 или позже.

**1. Возьмите ставки из вашего контракта**

Введите ставки за миллион токенов из вашего контракта. Claude Code не получает их из Claude Console, поэтому обновляйте параметр при изменении контракта.

**2. Напишите параметр**

Установите `multiplier` ниже 1 для фиксированной скидки или выше 1 для надбавки, перечислите четыре ставки за токен каждой модели в `overrides` или сделайте и то, и другое. Надбавка требует Claude Code v2.1.271 или позже. Запись [`modelPricing`](https://code.claude.com/docs/ru/settings-reference#modelpricing) содержит форму и готовый к вставке пример.

**3. Разверните его через управляемые параметры**

Доставьте его как [управляемые параметры](https://code.claude.com/docs/ru/managed-settings.md): параметры, управляемые сервером, политика MDM, `managed-settings.json` или [помощник политики](https://code.claude.com/docs/ru/managed-settings.md#compute-the-policy-with-a-helper-program). Claude Code игнорирует ключ в параметрах пользователя, проекта и локальных параметрах и в `--settings`.

Чтобы подтвердить, что ставки действуют, запустите `/usage` в сеансе, который [получил управляемые параметры](https://code.claude.com/docs/ru/managed-settings.md#read-the-source-in-%2Fstatus): строка `Total cost` блока Session содержит примечание `at your organization's configured rates`. Цифры по-прежнему являются оценками, а не счётом. Цены за миллион токенов в средстве выбора `/model` остаются по прейскурантной цене.

### Claude for Teams и Enterprise

На планах Claude for Teams и Enterprise использование Claude Code каждого члена команды берётся из лимита на одного пользователя, который сбрасывается в скользящем пятичасовом окне и еженедельном окне. Лимит совместно используется с Claude chat и Cowork, а его размер зависит от [уровня места](https://support.claude.com/en/articles/11845131-use-claude-code-with-your-team-or-enterprise-plan) (Standard или Premium). Ваши элементы управления находятся в консоли администратора claude.ai, а не в Claude Console.

* **Просмотр расходов**: [отчёт о расходах в аналитике организации](https://support.claude.com/en/articles/12883420-view-usage-analytics-for-team-and-enterprise-plans) показывает предполагаемые расходы по пользователям и по моделям с экспортом CSV, обновляется ежедневно. Отчёт охватывает расходы кредитов использования и появляется после включения кредитов использования. Использование в пределах лимита на одного пользователя не учитывается в долларах.
* **Просмотр внедрения**: [панель аналитики](https://claude.ai/analytics/claude-code) показывает ежедневно активных пользователей, сеансы и метрики вклада с экспортом CSV данных о вкладе. См. [отслеживание использования команды с помощью аналитики](https://code.claude.com/docs/ru/analytics.md).
* **Ограничение расходов**: лимит на одного пользователя является потолком по умолчанию. Чтобы позволить членам продолжить работу после его достижения, включите [кредиты использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) и установите лимиты расходов на уровне организации, группы или отдельного члена команды.
* **Получение данных по пользователям**: на плане Enterprise [Enterprise Analytics API](https://platform.claude.com/docs/en/api/admin/analytics) возвращает отчёты об использовании и затратах по пользователям на всех поверхностях Claude, включая Claude Code. Основной владелец создаёт ключ с областью `read:analytics` на [claude.ai/analytics/api-keys](https://claude.ai/analytics/api-keys). На плане Teams экспортируйте [CSV отчёт о расходах](https://support.claude.com/en/articles/12883420-view-usage-analytics-for-team-and-enterprise-plans), который содержит использование токенов и предполагаемые расходы по пользователям и по моделям.

[Руководство по потреблению Claude Enterprise](https://support.claude.com/en/articles/14782391-claude-enterprise-consumption-guide) является справочником по планированию для администраторов. Оно объясняет, как потребление отличается на Claude chat, Claude Code и Cowork, и даёт начальные точки в долларах на пользователя для бюджетирования. Выделите больше средств на место для кодирования, чем на место для чата: каждый ход Claude Code содержит содержимое файлов, вызовы инструментов и многошаговое рассуждение, поэтому один сеанс отладки может потребить больше, чем день чата.

### Claude Console

Организации API управляют расходами Claude Code через [рабочие пространства](https://platform.claude.com/docs/en/build-with-claude/workspaces). Вы можете [установить лимиты расходов рабочего пространства](https://platform.claude.com/docs/en/build-with-claude/workspaces#workspace-limits) на общие расходы Claude Code и [просмотреть отчёты о затратах и использовании](https://platform.claude.com/docs/en/build-with-claude/workspaces#usage-and-cost-tracking) в Console.

> [!NOTE]
>
> Когда вы впервые аутентифицируете Claude Code с помощью своей учётной записи Claude Console, автоматически создаётся рабочее пространство под названием "Claude Code". Это рабочее пространство обеспечивает централизованное отслеживание и управление затратами для всего использования Claude Code в вашей организации. Вы не можете создавать API ключи для этого рабочего пространства; оно предназначено исключительно для аутентификации и использования Claude Code.
>
> Для организаций с пользовательскими ограничениями скорости трафик Claude Code в этом рабочем пространстве учитывается в общих ограничениях скорости API вашей организации. Вы можете установить [ограничение скорости рабочего пространства](https://platform.claude.com/docs/en/api/rate-limits#setting-lower-limits-for-workspaces) на странице Limits этого рабочего пространства в Claude Console, чтобы ограничить долю Claude Code и защитить другие производственные рабочие нагрузки.

Для отчётности по пользователям [панель управления Console](https://platform.claude.com/claude-code) показывает расходы и принятые строки на члена команды, а [Claude Code Analytics API](https://platform.claude.com/docs/en/build-with-claude/claude-code-analytics-api) программно возвращает ежедневные метрики по пользователям с помощью [Admin API-ключа](https://platform.claude.com/settings/admin-keys). См. [аналитика для клиентов API](https://code.claude.com/docs/ru/analytics.md#access-analytics-for-api-customers).

#### Рекомендации по ограничению скорости

При настройке Claude Code для команд учитывайте эти рекомендации по Token Per Minute (TPM) и Request Per Minute (RPM) на пользователя в зависимости от размера вашей организации:

| Размер команды | TPM на пользователя | RPM на пользователя |
| - | - | - |
| 1-5 пользователей | 200k-300k | 5-7 |
| 5-20 пользователей | 100k-150k | 2.5-3.5 |
| 20-50 пользователей | 50k-75k | 1.25-1.75 |
| 50-100 пользователей | 25k-35k | 0.62-0.87 |
| 100-500 пользователей | 15k-20k | 0.37-0.47 |
| 500+ пользователей | 10k-15k | 0.25-0.35 |

Например, если у вас есть 200 пользователей, вы можете запросить 20k TPM для каждого пользователя, или 4 миллиона общего TPM (200\*20,000 = 4 миллиона).

TPM на пользователя уменьшается по мере роста размера команды, потому что в более крупных организациях меньше пользователей, как правило, используют Claude Code одновременно. Эти ограничения скорости применяются на уровне организации, а не для отдельного пользователя, что означает, что отдельные пользователи могут временно потреблять больше, чем их рассчитанная доля, когда другие не активно используют сервис.

> [!NOTE]
>
> Если вы предполагаете сценарии с необычно высоким одновременным использованием (такие как живые сеансы обучения с большими группами), вам может потребоваться более высокое распределение TPM на пользователя.

### Облачные провайдеры

На Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry Claude Code оплачивается за токен на ваш облачный счёт, и элементы управления расходами находятся в консоли биллинга вашего облачного провайдера. Claude Code не отправляет метрики из вашего облака обратно в Anthropic, поэтому [панели аналитики](https://code.claude.com/docs/ru/analytics.md) и Claude Code Analytics API не охватывают это использование.

Для атрибуции затрат по пользователям у вас есть три варианта:

* **OpenTelemetry**: [экспортируйте метрики](https://code.claude.com/docs/ru/monitoring-usage.md) с машины каждого разработчика в ваш собственный стек наблюдаемости. Это даёт вам подсчёты токенов по пользователям, затраты и активность инструментов независимо от провайдера.
* **Шлюз Claude apps**: самостоятельно размещённый [Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway) обеспечивает атрибуцию использования по пользователям, метрики OTLP с подсчётом токенов и [лимиты расходов по пользователям](https://code.claude.com/docs/ru/claude-apps-gateway-spend-limits.md) на этих провайдерах.
* **LLM gateway**: маршрутизируйте весь трафик Claude Code через прокси, который отслеживает расходы по ключу. Несколько крупных предприятий сообщили об использовании [LiteLLM](https://code.claude.com/docs/ru/llm-gateway), инструмента с открытым исходным кодом, который [отслеживает расходы по ключу](https://docs.litellm.ai/docs/proxy/virtual_keys#tracking-spend). Этот проект не связан с Anthropic и не был проверен на безопасность.

### Когда разработчик спрашивает об ограничении

Разработчики обычно обращаются к своему администратору с вопросами об ограничениях, поэтому полезно знать, какой потолок они достигли. Эти ситуации означают разные вещи:

* **"Вы достигли лимита сеанса" или "Вы достигли еженедельного лимита"**: ограничение использования на основе места в окне подписки, совместно используемое на всех моделях, поэтому разработчик не может восстановить доступ, переключив модели с помощью `/model`. Сообщение показывает, когда окно сбросится. После сообщения "Вы достигли лимита Opus" или "Вы достигли лимита Sonnet", переключение на модель вне этого семейства с помощью `/model` позволяет разработчику продолжить работу. См. [ошибки лимита использования](https://code.claude.com/docs/ru/errors.md#youve-hit-your-session-limit). Что разработчик может сделать в то же время:
  * Запустите `/usage-credits`, чтобы запросить использование сверх лимита, если у вас включены [кредиты использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans).
  * На Claude Code v2.1.234 или позже, [ждите и продолжайте прерванную задачу автоматически после сброса лимита использования](https://code.claude.com/docs/ru/interactive-mode.md#wait-for-a-usage-limit-to-reset); этот раздел указывает, когда Claude Code начинает ожидание самостоятельно и когда разработчик выбирает его из `/rate-limit-options`. Чтобы контролировать для вашего парка, начинает ли Claude Code это ожидание самостоятельно, установите [`autoContinueAtUsageLimit`](https://code.claude.com/docs/ru/settings-reference#autocontinueatusagelimit) в [управляемых параметрах](https://code.claude.com/docs/ru/settings.md#settings-precedence).
* **"You've hit your individual spend limit", "org's monthly spend limit" или "team's shared budget"**: запрос разработчика будет оплачен из кредитов использования, и эти кредиты достигли лимита расходов, который вы установили. Чтобы позволить разработчику продолжить, перейдите в [**Organization settings > Usage**](https://claude.ai/admin-settings/usage) и увеличьте лимит, который называет сообщение. Когда сообщение также называет время сброса плана, разработчик может вместо этого дождаться этого момента. См. [справочник по ошибкам](https://code.claude.com/docs/ru/errors.md#youve-hit-your-monthly-spend-limit) для каждого варианта.
* **Сообщение об ограничении расходов от [Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway)**: разработчик превысил лимит расходов, который вы установили на своём самостоятельно размещённом шлюзе. Шлюз блокирует его запросы, пока вы не повысите лимит или пока лимит не сбросится, если он выше \$0. См. [лимиты расходов шлюза](https://code.claude.com/docs/ru/claude-apps-gateway-spend-limits.md) для лимитов, расписания сброса и сообщения, которое видит разработчик.
* **Предупреждение о контексте или auto-compact**: не является лимитом использования. Разговор вырос близко к [окну auto-compact](https://code.claude.com/docs/ru/model-config.md#set-the-auto-compact-window) сеанса, пороговому значению, где Claude Code суммирует более старую историю, чтобы освободить место. Направьте разработчика на [снижение использования токенов](#reduce-token-usage).
* **Неожиданно высокие расходы на плане API или облачного провайдера**: обычно восходит к длительным сеансам, которые никогда не были очищены, или к Opus, оставленному в качестве модели по умолчанию. Наиболее эффективные привычки для совместного использования — это очистка между несвязанными задачами и соответствие модели работе, оба охватываются в [снижение использования токенов](#reduce-token-usage).

### Затраты на токены команды агентов

[Команды агентов](https://code.claude.com/docs/ru/agent-teams.md) запускают несколько экземпляров Claude Code, каждый со своим собственным контекстным окном. Использование токенов масштабируется в зависимости от количества активных товарищей по команде и того, как долго каждый из них работает.

Чтобы сохранить затраты команды агентов управляемыми:

* Используйте Sonnet для товарищей по команде. Он обеспечивает баланс между возможностями и стоимостью для задач координации.
* Держите команды небольшими. Каждый товарищ по команде запускает своё собственное контекстное окно, поэтому использование токенов примерно пропорционально размеру команды.
* Держите spawn prompts сфокусированными. Товарищи по команде автоматически загружают CLAUDE.md, MCP servers и skills, но всё в spawn prompt добавляется к их контексту с самого начала.
* Очищайте команды после завершения работы. Активные товарищи по команде продолжают потреблять токены до тех пор, пока они не выйдут или сеанс не завершится.
* Команды агентов отключены по умолчанию. Установите `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` в вашем [settings.json](https://code.claude.com/docs/ru/settings.md) или переменной окружения, чтобы включить их. См. [включение команд агентов](https://code.claude.com/docs/ru/agent-teams.md#enable-agent-teams).

## Снижение использования токенов

Затраты на токены масштабируются с размером контекста: чем больше контекста обрабатывает Claude, тем больше токенов вы используете. Claude Code автоматически оптимизирует затраты через [кэширование промптов](https://code.claude.com/docs/ru/prompt-caching.md), что снижает затраты на повторяющееся содержимое, такое как системные промпты, и автосжатие, которое суммирует историю диалога при приближении к лимитам контекста.

Следующие стратегии помогают вам сохранять контекст небольшим и снижать затраты на сообщение.

### Управление контекстом проактивно

Используйте `/usage` для проверки текущего использования токенов или [настройте вашу строку состояния](https://code.claude.com/docs/ru/statusline.md#context-window-usage) для непрерывного отображения.

* **Очищайте между задачами**: Используйте `/clear` для начала с чистого листа при переходе на несвязанную работу. Устаревший контекст тратит токены на каждое последующее сообщение. Используйте `/rename` перед очисткой, чтобы вы могли найти сессию позже, затем `/resume` для возврата к ней.
* **Добавляйте пользовательские инструкции сжатия контекста**: `/compact Focus on code samples and API usage` говорит Claude, что сохранять во время суммирования.

Вы также можете настроить поведение сжатия контекста в вашем файле CLAUDE.md в корне вашего проекта:

Compact instructions #

When you are using compact, please focus on test output and code changes


### Выберите правильную модель

Sonnet хорошо справляется с большинством задач кодирования и стоит дешевле, чем Opus. Зарезервируйте Opus для сложных архитектурных решений или многошаговых рассуждений. Используйте `/model` для переключения моделей в середине сессии или установите значение по умолчанию в `/config`. Переключение на Opus также применяется к [субагентам, которые наследуют модель вашей сессии](https://code.claude.com/docs/ru/model-config.md#setting-your-model). Для простых задач субагента укажите `model: haiku` в вашей [конфигурации субагента](https://code.claude.com/docs/ru/sub-agents.md#choose-a-model).

### Снижение накладных расходов MCP-серверов

Определения инструментов MCP [отложены по умолчанию](https://code.claude.com/docs/ru/mcp.md#scale-with-mcp-tool-search), поэтому только имена инструментов и инструкции сервера входят в контекст до тех пор, пока Claude не использует конкретный инструмент. Запустите `/context` для просмотра того, что потребляет пространство.

* **Предпочитайте CLI-инструменты, когда доступны**: Инструменты, такие как `gh`, `aws`, `gcloud` и `sentry-cli`, по-прежнему более эффективны по контексту, чем MCP-серверы, потому что они не добавляют никакого списка инструментов. Claude может запускать CLI-команды напрямую.
* **Отключайте неиспользуемые серверы**: Запустите `/mcp` для просмотра настроенных серверов и отключите любые, которые вы не активно используете.

### Установите плагины code intelligence для типизированных языков

[Плагины code intelligence](https://code.claude.com/docs/ru/plugins/code-intelligence.md) дают Claude точную навигацию по символам вместо поиска на основе текста, снижая ненужные чтения файлов при изучении незнакомого кода. Один вызов "go to definition" заменяет то, что в противном случае могло бы быть grep, за которым следует чтение нескольких файлов-кандидатов. Установленные языковые серверы также автоматически сообщают об ошибках типов после редактирования, поэтому Claude ловит ошибки без запуска компилятора.

### Делегируйте обработку хукам и скиллам

Пользовательские [хуки](https://code.claude.com/docs/ru/hooks.md) могут предварительно обрабатывать данные перед тем, как Claude их увидит. Вместо того, чтобы Claude читал лог-файл из 10,000 строк для поиска ошибок, хук может выполнить grep для `ERROR` и вернуть только совпадающие строки, снижая контекст с десятков тысяч токенов до сотен.

Этот хук PreToolUse обрезает вывод тестов до последних 100 строк:

> [tab] settings.json
>
> Добавьте это в ваш [settings.json](https://code.claude.com/docs/ru/settings.md#where-settings-live) для запуска хука перед каждой командой Bash:
>
> ```json theme={null}
> {
>   "hooks": {
>     "PreToolUse": [
>       {
>         "matcher": "Bash",
>         "hooks": [
>           {
>             "type": "command",
>             "command": "~/.claude/hooks/filter-test-output.sh"
>           }
>         ]
>       }
>     ]
>   }
> }
> ```

> [tab] filter-test-output.sh
>
> Хук вызывает этот скрипт. Создайте папку с помощью `mkdir -p ~/.claude/hooks`, сохраните скрипт ниже как `~/.claude/hooks/filter-test-output.sh` и сделайте его исполняемым с помощью `chmod +x ~/.claude/hooks/filter-test-output.sh`. Он проверяет, является ли команда запуском тестов, и если да, оставляет только последние 100 строк её вывода:
>
> ```bash theme={null}
> #!/bin/bash
> input=$(cat)
> cmd=$(echo "$input" | jq -r '.tool_input.command')
>
> # If running tests, keep only the last 100 lines
> pattern='^(npm test|pytest|go test)( [^;&|<>`$#\\[:cntrl:]]*)?$'
> if [[ "$cmd" =~ $pattern ]]; then
>   filtered_cmd="$cmd 2>&1 | tail -n 100"
>   echo "$input" | jq --arg filtered "$filtered_cmd" \
>     '{hookSpecificOutput: {hookEventName: "PreToolUse", updatedInput: (.tool_input + {command: $filtered})}}'
> else
>   echo "{}"
> fi
> ```

Для проверки настройки запустите `/hooks` и проверьте, что хук появляется под PreToolUse. Вы также можете запустить Claude Code с помощью `claude --debug-file ./claude-debug.txt` и попросить Claude запустить `npm test`. Когда хук переписывает команду, этот лог-файл содержит строку `modified tool input keys`, в которой указаны `command` и другие поля ввода Bash.

[Скилл](https://code.claude.com/docs/ru/skills.md) может дать Claude знание предметной области, чтобы ему не пришлось исследовать. Например, скилл "codebase-overview" может описать архитектуру вашего проекта, ключевые директории и соглашения об именовании. Когда Claude вызывает скилл, он получает этот контекст немедленно вместо того, чтобы тратить токены на чтение нескольких файлов для понимания структуры.

### Переместите инструкции из CLAUDE.md в скиллы

Ваш файл [CLAUDE.md](https://code.claude.com/docs/ru/memory.md) загружается в контекст при запуске сессии. Если он содержит подробные инструкции для конкретных рабочих процессов (такие как ревью PR или миграции баз данных), эти токены присутствуют даже когда вы выполняете несвязанную работу. [Скиллы](https://code.claude.com/docs/ru/skills.md) загружаются по требованию только при вызове, поэтому перемещение специализированных инструкций в скиллы сохраняет ваш базовый контекст меньшим. Стремитесь сохранять CLAUDE.md под 200 строк, включая только необходимое.

### Отрегулируйте расширенное мышление

Расширенное мышление включено по умолчанию, потому что оно значительно улучшает производительность на сложных задачах планирования и рассуждения. Токены мышления тарифицируются как выходные токены, и бюджет по умолчанию может составлять десятки тысяч токенов на запрос в зависимости от модели.

Для более простых задач, где глубокое рассуждение не требуется, вы можете снизить затраты, понизив [уровень effort](https://code.claude.com/docs/ru/model-config.md#adjust-effort-level) с помощью `/effort` или в `/model`, или отключив мышление в `/config`. Вы не можете отключить мышление на Opus 5.5, Sonnet 5.5, Haiku 5.5 или моделях Fable, которые всегда используют расширенное мышление.

На моделях с [фиксированным бюджетом мышления](https://code.claude.com/docs/ru/model-config.md#adaptive-reasoning-and-fixed-thinking-budgets) вы также можете понизить бюджет путём установки [переменной окружения](https://code.claude.com/docs/ru/env-vars.md) `MAX_THINKING_TOKENS`, например `MAX_THINKING_TOKENS=8000`. Модели адаптивного рассуждения игнорируют ненулевые бюджеты, поэтому используйте вместо этого уровни effort.

### Делегируйте многословные операции субагентам

Запуск тестов, получение документации или обработка лог-файлов может потребить значительный контекст. Делегируйте это [субагентам](https://code.claude.com/docs/ru/sub-agents.md#isolate-high-volume-operations), чтобы многословный вывод оставался в контексте субагента, в то время как только резюме возвращается в ваш основной диалог.

Собственные запросы субагента по-прежнему расходуют вашу квоту. Чтобы потратить на них меньше, [выберите меньшую модель для субагента](https://code.claude.com/docs/ru/sub-agents.md#choose-a-model) или [запускайте каждого субагента на одной модели](https://code.claude.com/docs/ru/sub-agents.md#run-every-subagent-on-one-model).

### Управление затратами команды агентов

Команды агентов используют примерно в 7 раз больше токенов, чем стандартные сессии, когда участники команды работают в режиме планирования, потому что каждый участник команды поддерживает своё собственное контекстное окно и работает как отдельный экземпляр Claude. Держите задачи команды небольшими и самостоятельными, чтобы ограничить использование токенов на каждого участника команды. См. [команды агентов](https://code.claude.com/docs/ru/agent-teams.md) для деталей.

### Пишите конкретные промпты

Расплывчатые просьбы, такие как "улучшить эту кодовую базу", запускают широкое сканирование. Конкретные просьбы, такие как "добавить проверку входных данных в функцию входа в auth.ts", позволяют Claude работать эффективно с минимальными чтениями файлов.

### Работайте эффективно над сложными задачами

Для более длительной или сложной работы эти привычки помогают избежать потраченных впустую токенов от неправильного направления:

* **Используйте режим планирования для сложных задач**: Нажмите Shift+Tab для переключения в [режим планирования](https://code.claude.com/docs/ru/permission-modes.md#analyze-before-you-edit-with-plan-mode) перед реализацией. Claude исследует кодовую базу и предлагает подход на ваше утверждение, предотвращая дорогостоящую переделку, когда первоначальное направление неправильно.
* **Корректируйте курс рано**: Если Claude начинает идти в неправильном направлении, нажмите Escape для немедленной остановки. Используйте `/rewind` или двойное нажатие Escape для восстановления диалога и кода к предыдущему чекпоинту.
* **Дайте цели проверки**: Включите тестовые случаи, вставьте скриншоты или определите ожидаемый вывод в вашем промпте. Когда Claude может проверить свою собственную работу, он ловит проблемы перед тем, как вам нужно запросить исправления.
* **Тестируйте постепенно**: Напишите один файл, протестируйте его, затем продолжайте. Это позволяет выявить проблемы рано.

## Использование токенов в фоновом режиме

Краткое содержание сессии и сжатие контекста при бездействии могут расходовать токены, пока вы неактивны. Подробнее о том, когда запускается каждая из этих функций и как её отключить, см. в разделах [краткое содержание сессии](https://code.claude.com/docs/ru/interactive-mode.md#session-recap) и [сжатие контекста при бездействии](https://code.claude.com/docs/ru/settings-reference.md#idlecompaction).

Когда предложения подсказок включены, Claude Code также отправляет короткий запрос к модели, которую использует ваша сессия, после ответа Claude, чтобы [предложить вашу следующую подсказку](https://code.claude.com/docs/ru/interactive-mode.md#prompt-suggestions). Этот запрос повторно использует кэш подсказок разговора, поэтому он в основном состоит из чтений кэша плюс несколько выходных токенов. Claude Code [пропускает его, когда ваш аккаунт близок к лимиту использования или достиг его](https://code.claude.com/docs/ru/interactive-mode.md#when-claude-code-skips-suggestions). Чтобы остановить эти запросы, [отключите предложения подсказок](https://code.claude.com/docs/ru/interactive-mode.md#turn-prompt-suggestions-off).

## Почему использование растёт в длительной сессии

Сессия, которая была открыта в течение часов, может использовать намного больше лимитов вашего плана, чем предполагает ваша активность, обычно по одной из этих причин:

* **Длинный контекст**: Claude Code отправляет вашу полную беседу с каждым запросом, и каждый раз, когда Claude использует инструменты, он отправляет ещё один запрос с этой партией результатов инструментов. С [prompt caching](https://code.claude.com/docs/ru/prompt-caching.md) Claude Code перечитывает эту историю по [кэшированному тарифу токенов](https://platform.claude.com/docs/en/about-claude/pricing), поэтому однострочный вопрос в сессии, которая была открыта весь день, всё равно потребляет использование для всей беседы. См. [Управляйте контекстом проактивно](#manage-context-proactively) для способов сохранения вашего контекста в малом размере
* **Промахи кэша**: ваше первое сообщение после перерыва, превышающего [время жизни кэша](https://code.claude.com/docs/ru/prompt-caching.md#cache-lifetime), промахивается мимо кэша и заново обрабатывает ваш полный контекст. См. [какое время жизни получают ваши запросы](https://code.claude.com/docs/ru/prompt-caching.md#which-ttl-each-request-gets) и [средства управления для его настройки](https://code.claude.com/docs/ru/prompt-caching.md#choose-the-ttl-yourself)
* **Запланированные задачи**: [запланированная задача в рамках сессии](https://code.claude.com/docs/ru/scheduled-tasks.md) срабатывает по своему интервалу даже во время простоя сессии, отправляя ваш полный контекст каждый раз
* **Сообщения между сессиями**: Claude Code доставляет [сообщение из другой вашей сессии](https://code.claude.com/docs/ru/cross-session-messaging.md) как новый ход, когда эта сессия находится в режиме ожидания, отправляя ваш полный контекст каждый раз. Чтобы удерживать входящие сообщения вместо их доставки, установите [`crossSessionInbound`](https://code.claude.com/docs/ru/settings-reference#crosssessioninbound) на `hold`
* **Проверки целей**: пока фоновая работа держит активную [цель](https://code.claude.com/docs/ru/goal.md) в ожидании, Claude Code [просит Claude проверить эту работу](https://code.claude.com/docs/ru/goal.md#background-work-defers-evaluation) даже когда сессия находится в режиме ожидания, начиная новый ход, который отправляет ваш полный контекст. Claude Code начинает максимум три проверки в режиме ожидания на цель между вашими подсказками. До версии v2.1.246 проверки в режиме ожидания были неограниченными. Чтобы отключить проверки, установите [`CLAUDE_CODE_GOAL_CHECKIN_MINUTES`](https://code.claude.com/docs/ru/env-vars) на `0`. Проверки в режиме ожидания требуют Claude Code v2.1.236 или позже
* **Подагенты и рабочие процессы**: каждый подагент и каждый агент, порождаемый [динамическим рабочим процессом](https://code.claude.com/docs/ru/workflows.md#cost), отправляют свои собственные запросы поверх запросов основной беседы. [Разбор атрибуции](#plan-usage-breakdown) показывает долю подагента
* **Товарищи-агенты**: каждый активный [товарищ](#agent-team-token-costs) продолжает потреблять токены до выхода
* **Компактность**: `/compact` читает беседу, которую он суммирует, поэтому [компактирование большого контекста](https://code.claude.com/docs/ru/prompt-caching.md#compacting-the-conversation) само по себе является большим запросом. Когда вы хотите свежее начало вместо непрерывности, `/clear` ничего не стоит

Чтобы узнать, что изменить на плане Pro, Max, Ultra, Team или Enterprise, выполните [`/usage`](#plan-usage-breakdown) в промпте Claude Code. Его разбор рекомендует изменения для поведений, которые составляют 10% или более вашего недавнего использования. К таким поведениям относятся длинный контекст и промахи кэша.

## Понимание изменений в поведении Claude Code

Claude Code регулярно получает обновления, которые могут изменить способ работы функций, включая отчетность о затратах. Запустите `claude --version`, чтобы проверить вашу текущую версию.

По вопросам выставления счетов для вашего конкретного аккаунта обратитесь в службу поддержки Anthropic через встроенный мессенджер:

* **Тарифы с подпиской** (Pro, Max, Ultra, Team, Enterprise): войдите на [claude.ai](https://claude.ai), нажмите на ваши инициалы в нижнем левом углу и выберите **Get help**
* **Выставление счетов Console (API)**: войдите на [platform.claude.com](https://platform.claude.com), нажмите на ваши инициалы и выберите **Get help**

См. [How to get support](https://support.claude.com/en/articles/9015913-how-to-get-support) для полного процесса, включая информацию о том, кто может связаться с представителем поддержки на каждом плане.

Материалы собраны из открытых источников; права принадлежат их авторам.
