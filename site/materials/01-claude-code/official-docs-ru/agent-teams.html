Координируйте команды сеансов Claude Code #

Координируйте несколько экземпляров Claude Code, работающих вместе как команда, с общими задачами, обменом сообщениями между агентами и централизованным управлением.

[!WARNING]

Команды агентов являются экспериментальными и отключены по умолчанию. Включите их, задав CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 в вашем settings.json или переменной окружения. Команды агентов имеют известные ограничения в отношении возобновления сессии, координации задач и поведения при завершении.

Команды агентов позволяют координировать несколько экземпляров Claude Code, работающих вместе. Один сеанс выступает в роли лидера команды, координируя работу, назначая задачи и синтезируя результаты. Товарищи по команде работают независимо, каждый в своем контекстном окне, и общаются друг с другом напрямую. Вы также можете общаться с любым товарищем по команде напрямую, не проходя через лидера.

Перед тем как настраивать команду, проверьте, подойдет ли вам более легкий вариант. Subagents работают в одном сеансе, а с помощью cross-session messaging Claude может передавать результаты между сеансами, которые вы запускаете самостоятельно.

Когда использовать команды агентов #

Команды агентов наиболее эффективны для задач, где параллельное исследование добавляет реальную ценность. Полные сценарии см. в примерах вариантов использования. Самые сильные варианты использования:

  • Исследование и проверка: несколько товарищей по команде могут одновременно исследовать различные аспекты проблемы, а затем делиться и оспаривать выводы друг друга
  • Новые модули или функции: товарищи по команде могут владеть отдельными частями без конфликтов друг с другом
  • Отладка с конкурирующими гипотезами: товарищи по команде тестируют различные теории параллельно и быстрее сходятся на ответе
  • Координация между слоями: изменения, охватывающие фронтенд, бэкенд и тесты, каждый из которых принадлежит другому товарищу по команде

Команды агентов добавляют накладные расходы на координацию и используют значительно больше токенов, чем один сеанс. Они работают лучше всего, когда товарищи по команде могут работать независимо. Для последовательных задач, редактирования одного файла или работы со множеством зависимостей более эффективны один сеанс или subagents.

Сравнение с subagents #

Как команды агентов, так и subagents позволяют вам распараллелить работу, но они работают по-разному. Для отдельных сеансов, которые передают сообщения друг другу без команды, см. обмен сообщениями между сеансами.

Subagents докладывают результаты основному агенту. В командах агентов товарищи по команде делят список задач, берут на себя работу и общаются друг с другом напрямую.

| | Subagents | Команды агентов | | :- | :- | :- | | Контекст | Собственное контекстное окно; результаты возвращаются вызывающему | Собственное контекстное окно; полностью независимы | | Коммуникация | Возвращают результат вызывающему. Субагенты, которым Claude дал имена при их создании, также могут обмениваться сообщениями друг с другом | Участники команды обмениваются сообщениями напрямую | | Координация | Основной агент управляет всей работой | Самокоординация через сообщения, плюс общий список задач для агентов, у которых есть инструменты Task | | Лучше всего для | Сосредоточенные задачи, где имеет значение только результат | Сложная работа, требующая обсуждения и сотрудничества | | Стоимость токенов | Ниже: результаты суммируются обратно в основной контекст | Выше: каждый товарищ по команде — отдельный экземпляр Claude |

Используйте subagents, когда вам нужны быстрые, сосредоточенные работники, которые докладывают обратно. Используйте команды агентов, когда товарищи по команде должны делиться выводами, оспаривать друг друга и координировать самостоятельно.

Включение команд агентов #

Команды агентов отключены по умолчанию. Включите их, установив переменную окружения CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS на 1, либо в переменной окружения вашей оболочки, либо через settings.json:

```json settings.json theme={null} { "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }


Включение команд агентов также изменяет обычное делегирование. Claude может [назвать подагента](https://code.claude.com/docs/ru/sub-agents.md#subagent-names) самостоятельно, и пока команды агентов включены, подагент, названный Claude, запускается как товарищ по команде, поэтому команды могут формироваться даже если вы не просили об этом. Для получения дополнительной информации см. [Как Claude начинает команды агентов](#how-claude-starts-agent-teams); чтобы отключить это поведение, см. [Claude порождает товарищей по команде вместо подагентов](#claude-spawns-teammates-instead-of-subagents).

Порождение товарищей по команде также требует интерактивного сеанса. В [неинтерактивном режиме](https://code.claude.com/docs/ru/headless.md) с флагом `-p`, включая сеансы Agent SDK, Claude не порождает товарищей по команде, и подагент, названный Claude, работает как обычный [подагент](https://code.claude.com/docs/ru/sub-agents.md) даже с включенными командами агентов.

## Запуск вашей первой команды агентов

После включения команд агентов опишите задачу и товарищей по команде, которых вы хотите, на естественном языке. Claude создает их и координирует работу на основе вашего запроса.

Этот пример хорошо работает, потому что три роли независимы и могут исследовать проблему без ожидания друг друга:

I'm designing a CLI tool that helps developers track TODO comments across their codebase. Spawn three teammates to explore this from different angles: one on UX, one on technical architecture, one playing devil's advocate.


После этого Claude заполняет [общий список задач](https://code.claude.com/docs/ru/interactive-mode.md#task-list) в [сеансе, который имеет инструменты Task](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability), создает товарищей по команде для каждой перспективы, заставляет их исследовать проблему и синтезирует выводы по завершении.

Claude иногда может использовать [подагентов](https://code.claude.com/docs/ru/sub-agents.md) вместо создания команды. Подагенты появляются на той же панели агентов, что и товарищи по команде, поэтому сама панель не подтверждает формирование команды. Если Claude создал подагентов вместо этого, попросите снова и явно запросите команду агентов.

Терминал лидера перечисляет товарищей по команде на панели агентов ниже поля ввода запроса. На панели:

* **Стрелки вверх и вниз**: выбрать товарища по команде
* **Enter**: открыть стенограмму выбранного товарища по команде и отправить ему сообщение напрямую
* **Escape**: очистить выделение. Пока вы просматриваете стенограмму товарища по команде, Escape прерывает текущий ход этого товарища по команде

Строка неактивного участника команды остается на панели, пока работает любой участник команды или субагент, поэтому вы можете выбрать ее, чтобы просмотреть его транскрипт или отправить ему дополнительную работу. Когда все агенты на панели неактивны, неактивные строки скрываются через 30 секунд и снова появляются при следующем ходе участника команды; участник команды продолжает работать и остается доступным, пока скрыт.

Когда более трех товарищей по команде неактивны одновременно, строки, выходящие за пределы первых трех, сворачиваются в одну строку, которая подсчитывает свернутых товарищей по команде, например `2 idle agents` когда пять неактивны. Выберите его и нажмите Enter для развертывания свернутых строк, или нажмите Esc для их свертывания снова. Работающие товарищи по команде, неудачные товарищи по команде и товарищ по команде, который вы просматриваете, всегда сохраняют свои собственные строки.

Если вы хотите, чтобы каждый товарищ по команде находился в отдельной разделенной панели, см. [Выбор режима отображения](#choose-a-display-mode).

## Управление вашей командой агентов

Скажите лидеру, что вы хотите, на естественном языке. Он обрабатывает координацию команды, назначение задач и делегирование на основе ваших инструкций.

### Выбор режима отображения

Команды агентов поддерживают два режима отображения:

* **In-process**: все товарищи по команде работают внутри вашего основного терминала. Используйте клавиши со стрелками вверх и вниз в панели агента для выбора товарища по команде, затем нажмите Enter для просмотра и введите сообщение для отправки ему напрямую. Работает в любом терминале, дополнительная настройка не требуется.
* **Split panes**: каждый товарищ по команде получает свою панель. Вы можете видеть вывод всех одновременно и щелкнуть в панель для прямого взаимодействия. Требует tmux или iTerm2.

> [!NOTE]
>
> `tmux` имеет известные ограничения на некоторых операционных системах и традиционно работает лучше всего на macOS. Использование `tmux -CC` в iTerm2 — это рекомендуемая точка входа в `tmux`.

Когда команды агентов [включены](#enable-agent-teams), выполните следующие шаги, чтобы дать каждому товарищу по команде собственную панель:

**1. Установите tmux или настройте iTerm2**

Режим разделённых панелей требует либо [tmux](https://github.com/tmux/tmux/wiki), либо iTerm2 с [`it2` CLI](https://github.com/mkusaka/it2). Настройте тот, в котором вы будете запускать Claude Code:

* **tmux**: установите через менеджер пакетов вашей системы. См. [tmux wiki](https://github.com/tmux/tmux/wiki/Installing) для инструкций, специфичных для платформы.
* **iTerm2**: установите [`it2` CLI](https://github.com/mkusaka/it2), затем включите Python API в **iTerm2 > Settings > General > Magic > Enable Python API**.

**2. Включите разделённые панели**

Товарищи по команде работают в режиме in-process, пока вы не измените настройку [`teammateMode`](https://code.claude.com/docs/ru/settings-reference#teammatemode).

Установите для неё значение `"auto"` в `~/.claude/settings.json`:

{ "teammateMode": "auto" }


При значении `"auto"` товарищи по команде открываются в разделённых панелях, когда вы запускаете Claude Code внутри tmux или iTerm2, а в других терминалах работают в режиме in-process.

**3. Запустите Claude Code и породите товарищей по команде**

Запустите `claude` внутри tmux или в iTerm2, затем попросите Claude породить товарищей по команде.

Если в iTerm2 появится запрос на настройку `it2`, выберите **Install it2 now**, чтобы панели открылись в вашем окне iTerm2.

Если вы запускаете Claude Code вне tmux и iTerm2 или панели не открываются в вашем окне iTerm2, снова измените `teammateMode`:

* **Вне tmux и iTerm2**: если tmux установлен, задайте для `teammateMode` значение `"tmux"`. Панели открываются в отдельной сессии tmux. Чтобы наблюдать за ними, скопируйте команду из строки `View teammates` в промпте Claude Code и выполните эту команду во втором терминале.
* **Панели не открываются в вашем окне iTerm2**: задайте для `teammateMode` значение `"iterm2"`, чтобы использовать собственные панели iTerm2. В этом случае товарищи по команде запускаются, только когда вы запускаете Claude Code в iTerm2 с настроенным `it2`.

Чтобы установить режим для одного сеанса, передайте его как флаг:

claude --teammate-mode auto


Флаг `--teammate-mode` является экспериментальным и не отображается в `claude --help`.

### Укажите товарищей по команде и модели

Claude решает количество товарищей по команде для порождения на основе вашей задачи, или вы можете указать ровно то, что вы хотите:

Spawn 4 teammates to refactor these modules in parallel. Use Sonnet for each teammate.


Claude Code выбирает модель каждого товарища по команде из первого из следующих применимых вариантов:

1. Модель, которую ваша подсказка порождения называет для этого товарища по команде.
2. Для товарища по команде, порожденного из [определения подагента](#use-subagent-definitions-for-teammates), определение `model`, где `inherit` выбирает модель лидера.
3. [`CLAUDE_CODE_SUBAGENT_MODEL`](https://code.claude.com/docs/ru/model-config#environment-variables), когда оно установлено на что-либо иное, чем `inherit`.
4. Текущая модель лидера.

Если установленный [мод](https://code.claude.com/docs/ru/plugins/mods/overview.md) задаёт модель в своём хуке [`agent.spawn`](https://code.claude.com/docs/ru/plugins/mods/reference#subagents), Claude Code использует эту модель вместо первого источника.

Если вы установите [`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`](https://code.claude.com/docs/ru/sub-agents#run-every-subagent-on-one-model), первые два источника не применяются. Claude Code выбирает модель каждого товарища по команде из `CLAUDE_CODE_SUBAGENT_MODEL`, когда оно установлено на что-либо иное, чем `inherit`, и из текущей модели лидера в противном случае. Требует Claude Code v2.1.257 или позже.

До версии v2.1.251 `CLAUDE_CODE_SUBAGENT_MODEL` был первым в этом порядке.

> [!NOTE]
>
> `teammateDefaultModel` был удален в версии v2.1.234; Claude Code игнорирует оставшееся значение. Назовите модель в вашей подсказке вместо этого.

Claude Code проверяет модель, которую он выбирает для товарища по команде, в соответствии со списком разрешений [`availableModels`](https://code.claude.com/docs/ru/model-config#restrict-model-selection) вашей организации. Когда список разрешений блокирует значение, Claude Code подставляет другую модель:

* **Псевдоним семейства, такой как `opus`**: На Anthropic API и Claude Platform на AWS, Claude Code запускает товарища по команде на самой новой версии этого семейства, которое разрешает список разрешений. На поставщиках с ID моделей, специфичными для поставщика, где [подстановка не работает](https://code.claude.com/docs/ru/model-config.md#restrict-model-selection), заблокированный псевдоним откатывается как любое другое заблокированное значение согласно следующему пункту
* **Любое другое заблокированное значение, включая псевдоним семейства на поставщиках, где подстановка не работает, или тот, у которого семейство не имеет разрешенной версии**: Claude Code запускает товарища по команде на модели лидера вместо этого. Если вы установили `CLAUDE_CODE_SUBAGENT_MODEL`, Claude Code сначала пробует эту модель согласно этим же правилам

По умолчанию участник команды, работающий на модели лидера, наследует [уровень effort](https://code.claude.com/docs/ru/model-config.md#adjust-effort-level) лидера. В режиме split-pane это применяется с версии v2.1.186; более ранние версии не передавали уровень effort сессии лидера участникам команды в режиме split-pane. Для участника команды на другой модели см. [Уровень effort субагентов и участников команды](https://code.claude.com/docs/ru/model-config.md#effort-level-of-subagents-and-teammates).

### Требуйте планирования товарищей по команде перед реализацией

Для сложных или рискованных задач вы можете потребовать, чтобы товарищи по команде планировали перед реализацией. Товарищ по команде, которого Claude порождает, пока лидер находится в [режиме планирования](https://code.claude.com/docs/ru/permission-modes.md#analyze-before-you-edit-with-plan-mode), также работает в режиме планирования до тех пор, пока его план не будет готов. Сначала переведите лидера в режим планирования, затем попросите товарища по команде:

Spawn an architect teammate to refactor the authentication module.


Когда этот товарищ по команде заканчивает планирование, он отправляет лидеру запрос на утверждение плана. Если вы не меняли режим разрешений этого товарища по команде с момента его порождения, Claude Code утверждает план сразу после поступления запроса, без проверки лидером. После утверждения товарищ по команде выходит из режима планирования и начинает реализацию. Claude Code передаёт ему текущий [режим разрешений](#permissions) лидера или Manual, если это режим планирования.

Если вы переведёте работающего товарища по команде в режиме in-process в режим планирования, нажав [`Shift+Tab`](https://code.claude.com/docs/ru/permission-modes#switch-permission-modes) во время просмотра его сессии, план этого запуска проверяет лидер, а не утверждает Claude Code. Вас не просят утвердить его; лидер утверждает план или отправляет его обратно на доработку.

### Разговаривайте с товарищами по команде напрямую

Каждый товарищ по команде — это полный, независимый сеанс Claude Code. Вы можете отправить сообщение любому товарищу по команде напрямую, чтобы дать дополнительные инструкции, задать дополнительные вопросы или переориентировать его подход.

* **Режим in-process**: используйте клавиши со стрелками вверх и вниз в панели агента для выбора товарища по команде, затем нажмите Enter для просмотра его сеанса и введите сообщение для отправки ему. Нажмите `x` на выбранном товарище по команде для его остановки. Нажмите Ctrl+T для переключения списка задач.
* **Режим split-pane**: щелкните в панель товарища по команде для прямого взаимодействия с его сеансом. Каждый товарищ по команде имеет полный вид своего собственного терминала.

Пока вы просматриваете товарища по команде в режиме in-process, простой текст и [скиллы](https://code.claude.com/docs/ru/skills.md) идут этому товарищу по команде, а встроенные команды идут в сессию лидера, со следующими мерами предосторожности:

* `/compact`, `/clear` и `/rewind` действуют на диалог лидера, поэтому Claude Code просит вас подтвердить перед запуском любой из них из этого представления.
* `/model` и `/fast` устанавливают модель и быстрый режим лидера, а не товарища по команде, поэтому они не запускаются из этого представления. Уведомление объясняет причину.

Модель участника команды и быстрый режим фиксируются при его порождении.

### Назначение и взятие задач

Общий список задач координирует работу по всей команде. Лидер создает задачи, а товарищи по команде работают над ними. Задачи имеют три состояния: ожидание, в процессе и завершено. Задача также может зависеть от других задач и отображается в списке задач как заблокированная, пока они не будут завершены. Товарищи по команде не берут заблокированную задачу самостоятельно, но вы или лидер всё равно можете её назначить.

Агенты [без инструментов Task](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability) координируют через сообщения вместо общего списка задач.

Лидер может явно назначать задачи или товарищи по команде могут самостоятельно брать их:

* **Лидер назначает**: скажите лидеру, какую задачу дать какому товарищу по команде
* **Самостоятельное взятие**: после завершения задачи товарищ по команде самостоятельно берет следующую неназначенную, разблокированную задачу

Взятие задач использует блокировку файлов для предотвращения условий гонки, когда несколько товарищей по команде пытаются взять одну и ту же задачу одновременно.

### Завершение работы товарищей по команде

Чтобы корректно завершить сеанс товарища по команде, обратитесь к нему по имени. Например, с товарищем по команде по имени researcher:

Ask the researcher teammate to shut down


Лидер отправляет запрос на завершение. Товарищ по команде может одобрить, выходя корректно, или отклонить с объяснением.

Общие каталоги команды очищаются автоматически при завершении сессии, поэтому отдельный шаг очистки не требуется. См. [Architecture](#architecture), чтобы узнать, какие каталоги удаляются, а какие остаются на диске.

### Обеспечение качества с помощью hooks

Используйте [hooks](https://code.claude.com/docs/ru/hooks.md) для обеспечения правил, когда товарищи по команде заканчивают работу или задачи создаются или завершаются:

* [`TeammateIdle`](https://code.claude.com/docs/ru/hooks#teammateidle): запускается, когда товарищ по команде собирается перейти в режим ожидания. Выйдите с кодом 2, чтобы отправить обратную связь и продолжить работу товарища по команде.
* [`TaskCreated`](https://code.claude.com/docs/ru/hooks#taskcreated): запускается, когда задача создается. Выйдите с кодом 2, чтобы предотвратить создание и отправить обратную связь.
* [`TaskCompleted`](https://code.claude.com/docs/ru/hooks#taskcompleted): запускается, когда задача отмечается как завершенная. Выйдите с кодом 2, чтобы предотвратить завершение и отправить обратную связь.

## Как работают команды агентов

Этот раздел охватывает архитектуру и механику команд агентов. Если вы хотите начать их использовать, см. [Управление вашей командой агентов](#control-your-agent-team) выше.

### Как Claude запускает команды агентов

Чтобы запустить команду агентов, попросите Claude создать участников команды. Claude запускает участника команды, когда вызывает [инструмент Agent](https://code.claude.com/docs/ru/tools-reference.md) с [`name`](https://code.claude.com/docs/ru/sub-agents#subagent-names) при включенных командах агентов, если только вызов не является [fork](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation) и не передает `isolation` в самом вызове. Claude Code не просит вас подтвердить запуск.

Claude также сам дает имена обычным субагентам, чтобы позже отправлять им сообщения. Эти вызовы следуют тому же правилу, поэтому команды агентов могут формироваться, даже если вы их не запрашивали. Если вместо этого вам нужны субагенты, [отключите команды агентов](#claude-spawns-teammates-instead-of-subagents).

### Архитектура

Команда агентов состоит из:

| Компонент | Роль |
| :- | :- |
| **Лидер команды** | Основная сессия Claude Code, которая порождает участников команды и координирует работу |
| **Участники команды** | Отдельные экземпляры Claude Code, каждый из которых работает над назначенными задачами |
| **Список задач** | Общий список рабочих элементов, которые участники команды берут и завершают |
| **Почтовый ящик** | Система обмена сообщениями для коммуникации между агентами |

Почтовый ящик каждого агента — это JSON-файл в `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`. Claude Code проверяет каждую запись при чтении файла почтового ящика. Записи, которые не соответствуют формату сообщения, регистрируются как ошибки и удаляются из файла; корректные сообщения по-прежнему доставляются.

Claude Code сообщает о сообщении как об отправленном только тогда, когда запись в файл почтового ящика получателя завершается успешно, независимо от того, является ли сообщение простым текстом или структурированным протокольным сообщением, таким как утверждение плана или запрос на завершение. Когда запись не удается, например потому что диск заполнен или директория почтового ящика недоступна для записи, отправляющий агент получает ошибку и ничего не отправляется. См. [Failed to write to a teammate's inbox](https://code.claude.com/docs/ru/errors.md#failed-to-write-to-a-teammate-inbox) для сообщений об ошибках и шагов восстановления.

Claude Code автоматически управляет зависимостями задач: когда участник команды завершает задачу, от которой зависят другие задачи, он разблокирует зависимые задачи без каких-либо действий с вашей стороны.

Команды агентов и задачи хранятся локально под именем, производным от сессии. Имя — это `session-` с последующими первыми восемью символами ID сессии:

* **Конфигурация команды**: `~/.claude/teams/{team-name}/config.json`. Claude Code удаляет директорию конфигурации команды при завершении сессии.
* **Список задач**: `~/.claude/tasks/{team-name}/`. Эта директория остается на диске после завершения сессии. Чтобы изменить, [как долго Claude Code ее хранит](https://code.claude.com/docs/ru/claude-directory.md#cleaned-up-automatically), задайте [`cleanupPeriodDays`](https://code.claude.com/docs/ru/settings-reference#cleanupperioddays).

Claude Code генерирует оба этих элемента автоматически при запуске сессии и обновляет их по мере того, как участники команды присоединяются, переходят в режим ожидания или уходят.

Конфигурация команды содержит состояние выполнения, такое как ID сессий и ID панелей tmux, поэтому не редактируйте ее вручную и не создавайте предварительно: ваши изменения будут перезаписаны при следующем обновлении состояния.

Чтобы определить переиспользуемые роли участников команды, используйте вместо этого [определения субагентов](#use-subagent-definitions-for-teammates).

Конфигурация команды содержит массив `members` с именем и ID агента каждого участника. Запись лидера всегда имеет тип агента `team-lead`. Запись участника команды имеет тот тип агента, который лидер указал при его порождении, будь то [встроенный тип](https://code.claude.com/docs/ru/sub-agents.md#built-in-subagents) или [определение субагента](#use-subagent-definitions-for-teammates), и не содержит этого поля, если лидер ничего не указал. Участники команды могут читать этот файл, чтобы узнавать о других участниках команды.

Эквивалента конфигурации команды на уровне проекта нет. Файл вроде `.claude/teams/teams.json` в каталоге вашего проекта не распознается как конфигурация; Claude обрабатывает его как обычный файл.

### Использование определений субагентов для участников команды

При порождении участника команды в любом режиме отображения вы можете сослаться на тип [субагента](https://code.claude.com/docs/ru/sub-agents.md) из [области действия субагентов](https://code.claude.com/docs/ru/sub-agents.md#choose-the-subagent-scope) проекта, пользователя, управляемой области или плагина. Это позволяет один раз определить роль, например security-reviewer или test-runner, и переиспользовать ее как в качестве делегированного субагента, так и в качестве участника команды агентов.

Чтобы использовать определение субагента, укажите его имя, когда просите Claude породить участника команды:

Spawn a teammate using the security-reviewer agent type to audit the auth module.


Claude Code читает указанное вами определение субагента и применяет к участнику команды следующие его части. Если часть зависит от [режима отображения](#choose-a-display-mode) участника команды, это указано в соответствующем пункте:

* **`tools`**: Claude Code ограничивает участника команды инструментами из списка `tools` определения. Для участника команды, работающего в процессе, Claude Code добавляет в этот список `SendMessage`, а в [сессии, где есть инструменты Task](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability), также добавляет `TaskCreate`, `TaskGet`, `TaskList` и `TaskUpdate`.
* **`model`**: Claude Code использует `model` из определения в любом режиме отображения, если ваш промпт порождения не указывает модель. См. [как Claude Code выбирает модель участника команды](#specify-teammates-and-models).
* **`disallowedTools`**: для участника команды, работающего в процессе, Claude Code удаляет инструменты из `disallowedTools` определения из набора участника. `SendMessage` и добавляемые инструменты Task остаются доступными, даже если они указаны в этом списке.
* **`effort`**: для участника команды, работающего в процессе, Claude Code применяет [`effort`](https://code.claude.com/docs/ru/sub-agents#supported-frontmatter-fields) из определения согласно [правилам effort во frontmatter](https://code.claude.com/docs/ru/model-config.md#set-the-effort-level).
* **`autoCompactWindow`**: для участника команды, работающего в процессе, Claude Code применяет [`autoCompactWindow`](https://code.claude.com/docs/ru/sub-agents#supported-frontmatter-fields) из определения согласно [правилам этого поля](https://code.claude.com/docs/ru/sub-agents.md#subagent-auto-compact-window). Участник команды в разделенной панели игнорирует это поле. Требуется Claude Code v2.1.296 или новее.
* **Body**: для участника команды, работающего в процессе, Claude Code добавляет body определения к его системному промпту по умолчанию в качестве дополнительных инструкций. Для участника команды в разделенной панели Claude Code использует body вместо его системного промпта по умолчанию.
* **`skills`**: Claude Code не применяет `skills` определения к участнику команды ни в одном режиме отображения. Участник команды загружает скиллы из настроек вашего проекта и пользователя.
* **`mcpServers`**: для участника команды в разделенной панели Claude Code применяет `mcpServers` определения в соответствии с [правилами для этого поля](https://code.claude.com/docs/ru/sub-agents.md#scope-mcp-servers-to-a-subagent), которые распространяются и на сессию, запущенную с `--agent`. Участник команды, работающий в процессе, игнорирует это поле и загружает MCP-серверы из настроек вашего проекта и пользователя.

Когда Claude отправляет сообщение участнику команды, работающему в процессе, который больше не запущен, Claude Code возвращает его в ту же сессию, восстанавливает сохраненный для него диалог и передает ему сообщение в качестве следующего промпта. После возобновления сессии участники команды таким образом не возвращаются, согласно [ограничению возобновления](#limitations).

Для возвращаемого участника команды Claude Code повторно применяет определение, полученное из директории `.claude/agents/` проекта или из директории `--add-dir`, только если вы [доверили папке, в которой находится файл агента](https://code.claude.com/docs/ru/permissions.md#what-runs-before-you-trust-a-folder). Доверие к родительской папке не учитывается. До тех пор участник команды возвращается без инструментов и инструкций из определения, сохраняя только инструменты, которые Claude Code добавляет каждому участнику команды, работающему в процессе. См. [определение агента участника команды не было восстановлено](https://code.claude.com/docs/ru/errors.md#teammate-agent-definition-not-restored) для текста уведомления.

### Разрешения

Чтобы переключить режим разрешений работающего участника команды, нажмите [`Shift+Tab`](https://code.claude.com/docs/ru/permission-modes#switch-permission-modes), хотя участник команды, работающий в процессе, может вместо этого работать в режиме лидера. Для участника команды в разделенной панели нажмите это сочетание в его панели. Для участника команды, [работающего в процессе](#choose-a-display-mode), нажмите его во время [просмотра его сессии](#talk-to-teammates-directly), и участник команды проверит свой режим, когда начнет следующий ход.

> [!NOTE]
>
> Участник команды, работающий в процессе и не находящийся в [режиме планирования](#have-teammates-plan-before-implementing), работает в режиме лидера, пока лидер находится в режиме [`acceptEdits`](https://code.claude.com/docs/ru/permission-modes#auto-approve-file-edits-with-acceptedits-mode), [`auto`](https://code.claude.com/docs/ru/permission-modes#eliminate-prompts-with-auto-mode) или [`bypassPermissions`](https://code.claude.com/docs/ru/permission-modes#skip-all-checks-with-bypasspermissions-mode). Переключение участника команды в Manual этого не меняет, даже если в его строке состояния отображается Manual.
>
> Чтобы он спрашивал перед редактированием, нажмите Enter на строке `main` в панели агентов и также переключите лидера в режим Manual. Тогда лидер тоже будет спрашивать, как и любой другой участник команды в режиме Manual.

Задать режимы разрешений для отдельных участников команды при порождении нельзя. Новый участник команды начинает в режиме лидера, включая режим `bypassPermissions`, который включается флагом `--dangerously-skip-permissions`. Если лидер находится в [режиме `dontAsk`](https://code.claude.com/docs/ru/permission-modes#allow-only-pre-approved-tools-with-dontask-mode), участник команды вместо этого начинает в [режиме Manual](https://code.claude.com/docs/ru/permission-modes.md#available-modes). Для участника команды в разделенной панели, лидер которого находится в режиме Manual или `dontAsk`, для этого требуется Claude Code v2.1.317 или новее.

Участник команды, [работающий в процессе](#choose-a-display-mode), работает по текущим правилам разрешения и запрета лидера, поэтому к нему применяются [`--disallowedTools`](https://code.claude.com/docs/ru/cli-reference#cli-flags), `--tools` и `--allowedTools`. Для участника команды в разделенной панели проверьте каждый флаг:

* **`--disallowedTools` и `--tools`**: участник команды начинает с правилами запрета и списком инструментов лидера, заданными в командной строке. Требуется Claude Code v2.1.309 или новее.
* **`--allowedTools`**: Claude Code не передает этот флаг участнику команды в разделенной панели, поэтому действие, разрешенное только этим флагом, там не подтверждено заранее. Чтобы подтвердить такие действия заранее, поместите правила в `permissions.allow` в [`--settings`](https://code.claude.com/docs/ru/settings#change-a-setting-for-one-session) при запуске лидера. Например, выполните в оболочке `claude --settings '{"permissions":{"allow":["Bash(npm *)"]}}'`. Правила применяются к лидеру и к каждому участнику команды в разделенной панели в рамках этой сессии.

Запросы разрешений участников команды появляются в сессии лидера, поэтому подтверждайте их там сами. Утверждать [план участника команды](#have-teammates-plan-before-implementing) вам не нужно.

#### Сообщения между агентами

Когда один агент отправляет другому сообщение через `SendMessage`, Claude Code сообщает получающему агенту, что сообщение пришло из другой сессии Claude, а не от вас. Участник команды не может подтвердить запрос разрешения или дать согласие от вашего имени, а участник команды, которому было отказано в действии, не может передать его другому участнику команды, чтобы обойти проверку. Те же правила применяются к сообщению, поступающему из [одной из ваших других сессий Claude Code](https://code.claude.com/docs/ru/cross-session-messaging.md#how-a-session-treats-an-incoming-message), полностью вне команды агентов.

В [авторежиме](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) классификатор применяет две проверки к сообщениям между агентами:

* Он рассматривает заявление о подтверждении, переданное от другого агента, как недоверенный ввод, а не как подтверждение от вас.
* Он проверяет сообщения перед тем, как Claude Code их доставит, включая структурированные протокольные сообщения, такие как запрос на завершение. Заблокированное им сообщение не доставляется. Прежде чем полагаться на эту проверку, узнайте, [какие сообщения ее обходят](https://code.claude.com/docs/ru/permission-modes.md#how-the-classifier-evaluates-actions).

### Контекст и коммуникация

У каждого участника команды есть собственное контекстное окно. При порождении участник команды загружает тот же контекст проекта, что и обычная сессия: CLAUDE.md, MCP-серверы и скиллы. Если вы запустите лидера с [`--setting-sources`](https://code.claude.com/docs/ru/cli-reference#cli-flags), участники команды загружают настройки из того же ограниченного списка источников. До версии 2.1.281 участники команды в [разделенной панели](#choose-a-display-mode) загружали все источники настроек.

Участник команды также получает от лидера промпт порождения. История диалога лидера не переносится.

**Как участники команды обмениваются информацией:**

* **Автоматическая доставка сообщений**: когда участники команды отправляют сообщения, они автоматически доставляются получателям. Лидеру не нужно опрашивать обновления.
* **Уведомления о простое**: когда участник команды заканчивает работу и останавливается, он автоматически уведомляет лидера и включает в уведомление свой окончательный ответ. Участник команды, чей ход завершается ошибкой API, уведомляет лидера о сбое и включает текст ошибки.
* **Общий список задач**: [агенты, у которых есть инструменты Task](https://code.claude.com/docs/ru/tools-reference.md#task-tool-availability), могут видеть статус задач и брать доступную работу.
* **Обмен сообщениями между участниками команды**: отправьте сообщение одному конкретному участнику команды по имени. Чтобы связаться со всеми, отправьте по одному сообщению каждому получателю.

Лидер назначает каждому участнику команды имя при его порождении, и любой участник команды может отправить сообщение любому другому по этому имени. Чтобы получить предсказуемые имена, на которые можно ссылаться в последующих промптах, укажите лидеру в инструкции по порождению, как назвать каждого участника команды.

### Использование токенов

Команды агентов используют значительно больше токенов, чем одна сессия. У каждого участника команды есть собственное контекстное окно, и использование токенов растет с количеством активных участников команды. Для исследования, проверки и работы над новыми функциями дополнительные токены обычно оправданы. Для рутинных задач одна сессия экономичнее. См. [стоимость токенов команды агентов](https://code.claude.com/docs/ru/costs.md#agent-team-token-costs) для рекомендаций по использованию.

Запросы участника команды, работающего в процессе, не попадают в [TTL bucket кэша](https://code.claude.com/docs/ru/prompt-caching.md#which-ttl-each-request-gets) основного диалога, поэтому его кэш по умолчанию хранится пять минут, в том числе при подписке Claude. Чтобы хранить его час, установите [`subagentPromptCacheTtl`](https://code.claude.com/docs/ru/settings-reference#subagentpromptcachettl) в значение `1h`. API тарифицирует записи в кэш на 1 час по более высокой ставке.

## Примеры вариантов использования

Эти примеры показывают, как команды агентов обрабатывают задачи, где параллельное исследование добавляет ценность.

### Запуск параллельной проверки кода

Один рецензент имеет тенденцию сосредотачиваться на одном типе проблемы за раз. Разделение критериев проверки на независимые области означает, что безопасность, производительность и покрытие тестами получают тщательное внимание одновременно. Запрос назначает каждому товарищу по команде отдельный объектив, чтобы они не перекрывались:

Spawn three teammates to review PR #142:

  • One focused on security implications
  • One checking performance impact
  • One validating test coverage

Have them each review and report findings.


Каждый рецензент работает с одного и того же PR, но применяет другой фильтр. Лидер синтезирует выводы всех трех после их завершения.

### Исследование с конкурирующими гипотезами

Когда первопричина неясна, один агент имеет тенденцию находить одно правдоподобное объяснение и останавливаться. Запрос борется с этим, делая товарищей по команде явно враждебными: работа каждого — не только исследовать свою теорию, но и оспаривать теории других.

Users report the app exits after one message instead of staying connected. Spawn 5 agent teammates to investigate different hypotheses. Have them talk to each other to try to disprove each other's theories, like a scientific debate. Update the findings doc with whatever consensus emerges.


Структура дебатов — это ключевой механизм здесь. Последовательное исследование страдает от якорения: как только одна теория исследуется, последующее исследование смещено в сторону нее.

С несколькими независимыми следователями, активно пытающимися опровергнуть друг друга, теория, которая выживает, гораздо более вероятна, что это будет фактическая первопричина.

## Лучшие практики

### Дайте товарищам по команде достаточно контекста

Товарищи по команде автоматически загружают контекст проекта, включая CLAUDE.md, MCP servers и skills, но они не наследуют историю разговора лидера. См. [Контекст и коммуникация](#context-and-communication) для деталей. Включите детали, специфичные для задачи, в запрос на порождение:

Spawn a security reviewer teammate with the prompt: "Review the authentication module at src/auth/ for security vulnerabilities. Focus on token handling, session management, and input validation. The app uses JWT tokens stored in httpOnly cookies. Report any issues with severity ratings."


### Выберите подходящий размер команды

Нет жесткого ограничения на количество товарищей по команде, но применяются практические ограничения:

* **Стоимость токенов масштабируется линейно**: каждый товарищ по команде имеет свое собственное контекстное окно и потребляет токены независимо. См. [стоимость токенов команды агентов](https://code.claude.com/docs/ru/costs.md#agent-team-token-costs) для деталей.
* **Накладные расходы на координацию увеличиваются**: больше товарищей по команде означает больше коммуникации, координации задач и потенциал для конфликтов
* **Убывающая отдача**: сверх определенной точки дополнительные товарищи по команде не ускоряют работу пропорционально

Начните с 3-5 товарищей по команде для большинства рабочих процессов. Это уравновешивает параллельную работу с управляемой координацией. Если у вас есть 15 независимых задач, 3 товарища по команде — хорошая отправная точка.

Масштабируйте только когда работа действительно выигрывает от одновременной работы товарищей по команде. Три сосредоточенных товарища по команде часто превосходят пять рассеянных.

### Размер задач надлежащим образом

* **Слишком маленькие**: накладные расходы на координацию превышают выгоду
* **Слишком большие**: товарищи по команде работают слишком долго без проверок, увеличивая риск потраченной впустую работы
* **Как надо**: самостоятельные единицы, которые производят четкий результат, такие как функция, файл теста или проверка

> [!TIP]
>
> Лидер разбивает работу на задачи и автоматически назначает их товарищам по команде. Если он не создает достаточно задач, попросите его разделить работу на более мелкие части. Наличие 5-6 задач на товарища по команде держит всех продуктивными и позволяет лидеру переназначить работу, если кто-то застрял.

### Ждите, пока товарищи по команде закончат

Иногда лидер начинает реализовывать задачи сам вместо ожидания товарищей по команде. Если вы заметите это:

Wait for your teammates to complete their tasks before proceeding


### Начните с исследования и проверки

Если вы новичок в командах агентов, начните с задач, которые имеют четкие границы и не требуют написания кода: проверка PR, исследование библиотеки или исследование ошибки. Эти задачи показывают ценность параллельного исследования без проблем координации, которые приходят с параллельной реализацией.

### Избегайте конфликтов файлов

Два товарища по команде, редактирующие один и тот же файл, приводит к перезаписям. Разбейте работу так, чтобы каждый товарищ по команде владел другим набором файлов.

### Мониторинг и управление

Проверяйте прогресс товарищей по команде, переориентируйте подходы, которые не работают, и синтезируйте выводы по мере их поступления. Оставление команды без присмотра на слишком долгое время увеличивает риск потраченной впустую работы.

## Устранение неполадок

### Товарищи по команде не появляются

Если товарищи по команде не появляются после того, как вы попросили Claude создать команду:

* В режиме in-process товарищи по команде появляются на панели агента ниже поля ввода подсказки. Используйте клавиши со стрелками вверх и вниз для выбора одного, затем нажмите Enter для его просмотра.
* Строка товарища по команде, которая исчезла после простоя, была скрыта, а не остановлена. Неактивные строки скрываются через 30 секунд после того, как вся панель переходит в режим ожидания, и снова появляются при следующем ходе товарища по команде. Когда более трех товарищей по команде неактивны, их избыточные строки сворачиваются в одну строку `N idle agents`, которую Enter разворачивает. Отправьте товарищу по команде сообщение по имени, чтобы вернуть скрытую строку.
* Проверьте, что задача, которую вы дали Claude, была достаточно сложной, чтобы оправдать команду. Claude решает, порождать ли товарищей по команде, на основе задачи.
* Если вы явно запросили разделенные панели, убедитесь, что tmux установлен и доступен в вашем PATH:

which tmux

* Для iTerm2 проверьте, что `it2` CLI установлен и Python API включен в предпочтениях iTerm2.

### Claude порождает товарищей по команде вместо подагентов

Пока включены команды агентов, подагент, который Claude называет в сеансе лидера, запускается как товарищ по команде. Claude [может называть подагентов самостоятельно](#how-claude-starts-agent-teams), поэтому это может произойти во время делегирования, которое вы никогда не рассматривали как командную работу.

Чтобы названные подагенты снова запускались как подагенты, отключите команды агентов, установив `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` на `0`:

{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "0" } }


Вам не нужно начинать новый сеанс: Claude Code переприменяет значения `env` из файла параметров к работающему сеансу при сохранении и перечитывает переменную каждый раз, когда Claude порождает подагента, поэтому следующий подагент, который Claude называет, запускается как подагент.

Установка переменной на `0` в вашем пользовательском `settings.json` переопределяет экспорт оболочки. Другие источники параметров все еще могут включать команды агентов:

* **Файлы параметров с более высоким приоритетом**: параметры проекта, локальные параметры и полезная нагрузка `--settings` применяются после пользовательских параметров, поэтому запись `env`, которая устанавливает переменную на `1` в любом из них, побеждает. См. [Приоритет параметров](https://code.claude.com/docs/ru/settings.md#settings-precedence).
* **Управляемые параметры**: [управляемые параметры](https://code.claude.com/docs/ru/server-managed-settings.md) применяются после всех остальных источников. Если ваша организация включает команды агентов там, попросите вашего администратора изменить управляемое значение.

После изменения Claude может все еще называть подагентов, и имя продолжает работать как адрес [`SendMessage`](https://code.claude.com/docs/ru/sub-agents#resume-subagents). Claude получает результат каждого подагента при его завершении.

### Слишком много запросов разрешений

Запросы разрешений товарищей по команде всплывают к лидеру, что может создать трение. Предварительно одобрите общие операции в ваших [параметрах разрешений](https://code.claude.com/docs/ru/permissions.md) перед порождением товарищей по команде, чтобы уменьшить прерывания.

### Агенты останавливаются рано

Товарищи по команде могут остановиться после возникновения ошибок вместо восстановления. Проверьте их вывод, выбрав товарища по команде на панели агента и нажав Enter в режиме in-process, или щелкнув панель в режиме split, затем либо:

* Дайте им дополнительные инструкции напрямую
* Порождите товарища по команде-замену для продолжения работы

Сообщение от лидера или другого товарища по команде пробуждает товарища по команде в режиме in-process, который ожидает повтора неудачного запроса API, поэтому он повторяет попытку немедленно вместо ожидания полной задержки повтора.

Лидер может также остановиться рано, решив, что команда закончена до того, как все задачи действительно завершены. Если это произойдет, скажите ему продолжать.

### Осиротевшие сеансы tmux

Если сеанс tmux сохраняется после завершения сеанса Claude Code, он может не быть полностью очищен. Перечислите сеансы и убейте созданный командой:

tmux ls tmux kill-session -t <session-name>


## Ограничения

Команды агентов являются экспериментальными. Текущие ограничения, о которых следует знать:

* **Нет возобновления сеанса с товарищами по команде in-process**: `/resume` и `/rewind` не восстанавливают товарищей по команде in-process. После возобновления сеанса лидер может попытаться отправить сообщение товарищам по команде, которые больше не существуют. Если это произойдет, скажите лидеру порождать новых товарищей по команде.
* **Статус задачи может отставать**: товарищи по команде иногда не отмечают задачи как завершенные, что блокирует зависимые задачи. Если задача кажется застрявшей, проверьте, действительно ли работа выполнена, и обновите статус задачи вручную или скажите лидеру подтолкнуть товарища по команде.
* **Завершение может быть медленным**: товарищи по команде завершают свой текущий запрос или вызов инструмента перед завершением, что может занять время.
* **Одна команда на сеанс**: сеанс имеет ровно одну команду, ограниченную этим сеансом. Вы не можете создавать дополнительные именованные команды или делиться командой между сеансами.
* **Нет вложенных команд**: товарищи по команде не могут порождать своих собственных товарищей по команде. Только лидер может управлять командой.
* **Нет фоновых субагентов от участников команды in-process**: собственные субагенты участника команды in-process работают на переднем плане, потому что фоновая работа участника команды не может пережить процесс лидера. Claude Code возвращает ошибку, когда участник команды порождает субагента, чье определение устанавливает `background: true`. Запрос участника команды `run_in_background: true` также не удается, либо с ошибкой, либо путем молчаливого запуска на переднем плане. Субагенты, запущенные из основного диалога, следуют [фоновому значению по умолчанию](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background).
* **Лидер фиксирован**: основной сеанс является лидером на протяжении всей его жизни. Вы не можете повысить товарища по команде до лидера или передать лидерство.
* **Нельзя задать режим разрешений для отдельного участника команды при создании**: участники команды начинают с режима разрешений, описанного в разделе [Разрешения](#permissions).
* **Разделенные панели требуют tmux или iTerm2**: режим in-process по умолчанию работает в любом терминале.

## Следующие шаги

Изучите связанные подходы для параллельной работы и делегирования:

* **Легкое делегирование**: [subagents](https://code.claude.com/docs/ru/sub-agents.md) порождают вспомогательных агентов для исследования или проверки в вашем сеансе, лучше для задач, которые не нуждаются в координации между агентами
* **Обмен сообщениями между вашими собственными сеансами**: [cross-session messaging](https://code.claude.com/docs/ru/cross-session-messaging.md) позволяет Claude передавать результаты между сеансами, которые вы запускаете самостоятельно
* **Ручные параллельные сеансы**: [Git worktrees](https://code.claude.com/docs/ru/worktrees.md) позволяют вам запускать несколько сеансов Claude Code самостоятельно без автоматической координации команды
