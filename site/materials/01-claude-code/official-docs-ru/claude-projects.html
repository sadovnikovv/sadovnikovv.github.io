Позвольте Claude координировать текущую работу с помощью Projects #

Предоставьте Claude набор связанной работы в одном разговоре и позвольте ему запускать их как параллельные облачные сеансы, которые совместно используют репозитории, инструкции и память.

[!NOTE]

Projects доступны в публичной бета-версии на планах Pro, Max и Ultra и развертываются постепенно. Развертывание началось с аккаунтов, которые использовали облачные сессии и не имеют существующих проектов в чате claude.ai или Cowork. Projects пока недоступны на планах Team и Enterprise.

Если вы не видите Projects на боковой панели на claude.ai/code или на вкладке Code настольного приложения, проверьте раздел More там же. Если их нет и там, развертывание еще не достигло вашего аккаунта. Вы можете присоединиться к списку ожидания, а в разделе Запуск агентов параллельно узнать, что можно использовать тем временем.

Проект — это один текущий разговор, в котором Claude координирует поток связанной работы для вас. Вы говорите ему, что нужно сделать, и он запускает поток для каждой задачи.

Каждый поток обычно является облачным сеансом: Claude Code, работающий в облаке, а не на вашем компьютере. Когда задаче требуется что-то, что есть только на вашем компьютере, вы можете попросить Claude запустить этот поток на вашем компьютере вместо облака через Remote Control. Потоки работают параллельно, и вы можете проверять их и управлять ими со своего телефона. Облачные потоки продолжают работать после того, как вы закроете ноутбук, в то время как поток на вашем компьютере работает только при включенном компьютере.

Без проекта запуск нескольких сеансов означает самостоятельное координирование: вы решаете, над чем работает каждый, повторяете одинаковый контекст в начале каждого и проверяете, какой завершился или требует ответа. С проектом вместо этого вы:

  • Отправляете работу в одно место: вставляйте отчет об ошибке, трассировку стека или список задач в разговор, когда они появляются. Claude запускает поток для каждого фрагмента работы или передает его потоку, который уже работает в этой области, и отвечает на быстрые вопросы на месте.
  • Устанавливаете контекст один раз: каждый новый поток начинается с инструкций проекта, поэтому правило, которое вы указываете один раз, например какую ветку выбрать, достигает все потоки.
  • Уходите и возвращаетесь к завершенной работе: панель Overview показывает, какие потоки завершены, какие pull request готовы к проверке и какой поток ждет вашего ответа.

Если вы уже знаете работу, которую хотите, чтобы проект выполнил, переходите прямо к Создание проекта.

Когда использовать проект #

Проект стоит создавать, когда работа имеет цель, которая выходит за рамки одного сеанса и продолжает создавать задачи. Эти виды работ хорошо подходят для проекта:

  • Одна цель в нескольких репозиториях: "Обновить каждый сервис на новую конфигурацию lint." Claude может запустить поток для каждого репозитория, каждый с собственным pull request, и панель Overview показывает, какие готовы к проверке.
  • Область, которую вы постоянно пополняете: ошибки, трассировки стека и запросы на проверку для одного сервиса, вставляемые в разговор по мере их поступления. Ошибка, которую вы просите Claude запомнить после одного исправления, находится в памяти проекта для следующей.
  • Сборка или миграция больше, чем сеанс: "Построить то, что описывает docs/spec.md" или "Перенести приложение с устаревшего ORM." Работа разбивается на потоки, каждый берет часть, решения, которые вы просите Claude запомнить в начале, достигают более поздние потоки, и изменения спецификации и ошибки, которые вы находите во время сборки, попадают в один разговор.
  • Работа, не связанная с кодом: папка с контрактами или экспорт обращений в службу поддержки, к которым вы постоянно возвращаетесь с новыми вопросами, например «найди десять самых распространённых ошибок интеграции в этих обращениях». Загрузите документы вместо добавления репозитория, и потоки будут сохранять каждый отчёт в виде файла в Library проекта.

В любом из этих случаев вы можете отправить пакет задач, попросить Claude начать без вашего подтверждения и уйти. Когда вы вернётесь, потоки, которым нужны вы, можно найти в разделе Waiting on you. Вы также можете попросить Claude поставить часть работы по расписанию как облачную запланированную задачу. Если это ваша ситуация, создайте проект.

Когда что-то другое подходит лучше #

Проект все еще подходит, когда только некоторые задачи требуют вашей машины. Облачные потоки работают с репозиториями GitHub и с файлами, папками и папками Google Drive, которые вы загружаете в проект, а для случайной задачи, которая требует локальной базы данных или инструмента на вашем компьютере, вы можете попросить Claude запустить поток этой задачи на вашем компьютере. Что-то другое подходит лучше в этих случаях:

  • Одна задача, которая подходит в сеанс: "Исправить нестабильный тест входа." Запустите облачный сеанс самостоятельно.
  • Работа, где каждая задача требует вашей машины: локальная база данных, эмулятор устройства или API за вашим VPN. Используйте локальный сеанс или agent view для запуска нескольких одновременно. Если работе нужны только локальные файлы, загрузите их в проект вместо этого.
  • Одна задача, которая повторяется по расписанию без диалога вокруг неё: "Публиковать отчёт о зависимостях каждый понедельник." Создайте отдельную облачную запланированную задачу.
  • Несколько человек дают Claude работу и направляют его вместе в канале Slack: см. Claude Tag.

Проект использует те же лимиты плана, что и другие сеансы Claude Code, и использует их быстрее. Использование и стоимость охватывает то, что использует ваш план и как его снизить.

Как устроен проект #

Проект — это один координирующий диалог с Claude плюс потоки, которые он запускает для выполнения работы. Вот его составные части:

  • Диалог проекта: одна долгоживущая сессия, в которой Claude выступает координатором. Он принимает то, что вы отправляете, решает, что станет потоком, и отслеживает каждый запущенный им поток. Он видит то, о чём потоки отчитываются, а не каждый их шаг.
  • Потоки: исполнители. Каждый из них — отдельная сессия со своим собственным контекстным окном, которая выполняет одну часть работы и отчитывается перед диалогом по завершении. Облачный поток работает в своей собственной ветке и открывает pull request, когда этого требует работа.
  • С чем начинает каждый облачный поток:
  • Репозитории и файлы проекта, а также его инструкции и память
  • CLAUDE.md в каждом из репозиториев проекта, но не скиллы, .claude/settings.json или .mcp.json этих репозиториев
  • Коннекторы в вашей учётной записи claude.ai
  • Облачное окружение, которое задаёт сетевой доступ, переменные окружения, сетевые секреты и установленные инструменты
  • Панель Overview: здесь вы видите все потоки сразу, а также какие из них требуют вашего участия.

Облачные потоки ничего не берут из настроек Claude Code на вашем собственном компьютере. В разделе Передача скиллов, плагинов, коннекторов и инструментов в потоки описано, как предоставить им то, чего им иначе не хватало бы.

Вот как связаны эти части — от вас через диалог к потокам, выполняющим работу, а Overview отслеживает их состояние:

Создание проекта #

Вы создаете и используете проекты в claude.ai/code, на вкладке Code настольного приложения или в мобильном приложении Claude для iOS и Android. В браузере и настольном приложении есть два способа начать проект:

  • С нуля, когда вы знаете поток работы, который хотите запустить в Claude: откройте диалог New project и назовите его. Запуск нового проекта с нуля проходит через диалог.
  • Из облачной сессии, которая уже выполняет работу: в меню этой сессии на боковой панели выберите Continue in project, затем Continue as new project. Claude предлагает настройку проекта на основе того, что делала сессия. См. Запуск из существующей облачной сессии.

В любом случае сначала проверьте предварительные условия.

Проверка предварительных условий #

Перед созданием проекта проверьте ваш план, настройку GitHub и то, что нужно работе для достижения:

  • План: вы на Pro, Max или Ultra, и Projects отображается на вашей боковой панели — напрямую или в разделе More. Выберите Projects и убедитесь, что там предлагается New project или Get started.
  • GitHub, если проект будет работать с кодом: ваш код находится на github.com, а не на GitHub Enterprise Server, GitLab или Bitbucket, ваш подключенный аккаунт GitHub имеет доступ на push к нему, и Claude GitHub App установлено на нем. Если вы подключили GitHub с помощью /web-setup, этот токен позволяет вашим другим облачным сеансам достичь репозитория, но недостаточно для облачных потоков проекта, которым нужно Claude GitHub App. Настройка доступа GitHub содержит шаги.
  • Сеть, секреты и инструменты: для облачных потоков они поступают из облачной среды проекта. Среда по умолчанию уже имеет доступ к распространенным реестрам пакетов, поэтому проверяйте это, только если работе нужны другие домены, секрет или инструмент, который не предустановлен. Если работе нужен MCP-сервер, проверьте, что он отображается как подключенный в ваших коннекторах claude.ai.

Запуск нового проекта с нуля #

Запуск проекта с нуля означает открытие диалога New project, назначение потока работы и опционально предоставление ему цели и репозиториев и файлов, над которыми он работает. Требуется только имя, поэтому вы можете создать проект первым и заполнить остальное по мере развития работы.

1. Откройте Projects

В claude.ai/code или на вкладке Code настольного приложения выберите Projects на левой боковой панели или в разделе More на ней. В браузере вы также можете перейти прямо на claude.ai/code/projects/browse. Затем выберите New project. Если вместо этого на кнопке написано Get started, выберите ее и сначала обновите или архивируйте существующие проекты claude.ai, которые в ней перечислены.

2. Заполните диалоговое окно New project

Ограничьте проект одним потоком работы, который вы будете постоянно пополнять, например всем, что требуется для поддержания одного API в пределах его целевой задержки. Когда использовать проект содержит больше примеров. Затем заполните поля диалогового окна:

  • Name: как проект отображается в списке Projects.
  • What do you want to work on? (опционально): одна строка, которая становится целью проекта, например «Держать p95 задержку API ниже 200 мс». Claude в диалоге работает над ее достижением. Без цели Claude работает на основе задач, которые вы отправляете, и вы можете добавить цель позже в Project settings > General.
  • Context (опционально): репозитории GitHub, над которыми работает этот проект, плюс любые файлы, папки или папки Google Drive, которые потоки должны читать. Нажмите + для каждого. Добавьте репозитории, которые нужны большинству задач, а не каждый, который работа может затронуть; Решение, какие репозитории добавить охватывает выбор, и вы можете добавить больше позже в Project settings > Environment.

Постоянные правила того, как потоки должны работать, идут в инструкции проекта, которые вы устанавливаете после создания проекта.

3. Создайте проект

Нажмите Create project. Разговор проекта открывается с полем сообщения внизу, где вы описываете работу для Claude.

На вашем первом проекте Claude делает ход самостоятельно сразу после создания проекта, если вы не отправите сообщение первым. Этот ход использует ваш план. В нем Claude может:

  • Запустить один поток, который исследует репозиторий, ничего не изменяя, и предлагает следующие шаги, если у проекта есть репозиторий, который он может читать.
  • Опубликовать Setup recommendations, основанные на ваших недавних облачных сессиях: репозитории для добавления, запланированные задачи для создания и потоки, которые он может запустить. Каждый рекомендуемый репозиторий и каждая запланированная задача изначально включены. Отключите те, которые вам не нужны, затем нажмите Update setup, чтобы добавить остальные, или игнорируйте рекомендации и опишите работу самостоятельно.

Проект теперь отображается на боковой панели, и его диалог открыт. Ваш первый пакет охватывает то, что нужно настроить перед отправкой ему работы.

Запуск из существующей сессии #

Если облачная сессия, которую вы запустили сами, выполняет работу, которая относится к проекту, откройте ее меню на боковой панели, выберите Continue in project, а затем выберите вариант в подменю:

  • Выберите Continue as new project, чтобы создать новый проект из сессии. Проект открывается, Claude читает сессию и публикует Setup recommendations в диалоге проекта для вашего подтверждения. Исходная сессия остается в вашем списке сессий. Если она была в середине хода, она продолжает работу, поэтому остановите ее самостоятельно, если вы не хотите, чтобы обе работали одновременно.
  • Выберите один из ваших существующих проектов, чтобы перенести работу сессии в этот проект. Этот проект открывается, и сообщение, отправленное от вашего имени, просит Claude прочитать сессию и продолжить с того места, где она остановилась. Исходная сессия остается в вашем списке сессий без изменений.

Над полем сообщения облачной сессии также может появиться баннер Set up project. Если вы используете его вместо Continue as new project, результат тот же, за исключением того, что выполняющийся ход сессии останавливается после открытия проекта.

Сессия на вашем собственном компьютере получает то же меню на боковой панели в claude.ai/code после того, как вы подключите ее через Remote Control. Из проекта Claude не может прочитать транскрипт сессии, которая была подключена, пока для вашего аккаунта была включена настройка Require trusted devices. Если эта настройка отключена:

  1. Если сессия еще не подключена, выполните в ней /remote-control. Если она была подключена, пока эта настройка была включена, сначала отключите ее и подключите снова.
  2. В браузере найдите строку сессии на боковой панели в claude.ai/code, откройте ее меню и выберите вариант в том же подменю.

Если Require trusted devices включена или вы не используете Remote Control, опишите работу в диалоге проекта самостоятельно. Или отправьте ветку сессии (push), добавьте ее репозиторий в проект и сообщите Claude имя ветки.

Настройка доступа GitHub #

Большинство настроек GitHub происходит один раз, а не для каждого проекта. Вы подключаете свой аккаунт GitHub к Claude один раз, и Claude GitHub App устанавливается один раз для каждого репозитория или один раз для всей организации GitHub, если вы даете ей все репозитории. Вы возвращаетесь к этим шагам, когда добавляете репозиторий, который Claude GitHub App еще не охватывает, или один в организации GitHub, которая требует SSO.

1. Подключите свой аккаунт GitHub

Если вы раньше не использовали claude.ai/code, ваше первое посещение проведет вас через подключение GitHub; см. Подключение GitHub. В противном случае используйте один из вариантов аутентификации GitHub.

2. Установите Claude GitHub App на репозитории проекта

Установите Claude GitHub App и предоставьте ей репозитории, которые будет использовать проект. На репозитории, принадлежащем организации GitHub, только владелец организации может завершить установку; если вы не являетесь одним из них, GitHub отправляет владельцу запрос на установку и проект не может использовать репозиторий, пока они его не одобрят.

3. Авторизуйте SSO для организаций, которые его требуют

Если организация GitHub требует SAML SSO, переподключите GitHub и авторизуйте Claude app для этой организации. До тех пор приватные репозитории этой организации не отображаются в диалоге New project или Project settings > Environment.

Когда один из этих шагов неполный, диалог New project и страница проекта называют отсутствующий шаг и ссылаются на то, где вы его завершаете. Завершите шаг там, затем нажмите Check again, если диалог это предлагает. Если репозиторий все еще отсутствует в списке после этого, откройте установку Claude GitHub App на GitHub в github.com/settings/installations для личного аккаунта и подтвердите, что репозиторий указан в разделе Repository access. Для сообщений об ошибках, которые поток или проект сообщают, когда доступ все еще неправильный, см. Ошибки доступа к репозиторию.

Работа в проекте #

Передавайте Claude работу через диалог проекта: задачи по одной или несколько сразу, а также обновления и разрозненные мысли по мере их появления. Claude распределяет каждое сообщение, а треды выполняют работу и отчитываются.

Ваш первый пакет задач #

Прежде чем отправлять новому проекту пакет работы, настройте его так, чтобы первые треды возвращали результаты в нужном вам виде:

  1. Напишите инструкции проекта: бриф, с которого начинается каждый тред, например, на какую ветку нацеливаться, как тред проверяет свою работу и что требует вашего согласия.
  2. Отправьте одну небольшую часть реальной работы или запустите один из тредов, предложенных Claude, если он их предложил, и откройте тред, когда он завершится, чтобы увидеть, как он отчитывается и что сделал в своей ветке. Если он сделал неверное допущение или не смог получить доступ к тому, что ему было нужно, раздел Треды угадывали или застревали вместо того, чтобы спросить описывает, где это исправить.
  3. Проверьте Thread model и Thread effort в Project settings > General. Новый проект запускает каждый тред на Opus с высоким уровнем усилий, что быстрее всего расходует ресурсы вашего плана; раздел Выбор моделей и управление контекстом силами Claude описывает альтернативы.
  4. Попросите Claude предлагать треды перед их запуском и запускать по несколько за раз, а затем снимите эти ограничения, когда несколько тредов вернут результаты в нужном вам виде.

Отправка работы и чтение результатов #

Claude решает, куда направить каждое сообщение, которое вы отправляете в диалоге:

  • На быстрый вопрос обычно приходит ответ прямо в диалоге.
  • Новая работа направляется в новый тред или в тред, который уже работает в этой области, и Claude сообщает вам, в какой именно. Каждый новый тред отображается в диалоге, и чтобы открыть тред, нужно нажать на него.
  • Несколько несвязанных задач в одном сообщении становятся отдельными тредами.

Если Claude распределил что-то не так, как вы хотели, скажите ему об этом. Раздел Настройка того, как Claude ведёт проект перечисляет, что вы можете ему сказать, например, использовать существующий тред для последующих задач или отвечать на месте вместо запуска треда.

Полные результаты треда остаются в треде, поэтому, чтобы прочитать их, откройте тред. Файлы, созданные тредом, также находятся в Library проекта.

Иногда Claude предлагает треды вместо того, чтобы запускать их, в списке Suggested threads. Нажмите стрелку у предложения, чтобы запустить этот тред. Если в списке несколько предложений, кнопка под списком запускает их все.

Проверка pull request треда #

Когда облачный тред изменяет код, он делает следующее, если вы не укажете иное:

  • Ветка: работает в новой ветке, созданной от ветки по умолчанию репозитория.
  • Pull request: открывает его, когда вы попросите, и может открыть его самостоятельно для исправления ошибки или другого конкретного изменения.
  • После открытия: отслеживает pull request с включённым автоисправлением, независимо от того, включено ли автоисправление для других ваших облачных сессий. Он отправляет исправления, когда CI завершается с ошибкой, обрабатывает комментарии ревью и отвечает в треде, когда проверки пройдены и pull request готов для вас.

Чтобы изменить, когда треды открывают pull request, например только по вашей просьбе, или от какой ветки они начинают, укажите это в задаче или в инструкциях проекта.

  • Прочитать, что сделал Claude, шаг за шагом.
  • Направлять выполнение задачи, написав в собственном поле сообщения треда. Сообщение там попадает прямо в этот тред, тогда как последующее сообщение в диалоге проекта доходит до него, только если Claude сопоставит его с этим тредом.
  • Ответить на запрос разрешения, который ожидает тред.

Выбор моделей и управление контекстом силами Claude #

Задайте модели и уровень усилий в Project settings > General. Новый проект везде использует Opus, с высоким уровнем усилий для тредов и низким для диалога:

  • Thread model и Thread effort применяются к тредам. Чтобы использовать другую модель для одной задачи, попросите об этом в задаче; для уже запущенного треда используйте селектор модели этого треда.
  • Coordinator model и Coordinator effort применяются к Claude в диалоге проекта.

В проекте вы не управляете контекстными окнами. Треды сжимаются автоматически, а диалог работает на основе недавних сообщений, недавних тредов и памяти проекта, а не всей своей истории, поэтому он продолжается столько, сколько работает проект. Всё, что никогда не должно быть отброшено, поместите в память проекта. Если один тред перерастает свой контекст, он показывает Claude ran out of context on this turn.

Настройка того, как Claude ведёт проект #

Сообщите Claude в диалоге, сколько тредов запускать одновременно, когда публиковать обновления и когда открывать pull request. Если Claude координирует работу не так, как вы хотите, скажите ему об этом. Например, вы можете сказать:

  • «Предлагай треды и жди моего согласия, прежде чем запускать их» или «Запусти их сейчас, не спрашивая подтверждения»
  • «Запускай не более двух тредов одновременно» или «Используй существующий тред для последующих задач в той же области»
  • «Публикуй более короткие обновления» или «Пиши только тогда, когда что-то завершилось или заблокировано»
  • «Дай мне сводку статуса по каждому треду»
  • «Выполни эту задачу с моделью поменьше»
  • «Не открывай pull request, пока я не посмотрю план»
  • «Скажи, что не так в этих репозиториях, и пока ничего не исправляй», когда вы хотите просмотреть выводы до того, как какой-либо из них станет тредом
  • «Ответь здесь, а не запускай тред», когда Claude запускает тред для того, что вы задумывали как быстрый вопрос

Claude самостоятельно сохраняет подобные предпочтения в память проекта и следует им в последующих облачных тредах. Это инструкции, которых Claude придерживается, а не принудительно применяемые настройки, поэтому заданное таким образом ограничение на число тредов не является жёстким пределом. Добавьте его в инструкции проекта, если хотите, чтобы оно было сформулировано точно и применялось к каждому треду с самого начала.

Разблокировка треда, ожидающего подтверждения #

Треды работают в авторежиме, если модель треда его поддерживает, поэтому большинство вызовов инструментов выполняется без вашего участия. Когда треду нужно ваше подтверждение, запрос находится внутри этого треда, и тред ждёт, пока вы ответите на него там. Если сказать Claude в диалоге проекта продолжать, это до треда не дойдёт.

Каждое подтверждение распространяется на этот запрос или на весь оставшийся тред, если вы выберете более широкий вариант. Облачные треды не читают правила разрешений из .claude/settings.json репозитория, поэтому вы полагаетесь на авторежим и на подтверждения, которые даёте внутри каждого треда.

Запуск треда на вашем компьютере #

Когда задаче нужно что-то, что есть только на вашем компьютере, например локальная база данных, эмулятор устройства или API за вашим VPN, попросите Claude запустить тред для этой задачи на вашем компьютере, а не в облаке. Когда вы просите об этом в диалоге проекта, тред представляет собой сессию Claude Code в папке на вашем компьютере, подключённую через Remote Control. Остальные треды проекта продолжают работать в облаке. По сравнению с облачным тредом, тред на вашем компьютере:

  • Работает с файлами, инструментами, MCP-серверами и настройками Claude Code на этом компьютере, включая его хуки и правила разрешений, а не с облачной средой проекта
  • Запускается с инструкциями проекта, но без загруженных файлов его памяти
  • Работает, только пока этот компьютер не находится в спящем режиме и на нём включён Remote Control

1. Подключите папку

На компьютере, где находится нужная задаче папка, сделайте её доступной через Remote Control одним из двух способов. Для обоих требуется Claude Code v2.1.280 или новее на этом компьютере.

  • В настольном приложении Claude: откройте Settings > Code или Settings > Claude Code и включите Use this computer from your phone and claude.ai. Добавьте папку в список под этим переключателем. Треды могут работать на этом компьютере, пока приложение открыто.
  • В терминале: выполните claude remote-control в папке и оставьте команду работать. В Git-репозитории добавьте --spawn worktree, чтобы каждый тред там получал собственный worktree, а не саму папку.

2. Запросите задачу

В диалоге проекта выберите Work locally в меню + или Work in a local folder в настольном приложении и напишите, что нужно сделать. Также можно просто указать в сообщении, что задача должна выполняться на вашем компьютере.

Если пункт Work locally неактивен и рядом показано примечание о доверенных устройствах, для вашей учётной записи включена настройка Require trusted devices, и этот проект не может запустить тред на вашем компьютере. Чтобы работать в этой папке, запустите Claude Code непосредственно на этом компьютере.

3. Разрешите это на карточке

Claude ответит карточкой Allow Claude to work in a folder on your computer. Выберите папку, если вы подключили несколько. Два треда, одновременно работающие в одной папке, могут перезаписывать изменения друг друга. Если папка является Git-репозиторием, вы можете вместо этого включить Worktree в параметрах папки, чтобы этот тред получил собственный worktree. Затем нажмите Allow once.

Тред работает в авторежиме, поэтому Claude выполняет команды и редактирует файлы в этой папке, не спрашивая вас каждый раз. Если авторежим недоступен или отключён в Claude Code на этом компьютере, тред работает без него, и любой запрос разрешения, который он выдаёт, ожидает вашего ответа в треде, как описано в разделе Разблокировка треда, ожидающего подтверждения.

Чтобы запустить тред в другом режиме, запустите claude remote-control с --settings. Тогда permissions.defaultMode в этом файле или в настройках этого компьютера может выбрать другой режим.

Пока тред работает, значок ноутбука в его заголовке показывает, подключён ли ваш компьютер. Нажмите на него, чтобы увидеть, какую папку использует тред, или отключить соединение. Тред приостанавливается, пока этот компьютер находится в спящем режиме, и останавливается, если настольное приложение или claude remote-control завершает работу.

  • Чтобы снова запустить тред: см. Lost contact with your folder
  • Чтобы компьютер сам не переходил в спящий режим: в настольном приложении включите Keep this computer awake for Remote Control в Settings > Code или Settings > Claude Code

Напишите инструкции проекта #

Инструкции проекта — это краткое описание, с которого начинает каждый новый поток. Выберите Settings в меню ⋯ в заголовке проекта, чтобы открыть Project settings, затем перейдите в Memory > Project instructions. Полезное краткое описание охватывает:

  • Для чего предназначен проект
  • Где происходит работа: какие репозитории, от какой ветки начинать, как называть pull requests
  • Как поток проверяет свою работу, прежде чем считать её выполненной
  • Что делать, когда чего-то нужного не хватает
  • Что сначала требует вашего одобрения

Например:

```text theme={null} This project holds p95 latency for the payments API under 200 ms: profiling, query and caching fixes, and the dependency upgrades that come with them, in the payments-api repository.

  • Branch from main and open one draft pull request per thread.
  • Before you call work done, run make test and make lint and paste the summary lines in your final message.
  • If you can't reach something you need, such as a repository, a secret, an API, or a connector, say exactly what's missing in your first message and stop. Don't substitute, mock, or guess.

Правила, касающиеся одного репозитория, например его команды сборки, следует размещать в `CLAUDE.md` этого репозитория, который каждый облачный поток читает, когда репозиторий входит в проект. ### Решение, какие репозитории добавить

Репозитории, которые вы добавляете в проект, попадают в каждый облачный поток со своим кодом и `CLAUDE.md`, но [без своих скиллов, `.claude/settings.json` и `.mcp.json`](#what-threads-pick-up-from-your-repositories). Репозитории, которые вы не добавляете, всё равно остаются доступными: облачный поток может добавить такой репозиторий себе, когда это требуется для его задачи. Большинство проектов используют оба варианта:

* **Добавьте его в проект** в диалоговом окне **New project**, в **Project settings > Environment** или попросив Claude в диалоге добавить его в проект. Каждый облачный поток с этого момента клонирует его и начинает с загруженным `CLAUDE.md` этого репозитория, независимо от того, затрагивает ли его задача.
* **Не добавляйте его и позвольте потокам добавлять его при необходимости.** Облачный поток, задаче которого нужен репозиторий, отсутствующий в проекте, может добавить его себе, и заметка в потоке сообщает, что он добавлен только в этот поток. Клонирование происходит в середине задачи, поэтому `CLAUDE.md` этого репозитория не было, когда поток запускался. Следующий поток начинает без него. Репозиторию, добавленному таким образом, нужны те же [предварительные требования](#check-the-prerequisites), что и репозиторию проекта: установленное на нём Claude GitHub App и доступ на push из вашего аккаунта GitHub.

Проекту вообще не обязателен репозиторий. Его облачные потоки всё равно могут проводить исследования, писать документы, а также писать и запускать код в собственной песочнице. Они доставляют файлы в раздел **Library** проекта. Любой из его облачных потоков по-прежнему может добавить себе репозиторий, когда этого требует задача.

Когда у проекта есть репозитории, Claude может добавлять только репозитории того владельца GitHub, которого проект уже использует, — добавляет ли он репозиторий в проект или поток добавляет его себе. Чтобы подключить репозиторий другого владельца, добавьте его в проект самостоятельно в **Project settings > Environment**.

Для проекта, охватывающего много репозиториев, например одну функцию с серверным, веб-, мобильным и десктопным кодом, добавьте один или два репозитория, которые затрагивает почти каждая задача, и назовите остальные в [инструкциях проекта](#write-project-instructions), чтобы Claude знал, где находится остальной код. Тогда облачные потоки начинают с малого и подтягивают другие репозитории только для тех задач, которым они нужны.

### Добавьте файлы и папки

Добавьте файлы и папки, которые должны читать потоки, в поле **Context** диалогового окна **New project** или позже с помощью **Add** в разделе [**Library**](#see-what-needs-you-in-overview) проекта. К добавляемому применяются следующие ограничения:

* **Файлы, которые вы загружаете на claude.ai/code или в десктопном приложении**: до 1 000 файлов и 2 ГБ за один раз, при этом один файл — до 480 МБ.
* **Папки, которые вы загружаете**: скрытые файлы и `node_modules` не добавляются. Проект может содержать до 10 папок и папок Google Drive в сумме, а отдельные файлы в это ограничение не засчитываются.
* **Изменения после загрузки**: загрузки являются копиями, поэтому изменение, которое вы позже вносите на своём компьютере, не попадает в проект, пока вы снова не загрузите файл и не выберете **Replace** при запросе о существующем имени.

### Что потоки берут из ваших репозиториев

Облачные потоки загружают инструкции `CLAUDE.md` каждого репозитория, но не его скиллы, серверы из `.mcp.json` или `.claude/settings.json`, независимо от того, один репозиторий в проекте или несколько.

| В каждом репозитории | В облачном потоке |
| :- | :- |
| `CLAUDE.md`, `.claude/CLAUDE.md` и `.claude/rules/` в корне репозитория | Загружаются из каждого репозитория при запуске потока. Файлы `CLAUDE.md` в поддиректориях и [правила для конкретных путей](https://code.claude.com/docs/ru/memory.md#path-specific-rules) не загружаются |
| Скиллы в `.claude/skills/` | Не загружаются. Вместо этого включите скилл для своего аккаунта claude.ai, как описано в разделе [Передача скиллов, плагинов, коннекторов и инструментов в потоки](#get-skills-plugins-connectors-and-tools-into-threads) |
| Агенты и команды в `.claude/` | Не загружаются. Чтобы использовать их, [запустите поток на своём компьютере](#run-a-thread-on-your-own-computer) |
| MCP-серверы в `.mcp.json` | Не загружаются. Вместо этого используйте коннекторы своего аккаунта claude.ai, как описано в разделе [Передача скиллов, плагинов, коннекторов и инструментов в потоки](#get-skills-plugins-connectors-and-tools-into-threads) |
| Плагины, включённые в `.claude/settings.json` | Не загружаются. Вместо этого добавьте плагин в **Project settings > Plugins** |
| Правила разрешений в `.claude/settings.json` | Не применяются. Подтверждайте вызовы инструментов внутри потока, как описано в разделе [Разблокировка потока, ожидающего подтверждения](#unblock-a-thread-waiting-on-approval), или [запустите поток на своём компьютере](#run-a-thread-on-your-own-computer) |
| Хуки в `.claude/settings.json` | Не запускаются. Чтобы использовать свои хуки, [запустите поток на своём компьютере](#run-a-thread-on-your-own-computer) |
| `env` в `.claude/settings.json` | Не применяется. Задайте переменные окружения в [облачной среде](#choose-an-environment-for-threads) |

### Выбор среды для потоков

Каждый новый облачный поток начинается в [облачной среде](https://code.claude.com/docs/ru/cloud-environments.md) проекта. Среда определяет, к каким доменам могут обращаться потоки, какие переменные окружения у них есть, какие сетевые секреты добавляются в их запросы и что устанавливает скрипт настройки до запуска Claude. Облачные потоки используют среду по умолчанию, размещённую Anthropic, пока вы не выберете другую в **Project settings > Environment**.

Если облачным потокам нужно обращаться к внутреннему API или приватному реестру пакетов либо нужен токен, который обычно хранится на вашей машине, измените среду, а не проект: см. [Сетевой доступ](https://code.claude.com/docs/ru/cloud-environments.md#network-access), [Добавление сетевых секретов](https://code.claude.com/docs/ru/cloud-environments.md#add-network-secrets) и [Скрипты настройки](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts).

### Передача скиллов, плагинов, коннекторов и инструментов в потоки

У облачных потоков нет скиллов, MCP-серверов, плагинов и инструментов, установленных только на вашей машине. Поток, который Claude запускает на вашей машине через [Remote Control](https://code.claude.com/docs/ru/remote-control.md), использует то, что установлено там. Чтобы сделать каждый из них доступным для облачных потоков:

* Скиллы: включите их для своего аккаунта claude.ai, и облачные потоки будут загружать [скиллы, которые вы там включили](https://code.claude.com/docs/ru/skills.md#skills-in-cowork-and-cloud-sessions), за исключением [некоторых потоков в самостоятельно размещённой среде](https://code.claude.com/docs/ru/self-hosted-environments-configuration.md#how-each-session’s-config-is-assembled). Скиллы, добавленные коммитом в `.claude/skills/` репозитория, не загружаются в облачных потоках.
* Плагины: добавьте их в **Project settings > Plugins**; они загружаются в каждый новый облачный поток. Плагины, которые репозиторий объявляет в своём `.claude/settings.json`, [не загружаются в облачных потоках](https://code.claude.com/docs/ru/cloud-environments.md#what-carries-over-from-your-setup).
* MCP-серверы: облачные потоки получают свои инструменты MCP из коннекторов вашего аккаунта claude.ai — это MCP-серверы, которые вы один раз подключаете на [claude.ai/customize/connectors](https://claude.ai/customize/connectors). Каждый облачный поток может использовать их все без настройки для каждого проекта. У самого диалога проекта нет коннекторов, поэтому работу, требующую коннектора, отправляйте как задачу для облачного потока. В разделе [Как коннекторы попадают в Claude Code](https://code.claude.com/docs/ru/mcp.md#how-connectors-reach-claude-code) перечислены правила для облачных сессий и настройки, отключающие коннекторы.
* Инструменты командной строки и пакеты: установите их в [скрипте настройки](https://code.claude.com/docs/ru/cloud-environments.md#setup-scripts) среды.

Чтобы увидеть, какие коннекторы есть у работающего облачного потока в claude.ai/code, откройте поток и выберите **Connectors** в меню **+** рядом с его полем ввода сообщения. Отключение коннектора там удаляет его из этого потока и сохраняет это как значение по умолчанию для вашего аккаунта, поэтому новые потоки и чаты claude.ai начинаются без него, пока вы снова его не включите. Облачный поток подхватывает коннектор, который вы добавили или переподключили, после следующего отправленного ему сообщения.

## Справочник параметров проекта

Вы изменяете настройки проекта в claude.ai/code или в настольном приложении, а не в `settings.json`. Откройте **Project settings** из **Settings** в меню боковой панели проекта или в меню **⋯** в заголовке проекта.

Параметры сохраняются по мере их изменения; текстовое поле, которое вы редактируете, например цель или инструкции, показывает **Save changes** и **Discard** до тех пор, пока вы его не покинете. Изменения инструкций, репозиториев, plugins и среды в **Project settings** достигают новые потоки, а не уже работающие потоки.

| Параметр | Раздел | Что он контролирует |
| :- | :- | :- |
| Имя, значок и цель | General | Имя и значок проекта на боковой панели и его одностроковая цель |
| Модель Coordinator и интенсивность | General | Модель и [уровень интенсивности](https://code.claude.com/docs/ru/model-config.md#adjust-effort-level) для Claude в разговоре проекта |
| Модель Thread и интенсивность | General | Модель и уровень интенсивности для потоков |
| Инструкции проекта | Memory | [Постоянные правила](#give-a-project-standing-context), которые получает каждый новый поток |
| Репозитории проекта | Environment | Репозитории, которые клонируют новые потоки |
| Облачная среда | Environment | [Облачная среда](#choose-an-environment-for-threads), в которой работают новые потоки |
| Plugins | Plugins | Plugins, которые загружаются в каждый новый поток |

### Пауза, архивирование или удаление проекта

Все три элемента управления находятся в нижней части **Project settings > General**:

* **Pause**: останавливает все сразу. Каждый работающий поток и диалог прерываются, новые потоки не запускаются, запланированные задачи не выполняются, и проект не принимает сообщения, пока вы его не возобновите. Нажмите **Resume** в том же месте или на баннере выше поля сообщения проекта; приостановленный поток продолжает работу, когда вы отправляете ему сообщение после этого.
* **Archive**: скрывает проект из боковой панели и архивирует его потоки, что останавливает любой поток, который работал или наблюдал за pull request. Запланированные задачи в проекте не выполняются, пока он архивирован. Чтобы вернуть проект, откройте его со страницы Projects и нажмите **Unarchive**. Его потоки остаются архивированными, пока вы не разархивируете их отдельно из списка сессий.
* **Delete**: постоянно удаляет проект вместе с его потоками, его памятью и его файлами, и отключает запланированные задачи проекта. Это не может быть отменено. Ветки и pull request, которые потоки отправили на GitHub, не затрагиваются.

## Использование и стоимость

Использование проекта считается против тех же [лимитов плана](https://code.claude.com/docs/ru/errors.md#youve-hit-your-session-limit), что и ваши другие сеансы Claude Code, и проект не может потратить больше этих лимитов самостоятельно.

Поток, который останавливается на лимите вашего плана, ждет и по умолчанию продолжает работу самостоятельно, когда лимит сбрасывается. Тогда его работа засчитывается в ваше следующее окно использования. Чтобы потоки не продолжали работу, см. [Поток достиг лимита использования](#usage-limit-reached).

Работа выходит за пределы лимитов вашего плана только если вы включили [usage credits](https://code.claude.com/docs/ru/costs.md#add-usage-credits-to-your-subscription) для вашего аккаунта. Поток не может включить их для вас.

### Что использует ваш план

Проект использует ваши лимиты быстрее, чем один сеанс, и на плане Pro в частности вы должны ожидать достичь ваш лимит раньше в дни, когда вы запускаете один. Это части проекта, которые используют ваш план:

* **Работающие потоки**: каждый — это полноценная сессия, и несколько могут работать одновременно. Нет фиксированного числа; Claude запускает столько, сколько требует работа, и лимит, который вы [просите](#tune-how-claude-runs-a-project), — это предпочтение, а не ограничение. Принудительный лимит — 500 новых потоков в день во всех ваших проектах.
* **Разговор**: Claude использует токены самостоятельно, читая то, что сообщают потоки и решая, что делать дальше.
* **Потоки, наблюдающие за pull request**: неактивный поток просыпается и использует ваш план снова, когда CI не работает или приходит комментарий проверки на его pull request. Чтобы остановить это, попросите в потоке остановить наблюдение за pull request.

Проект без работающих потоков, без наблюдаемых pull request и без новых сообщений не использует ваш план, пока он сидит неактивным, и архивированный проект тоже.

### Посмотрите и уменьшите использование проекта

Откройте **Usage** в **Project settings**, чтобы увидеть использование токенов по потокам и по моделям, и сколько пошло в разговор проекта. Чтобы снизить его:

* На Pro, Max и Ultra в пределах лимитов вашего плана [время жизни кэша](https://code.claude.com/docs/ru/prompt-caching.md#cache-lifetime) составляет один час. Поток, который был неактивен дольше этого времени, перечитывает весь свой диалог, прежде чем что-либо делать, когда до него доходит последующее сообщение. Для новой работы попросите Claude запустить свежий поток — это может использовать меньше, чем возрождение большого старого.
* Для работы, которая не требует самую большую модель, [выберите меньшую модель или более низкий уровень интенсивности](#choose-models-and-let-claude-manage-context) для потоков, разговора или обоих.
* Попросите Claude в разговоре проекта запускать меньше потоков одновременно или отвечать на маленькие вопросы самостоятельно вместо запуска потока.

## Как проекты связаны с другими функциями Claude Code

Несколько функций Claude Code позволяют более чем одному сеансу работать одновременно, поэтому запуск работы параллельно — это не само по себе то, для чего предназначен проект. В проекте Claude запускает и отслеживает сеансы вместо вас, и каждый начинается с одних и тех же инструкций. Вот как каждая соседняя функция соединяется с проектом:

* **Claude Tag**: [Claude Tag](https://claude.com/docs/claude-tag/overview) — это Claude в каналах Slack вашей команды, на планах Team и Enterprise. Любой в канале может дать ему работу, все в канале видят и направляют его, и он использует подключения, которые администратор настроил для этого канала.

  Проекты доступны на планах Pro, Max и Ultra. Проект принадлежит только вам: только вы отправляете ему работу и видите его потоки, и он использует ваш собственный доступ к GitHub и ваши коннекторы. Сравнение приведено в разделе [Как Claude Tag отличается от Cowork и Claude Code](https://claude.com/docs/claude-tag/concepts/how-it-works#how-claude-tag-differs-from-cowork-and-claude-code).
* **Облачные сессии**: каждый поток — это [облачная сессия](https://code.claude.com/docs/ru/claude-code-on-the-web.md), если вы не попросите Claude запустить его на вашей машине. В любом случае Claude запускает и отслеживает его вместо вас. Вы также можете перенести в проект работу облачной сессии, которую запустили самостоятельно: выберите [**Continue in project**](#start-from-an-existing-cloud-session) в меню боковой панели этой сессии.
* **Запланированные задачи**: когда вы запрашиваете работу по расписанию в проекте, Claude создаёт [облачную запланированную задачу](https://code.claude.com/docs/ru/routines.md), которая выполняется в виде тредов в этом проекте и отображается в его представлении **Запланированные задачи**. Запланированные задачи, созданные вне проекта, продолжают работать самостоятельно.
* **Remote Control**: [Remote Control](https://code.claude.com/docs/ru/remote-control.md) соединяет claude.ai с сеансом Claude Code, работающим на вашей машине. Когда вы просите Claude в проекте запустить поток на вашем компьютере, проект [использует Remote Control для этого](#run-a-thread-on-your-own-computer).
* **Локальные сессии и agent view**: сессия, которую вы запускаете самостоятельно в терминале, IDE или локальной среде настольного приложения, остается вне ваших проектов, хотя вы можете [перенести ее работу в проект](#start-from-an-existing-cloud-session). [Agent view](https://code.claude.com/docs/ru/agent-view.md) — это экран для отслеживания нескольких локальных сессий рядом, и вы по-прежнему сами запускаете каждую из них и даете ей задачу.
* **Worktrees**: [worktree](https://code.claude.com/docs/ru/worktrees.md) дает каждой локальной сессии собственную рабочую копию репозитория. Облачным потокам они не нужны: каждый клонирует свои репозитории в собственную облачную песочницу и работает в собственной ветке.
* **Agent teams**: [agent team](https://code.claude.com/docs/ru/agent-teams.md) — это один сеанс, который запускает сеансы товарищей для одной задачи, на вашей машине или внутри облачного сеанса, и заканчивается этой задачей.
* **Subagents**: [subagent](https://code.claude.com/docs/ru/sub-agents.md) работает внутри одного сеанса, выполняет побочную задачу в своем собственном контекстном окне и возвращает резюме в этот сеанс. Потоки проекта — это целые сеансы, которые Claude запускает и которые отчитываются перед разговором проекта, и поток все еще может использовать subagents для своих собственных побочных задач.
* **Projects в claude.ai chat и Cowork**: [более ранний опыт Projects](https://support.claude.com/en/articles/9517075-what-are-projects), который группирует разговоры и справочные файлы без потоков или координатора. Эти проекты продолжают работать так, как они работают сегодня, пока переработанный опыт не достигнет их.

[Запуск агентов параллельно](https://code.claude.com/docs/ru/agents.md) сравнивает эти варианты рядом.

## Ограничения

* Projects доступны в claude.ai/code, в настольном приложении и в мобильном приложении Claude, но не в CLI терминала, расширении VS Code или плагине JetBrains, и не через Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry.
* Потоки проекта — это [облачные сеансы](https://code.claude.com/docs/ru/claude-code-on-the-web.md) или сеансы на вашей собственной машине через [Remote Control](https://code.claude.com/docs/ru/remote-control.md), с Anthropic в качестве поставщика модели в обоих случаях. [Безопасность](https://code.claude.com/docs/ru/security.md) и [Использование данных](https://code.claude.com/docs/ru/data-usage.md) охватывают, как облачные сеансы изолированы и что сохраняется, а [Connection and security](https://code.claude.com/docs/ru/remote-control.md#connection-and-security) охватывает, как поток на вашей машине подключается и что хранится.
* Вы не можете добавить в проект сессию, которую запустили сами на своей машине, но можете [перенести её работу в проект](#start-from-an-existing-cloud-session). Проект попадает на вашу машину путём [запуска потока там через Remote Control](#run-a-thread-on-your-own-computer), и в этом разделе перечислено, что для этого нужно.
* Песочница потока приостанавливается между ходами и возобновляется, когда поток продолжает. Если песочница не может быть возобновлена, поток продолжает с свежего клона, поэтому незафиксированные изменения могут быть потеряны. На долгих задачах попросите Claude зафиксировать и отправить работу в процессе.
* Проект принадлежит одному пользователю. Вы не можете поделиться проектом или его потоками с другим пользователем, и транскрипты потоков не имеют опции поделиться, которую имеют другие облачные сеансы. Нет элементов управления на уровне организации для проектов во время бета-версии.
* Поток принадлежит одному проекту, который его запустил. Вы не можете переместить или скопировать поток в другой проект или вынести его в отдельный поток. [**Continue in project**](#start-from-an-existing-cloud-session) работает только в обратную сторону: эта функция переносит работу облачной сессии в проект. Вы не можете объединить два проекта в один.

Для подсказок настройки GitHub в диалоге **New project**, см. [Настройка доступа GitHub](#set-up-github-access).

### Поток выглядит застрявшим

Claude не публикует каждый шаг, который делает поток, поэтому поток, который показывает как работающий без новых сообщений в разговоре проекта, обычно все еще работает. Новый облачный поток также подготавливает свою [облачную среду](https://code.claude.com/docs/ru/cloud-environments.md) перед началом Claude, поэтому его первое обновление занимает момент. Откройте поток, чтобы прочитать его транскрипт. Если поток ждет подсказку разрешения, ответьте там.

### Потоки угадали или застопорились вместо того, чтобы спросить

Когда несколько потоков возвращаются, имея предположено что-то неправильно, обошли отсутствующий доступ или остановились с "blocked", причина обычно одна и та же пробел в настройке проекта, а не проблема с каждой задачей. Отсортируйте, какие потоки звучат правильно, перед тем, как вы что-то исправляете:

1. Попросите Claude в разговоре: "Для каждого открытого потока, перечислите, что вы просили его сделать, что он предположил или не мог достичь, и на что он ждет." Claude читает каждый поток и отвечает в разговоре.
2. Для потоков, которые начались с неверного предположения, откройте поток из Overview и отметьте его как решенный через его меню или скажите ему, что делать вместо этого. Его ветка и любой pull request остаются на GitHub, пока вы их не удалите.
3. Исправьте пробел один раз, в [инструкциях проекта](#give-a-project-standing-context) или [среде](#choose-an-environment-for-threads), затем отправьте один поток перед отправкой остальной работы снова как новые потоки.

### Claude не ответил

Разговор проекта показывает баннер "Claude hasn't responded", когда Claude работает, но его ответы не достигают проекта. Нажмите **Restart Claude** на баннере или перейдите в **Project settings > General** и нажмите **Restart** в строке **Restart Claude**. Claude переподключается к разговору; любой ответ, который он был в процессе написания, потеряется, и потоки не затрагиваются.

### Ошибки доступа к репозиторию

Три сообщения означают, что поток или проект не может достичь один из своих репозиториев. Потокам проекта требуются [предварительные условия GitHub](#check-the-prerequisites) даже когда ваши другие облачные сеансы клонируют один и тот же репозиторий без проблем.

* **"Couldn't start the session — Claude doesn't have GitHub access to this project's repository"**, сообщено перед запуском потока, когда Claude GitHub App не установлено на этом репозитории, приостановлено или не связано с аккаунтом GitHub, который вы подключили.
* **"Unable to access your repository"**, сообщено потоком, когда его клон не работает: GitHub отклонил клон, репозиторий не был найден под названием, которое имеет проект, или ветка, с которой потоку было предложено начать, не существует.
* **"Claude can't access"** репозиторий, показано, когда вы сохраняете репозитории в диалоге **New project** или **Project settings**. Сообщение продолжается со ссылкой на установку и ссылкой на переподключение. Используйте ссылку на установку, если Claude GitHub App не установлено на этом репозитории, и ссылку на переподключение, если оно уже установлено, так как GitHub App может быть установлено на GitHub без связи с аккаунтом, который вы подключили к Claude. Если сообщение говорит, что GitHub App приостановлено или не включает этот репозиторий, следуйте его ссылке на GitHub, чтобы это исправить.

Чтобы исправить доступ GitHub при сообщениях "Couldn't start the session" или "Unable to access your repository", нажмите кнопку, которую предлагает сообщение, например **Install on GitHub** или **Select repositories**. Если кнопки нет, следуйте инструкциям в разделе [Настройка доступа GitHub](#set-up-github-access). После исправления попросите Claude в диалоге проекта запустить новый поток для той же работы.

### Поток достиг лимита использования

Когда поток или диалог проекта останавливается на пятичасовом или недельном лимите вашего плана, он ждет и по умолчанию продолжает работу самостоятельно, когда лимит сбрасывается.

Чтобы поток или диалог не продолжил работу во время сброса, указанное в его сообщении, отключите **Auto-continue when usage limits reset** в [**Project settings > General**](#project-settings-reference) до этого момента. Настройка действует для всего проекта, а не только для потока, который вы просматриваете. Чтобы продолжить при отключенной настройке, отправьте потоку или диалогу сообщение после сброса. [Ошибки лимита использования](https://code.claude.com/docs/ru/errors.md#youve-hit-your-session-limit) объясняют лимиты и когда они сбрасываются.

### Требуются дополнительные usage credits

Поток или разговор проекта сделал запрос, который ваш план охватывает только с usage credits, например один к модели или размеру контекста, который ваш план не включает, и usage credits не включены для вашего аккаунта. [Добавить usage credits к вашей подписке](https://code.claude.com/docs/ru/costs.md#add-usage-credits-to-your-subscription) охватывает, кто может их включить или купить на каждом плане. Когда credits доступны, отправьте другое сообщение для повтора.

### Потеря контакта с вашей папкой

Поток, работающий на вашем компьютере, показывает это, когда сессия Claude Code там перестала отвечать, обычно потому, что компьютер перешел в режим сна или настольное приложение либо `claude remote-control` завершили работу. Выведите компьютер из режима сна. Если настольное приложение или `claude remote-control` там больше не работает, запустите его снова:

* **Настольное приложение**: снова откройте приложение и убедитесь, что **Use this computer from your phone and claude.ai** по-прежнему включено в **Settings > Code** или **Settings > Claude Code**
* **Терминал**: снова запустите `claude remote-control` в той же папке

### Другие сообщения

Эти сообщения называют свою собственную причину. Таблица дает следующий шаг для каждого.

| Сообщение | Что делать |
| :- | :- |
| "Unable to connect to repository" с "Claude couldn't reach GitHub to fetch your repository" | Подождите немного, затем попросите Claude в диалоге проекта запустить новый поток для той же работы |
| "Unable to connect to repository" с "Claude couldn't access your repository or environment" | Ваш аккаунт GitHub требует доступ на push к репозиторию, и среда должна все еще существовать. Проверьте оба в **Project settings > Environment**, затем повторите |
| "Couldn't show the setup proposal" | Приложение, которое у вас открыто, старше, чем **Setup recommendations**, которые Claude отправил. Обновите страницу или перезагрузите настольное приложение, или попросите Claude предложить настройку снова |
| "The project's environment was removed" | Выберите другую среду в **Project settings > Environment**; изменение применяется к новым потокам |
| "Setup script failed" | В разделе [Setup script failed](https://code.claude.com/docs/ru/web-quickstart.md#setup-script-failed) перечислены распространенные причины. Исправьте скрипт в среде, затем попросите Claude в диалоге проекта выполнить задачу в новом потоке, чтобы скрипт запустился снова |
| "Claude ran out of context on this turn" | Поток заполнил свое контекстное окно. Если сообщение говорит, что поток продолжает в свежем сеансе, он продолжает самостоятельно; в противном случае попросите Claude в разговоре проекта запустить новый поток для оставшейся работы |
| "Couldn't start in" с последующим названием вашей папки | Вы разрешили потоку работать на вашем компьютере, но сеанс не смог там начать. Когда строка под сообщением дает причину, исправьте это, затем попросите Claude запустить задачу снова |
| "Claude is out of date on your device" | Компьютер, который вы выбрали для запуска потока, имеет версию Claude Code старше v2.1.280. Обновите Claude Code там или обновите настольное приложение, если это то, что подключает папку, затем попросите Claude запустить задачу снова |
| "Reached the turn limit" | Поток достиг ограничения на шаги для одного сообщения, которое устанавливает [`CLAUDE_CODE_MAX_TURNS`](https://code.claude.com/docs/ru/env-vars). Отправьте другое сообщение для продолжения, или повысьте или удалите эту переменную там, где она установлена |
