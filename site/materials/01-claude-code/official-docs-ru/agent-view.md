# Управление несколькими агентами с помощью agent view

> Отправляйте и управляйте множеством сеансов Claude Code с одного экрана. Agent view показывает, что делает каждый сеанс и какие из них требуют вашего ввода.

Agent view, открываемое с помощью `claude agents`, — это один экран для всех ваших фоновых сеансов: что работает, что требует вашего ввода и что завершено. Отправляйте новые сеансы, наблюдайте их состояние с первого взгляда вместо прокрутки стенограмм и вмешивайтесь только когда один из них требует вас. Каждый фоновый сеанс — это полная беседа Claude Code, которая продолжает работать без подключённого терминала, поэтому вы можете открыть его, ответить и уйти в любой момент.

![Agent view в терминале. Строка в верхней части подсчитывает сеансы, ожидающие ввода, работающие и завершённые. Четыре сеанса сгруппированы под Требуется ввод, Работает и Завершено. Каждая строка показывает имя сеанса, его последний статус или вопрос и время. В нижней части находится поле ввода для описания новой задачи и строка подсказок сочетаний клавиш.](https://mintcdn.com/claude-code/H7YQo-xfDxC94ETh/images/agent-view-light.png?fit=max\&auto=format\&n=H7YQo-xfDxC94ETh\&q=85\&s=f27b570ff81c2a316bef487645b1331c)

Используйте agent view, когда у вас есть несколько независимых задач, над которыми Claude может работать без вашего наблюдения на каждом шаге. Отправьте исправление ошибки, проверку pull request и исследование нестабильного теста как три строки, продолжайте работать в другом окне и проверьте, когда строка показывает, что она требует вас или имеет результат.

Когда вы хотите работать более непосредственно в сеансе любого агента, подключитесь к строке, чтобы войти в полную беседу.

Для сравнения agent view с subagents, agent teams и worktrees см. [Запуск агентов параллельно](https://code.claude.com/docs/ru/agents.md). Agent view запускает сеансы на вашей машине и вы отправляете каждый из них; чтобы Claude начал и отслеживал параллельные сеансы в облаке из одной беседы, см. [Projects](https://code.claude.com/docs/ru/claude-projects.md).

> [!NOTE]
>
> Agent view находится в исследовательском предпросмотре. Интерфейс и сочетания клавиш могут измениться по мере развития функции.

## Быстрый старт

Это пошаговое руководство охватывает основной цикл agent view: отправьте задачу, смотрите, как её строка обновляется по мере работы Claude, посмотрите, чтобы проверить её и ответить, а затем подключитесь для полного диалога. Сессия, которую вы отправляете, продолжает работать после закрытия agent view, поэтому вы можете уйти и вернуться к ней позже.

**1. Открыть agent view**

Из вашей оболочки запустите:

```bash theme={null}
claude agents
```

Если вы ещё не приняли [диалоговое окно доверия рабочему пространству](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust) для каталога, Claude Code показывает его перед открытием agent view — то же диалоговое окно, которое показывает `claude`. Примите его, чтобы сохранить доверие для рабочего пространства и продолжить. Если вы откажетесь, Claude Code завершит работу, не открывая agent view.

Agent view открывается с полем ввода внизу и таблицей, которая заполняется по мере запуска сессий. Нажмите `Esc` для возврата в вашу оболочку; если вы открыли agent view, отправив сессию в фон с помощью `←`, `Esc` вместо этого вернёт вас к этому диалогу. Ваши сессии продолжают работать, пока вас нет, и снова появляются в следующий раз, когда вы откроете agent view.

**2. Отправить сессию**

Введите промпт, описывающий задачу, и нажмите `Enter`. Для этой задачи запускается новая фоновая сессия, которая появляется в виде строки, показывающей, работает ли она, ждёт ли вас или завершена. Новая сессия использует модель, показанную в заголовке agent view. [В каком режиме разрешений она запускается](#permission-mode-model-and-effort), зависит от того, как вы открыли agent view.

Каждый промпт, который вы вводите здесь, запускает свою собственную новую сессию. Ввод другого промпта и нажатие `Enter` запускает вторую сессию рядом с первой, а не отправляет ей продолжение. Таким образом вы можете запустить несколько сессий параллельно.

Каждая сессия расходует квоту вашей подписки независимо, поэтому ознакомьтесь с разделом [Ограничения](#limitations), прежде чем отправлять много сессий одновременно.

**3. Просмотр и ответ**

Выберите строку с помощью клавиш со стрелками и нажмите `Space`, чтобы открыть панель просмотра. Она показывает самый последний вывод сессии или вопрос, на который она ждёт ответа, а не полный транскрипт. Введите ответ и нажмите `Enter`, чтобы отправить его, не покидая agent view.

**4. Подключение и отключение**

Нажмите `Enter` или `→` на строке для подключения, когда вам нужен полный диалог. Сессия занимает терминал как полноценная интерактивная сессия Claude Code. Нажмите `←` на пустом промпте, чтобы отключиться и вернуться к таблице.

**5. Перенести существующую сессию**

Для этого шага нужна запущенная сессия. Если вы следовали предыдущим шагам, у вас нет открытой сессии в этом терминале, поэтому откройте обычную сессию `claude` в другом терминале и сначала отправьте ей сообщение.

Чтобы перенести уже открытую сессию в agent view, запустите в ней `/bg` или нажмите `←` на пустом промпте, чтобы отправить её в фон и открыть agent view за один шаг. В новой сессии без сообщений `/bg` просит вас сначала отправить сообщение, а `←` работает сразу. Сессия продолжает работать и появляется в виде строки рядом с теми, которые вы отправили.

В обычной сессии `claude` нажатие `←` на пустом промпте открывает agent view, а подсказка `←` в нижней строке сообщает о ваших фоновых сессиях:

* **Подсказка**: нижняя строка показывает `← for agents` в течение десяти секунд после открытия сессии. Нажатие `←` продолжает работать и после исчезновения подсказки
* **Количество ожидающих**: пока фоновые сессии ждут вашего ввода, в том же месте отображается их количество, например `← 2 agents`, или `← 99+ agents`, когда ждут более 99. Количество обновляется примерно каждые десять секунд, пока терминал в фокусе, и сразу же, когда фокус возвращается
* **Количество завершённых**: когда фоновые сессии успешно завершаются, пока ни одна не ждёт вашего ввода, нижняя строка ненадолго показывает, сколько из них завершилось, например `← 2 done` для двух

Количество ожидающих ненадолго меняет цвет, когда оно увеличивается или уменьшается, а также когда фоновая сессия успешно завершается. Если вы включите [`prefersReducedMotion`](https://code.claude.com/docs/ru/settings-reference#prefersreducedmotion), вы не увидите ни изменения цвета, ни количества `done`. В [режиме чтения с экрана](https://code.claude.com/docs/ru/accessibility.md) подсказка `←` и её счётчики скрыты.

### Открыть agent view по умолчанию

Чтобы `claude` без аргументов открывал agent view вместо нового диалога, включите настройку в `/config`.

**1. Включить настройку**

В обычной сессии `claude` запустите `/config` и включите **Open agents view by default**. Чтобы пропустить меню, задайте ключ [`defaultToAgentsView`](https://code.claude.com/docs/ru/settings-reference#defaulttoagentsview) напрямую:

```text theme={null}
/config defaultToAgentsView=true
```

**2. Запустить Claude Code**

Выйдите из сессии, затем запустите `claude` без аргументов:

```bash theme={null}
claude
```

Agent view открывается вместо нового диалога.

Чтобы запустить обычную сессию, пока настройка включена, передайте промпт: `claude "fix the login test"`. Чтобы отключить настройку, запустите `/config defaultToAgentsView=false` в обычной сессии или в сессии, к которой вы подключаетесь из agent view.

## Мониторинг сессий с помощью agent view

Запустите `claude agents`, чтобы открыть agent view. Он занимает весь терминал и перечисляет все сессии, сгруппированные по состоянию: закреплённые сессии и те, которым нужны вы, находятся вверху. Каждая строка показывает имя сессии, текущую активность и её возраст, отсчитываемый с момента создания сессии; возраст завершённой сессии фиксируется на продолжительности выполнения.

Имя окрашено в цвет, установленный с помощью [`/color`](https://code.claude.com/docs/ru/commands) в этой сессии, в том числе когда вы [отправляете сессию в фон](#from-inside-a-session) с помощью `←` или `/background`.

По умолчанию список показывает все запущенные вами фоновые сессии во всех ваших проектах. Сессия, работающая в одном репозитории, и другая — в другом worktree, обе появляются здесь, независимо от того, из какого каталога вы открыли agent view. Чтобы ограничить список одним проектом, передайте `--cwd`:

```bash theme={null}
claude agents --cwd ~/projects/my-app
```

Так показываются только сессии, запущенные в этом каталоге. В списке по-прежнему остаётся сессия, которая [переместилась в worktree](#how-file-edits-are-isolated) в `~/projects/my-app/.claude/worktrees/`.

Интерактивные сессии, открытые в других терминалах, не появляются, пока вы не [отправите их в фон](#from-inside-a-session). [Субагенты](https://code.claude.com/docs/ru/sub-agents.md) и [участники команды](https://code.claude.com/docs/ru/agent-teams.md), которых порождает сессия, не отображаются отдельными строками.

### Чтение состояния сессии

Каждая строка начинается со значка, цвет и анимация которого показывают состояние сессии:

| Состояние | Как выглядит значок | Что это означает |
| :- | :- | :- |
| Working | Анимированный | Claude активно запускает инструменты или генерирует ответ |
| Needs input | Жёлтый | Claude ждёт того, что можете предоставить только вы: ответа на вопрос, решения о разрешении или другого ответа, который можете дать только вы, например ответа на запрос [песочницы](https://code.claude.com/docs/ru/sandboxing.md) о разрешении сетевого хоста или на [запрос ввода](https://code.claude.com/docs/ru/mcp.md#respond-to-mcp-elicitation-requests) от MCP-сервера. Команда, которой нужен подключённый терминал, например `/install-github-app` или список настроек `/mcp`, [также удерживает здесь сессию без присмотра](#attach-to-a-session) |
| Idle | Приглушённый | Сессии нечего делать, и она готова к вашему следующему промпту |
| Completed | Зелёный | Задача успешно завершена |
| Failed | Красный | Задача завершилась с ошибкой |
| Stopped | Серый | Вы остановили сессию с помощью `Ctrl+X` или `claude stop`, [её процесс был завершён извне Claude Code](#the-supervisor-process) или [она завершилась, пока фоновая служба была выключена](#sessions-show-as-failed-after-shutdown) |

Кроме того, форма значка имеет собственное значение:

| Форма | Что это означает |
| :- | :- |
| `✻` или анимированный `✽` | Процесс сессии работает или сессии нужен ваш ввод |
| `∙` | Процесс завершился. Вы всё ещё можете просмотреть строку, а когда вы ответите или нажмёте `Enter`, Claude перезапустит его из сохранённого диалога |
| `✢` | Сессия [`/loop`](https://code.claude.com/docs/ru/scheduled-tasks), ожидающая между итерациями. Строка показывает количество запусков и обратный отсчёт |

Метка `#N` или `!N`, которая может появиться у правого края строки, — это ссылка на [pull request или merge request](#pull-request-status) сессии, а не часть значка состояния.

Пока agent view открыт, заголовок вкладки терминала показывает количество сессий, ожидающих ввода: `2 awaiting input · claude agents`, когда сессиям нужен ввод, или `claude agents`, когда не нужен.

Чтобы прочитать состояние сессий из скрипта или другой программы, используйте [`claude agents --json`](#read-session-state-from-a-script), а не файлы в `~/.claude/jobs/`.

Пока agent view открыт, Claude Code также отправляет уведомление через настроенный вами [канал уведомлений терминала](https://code.claude.com/docs/ru/terminal-config.md#get-a-terminal-bell-or-notification), когда локальной фоновой сессии начинает требоваться ваш ввод, когда она завершается или завершается с ошибкой. Сессии, работающие по расписанию, например сессии [`/loop`](https://code.claude.com/docs/ru/scheduled-tasks), уведомляют только тогда, когда им нужен ваш ввод. Уведомления используют ту же [настройку `preferredNotifChannel`](https://code.claude.com/docs/ru/settings-reference#preferrednotifchannel), что и остальной Claude Code, и запускают [хук `Notification`](https://code.claude.com/docs/ru/hooks#notification) с типом `agent_needs_input` или `agent_completed`.

Фоновым сессиям не нужен открытый терминал, чтобы продолжать работу. Их запускает отдельный [процесс супервизора](#the-supervisor-process), поэтому вы можете закрыть agent view, закрыть оболочку или запустить новую интерактивную сессию, а отправленная вами работа продолжит выполняться.

Состояние сессий сохраняется на диске при автообновлениях и перезапусках супервизора. Сессии также сохраняются, когда компьютер переходит в спящий режим. Их процессы возобновляются при пробуждении, и супервизор переподключается к ним, а не считает перерыв бездействием. Выключение компьютера по-прежнему останавливает работающие сессии; о том, как их восстановить, см. [Sessions show as failed or stopped after shutdown](#sessions-show-as-failed-after-shutdown).

Сессия, которая была в процессе ответа, когда компьютер перешёл в спящий режим, может после пробуждения не отвечать. Когда вы открываете переставшую отвечать сессию, супервизор перезапускает её процесс, и сессия продолжает прерванный ответ с того места, где остановилась.

### Сводки в строках

Однострочная сводка в каждой строке генерируется [моделью класса Haiku](https://code.claude.com/docs/ru/model-config.md), чтобы строка могла сообщить, что делает сессия, что ей нужно или что она сделала, без открытия транскрипта. Пока сессия активно работает, текст строки обновляется не чаще одного раза в 15 секунд на основе недавнего вывода самой сессии без отправки запроса к модели, а в конце каждого хода модель пишет свежую сводку.

Строка работающей сессии показывает то, что, по словам сессии, она делает, а строка заблокированной сессии — заданный ею вопрос. Во время долгого хода модель также переписывает сводку каждые несколько минут, чтобы в строке занятой сессии не оставалась устаревшая сводка. Текст сводки заполняет оставшуюся ширину строки; откройте [панель просмотра](#peek-and-reply), чтобы прочитать предложение, обрезанное краем терминала.

Когда список [сгруппирован по каталогам](#organize-the-list), сводка начинается с состояния сессии, выделенного цветом, например `Needs input · double jump or wall climb?`. При группировке по состоянию (по умолчанию) заголовок группы уже называет состояние, поэтому строка показывает только сводку.

#### Стоимость сводок в строках

Сводка в конце хода и каждая промежуточная переписка во время хода — это один короткий запрос через вашего обычного провайдера, тарифицируемый и обрабатываемый на тех же [условиях использования данных](https://code.claude.com/docs/ru/data-usage.md), что и сама сессия. У стороннего провайдера или шлюза сводки используют модель, заданную в [`ANTHROPIC_DEFAULT_HAIKU_MODEL`](https://code.claude.com/docs/ru/model-config#environment-variables). Если эта переменная не задана, используется модель вашего провайдера для фоновых задач: см. [Amazon Bedrock](https://code.claude.com/docs/ru/amazon-bedrock.md#4-pin-model-versions), [Google Cloud Agent Platform](https://code.claude.com/docs/ru/google-vertex-ai.md#5-pin-model-versions), [Microsoft Foundry](https://code.claude.com/docs/ru/microsoft-foundry.md#4-pin-model-versions) или ваш [шлюз](https://code.claude.com/docs/ru/llm-gateway-protocol.md#requests-and-defaults-by-connection-method).

### Статус pull request

Когда сессия [открывает pull request](#how-file-edits-are-isolated), Claude Code добавляет у правого края строки метку со ссылкой на pull request:

* Claude Code отображает метку как `#1234` для pull request и как `!1234` для merge request в GitLab.
* Claude Code выводит ссылку, даже если не может определить поддержку гиперссылок, например через SSH или tmux. Задайте [`FORCE_HYPERLINK=0`](https://code.claude.com/docs/ru/env-vars), чтобы отображать метку как обычный текст.
* После того как вы отправите сессии следующее сообщение, Claude Code сохраняет метку, пока строка снова показывает текущий прогресс.

Сессия, работающая над существующим pull request, связывается с ним так же. Способ, которым Claude Code находит pull request, зависит от команды, которую запускает Claude:

* Когда Claude редактирует, комментирует, закрывает pull request или помечает его как готовый с помощью `gh`, Claude Code связывает pull request, указанный в выводе самой команды. Команда `gh`, в захваченном выводе которой не указан pull request, не создаёт связь; типичный случай — `gh pr merge`, поскольку эта команда выводит результат только в интерактивный терминал.
* Когда Claude переключается на pull request с помощью `gh pr checkout` или выполняет push в ветку, Claude Code ищет ветку с помощью `gh pr view` и связывает её открытый pull request.
* Pull request не обязательно должен существовать в момент push: Claude Code повторяет поиск ветки после каждой из не более чем пяти последующих команд `git`, `gh`, `glab` или `curl`, запущенных в том же каталоге, поэтому pull request, созданный после push, включая созданный Claude через GitHub REST API, связывается, когда повторная попытка его находит.

Когда сессия связана более чем с одним pull request, метка вместо номера показывает количество, например `3 PRs`, окрашенное по тому открытому pull request, который больше всего требует внимания. Откройте [панель просмотра](#peek-and-reply), чтобы увидеть их все.

Номер pull request окрашивается в соответствии с его статусом:

| Цвет | Статус pull request |
| :- | :- |
| Жёлтый | Ожидает проверок или ревью либо проверки не пройдены |
| Зелёный | Проверки пройдены, и никакое ревью не блокирует |
| Фиолетовый | Слит |
| Серый | Черновик или закрыт |

Для задачи, результатом которой является pull request, смотрите результат по этой метке: проведите ревью и выполните слияние pull request, когда его номер станет зелёным.

### Просмотр и ответ

Нажмите `Space` на выбранной строке, чтобы открыть панель просмотра. Она открывается с предложением, которое в строке обрезается краем терминала, и то, какое это предложение, зависит от состояния сессии:

* Сессия, ожидающая вас: точный вопрос, который она задаёт, над полем ответа
* Завершённая сессия: её результат
* Работающая сессия: её полное предложение о статусе

Далее перечисляются все pull request, связанные с сессией. Для сессии, которая ожидает вас или работает в безопасном режиме, под ними появляется ещё одна строка:

* Строка вроде `waiting 3m`: как долго сессия ожидает вас. Возраст у правого края строки — другое число: он отсчитывается с момента запуска сессии
* `safe mode · customizations are off`: эта сессия работает с [отключёнными пользовательскими настройками](https://code.claude.com/docs/ru/debug-your-config.md#test-against-a-clean-configuration), потому что вы запустили её из оболочки командой `claude --bg --safe-mode`. Её можно оставить как есть. Чтобы продолжить диалог с включёнными пользовательскими настройками, выполните [`claude stop <id>`](#manage-sessions-from-the-shell), а затем [`claude --resume`](https://code.claude.com/docs/ru/sessions#resume-a-session), обе команды — в оболочке

В большинстве случаев панели просмотра достаточно, и открывать полный транскрипт не нужно.

Введите ответ на панели просмотра и нажмите `Enter`, чтобы отправить его этой сессии. Начните ответ с `!`, чтобы вместо этого отправить команду Bash. Что произойдёт с ответом, зависит от сессии и от того, что вы отправляете:

* Работающая сессия: `/model`, `/effort`, `/rename` и `/usage` выполняются сразу. Другие ответы попадают в [очередь сообщений](https://code.claude.com/docs/ru/interactive-mode.md#queue-messages-while-claude-works) сессии, не прерывая ответ, и вступают в силу [тогда же, когда и ввод из очереди](https://code.claude.com/docs/ru/interactive-mode.md#when-claude-code-sends-what-you-queued). Другие [команды](https://code.claude.com/docs/ru/commands.md) ждут окончания хода, даже те, которые выполняются сразу, если ввести их в промпте самой сессии
* Ответ, состоящий ровно из `/stop`: немедленно останавливает сессию, а не доставляется ей, независимо от того, работает сессия или ждёт вас
* [Shell-задача](#run-a-shell-command): ответ, включая `/stop`, передаётся в терминал команды как введённый текст

Когда сессия ожидает вас, способ ответа с панели просмотра зависит от того, чего она ждёт:

* Вопрос с предопределёнными вариантами: панель перечисляет варианты с номерами. При пустом поле ответа нажмите номер варианта, чтобы подставить его, а затем `Enter`, чтобы отправить, или введите свой собственный ответ
* Вопрос без предопределённых вариантов: введите ответ. Когда в пустом поле показан предлагаемый ответ, нажмите `Tab`, чтобы подставить его и отредактировать перед отправкой
* Запрос разрешения или другое диалоговое окно, например запрос [песочницы](https://code.claude.com/docs/ru/sandboxing.md) или [запрос на ввод](https://code.claude.com/docs/ru/mcp.md#respond-to-mcp-elicitation-requests) от MCP-сервера: ответ на него не отвечает. Ваш ответ ждёт в очереди. Чтобы ответить на диалоговое окно, подключитесь с помощью `→`

Когда хук [`PermissionRequest`](https://code.claude.com/docs/ru/hooks#permissionrequest) или [`PreToolUse`](https://code.claude.com/docs/ru/hooks#pretooluse) возвращает вывод, который Claude Code не может проверить для вызова, о котором спрашивает сессия, строка показывает событие хука и `hook output invalid:` с ошибкой проверки перед текстом ожидающего запроса. Если хук завершается с ошибкой иным образом, строка сообщает, что хук завершился с ошибкой. Сессия по-прежнему ждёт того же запроса.

Если ответ не удаётся доставить, сообщение об ошибке указывает, был ли он сохранён. Ответ с префиксом `!` или `/` никогда не сохраняется. Claude Code отправляет сохранённый ответ в качестве следующего промпта сессии при следующем перезапуске сессии; любой другой ответ отправьте снова.

Если [голосовая диктовка](https://code.claude.com/docs/ru/voice-dictation.md) включена в [режиме удержания](https://code.claude.com/docs/ru/voice-dictation.md#hold-to-record), удерживайте клавишу push-to-talk, пока фокус находится в поле ответа, чтобы продиктовать ответ вместо ввода. То же работает в поле отправки внизу agent view.

Используйте `↑` и `↓`, чтобы просматривать соседние сессии, не закрывая панель, или `→`, чтобы подключиться.

### Подключение к сессии

Нажмите `Enter` или `→` на выбранной строке, чтобы подключиться. Agent view сменяется полной интерактивной сессией. При подключении Claude публикует краткое резюме того, что произошло, пока вас не было.

Пока вы подключены, сессия ведёт себя как любая другая сессия Claude Code: [команды](https://code.claude.com/docs/ru/commands.md), сочетания клавиш и функции работают, за исключениями, описанными ниже.

Пока вы подключены, `/install-github-app` и список настроек [`/mcp`](https://code.claude.com/docs/ru/mcp) работают как обычно, поскольку человек за терминалом может завершить их диалоговые окна. Когда никто не подключён, эти команды не могут открыть свои диалоговые окна, поэтому сессия появляется в группе `Needs input` в agent view со строкой вроде `open this session to manage MCP servers`, и ответ в транскрипте сообщает то же самое. Подключитесь и запустите команду снова, чтобы продолжить; строка needs-input исчезает при подключении. `/mcp reconnect <server>`, `/mcp enable` и `/mcp disable` работают без подключения в любом случае.

Подключённые сессии всегда отображаются в [полноэкранном режиме](https://code.claude.com/docs/ru/fullscreen.md), независимо от вашей настройки `tui`, поскольку у фоновой сессии нет истории прокрутки терминала, в которую можно дописывать вывод. Прокручивайте с помощью `PgUp`, `PgDn` или колеса мыши и нажмите `Ctrl+O` для режима транскрипта. Встроенная прокрутка терминала и режим копирования tmux показывают только текущую видимую область, как при запуске любого полноэкранного приложения.

Подключённая сессия не [сообщает свой статус терминалу](https://code.claude.com/docs/ru/terminal-config.md#see-session-status-in-your-terminal).

Нажмите `←` в пустом промпте или выполните `/exit`, чтобы отключиться и вернуться в agent view, независимо от того, открыли ли вы сессию из agent view или с помощью `claude attach <id>` из оболочки.

`←` также отключает от сессии, пока открыта [панель `/btw`](https://code.claude.com/docs/ru/interactive-mode#side-questions-with-%2Fbtw). Требуется Claude Code v2.1.257 или новее. Побочный вопрос, ответ на который ещё формируется, продолжает выполняться, пока вас нет. При следующем подключении панель снова откроется с ним или с его ответом.

В Windows, если нажать `←` в течение примерно половины секунды после подключения, Claude Code показывает `Ambiguous ←, press again to detach`, поскольку в этот промежуток терминал может повторно доставить нажатие, сделанное до подключения. Нажмите `←` ещё раз, чтобы отключиться.

`Ctrl+Z` также отключает от сессии, но возвращает туда, откуда вы начали: в agent view, если вы подключились оттуда, или в оболочку, если вы выполнили `claude attach`. Используйте `Ctrl+Z`, когда фокус находится в диалоговом окне, которое не реагирует на `←`.

`Ctrl+C` при подключении сохраняет стандартное поведение прерывания: отменяет выполняющийся ответ или shell-команду `!`, а не отключает. Двойное нажатие `Ctrl+C` в пустом промпте отключает от сессии.

Отключение никогда не останавливает фоновую сессию: `←`, `Ctrl+Z`, `/exit`, а также двойное `Ctrl+C` или двойное `Ctrl+D` оставляют её работающей. Если вы отключитесь, пока `/loop` ожидает следующей итерации, цикл продолжит работать, и эта итерация начнётся по расписанию без вас. Чтобы остановить цикл перед отключением, см. [Stop a loop](https://code.claude.com/docs/ru/scheduled-tasks.md#stop-a-loop). Чтобы завершить сессию изнутри, выполните `/stop`.

#### Переключение сессий без выхода из терминала

В сессии, работающей на переднем плане, то есть запущенной вами в терминале, а не подключённой из agent view, нажатие `←` в пустом промпте отправляет её в фон и открывает agent view с выбранной строкой этой сессии, так что вы можете переключаться между сессиями, не выходя из терминала. То же одиночное нажатие отключает от подключённой сессии.

Если нажать `←` сразу после удаления последнего символа промпта или перемещения по истории промптов, Claude Code просит подтверждения: первое нажатие показывает `Press ← again to open agents` или, в подключённой сессии, `Press ← again to go back to agents`, а второе нажатие выполняет переключение.

После того как вы отправите сессию в фон с помощью `←`:

* Нажмите `Enter`, чтобы снова открыть диалог.
* Нажмите `Esc`, чтобы отменить переключение и вернуться к диалогу. Если `Esc` показывает `Still starting — try again in a moment`, фоновая сессия ещё не готова, поэтому нажмите `Esc` ещё раз чуть позже.
* Нажмите `Ctrl+C` дважды, чтобы выйти в оболочку.

Если Claude Code не может снова открыть диалог, он завершает работу и выводит команду `claude --resume`, которая его возобновляет.

[Список задач Claude](https://code.claude.com/docs/ru/interactive-mode.md#task-list) переходит в фоновую сессию вместе с диалогом, поэтому чек-лист остаётся нетронутым, когда вы возвращаетесь к этой строке.

Строка, из которой вы нажали `←`, также сохраняет жирное, неприглушённое имя после того, как вы переместите выделение клавишами со стрелками или мышью, так что вы видите, из какой сессии пришли.

Если в момент нажатия `←` выполняется инструмент, Claude Code ждёт его завершения, прежде чем отправить сессию в фон, и Claude продолжает ответ в фоновой сессии. Нажмите `←` ещё раз, чтобы отправить в фон немедленно, не дожидаясь. Если выполняющуюся фоновую работу нельзя перенести в фоновую сессию, Claude Code сначала показывает диалоговое окно `Background this session?`, как и при [`/background`](#from-inside-a-session).

Примерно через десять секунд Claude Code отправляет сессию в фон, не дожидаясь дольше, за исключением, например, следующих случаев:

* **Субагенты переднего плана всё ещё выполняются**: Claude Code продолжает ожидание, чтобы работа [субагентов переднего плана](https://code.claude.com/docs/ru/sub-agents.md#run-subagents-in-foreground-or-background), запущенных Claude, была сохранена, и показывает `Still backgrounding after the current tool`. Нажмите `←` ещё раз, чтобы перевести работу в фоновый режим без ожидания; при этом эти субагенты будут перезапущены с самого начала.
* **Запрос разрешения или вопрос ожидает вашего ответа**: пока ожидает запрос разрешения или вопрос, заданный Claude, Claude Code продолжает ждать и показывает `Still backgrounding after the current tool — a question is waiting for your answer.` Если ваш ответ позволяет ходу продолжиться, например **Yes** в запросе разрешения, Claude Code отправляет сессию в фон, когда текущий инструмент завершит работу.
* **Вы вводите текст в поле ввода промпта**: Claude Code отменяет переключение, потому что неотправленный текст остаётся в поле ввода вашего терминала и не перейдёт в фоновую сессию. Он показывает `Backgrounding cancelled — you have unsent text in the input. Send it or clear it, then press ← again.` Claude продолжает работать на переднем плане.
* **Вы останавливаете ход**: Claude Code отменяет переключение и показывает `Backgrounding cancelled — the turn was stopped.` Например, ход останавливается, когда вы [прерываете Claude с помощью `Esc`](https://code.claude.com/docs/ru/interactive-mode#general-controls) или выбираете **No** [без комментария](https://code.claude.com/docs/ru/permissions.md#add-a-comment-when-you-answer-a-permission-prompt) в запросе разрешения из основного диалога либо нажимаете `Esc` на вопросе, который Claude задаёт там. Нажмите `←` ещё раз, чтобы отправить сессию в фон.
* **Сообщение из очереди нельзя перенести**: сообщения, которые вы [поставили в очередь, пока Claude работал](https://code.claude.com/docs/ru/interactive-mode.md#queue-messages-while-claude-works), переходят в фоновую сессию вместе с диалогом. Если какое-либо из них перенести нельзя, сессия остаётся на переднем плане, и Claude Code показывает уведомление, например `Cannot open agents — 1 queued message can't move to the background. Press ← again once Claude has read it.`

Когда Claude Code отправляет сессию в фон — примерно через десять секунд или после того, как вы снова нажмёте `←`, — он останавливает shell-команду, которую Claude всё ещё выполняет на переднем плане. Claude Code не показывает для этой команды диалоговое окно `Background this session?`. В фоновой сессии у Claude нет записи о том, что команда была запущена, поэтому Claude может выполнить её снова. Чтобы команда продолжала работать при переносе сессии, нажмите `Ctrl+B`, чтобы [превратить её в фоновую команду](https://code.claude.com/docs/ru/interactive-mode.md#background-bash-commands), пока Claude Code ещё ждёт.

Нажатие `←` создаёт строку сессии, даже если в диалоге ещё нет сообщений, поэтому `→` по-прежнему возвращает к нему.

Это сочетание клавиш для сессий переднего плана можно отключить с помощью настройки [`leftArrowOpensAgents`](https://code.claude.com/docs/ru/settings-reference#leftarrowopensagents) в `/config`.

##### Промпты, отправленные в момент переноса сессии в фон

Если вы вводите промпт или shell-команду `!` в тот момент, когда сессия переходит в фон, он останавливается или остаётся неотправленным:

* **Отправлено в момент закрытия диалога**: ответ или команда останавливается, когда диалог закрывается и открывается agent view
* **В этот момент ещё ожидаются [хуки](https://code.claude.com/docs/ru/hooks.md)**: промпт не отправляется, и на экране об этом ничего не сообщается. Это относится и к промпту, введённому, пока ещё выполнялись [хуки `SessionStart`](https://code.claude.com/docs/ru/hooks#sessionstart)

В обоих случаях введённый вами текст сохраняется в [истории промптов](https://code.claude.com/docs/ru/interactive-mode.md#command-history). Чтобы отправить его снова, откройте сессию, отправленную в фон, и нажмите `↑` в её промпте, чтобы вернуть текст.

### Организация списка

Agent view группирует сессии так, чтобы те, которым нужен ввод, были вверху: `Ready for review` и `Needs input` располагаются над `Working` и `Completed`. Эти названия групп не соответствуют [состояниям](#read-session-state) выше один к одному: сессия переходит в `Ready for review`, когда у неё есть открытый pull request, которому нужно ревью или у которого не пройдены проверки, а `Completed` объединяет завершённые, завершившиеся с ошибкой и остановленные сессии.

Нажмите `Ctrl+S`, чтобы вместо этого группировать по каталогам. Ваш выбор сохраняется между запусками.

Внутри группы:

* Нажмите `Ctrl+T`, чтобы закрепить сессию вверху и [сохранять её процесс работающим](#the-supervisor-process) во время бездействия
* Нажмите `Shift+↑` или `Shift+↓`, чтобы изменить порядок сессий
* Нажмите `Ctrl+R`, чтобы переименовать сессию
* Нажмите `Enter` на заголовке группы, чтобы свернуть её, кроме случаев, когда активен [фильтр](#filter-sessions): тогда все группы остаются развёрнутыми
* Нажмите `Ctrl+X`, чтобы остановить сессию, и ещё раз `Ctrl+X` в течение двух секунд, чтобы удалить её из списка, или `Esc`, чтобы закрыть подтверждение без удаления. Второе нажатие удаляет сессию, даже если попытка остановки не удалась, например потому что [фоновая служба не отвечает](#agent-view-says-the-background-service-did-not-respond). В этом случае подтверждение остаётся активным ещё две секунды, и удаление само завершает процесс сессии

Нажмите `Ctrl+X` на заголовке группы, чтобы после подтверждения удалить все сессии в этой группе, кроме тех, которые Claude Code [отказывается удалять](#delete-a-session-after-claude-code-refuses). О том, что происходит с worktree каждой сессии, см. [What deleting a session removes](#what-deleting-a-session-removes). Транскрипт диалога остаётся на вашем локальном компьютере и доступен через `claude --resume`.

Завершённые сессии, которые не помещаются на экране, сворачиваются в строку `… N more`. Группа `Completed` занимает вертикальное пространство, оставшееся после активных групп. В невысоком терминале заголовок сжимается до одной сводной строки, чтобы сессии, которые работают или которым нужен ввод, оставались видимыми.

#### Возврат прошлой сессии

Чтобы вернуть сессию, введите `/resume` в [поле отправки](#dispatch-an-agent-from-agent-view). Откроется окно выбора с прошлыми сессиями репозитория, из которого вы открыли agent view, начиная с самых новых, включая сессии, удалённые из списка. Сессии, у которых уже есть строка, не отображаются. Нажмите `Enter`, чтобы возобновить выбранную сессию как фоновую, и она снова появится в списке строкой.

`/resume` завершается с ошибкой `isn't available in agent view`, когда:

* `/resume` указывает id или поисковый запрос
* представление ограничено с помощью `--cwd`
* представление запущено с [`--safe-mode`](https://code.claude.com/docs/ru/cli-reference#cli-flags)
* представление открыто с флагом, например `--permission-mode` или `--settings`

Если вы ввели что-либо после `/resume`, введите команду заново без этого. Если вы использовали один из этих флагов, запустите `claude agents` в оболочке без него, а затем введите `/resume` без аргументов.

### Фильтрация сессий

Начните ввод в поле отправки с одного из этих фильтров, чтобы сужать список по мере ввода:

| Фильтр | Показывает |
| :- | :- |
| `a:<name>` | Сессии, в которых работает указанный агент |
| `s:<state>` | Сессии в указанном состоянии, например `s:working`, или под указанным заголовком группы, например `s:ready` для `Ready for review`. `s:blocked` показывает всё, что ждёт вас |
| `n:<text>` | Сессии, имя или первый промпт которых содержит текст, например `n:login`. Требуется Claude Code v2.1.287 или новее |
| `o:<text>` | Сессии, результат которых содержит текст, например `o:merged`. `o:` без текста показывает все сессии, сообщившие результат |
| Номер pull request или merge request, например `#1234`, или его URL | Сессия, работающая над этим pull request или merge request |
| Любой другой URL | Сессия, первый промпт которой содержал этот URL |

Чтобы объединить фильтры, начните с `a:`, `s:`, `n:` или `o:` и добавьте другие через пробел. Список показывает сессии, соответствующие всем фильтрам. Например, `s:blocked a:reviewer` показывает сессии `reviewer`, ожидающие вас.

Пока фильтр активен, свёрнутые вами группы разворачиваются, чтобы показать совпадения, и совпадение выбирается, так что нажатие `Enter` открывает его. Очистите поле ввода, чтобы снять фильтр, и эти группы снова свернутся.

## Отправка новых агентов

Вы можете отправлять новые фоновые сессии из agent view, отправлять существующую интерактивную сессию или её копию в фон, а также запускать сессию прямо из оболочки.

### Отправка агента из agent view

Введите промпт в поле ввода внизу agent view и нажмите `Enter`, чтобы запустить новую фоновую сессию. Сессия автоматически получает имя на основе промпта; позже её можно переименовать с помощью `Ctrl+R`.

Автоматическое имя — это короткая метка, которую пишет [модель класса Haiku](https://code.claude.com/docs/ru/model-config.md). Имя, которое сессия получает позже, также отображается в её строке, включая [сгенерированное название](https://code.claude.com/docs/ru/sessions.md#name-your-sessions), которое сессия получает, когда вы [принимаете план](https://code.claude.com/docs/ru/permission-modes.md#review-and-approve-a-plan) в этой сессии.

Вставьте изображение в промпт, чтобы приложить к задаче снимок экрана или диаграмму.

Вставленный текст длиннее 800 символов или более трёх строк сворачивается в заполнитель `[Pasted text #N]`, чтобы поле ввода оставалось однострочным; при отправке передаётся полный текст. Чтобы просмотреть или отредактировать свёрнутый текст перед отправкой, вставьте тот же текст ещё раз, и заполнитель развернётся обратно в поле ввода.

С помощью префиксов или упоминаний в промпте можно управлять тем, как запускается сессия:

| Ввод | Результат |
| :- | :- |
| `<agent-name> <prompt>` | Если первое слово совпадает с именем пользовательского [субагента](https://code.claude.com/docs/ru/sub-agents.md), этот субагент запускается как основной агент сессии с конфигурацией из его frontmatter |
| `@<agent-name>` | Упомяните пользовательского субагента в любом месте промпта, чтобы запустить его как основного агента |
| `@<repo>` | Упомяните репозиторий, чтобы запустить сессию в нём. О том, какие репозитории отображаются в списке, см. в разделе [Отправка в конкретный каталог](#dispatch-to-a-specific-directory) |
| `/<command>` | Предлагает [скиллы](https://code.claude.com/docs/ru/skills.md) и [команды](https://code.claude.com/docs/ru/commands.md) для отправки в качестве промпта |
| `! <command>` | Запускает shell-команду как фоновое задание вместо сессии Claude. Задание отображается строкой, к которой можно подключиться, за которой можно наблюдать и от которой можно отключиться |
| `#<number>` или URL pull request или merge request | Если над этим pull request или merge request уже работает какая-либо сессия, Claude Code выделяет её строку вместо отправки новой сессии |

Небольшой набор команд выполняется в самом agent view, а не отправляется:

* `/exit` и `/quit` закрывают agent view
* `/logout` выполняет выход из учётной записи
* `/model`, `/effort` и `/fast` задают [то, с чем запускаются сессии, которые вы отправите далее](#set-the-model-effort-and-fast-mode). Для `/effort` и `/fast` требуется Claude Code v2.1.299 или новее.
* `/login` открывает диалоговое окно входа, чтобы вы могли войти снова без подключения к сессии
* `/resume` без аргументов или его псевдоним `/continue` открывает список прошлых сессий репозитория, чтобы [вернуть одну из них](#bring-back-a-past-session) как фоновую сессию

Скиллы, ваши собственные команды и встроенные команды, разворачивающиеся в промпт, такие как `/init`, отправляются в новую фоновую сессию как её первый промпт. Подсказка `isn't available in agent view` означает, что введённая вами встроенная команда не была выполнена. Чтобы выполнить её, [подключитесь к сессии](#attach-to-a-session) и введите её там. Всё, что вы ввели, остаётся в поле ввода рядом с подсказкой, чтобы вы могли это отредактировать.

Если оформить повторяющуюся задачу как [скилл](https://code.claude.com/docs/ru/skills.md), вы сможете многократно запускать один и тот же рабочий процесс из agent view, не вводя промпт заново.

Когда одно и то же `@name` совпадает и с субагентом, и с соседним репозиторием, приоритет имеет субагент. Совпадение по первому слову без `@` тоже действует, поэтому промпт, который случайно начинается с имени одного из ваших субагентов, отправляет этого субагента, а не трактует слово как обычный текст. Используйте форму с `@`, если хотите указать субагента явно, или начните промпт с другого слова, чтобы избежать совпадения.

#### Отправка в конкретный каталог

Новая сессия запускается в каталоге, из которого вы открыли agent view. Чтобы выбрать другой каталог, используйте любой из этих способов:

* Откройте `claude agents` в этом каталоге.
* Откройте `claude agents` в родительском каталоге и упомяните дочерний репозиторий с помощью `@<repo>` в промпте. При вводе `@` отображаются следующие цели:

  * Git-репозитории на один уровень ниже каталога запуска
  * Зарегистрированные [git worktree](https://code.claude.com/docs/ru/worktrees.md) репозитория, из которого вы запустили agent view, расположенные внутри его дерева каталогов, например те, которые Claude создаёт в `.claude/worktrees/`; они помечены извлечённой в них веткой. Worktree, добавленные за пределами репозитория, например с помощью `git worktree add ../feature`, не отображаются
  * Любой каталог, для которого в списке уже есть сессия

  Каталог, имя которого содержит пробел, не отображается.
* Из оболочки перейдите в каталог с помощью `cd` и выполните `claude --bg "<prompt>"`.

Когда agent view сгруппирован по каталогам, промпт отправляется в каталог выделенной строки, поэтому можно выбрать группу и отправить в неё сессию, не вводя путь заново.

### Отправка сессии или её копии в фон

Две команды переносят работу из текущей сессии в фон: `/background` отправляет туда текущий диалог и освобождает терминал, а `/fork` отправляет копию, пока вы продолжаете работать на месте.

#### Отправка сессии в фон

Выполните `/background` или его псевдоним `/bg`, чтобы перенести текущий диалог в фоновую сессию. Передайте промпт, например `/bg run the test suite and fix any failures`, чтобы сначала дать ещё одну инструкцию. Если Claude отвечает в момент выполнения `/bg`, ответ продолжится в фоновой сессии.

Если вы выходите из сессии, пока выполняются некоторые виды фоновой работы, например субагенты или рабочие процессы, диалоговое окно `Background work is running` предупреждает, что эта работа будет остановлена. Выберите `Move to background and exit`, чтобы отправить сессию в фон так же, как это делает `/background`, и вернуться в оболочку. Этот вариант не отображается, если agent view [отключён](#turn-off-agent-view).

Если у фоновой сессии в списке уже есть такое же имя, как у диалога, Claude Code добавляет номер к имени новой строки, например `my-session (2)`, а имя существующей строки не меняет. Чтобы переименовать новую строку, выделите её в agent view и нажмите `Ctrl+R`.

#### Копирование сессии с помощью /fork

Выполните `/fork`, чтобы скопировать текущий диалог в новую фоновую сессию, пока исходная продолжает работать. Копия начинается со всего содержимого диалога до этого момента; где именно запускается копия, описано в пунктах ниже. В неё также переносятся модель, режим разрешений, уровень effort и все каталоги или разрешения «больше не спрашивать», добавленные во время сессии. Копия отображается в agent view отдельной строкой.

После ответвления два диалога независимы: ничто из того, что делает копия, само по себе не попадает в исходный диалог, хотя в сессиях, где включён [обмен сообщениями между сессиями](https://code.claude.com/docs/ru/cross-session-messaging.md), Claude в любой из сессий может явно отправить сообщение другой.

Когда [agent view отключён](#turn-off-agent-view), `/fork` вместо копирования сессии запускает [ответвлённого субагента](https://code.claude.com/docs/ru/sub-agents.md#fork-the-current-conversation).

##### Промпт для копии и открытие её сессии

Передайте промпт, например `/fork open a draft pull request with the work so far`, и копия сразу начнёт над ним работать. Без промпта копия ждёт первой инструкции: выделите её строку в `claude agents` и нажмите `Space`, чтобы отправить инструкцию, или выполните `claude attach <id>`. Пока копия ждёт, в выделенной строке отображается `space to send it a prompt`.

Подтверждение `/fork` — это одна строка, показывающая состояние копии, например `session running`, имя её строки в agent view и её ID сессии для `claude attach`. Щёлкните имя, чтобы переключиться на копию: текущая сессия уходит в фон, как при нажатии `←`, а agent view открывает сессию копии.

##### Где запускается копия

Кроме случаев, когда копия [редактирует файлы на месте](#how-file-edits-are-isolated), Claude Code указывает ей создать собственный worktree перед внесением изменений в код. Вне Git-репозитория такую инструкцию получает только копия, вынесенная из worktree, созданного хуком; без [хука `WorktreeCreate`](https://code.claude.com/docs/ru/hooks#worktreecreate) копия редактирует файлы на месте. Копии, вынесенной из вашего worktree, также указывается никогда не редактировать файлы в этом worktree, не запускать в нём команды и не входить в него, независимо от настройки изоляции.

Место запуска копии зависит от того, где выполняется текущая сессия:

* Как и любая отправленная сессия, копия [переходит в собственный worktree перед редактированием файлов](#how-file-edits-are-isolated). В этом случае в подтверждении не указывается, где запускается копия.
* Если ваша сессия перешла в свой связанный [worktree](https://code.claude.com/docs/ru/worktrees.md) уже после запуска, копия начинает работу там, где сессия находилась до перехода, и, если только она не [редактирует файлы на месте](#how-file-edits-are-isolated), вносит изменения в код в собственном worktree. Если в вашем worktree извлечена ветка, эта инструкция также указывает копии, чья задача основана на вашей работе, создать новую ветку на основе вашей, поскольку ваша ветка остаётся извлечённой в вашем worktree. Подтверждение заканчивается на `runs in the origin tree`.
* Если вы запустили сессию внутри связанного worktree репозитория, у которого есть основное рабочее дерево, копия запускается в этом основном рабочем дереве с тем же правилом о собственном worktree, но без инструкции о ветке. Подтверждение и здесь заканчивается на `runs in the origin tree`.
* У сессии, запущенной внутри worktree в структуре с bare-репозиторием, нет основного рабочего дерева, куда можно вернуться, поэтому копия остаётся на месте, а подтверждение заканчивается на `edits this checkout`. То же примечание появляется, когда изоляция в worktree [отключена](#how-file-edits-are-isolated) в сессии, которая не находится внутри связанного worktree, поскольку тогда копия редактирует открытые вами файлы.

##### Сессии, которые нельзя скопировать

Сессии, запущенные с флагами запуска, которые копия не унаследовала бы, например с заменённым системным промптом или списком разрешённых инструментов `--tools`, скопировать нельзя; Claude Code сообщает об этом, а не создаёт неполную копию. Сессия, отправленная из agent view, копируется как обычно: копия запускается с тем же [определением агента](https://code.claude.com/docs/ru/sub-agents.md) и теми же добавленными инструкциями, что и исходная сессия.

#### Что переносится при отправке в фон

При отправке сессии в фон каждый вид выполняющейся фоновой работы либо переносится в фоновую сессию, либо продолжается, только когда Claude перезапустит его там, либо останавливается:

* **Переносится**: запущенные фоновые shell-команды, субагенты в фоне и запланированные задачи, созданные с помощью [`/loop`](https://code.claude.com/docs/ru/scheduled-tasks), продолжают выполняться в фоновой сессии. Субагент переходит вместе со всем, что он запустил, поэтому он переносится, только если вся эта работа тоже может перейти.
* **Продолжается, только когда Claude перезапустит его**: выполняющийся [динамический рабочий процесс](https://code.claude.com/docs/ru/workflows.md). Если рабочий процесс не продолжился к моменту, когда вы проверяете фоновую сессию, [попросите Claude перезапустить его](#dynamic-workflows-when-you-background).
* **Останавливается**: работа, которую нельзя перенести в фоновую сессию, например запущенный [монитор](https://code.claude.com/docs/ru/tools-reference.md#monitor-tool). Если такая работа выполняется, Claude Code показывает диалоговое окно `Background this session?`, чтобы вы подтвердили её остановку. Субагент в фоне, которому принадлежит монитор, останавливается вместе с монитором.

Уже находясь в фоне, сессия может запускать новых субагентов, мониторы и фоновые команды, и они продолжают работать при последующих отключениях и повторных подключениях.

Флаги конфигурации из исходного запуска переносятся в фоновую сессию, поэтому её MCP-серверы, настройки и резервная модель продолжают действовать:

* `--mcp-config` и `--strict-mcp-config`
* `--settings`
* `--setting-sources`
* `--add-dir`
* `--plugin-dir`
* `--fallback-model`
* `--allow-dangerously-skip-permissions`

Каталоги, добавленные во время сессии с помощью [`/add-dir`](https://code.claude.com/docs/ru/permissions#additional-directories-grant-file-access-not-configuration), тоже переносятся. Перенос `--allow-dangerously-skip-permissions` сохраняет доступность `bypassPermissions` в фоновой сессии, но не даёт ничего нового: режим по-прежнему требует, чтобы ваше [согласие с предупреждением об обходе разрешений](https://code.claude.com/docs/ru/permission-modes.md#skip-all-checks-with-bypasspermissions-mode) уже было зафиксировано.

##### Динамические рабочие процессы при отправке в фон

Если [динамический рабочий процесс](https://code.claude.com/docs/ru/workflows.md) не продолжился после того, как вы отправили его сессию в фон, попросите Claude [перезапустить рабочий процесс](https://code.claude.com/docs/ru/workflows.md#resume-after-you-leave-the-session). Запуск продолжается, только когда Claude перезапускает его в фоновой сессии, и Claude Code может сначала попросить вас подтвердить этот перезапуск. В диалоге сессии отображается уведомление о том, что рабочий процесс `could not be resumed`.

Когда Claude перезапускает рабочий процесс, все его субагенты, которые ещё выполнялись в момент отправки сессии в фон, начинают работу заново и снова расходуют свои токены. Если вы нажмёте `←` или выполните `/background`, пока какие-либо из них ещё выполняются, в диалоговом окне `Background this session?` указывается, сколько их. Чтобы сначала дать им завершиться, выберите `Stay`.

### Отправка агента из оболочки

Передайте `--bg` или его полную форму `--background`, чтобы запустить сессию, которая сразу уходит в фон:

```bash theme={null}
claude --bg "investigate the flaky SettingsChangeDetector test"
```

Промпт передаётся позиционным аргументом, а не значением `-p`. Claude Code отклоняет сочетание `--bg` с `-p` или `--print` ещё до создания сессии, поскольку `--print` никогда не запускает интерактивную сессию, к которой подключается `claude agents`.

Если вы запускаете `claude --bg` из терминала в каталоге, которому вы ещё не [доверяете](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust), сначала появляется диалоговое окно доверия рабочему пространству, и сессия запускается после вашего согласия. Если вы откажетесь, Claude Code завершит работу, не запуская сессию. Там, где диалоговое окно появиться не может, например в скрипте, команда вместо этого завершается с ошибкой [`Workspace not trusted`](https://code.claude.com/docs/ru/errors#workspace-not-trusted-when-dispatching-a-background-session).

Чтобы запустить определённого вами [субагента](https://code.claude.com/docs/ru/sub-agents.md), например `code-reviewer`, как основного агента сессии, используйте `--bg` вместе с `--agent`:

```bash theme={null}
claude --agent code-reviewer --bg "address review comments on PR 1234"
```

Если имя не совпадает ни с одним из ваших субагентов, запуск не удаётся: Claude Code выводит предупреждение `no agent named` и всё равно сообщает, что сессия отправлена в фон, но сессия сразу завершается с ошибкой `--agent '<name>' not found`.

Когда фоновая сессия позже возобновляется или перезапускается, Claude Code восстанавливает агента и его ограничения на инструменты; о его системном промпте см. в разделе [Флаги системного промпта в возобновлённых диалогах](https://code.claude.com/docs/ru/cli-reference.md#system-prompt-flags-in-resumed-conversations). Сначала агент ищется в собственном каталоге сессии, при условии что вы [доверяете этому рабочему пространству](https://code.claude.com/docs/ru/permissions.md#project-allow-rules-and-workspace-trust), поэтому агент уровня проекта загружается, даже если сессия возобновлена из другого каталога. Если агента больше не существует, сессия продолжается со стандартными инструментами, а её транскрипт открывается [предупреждением с именем агента](https://code.claude.com/docs/ru/errors.md#session-agent-no-longer-available).

Чтобы продолжить существующий диалог в фоне, передайте его полный ID сессии с помощью `--resume`:

```bash theme={null}
claude --resume 1f0e2c9a-6d0b-4c11-9f39-2a77c1d4e8b5 --bg "pick up where you left off and finish the migration"
```

В Claude Code v2.1.257 или новее Claude Code либо продолжает эту сессию под тем же ID, либо запускает копию под новым ID и выводит строку `note:` с объяснением, почему не удалось продолжить на месте. Когда сессия продолжается на месте, `claude agents` показывает для неё одну строку.

Если вы сочетаете `--bg` с `--continue`, с `--resume` без аргумента или с `--resume` с именем или путём к файлу, Claude Code всегда запускает такую копию. Добавьте `--fork-session`, чтобы намеренно запустить копию без примечания.

Передайте `--name`, чтобы задать отображаемое имя сессии в agent view вместо автоматически сгенерированного:

```bash theme={null}
claude --bg --name "flaky-test-fix" "investigate the flaky SettingsChangeDetector test"
```

После отправки в фон Claude выводит короткий ID сессии и команды для управления ею. Если служба, в которой работают фоновые сессии, ещё не запущена, `--bg` может сначала вывести `Starting background service…` над этим выводом. Если вы передали `--name`, имя отображается после короткого ID:

```text theme={null}
backgrounded · 7c5dcf5d · flaky-test-fix
  claude agents             list sessions
  claude attach 7c5dcf5d    open in this terminal
  claude logs 7c5dcf5d      show recent output
  claude stop 7c5dcf5d      stop this session
```

#### Промпты, содержащие `--bg`

Промпт, в котором упоминается `--bg` или `--background`, доставляется в том виде, в каком он введён; то же относится к ответу `--bg`, который вы отправляете фоновой сессии. Например, эта команда запускает одну фоновую сессию, а второй `--bg` является частью её промпта:

```bash theme={null}
claude --bg "find out why --bg sessions are slow to start on this machine"
```

Claude Code считает аргумент целиком флагом только там, где может стоять флаг: до любого отдельного разделителя `--` и не там, где другой флаг ожидает своё значение. Ставьте флаг первым, как в `claude --bg "<prompt>"`.

Там, где позиция неоднозначна, например после серии объединённых коротких флагов, Claude Code ничего не запускает. Вместо этого он завершает работу с ошибкой [`Couldn't tell whether --bg is a flag or text here`](https://code.claude.com/docs/ru/errors#couldnt-tell-whether-bg-is-a-flag-or-text).

#### Запуск shell-команды

Чтобы запустить shell-команду как фоновое задание вместо сессии Claude, передайте `--exec`. В следующем примере `pytest -x` запускается как фоновое задание:

```bash theme={null}
claude --bg --exec 'pytest -x'
```

В agent view такое же задание можно отправить, введя `!` первым символом в поле ввода: `!` отображается как префикс, всё после него — это команда, а `Enter` запускает задание.

Команда выполняется как задание на базе PTY и отображается строкой в agent view, где статусом служит последняя строка вывода. Shell-задание выполняет команду вместо Claude, поэтому модель не вызывается, а вывод не отправляется ни в одну сессию.

Чтобы увидеть вывод, подключитесь к строке, нажмите `Space` для просмотра без подключения или выполните `claude logs <id>` из оболочки. Захваченный вывод хранится в памяти и не записывается на диск. Строка и её вывод автоматически удаляются примерно через пять минут после завершения команды, поэтому, если вам нужен результат, прочитайте его до этого.

### Как изолируются правки файлов

Когда вы отправляете фоновую сессию из agent view или запускаете её с помощью `claude --bg`, сессия запускается в вашем рабочем каталоге. Перед редактированием файлов Claude переносит сессию в изолированный [git worktree](https://code.claude.com/docs/ru/worktrees.md) в `.claude/worktrees/`, поэтому параллельные сессии могут читать одну и ту же рабочую копию, но каждая пишет в свою. Как только сессия оказывается в своём worktree, Claude Code [обеспечивает изоляцию в worktree](https://code.claude.com/docs/ru/worktrees.md#how-claude-code-enforces-isolation) для сессии и для всех порождаемых ею субагентов.

Claude не использует worktree, когда:

* Вы [отправили уже открытую сессию в фон](#from-inside-a-session) с помощью `←` или `/background`. Эта сессия продолжает редактировать файлы там, где уже работала
* Сессия уже находится внутри связанного git worktree, независимо от того, создал ли его Claude в `.claude/worktrees/` или вы создали его в другом месте с помощью `git worktree add`
* Файл, который редактирует Claude, находится внутри связанного git worktree, например созданного сессией или её субагентом с помощью `git worktree add`
* Рабочий каталог не является Git-репозиторием и [хук `WorktreeCreate`](https://code.claude.com/docs/ru/hooks#worktreecreate) не настроен
* Запись выполняется за пределами рабочего каталога

Чтобы отключить изоляцию в worktree для репозитория, где git worktree неудобны, задайте для [`worktree.bgIsolation`](https://code.claude.com/docs/ru/settings-reference#worktree-bgisolation) значение `"none"`. Тогда фоновые сессии редактируют вашу рабочую копию напрямую, не переходя сначала в worktree. Добавьте настройку в файл `.claude/settings.json` проекта:

```json theme={null}
{
  "worktree": {
    "bgIsolation": "none"
  }
}
```

Вне Git-репозитория сессии пишут непосредственно в рабочий каталог и не изолированы друг от друга, поэтому не отправляйте параллельные сессии, редактирующие одни и те же файлы. Если вы используете другую систему контроля версий, настройте [хук `WorktreeCreate`](https://code.claude.com/docs/ru/worktrees#non-git-version-control), и Claude будет изолировать правки так же, как для Git.

Если хук завершается с ошибкой в каталоге, который не является Git-репозиторием, Claude пропускает изоляцию для этого каталога и редактирует рабочий каталог на месте. Внутри Git-репозитория сессия, которую Claude переносит в worktree перед редактированием, не может использовать инструменты `Edit`, `Write` или `NotebookEdit` в общей рабочей копии, пока этот перенос не произойдёт.

Чтобы узнать путь к worktree сессии, подключитесь к ней и проверьте её рабочий каталог.

[Субагент](https://code.claude.com/docs/ru/sub-agents.md), порождённый фоновой сессией, наследует рабочий каталог сессии. Когда сессия находится в worktree, правки файлов субагента попадают в этот worktree, а не в вашу рабочую копию. Чтобы вместо этого выделить субагенту отдельный worktree, задайте [`isolation: worktree`](https://code.claude.com/docs/ru/sub-agents#supported-frontmatter-fields) в его frontmatter или передайте `isolation: "worktree"` при его запуске.

Когда фоновая сессия внесла изменения в код в worktree, в который перешёл Claude, Claude Code указывает Claude сохранить работу перед завершением, чтобы она уцелела, если вы удалите сессию и её worktree:

* **Коммит и push**: Claude делает коммит, не спрашивая, и выполняет push ветки, если у репозитория есть удалённый репозиторий.
* **Черновой pull request**: Claude открывает его, когда этого требует задача, и в строке появляется [метка `#N`](#pull-request-status).
* **Никогда**: push в `main` или `master`, принудительный push и слияние.
* **Ваши инструкции по Git имеют приоритет**: если в задаче, `CLAUDE.md` или [памяти](https://code.claude.com/docs/ru/memory.md) сказано, что коммиты или push вы выполняете сами, Claude оставляет работу с Git вам.

Сессия, которая редактирует рабочую копию, не изолированную ею самой, по-прежнему спрашивает перед коммитом или переключением веток. Это относится к случаям, когда для изоляции задано `"none"`, когда перенос в worktree не удался или когда сессия запустилась внутри уже существовавшего worktree.

Какой бы ни была задача, Claude завершает работу отчётом о том, что он сделал и где находится результат: путь, ветка, pull request или сам ответ.

#### Что удаляется при удалении сессии

Удалите сессию двойным нажатием `Ctrl+X` в [agent view](#organize-the-list) или с помощью [`claude rm`](#manage-sessions-from-the-shell). Сессия исчезает из списка, если только Claude Code не [откажется её удалять](#delete-a-session-after-claude-code-refuses). Её транскрипт остаётся на вашем компьютере и доступен через `claude --resume`.

Что происходит с worktree, который Claude создал для сессии:

* Agent view удаляет его вместе с незафиксированными изменениями, поэтому сначала сделайте коммит того, что хотите сохранить.
* `claude rm` сохраняет его вместе со строкой сессии, если в нём есть незафиксированные изменения.

Одна из причин, по которой Claude Code отказывается удалять сессию, — это [коммиты без push в её worktree](https://code.claude.com/docs/ru/errors.md#worktree-has-commits-that-are-not-pushed-anywhere). Чтобы сохранить эти коммиты, выполните их push перед удалением сессии.

Некоторые worktree остаются на диске независимо от того, используете ли вы agent view или `claude rm`:

* Если вы сами создали worktree и запустили сессию внутри него, worktree остаётся на диске, чтобы вы сами решили, сохранить его или удалить.
* Если в каталоге worktree, который Claude создал внутри вашего репозитория, больше нет файла `.git`, каталог остаётся на диске, чтобы вы удалили его сами. Ветка worktree остаётся в репозитории, поэтому коммиты в этой ветке сохраняются.

##### Удаление сессии после отказа Claude Code

Когда Claude Code отказывается удалять сессию из-за её worktree, следуйте показанному сообщению. Если в сообщении указаны коммиты без push, см. раздел [Worktree has commits that are not pushed anywhere](https://code.claude.com/docs/ru/errors.md#worktree-has-commits-that-are-not-pushed-anywhere).

##### Устранение сообщения `Worktree not removed`

Сообщение `Worktree not removed` означает, что Claude Code или ваш [хук `WorktreeRemove`](https://code.claude.com/docs/ru/hooks#worktreeremove) не завершил удаление worktree сессии. Выполните push всех коммитов и скопируйте все файлы, которые хотите сохранить, затем следуйте сообщению.

##### Устранение сообщения `files that weren't checked against a repository`

Это сообщение от `claude rm` означает, что в каталоге worktree остаются файлы, а сам каталог не находится ни в одном Git-репозитории или управляется [хуком `WorktreeCreate`](https://code.claude.com/docs/ru/hooks#worktreecreate). Скопируйте все файлы, которые хотите сохранить, затем выполните действие для вашего случая:

| Ваш случай | Что делать |
| :- | :- |
| Каталогом не управляет ни один хук `WorktreeCreate` | Чтобы отбросить файлы, дважды нажмите `Ctrl+X` на строке сессии в agent view. Или удалите каталог самостоятельно, затем снова выполните `claude rm <id>` |
| Каталогом управляет хук `WorktreeCreate`, и у вас есть [хук `WorktreeRemove`](https://code.claude.com/docs/ru/hooks#worktreeremove) | Чтобы попытаться удалить каталог с помощью вашего хука, дважды нажмите `Ctrl+X` на строке сессии в agent view. Или удалите каталог самостоятельно, затем снова выполните `claude rm <id>` |
| Каталогом управляет хук `WorktreeCreate`, и у вас нет хука `WorktreeRemove` | Удалите каталог самостоятельно, затем снова выполните `claude rm <id>` |

### Выбор модели, уровня effort и быстрого режима

В agent view введите `/model`, `/effort` или `/fast` в [поле ввода для отправки](#dispatch-an-agent-from-agent-view) и нажмите `Enter`, и сессии, которые вы отправите после этого, запустятся с заданными значениями. Ваш выбор действует в этом окне agent view и не сохраняется в файл настроек. Для `/effort` и `/fast` требуется Claude Code v2.1.299 или новее; то же относится к `/model`, введённой без аргументов.

Укажите значение после команды или введите одну команду, чтобы выбрать значение из списка:

* **Модель**: `/model <name>`, например `/model opus`
* **[Уровень effort](https://code.claude.com/docs/ru/model-config.md#adjust-effort-level)**: `/effort` с `low`, `medium`, `high`, `xhigh` или `max`, например `/effort high`. Чтобы запускать сессии в [ultracode](https://code.claude.com/docs/ru/workflows.md#let-claude-decide-with-ultracode), вместо этого откройте agent view из оболочки с помощью [`claude agents --effort ultracode`](#dispatch-defaults); поле ввода для отправки не принимает `/effort ultracode`
* **Быстрый режим**: `/fast on` или `/fast off`. Сессия запускается в быстром режиме, только если быстрый режим [вам доступен](https://code.claude.com/docs/ru/fast-mode.md#requirements) и её модель поддерживает быстрый режим. На модели, которая его не поддерживает, сессия запускается с выключенным быстрым режимом, поэтому сначала с помощью `/model` выберите одну из [моделей, поддерживающих быстрый режим](https://code.claude.com/docs/ru/fast-mode.md). Получат ли новые сессии быстрый режим, подтверждает подсказка под полем ввода, а не заголовок.

Чтобы отменить выбор, укажите значение `default`, например `/effort default`.

В следующем примере одна сессия отправляется на Opus, а следующая — на Sonnet:

```text theme={null}
/model opus
refactor auth
/model sonnet
run the test suite
```

Каждая фоновая сессия может работать на своей модели. Чтобы переопределить модель для одной сессии:

* Из оболочки передайте `--model` вместе с `claude --bg`.
* Подключитесь к работающей сессии и выполните `/model`, чтобы переключиться. Выбор в меню или введённая команда `/model <name>` сохраняется как модель по умолчанию для новых сессий, если только вы не нажмёте `s` в меню, чтобы переключиться только для этой сессии. Переключение только для сессии сохраняется, если процесс сессии запускается заново.
* Отправьте [субагента](https://code.claude.com/docs/ru/sub-agents.md), в frontmatter которого задано поле `model`, начав промпт с его имени или упомянув `@name`. Пока действует выбор `/model` в поле ввода для отправки, поле `model` субагента не используется, поэтому введите там `/model default`. Если вы запустили agent view с [`claude agents --model`](#dispatch-defaults), модель субагента тоже не используется, поэтому выполните `claude agents` в оболочке без `--model`.

### Режим разрешений, модель и effort

Фоновая сессия получает настройки, провайдера, режим разрешений, модель и уровень effort в зависимости от того, где и как вы её отправили. В подразделах ниже описан каждый источник, а также то, что сохраняется, когда супервизор перезапускает сессию.

#### Настройки и провайдер

Фоновая сессия читает свои [настройки](https://code.claude.com/docs/ru/settings.md) из каталога, в котором она работает, так же как если бы вы запустили там `claude` с [перенесёнными в неё флагами конфигурации](#what-carries-over-when-you-background). Сюда входят [значения `env`](https://code.claude.com/docs/ru/settings-reference#env) в настройках проекта, поэтому заданная там `ANTHROPIC_MODEL` или переменная провайдера применяется ко всем фоновым сессиям в этом каталоге.

Фоновая сессия также работает с `PATH` той оболочки, из которой вы её отправили, поэтому запускаемые ею команды находят те же инструменты, что и ваш терминал. Она также сохраняет выбор облачного провайдера этой оболочки, например `CLAUDE_CODE_USE_BEDROCK` или `CLAUDE_CODE_USE_VERTEX`, вместе с псевдонимами `ANTHROPIC_DEFAULT_*_MODEL` и любым экспортированным там переопределением [`CLAUDE_CODE_EXTRA_BODY`](https://code.claude.com/docs/ru/env-vars).

#### LLM-шлюз

Если вы направляете Claude Code через [LLM-шлюз](https://code.claude.com/docs/ru/llm-gateway), поместите переменные шлюза в блок `env` файла настроек, а не экспортируйте их в оболочке, и фоновые сессии прочитают их вместе с остальными настройками. В разделе [Задание в файле настроек](https://code.claude.com/docs/ru/llm-gateway-connect.md#set-in-a-settings-file) показан этот блок и указано, какой файл настроек использовать для учётных данных.

Если же вы экспортируете `ANTHROPIC_BASE_URL` шлюза только в оболочке, он попадает в фоновую сессию вместе с экспортированными с ним `ANTHROPIC_CUSTOM_HEADERS` и учётными данными, только если [супервизор](#the-supervisor-process) сам был запущен из оболочки, экспортировавшей тот же шлюз, и только в следующих случаях:

* Вы отправляете собственную сессию в фон с помощью `←` или `/background`
* Вы отправляете сессию в каталог, в котором находитесь
* Вы пробуждаете остановленную сессию в каталоге, в котором находитесь, подключаясь к ней или отвечая ей
* Вы перезапускаете сессию в каталоге, в котором находитесь, с помощью [`claude respawn`](#manage-sessions-from-the-shell)

Claude Code передаёт и шлюз, стоящий перед облачным провайдером. Если оболочка, из которой вы отправляете сессию, выбирает провайдера и экспортирует эндпоинт его шлюза вместе с флагом обхода аутентификации, Claude Code передаёт эту пару из эндпоинта и флага в сессию на тех же условиях, что и `ANTHROPIC_BASE_URL`, вместе с `ANTHROPIC_CUSTOM_HEADERS`. Например, экспортируйте `CLAUDE_CODE_USE_VERTEX=1` вместе с `ANTHROPIC_VERTEX_BASE_URL` и `CLAUDE_CODE_SKIP_VERTEX_AUTH=1`, и Claude Code передаст этот эндпоинт и флаг.

Claude Code применяет переданный шлюз только к работающему процессу этой сессии и никогда не записывает его на диск.

#### Режим разрешений

* **Отправлена в фон с помощью `/bg` или `←`**: Claude Code сохраняет [режим разрешений](https://code.claude.com/docs/ru/permissions.md), в котором находилась сессия, поэтому сессия, переключённая вами на `acceptEdits` или `auto`, остаётся в нём после отключения
* **Отправлена из `claude agents`, запущенного в оболочке, или с помощью `claude --bg`**: новая сессия запускается так же, как новая сессия `claude` в этом каталоге, если только вы не отправили её из agent view, открытого со [значениями по умолчанию для отправки](#dispatch-defaults). Порядок приведён в разделе [В каком режиме разрешений запускается сессия](https://code.claude.com/docs/ru/permission-modes.md#which-mode-a-session-starts-in)

Для сессии, отправленной из agent view, открытого с помощью `←`, Claude Code берёт режим разрешений из первого подходящего источника:

1. [`permissions.defaultMode`](https://code.claude.com/docs/ru/settings-reference#permissions-defaultmode) целевого каталога. `auto` и `bypassPermissions` [вступают в силу только из управляемых настроек, файла `--settings` или `~/.claude/settings.json`](https://code.claude.com/docs/ru/settings-reference#permissions-defaultmode). Claude Code отклоняет `defaultMode` из файлов `.claude/settings.json` или `.claude/settings.local.json` проекта, если он выбирает более разрешительный режим, чем тот, в котором находилась исходная сессия.
2. Режим разрешений исходной сессии.

   Если эта сессия находилась в режиме `bypassPermissions`, новая сессия может вместо этого запуститься в режиме Manual с уведомлением `Bypass permissions was requested at launch and ignored`. Это происходит, когда ваше согласие с предупреждением об обходе разрешений зафиксировано только в `.claude/settings.local.json` или в файле `--settings`. Продолжите работу в режиме Manual или [добавьте это согласие в `~/.claude/settings.json`](https://code.claude.com/docs/ru/permission-modes#bypass-permissions-ignored-in-a-background-session).

Когда Claude Code отклоняет режим источника как слишком разрешительный, решение принимает следующий источник в списке. Например, если вы отправляете сессию из сессии в режиме планирования в каталог, в зафиксированных в репозитории настройках которого запрошен `acceptEdits`, новая сессия запускается в режиме планирования. Если перенести этот `defaultMode` в `~/.claude/settings.json`, он применяется независимо от режима разрешений исходной сессии.

По степени разрешительности режимы идут так: plan, затем Manual и `dontAsk`, затем `acceptEdits` и auto, каждый из которых считается более разрешительным, чем другой, затем `bypassPermissions`.

#### Значения по умолчанию для отправки

Чтобы задать значения по умолчанию для всех сессий, отправляемых из agent view, передайте при его открытии любой из флагов `--permission-mode`, `--model`, `--effort` или `--agent`:

```bash theme={null}
claude agents --permission-mode plan --model opus --effort high
```

`--effort` здесь принимает те же значения, что и [флаг `--effort` верхнего уровня](https://code.claude.com/docs/ru/cli-reference#cli-flags), включая `ultracode`.

`--agent` задаёт [субагента](https://code.claude.com/docs/ru/sub-agents.md), который используется, когда промпт отправки не называет субагента ни через `@name`, ни первым словом. По умолчанию используется [настройка `agent`](https://code.claude.com/docs/ru/settings-reference#agent), если она задана, иначе — встроенный универсальный агент `claude`. Указание субагента в поле ввода переопределяет оба варианта.

`claude agents` также принимает `--dangerously-skip-permissions` как сокращение для `--permission-mode bypassPermissions`, а `--allow-dangerously-skip-permissions` — чтобы сделать `bypassPermissions` доступным в цикле `Shift+Tab` каждой отправленной сессии, не запуская её в этом режиме. Оба флага соответствуют [флагам CLI верхнего уровня](https://code.claude.com/docs/ru/cli-reference.md).

Передайте `--restricted`, чтобы каждая сессия, отправленная из этого представления, запускалась в [ограниченном режиме](https://code.claude.com/docs/ru/cli-reference.md#cli-flags), как если бы она была запущена с флагом `--restricted` верхнего уровня. Требуется Claude Code v2.1.248 или новее.

Действующие значения по умолчанию отображаются в нижней строке под полем ввода.

Фоновой сессии, запущенной в режиме `bypassPermissions`, требуется уже зафиксированное [согласие с предупреждением об обходе разрешений](https://code.claude.com/docs/ru/permission-modes.md#skip-all-checks-with-bypasspermissions-mode), поскольку этот режим позволяет сессии, за которой вы не наблюдаете, действовать без подтверждения. Передача `--dangerously-skip-permissions` или `--permission-mode bypassPermissions` в `claude agents` показывает то же предупреждение, если вы не принимали его ранее, и после согласия `bypassPermissions` применяется к сессиям, которые вы запускаете из этого представления. Передача `--allow-dangerously-skip-permissions` тоже показывает это предупреждение, и после согласия `bypassPermissions` становится доступным в цикле `Shift+Tab` этих сессий, но они в нём не запускаются.

#### Что сохраняется при перезапусках

Выбранные для фоновой сессии режим разрешений, модель и уровень effort, а также [переносимые ею флаги конфигурации](#what-carries-over-when-you-background) сохраняются, когда супервизор позже [останавливает и перезапускает](#the-supervisor-process) её процесс. Модель или уровень effort, изменённые во время сессии с помощью `/model` или `/effort`, тоже сохраняются.

Если сессия взяла уровень effort из ваших настроек, а не из `--effort` или `/effort`, Claude Code заново читает настройки при каждом запуске процесса для этой сессии. После того как вы отредактируете сохранённый уровень effort в `settings.json`, изменение применяется к сессиям, которые вы отправляете в фон с помощью `←` или `/bg`, и к их последующим перезапускам. Сохранённый уровень effort — это ключ [`effortLevel`](https://code.claude.com/docs/ru/settings-reference#effortlevel) или запись [`modelSettings`](https://code.claude.com/docs/ru/settings-reference#modelsettings).

Claude Code также сохраняет при таком перезапуске имя, заданное с помощью [`/rename`](https://code.claude.com/docs/ru/commands) или `Ctrl+R`, поэтому вы по-прежнему можете выполнить [`claude --resume <name>`](https://code.claude.com/docs/ru/sessions#name-your-sessions), чтобы перейти к сессии.

Промпт, отложенный с помощью [`Ctrl+S`](https://code.claude.com/docs/ru/interactive-mode#general-controls) во время подключения, тоже сохраняется вместе с сессией. Снова откройте сессию после того, как её процесс был остановлен или перезапущен, и нажмите `Ctrl+S`, чтобы восстановить отложенный текст. Вставленное содержимое в отложенном промпте после перезапуска не сохраняется.

### Настройки, плагины и MCP-серверы

Agent view принимает те же флаги конфигурации, что и `claude`, для загрузки настроек, плагинов, MCP-серверов и дополнительных каталогов. Agent view применяет `--settings`, `--setting-sources` и `--plugin-dir` к себе и передаёт все флаги конфигурации в сессии, которые вы из него отправляете, поэтому плагин или MCP-сервер, загруженный таким образом, доступен в этих сессиях.

| Флаг | Результат |
| :- | :- |
| [`--settings <file-or-json>`](https://code.claude.com/docs/ru/settings) | Переопределяет настройки для agent view и отправленных сессий |
| [`--setting-sources <sources>`](https://code.claude.com/docs/ru/cli-reference#cli-flags) | Загружает только указанные источники настроек в agent view и отправленных сессиях |
| [`--add-dir <path>`](https://code.claude.com/docs/ru/permissions#additional-directories-grant-file-access-not-configuration) | Предоставляет доступ к файлам в дополнительном каталоге |
| [`--plugin-dir <path>`](https://code.claude.com/docs/ru/plugins/create#load-a-directory-or-archive-for-one-session) | Загружает плагин из локального каталога |
| [`--mcp-config <file-or-json>`](https://code.claude.com/docs/ru/mcp) | Загружает MCP-серверы из файла конфигурации или строки JSON |
| `--strict-mcp-config` | Пропускает MCP-серверы, настроенные в таких местах, как `.mcp.json`, и загружает те, которые вы передаёте с помощью `--mcp-config`. О том, как действует этот флаг при наличии управляемого файла MCP, см. в разделе [Исключительный контроль с помощью managed-mcp.json](https://code.claude.com/docs/ru/managed-mcp.md#exclusive-control-with-managed-mcp-json) |

Повторяйте `--add-dir`, `--plugin-dir` или `--mcp-config` для каждого значения. `claude agents` не поддерживает форму со значениями через пробел, например `--add-dir a b c`.

`--settings`, `--setting-sources` и `--plugin-dir` можно указывать до или после `agents`. `--add-dir` и `--mcp-config` указывайте после `agents`: если поставить любой из них перед `agents`, [`claude agents --json`](#manage-sessions-from-the-shell) завершится с ошибкой `unknown option`.

В следующем примере agent view открывается с переопределением настроек и одним дополнительным каталогом:

```bash theme={null}
claude agents --settings ./ci-settings.json --add-dir ../shared-lib
```

`--settings` принимает путь к файлу или встроенную строку JSON. Путь к файлу должен указывать на существующий файл; в противном случае Claude Code завершает работу с ошибкой `Settings file not found`.

## Управление сессиями из оболочки

Каждая фоновая сессия имеет короткий ID, который вы можете использовать из оболочки. ID выводится при запуске сессии с помощью `claude --bg`, и ID каждой сессии — это имя её каталога в `~/.claude/jobs/`. Эти команды полезны для написания скриптов или когда вы не хотите открывать agent view.

| Команда | Назначение |
| :- | :- |
| `claude agents` | Открыть agent view |
| `claude agents --cwd <path>` | Открыть agent view с областью действия сессий, запущенных в `<path>` |
| `claude agents --json` | Вывести сессии в виде массива JSON и выйти. См. [Вывод сессий в виде JSON](#list-sessions-as-json) |
| `claude attach <id\|name>` | Подключиться к сессии в этом терминале |
| `claude logs <id\|name>` | Вывести последний вывод сессии |
| `claude stop <id>` | Остановить сессию. Также принимает `claude kill` |
| `claude respawn <id>` | Перезапустить сессию, работающую или остановленную, например, чтобы подхватить обновленный бинарный файл Claude Code. Сессия, у которой есть сохраненный диалог, возобновляет его |
| `claude respawn --all` | Перезапустить каждую работающую сессию, например, чтобы перевести все сессии на обновленный бинарный файл Claude Code одновременно |
| `claude rm <id>` | Удалить сессию из списка вместе с worktree, созданным Claude для неё, когда его безопасно удалить. Если Claude Code отказывается удалять сессию из-за её worktree, см. [Удаление сессии после отказа Claude Code](#delete-a-session-after-claude-code-refuses). Транскрипт диалога остается на вашем локальном компьютере и остается доступным через `claude --resume` |
| `claude rm <id> --discard-unpushed <commit>@<worktree-id>` | Повторить попытку удалить сессию и отбросить её worktree после того, как Claude Code отказал из-за неотправленных коммитов. Скопируйте команду из сообщения `claude rm`, которое её предлагает; см. [Worktree has commits that are not pushed anywhere](https://code.claude.com/docs/ru/errors.md#worktree-has-commits-that-are-not-pushed-anywhere). Требуется v2.1.260 или позже |
| `claude rm <id> --force-remove-worktree <worktree-id>` | Повторить попытку удалить сессию и всё равно удалить каталог её worktree после того, как Claude Code отказал, потому что не смог удалить worktree. Скопируйте команду из сообщения `claude rm`, которое её предлагает; см. [Устранение сообщения `Worktree not removed`](#resolve-a-worktree-not-removed-message). Требуется v2.1.268 или позже |
| `claude daemon status` | Вывести состояние [supervisor](#the-supervisor-process), версию, каталог сокета и количество рабочих процессов |
| `claude daemon logs` | Следить за файлом лога supervisor, [`~/.claude/daemon.log`](#where-state-is-stored), выводя новые строки по мере их появления, пока вы не нажмете `Ctrl+C` |
| `claude daemon stop --any` | Остановить процесс supervisor и фоновые сессии, которые он размещает. Передайте `--keep-workers`, чтобы оставить фоновые сессии работающими, чтобы [следующий supervisor](#the-supervisor-process) переподключился к ним. Следующий `claude agents` или `claude --bg` запускает новый supervisor |

`claude attach` и `claude logs` могут принимать часть имени сессии вместо ID, например `claude logs "auth refactor"`. `claude attach` открывает сессию по имени, только пока её процесс работает, поэтому, чтобы перезапустить остановленную сессию, передайте вместо имени ID. Для передачи имени требуется Claude Code v2.1.290 или позже.

### Вывод сессий в виде JSON

`claude agents --json` выводит активные сессии в виде массива JSON и выходит: каждую живую сессию, плюс фоновые сессии, которые всё ещё работают или заблокированы, даже если их процесс завершился. Добавьте `--all`, чтобы также включить завершенные фоновые сессии, и `--cwd <path>`, чтобы ограничить список сессиями, запущенными в этом каталоге.

Каждая запись описывает одну сессию:

| Поле | Присутствует | Описание |
| :- | :- | :- |
| `cwd`, `kind`, `startedAt` | Всегда | Рабочий каталог, `interactive` или `background`, и время начала в миллисекундах Unix |
| `id` | Фоновые сессии | Короткий ID, используемый с `claude attach`, `claude logs` и `claude stop` |
| `state` | Фоновые сессии | Одно из `working`, `blocked`, `done`, `failed` или `stopped`. См. [Чтение состояния сессии из скрипта](#read-session-state-from-a-script) для объяснения каждого значения |
| `pid`, `status` | Пока процесс активен | ID процесса и одно из `busy`, `waiting` или `idle` |
| `waitingFor` | Когда `status` равен `waiting` | На чём заблокирована сессия: `permission prompt` для подтверждения, `input needed` для вопроса от Claude или запроса ввода от MCP-сервера, `sandbox request`, `worker request` или `dialog open` |
| `sessionId`, `name` | Когда установлены | `sessionId` — это полный UUID сессии, используемый с [`claude --resume`](https://code.claude.com/docs/ru/sessions). Имя интерактивной сессии — это её [имя отображения по умолчанию](https://code.claude.com/docs/ru/sessions.md#name-your-sessions) до тех пор, пока вы не назовете сессию или не примете в ней план |

### Чтение состояния сессии из скрипта

`claude agents --json` — это поддерживаемый способ чтения состояния сессии извне Claude Code, например из строки состояния, планировщика или другой сессии Claude, которая контролирует фоновую работу. Опрашивайте `claude agents --json --all`, который продолжает выводить сессии, чей процесс завершился, и читайте `state`, `status` и `waitingFor` каждой записи.

| `state` | Что это означает |
| :- | :- |
| `working` | Выполняется ход, или сессия находится между шагами работы, которую она выполняет самостоятельно, такой как итерация [`/loop`](https://code.claude.com/docs/ru/scheduled-tasks) или ожидание CI. `status` показывает, занят ли её процесс прямо сейчас |
| `blocked` | Сессия ждет вас: вопрос, который она задала, решение о разрешении или песочнице, ошибка, которую можете устранить только вы, например истекший вход, или её первый промпт, если вы запустили её без него. Когда ожидание — это открытый промпт в живом процессе, `waitingFor` его называет |
| `done` | Последний ход завершил то, что вы просили, и сессия готова к вашему следующему промпту, независимо от того, активен ли её процесс |
| `failed`, `stopped` | Задача завершилась с ошибкой или сессия была остановлена |

Сессия, которая завершила свой ход и ждет вашей следующей инструкции, имеет состояние `done`, а не `blocked`. `blocked` всегда означает, что сессии нужно что-то от вас, прежде чем она сможет продолжить.

Файлы в `~/.claude/jobs/<id>/` не являются стабильным интерфейсом. Значения, которые сессия или другая программа записывает в `state`, `detail`, `tempo` или `needs`, заменяются при следующем обновлении.

Если вы хотите, чтобы сессия сообщала о прогрессе своими словами, попросите её написать свой собственный файл, например в `$CLAUDE_JOB_DIR/tmp`, вместо редактирования `state.json`.

## Как размещаются фоновые сессии

Claude Code рассматривает каждую сессию, указанную в представлении агента, как фоновую сессию, независимо от того, подключены ли вы к ней в данный момент. В отличие от этого, сессия, запущенная путём прямого запуска `claude`, привязана к этому терминалу и завершается при его закрытии, если вы не [отправите её в фон](#from-inside-a-session).

Чтобы проверить, какой тип сессии вы используете, запустите [`/status`](https://code.claude.com/docs/ru/commands). Строка `Session kind` показывает `background job · attached` или `background job · unattended` в фоновой сессии, в зависимости от того, подключён ли терминал, и `interactive` в любой другой сессии.

### Процесс супервизора

Супервизор — это фоновая служба, которая запускает ваши фоновые сессии, чтобы они продолжали работать после закрытия представления агента или вашего терминала. Claude Code запускает его в первый раз, когда вы отправляете сессию в фон или открываете представление агента, и вам не нужно управлять им самостоятельно.

Каждая сессия — это собственный процесс Claude Code под супервизором, и то, что происходит с этим процессом, зависит от состояния сессии:

* **Работает, приостановлена на запросе разрешения или другом диалоговом окне, или подключена**: процесс продолжает работать. Работающий субагент, рабочий процесс или монитор считается работой, как и ожидающая [запланированная задача в рамках сессии](https://code.claude.com/docs/ru/scheduled-tasks.md), например пробуждение `/loop`.
* **Завершена или ожидает вашего следующего сообщения, и не подключена примерно час**: супервизор останавливает процесс для освобождения ресурсов. Сессия, которая завершила свой ход, задав вам вопрос, считается ожидающей вашего следующего сообщения. Диалог остаётся на диске, и в следующий раз, когда вы подключитесь или ответите, сессия возобновляется с того места, где она остановилась. Закрепите сессию с помощью `Ctrl+T`, чтобы её процесс продолжал работать.
* **Неожиданно завершилась, пока супервизор работает**: супервизор перезапускает процесс. Завершение сессии, которую вы отправили в фон самостоятельно с помощью `←` или `/background`, например с помощью `kill`, отмечает её как остановленную вместо перезапуска. Для сессий, которые завершились при выключении, см. [Sessions show as failed or stopped after shutdown](#sessions-show-as-failed-after-shutdown).
* **После автоматического обновления**: супервизор перезапускает себя на новую версию и переносит неактивные сессии в фоновом режиме. Сессии, которые работают, ожидают вас или подключены, не прерываются.
* **Сам супервизор останавливается**, например потому, что его процесс был завершён извне Claude Code: в macOS и Linux ваши сессии останавливаются, если к ним примерно в течение минуты не подключится новый супервизор. Чтобы запустить его, выполните `claude agents` в своей оболочке. Если эта минута прошла, см. [Сохранение работы сессий после остановки супервизора](#keep-sessions-running-after-the-supervisor-stops).

Когда процесс сессии останавливается или перезапускается, фоновые команды оболочки и фоновые субагенты, которые Claude запустил в ней, переносятся в её следующий процесс. Динамический рабочий процесс [продолжается, только если Claude перезапустит его](#dynamic-workflows-when-you-background). Работающие мониторы и команды оболочки, которые запустил субагент, останавливаются вместе с процессом. Если вы удалите сессию, всё, что она перенесла, остановится. Чтобы вместо этого останавливать всё это вместе с процессом, установите [`CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF`](https://code.claude.com/docs/ru/env-vars#variables) в значение `1`.

Супервизор и его сессии аутентифицируются с теми же сохранёнными учётными данными, что и ваши интерактивные сессии. О том, какие настройки и переменные оболочки доходят до сессии, включая `PATH`, см. [Settings and provider](#settings-and-provider). Об эндпоинтах шлюза см. [LLM gateway](#llm-gateway).

#### Сохранение работы сессий после остановки супервизора

Если представление агента при выходе выводит это уведомление, значит, ни один [супервизор](#the-supervisor-process) не запущен:

```text theme={null}
Background sessions still running will stop in about a minute. Run 'claude agents' to keep them.
```

Запустите `claude agents` в своей оболочке в течение этой минуты, чтобы запустить новый супервизор и сохранить работу ваших сессий.

Если минута истечёт раньше, сессии остановятся, но их сохранённые диалоги останутся на диске. Чтобы перезапустить сессию из сохранённого диалога, [подключитесь](#attach-to-a-session) к ней или [ответьте](#peek-and-reply) в ней, как описано в разделе [Sessions show as failed or stopped after shutdown](#sessions-show-as-failed-after-shutdown).

### Где хранится состояние

Состояние сессии хранится в каталоге конфигурации Claude Code. Если вы установили [`CLAUDE_CONFIG_DIR`](https://code.claude.com/docs/ru/env-vars), супервизор использует этот каталог вместо `~/.claude` и запускается как отдельный экземпляр со своими собственными сессиями.

| Путь | Содержимое |
| :- | :- |
| `~/.claude/daemon.log` | Лог супервизора |
| `~/.claude/daemon/roster.json` | Список работающих фоновых сессий, используется для переподключения после перезапуска |
| `~/.claude/jobs/<id>/state.json` | Состояние каждой сессии, показанное в представлении агента. Читайте его через [`claude agents --json`](#read-session-state-from-a-script) вместо анализа файла |
| `~/.claude/jobs/<id>/tmp/` | Каталог временных файлов для каждой сессии. Вызовы Claude `Write` и `Edit` здесь не запрашивают разрешения. Удаляется при удалении сессии |

Для каждой фоновой сессии переменная окружения `CLAUDE_JOB_DIR` установлена в её каталог `~/.claude/jobs/<id>`, поэтому команды оболочки, которые запускает сессия, могут записывать временные файлы в `$CLAUDE_JOB_DIR/tmp` без конфликтов с параллельными сессиями.

Чтобы проверить это состояние без прямого чтения файлов, запустите `claude daemon status`. Команда сообщает, доступен ли супервизор, его идентификатор процесса и версию, каталог сокета и сколько фоновых сессий активны.

Команда также предупреждает, когда работающий супервизор находится на другой версии, чем `claude`, который вы вызвали, что происходит после обновления, на которое супервизор ещё не перезапустился. Предупреждение показывает обе версии и предлагает вам запустить `claude daemon stop --any`, чтобы перейти на новую версию.

### Отключение представления агента

Чтобы полностью отключить фоновых агентов и представление агента, установите [настройку](https://code.claude.com/docs/ru/settings.md) `disableAgentView` в значение `true` или установите переменную окружения `CLAUDE_CODE_DISABLE_AGENT_VIEW`. Администраторы могут применить это через [управляемые настройки](https://code.claude.com/docs/ru/managed-settings.md).

## Устранение неполадок

### `claude agents` выводит список субагентов вместо открытия представления агентов

Если `claude agents` выводит количество, за которым следует список ваших настроенных субагентов, а затем завершает работу, представление агентов недоступно в вашей среде. Запустите `claude update`, чтобы установить последнюю версию.

Если представление агентов по-прежнему не открывается после обновления, проверьте, было ли оно [отключено](#turn-off-agent-view) настройкой или переменной окружения.

### Представление агентов открывается без сессий

До отправки вашей первой сессии представление агентов вместо списка сессий показывает пустые заголовки разделов с описанием под каждым, а также однострочное пояснение над полем ввода. Введите промпт в поле ввода внизу и нажмите `Enter`, чтобы отправить вашу первую сессию.

### При переводе в фоновый режим показывается диалоговое окно `Background this session?`

Когда вы нажимаете `←`, чтобы перевести сессию в фоновый режим, диалоговое окно `Background this session?` означает, что в сессии выполняется фоновая работа, которая будет остановлена или прервана:

* **Работа, которую нельзя перенести**: в сессии есть работа, которую нельзя перенести в фоновую сессию, например работающий [монитор](https://code.claude.com/docs/ru/tools-reference.md#monitor-tool). Диалоговое окно называет фоновую работу, которую Claude Code остановит, и отдельно указывает количество задач, которые будут перенесены.
* **Workflow с работающими субагентами**: у [динамического workflow](https://code.claude.com/docs/ru/workflows.md) всё ещё работают субагенты. Если вы всё же переведёте сессию в фоновый режим, эти субагенты остановятся, и диалоговое окно указывает, сколько их. Они начнут заново с самого начала, когда Claude [перезапустит workflow в фоновой сессии](#dynamic-workflows-when-you-background).
* **Автоматические ответы в артефакте**: Claude [самостоятельно отвечает на комментарии к артефакту](https://code.claude.com/docs/ru/artifacts.md#let-claude-reply-to-comments-on-its-own). Если вы всё же переведёте сессию в фоновый режим, эти ответы остановятся.

Запустите `/tasks`, чтобы увидеть всё, что выполняется, затем подтвердите перевод в фоновый режим или выберите `Stay`, чтобы сначала дать работе завершиться. См. раздел [Что переносится при переводе в фоновый режим](#what-carries-over-when-you-background), чтобы узнать, какие виды работы переносятся, а какие Claude Code останавливает.

### В диалоге сообщается, что фоновый агент `was carried into this session and not resumed`

Это уведомление называет фоновый [субагент](https://code.claude.com/docs/ru/sub-agents.md), который не выполняется в этой сессии.

Claude видит уведомление и отвечает самостоятельно, поэтому вам не нужно давать ему промпт. Если после прочтения ответа Claude вам всё ещё нужна работа этого субагента, попросите Claude об этом.

### Промпт отклонён как слишком короткий

Поле ввода для отправки ожидает описание задачи, а не начало разговора. Промпт короче четырёх символов отклоняется с подсказкой `Too short`, чтобы случайное нажатие клавиши не запустило сессию. Опишите, что должна сделать сессия, например `investigate the flaky checkout test`.

### Сессии отображаются как завершившиеся с ошибкой или остановленные после выключения

Выключение или перезагрузка вашей машины останавливает работающие фоновые сессии. Сессия, которая ожидала вашего ввода, остаётся в `Needs input`, когда вы вернётесь. Для любой другой работающей сессии то, что показывает представление агентов, зависит от того, как давно она в последний раз продвигалась:

* В пределах 48 часов сессия отображается как завершившаяся с ошибкой. Подключитесь к ней или ответьте ей, и она перезапустится из сохранённого диалога. Чтобы продолжить прерванную работу, отправьте ей ответ с просьбой продолжить.
* Более 48 часов, например если машина была выключена несколько дней, сессия отображается как остановленная с пометкой `ended while the background service was off`.

  Нажмите `Enter` на строке, и в нижней строке появится `Press enter again to resume this session (it ended while the background service was off), or ctrl+x to remove it.` Нажмите `Enter` на той же строке ещё раз, чтобы возобновить её сохранённый диалог. Ответ или `claude attach <id>` возобновляет её без этого сообщения в нижней строке.

Если [очистка транскриптов](https://code.claude.com/docs/ru/settings-reference.md#cleanupperioddays) удалила сохранённый диалог остановленной сессии, Claude Code отказывается открывать строку: сообщение говорит, что возобновлять нечего. `claude rm <id>` удаляет строку, за исключением случаев, когда [Claude Code отказывается это делать](#what-deleting-a-session-removes), а `claude respawn <id>` снова запускает её исходный промпт. См. [This session's saved conversation is no longer on disk](https://code.claude.com/docs/ru/errors.md#this-sessions-saved-conversation-is-no-longer-on-disk).

Спящий режим сам по себе не останавливает сессии. Сессии сохраняются во время спящего режима, и супервизор переподключается к ним при пробуждении.

### При открытии сессии сообщается, что диалог уже открыт

Эти сообщения означают, что сохранённый диалог остановленной сессии открыт другим процессом Claude Code на этой машине, поэтому представление агентов и `claude attach` не откроют сессию:

* `Can't open — this session is running in another terminal`: диалог открыт другим процессом, например запуском `claude -p` или терминалом, в котором вы его возобновили. Продолжайте в этом терминале либо завершите этот процесс или дождитесь его завершения, затем снова откройте сессию.
* `This conversation is already open in another running Claude session`: диалог открыт другой фоновой сессией. Используйте эту сессию или остановите её и снова откройте эту сессию.

Claude Code сохраняет ответ, который вы ввели при отклонённой попытке, если только он не начинается с `!` или `/`, и отправляет его при следующем запуске сессии.

### При открытии сессии сообщается, что у неё нет сохранённого транскрипта

Когда вы открываете сессию, которую [перевели в фоновый режим из другого диалога](#from-inside-a-session) и которая остановилась до того, как выполнила собственный ход, Claude Code возобновляет тот диалог. Если Claude Code не может найти диалог, он отказывается открывать сессию:

* `claude attach` выводит `This session has no saved transcript`.
* Представление агентов показывает `Press enter again to restart this session fresh` под списком.

Нажмите `Enter` на той же строке ещё раз, чтобы перезапустить сессию с пустым диалогом, или запустите `claude respawn <id>` из оболочки.

Подробности см. в [справочнике по ошибкам](https://code.claude.com/docs/ru/errors.md#this-session-has-no-saved-transcript).

### Хост-процесс терминала завершился аварийно или сессия перестала отвечать

[Супервизор](#the-supervisor-process) запускает терминал каждой фоновой сессии в собственном хост-процессе. Когда этот процесс аварийно завершается или перестаёт отвечать, Claude Code показывает причину и предлагает перезапуск; в обоих случаях диалог сохраняется, и перезапуск возобновляет его. Полные тексты сообщений приведены в [справочнике по ошибкам](https://code.claude.com/docs/ru/errors.md#terminal-host-process-died).

Claude Code никогда не перезапускает строку, выполняющую [shell-команду](#run-a-shell-command), ни по `Enter`, ни через `claude attach`, потому что это запустило бы команду снова; и сообщение строки, и `claude attach` указывают, что команда повторно не запускается.

### Сессия завершается до запуска с пометкой `possibly low memory`

Когда процесс фоновой сессии завершается до окончания запуска, а на хосте мало памяти, статус строки указывает код завершения и добавляет `possibly low memory — free some up and retry`.

> [!NOTE]
>
> Эта пометка — предположение, а не подтверждённая причина. Claude Code добавляет её, только если процесс завершился молча, не записав ошибку и не будучи остановлен сигналом, а хост в этот момент сообщал о нехватке памяти. Если процесс записал ошибку перед завершением, строка показывает эту ошибку.

Освободите оперативную память на хосте, затем нажмите `Enter` на строке и нажмите ещё раз, если [об этом попросит нижняя строка](#opening-a-session-says-it-has-no-saved-transcript). [Супервизор](#the-supervisor-process) запустит новый процесс для сессии. Если памяти по-прежнему мало, супервизор также самостоятельно [останавливает неактивные сессии](#the-supervisor-process), чтобы освободить ресурсы, а если остановка остальных ничего не освободила, останавливает и неактивные закреплённые сессии.

### Представление агентов сообщает, что фоновый сервис не ответил

Если при подключении, просмотре или выполнении `claude logs` сообщается, что фоновый сервис не ответил, процесс супервизора, вероятно, завис. Остановите его, и следующий запуск `claude agents` запустит новый. Чтобы ваши фоновые сессии продолжали работать во время перезапуска, передайте `--keep-workers`:

```bash theme={null}
claude daemon stop --any --keep-workers
```

Затем выполните `claude agents` в оболочке, чтобы запустить новый супервизор. В macOS и Linux сделайте это в течение примерно минуты после завершения старого, иначе сессии [остановятся без супервизора](#the-supervisor-process). Если вы увидели `stopped`, но та же ошибка возвращается, и вы используете macOS или Linux с Claude Code версии старше v2.1.300, выполните `claude update`, а затем снова обе команды.

Если вместо этого команда остановки вывела одно из этих четырёх сообщений, старый процесс не был остановлен. Выполните в оболочке то, что указано в соответствующей строке, затем запустите `claude agents`:

| Сообщение содержит | Платформа | Действие |
| :- | :- | :- |
| `could not be verified as the daemon, so it was not signalled` | Все | Выясните, какой программе принадлежит этот идентификатор процесса. Если это ваш собственный супервизор, остановите его; любую другую программу не трогайте. Затем удалите `~/.claude/daemon.lock`. |
| `is still running after SIGKILL` | macOS, Linux | Дождитесь завершения процесса. Если он так и не завершится, перезагрузите компьютер. |
| `was not sent SIGKILL` | macOS, Linux | Выполните команду остановки ещё раз. Если процесс остаётся, проверьте его с помощью `ps -ww -o args= -p <pid>`: Claude Code, запущенный с `daemon`, — это супервизор, поэтому выполните `kill -9 <pid>`. Всё остальное не трогайте; если после этого `claude agents` не может запустить супервизор, удалите `~/.claude/daemon.lock`. |
| `supervisor (pid=<pid>) is still running` | Windows | Завершите процесс с помощью `taskkill /PID <pid>` |

### Отправка завершается ошибкой `Could not resolve authentication method`

Если фоновая отправка завершается ошибкой `Could not resolve authentication method`, в то время как интерактивные сессии проходят аутентификацию нормально, рабочий процесс, получивший отправку, не получил учётные данные. Фоновые сессии получают учётные данные от [супервизора](#the-supervisor-process), поэтому эта ошибка означает, что самому процессу супервизора не были доступны сохранённые учётные данные. Убедитесь, что вы выполнили `/login` или настроили API-ключ, затем остановите супервизор:

```bash theme={null}
claude daemon stop --any --keep-workers
```

В течение [примерно минуты](#the-supervisor-process) выполните `claude agents` или `claude --bg` в оболочке, чтобы запустить новый супервизор, который читает ваши сохранённые учётные данные. Если вы проходите аутентификацию с помощью переменной окружения, например `ANTHROPIC_API_KEY`, а не через `/login`, выполните эту следующую команду из оболочки, в которой задана эта переменная.

Полный список причин и способов исправления см. в [справочнике по ошибкам](https://code.claude.com/docs/ru/errors.md#could-not-resolve-authentication-method).

### Фоновая сессия показывает `No LLM gateway`

Если фоновая сессия показывает [`No LLM gateway`](https://code.claude.com/docs/ru/errors#no-llm-gateway-opened-from-another-folder), она не получила ваш `ANTHROPIC_BASE_URL` шлюза, поэтому её запросы завершаются ошибкой. Claude Code не передал его, потому что вы отправили, разбудили или перезапустили сессию из каталога, отличного от папки, указанной в сообщении.

Вы увидите это сообщение, например, после отправки в репозиторий с помощью [`@<repo>`](#dispatch-to-a-specific-directory) или пробуждения остановленной сессии запуском `claude attach` из другого каталога. Чтобы передать сессии ваш шлюз, выберите исправление в зависимости от того, где задан ваш шлюз:

* **Вы экспортировали шлюз в терминале**: в терминале, где вы экспортировали переменные шлюза, выполните `cd` в папку, указанную в сообщении, и запустите команду [`claude respawn <id>`](#manage-sessions-from-the-shell) из сообщения.
  * Шлюз доходит до сессии, только если [супервизор](#the-supervisor-process) сам был запущен из оболочки, в которой экспортирован тот же шлюз. Если это не так, перезапустите его из терминала, в котором вы выполнили команду respawn, как описано в разделе [Отправка завершается ошибкой `Could not resolve authentication method`](#dispatch-fails-with-could-not-resolve-authentication-method), затем выполните эту команду снова.
* **Вы использовали представление агентов в проекте, настройки которого задают шлюз**: поместите `ANTHROPIC_BASE_URL` и его учётные данные в [блок `env` файла настроек](https://code.claude.com/docs/ru/llm-gateway-connect#set-in-a-settings-file). Используйте `~/.claude/settings.json` или `.claude/settings.local.json` в собственном проекте сессии — оба этих файла читает перезапущенная сессия. Затем выполните [`claude respawn <id>`](#manage-sessions-from-the-shell) в оболочке из любого каталога, чтобы перезапустить эту сессию через шлюз.

### Фоновые сессии не могут читать Desktop, Documents или Downloads в macOS

В macOS хост фоновых сессий работает как отдельный процесс и запрашивает доступ к защищённым папкам отдельно от вашего терминала. Если фоновая сессия сообщает `Operation not permitted` при чтении `~/Desktop`, `~/Documents`, `~/Downloads` или другого защищённого расположения, предоставьте доступ в System Settings в разделе Privacy & Security > Files and Folders или включите Full Disk Access для этой записи.

В любом из этих списков найдите запись с именем Claude Code или запись, названную по пути или имени файла исполняемого файла `claude`. Имя этого файла может быть номером версии, например `2.1.316`. Если после обновления Claude Code ошибка `Operation not permitted` возвращается, найдите новую запись, например названную по новой версии. Если она есть, предоставьте ей доступ.

### Фоновые сессии не могут подключиться к хостам локальной сети в macOS

В macOS 15 и более поздних версиях система не позволяет процессу обращаться к устройствам в вашей локальной сети, пока вы не предоставите разрешение Local Network, поэтому команда, обращающаяся к адресу в LAN, может завершиться ошибкой `connect: no route to host` в фоновой сессии, хотя в терминале на переднем плане она работает. Первая команда в фоновой сессии, подключающаяся к адресу локальной сети, вызывает запрос разрешения macOS Local Network для Claude Code. Предоставьте его один раз, и эти команды будут обращаться к хостам LAN так же, как в терминале на переднем плане.

### Сессия медленно отвечает после подключения

Когда сессия, которая завершила работу или ожидает вашего следующего сообщения, остаётся без подключения около часа, супервизор останавливает её процесс, чтобы освободить ресурсы. Подключение запускает новый процесс с того места, где сессия остановилась, и сразу переключает вас на сессию, пока процесс перезапускается. Сессии, которые работают, ожидают ответа на запрос разрешения или в другом диалоговом окне либо [закреплены](#organize-the-list), таким образом не останавливаются, поэтому закрепите сессию с помощью `Ctrl+T`, чтобы она оставалась отзывчивой.

Пока процесс запускается, Claude Code показывает конец транскрипта сессии, отформатированный так же, как его отображает работающая сессия, — с markdown, подсвеченными блоками кода и вызовами инструментов в виде затемнённых строк — над затемнённой областью ввода промпта с пометкой `Session is starting`. Работающая сессия заменяет это отображение, как только будет готова.

### `.claude/worktrees/` заполняется

Удаление сессии в представлении агентов удаляет worktree, который Claude создал для неё, но [некоторые каталоги worktree остаются на диске](#what-deleting-a-session-removes). Каталоги, которые git больше не распознаёт, не отображаются в `git worktree list`, поэтому удаляйте их вручную.

Выведите список оставшихся записей с помощью `git worktree list` в каталоге проекта и удалите каждую с помощью `git worktree remove <path>`. Если git отказывается это делать, см. [Очистка worktree субагентов и фоновых сессий](https://code.claude.com/docs/ru/worktrees.md#clean-up-subagent-and-background-session-worktrees).

## Ограничения

Agent view находится в исследовательском предпросмотре со следующими ограничениями:

* **Применяются ограничения скорости**: фоновые сеансы потребляют использование вашей подписки так же, как интерактивные сеансы, поэтому запуск десяти агентов параллельно использует квоту примерно в десять раз быстрее, чем запуск одного.
* **Сеансы локальны**: фоновые сеансы работают на вашей машине. Они сохраняются при переходе в спящий режим, но останавливаются при выключении машины.
* **Worktree, созданные Claude, удаляются вместе с сессией в agent view**: зафиксируйте изменения перед удалением сессии, которая редактировала файлы в собственном worktree. [Некоторые worktree остаются на диске](#what-deleting-a-session-removes).
