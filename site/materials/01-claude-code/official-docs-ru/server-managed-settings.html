Настройка параметров, управляемых сервером #

Централизованно настраивайте Claude Code для вашей организации через параметры, доставляемые сервером, без необходимости инфраструктуры управления устройствами.

Настройки, управляемые сервером, позволяют владельцам организации централизованно настраивать Claude Code из Organization settings > Claude Code > Managed settings в консоли claude.ai. Клиенты Claude Code автоматически получают эти настройки при аутентификации пользователей с использованием подходящих учётных данных на платформе, где поддерживается доставка настроек, управляемых сервером. См. Доступность платформы для получения информации об учётных данных и платформах, которые соответствуют требованиям.

[!NOTE]

Параметры, управляемые сервером, доступны для клиентов Claude for Teams и Claude for Enterprise.

Требования #

Для использования параметров, управляемых сервером, вам необходимо:

  • План Claude for Teams или Claude for Enterprise
  • Роль Owner или Primary Owner в вашей организации Claude для просмотра и редактирования конфигурации
  • Сетевой доступ к api.anthropic.com

Выбор между параметрами, управляемыми сервером, и параметрами, управляемыми конечной точкой #

Claude Code поддерживает два подхода к централизованной конфигурации. Параметры, управляемые сервером, доставляют конфигурацию с серверов Anthropic. Параметры, управляемые конечной точкой развертываются непосредственно на устройства через встроенные политики ОС (управляемые параметры macOS, реестр Windows) или управляемые файлы параметров.

| Подход | Лучше всего подходит для | Модель безопасности | | :- | :- | :- | | Параметры, управляемые сервером | Организации без MDM или пользователи на неуправляемых устройствах | Параметры, которые Claude Code получает с серверов Anthropic при запуске и обновляет каждый час во время сеанса | | Параметры, управляемые конечной точкой | Организации с MDM или управлением конечными точками | Параметры развертываются на устройства через профили конфигурации MDM, политики реестра или управляемые файлы параметров |

Если ваши устройства зарегистрированы в решении MDM или управления конечными точками, параметры, управляемые конечной точкой, обеспечивают более сильные гарантии безопасности, поскольку файл параметров может быть защищен от изменения пользователем на уровне ОС. Параметры, управляемые конечной точкой, не достигают облачных сеансов в размещенных в Anthropic средах, поэтому организации, разработчики которых запускают облачные сеансы, должны также настроить параметры, управляемые сервером. Сеансы в самостоятельно размещенной среде также читают управляемый файл параметров в образе runner. Приоритет параметров ниже указывает, когда этот файл применяется.

Настройка параметров, управляемых сервером #

1. Откройте консоль администратора

В консоли claude.ai перейдите в Organization settings > Claude Code > Managed settings.

Если в организации Team или Enterprise на странице указано, что у вас нет доступа, попросите Owner или Primary Owner внести изменение.

2. Определите ваши настройки

Добавьте вашу конфигурацию как JSON. Все настройки, доступные в settings.json, поддерживаются, за исключением тех, которые ограничены доставкой политики на уровне ОС; см. Текущие ограничения для этого краткого списка. Это включает хуки, переменные окружения и настройки только для управляемого уровня, такие как allowManagedPermissionRulesOnly.

Этот пример применяет список отказа в разрешениях, предотвращает обход разрешений пользователями и ограничивает правила разрешений только теми, которые определены в управляемых параметрах. Правило Bash(curl *) соответствует curl так, как его пишет Claude, а не /usr/bin/curl или sh -c 'curl …'; для применения сетевых ограничений, которые не зависят от текста команды, добавьте sandbox блок с allowManagedDomainsOnly.

```json theme={null} { "permissions": { "deny": [ "Bash(curl *)", "Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)" ], "disableBypassPermissionsMode": "disable" }, "allowManagedPermissionRulesOnly": true }


Hooks используют тот же формат, что и в `settings.json`.

Этот пример запускает скрипт аудита после вызовов инструментов `Edit` и `Write` во всей организации:

{ "hooks": { "PostToolUse": [ { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "/usr/local/bin/audit-edit.sh" } ] } ] } }


Поскольку hooks выполняют команды оболочки, пользователи в интерактивных сеансах видят [диалог одобрения безопасности](#security-approval-dialogs) перед тем, как Claude Code применит их.

Чтобы настроить классификатор [авторежима](https://code.claude.com/docs/ru/permission-modes.md#eliminate-prompts-with-auto-mode) так, чтобы он знал, каким репозиториям, бакетам и доменам доверяет ваша организация, доставьте блок `autoMode` таким же образом; см. [Настройка авторежима](https://code.claude.com/docs/ru/auto-mode-config.md) для информации о том, как записи `autoMode` влияют на то, что блокирует классификатор, и важные предупреждения о полях `environment`, `allow`, `soft_deny` и `hard_deny`.

**3. Сохраните и разверните**

Сохраните ваши изменения. Клиенты Claude Code получат обновленные настройки при следующем запуске или в цикле опроса каждый час.

Редактор проверяет ваш JSON по опубликованной JSON-схеме настроек Claude Code. Если он находит проблему в JSON, который успешно разбирается, он показывает предупреждение и меняет надпись на кнопке сохранения. Надпись будет **Update with errors**, если настройки уже сохранены, и **Add with errors**, если настройки еще не сохранены. Эта кнопка все равно сохраняет, поскольку предупреждение схемы не блокирует сохранение.

Схема [может отставать от новейших релизов](https://code.claude.com/docs/ru/settings.md#edit-a-settings-file), поэтому редактор может пометить ключ или значение, которые описаны в [справочнике настроек](https://code.claude.com/docs/ru/settings-reference.md#all-settings). Claude Code получает сохраненные вами ключи и значения и выполняет [собственную проверку](#invalid-entries-in-delivered-settings) при их загрузке.

### Проверка доставки параметров

Чтобы подтвердить, что параметры применяются, попросите пользователя перезагрузить Claude Code. Если конфигурация включает параметры, которые запускают [диалог одобрения безопасности](#security-approval-dialogs), пользователь видит подсказку, описывающую управляемые параметры при следующей загрузке параметров Claude Code: при следующем запуске или в течение часа в работающем интерактивном сеансе. Вы также можете проверить, что активны управляемые правила разрешений, попросив пользователя запустить `/permissions` для просмотра его эффективных правил разрешений.

В сессии попросите пользователя запустить `/status`. [Строка `Setting sources`](https://code.claude.com/docs/ru/managed-settings#read-the-source-in-/status) содержит `Enterprise managed settings` с `remote` в скобках, когда применяются настройки, управляемые сервером.

Чтобы проверить результат загрузки на конкретной машине, попросите пользователя запустить `claude doctor` и прочитать строку `Managed settings (remote)`. Требуется Claude Code v2.1.248 или позже. Строка сообщает об одном из четырех результатов:

* Доставленные параметры загружены
* Ваша организация не имеет настроенных параметров, управляемых сервером
* Загрузка не удалась, с указанием причины и того, применяется ли кэшированная политика
* Claude Code пропустил загрузку, с указанием причины. См. [Доступность платформы](#platform-availability) для поставщиков и конфигураций, которые пропускают её

Пока загрузка еще выполняется, строка сообщает об этом вместо этого.

В работающем сеансе `/status` показывает ту же строку после неудачной загрузки и для некоторых причин пропуска загрузки, таких как переменная поставщика третьей стороны или пользовательский `ANTHROPIC_BASE_URL`, экспортированный в оболочке пользователя.

### Разные настройки для групп

На плане Enterprise вы можете задать каждой группе участников собственную конфигурацию вместо одной конфигурации для всей организации. Если в вашей организации [включен HIPAA](https://code.claude.com/docs/ru/hipaa-setup.md), групповые конфигурации пока недоступны. Каждая группа должна уже существовать: либо синхронизированная из вашего поставщика удостоверений через SCIM, либо как пользовательская группа, которой вы управляете в консоли администратора.

Каждый участник получает не более одной конфигурации, одинаковой на всех устройствах:

* **Участник группы с конфигурацией**: конфигурация с наивысшим рангом среди его групп
* **Все остальные**, включая участника, чья единственная группа с конфигурацией была удалена: конфигурация по умолчанию для всех остальных, если вы ее задали

Конфигурации не объединяются ни друг с другом, ни с конфигурацией для всей организации, поэтому каждая из них должна содержать все настройки, которые вы хотите задать для этой группы. Чтобы применить ограничение ко всем участникам, добавьте его в каждую групповую конфигурацию и в конфигурацию для всех остальных.

Участники продолжают получать конфигурацию для всей организации до последнего из этих шагов, поэтому вы можете сначала все настроить и протестировать:

**1. Добавьте конфигурацию для каждой группы**

В [**Organization settings > Claude Code > Managed settings**](https://claude.ai/admin-settings/claude-code) нажмите **Add configuration**, выберите группу и выберите отправную точку. Чтобы ослабить политику для группы, выберите группу, которую синхронизирует ваш поставщик удостоверений, чтобы никто не мог добавить себя в нее в консоли администратора.

Чтобы сохранить то, что участники имеют сейчас, и изменить несколько настроек, начните с копии конфигурации для всей организации. Отредактируйте конфигурацию и сохраните ее.

**2. Задайте конфигурацию для всех остальных**

Нажмите **Set** в разделе **Everyone else** и добавьте JSON для участников, которым не соответствует ни одна групповая конфигурация. Чтобы оставить им то, что у них есть сейчас, вставьте конфигурацию для всей организации. Если вы пропустите этот шаг, их локальные сессии не получат настроек, управляемых сервером, а любые [настройки, управляемые на конечных устройствах](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), на устройстве по-прежнему применяются.

**3. Упорядочьте группы**

Перетащите конфигурации в нужном порядке. Участник нескольких групп получает только конфигурацию с наивысшим рангом, поэтому размещайте самые строгие или самые специфичные группы вверху.

**4. Проверьте, кто что получает**

В разделе **Check effective settings** внизу страницы найдите участника, чтобы увидеть, какую конфигурацию он получит. Проверьте участника из каждой группы, участника нескольких групп и участника, которому не соответствует ни одна групповая конфигурация.

**5. Переключитесь на режим на основе групп**

Нажмите **Switch to group-based configurations** в баннере вверху страницы и подтвердите. Участники получат свои конфигурации примерно в течение часа, за исключением [ключей, которые применяются только при следующем запуске](#fetch-and-caching-behavior). Чтобы вернуться, переключитесь на режим для всей организации в том же баннере: снова применяется конфигурация для всей организации, если она у вас есть, а ваши групповые конфигурации сохраняются.

Ограничения моделей для группы действуют только в локальных сессиях. Облачные и удаленные сессии Cowork используют список [`availableModels`](https://code.claude.com/docs/ru/model-config#restrict-model-selection) из конфигурации для всех остальных. Если вы не задали конфигурацию для всех остальных, он берется из конфигурации для всей организации, даже после переключения на режим на основе групп. Если вы не включите этот ключ в конфигурацию для всех остальных, участники в этих сессиях не ограничены этим списком.

Если вы используете конфигурацию группы, чтобы задать, куда направляются запросы API, это применяется только к Claude Code, а не к другим инструментам, которые вызывают API.

### Контроль доступа

Следующие роли могут управлять параметрами, управляемыми сервером:

* **Primary Owner**
* **Owner**

Ограничьте доступ доверенному персоналу, так как изменения настроек могут применяться ко всем пользователям в организации.

### Параметры только для управления

Большинство [ключей параметров](https://code.claude.com/docs/ru/settings-reference.md#all-settings) работают в любой области. Несколько ключей читаются только из управляемых параметров и не имеют эффекта при размещении в файлах параметров пользователя или проекта. См. [параметры только для управления](https://code.claude.com/docs/ru/managed-settings.md#managed-only-settings) для элементов управления разрешениями и плагинами, или прочитайте столбец Scope в индексе [Все параметры](https://code.claude.com/docs/ru/settings-reference.md#all-settings) для полного набора.

### Текущие ограничения

Параметры, управляемые сервером, имеют следующие ограничения:

* На плане Team настройки применяются одинаково ко всем пользователям в организации. [Групповые конфигурации](#give-groups-different-settings) требуют плана Enterprise.
* Вы не можете распространять файл [`managed-mcp.json`](https://code.claude.com/docs/ru/managed-mcp) через параметры, управляемые сервером. Вместо этого доставьте там ключи политики `allowedMcpServers` и `deniedMcpServers`. На Claude Code v2.1.259 или позже вы также можете предоставить удаленные серверы с помощью [`managedMcpServers`](https://code.claude.com/docs/ru/managed-mcp#provide-servers-through-managed-settings), который принимает только серверы `http` и `sse` и не берет исключительный контроль так, как это делает файл.

  Claude Code читает `managed-mcp.json`, развернутый по его [системному пути](https://code.claude.com/docs/ru/managed-mcp.md#exclusive-control-with-managed-mcp-json), отдельно от уровня управляемых параметров, поэтому файл все еще применяется, когда действуют параметры, управляемые сервером.
* Параметры, ограниченные источниками политики на уровне ОС, такие как `policyHelper` и `wslInheritsWindowsSettings`, не учитываются. Разверните их через MDM или системный файл `managed-settings.json` вместо этого. `policyHelper`, развернутый таким образом, работает только тогда, когда его источник является выбранным в [приоритете в пределах управляемого уровня](https://code.claude.com/docs/ru/managed-settings.md#precedence-within-the-managed-tier).

## Доставка настроек

### Приоритет настроек

Настройки, управляемые сервером, и [настройки, управляемые на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), занимают высший уровень в [иерархии настроек](https://code.claude.com/docs/ru/settings.md#settings-precedence) Claude Code. Ключ, который вы задаёте здесь, имеет приоритет над тем же ключом в собственных файлах настроек пользователя или в значении `--settings`, за исключением [исключений из приоритета управляемых настроек](https://code.claude.com/docs/ru/settings.md#exceptions-to-managed-settings-precedence).

На управляемом уровне Claude Code по умолчанию использует первый источник, который доставляет хотя бы один ключ политики: сначала проверяются настройки, управляемые сервером, а затем настройки, управляемые на уровне конечного устройства, за исключением [ключей-исключений, описанных далее](#per-key-exceptions-across-managed-sources). В разделе [Как Claude Code объединяет управляемые источники](https://code.claude.com/docs/ru/managed-settings.md#precedence-within-the-managed-tier) приведены полный порядок приоритета, особый порядок для управляющих ключей и необязательная настройка, при включении которой Claude Code применяет все источники.

Если выбранный источник — это политика MDM или файл управляемых настроек, чей [`policyHelper`](https://code.claude.com/docs/ru/settings-reference#policyhelper) предоставляет управляемые настройки, вывод этого хелпера заменяет данный источник и становится единственной управляемой конфигурацией для запуска. Claude Code не обращается к `policyHelper`, настроенному в MDM или в настройках на основе файлов, пока настройки, управляемые сервером, доставляют ключ политики.

Если при последующем получении выясняется, что настройки, управляемые сервером, удалены, Claude Code запускает этот хелпер сразу, а не при следующем запуске. В записи [`policyHelper`](https://code.claude.com/docs/ru/settings-reference#policyhelper) описано, что происходит, если этот запуск завершается неудачно.

Если вы очищаете конфигурацию, управляемую сервером, в консоли администратора, чтобы вернуться к политике plist или реестра, управляемой на уровне конечного устройства, учтите, что [кэшированные настройки](#fetch-and-caching-behavior) сохраняются на клиентских машинах до следующего успешного получения, а ключи, которые [применяются только при следующем запуске](#fetch-and-caching-behavior), например `model`, остаются в силе, пока каждый клиент не будет перезапущен. Выполните `/status`, чтобы увидеть, какой управляемый источник активен.

### Исключения для отдельных ключей в управляемых источниках

Эти ключи являются исключениями из правила отсутствия объединения:

* **Ключи блокировки, действующие во всех источниках**: небольшой набор ключей, например блокировки списка разрешённых для песочницы, [перечисленных на странице управляемых настроек](https://code.claude.com/docs/ru/managed-settings.md#precedence-within-the-managed-tier). Claude Code учитывает их, когда их задаёт любой управляемый источник, контролируемый администратором; уровень реестра HKCU, доступный пользователю для записи, исключён.

  Когда [`policyHelper`](https://code.claude.com/docs/ru/settings-reference#policyhelper) предоставляет управляемые настройки, его вывод — единственный источник, который читают эти проверки, за исключением [`forceRemoteSettingsRefresh`](https://code.claude.com/docs/ru/settings-reference#forceremotesettingsrefresh), который Claude Code читает непосредственно из источников администратора при запуске.
* **Блок `env`**: за исключением единого блока телеметрии и переменных маршрутизации, связанных с ключом учётных данных (оба описаны ниже), он объединяется по ключам между источниками, контролируемыми администратором. Для каждой переменной окружения побеждает источник с наивысшим приоритетом, который её определяет, а источники администратора с более низким приоритетом заполняют переменные, которые источники с более высоким приоритетом оставляют незаданными. Поэтому запись `env`, управляемая на уровне конечного устройства, применяется всякий раз, когда конфигурация, управляемая сервером, оставляет эту переменную незаданной, или пока кэшированное серверное значение для неё [удерживается в ожидании подтверждения сервером](#fetch-and-caching-behavior). Требуется Claude Code v2.1.223 или более поздней версии. До v2.1.223 Claude Code применяет только весь блок `env` выбранного источника.
  * **Единый блок телеметрии**: ключи экспортера `OTEL_EXPORTER_OTLP_*`, переключатели захвата содержимого `OTEL_LOG_*`, `OTEL_LOGS_EXPORTER` и переменные бета-трассировки `ENABLE_BETA_TRACING_DETAILED` и `BETA_TRACING_ENDPOINT` берутся как единое целое из источника с наивысшим приоритетом, задающего любую из них. Источник, доставляющий ключ учётных данных `otelHeadersHelper`, тоже претендует на этот блок, но устанавливает эти переменные только тогда, когда он является выбранным источником: источник, который не выбран, но доставляет этот ключ, не предоставляет ни одной из них и всё равно не позволяет источникам с более низким приоритетом их заполнить. В любом случае эндпоинт экспортера из одного источника никогда не может сочетаться с учётными данными из другого.
  * **Маршрутизация, связанная с учётными данными**: источник, который сочетает переменные маршрутизации с ключом учётных данных, действующим только для выбранного источника, например `apiKeyHelper` или `otelHeadersHelper`, предоставляет эти переменные маршрутизации, только если он занимает эту позицию.
* **`allowedProviders`**: список, заданный на машине, и список, управляемый сервером, объединяются так, как указано в [примечании об области действия в его записи](https://code.claude.com/docs/ru/settings-reference.md#allowedproviders). Требуется Claude Code v2.1.285 или более поздней версии
* **Ключи входа в собственные сервисы Anthropic**: [`forceLoginOrgUUID`](https://code.claude.com/docs/ru/settings-reference#forceloginorguuid) и значения `"claudeai"` и `"console"` ключа [`forceLoginMethod`](https://code.claude.com/docs/ru/settings-reference#forceloginmethod). Если вы также развёртываете политику MDM или файл управляемых настроек, задайте их и там, и в настройках, управляемых сервером, на claude.ai, пока все клиенты не будут работать на v2.1.299 или более поздней версии. О том, где задавать эти ключи после этого и значение из какого источника применяется, см. [Какой управляемый источник предоставляет ключи входа](https://code.claude.com/docs/ru/managed-settings.md#which-managed-source-supplies-login-keys).
* **Ключи входа через шлюз**: Claude Code никогда не читает [`forceLoginGatewayUrl`](https://code.claude.com/docs/ru/settings-reference#forcelogingatewayurl), [`gatewayInternalNetworks`](https://code.claude.com/docs/ru/settings-reference#gatewayinternalnetworks) или значение `"gateway"` ключа [`forceLoginMethod`](https://code.claude.com/docs/ru/settings-reference#forceloginmethod) из настроек, управляемых сервером, поэтому значение там не применяется и не скрывает значение, заданное в политике MDM или файле управляемых настроек. В [записи `managedSourcesBehavior`](https://code.claude.com/docs/ru/settings-reference#managedsourcesbehavior) указано, какой источник администратора на машине их предоставляет.

#### Когда `apiKeyHelper` машины не действует

Когда выбранным источником являются ваши настройки, управляемые сервером, `apiKeyHelper` в файле управляемых настроек или политике MDM машины не действует. В этом случае Claude Code [отклоняет промпты](https://code.claude.com/docs/ru/errors.md#claude-code-didnt-send-your-claude-ai-login) в сессии, которая использовала бы сохранённый вход claude.ai, при выполнении обоих условий:

* Файл или политика включает облачного провайдера, или какой-либо источник задаёт адрес API, отличный от адреса Anthropic
* Настройки, управляемые сервером, не задают хелпер и не указывают адрес API Anthropic

Чтобы снять отказ, сохраните действие хелпера и его адреса API, укажите адрес API Anthropic в настройках, управляемых сервером, или удалите хелпер из политики машины. Отказ требует Claude Code v2.1.314 или более поздней версии.

### Получение и кэширование

Claude Code получает настройки с серверов Anthropic при запуске и ежечасно проверяет наличие обновлений во время активных сессий.

Клиент, вошедший через [шлюз приложений Claude](#platform-availability), получает настройки от шлюза и дожидается этого получения до начала сессии, поэтому описанное в списках ниже получение к нему не относится. Что происходит при сбое этого получения, описано в разделе [Принудительный запуск с отказом при сбое](#enforce-fail-closed-startup).

> [!NOTE]
>
> При входе в claude.ai с тарифом Team или Enterprise, сохранённом на машине, Anthropic может требовать настройки вашей организации до начала сессии. В этом случае, независимо от того, что сказано в списках ниже, разработчик [не может начать сессию](https://code.claude.com/docs/ru/errors.md#couldnt-load-your-organizations-settings), например в таких случаях:
>
> * Срок действия его входа истёк — до тех пор, пока он не выполнит `claude auth login`
> * У Claude Code нет ни настроек, ни недавней кэшированной копии. Проверьте, может ли машина подключиться к `api.anthropic.com`
>
> Сообщение при запуске с `before a session can start` или `Your Claude session has expired` означает, что это требование действует.

**Первый запуск без кэшированных настроек:**

* Когда разработчик входит при запуске, например при первом запуске или после `/logout`, Claude Code ждёт получения до пяти секунд, прежде чем открыть сессию. Если политика приходит вовремя, Claude Code применяет её с первого экрана и показывает на нём ваши [`companyAnnouncements`](https://code.claude.com/docs/ru/settings-reference#companyannouncements). Если данные требуют [подтверждения безопасности](#security-approval-dialogs), Claude Code прекращает ожидание и применяет данные после подтверждения разработчиком
* При любом другом запуске, а также когда пятисекундное ожидание истекает, Claude Code открывает сессию, пока получение продолжается, поэтому проходит короткий промежуток времени, прежде чем настройки загрузятся и ограничения вступят в силу
* Если получение завершается неудачно, Claude Code продолжает работу без настроек, управляемых сервером, и в интерактивных сессиях, а также на [вкладке Code в Claude Desktop](https://code.claude.com/docs/ru/desktop.md) предупреждает, что удалённая политика не применяется; настройки, управляемые на уровне конечного устройства, по-прежнему применяются. Если управляемый источник задаёт [`forceRemoteSettingsRefresh`](#enforce-fail-closed-startup), Claude Code вместо этого завершает работу

**Последующие запуски с кэшированными настройками:**

* Кэшированные настройки применяются сразу при запуске, за исключением кэшированных значений `modelPricing` и `managedMcpServers`; переменных окружения, которые Claude Code удерживает до подтверждения данных сервером; удаления, перемещения или отключения [встроенного стража](https://code.claude.com/docs/ru/plugins/mods/admin.md#know-what-happens-by-default) кэшированным списком плагинов; а также, на машине, где источник, управляемый на уровне конечного устройства, перечисляет или включает собственные плагины, [статуса организации](https://code.claude.com/docs/ru/plugins/mods/admin.md#install-your-organizations-mods) для плагина, который включён только кэшированным списком
* Кэшированный [`modelPricing`](https://code.claude.com/docs/ru/settings-reference#modelpricing) не применяется, пока получение в рамках сессии не подтвердит данные. До этого показатели стоимости, которые разработчики видят в `/usage` и строке состояния, рассчитываются по прейскурантной цене
* Кэшированный блок [`managedMcpServers`](https://code.claude.com/docs/ru/settings-reference#managedmcpservers) не применяется, пока получение в рамках сессии не подтвердит данные. Claude Code ждёт этого получения до 30 секунд, прежде чем подключать MCP-серверы. Если получение завершается неудачно или по таймауту, сессия начинается без серверов организации, `/status` сообщает об этом, а серверы подключаются, как только последующее получение их подтвердит. Полное описание поведения, включая первый запуск, см. в разделе [Когда подключаются предоставленные серверы](https://code.claude.com/docs/ru/managed-mcp.md#when-provided-servers-connect). Требуется Claude Code v2.1.259 или более поздней версии
* Кэшированное значение [`prependPlugins`](https://code.claude.com/docs/ru/settings-reference#prependplugins), [`appendPlugins`](https://code.claude.com/docs/ru/settings-reference#appendplugins) или [`enabledPlugins`](https://code.claude.com/docs/ru/settings-reference#enabledplugins) не может удалить встроенного стража, изменить его позицию или отключить его, пока получение в рамках сессии не подтвердит данные
* На машине, где [источник, управляемый на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#choose-a-delivery-mechanism), перечисляет или включает собственные плагины, плагин, который включён только кэшированным списком, считается [плагином пользователя](https://code.claude.com/docs/ru/plugins/mods/admin.md#install-your-organizations-mods), а не вашей организации, пока получение не подтвердит данные
* Claude Code получает свежие настройки в фоновом режиме
* Если провайдер сессии отсутствует в кэшированном списке [`allowedProviders`](https://code.claude.com/docs/ru/settings-reference#allowedproviders), Claude Code может дождаться этого получения и проверить ещё раз, прежде чем отклонить сессию. Если получение завершается неудачно, сессия отклоняется
* Рассчитывайте на то, что срок действия кэшированных настроек истекает через 24 часа после последнего успешного получения
* Если получение при запуске завершается неудачно до истечения срока действия кэшированных настроек, Claude Code предупреждает в интерактивных сессиях и на вкладке Code, что действует кэшированная политика
* Если получение при запуске завершается неудачно после истечения срока действия кэшированных настроек, сессия начинается без настроек, управляемых сервером, а предупреждение сообщает, что удалённая политика не применяется. Чтобы Claude Code вместо этого завершал работу, задайте [`forceRemoteSettingsRefresh`](#enforce-fail-closed-startup)
* Пока получение не завершится успешно, значения, удержанные при запуске, остаются удержанными

Claude Code удерживает несколько категорий переменных в кэшированном блоке `env`, пока сервер не подтвердит данные для сессии. Это не позволяет кэшированному значению прокси, центра сертификации, эндпоинта или учётных данных перенаправить, перехватить или повторно аутентифицировать получение настроек, которое подтверждает данные. Эта защита применяется только к кэшу настроек, полученных с сервера: [настройки, управляемые на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms) и развёрнутые через MDM или `managed-settings.json`, не затрагиваются. Удерживаемые категории включают:

* Конфигурацию прокси и TLS, например `HTTPS_PROXY`, `NODE_EXTRA_CA_CERTS` и переменные клиентского сертификата mTLS `CLAUDE_CODE_CLIENT_CERT` и `CLAUDE_CODE_CLIENT_KEY`
* Маршрутизацию API и выбор провайдера, включая `ANTHROPIC_BASE_URL`, переменные выбора провайдера, такие как `CLAUDE_CODE_USE_BEDROCK` и `CLAUDE_CODE_USE_VERTEX`, и URL-адреса эндпоинтов провайдеров, такие как `ANTHROPIC_BEDROCK_BASE_URL`
* Учётные данные аутентификации, например `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` и `CLAUDE_CODE_OAUTH_TOKEN`
* Селектор каталога конфигурации `CLAUDE_CONFIG_DIR`
* Селекторы источника учётных данных и каталога конфигурации в Claude Code v2.1.223 или более поздней версии: переменные Workload Identity Federation, такие как `ANTHROPIC_FEDERATION_RULE_ID` и `ANTHROPIC_IDENTITY_TOKEN`, селекторы профиля и каталога конфигурации `ANTHROPIC_PROFILE` и `ANTHROPIC_CONFIG_DIR`, а также переменные каталогов операционной системы `HOME`, `XDG_CONFIG_HOME`, `APPDATA` и `USERPROFILE`

Claude Code читает переменные Workload Identity Federation и селекторы `ANTHROPIC_PROFILE` и `ANTHROPIC_CONFIG_DIR` только при запуске, поэтому значение, доставленное сервером, не переключает источник учётных данных сессии даже после успешного получения. Чтобы доставить эти селекторы в Claude Code v2.1.223 или более поздней версии, используйте [настройки, управляемые на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), например MDM или `managed-settings.json`. Для `CLAUDE_CONFIG_DIR` и переменных каталогов операционной системы защитой служит само удержание: кэшированное значение не попадает в окружение, пока сервер не подтвердит данные.

Все остальные ключи в кэшированном блоке `env` применяются при запуске. Как только сервер подтвердит данные и вы их одобрите, если они требуют [подтверждения безопасности](#security-approval-dialogs), удержанные переменные применяются до конца сессии.

Если для получения нужен прокси, задайте `HTTPS_PROXY` в одном из следующих мест:

* В блоке `env`, [управляемом на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), через MDM или `managed-settings.json`. Этот источник требует Claude Code v2.1.223 или более поздней версии. До v2.1.223 используйте окружение оболочки или пользовательские настройки, чтобы прокси [применялся вместе с кэшированными серверными данными](#per-key-exceptions-across-managed-sources).
* В окружении оболочки
* В [пользовательских настройках](https://code.claude.com/docs/ru/settings.md#where-settings-live)

Задайте `HTTPS_PROXY`, даже если `ALL_PROXY` уже указывает этот прокси.

Claude Code применяет большинство обновлений настроек к работающим сессиям без перезапуска. Некоторые обновления применяются только при следующем запуске, включая конфигурацию экспортера OpenTelemetry, ключ `model` и удаление переменной из блока `env`.

### Недопустимые записи в доставленных настройках

Когда часть данных не проходит проверку по схеме, Claude Code сообщает об ошибке проверки и применяет все остальные допустимые настройки; в разделе [Недопустимые записи в управляемых настройках](https://code.claude.com/docs/ru/managed-settings.md#invalid-entries-in-managed-settings) указано, что отбрасывается и какие ключи возвращаются к более строгому значению. Требуется Claude Code v2.1.169 или более поздней версии.

Доставка, управляемая сервером, добавляет следующее поведение:

* Запуск, использующий кэш в `~/.claude/remote-settings.json`, обрабатывает недопустимые записи так же, как получение, записавшее этот кэш:
  * Записи, не прошедшие проверку, остаются отброшенными.
  * [Ключи с отказом при сбое](https://code.claude.com/docs/ru/managed-settings.md#keys-that-fail-closed) сохраняют свои более строгие значения.
  * Недопустимое значение `cleanupPeriodDays` или `desktopSessionCleanupPeriodDays` остаётся в кэшированной копии и никогда не применяется.
* Claude Code ничего не применяет из данных и оставляет кэш без изменений, когда выполняются все три условия:

  * Каждая настройка в данных не проходит проверку.
  * Ни одна из них не возвращается к более строгому значению.
  * Данные содержат ключ, отличный от этих двух ключей хранения.

  В этом случае уведомление при запуске, `/status` и `claude doctor` сообщают о [неудачной загрузке](https://code.claude.com/docs/ru/errors.md#remote-managed-settings-failed-to-load) с причиной `no setting in the server response could be applied as written`, а в этой записи указано, на какой политике работает сессия. Клиенты, которые [применяют запуск с отказом при сбое](#enforce-fail-closed-startup), вместо этого завершают работу при запуске. Если запуск прерывается с сообщением о том, что вашей организации требуются её настройки `before a session can start`, см. [Claude Code не смог загрузить настройки вашей организации](https://code.claude.com/docs/ru/errors.md#couldnt-load-your-organizations-settings).
* [Диалог подтверждения безопасности](#security-approval-dialogs) оценивает очищенные данные, поэтому удалённая недопустимая запись никогда не предлагается для подтверждения и никогда не выполняется.

Чтобы отладить проблемы с доставкой, выполните `claude --debug-file <path>` и найдите в логе `Remote settings`. Проверьте изменение данных с помощью `claude doctor` на тестовой машине, прежде чем развёртывать его в организации.

### Принудительный запуск с отказом при сбое

По умолчанию, если получение удалённых настроек при запуске завершается неудачно, CLI продолжает работу с настройками, кэшированными при последнем успешном получении, если только срок их действия не [истёк](#fetch-and-caching-behavior). [Значения, которые Claude Code удерживает](#fetch-and-caching-behavior), остаются удержанными, пока получение не завершится успешно. Если срок действия кэшированных настроек истёк или они отсутствуют, CLI продолжает работу без настроек, управляемых сервером, и по-прежнему применяет все [настройки, управляемые на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), на устройстве. Вместо этого [Anthropic может требовать наличия настроек](#fetch-and-caching-behavior).

Чтобы клиенты не запускались с кэшированными или отсутствующими настройками, управляемыми сервером, задайте `forceRemoteSettingsRefresh: true` в управляемых настройках.

Клиенты, вошедшие через [шлюз приложений Claude](#platform-availability), ждут получения при запуске независимо от того, задана ли эта настройка, и обрабатывают неудачное получение следующим образом:

* Если шлюз отвечает на интерактивный запуск с участием пользователя кодом `401`, а эта настройка отключена, значит, шлюз завершил этот вход. Claude Code выводит [`Cloud gateway session expired — run /login to reconnect.`](https://code.claude.com/docs/ru/errors#cloud-gateway-session-expired) и открывает сессию без входа в шлюз, пока пользователь не выполнит `/login`.
* Если получение завершается неудачно любым другим образом или при запуске любого другого типа, кроме подкоманды `claude auth`, клиент завершает работу с ошибкой.

Когда эта настройка активна в сессии, которая получает настройки, управляемые сервером, CLI блокируется при запуске, пока удалённые настройки не будут заново получены. Если получение завершается неудачно, CLI завершает работу, а не продолжает без политики. Сессия, которая [не получает настройки, управляемые сервером](#platform-availability), запускается без ожидания.

Чтобы включить эту возможность, добавьте ключ в конфигурацию управляемых настроек:

{ "forceRemoteSettingsRefresh": true }


Вы также можете задать этот ключ в [управляемом на уровне конечного устройства](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms) профиле MDM или системном файле `managed-settings.json`, чтобы применить поведение с отказом при сбое при первом запуске, до поступления каких-либо данных с сервера. Этот флаг является исключением из описанного выше [правила приоритета](#settings-precedence): Claude Code учитывает его, когда его задаёт любой управляемый источник, контролируемый администратором, даже если также присутствуют кэшированные данные, управляемые сервером, поэтому значение, доставленное через MDM, не игнорируется при наличии настроек, управляемых сервером.

При последующих запусках Claude Code читает значение, доставленное сервером, из кэшированных настроек, поэтому настройка активна ещё до первого получения в новой сессии. Чтобы настройка оставалась активной без опоры на кэшированную копию, также задайте ключ в источнике, управляемом на уровне конечного устройства.

Когда [`policyHelper`](https://code.claude.com/docs/ru/settings-reference#policyhelper) предоставляет управляемые настройки, его вывод заменяет все остальные управляемые источники для ключей, которые Claude Code читает после запуска. Об источниках, из которых Claude Code читает этот ключ, см. [его запись в справочнике настроек](https://code.claude.com/docs/ru/settings-reference.md#forceremotesettingsrefresh). В записи `policyHelper` указано, из каких источников Claude Code читает хелпер и когда он запускается.

При получении настроек также отправляется заголовок `Cache-Control: no-cache`, чтобы промежуточные HTTP-прокси не отдавали устаревший ответ.

Прежде чем включать эту настройку, убедитесь, что сетевые политики разрешают подключение к `api.anthropic.com`. Если этот эндпоинт недоступен, CLI завершает работу при запуске, и пользователи не могут запустить Claude Code.

Подкоманды `claude auth`, такие как `claude auth login`, освобождены от этой проверки и от завершения при запуске через шлюз, чтобы пользователи могли повторно пройти аутентификацию, когда причиной неудачного получения настроек являются истёкшие учётные данные.

### Диалоги подтверждения безопасности

Некоторые настройки, которые могут представлять угрозу безопасности, требуют явного подтверждения пользователя, прежде чем Claude Code применит их в интерактивной сессии:

* **Настройки shell-команд**: настройки, выполняющие shell-команды, например `apiKeyHelper`, `statusLine` и `otelHeadersHelper`
* **Настройки исполняемых файлов песочницы**: `sandbox.bwrapPath`, `sandbox.socatPath` и `sandbox.ripgrep`. Каждая из этих настроек указывает на исполняемый файл, и Claude Code запускает этот исполняемый файл
* **Настройки сети и изоляции песочницы**: настройки [песочницы](https://code.claude.com/docs/ru/sandboxing.md), которые позволяют прокси песочницы читать, перенаправлять или аутентифицировать трафик или ослабляют изоляцию песочницы: `sandbox.network.tlsTerminate`, `sandbox.network.httpProxyPort`, `sandbox.network.socksProxyPort`, `sandbox.credentials`, `sandbox.allowAppleEvents`, `sandbox.allowNestedUserNamespaces`, `sandbox.enableWeakerNestedSandbox`, `sandbox.enableWeakerNetworkIsolation`, `sandbox.filesystem.disabled`, `sandbox.network.allowAllUnixSockets`, `sandbox.network.allowUnixSockets` и `sandbox.network.allowMachLookup`. Блок `sandbox.credentials`, содержащий только правила `deny`, не требует подтверждения, поскольку он ограничивает песочницу, не предоставляя прокси учётных данных. До v2.1.251 Claude Code применял эти настройки без подтверждения
* **Пользовательские переменные окружения**: доставленные переменные `env`, требующие подтверждения пользователя, например переменные прокси и базового URL; см. [Переменные окружения и диалог подтверждения](#environment-variables-and-the-approval-dialog)
* **Конфигурации хуков**: любое определение хука

Когда эти настройки присутствуют, пользователи видят диалог безопасности с объяснением того, что настраивается. Чтобы продолжить, пользователи должны дать подтверждение. Если пользователь отклоняет настройки, Claude Code завершает работу.

Управляемый CLAUDE.md, доставленный через ключ [`claudeMd`](https://code.claude.com/docs/ru/settings-reference#claudemd), не требует подтверждения, поскольку это текст инструкций для Claude, а не команда, которую запускает Claude Code. Claude Code по-прежнему проверяет [разрешения](https://code.claude.com/docs/ru/permissions.md) для инструментов, которые Claude использует, следуя этим инструкциям. До v2.1.260 значение `claudeMd` также требовало подтверждения.

#### Запоминание подтверждения

Claude Code записывает ваше подтверждение в каталог конфигурации — `~/.claude`, если вы не задали [`CLAUDE_CONFIG_DIR`](https://code.claude.com/docs/ru/env-vars). Что именно записывается, зависит от учётных данных, которые использует получение настроек:

* **Вход claude.ai, сохранённый с помощью `/login` или `claude auth login`, или [вход в Console без ключа](https://code.claude.com/docs/ru/authentication.md#sign-in-without-an-api-key)**: одно подтверждение на организацию, которое принадлежит аккаунту, давшему подтверждение последним.
* **Вход через [шлюз приложений Claude](https://code.claude.com/docs/ru/claude-apps-gateway)**: одно подтверждение на шлюз.

  Если вы выходите и снова входите в тот же шлюз, Claude Code не показывает диалог повторно, пока настройки, требующие подтверждения, не изменились. Claude Code показывает его снова, когда эти настройки меняются, когда вы входите в другой шлюз и когда вы принимаете новый сертификат для того же шлюза.

  Claude Code не сохраняет подтверждение для loopback-шлюза разработки, доступного по обычному HTTP, поэтому диалог появляется снова после каждого входа.
* **Любые другие учётные данные**, например API-ключ или `CLAUDE_CODE_OAUTH_TOKEN`: одно подтверждение для доставленных настроек, хранящееся вместе с кэшированной копией настроек в этом каталоге конфигурации. Claude Code показывает диалог снова, когда меняются настройки, требующие подтверждения, и после того, как вы выполните `/logout` или `claude auth logout` — любая из этих команд удаляет кэшированную копию.

Подтверждение для `sandbox.credentials` или `sandbox.network.tlsTerminate` также распространяется на записи [`sandbox.network.allowedDomains`](https://code.claude.com/docs/ru/settings-reference#sandbox-network-alloweddomains) в тех же доставленных настройках, поскольку обе настройки действуют на этот список разрешённых доменов. Диалог появляется снова, когда администратор добавляет или удаляет одну из этих записей, даже несмотря на то что `sandbox.network.allowedDomains` сам по себе не требует подтверждения.

При сохранённом входе claude.ai:

* Если вы выходите и снова входите или переключаетесь на другую организацию, а затем возвращаетесь, Claude Code не показывает диалог повторно, пока эти настройки не изменились, если только в промежутке другой аккаунт не подтвердил их для этой организации в том же каталоге конфигурации.
* Если вы входите в ту же организацию с другим аккаунтом, Claude Code показывает диалог снова, даже если настройки не изменились. Подтверждение этого аккаунта заменяет предыдущее, поэтому при обратном переключении Claude Code снова показывает диалог.

Claude Code не всегда может показать диалог. В каждом из случаев ниже указано, какие настройки применяются, когда это невозможно, и когда вы увидите диалог в следующий раз:

* **Интерактивная сессия, которая не может показать диалог**: Claude Code не применяет доставленные настройки и сохраняет последние подтверждённые настройки. Диалог появляется в следующей сессии, которая может его показать.
* **`claude install` или `claude update`**: Claude Code не показывает диалог во время выполнения этих команд. Команда выполняется с последними подтверждёнными настройками, а диалог появляется в вашей следующей интерактивной сессии. Если Claude Code ждёт получения настроек при запуске, например когда задан [`forceRemoteSettingsRefresh`](#enforce-fail-closed-startup) или при развёртывании [шлюза приложений Claude](https://code.claude.com/docs/ru/claude-apps-gateway), он вместо этого показывает диалог во время выполнения команды, и установка, запущенная из канала, завершается неудачно; см. [`Raw mode is not supported` во время установки](https://code.claude.com/docs/ru/troubleshoot-install#raw-mode-is-not-supported-during-install). До v2.1.246 Claude Code также пытался показать диалог во время этих команд.
* **Команда `claude plugin`, которая выводит данные в терминал, но не может читать с клавиатуры**: когда Claude Code не ждёт получения настроек при запуске, команда не применяет доставленные настройки. Без [кэшированных настроек](#fetch-and-caching-behavior) команда, изменяющая ваши плагины или маркетплейсы, [останавливается с ошибкой](https://code.claude.com/docs/ru/errors.md#managed-settings-need-your-approval). С кэшированными настройками она выполняется с последними подтверждёнными настройками. Диалог появляется, когда вы в следующий раз запустите `claude` в терминале.

  Команда не может читать с клавиатуры, когда вы передаёте ей ввод через канал или перенаправляете его и, в macOS и Linux, она также не может открыть `/dev/tty`. Если вы также передаёте через канал или перенаправляете её вывод, запуск становится неинтерактивным, и доставленные настройки применяются только для этого запуска.
* **Ошибка закрывает диалог до того, как вы ответите**: Claude Code не применяет доставленные настройки и сохраняет последние подтверждённые настройки. Он снова показывает диалог в следующей сессии, которая может его показать.
* **Неинтерактивный запуск**, например `claude -p`, сессия Agent SDK или сессия на панели чата расширения VS Code либо на вкладке Code настольного приложения: Claude Code не может показать диалог. Если доставленные настройки требуют подтверждения, они применяются только для этого запуска.

  Claude Code не отмечает настройки как подтверждённые и не записывает их в [локальный кэш](#fetch-and-caching-behavior), а следующая интерактивная сессия показывает диалог. Пока пользователь не даст подтверждение в интерактивной сессии, каждый неинтерактивный запуск заново получает настройки при запуске.

#### Переменные окружения и диалог подтверждения

Claude Code применяет некоторые доставленные переменные `env`, не показывая пользователю диалог подтверждения, в том числе:

* Переключатели функций и команд
* Настройки выбора и поведения модели, например `ANTHROPIC_MODEL`, `DISABLE_PROMPT_CACHING` и `CLAUDE_CODE_EFFORT_LEVEL`
* Настройки контекстного окна и сжатия контекста, например `DISABLE_AUTO_COMPACT`, но не `CLAUDE_CODE_DISABLE_1M_CONTEXT`
* Параметры пользовательского интерфейса терминала и специальных возможностей
* Числовые ограничения, бюджеты и таймауты

Другие доставленные переменные могут требовать подтверждения пользователя, прежде чем вступят в силу. Например, в интерактивных сессиях следующие переменные всегда требуют его при любом непустом значении:

* Переменная прокси или базового URL
* `OTEL_EXPORTER_OTLP_ENDPOINT`
* `CLAUDE_CODE_DISABLE_1M_CONTEXT`

Когда доставленной переменной требуется подтверждение, диалог называет её, чтобы пользователь точно видел, что политика пытается задать.

Для четырёх переключателей конфиденциальности Claude Code решает, нужно ли подтверждение, по доставленному значению, а не по имени переменной: `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_ERROR_REPORTING`, `DISABLE_TELEMETRY` и `DO_NOT_TRACK`. Истинное значение, например `1` или `true`, лишь отключает отслеживание, отправку отчётов или другой необязательный трафик, поэтому Claude Code применяет его, не спрашивая пользователя. Для любого другого непустого значения Claude Code показывает диалог.

Для [`API_FORCE_IDLE_TIMEOUT`](https://code.claude.com/docs/ru/env-vars) Claude Code также решает, нужно ли подтверждение, по доставленному значению: истинное значение лишь включает [таймаут простоя тела ответа](https://code.claude.com/docs/ru/network-config.md#streaming-idle-watchdogs), поэтому Claude Code применяет его, не спрашивая пользователя. Для любого другого непустого значения Claude Code показывает диалог. До v2.1.248 любое непустое значение вызывало диалог.

Нужно ли подтверждение для [`ANTHROPIC_CUSTOM_HEADERS`](https://code.claude.com/docs/ru/env-vars#variables), также зависит от доставленного значения. Заголовки, которые лишь помечают запросы, например `Accept-Language`, применяются без диалога. Строка, которая указывает учётные данные, селектор организации или тенанта, переопределение маршрутизации или хоста либо заголовок, влияющий на поведение API, например `Authorization`, `X-Api-Key`, `Host`, `anthropic-beta` или заголовки `X-Amzn-Bedrock-*`, требует подтверждения. Строка также требует подтверждения, если её имя не является допустимым токеном HTTP-заголовка или её значение содержит символ, который не может передаваться в HTTP-заголовке. Проверка сопоставляет слова внутри имени заголовка, поэтому `X-Client-Version`, содержащий `client` и `version`, тоже требует подтверждения. До v2.1.251 любое значение `ANTHROPIC_CUSTOM_HEADERS` применялось без него.

Ложное значение, например `0` или `false`, для [`ENABLE_BETA_TRACING_DETAILED`](https://code.claude.com/docs/ru/env-vars#variables) или [`OTEL_LOG_RAW_API_BODIES`](https://code.claude.com/docs/ru/env-vars#variables) применяется без диалога, поскольку оно лишь отключает подробную трассировку или захват необработанных тел запросов API. Любое другое непустое значение для любой из этих переменных требует подтверждения.

## Доступность платформы

Параметры, управляемые сервером, требуют прямого подключения к `api.anthropic.com`. Доставка также требует, чтобы сеанс аутентифицировался с помощью одного из этих учетных данных:

* Вход в организацию Team или Enterprise через OAuth
* Токен OAuth, предоставленный через `CLAUDE_CODE_OAUTH_TOKEN`
* Напрямую настроенный ключ API
* Профиль `user_oauth` [Anthropic](https://code.claude.com/docs/ru/authentication.md#anthropic-profiles-and-federation-credentials), если только профиль не устанавливает `base_url`, отличный от Anthropic API. Требуется Claude Code v2.1.257 или позже.

Ни ключи, возвращаемые скриптом [`apiKeyHelper`](https://code.claude.com/docs/ru/settings-reference#apikeyhelper), ни учетные данные [Workload Identity Federation](https://platform.claude.com/docs/en/manage-claude/workload-identity-federation) не запускают выборку параметров.

Сессия получает управляемые настройки той организации, которой принадлежат учётные данные, используемые ею для аутентификации. API-ключ из [Claude Console](https://platform.claude.com) принадлежит организации Console, в которой он был создан, и это отдельная организация, отличная от вашей организации Team или Enterprise на claude.ai. Поэтому настройки, которые вы задаёте в Admin Settings на claude.ai, не доходят до сессии, которая аутентифицируется с помощью этого ключа, например до задания CI, использующего API-ключ Console вашей компании. Чтобы применить их к такому заданию, используйте один из следующих вариантов. Вариант с токеном OAuth не подходит для задания, запускаемого с [`--bare`](https://code.claude.com/docs/ru/headless#start-faster-with-bare-mode), поскольку режим bare не читает `CLAUDE_CODE_OAUTH_TOKEN`.

* **Токен OAuth**: сгенерируйте токен с помощью [`claude setup-token`](https://code.claude.com/docs/ru/authentication#generate-a-long-lived-token), авторизуйте его для вашей организации Team или Enterprise и задайте его как `CLAUDE_CODE_OAUTH_TOKEN` в окружении задания. Удалите из этого окружения все учётные данные, которые [имеют приоритет](https://code.claude.com/docs/ru/authentication.md#authentication-precedence) над токеном, например `ANTHROPIC_API_KEY`.
* **Настройки, управляемые конечной точкой**: разверните [файл управляемых настроек](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms) на машине, на которой выполняется задание.

В сессии [Cowork](https://claude.com/docs/cowork/overview) в приложении Claude Desktop Claude Code не получает настройки, управляемые сервером, из консоли администратора claude.ai, даже если пользователь входит с учётной записью Team или Enterprise. Раздел [Где и когда применяется политика](https://code.claude.com/docs/ru/managed-settings.md#where-and-when-a-policy-applies) описывает, какая политика достигает сессий Cowork на машине пользователя и удалённых сессий Cowork. claude.ai по-прежнему сам применяет ваши списки [`strictKnownMarketplaces`](https://code.claude.com/docs/ru/settings-reference#strictknownmarketplaces) и [`blockedMarketplaces`](https://code.claude.com/docs/ru/settings-reference#blockedmarketplaces), когда пользователь Cowork добавляет маркетплейс из git-репозитория на claude.ai или из **Customize** в Cowork. Раздел [Как работают ограничения](https://code.claude.com/docs/ru/plugins/org.md#restrict-what-users-can-install) описывает эту проверку.

Если вы экспортируете переменную поставщика `CLAUDE_CODE_USE_*` или нестандартный `ANTHROPIC_BASE_URL` в вашей оболочке, Claude Code пропускает выборку параметров для ваших сеансов. [`claude doctor` и `/status` сообщают о пропущенной выборке и ее причине](#verify-settings-delivery).

Вы не можете очистить экспорт с помощью управляемого сервером блока `env`, потому что блок поступает через выборку, которую экспорт предотвращает. Блок `env` [параметров, управляемых конечной точкой](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms), также не восстанавливает выборку: Claude Code проверяет приемлемость перед применением управляемых блоков `env`, поэтому значение, управляемое конечной точкой, изменяет выбор поставщика сеанса, но выборка остается пропущенной.

Чтобы восстановить доставку, управляемую сервером, удалите экспорт из вашей оболочки или установите переменную на `""` в блоке `env` пользовательских параметров, который применяется перед проверкой приемлемости. Чтобы обеспечить политику без полагания на пользователей для изменения их оболочек, доставляйте параметры через управляемый конечной точкой канал вместо этого.

Для развертываний Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry и [Claude Platform on AWS](https://code.claude.com/docs/ru/claude-platform-on-aws.md), самостоятельно размещаемый [Claude apps gateway](https://code.claude.com/docs/ru/claude-apps-gateway) обеспечивает эквивалентную доставку удаленных управляемых параметров: клиенты, вошедшие в шлюз, получают управляемые параметры из шлюза вместо `api.anthropic.com`. Семантика отказов отличается при запуске: клиент шлюза, который не может достичь шлюз, завершает работу с ошибкой вместо возврата к кэшированным параметрам, в то время как почасовое фоновое обновление открыто при отказе на обоих каналах.

## Аудит логирования

События журнала аудита для изменений параметров доступны через API соответствия или экспорт журнала аудита. Свяжитесь с вашей командой учета Anthropic для получения доступа.

События аудита включают тип выполненного действия, учетную запись и устройство, которые выполнили действие, и ссылки на предыдущие и новые значения.

## Соображения безопасности

Параметры, управляемые сервером, обеспечивают централизованное применение политики, но они работают как элемент управления на стороне клиента, а не как граница безопасности. На неуправляемых устройствах пользователю не требуется доступ администратора или sudo для их обхода.

| Сценарий | Поведение |
| :- | :- |
| Пользователь редактирует кэшированный файл настроек | Изменённый файл может применяться при запуске, за исключением [значений, которые Claude Code удерживает](#fetch-and-caching-behavior) до подтверждения сервером полезной нагрузки. При следующей выборке с сервера восстанавливаются правильные настройки. Изменённое значение [ключа, который применяется только при следующем запуске](#fetch-and-caching-behavior), например `model` или переменной, добавленной в блок `env`, остаётся в силе до перезапуска |
| Пользователь удаляет кэшированный файл параметров | Происходит [поведение первого запуска](#fetch-and-caching-behavior) |
| Пользователь запускает измененный двоичный файл Claude Code | Пользователь, который может запустить измененный клиент, может обойти любой элемент управления на стороне клиента |
| Пользователь запускает более старую версию Claude Code | Версии, которые предшествуют параметрам, управляемым сервером, не выбирают и не применяют их |
| API недоступен | Кэшированные настройки применяются, если они доступны и не [истекли](#fetch-and-caching-behavior). Без них Claude Code не применяет настройки, управляемые сервером, до следующей успешной выборки. В разделе [Поведение выборки и кэширования](#fetch-and-caching-behavior) перечислены исключения, в том числе случай, когда Anthropic требует эти настройки. С `forceRemoteSettingsRefresh: true` CLI завершает работу вместо продолжения, за исключением [подкоманд `claude auth`](#enforce-fail-closed-startup). Клиенты, вошедшие через [шлюз приложений Claude](#platform-availability), завершают работу при запуске и без этой настройки, с тем же исключением для `claude auth` |
| Пользователь аутентифицируется с другой организацией | Настройки не доставляются для учётных записей вне управляемой организации, включая сессию, которая аутентифицируется с помощью [API-ключа Console](#platform-availability) |
| Пользователь настраивает [поставщика моделей третьей стороны](#platform-availability) | Параметры, управляемые сервером, обходятся. Это включает установку `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_MANTLE`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_ANTHROPIC_AWS` или нестандартного `ANTHROPIC_BASE_URL` |
| Сетевой трафик перехватывается или перенаправляется | Отключенная проверка TLS или перехваченный трафик могут изменить параметры, которые получает клиент |

Для логирования изменений локальных файлов параметров, включая `managed-settings.json`, используйте [`ConfigChange` hooks](https://code.claude.com/docs/ru/hooks#configchange). Claude Code не запускает их при поступлении параметров, управляемых сервером, или при их обновлении, или при изменении профиля MDM или политики реестра, и hook не может заблокировать изменение `policy_settings`.

Для ограничения организаций, к которым ваши пользователи могут получить доступ с учетными данными, которые предоставляет клиент, см. [Enforce network-level access control with Tenant Restrictions](https://support.claude.com/en/articles/13198485-enforce-network-level-access-control-with-tenant-restrictions) в Центре справки Claude. Для более сильных гарантий применения используйте [параметры, управляемые конечной точкой](https://code.claude.com/docs/ru/managed-settings.md#delivery-mechanisms) на устройствах, зарегистрированных в решении MDM.
