GitHub Copilot #
Dashboard → Providers → Connect GitHub
→ OAuth через GitHub
→ Ежемесячный сброс (1-го числа месяца)

Models:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview

Кредиты AI (тарификация на основе токенов). Когда GitHub сообщает credits_used для учётной записи, карточка лимитов провайдера показывает строку Кредиты AI с количеством кредитов, использованных в текущем расчётном периоде, в том числе для безлимитных тарифов организаций.

Локальный лимит кредитов AI. Измените подключение GitHub и задайте параметр Лимит кредитов AI на расчётный период (providerSpecificData.githubCreditLimit). Пустое значение отключает лимит; 0 всегда пропускает подключение. Когда последнее значение использования равно лимиту или превышает его, при выборе учётной записи это подключение пропускается, а маршрутизация переключается на другие подключения — так же, как при срабатывании ограничения политики квоты. Проверка использует данные об использовании, которые уже собираются периодическим обновлением квоты: GitHub никогда не вызывается непосредственно во время обработки запроса. Проверка работает по принципу fail-open: отсутствующее или устаревшее значение (старше 15 минут либо полученное в расчётном периоде, который уже завершился) не блокирует подключение. Это локальная мера предосторожности, а не гарантированный потолок расходов: задержки в отчётности GitHub, интервал обновления, выполняющиеся запросы и использование за пределами OmniRoute могут привести к превышению лимита. Для жёсткого ограничения используйте собственные средства контроля расходов GitHub.

Развертывание 🚀 #

Глобальная установка npm (рекомендуется) #

npm install -g omniroute

# Create config directory
mkdir -p ~/.omniroute

# Create .env file (see .env.example)
cp .env.example ~/.omniroute/.env

# Start server
omniroute
# Or with custom port:
omniroute --port 3000

CLI автоматически загружает .env из ~/.omniroute/.env или ./.env. ./.env в рабочем каталоге может устанавливать только короткий список разрешенных ключей (REQUIRE_API_KEY, локаль, часовой пояс и настройки цвета, но не порты); все остальное поместите в ~/.omniroute/.env. См. контракты на запуск CLI.

Режим лотка #

Запустите OmniRoute в системном трее:

omniroute serve --tray

Команда возвращается после того, как сервер и лоток будут готовы.

Сервер продолжает работу без терминала.

Режим лотка поддерживает сеансы macOS, Windows и графический Linux. В режиме лотка панель мониторинга не открывается автоматически.

Используйте меню панели задач для следующих действий:

  • Откройте панель управления.
  • Откройте /dashboard/logs.
  • Изменить автозапуск.
  • Стоп OmniRoute.

Не комбинируйте --tray со следующими опциями:

  • --daemon
  • --log
  • --no-recovery

Эти режимы требуют разных владельцев процессов.

Включите запуск при следующем входе в систему:

omniroute autostart enable

При автозапуске используется режим лотка в сеансах macOS, Windows и графическом Linux. Headless Linux использует существующую пользовательскую службу systemd.

Отключить запуск при входе в систему:

omniroute autostart disable

Удаление #

Если OmniRoute вам больше не нужен, мы предоставляем два быстрых сценария для чистого удаления:

КомандаДействие
npm run uninstallУдаляет системное приложение, но сохраняет ваш DB и конфигурации в ~/.omniroute.
npm run uninstall:fullУдаляет приложение AND навсегда стирает все конфигурации, ключи и базы данных .

Примечание. Чтобы запустить эти команды, перейдите в папку проекта OmniRoute (если вы ее клонировали) и запустите их. В качестве альтернативы, если он установлен глобально, вы можете просто запустить npm uninstall -g omniroute.

Пользовательские модели #

Добавьте любую модель ID к любому провайдеру, не дожидаясь обновления приложения:

# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# List: curl http://localhost:20128/api/provider-models?provider=openai
# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"

Или используйте панель управления: Поставщики → [Поставщик] → Пользовательские модели .

Примечания:

  • Поставщики OpenRouter и OpenAI/Anthropic-compatible управляются из Доступные модели только. Добавление, импорт и автоматическая синхронизация вручную попадают в один и тот же список доступных моделей, поэтому для этих поставщиков нет отдельного раздела «Пользовательские модели».
  • Пользовательские модели Раздел предназначен для поставщиков, которые не предоставляют управляемый импорт доступных моделей.

Пользовательские поставщики, совместимые с OpenAI #

Любой шлюз, поддерживающий OpenAI API (автономный прокси-сервер, vLLM, сторонний агрегатор), можно добавить в качестве собственного узла провайдера:

  1. Поставщики → Добавить OpenAI Совместимость .
  2. Имя : отображаемая метка узла.
  3. Префикс : имя маршрутизации. Клиенты называют модели <prefix>/<model>, поэтому узел с префиксом mygw обслуживает mygw/gpt-4o-mini. Необходимый; ограничений по количеству символов нет.
  4. тип API : семейство конечных точек, которые обслуживает шлюз (завершения чата, ответы, встраивания, аудио, изображения).
  5. База URL : корень API, вплоть до /v1 (например https://gateway.example.com/v1), а не полный путь /chat/completions. Шлюзы с нестандартными путями устанавливают их под Расширенные настройки (путь чата, путь моделей).
  6. Ключ API (для проверки) поле только проверяет соединение. После создания узла откройте его и используйте Добавить соединение для хранения ключа, который будут использовать запросы.

Узел получает внутренний идентификатор в форме openai-compatible-<apiType>-<uuid>; вам не нужно его вводить, префикс — это общедоступное имя.

Зарезервированные префиксы #

Префикс не может быть идентификатором или псевдонимом встроенного поставщика (например, openai, cf), а также идентификатором устаревшего поставщика. Распознаватель модели проверяет встроенные идентификаторы и псевдонимы перед пользовательскими узлами, поэтому узел, использующий один из этих префиксов, никогда не получит трафик: вместо этого <prefix>/model перейдет к встроенному поставщику или закроется с ошибкой, если этот поставщик будет удален. Создание или редактирование узла с таким префиксом отклоняется с помощью:

prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)

Выберите отдельный префикс (mygw, acme-proxy). Если запросы к пользовательскому узлу завершаются с ошибкой, в которой указывается встроенный поставщик или его учетные данные, проверьте, зарезервирован ли префикс узла: узлы, сохраненные до существования этого правила, все еще сохраняются, но их префикс направляется к встроенному поставщику. Отредактируйте узел и присвойте ему новый префикс.

Параметры шлюза для каждого соединения #

Эти ключи входят в providerSpecificData соединения (например, через PUT /api/providers/{id}):

  • toolNameMaxLength (целое число, 1–1024) — для соединений, совместимых с форматом чата OpenAI, шлюз которых отклоняет длинные имена инструментов. Более длинные имена передаются как короткие псевдонимы и восстанавливаются в ответе. OpenAI, Azure OpenAI, Azure AI Foundry, Mistral, NVIDIA, OpenCode Zen/Go и Muse Code уже используют псевдонимы имен длиной более 64 символов без каких-либо настроек. Значение соединения заменяет значение по умолчанию Azure OpenAI /Azur AI Foundry (подключение Azure за более строгим шлюзом) и устанавливает ограничение для настраиваемого совместимого узла; OpenAI, Mistral, NVIDIA, OpenCode Zen/Go и Muse Code сохраняют ограничение реестра и игнорируют его.
  • quotaEndpoint — конечная точка quota/credits шлюза, чтение полосы квот панели мониторинга и маршрутизации с учетом квот. Работает как с OpenAI, так и с Anthropic-совместимыми соединениями; полная форма документирована в open-sse/services/usage/openaiCompatible.ts.
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}

Объединение пиров OmniRoute в цепочку #

Еще один шлюз OmniRoute можно добавить в качестве Пользовательский OpenAI-совместимый провайдер. Используйте базовый /v1 URL узла и выделенный ключ API с наименьшими привилегиями, выданный этим узлом.

Для взаимных или многопрыжковых цепочек включите защиту от петель на каждом шлюзе:

# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4

Заголовок X-OmniRoute-Peer-Trace получают только запросы, отправленные узлу URL явно включенному в разрешенный список. Шлюз отклоняет повторный экземпляр ID или исчерпанный бюджет переходов с помощью HTTP 508 Loop Detected; обычные вышестоящие поставщики не получают метаданных одноранговых узлов.

Цепочка одноранговых узлов не является репликацией базы данных или переключением хоста при сбое. Каждый шлюз сохраняет независимое состояние SQLite, кэши, счетчики скорости и сеансы. Используйте обратный прокси-сервер с проверкой работоспособности или аварийное переключение клиента для доступности active/passive или active/active и никогда не монтируйте одну базу данных SQLite в несколько работающих экземпляров OmniRoute.

  • Создает временный https://*.trycloudflare.com URL, который перенаправляет вашу текущую конечную точку /v1, совместимую с OpenAI.

  • Панели Cloudflare Quick Tunnel, Tailscale Funnel и ngrok Tunnel можно отображать или скрывать в Настройки → Внешний вид . Скрытие панели не останавливает работающий туннель.

Стратегии маршрутизации #

Настроить через Панель мониторинга Настройки → Маршрутизация → . На информационной панели представлены шесть наиболее часто используемых стратегий; комбинации и автоматическая трассировка поддерживают более широкий набор.

Стратегии, видимые на информационной панели (маршрутизация на уровне учетной записи):

СтратегияОписание
Сначала заполнитеИспользует учетные записи в порядке приоритета. Основная учетная запись — обрабатывает все запросы, пока они не станут недоступны.
Круговая системаЦиклическое переключение всех учетных записей с настраиваемым фиксированным лимитом (по умолчанию: 3 вызова на учетную запись).
P2C (Сила двух вариантов)Выбирает 2 случайных аккаунта и направляет к более здоровому. — балансирует нагрузку с осознанием здоровья.
СлучайныйСлучайным образом выбирает учетную запись для каждого запроса, используя перемешивание Фишера-Йейтса.
Наименее используемыйМаршруты к аккаунту с самой старой отметкой времени lastUsedAt, распределение трафика равномерно.
Оптимизированная стоимостьМаршруты к учетной записи с наименьшим значением приоритета, оптимизация для поставщиков с наименьшими затратами.

Продвинутые комбо и автоматические стратегии (настраивается для каждой комбинации или с помощью префиксов auto/* — см. AUTO-COMBO.md ):

  • priority — строгий порядок, никогда не циклический порядок
  • weighted — пропорциональное разделение трафика по весам для каждой модели
  • fill-first — сливает первую модель, пока не достигнут предел
  • round-robin / strict-random / random
  • p2c (Сила двух вариантов)
  • least-used и cost-optimized
  • auto — на основе оценок всех кандидатов
  • lkgp (последний удачный поставщик) — связывается с последним успешным поставщиком, а затем возвращается к правилам
  • context-optimized — выбирает модель с самым большим окном свободного контекста
  • context-relay — объединяет модели с длинным контекстом для последующих ходов

Устойчивость и автоматические выключатели #

Настроить через Панель мониторинга Настройки → Устойчивость → .

OmniRoute реализует устойчивость на уровне поставщика с помощью пяти компонентов:

  1. Очередь запросов и скорость выполнения — Формирование запросов на уровне системы:
  2. Запросов в минуту (RPM) — Максимальное количество запросов в минуту на аккаунт
  3. Минимальное время между запросами — Минимальный промежуток в миллисекундах между запросами
  4. Максимальное количество одновременных запросов — Максимальное количество одновременных запросов на одну учетную запись
  1. Время восстановления соединения — Конфигурация по типу аутентификации для одного соединения после повторных сбоев:
  2. Базовое время восстановления — Окно восстановления по умолчанию для повторных сбоев восходящего потока
  3. Используйте подсказки для повторных попыток восходящего потока — Уважает авторитетные подсказки Retry-After или сброса, если они предоставлены.
  4. Максимальное количество шагов отсрочки — Максимальный уровень экспоненциальной задержки для повторяющихся сбоев
  1. Автоматический выключатель поставщика — Отслеживает сквозные сбои поставщика, отмечает, что производительность провайдера снизилась при достижении настроенного порога предупреждения, и включает прерыватель при достижении настроенного порога отказа:
  2. Порог деградации — Последовательные сбои поставщика перед входом DEGRADED
  3. Порог отказа — Последовательные сбои поставщика перед входом OPEN
  4. Сбросить тайм-аут — Временной интервал перед повторным тестированием поставщика
  5. CLOSED (Работно) Запросы — выполняются нормально
  6. DEGRADED Запросы — продолжают обрабатываться, а сбои с повышенными правами отслеживаются.
  7. OPEN Поставщик — временно заблокирован после неоднократных сбоев
  8. HALF_OPEN — Тестирование, восстановился ли провайдер

Ограничения скорости 429 на уровне соединения остаются в силе Время восстановления соединения и не засчитывайте в счет прерывателя провайдера.

Состояние выполнения прерывателя поставщика показано на Панель управления → Health только.

  1. Подождите перезарядки — Если каждое потенциальное соединение уже остывает, OmniRoute может дождаться самого раннего остывания и автоматически повторить тот же клиентский запрос.
  1. Автоматическое определение ограничения скорости — Когда вышестоящие поставщики возвращают явные окна ожидания, эти подсказки переопределяют время восстановления локального соединения, если этот параметр включен.

Совет для профессионалов: Используйте Здоровье страница для проверки и сброса автоматических выключателей действующего поставщика после сбоя. Страница «Устойчивость» меняет только конфигурацию.

Настройте балансировку для каждой комбинации в Панель управления → Combos → Create/Edit → Стратегия .

Глобальные настройки комбо по умолчанию можно установить в Панель мониторинга Настройки → Маршрутизация → Комбинированные настройки → по умолчанию . Целевые тайм-ауты комбо по умолчанию наследуют текущий тайм-аут запроса. Использовать Целевой тайм-аут (секунды) по умолчанию для комбо или отдельного комбо только в том случае, если более короткий лимит для каждой цели должен вызвать более быстрый откат.

Комбинированная оптимизация с нулевой задержкой включена по желанию. Оставлять Оптимизация с нулевой задержкой отключено, чтобы предотвратить использование этих функций задержки в гонке за резервными целями, пропуске целей на основе истории TTFT или сжатии резервных запросов; его включение позволяет настраивать хеджирование, прогнозировать пропуски TTFT и упреждающее резервное сжатие, чтобы заменить точность routing/request на меньшую задержку хвоста.

Запрещать Буфер токена рассуждения когда вышестоящие провайдеры требуют строгих ограничений max_tokens / maxOutputTokens. Если эта функция включена, комбинированная маршрутизация добавляет запас для модели рассуждения только для моделей с известным ограничением вывода и оставляет предел клиентского токена неизменным, когда безопасное буферизованное значение превысит это ограничение. Если лимит клиента уже превышает известный предел, OmniRoute ограничивает его до этого предела перед отправкой восходящего запроса.

🤖 Автоматическая маршрутизация (без настройки) #

OmniRoute поставляется с автоматическим маршрутизатором на основе оценок, который выбирает лучшую модель для каждого запроса среди всех подключённых провайдеров — не нужно вручную поддерживать комбинации. Просто отправьте запрос с одним из префиксов auto/*, и OmniRoute динамически соберёт виртуальную комбинацию, оценивая кандидатов по задержке, стоимости, доле успешных запросов, соответствию контексту, пригодности модели для задачи, недавним сбоям, квоте и состоянию автоматического выключателя.

ПрефиксКритерий оптимизации
autoСбалансированный режим по умолчанию (задержка × стоимость × доля успешных запросов)
auto/codingЗадачи программирования: предпочтение Claude, GPT-5, GLM, Kimi, Qwen Coder и моделям DeepSeek для написания кода
auto/cheapМинимальная стоимость за токен, допускается более высокая задержка
auto/fastМинимальная задержка без учёта стоимости
auto/offlineТолько локальные провайдеры (Ollama, vLLM, llama.cpp) — полезно для изолированных сред
auto/smartПриоритет качества рассуждений (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)
auto/lkgp«Последний заведомо исправный провайдер» — закрепляет последний успешный провайдер, а затем использует правила резервного переключения

Пример:

curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'

Полное описание автоматического маршрутизатора приведено в AUTO-COMBO.md, включая настройку весов оценивания, добавление провайдеров в чёрный список и просмотр решений маршрутизации в разделе Панель управления → Автоматическая комбинация.

🔌 Интеграция с MCP и A2A #

OmniRoute одновременно является сервером MCP (Model Context Protocol) и сервером A2A (Agent-to-Agent JSON-RPC 2.0). Любая IDE или среда размещения агентов, совместимая с MCP, может напрямую вызывать инструменты OmniRoute — дополнительная обёртка не требуется.

Транспорты MCP #

  • SSE: http://localhost:20128/api/mcp/sse
  • Потоковый HTTP: http://localhost:20128/api/mcp/stream
  • stdio: omniroute --mcp (для плагинов IDE, предпочитающих stdio)

Подключение Claude Desktop #

Отредактируйте ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) или аналогичный файл в Windows/Linux:

{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}

Подключение Cursor / Continue / VS Code MCP #

Используйте URL-адрес SSE http://localhost:20128/api/mcp/sse и API-ключ Bearer, созданный в разделе Панель управления → API-ключи.

Области доступа #

В настоящее время MCP определяет 32 именованные области доступа. Каждый ключ Bearer можно ограничить определёнными областями доступа — полный перечень областей и инструментов приведён в MCP-SERVER.md, а схема JSON-RPC — в A2A-SERVER.md.

🧠 Система навыков #

OmniRoute предоставляет расширяемый фреймворк навыков (src/lib/skills/), позволяющий агентам и конечной точке A2A запускать специализированные процедуры (например, code-review, summarize, extract-facts, web-research).

  • Интерфейс каталога — Просматривайте и устанавливайте навыки через Панель управления → Навыки
  • Области действия для отдельных ключей — Ограничивайте навыки, которые могут вызывать конкретные API-ключи
  • Пользовательские навыки — Поместите TypeScript-файл в src/lib/a2a/skills/, зарегистрируйте его, и он сразу станет доступен для вызова через A2A

Полная документация: SKILLS.md.

💾 Система памяти #

OmniRoute обеспечивает постоянное хранение долговременной памяти диалогов с гибридным поиском:

  • SQLite FTS5 для поиска по ключевым словам в предыдущих репликах
  • Векторное хранилище Qdrant (необязательно) для семантического поиска
  • Автоматическое извлечение фактов — сущности, предпочтения и решения обобщаются после каждого сеанса и сохраняются в таблице memory_facts
  • Область видимости воспоминаний ограничивается API-ключом и сеансом

Управляйте воспоминаниями в разделе Панель управления → Память (поиск, редактирование, экспорт, удаление). HTTP-интерфейс (/api/memory/*) позволяет агентам программно добавлять и запрашивать факты — см. MEMORY.md.

🔔 Вебхуки #

Подписывайтесь на события OmniRoute для мониторинга и автоматизации в реальном времени.

  • Создайте вебхук в разделе Панель управления → Вебхуки, указав целевой URL и секретный ключ для HMAC-подписи
  • Доступные события: request.completed, request.failed, provider.unavailable, budget.exceeded, combo.switched, circuit_breaker.opened, circuit_breaker.closed
  • Каждая полезная нагрузка содержит X-OmniRoute-Signature (HMAC-SHA256) для проверки
  • Повторные попытки: 3 попытки с экспоненциальной задержкой, после чего сообщение помещается в очередь необработанных сообщений

Полная схема приведена в WEBHOOKS.md.

🛠️ Программное управление #

Вы можете управлять всеми ресурсами OmniRoute (провайдерами, комбинациями, ключами и настройками) через HTTP, используя Bearer-ключ с областью действия manage.

Создайте ключ в разделе Панель управления → API-ключи → Новый ключ → Область действия: manage, затем выполните:

# Получить список провайдеров
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Добавить подключение к провайдеру
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Создать комбинацию
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Получить список API-ключей или создать новый
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'

Полный каталог конечных точек и схемы запросов/ответов см. в API_REFERENCE.md.

💻 Внутренний CLI #

OmniRoute поставляется с внутренним CLI (omniroute …) для настройки, диагностики и управления во время выполнения. Он отличается от страницы «Инструменты CLI» в панели управления, где настраиваются сторонние CLI (Claude Code, Cursor, Codex, Cline, …), чтобы они могли взаимодействовать с OmniRoute.

omniroute setup                    # Интерактивный мастер (пароль, провайдеры, комбинации)
omniroute setup --non-interactive  # Подходит для CI
omniroute doctor                   # Диагностика состояния (каталог данных, БД, провайдеры, порты)
omniroute providers available      # Вывести список поддерживаемых провайдеров
omniroute providers list           # Вывести список настроенных подключений
omniroute providers test <id>      # Проверить подключение к провайдеру в реальном времени
omniroute combos list              # Вывести список комбинаций
omniroute combos switch <name>     # Установить комбинацию по умолчанию
omniroute models                   # Вывести список доступных моделей (--json, --search)
omniroute keys add | list | remove # Управлять ключами API из терминала
omniroute backup                   # Создать снимок конфигурации и БД
omniroute restore [<timestamp>]    # Восстановить данные из снимка
omniroute health                   # Подробное состояние (предохранители, кеш, память)
omniroute quota                    # Использование квот провайдеров
omniroute mcp status               # Состояние сервера MCP
omniroute a2a status               # Состояние сервера A2A
omniroute tunnel list|create|stop  # Туннели Cloudflare/Tailscale/ngrok
omniroute reset-password           # Сбросить пароль администратора
omniroute --mcp                    # Запустить сервер MCP через stdio
omniroute --port 3000              # Запустить сервер на пользовательском порту

Совет: используйте omniroute doctor --json вместе со своим инструментом мониторинга, чтобы получать оповещения о неработоспособных подключениях к провайдерам.
