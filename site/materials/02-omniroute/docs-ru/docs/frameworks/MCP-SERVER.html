Сервер Model Context Protocol со 110 инструментами для операций маршрутизации, кэширования, сжатия, памяти, навыков, прокси, пула, Radar и источников контекста.

Источник истины: open-sse/mcp-server/server.ts вычисляет 110 уникальных инструментов с помощью countUniqueMcpTools(): 45 канонических определений (включая шесть инструментов жизненного цикла CCR, три инструмента навыков агента, omniroute_radar_catalog и omniroute_x_search), а также инструменты памяти (3), навыков (4), навыков GitHub (3), пула (6), геймификации (8), плагинов (8), Notion (6), Obsidian (22), локального корпуса (3) и два инструмента сжатия только для RTK.

Установка #

OmniRoute MCP встроен. Начните с:

omniroute --mcp

Или через транспорт open-sse:

# Streamable HTTP transport (default port 20128, in-process on the dashboard server)
omniroute                                          # start the dashboard server
omniroute mcp enable --transport streamable-http   # from another shell; HTTP is off by default
# Client endpoint: http://localhost:20128/api/mcp/stream
# stdio: omniroute --mcp

Транспорты HTTP (sse / streamable-http, обслуживаемые в процессе сервером информационной панели) по умолчанию отключены, и ранее их можно было переключать только со страницы /dashboard/mcp. Начиная с версии 3.8.51, CLI имеет четность:

omniroute mcp status                                  # enabled/online, transport, tool count
omniroute mcp enable [--transport stdio|sse|streamable-http]
omniroute mcp disable
omniroute mcp restart                                 # resets active sse/streamable-http sessions

mcp enable/mcp disable PATCH тот же mcpEnabled (и, возможно mcpTransport), настройка переключения панели управления через /api/settings. mcp restart вызывает POST /api/mcp/restart: он разрывает активные сеансы sse/streamable-http, чтобы следующий запрос повторно инициализировался без ошибок, возвращает 409 если MCP отключен, и 501 для транспорта stdio (клиенты stdio владеют собственным подпроцессом — внутри процесса нет дескриптора для перезапуска).

Транспорты #

Сервер MCP предоставляет три транспорта, использующих одну и ту же фабрику createMcpServer():

ТранспортГдеКогда использовать

ssePOST/GET /api/mcp/sse через httpTransportБраузерные клиенты и клиенты-агенты, которым нужен поток событий

Активный HTTP-транспорт (sse или streamable-http) выбирается параметром mcpTransport. При переключении транспорта существующие сеансы другого транспорта закрываются.

Удалённый доступ (обход через область manage) #

/api/mcp/* относится к уровню LOCAL_ONLY (src/server/authz/routeGuard.ts) — по умолчанию доступ к нему разрешён только с loopback-хостов (localhost, 127.0.0.1, ::1). Начиная с v3.8.2 клиенты не с loopback-адресов могут подключаться, если передают Authorization: Bearer <api-key>, где ключ имеет область manage. Это единственный способ получить удалённый доступ к серверу MCP через туннель, обратный прокси или публичное имя хоста.

# Предоставьте область manage: откройте страницу API Keys панели управления и включите
# «Management Access» для ключа либо передайте POST scopes:["manage"] при создании.

# Затем подключитесь из удалённого клиента MCP:
curl -i \
  -H "Host: your-public-host.example" \
  -H "Authorization: Bearer sk-…" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"my-client","version":"0"}}}' \
  https://your-public-host.example/api/mcp/stream

Ключ без области manage (или отсутствие Bearer) приводит к ответу 403 LOCAL_ONLY. Для соседнего префикса /api/cli-tools/runtime/* обход намеренно НЕ предусмотрен — см. Уровни Route Guard — исключение для области manage.

Проверка Origin #

После аутентификации у каждого запроса к /api/mcp/* — транспортам и управляющим маршрутам вроде status, tools, audit, restart — проверяется заголовок Origin, кем бы ни был вызывающий (API-ключ, токен CLI, сессия дашборда или анонимный loopback при отключённом входе). Это защита от DNS rebinding, которую требует спецификация MCP Streamable HTTP.

  • Нет заголовка Origin → разрешено. CLI OmniRoute, SDK и IDE-клиенты его не отправляют.
  • Допустимый Origin → localhost / 127.0.0.1 / [::1] на любом порту или собственный публичный origin OmniRoute: OMNIROUTE_PUBLIC_BASE_URL / NEXT_PUBLIC_BASE_URL / NEXT_PUBLIC_APP_URL, origin, переданный доверенным обратным прокси (OMNIROUTE_TRUST_PROXY, только если base URL не задан), или прямое обращение к loopback/LAN IP-хосту. Один лишь заголовок Host никогда не делает origin доверенным.
  • Любой другой Origin, включая null → 403 с телом ошибки JSON-RPC: id: null, error.code: -32000, error.data.code: "INVALID_ORIGIN". Сессия дашборда с действительным CSRF-токеном по-прежнему принимается, как и для других операций записи дашборда.

Браузерному MCP-клиенту за обратным прокси нужен OMNIROUTE_PUBLIC_BASE_URL; списка разрешённых других origin нет. Предварительный CORS-запрос (OPTIONS) не проверяется по Origin; последующий запрос — проверяется.

Записи CCR используют двухуровневое хранилище: горячий уровень в памяти, поддерживаемый в локальных необлачных средах выполнения надежным уровнем SQLite (ccr_blocks, включен по умолчанию), поэтому блок выдерживает вытеснение или перезапуск до тех пор, пока в его TTL не закончится — за исключением блоков старше 512 KB, облачных сред выполнения и COMPRESSION_CCR_DURABLE_STORE=false, которые остаются только в памяти. Надежная запись — это лучшее, что можно сделать: она отбрасывается, когда уже ожидаются 1000 операций записи, а неудачная запись SQLite регистрируется, а не повторяется, так что блок теряется при перезапуске. Каждый блок ограничен 2 MiB, каждый принципал — 16 MiB, а глобальное хранилище — 64 MiB. По умолчанию для записей используется 24-часовой TTL (максимум семь дней). Полное извлечение MCP ограничено 256 KiB; более крупные блоки остаются доступными в режимах range и grep. Хранение, извлечение, перечисление, проверка, удаление и статистика изолированы аутентифицированным принципалом API-ключа. Записи аудита содержат хэши и метаданные размера, а не контент. Детали, доступные для оператора (два маркера, предварительные требования клиента, codemode:false, области для каждого инструмента, разбиение на страницы и диагностическая матрица) находятся в разделе «Предварительные требования/руководство оператора» модулей сжатия →.

omniroute_compression_status сообщает о сжатии описания MCP отдельно в analytics.mcpDescriptionCompression. Эти значения представляют собой оценки размера метаданных для перечисляемых описаний MCP (tools, prompts, resources и resourceTemplates); они не являются квитанциями об использовании поставщика и отмечены значком source: "mcp_metadata_estimate".

Фильтр дерева доступности MCP (v3.8.0) #

Помимо перечисленных выше инструментов сжатия, OmniRoute включает в себя фильтр после выполнения, который сжимает результаты инструмента инструментов MCP browser/accessibility прежде чем они будут возвращены агенту. Этот фильтр сам по себе не является инструментом — он прозрачно запускается для любого результата инструмента, который содержит подробное дерево доступности или текст снимка браузера (≥ 2000 символов).

Ключевые модели поведения:

  • Сворачивает ≥ 30 последовательных повторяющихся одноуровневых строк в заголовок + хвостовую сводку
  • Сохраняет привязки [ref=eXX] необходимые для Playwright/computer-use
  • Жесткое сокращение текста большого размера (50 000 >) с подсказкой по навигации.
  • Ожидаемая экономия: 60–80% в полезных данных снимка браузера

Конфигурация: compression.mcpAccessibility в глобальных настройках (миграция 056). Реализация: open-sse/services/compression/engines/mcpAccessibility/. Полная документация: Механизмы сжатия — MCP Фильтр дерева доступности.

  -d '{"token": "ntn_..."}'

# Проверить состояние
curl http://localhost:20128/api/settings/notion

# Отключить
curl -X DELETE http://localhost:20128/api/settings/notion

Связанные фреймворки (v3.8.0) #

Приведённый выше набор инструментов MCP (110 уникальных инструментов, подсчитанных с помощью countUniqueMcpTools()) намеренно ограничен операциями маршрутизации, кэширования, сжатия, памяти, навыков, прокси и источников контекста во время выполнения. В v3.8.0 вместе с сервером MCP поставляются два смежных фреймворка, которые документированы отдельно:

Облачные агенты #

Облачные агенты — это выполняемые вне процесса ИИ-агенты для разработки (codex-cloud, cursor-cloud, devin, jules), подключённые к OmniRoute через ту же модель соединения, которая используется для поставщиков LLM. Они доступны через собственный REST-интерфейс (/api/v1/agents/*) и не являются частью каталога инструментов MCP — вызов облачного агента не использует область доступа MCP.

  • Реализация: src/lib/cloudAgent/ (registry.ts, agents/codex.ts, agents/cursor.ts, agents/devin.ts, agents/jules.ts).
  • Жизненный цикл: createTask, getStatus, approvePlan, sendMessage, listSources.
  • Документация: docs/frameworks/CLOUD_AGENT.md.

Защитные механизмы #

Защитные механизмы — это фильтры, применяемые до и после выполнения (vision-bridge, pii-masker, prompt-injection) внутри конвейера чата. Они запускаются до достижения уровня инструментов и маршрутов MCP и отправляют структурированные сведения о нарушениях в конвейер аудита; они не вызываются как инструменты MCP.

  • Реализация: src/lib/guardrails/.
  • Документация: docs/security/GUARDRAILS.md.

При отладке вызова MCP, который выглядит заблокированным, проверяйте как журнал аудита MCP (записи scope_denied:*), так и журнал аудита защитных механизмов — запрос может быть отклонён защитным механизмом до того, как он достигнет уровня проверки областей доступа MCP.

Аутентификация и области действия #

Инструмент MCP вызывает чтение строк области от вызывающего объекта. Эта проверка является одним из трех независимых пространств имен. Пропуск одной шашки не является пропуском остальных. Правила — это три пространства имен. Каталог инструментов — MCP.

Три пространства имен области видимости #

manage для ключа API, read:compression для инструмента MCP и read для токена доступа oma_live_… — это три разных гранта. Вызывающие абоненты, которые отправляют токен доступа read на изменяющийся маршрут управления, получают HTTP 403 Access token scope 'read' is insufficient; 'write' required. Этот ранг равен scopeSatisfies. Он не обращается к таблице MCP, и средство сопоставления MCP не обращается к ней.

Соответствие #

Каталог представляет собой таблицу областей действия инструментов MCP. Не рассматривайте MCP_SCOPE_LIST в src/shared/constants/mcpScopes.ts как этот каталог: это исходное типизированное подмножество. Более поздние инструменты объявляют рядом с ним дополнительные области действия (read:notion, read:skills, read:local-corpus и остальная часть таблицы).

evaluateToolScopes в open-sse/mcp-server/scopeEnforcement.ts разрешает вызов, когда каждая требуемая область соответствует некоторой предоставленной области:

  • * соответствует каждой необходимой области.
  • Предоставленная область, оканчивающаяся на * соответствует требуемой области, которая начинается с префикса перед звездочкой. read:* соответствует read:compression.
  • Любая другая предоставленная область соответствует только идентичной требуемой строке.

Ключ с областью действия ["manage"] не работает scopeMatches для read:compression. Тот же вызов завершается неудачно для admin, mcp:connect, read и write если это единственные разрешенные строки. Между областями действия инструмента MCP нет никакой иерархии, кроме завершающего *.

Принудительное применение отключено, кроме случаев, когда используется OMNIROUTE_MCP_ENFORCE_SCOPES=true ( false по умолчанию). Пока он выключен, evaluateToolScopes разрешает вызов и пропускает каталог. Пока он включен, HTTP использует api_keys.scopes ключа носителя в качестве authInfo (см. Привязка области действия HTTP для каждого ключа ). Когда никакие области ключей не разрешаются, предоставленный набор переходит к MCP _meta (соблюдается только для вызывающих HTTP/SSE, внутри контекста аутентификации HTTP ; _meta вызывающего stdio игнорируется, поскольку клиент управляет им и не несет идентификатора для каждого вызывающего абонента), затем OMNIROUTE_MCP_SCOPES.

Области токена доступа #

Токены oma_live_… (src/lib/accessTokens/scopes.ts) содержат read, write или admin. scopeSatisfies — ранг: admin покрывает write и read, а write покрывает read. Неизвестные области ничего не покрывают.

evaluateAccessTokenAuth (src/server/authz/accessTokenAuth.ts) сравнивает этот ранг с inferRequiredScope (src/server/authz/accessScopes.ts):

  • GET, HEAD и OPTIONS требуют read.
  • Для любого другого метода требуется write.
  • Пути в ADMIN_SCOPE_PREFIXES требуют admin для каждого метода. /api/mcp находится в этом списке, поэтому токен доступа write по-прежнему не может вызвать поверхность MCP HTTP.
  • Пути в ADMIN_MUTATION_PREFIXES требуют admin только для мутаций.
  • Пути в ADMIN_MUTATION_EXACT_PATHS (/api/settings, /api/settings/require-login) требуют admin только для мутаций, и только на этом точном пути — другие подмаршруты /api/settings/* сохраняют write.

PATCH /api/keys/{id} является мутацией и не находится в этих списках администраторов, поэтому токен read получает 403 Access token scope 'read' is insufficient; 'write' required. Токен доступа write или admin удовлетворяет этому маршруту. Панель мониторинга JWT, токен машинного идентификатора обратной связи CLI и ключ API с manage или admin берут другие ветви и не сужаются этим рангом.

Токен доступа, который передает scopeSatisfies для /api/mcp, очищает только шлюз управления. Вызовы инструментов по-прежнему запускают scopeMatches для областей ключей API. Ранг токена доступа не является входными данными для scopeMatches.

mcp:connect — возможность узкого маршрута (#7895) #

Для достижения транспорта HTTP/SSE MCP (/api/mcp/*) без обратной связи требуется вырезание /api/mcp/ LOCAL_ONLY (см. docs/security/ROUTE_GUARD_TIERS.md). Исторически сложилось так, что при таком выделении допускался только полный ключ manage/admin -scope API — слишком широкий для вызывающего абонента, которому нужно только говорить MCP. src/shared/constants/managementScopes.ts теперь экспортирует MCP_CONNECT_SCOPE = "mcp:connect": аддитивную узкую область действия (тот же прецедент, что и SELF_USAGE_SCOPE), которая разрешает ONLY обход /api/mcp/ в src/server/authz/policies/management.ts — он не предоставляет никакого другого доступа к маршруту управления и намеренно сохраняет OUT из MANAGEMENT_API_KEY_SCOPES. Ключ, содержащий manage/admin по-прежнему проходит вырезание без изменений; mcp:connect — это альтернатива с более низкими привилегиями для удаленных вызывающих абонентов, использующих только MCP, проверенная через hasMcpConnectOrManageScope().

Привязка области действия HTTP для каждого ключа (#7895) #

Через HTTP/SSE open-sse/mcp-server/httpTransport.ts теперь разрешает реальный api_keys.scopes вызывающего объекта через resolveMcpCallerAuthInfo() (open-sse/mcp-server/httpAuthContext.ts) и передает его MCP transport.handleRequest(req, { authInfo }) SDK, поэтому extra.authInfo.scopes достигающий каждого вызова инструмента, отражает собственные области действия ключа-носителя. scopeEnforcement.ts в resolveCallerScopeContext() уже отдал приоритет authInfo над резервным вариантом _meta и OMNIROUTE_MCP_SCOPES env. — это заполняет только тот первый источник с наивысшим приоритетом, который ранее не был подключен к HTTP. Когда ключ API не разрешается (нет заголовка, неверный ключ), authInfo остается undefined, и разрешение попадает в существующую цепочку meta/env без изменений. stdio не имеет идентификации для каждого вызывающего абонента (см. mcpCallerIdentity.ts) и на него не влияет привязка каждого ключа — он пропускает шаг _meta (_meta учитывается только внутри контекста аутентификации HTTP, #15159) и разрешается только из ключа OMNIROUTE_MCP_SCOPES env.

Принудительное применение принудительно применяется для вызывающих HTTP/SSE с узкой областью независимо от OMNIROUTE_MCP_ENFORCE_SCOPES. OMNIROUTE_MCP_ENFORCE_SCOPES значение которого по умолчанию равно false безопасно только для потока local/stdio с одним оператором, где нет идентификатора для каждого вызывающего абонента, на который можно было бы ориентироваться. open-sse/mcp-server/server.ts::withScopeEnforcement() включает безусловное принудительное применение области для каждого инструмента (shouldForceScopeEnforcement() в scopeEnforcement.ts), когда resolveCallerScopeContext() разрешает source === "authInfo" (т. е. реальный заголовок авторизации HTTP для каждого ключа, HTTP/SSE-only) AND этот ключ не содержит полной области manage/admin. Это закрывает пробел, где ключ, содержащий ONLY узкую область обхода mcp:connect — описанную выше как не разрешающую ничего, кроме исключения /api/mcp/ LOCAL_ONLY — в противном случае мог бы вызвать каждый инструмент MCP как только оператор включил доступ remote/non-loopback MCP, просто потому, что OMNIROUTE_MCP_ENFORCE_SCOPES поставляет false по умолчанию. Полный ключ manage/admin поверх HTTP и каждый вызывающий stdio/local сохраняют существующее поведение OMNIROUTE_MCP_ENFORCE_SCOPES -gated неизменным.

Сжатие описаний #

Реестры инструментов, запросов и ресурсов MCP могут сжимать описания во время регистрации или получения списка, чтобы уменьшить объём метаданных, предоставляемых клиентам (и, следовательно, затраты контекста запроса). Реализация находится в open-sse/mcp-server/descriptionCompressor.ts и подключена к серверу MCP через compressMcpRegistryMetadata внутри createMcpServer().

  • Сжатие применяется к тексту описания с использованием набора правил Caveman (getRulesForContext("all", "full")) и извлечением сохраняемых блоков (фрагментов кода, блоков с ограждением и т. д.), поэтому структурное содержимое не изменяется.
  • Переключение для каждого развёртывания выполняется через значение compression.mcpDescriptionCompressionEnabled в таблице настроек key_value (по умолчанию включено) — в пользовательском интерфейсе доступно как Аналитика → Сжатие описаний MCP.
  • Переключение для всего процесса выполняется с помощью OMNIROUTE_MCP_COMPRESS_DESCRIPTIONS=false или OMNIROUTE_MCP_DESCRIPTION_COMPRESSION=false.
  • Статистика в реальном времени доступна через omniroute_compression_status в разделе analytics.mcpDescriptionCompression и помечается source: "mcp_metadata_estimate", чтобы отличать её от фактических данных об использовании поставщика.

Сокращение количества инструментов (F4.3) #

Сжатие описаний уменьшает объём метаданных каждого инструмента; сокращение количества инструментов идёт ещё дальше, уменьшая _число_ объявляемых инструментов. Публикация меньшего количества инструментов в манифесте tools/list снижает затраты токенов на каждый запрос, которые несёт модель клиента из-за каталога инструментов (сжатие «уровня 5»). Реализация представляет собой чистый фильтр без состояния в open-sse/mcp-server/toolCardinality.ts (reduceToolManifest), подключённый к циклу регистрации в createMcpServer() (open-sse/mcp-server/server.ts).

Включается явно и по умолчанию отключено. Фильтр запускается только тогда, когда задана хотя бы одна из двух переменных окружения; если не задана ни одна из них, все 110 инструментов объявляются без изменений.

ПеременнаяРежим
MCP_TOOL_DENYЧёрный список — разделённые запятыми имена инструментов, которые всегда исключаются из tools/list
MCP_TOOL_ALLOWСписок разрешённых — разделённые запятыми имена инструментов; сохраняются только они, а все остальные исключаются

deny имеет приоритет над allow. Имена разделяются запятыми, пробелы по краям удаляются, а пустые элементы игнорируются. Примеры:

# Исключить два инструмента из каталога
MCP_TOOL_DENY="omniroute_get_health,omniroute_list_combos" omniroute --mcp

# Объявить только инструменты маршрутизации и квот (режим списка разрешённых)
MCP_TOOL_ALLOW="omniroute_route_request,omniroute_check_quota" omniroute --mcp

Как удаляются отфильтрованные инструменты: регистрация всегда выполняется успешно; затем для инструмента, отклонённого профилем, вызывается .disable() у дескриптора MCP SDK, поэтому он никогда не появляется в tools/list, но вся связующая логика остаётся нетронутой (чистое включение/отключение без повторной регистрации). Парсер профиля — readMcpToolProfileFromEnv(process.env), который возвращает null (без фильтрации), когда обе переменные пусты.

Более функциональная структура ToolProfile, лежащая в основе reduceToolManifest, также поддерживает фильтрацию по пересечению областей доступа (allowScopes, с сопоставлением по шаблону вида read:*) и детерминированное ограничение maxTools, однако для этих двух параметров во время регистрации требуется полный манифест, и сегодня они не доступны через переменные окружения (отслеживаемая последующая задача — перехватчик на уровне tools/list). Функция estimateManifestTokens() позволяет сравнивать затраты токенов на манифест до и после сокращения.

Пульс среды выполнения #

Транспорт stdio каждые 5 секунд сохраняет сведения о работоспособности в ${DATA_DIR}/runtime/mcp-heartbeat.json. Панель управления (/api/mcp/status) считывает этот файл и проверяет активность PID, чтобы определить значение online. HTTP-транспорты вместо этого сообщают состояние через внутрипроцессную функцию getMcpHttpStatus() (без записи в файл).

Снимок пульса содержит:

{
  "pid": 12345,
  "startedAt": "2026-05-13T12:34:56.000Z",
  "lastHeartbeatAt": "2026-05-13T12:35:01.000Z",
  "version": "1.8.1",
  "transport": "stdio",
  "scopesEnforced": false,
  "allowedScopes": [],
  "toolCount": 110
}

Журналирование аудита #

Каждый вызов инструмента регистрируется в таблице SQLite mcp_tool_audit модулем open-sse/mcp-server/audit.ts:

  • Имя инструмента, аргументы (хешированные/усечённые в соответствии с auditLevel конкретного инструмента), результат
  • Длительность в мс, признак успеха/сбоя, сообщение об ошибке (если применимо)
  • Хеш ключа API, временная метка
  • Отказы из-за областей доступа регистрируются как scope_denied:<reason> со списком недостающих областей

Для просмотра последних вызовов используйте панель управления или REST-эндпоинты /api/mcp/audit и /api/mcp/audit/stats.
