🚀 OmniRoute — Бесплатный шлюз для ИИ #

Создано Diego Souza

<img src="./docs/diagrams/readme-hero.svg" width="100%" alt="OmniRoute — Никогда не прекращайте программировать. Каждый инструмент ИИ → 394 провайдера — 150+ бесплатных — через одну конечную точку. Claude Code, Codex, Cursor, Cline, Copilot и Antigravity для БЕСПЛАТНЫХ Claude / GPT / Gemini с автоматическим резервным переключением. Ступенчатое сжатие RTK + Caveman экономит 15–95% токенов (в среднем ~89%) — ограничения больше не помеха. 394 провайдера ИИ · 150+ бесплатных тарифов · ~1,62 млрд бесплатных токенов в месяц · 22 стратегии маршрутизации · начать за $0."/>

<div align="center">

💰 ~1,62 млрд токенов / месяц в бесплатных тарифах сторонних провайдеров #

</div>

Используйте собственные аккаунты провайдеров. Это оценочный совокупный показатель по отдельно доступным бесплатным тарифам сторонних провайдеров, а не грант токенов от OmniRoute. Зарегистрируйтесь, получите необходимые учётные данные и подключите доступных вам провайдеров; каждый провайдер самостоятельно устанавливает лимиты, доступность и условия использования.

Собирать бесплатные тарифы вручную мучительно — десятки SDK, десятки ограничений скорости и никакого понимания того, сколько ресурсов у вас действительно есть. OmniRoute каталогизирует 465 записей бесплатных тарифов по 34 повторяющимся ключам пулов и вычисляет итоговое количество токенов на основе 17 пулов с опубликованным положительным месячным бюджетом, а также пяти лимитов Groq для отдельных моделей, с устранением дублирования общих пулов. Квоты, которые становятся доступными только после региональной проверки личности (на сегодняшний день: ModelScope), отображаются отдельно: дополнительно ~6 млн после региональной проверки личности, и никогда не включаются в итоговый показатель. Результат остаётся доступным на панели управления (/dashboard/free-tiers).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="Карточка бесплатного тарифа OmniRoute: ~1,62 млрд бесплатных токенов в месяц стабильно и до ~2,22 млрд в первый месяц с бонусами за регистрацию, из 34 документированных повторяющихся ключей пулов, охватывающих 465 записей бесплатных тарифов, доступных через одну конечную точку. Честный расчёт с устранением дублирования пулов — каждый общий пул учитывается один раз, включая 17 повторяющихся пулов с опубликованным положительным месячным бюджетом токенов и пять лимитов Groq для отдельных моделей; 12 провайдеров отмечены как нежелательные в каталоге рисков условий, поэтому решение остаётся за вами. Полоса бюджета включает Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (пять лимитов для отдельных моделей) и меньшие пулы, а также бонусы за регистрацию в первый месяц и провайдеров, которые навсегда предоставляют бесплатный доступ без ограничения количества токенов и отображаются отдельно, поэтому никогда не завышают итоговый показатель. Актуальные использованные и оставшиеся значения на /dashboard/free-tiers."/>

Анимированный обзор актуальной страницы /dashboard/free-tiers. Полная методология (устранение дублирования пулов, уровни кредитов, условия провайдеров): docs/reference/FREE_TIERS.md.

<sub>Эти показатели повторно проверяются каждые две недели по актуальному каталогу и могут изменяться в обе стороны — провайдер прекращает действие бесплатного тарифа, и число уменьшается; появляется новый провайдер, и оно увеличивается. Мы публикуем результаты фактических вычислений каталога, а не округлённый вверх наиболее благоприятный сценарий.</sub>

📡 Радар OmniRoute #

Основной показатель бесплатного уровня по-прежнему составляет ~1,62 млрд токенов в месяц согласно приведённому выше документированному каталогу с устранением дублирования пулов. Временные приветственные кредиты провайдеров могут отдельно увеличить объём в первый месяц до ~2,22 млрд. Radar — это необязательное подписанное дополнение к каталогу для тех, кому нужна более актуальная информация о доступности бесплатных моделей между выпусками OmniRoute; каталог сообщества и все существующие бесплатные функции остаются бесплатными.

Сторонники проекта могут получать актуальный каталог и сведения о дополнительных предложениях провайдеров. Его отдельный изменяемый верхний предел составляет не более приблизительно 3 млрд токенов в месяц в зависимости от доступности провайдеров. Этот предел не гарантируется: провайдеры могут в любое время изменять квоты, требования к участникам, модели или регионы.

Radar используется по желанию и выполняет только GET-запросы. Клиент OmniRoute не отправляет запросы пользователей, данные о трафике, конфигурацию провайдеров, телеметрию использования или локальное состояние скрытия объявлений. Узнать о требованиях к участникам и ознакомиться с текущим каталогом можно на странице radar.omniroute.online/planos.

🎩 Новинка: OmniRouteTray — ваш шлюз в строке меню #

</div>

omniroute serve лучше всего работает постоянно. OmniRouteTray превращает его в приложение для строки меню macOS, которое можно настроить один раз и забыть: оно запускает сервер, поддерживает его работу после перезагрузок, обновляет его на месте и показывает текущий бюджет токенов в один клик — никаких открытых окон терминала и npm install -g omniroute, за которыми нужно следить.

📖 Как это работает — конвейер, архитектура и расчёт экономии #

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="Конвейер сжатия OmniRoute: иллюстративный запрос клиента на 10 000 токенов проходит через 12 компонуемых движков — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra и OmniGlyph — и в описанном примере с последовательным применением может достигать провайдера примерно в объёме 1 080 токенов. Структурированное содержимое защищено механизмами сохранения и проверками точности на каждом шаге; явные режимы с потерями или экспериментальные режимы могут преобразовывать подходящее содержимое."/>

Стандартная комбинация с последовательным применением использует RTK → Caveman. Когда оба движка обрабатывают один и тот же payload инструмента/контекста, экономия суммируется:

combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%

Блоки кода, URL, JSON и структурированные данные всегда защищены движком сохранения.

Зачем использовать много токенов, если можно обойтись малым их количеством? Каждый запрос прозрачно проходит через конвейер сжатия OmniRoute — без изменений на стороне клиента. Теперь это набор из 12 компонуемых движков, которые запускаются по порядку и комбинируются для каждого варианта маршрутизации, опираясь на идеи из RTK, Caveman (⭐ 90K+), LLMLingua-2 и Troglodita (PT-BR).

🎚️ Помимо движков — стили вывода, адаптивный регулятор и управление для каждого запроса #

12 движков выше сокращают то, что поступает. Ещё три уровня определяют как, когда и что поступает на выходе:

  • 🪄 Стили вывода _(управление осью вывода)_ — добавляют детерминированные инструкции для формирования ответа, безопасные для кэша; их можно комбинировать, причём каждый доступен с интенсивностью lite / full / ultra. Добавление стиля — это одна строка в реестре:
  • Лаконичная проза — убрать заполнители / артикли / смягчающие формулировки; сохранить техническую суть без изменений.
  • Меньше кода — YAGNI в духе «ленивого старшего разработчика»: минимальное рабочее изменение, без незапрошенной инфраструктуры.
  • Конский хвост (ленивый старший разработчик) — подняться по лестнице YAGNI, исправить корневую причину, внести минимальное рабочее изменение.
  • У меня СДВГ (сначала действие) — сначала указать следующее действие, пронумеровать шаги, привести один конкретный следующий шаг, без вступления.
  • Лаконичный CJK (文言) — ультралаконичный стиль на классическом китайском (ограничен локалью zh).
  • 🎯 Адаптивный бюджет контекста _(регулятор)_ — вместо одного порога токенов вкл./выкл. наращивать использование самых дешёвых и наименее искажающих движков только настолько, насколько необходимо, чтобы вместить запрос в окно контекста модели. Политика: reserve-output (по умолчанию, с учётом модели) · percentage · absolute. Режим: floor (гарантировать соответствие) · replace-autotrigger (ваш явный выбор имеет приоритет) · off (устаревший порог).
  • 🎛️ Где принимается решение о сжатии _(приоритет, от высокого к низкому)_ — заголовок x-omniroute-compression для запроса › переопределение комбинации маршрутизации › активный именованный профиль › адаптивный режим / автоматический триггер › значение по умолчанию панели › выключено. Применённый план возвращается в заголовке ответа X-OmniRoute-Compression: <mode>; source=<source>.

Автоматически запускайте сжатие по порогу токенов, включайте адаптивный регулятор, закрепляйте именованный профиль, задавайте разовое значение для запроса или назначайте конвейер для каждой комбинации маршрутизации — выбирайте вариант, подходящий для рабочей нагрузки. Опциональный офлайн-eval harness (npm run eval:compression) оценивает точность и экономию на зафиксированном корпусе до публикации изменения.

npm install -g omniroute

Список зависимостей может меняться от релиза к релизу; если npm сообщает другой список, используйте имена пакетов из этого предупреждения. Разрешение для пакета позволяет запускать его скрипты установки. Используете Gemini Web или другого провайдера на основе веб-cookie? Пакет npm включает Playwright, но не его бинарный файл Chromium. Перед первым запросом к веб-провайдеру ознакомьтесь с примечанием Настройка Playwright Chromium.

Панель доступна по адресу http://localhost:20128 · API — по адресу http://localhost:20128/v1.

2) Подключите подходящего провайдера, используя собственную учётную запись

Панель → Провайдеры → выберите провайдера, чьи текущие условия и квота подходят для вашего сценария использования → добавьте его API-ключ или завершите процедуру подключения учётной записи. Бесплатные тарифы могут требовать регистрации, одобрения или способа оплаты. Ознакомьтесь с Руководством по бесплатным тарифам; доступность без ключа не гарантируется, а провайдеры, отмеченные как tos: avoid, по умолчанию исключаются из auto.

3) Укажите провайдера в инструменте разработки

Base URL: http://localhost:20128/v1
API Key:  [скопируйте из Панель → Конечные точки]
Model:    auto            (маршрутизация среди подходящих подключений — или выберите провайдера/модель)

4) Убедитесь, что всё работает

curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"

Вы должны увидеть список подключённых моделей. 🎉 Вот и всё — начинайте писать код, а OmniRoute автоматически выбирает маршруты и выполняет переключение при сбоях.

Если ваш клиент не может отправлять пользовательские заголовки, OmniRoute также предоставляет токенизированные совместимые псевдонимы:

OpenAI catalog:   http://localhost:20128/vscode/YOUR_KEY/
OpenAI models:    http://localhost:20128/vscode/YOUR_KEY/models
OpenAI chat:      http://localhost:20128/vscode/YOUR_KEY/chat/completions
OpenAI responses: http://localhost:20128/vscode/YOUR_KEY/responses
Ollama chat:      http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama tags:      http://localhost:20128/vscode/YOUR_KEY/api/tags

Используйте их только для клиентов, которые не могут добавлять Authorization: Bearer .... Аутентификация через заголовок остаётся предпочтительным режимом.

📦 Больше способов установки — Docker, из исходного кода, pnpm, Arch #

🐳 Docker

docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest

:latest соответствует последней опубликованной стабильной версии SemVer. Тег не отслеживает git main. Для GitOps используйте :X.Y.Z. См. Каналы релизов Docker.Образ фиксирует значение OMNIROUTE_MEMORY_MB=1024. Этого достаточно для панели управления и лёгкого чата. Агентам для программирования (POST /v1/responses из Claude Code, Codex, Grok, …) требуется значительно большая куча V8, иначе процесс завершается с FATAL ERROR примерно при ~12 ГиБ в случае двух перекрывающихся длинных контекстов. Объём контейнера должен превышать размер кучи (нативные буферы находятся за пределами V8):

Рабочая нагрузкаКуча (-e OMNIROUTE_MEMORY_MB)Контейнер (--memory)
Панель управления / лёгкий чат1024 (значение по умолчанию)≥2 ГиБ
Один агент для программирования8192≥10 ГиБ
Два одновременных длинных /v1/responses10240–12288≥12–16 ГиБ
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest

Канал предварительных релизов Docker: diegosouzapw/omniroute:next и diegosouzapw/omniroute:next-web отслеживают текущую ветку по умолчанию release/v*. Эти изменяемые теги предназначены только для тестирования ещё не выпущенных исправлений и не поддерживаются для эксплуатации в production. См. Каналы релизов Docker.

🥟 Bun

Поддерживаются стандартная установка с помощью bun install и глобальная установка (bun install -g omniroute) благодаря обнаружению среды выполнения Bun:

  • Встроенный bun:sqlite: OmniRoute использует встроенный драйвер Bun bun:sqlite при работе под Bun, переключаясь на better-sqlite3 в Node.js или sql.js.
  • Автоматический выбор сборщика Webpack в режиме разработки: среда разработки (bun run dev) автоматически обнаруживает Bun и отключает Turbopack в пользу Webpack, чтобы предотвратить несовместимость нативных привязок V8. Производственные сборки (bun run build) точно следуют OMNIROUTE_USE_TURBOPACK, как и в Node: по умолчанию используется Turbopack, а OMNIROUTE_USE_TURBOPACK=0 позволяет выполнить сборку с Webpack (Dockerfile.bun предоставляет этот параметр как --build-arg).
  • Специализированный Dockerfile для Bun: многоэтапный Dockerfile.bun для производственных развёртываний с нативным Bun (docker build -f Dockerfile.bun -t omniroute:bun .).
# Установка и запуск с Bun
bun install
bun run dev

🦭 Podman

# 1. Подготовьте каталог данных, подключаемый через bind-mount
mkdir -p data

# 2. Только Linux + локальный rootless Podman (никогда не используйте клиент удалённой Podman Machine):

⚡ Более быстрая и компактная установка (без нативной сборки)

Нативный движок SQLite (better-sqlite3) является необязательной зависимостью, поэтому глобальная установка никогда не блокируется из-за компиляции из исходного кода: используется предварительно собранный двоичный файл, если он подходит для вашей платформы/Node, а в противном случае выполняется прозрачный переход на движок на чистом JavaScript (node:sqlite в Node 22+, иначе встроенный sql.js WASM) — инструменты сборки не требуются.

Чтобы полностью пропустить этап нативного прогрева после установки (CI, безголовые среды или медленные машины). Примечание: пропускается только этап прогрева нативного SQLite (scripts/postinstall.mjs); хук копирования/исправления двоичного файла (scripts/build/postinstall.mjs) по-прежнему выполняется в обычном режиме:

OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 также пропускает его

Для максимально быстрой установки предпочтителен pnpm (контентно-адресуемое хранилище + жёсткие ссылки — см. выше). Для работы без панели управления и в безголовом режиме используйте профиль Docker base (см. выше) или руководство по Termux. CLI и веб-панель управления обслуживаются одним и тем же процессом на одном порту, поэтому отдельного пакета только для CLI пока нет.

Как внести вклад #

  1. Создайте форк репозитория
  2. Создайте ветку от актуального коммита release/vX.Y.Z (не от main) — см. Модель ветвления и выпуска
