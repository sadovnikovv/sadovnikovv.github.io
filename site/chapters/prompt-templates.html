Глава 26 Шаблоны промптов

Готовые формулировки для типовых инженерных задач. Копируйте и адаптируйте.

26.1. Разбор даташита

Прочитай [файл PDF]. Составь таблицу:
параметр | значение | условия | страница
Нужны: абсолютные максимумы, рекомендуемые режимы, токи, тепловые параметры,
типовая схема включения, примечания и errata.
Всё, в чём не уверен, вынеси в «Требует проверки». Не выдумывай страницы.

26.2. Ревью схемы

Ты - независимый рецензент. Проверь схему [файл] по даташитам [файлы].
Ищи: неверные номиналы, отсутствие защит, перегрузку, тепловые проблемы,
неверные уровни, конфликты выводов, отсутствие развязки.
Формат: замечание | критичность (блокер/важно/желательно) | обоснование | ссылка.
Файлы не меняй.

26.3. Симуляция

Создай netlist для [схема] и запусти [тип анализа].
Выведи: схему соединений, команды запуска, ключевые графики/числа,
сравнение с аналитическим расчётом и объяснение расхождений.
Сохрани netlist и отчёт в docs/simulation/.

26.4. Прошивка

Реализуй [функция] для [MCU/фреймворк].
Требования: [перечень].
Ограничения: без блокирующих задержек, обработка ошибок, watchdog, [ещё].
Раздели на модули, добавь тесты на хосте, объясни регистры и тайминги.
Не выдумывай адреса: используй docs/datasheets/.

26.5. Ревью кода

Проведи ревью [файлы] как инженер по надёжности.
Ищи: гонки, переполнения, неинициализированные переменные, утечки,
отсутствие проверок, магические числа, нарушения таймингов.
Формат: файл:строка | проблема | почему опасно | как исправить.
Не меняй код, только отчёт.

26.6. План испытаний

Составь протокол испытаний для [изделие].
Требования: [ссылка].
Включи: условия, оборудование, точки измерения, допуски, последовательность,
критерии pass/fail, форму записи, действия при отказе.
Формат: таблица. Отметь, какие пункты требуют калибровки.

26.7. Поиск причины отказа

Опиши отказ: [симптомы, условия, логи, осциллограммы].
Предложи дерево диагностики от наиболее вероятного к наименее.
Для каждой ветви: что проверить, каким прибором, какой ожидаемый результат.
Не делай выводов без данных; помечай предположения.

26.8. Документация

Составь README для проекта по файлам [пути].
Разделы: назначение, состав, сборка, прошивка, проверка, известные ограничения.
Все команды должны быть проверяемыми; спорное помечай.
Добавь матрицу «требование → реализация → проверка».

26.9. Обучение

Объясни [тема] инженеру с опытом в [область], но без опыта в [тема].
Используй аналогии из [область], не упрощай до неверного.
В конце: три вопроса для самопроверки и три типичные ошибки.

26.10. Перевод и терминология

Переведи [текст] на русский, сохранив технические термины.
Для каждого спорного термина дай английский оригинал в скобках.
Не меняй числа, обозначения и единицы. Сомнительные места пометь.
